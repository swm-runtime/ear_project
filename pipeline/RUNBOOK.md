# 파이프라인 운영 가이드 (RUNBOOK)

> 콘솔의 **가이드** 탭이 이 파일을 그대로 보여준다. 대상: 파이프라인을 **돌리는 사람**. 무엇을 켜고, 어디서 보고, 막히면 어떻게 푸는가. 규칙·설계는 `docs/ai/spec/*`, 코드 규칙은 [`CLAUDE.md`](CLAUDE.md), 설치·구조는 [`README.md`](README.md).
> 작성 2026-09-09 (초안 2단계·단발 호출 구성 기준). 숫자(시간·비용)는 실측치이며 구성이 바뀌면 갱신한다.

## 1. 구성 요소 — 무엇이 어디서 도는가

| 구성 | 어디서 | 하는 일 | 켜는 사람 |
|---|---|---|---|
| **콘솔(웹)** | https://admin.earcast.co.kr (EC2, `dev` 머지 시 CI 자동 배포) | 승인·판정·발행 등 사람 몫 + 진행 상황 | 항상 켜져 있음 |
| **io 워커** | 같은 EC2 (`EXECUTOR=none`, `CAPABILITIES=io`) | TTS · 패키지 · 소스 풀 도메인 검사 | CI 배포 시 자동 재시작 |
| **AI 워커** | **팀원 노트북** (`EXECUTOR=claude-cli`, 본인 Claude 구독) | 군집화 · 초안(설계→대본) · QA · 비평 | **사람이 직접** (`npm run worker`) |
| DB | Supabase Postgres | 큐(`jobs`)·상태(`backlog`·`episodes`)·기록(`runs`) | — |
| 산출물 저장소 | S3 `earcast-pipeline-prod` | 대본·발췌·QA·오디오 원본 | — |
| 제품 서버 | ear-prod | 발행된 콘텐츠 (관리자 API는 콘솔의 브라우저 세션으로만 호출) | 백엔드 |

AI 단계는 **노트북 워커가 떠 있을 때만** 진행된다. 콘솔에서 승인해도 워커가 없으면 큐에 "대기"로 쌓여 있다가, 워커가 뜨면 집는다.

## 2. 시작 전 준비 (처음 한 번)

1. Node 20+, `cd pipeline && npm install`.
2. Claude Code 설치 후 `claude` → `/login` (워커의 AI 단계가 이 로그인 = 본인 구독을 쓴다. API 키 없음).
3. `apps/worker/.env` — `cp apps/worker/.env.example apps/worker/.env` 후 값을 채운다. 최소: `DATABASE_URL`, `PIPELINE_WEB_URL`, `PIPELINE_WORKER_TOKEN`.
   비밀은 두 개뿐이다 — `DATABASE_URL`(Supabase 비밀번호 포함)과 `PIPELINE_WORKER_TOKEN`(웹·워커 공유 키). 새 팀원은 이 둘만 기존 팀원에게 **안전한 경로**(비밀 관리 도구·만료되는 메시지)로 받는다. `.env` 파일을 통째로 주고받거나 채팅에 붙이지 않는다. `ELEVENLABS_API_KEY`는 서버 워커 전용이라 노트북에는 넣지 않는다.
4. **산출물 저장소 접근** — `S3_MODE=direct` + `AWS_PROFILE=<SSO 프로필>`. 워커가 AWS SDK 로 S3 를 직접 읽고 쓴다. SSO 세션은 **매일 만료**되므로 3장의 `aws sso login`이 매일 켜기의 첫 단계다.
5. `WORK_ROOT`는 레포 밖 경로(기본 `pipeline/.work`). 지워도 S3에서 다시 내려받는다.

## 3. AI 워커 작동

```bash
aws sso login --profile <프로필>   # S3 자격 증명 — 매일 만료된다. 워커 시작 전에 먼저
cd pipeline
git pull                      # 코드 최신화 (dev)
npm install                   # 의존성이 바뀐 날만 필요하지만 늘 해도 된다
npm run worker                # 계속 폴링. 끄려면 Ctrl+C (진행 중 작업은 큐로 되돌아간다)
```

- 시작 로그 `워커 시작 — … rev=<커밋> · storage=…` 를 확인한다. `rev`가 `git log -1`의 커밋과 다르면 `git pull`이 안 된 것. `storage` 확인에 실패하면(자격 증명 만료) 워커는 작업을 집기 전에 죽는다 — SSO 로그인 후 다시.
- 워커를 켜 둔 채 하루가 넘어가면 SSO 가 도중에 만료된다. 업로드 단계에서 `Token is expired`로 실패하면 5장대로 로그인 후 재시작하면 이어진다.
- 실행 중에는 **노트북이 잠들지 않게** 한다. 하트비트가 15분 끊기면 DB가 작업을 회수해 다른/같은 워커가 처음부터 다시 집는다. `caffeinate -i npm run worker` 로 띄우면 워커가 도는 동안 잠들지 않는다.
- 하루 물량 감각: 한 편 = 설계 10분 + 대본 15분 + QA 7분(회차당) + 비평 10분 ≈ **45분~1시간**. 구독 5시간 창의 15~20%를 쓴다. 창은 02:20 KST에 리셋된다.

## 4. 한 편이 지나가는 길 — 어디서 무엇을 하는가

```
스윕·군집화 ──▶ 백로그 ──승인(사람)──▶ 초안(설계→대본) ──▶ QA ──▶ 비평 ──판정(사람)──▶ TTS ──청취 확인(사람)──▶ 패키지 ──▶ 제품 발행(사람) ──▶ 발행 기록
```

| 단계 | 누가 | 콘솔 위치 | 걸리는 시간 · 비용(정가 환산) | 다음 단계로 |
|---|---|---|---|---|
| 스윕 | io/AI 워커 (사람 트리거) | 스윕·군집화 → [스윕 요청] | 수 분 | 완료 시 군집화 자동 |
| 군집화 | AI 워커 | 같은 화면 | 5~10분 · ~$1 | 후보가 백로그 "에피소드 승인 대기"에 |
| **승인 (게이트 1)** | **사람** | 백로그 → [승인] | — | 승인 즉시 draft 작업이 큐에 (대시보드 "진행 중") |
| 초안 — 설계 | AI 워커 | 대시보드 진행 중 · 작업 기록 | 9~13분 · ~$2 | 산출물: 발췌·claims·**구성안** (에피소드 → 구성안 탭) |
| 초안 — 대본 | AI 워커 | 〃 | 13~25분 · ~$2 | 대본 탭. L0(형식·구간·분량·턴 길이) 위반이면 자동 수정 재생성 |
| QA | AI 워커 | 에피소드 → QA 탭 | 5~7분/회차 · ~$0.7 · 최대 3회 | 통과 → 비평 자동. 3회 실패 → "사람 검토 필요" |
| 비평 | AI 워커 | 에피소드 → 비평·판정 탭 | 8~10분 · ~$1.4 | 사람 판정 대기 |
| **판정** | **사람** | 에피소드 → 대본 탭 (플래그·점수) | — | 저장하면 끝. 회귀 세트면 spec/09 집계에 반영 |
| TTS | io 워커 (사람 트리거) | 에피소드 상단 [TTS] | 3~5분 · **실비** 약 $0.7/편 | 오디오 탭에서 **청취 확인**. 발음 잔존은 발음 탭에서 추가 후 재요청 |
| 패키지 | io 워커 (사람 트리거) | 에피소드 상단 [패키지] | 수 초 | 메타 탭에 upload-meta |
| **제품 발행 (게이트 2)** | **사람** | 에피소드 상단 [제품 발행] → 검수 체크 → 업로드 | — | 제품 발행 목록에 등장, 백로그 `published` |
| 재발행·메타 수정 | 사람 | 에피소드 [재발행 — 오디오 교체] · 제품 발행 → 콘텐츠 상세 | — | 발행 이력에 기록 |

**비용 목표(2026-09-09 박수헌): 대본 생성 완료(설계 + 대본 + L0 수정 + QA 통과)까지 편당 $1.5.** 상한이 아니라 목표다. 현재 구성(설계·대본 opus-5, QA Sonnet 5, 단발 호출)의 실측은 약 $6 (T260909-002: 3.48 + 1.92 + 0.65), 구 방식은 $13~20. 비평은 별도(약 $2). LLM 비용은 구독이라 실제 청구는 없고, TTS만 실비다.

## 5. 막혔을 때 — 상황별 대처

| 증상 | 원인 | 대처 |
|---|---|---|
| 승인했는데 대시보드 "진행 중"에 아무것도 없다 | (2026-09-08 이전 승인분) 작업을 워커가 만들던 시절의 후보 | 워커를 띄우면 폴백이 집는다. 새 승인은 즉시 큐에 뜬다 |
| "진행 중"에 `draft · 대기`가 계속 대기 | 노트북 AI 워커가 없다 | 3장대로 워커 시작 |
| 작업이 `running`인데 하트비트가 15분 넘게 멈춤 | 노트북 잠듦·네트워크 끊김 | DB가 큐로 회수한다. 워커가 살아 있으면 다시 집고, 설계 산출물이 있으면 대본부터 이어간다 |
| 백로그에 **⚠️ 초안 실패** 사유와 함께 "에피소드 승인 대기"로 돌아옴 | 초안이 대본 없이 실패(산출물 누락·재료 13분 미만·호출 오류 2회) | 사유를 읽고 **다시 승인**(새 id로 처음부터) 또는 반려 |
| 작업 기록에 `Token is expired … aws sso login` | AWS SSO 세션 만료 (하루) | `aws sso login --profile <프로필>` 후 워커 재시작. 산출물은 로컬에 남아 있고 작업은 5분 간격으로 업로드를 재시도하므로 생성을 다시 하지 않는다 |
| 작업 기록에 `claude -p 결과 없음 (exit 143)` | 호출이 제한 시간(대본 60분·설계 40분)을 넘김 | 한 번은 자동 재시도. 반복되면 `THINKING_*` 상한을 낮추거나 모델 확인 |
| 작업 기록에 rate limit / 구독 한도 | 5시간 창 소진 | 02:20 KST 리셋까지 대기. 작업은 큐에 남는다 |
| 백로그 "사람 검토 필요" (QA 3회 실패) | 발췌 밖 주장이 수정으로 안 잡힘 | 에피소드 QA 탭에서 사유 확인 → 대본 탭에서 턴 수정 → [재QA 요청] / 백로그에서 [QA 통과 처리] 또는 [반려] |
| TTS가 "발음 잔존"으로 실패 | 대본의 비한글 표기가 발음 맵·전역 사전에 없다 | 에피소드 발음 탭에 추가 → [TTS] 재요청 |
| 제품 발행 화면 "제품 서버 세션이 만료" | 브라우저의 제품 SSO 토큰 만료 | 새로고침(자동 재연결). 로컬 개발 서버에서는 SSO 시크릿이 없어 원래 안 된다 |
| 재발행 버튼이 안 보인다 | 백로그에 제품 content id 가 없다 (0012 이전 발행) | 제품 발행 → "발행 기록 연결" 패널에서 연결 |
| 잘못 만들어진 에피소드를 지우고 싶다 | — | 에피소드 상세 상단 [삭제] — 사유를 적고 후보를 재승인 대기/반려 중 고른다. 산출물도 지워진다. 발행된 편·회귀 세트·진행 중 작업이 있는 편은 막힌다 |

## 6. 설정 토글 (`apps/worker/.env`)

| 변수 | 기본 | 뜻 |
|---|---|---|
| `DRAFT_MODE` | `two-stage` | 초안 2단계(설계→대본). `single`=구 방식 |
| `DESIGN_MODE` / `QA_MODE` | `single` | 단발 호출(도구 없음). `agent`=에이전트 루프 |
| `CLUSTER_MODE` | `v1` | 군집화. `v2`=축 먼저·역할·다양성(단발, 대분류 풀). 콘솔 [군집화 v2] 버튼은 토글과 무관하게 v2 로 돈다 |
| `REVISION_MODE` | `agent` | QA·L0 수정 재생성. `single`=바꿀 턴만 받아 워커가 치환(스모크 $1.92 → $0.89). 판정 3편이 끝나면 `single`로 |
| `DRAFT_DESIGN_MODEL` / `DRAFT_WRITE_MODEL` | `claude-opus-5` | 설계·대본 모델. Fable 로 되돌리려면 `claude-fable-5-1` |
| `QA_MODEL` / `CRITIC_MODEL` / `CLUSTER_MODEL` | Sonnet 5 / opus-5 / opus-5 | 판정·군집화 모델. QA·비평 모델 변경은 회귀 세트 재검증(spec/09 7.4) |
| `THINKING_QA` / `THINKING_DESIGN` / `THINKING_WRITE` / `THINKING_CRITIC` | 6000 / 8000 / 8000 / 없음 | 생각 토큰 상한. `none`=상한 없음. **opus-5·Sonnet 5 는 적응형 생각이라 이 상한을 무시한다** — 아래 `EFFORT_*` 로 묶는다 |
| `EFFORT_DESIGN` / `EFFORT_WRITE` | `medium` / `medium` | 설계·대본의 `claude --effort`. 실측(T260909-004 대본): high $2.02·11분 → medium $1.63·7분(QA 1회 통과) → low $1.35·4분(QA 실패 3). `none`=CLI 기본(high) |
| `CRITIC_RUBRIC` | `v2` | 비평 루브릭 |
| `S3_MODE` / `AWS_PROFILE` | `direct` / SSO 프로필 | 산출물 저장소 접근. 비워 두면 `PIPELINE_WEB_URL` 유무로 정해지니 `direct`를 명시한다 |
| `TTS_SPEED_YUNA` / `TTS_SPEED_EUM` | 1.2 / 1 | 화자별 배속 |

바꾼 뒤에는 워커 재시작. 어느 구성으로 만든 에피소드인지는 `runs.prompt_version`(예: `full-v5.2+2stage`, `qa-v1.2+single`)로 구분한다.

## 7. 규칙을 고칠 때

- 대본 규칙·골드·QA 프롬프트·루브릭·TTS 음차 사전은 **콘솔 → 규칙 자산(`/assets`)** 에서 새 버전(draft) 저장 → 활성화. git 의 `docs/ai/skills/`는 스냅샷이다.
- 단계 규칙(spec/02~07)·프롬프트 조립(`packages/pipeline`)은 코드/문서 PR. 규칙(`guidelines`)을 고치면 루브릭·QA 프롬프트·생성 프롬프트를 같이 본다(spec/09 4.3).
- 에피소드는 만들 때의 규칙 버전에 고정된다(`episodes.asset_versions`). 규칙을 바꿔도 이미 만든 편의 QA·비평은 그 버전으로 돈다.
