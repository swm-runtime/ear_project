# 온보딩 기능 명세서

> 연결 PRD: FR-03, FR-04, FR-17 / 사용자흐름 5.1

## 1. 목적 & 연결

신규 사용자에게서 드립 편성에 필요한 최소 신호(관심 주제)를 받고, 첫 라이브러리를 비어 있지 않은 상태로 만들어 "열면 들을 게 준비되어 있는" 첫인상(PRD 1.3)을 완성한다.

- PRD FR-03 (P0) 중분류 관심 주제 최소 1개 선택
- PRD FR-04 (P0) 커리어 정보 입력(선택, 이후 수정 가능)
- PRD FR-17 (P0) 콜드스타트 — 신호가 없는 신규 사용자 대체 편성
- PRD 사용자흐름 5.1

## 2. 진입 조건

- 신규 가입 직후(약관 동의 완료 시점)
- 기존 계정이지만 `onboarding_completed == false`인 상태로 앱을 실행했을 때 → `onboarding_step`에 저장된 단계부터 재개
- 온보딩 중에는 라이브러리·탐색 등 다른 탭에 접근할 수 없다

## 3. 입력값

| 단계 | 값 | 필수 |
|---|---|---|
| 1. 관심 주제 | selected_topic_ids: string[] | **필수, 최소 1개 · 최대 3개** |
| 2. 커리어 | job_category: string | 선택 |
| 2. 커리어 | job_title: string | 선택 |
| 2. 커리어 | years_of_experience: enum(0-1/2-3/4-6/7+) | 선택 |
| 3. 콘텐츠 선택 | picked_content_ids: string[] | 선택(0개 허용) |
| (단계 밖) 알림 권한 | OS 권한 응답 | — |

- **주제는 3개까지만 고를 수 있다.** 상한을 두는 이유는 드립 편성 때문이다 — 하루 2편(무료 기준)을 여러 주제에 분산하면 어느 주제도 충분히 쌓이지 않아 "내 관심사가 반영된다"는 느낌이 생기지 않는다. 주제를 넓히는 경로는 3단계의 월간 인기 추천(4.3)과 자동 확장(FR-18)이 따로 맡는다.
- **상한은 서버도 검증한다.** 클라이언트의 선택 제한만으로는 우회된다.
- 주제 목록은 서버가 제공한다. **수급 콘텐츠에서 역산한 중분류만 노출**한다(FR-03).
- 노출 여부는 `topics.is_visible`로 결정되며 **이 값은 관리자만 변경한다**(FR-38). **콘텐츠 풀이 없는 주제는 애초에 노출되지 않는다** — 관리자가 관리자 페이지에서 `is_visible`로 제어한다(`admin.md`). 따라서 온보딩에서 "고를 수는 있는데 볼 게 없는 주제"는 존재하지 않는다.

## 4. 처리 로직

### 단계 구성

**진행 인디케이터는 3개다.** 완료 화면과 알림 권한 요청은 **인디케이터 밖**에 둔다.

```
[0] 온보딩 시작 안내(선택 화면 없이 바로 1로 갈 수도 있음)
 → [1] 관심 주제 선택      (1/3) 필수, 건너뛰기 불가
 → [2] 커리어 정보 입력    (2/3) 건너뛰기 가능
 → [3] 추천 콘텐츠 담기    (3/3) 건너뛰기 가능
━━━━━━━━ 인디케이터 종료 ━━━━━━━━
 → [완료] 주제 요약 — 인디케이터 없음
 → [알림] 권한 사전 안내   — 인디케이터 없음
 → 라이브러리 진입
```

- **인디케이터에 들어가는 것은 사용자가 값을 입력하는 단계뿐이다.** 완료 화면은 결과 확인이고 알림은 권한 요청이라, 이 둘을 `4/5` · `5/5`로 세면 "아직 두 단계나 남았다"는 인상을 준다. 실제로 입력이 끝난 뒤라 이탈 지점을 하나 더 만드는 셈이다.
- 3단계를 마치면 인디케이터가 사라지고 완료 화면으로 전환된다. **완료·알림 화면에서는 인디케이터를 그리지 않는다.**
- `onboarding_step` enum(`topic | career | pick | done`)은 그대로 쓴다. 인디케이터 표시 방식이 바뀐 것이지 서버가 관리하는 재개 지점이 바뀐 것은 아니다.

### 단계별 로직

**[1] 관심 주제 선택 (1/3)**
- 서버에서 중분류 주제 목록 조회(`is_visible = true`만, `display_order` 순)
- **최소 1개 · 최대 3개.** 1개 미만이면 [다음] 비활성, 3개를 고른 뒤에는 나머지 칩을 비활성 처리한다
  - 4번째를 탭하면 무시하지 말고 **"관심 주제는 3개까지 선택할 수 있어요"** 토스트로 이유를 알린다. 아무 반응이 없으면 오류로 읽힌다
  - 선택을 바꾸려면 기존 선택을 해제하면 된다
- 선택 즉시 서버에 저장하지 않고, 단계 이탈(뒤로가기 아닌 앱 종료) 대비로 **로컬 임시 저장** → [다음] 탭 시 서버 저장 + `onboarding_step = career`
- 서버는 저장 시 **개수 상한(3개)을 다시 검증**하고 초과분은 저장하지 않는다

**[2] 커리어 정보 (2/3)**
- 전부 선택 항목. [건너뛰기]와 [다음] 모두 제공
- 입력값은 드립 편성의 보조 신호로만 쓰이고, 미입력이어도 편성은 정상 동작해야 한다
- **건너뛰어도 손해가 없다는 것을 화면에서 알린다** — "나중에 프로필에서 언제든 입력할 수 있어요"
  - 커리어 입력·수정은 **프로필 화면**이 담당한다(`profile.md` 4.4). 온보딩에서 못 받은 값을 다시 요구하는 별도 유도 화면은 만들지 않는다
- 저장 후 `onboarding_step = pick`

**[3] 추천 콘텐츠 담기 (3/3)**

서버는 **9건을 두 그룹으로 나눠** 반환한다. 한 덩어리로 주지 않는다 — 그룹이 구분돼야 "내가 고른 주제"와 "새로 만나는 주제"가 화면에서도 나뉜다.

| 그룹 | 건수 | 선정 기준 |
|---|---|---|
| **관심 주제 추천** | **6건** | 1단계에서 고른 주제(최대 3개)의 콘텐츠. 콜드스타트 규칙(FR-17) — 인기·신규 우선 |
| **이번 달 인기** | **3건** | 주제와 무관한 **월간 인기 상위**. 관심사를 넓히는 용도 |

- **월간 인기 3건은 관심 주제 밖에서 고른다.** 목적이 관심사 확장이므로, 이미 고른 주제 안에서 뽑으면 위 6건과 성격이 같아져 의미가 없다.
  - 순위는 **직전 확정 구간**의 월간 집계를 쓴다(5월이면 4월 기준 — README 결정 16번). 진행 중인 달의 미확정 집계를 쓰면 순위가 매일 흔들린다.
  - 6건과 중복되면 인기 쪽에서 빼고 **다음 순위로 채운다.** 9건이라는 수는 유지한다.
- 관심 주제 추천 6건은 **선택한 주제에 고르게 배분한다.** 3개를 골랐으면 2건씩이 기준이고, 특정 주제의 재고가 부족하면 남은 주제에서 채운다.
- 사용자가 카드를 탭해 다중 선택 → [담기] 시 라이브러리에 적립(`source = onboarding`)
- 0개 선택하고 넘어가도 진행 가능. 이 경우 **완료 시점의 자동 드립으로 라이브러리를 채운다**([완료] 참조)
- 여기서의 담기는 재생이 아니므로 무료 티어 카운트와 무관하다
- **추천 0건 상태는 존재하지 않는다.** 콘텐츠 풀이 없는 주제는 애초에 선택지에 없기 때문이다(3장). 그럼에도 0건이 반환되면 정상 상태가 아니라 **데이터 정합성 오류**로 다룬다(7장).

**[완료] 주제 요약** — 인디케이터 없음

- 선택한 주제를 요약해 보여주고 "매일 새로운 콘텐츠가 도착합니다" 안내
- 서버는 이 시점에 `onboarding_completed = true` 처리 및 **첫 드립 편성을 즉시 트리거**한다(드립 명세 참조)
  - 라이브러리가 비어 있지 않도록, [3]에서 담은 수와 무관하게 첫 드립은 실행한다
  - 중복 적립 방지(FR-16)로 [3]에서 담은 콘텐츠는 드립 대상에서 제외
- **무료(라이트) 티어도 온보딩 초기 적립과 이후의 일일 자동 드립을 모두 받는다.** 무료 티어의 드립 편수는 하루 2편으로 고정한다(PRD FR-14).

**[알림] 권한 요청** — 인디케이터 없음

- OS 권한 다이얼로그 직전에 사전 안내(프리퍼미션) 화면을 노출한다 — "드립 도착을 알려드릴까요?"
- [나중에]를 누르면 **재고 팝업을 한 번 띄운다.**
  - 문구: "알림을 받는 분들이 평균 20% 이상 더 많이 듣고 있어요. 정말 설정하지 않으시겠어요?"
  - 버튼: [알림 받기] / [괜찮아요]
  - **[괜찮아요]는 [알림 받기]와 같은 비중으로 노출한다.** 회색 처리하거나 작게 만들지 않는다 — 거부를 어렵게 만드는 순간 다크패턴이 되고, 스토어 심사에서도 지적 대상이다
  - **이 팝업은 온보딩 전체에서 1회만 뜬다.** 팝업의 [괜찮아요]를 누르면 다시 묻지 않고 라이브러리로 진입한다
  - 팝업에서 [알림 받기]를 누르면 OS 권한 다이얼로그로 진행한다
  - ⚠️ **"20%"는 실측 근거가 필요한 수치다.** 자체 데이터가 없는 상태로 단정하면 표시광고 이슈가 된다 → 미결 사항 참조
- [나중에] → [괜찮아요] 경로에서는 **OS 다이얼로그를 띄우지 않는다**(OS 권한은 한 번 거부되면 재요청이 불가하므로 소진하지 않는다)
- 허용/거부 결과와 무관하게 라이브러리로 진입

## 7. 예외 상황

- **1단계에서 주제를 고르다 앱을 강제 종료**: 서버 저장 전이므로 재실행 시 1단계부터. 로컬 임시 저장분을 복원해 선택 상태는 유지한다.
- **로컬 임시 저장분이 3개를 넘는 경우**(상한 도입 이전 버전에서 남은 값): 앞의 3개만 복원한다.
- **2단계 저장 후 종료**: `onboarding_step = pick`이므로 3단계부터 재개.
- **커리어를 건너뛴 사용자**: 재촉하지 않는다. 이후 입력·수정은 프로필에서 한다(`profile.md` 4.4).
- **주제 목록이 비어 있는 경우**(콘텐츠 풀 미구축): 온보딩을 진행할 수 없다. 이 경우 "준비 중입니다" 안내 후 라이브러리 진입을 막지 말고, 기본 주제 세트(하드코딩 폴백)를 노출한다.
- **3단계 추천이 0건으로 반환됨**: **정상 상태가 아니다.** 콘텐츠 풀이 없는 주제는 `is_visible = false`로 노출되지 않기 때문이다(3장). 발생 시 사용자에게는 3단계를 건너뛰고 완료 화면으로 보내되, **운영 알림을 발생시켜 `is_visible` 설정과 콘텐츠 풀을 점검하게 한다.** 사용자 화면에 "추천할 콘텐츠가 없어요" 상태를 두지 않는다 — 정상 경로가 아닌 것을 정상 화면으로 만들면 관리자가 문제를 인지하지 못한다.
- **관심 주제 추천 6건을 채우지 못하는 경우**(선택 주제의 재고 부족): 부족분을 월간 인기에서 끌어와 **총 9건은 유지한다.** 두 섹션의 비율(6:3)보다 전체 건수를 우선한다.
- **월간 인기 3건이 전부 이미 고른 주제와 겹치는 경우**: 중복을 뺀 다음 순위로 채운다. 그래도 모자라면 인기 섹션을 줄여서 노출한다(빈 카드를 만들지 않는다).
- **3단계에서 담기 API 일부 실패**: 성공한 건만 적립하고 실패 건은 토스트로 알린 뒤 진행을 막지 않는다(온보딩 이탈 방지 우선).
- **완료 화면에서 첫 드립 트리거 실패**: 온보딩 완료 처리는 롤백하지 않는다. 드립은 비동기 재시도 큐로 넘기고 라이브러리는 "콘텐츠를 준비하고 있어요" 상태로 노출한다.
- **이미 OS 알림 권한이 허용된 상태**(재설치 등): 알림 단계를 건너뛴다. **재고 팝업도 뜨지 않는다.**
- **재고 팝업을 본 뒤 뒤로가기**: 팝업만 닫고 사전 안내 화면에 머문다. 팝업 노출 이력은 소진된 것으로 처리해 다시 띄우지 않는다.
- **온보딩 도중 로그아웃·세션 만료**: 시작 화면으로 이동. 재로그인 시 저장된 `onboarding_step`부터 재개.
- **뒤로가기로 1단계에서 더 뒤로**: 온보딩 이탈 확인 팝업 없이 아무 동작 안 함(계정은 이미 생성됨). 이탈하려면 설정이 아니라 앱 종료뿐.

## 8. 완료 조건

- Given 신규 가입 직후 사용자 / When 관심 주제를 하나도 선택하지 않는다 / Then [다음] 버튼이 비활성 상태로 유지된다
- Given 관심 주제를 2개 선택했다 / When [다음]을 누른다 / Then 서버에 관심사가 저장되고 커리어 입력 단계로 이동한다
- Given 관심 주제를 3개 선택했다 / When 4번째 주제를 탭한다 / Then 선택되지 않고 **"3개까지 선택할 수 있어요"** 토스트가 노출된다
- Given 클라이언트를 우회해 주제 4개를 서버로 보낸다 / When 저장을 요청한다 / Then 서버가 상한을 검증해 거부한다
- Given 온보딩 1~3단계 / When 각 화면을 본다 / Then 상단 인디케이터가 **`1/3` · `2/3` · `3/3`** 으로 표시된다
- Given 3단계를 마쳤다 / When 완료 화면과 알림 화면으로 넘어간다 / Then **인디케이터가 노출되지 않는다**
- Given 커리어 입력 단계 / When [건너뛰기]를 누른다 / Then 커리어 정보 없이 다음 단계로 이동하고, 이후 드립 편성이 정상 동작한다
- Given 커리어를 건너뛴 사용자 / When 온보딩 완료 후 프로필에 진입한다 / Then 커리어를 입력·수정할 수 있다
- Given 관심 주제를 선택하고 3단계에 진입한다 / When 화면을 본다 / Then **관심 주제 추천 6건과 이번 달 인기 3건이 섹션으로 구분되어** 총 9건이 노출된다
- Given 3단계의 이번 달 인기 3건 / When 각 콘텐츠의 주제를 확인한다 / Then 1단계에서 고른 주제 밖의 콘텐츠가 포함되어 있다
- Given 추천 콘텐츠 단계에서 아무것도 담지 않았다 / When 온보딩을 완료한다 / Then 라이브러리가 비어 있지 않고 첫 드립 콘텐츠가 적립되어 있다
- Given 추천 콘텐츠 3건을 담았다 / When 온보딩을 완료한다 / Then 첫 드립에는 방금 담은 3건이 중복 적립되지 않는다
- Given 커리어 단계까지 마치고 앱을 종료한 사용자 / When 앱을 재실행한다 / Then 추천 콘텐츠 선택 단계부터 재개된다
- Given 알림 사전 안내에서 [나중에]를 누른다 / When 화면을 본다 / Then **재고 팝업이 1회 노출**되고 [알림 받기]/[괜찮아요] 두 선택지가 동등한 비중으로 표시된다
- Given 재고 팝업에서 [괜찮아요]를 누른다 / When 다음으로 넘어간다 / Then OS 권한 다이얼로그가 뜨지 않고 라이브러리로 진입하며, 팝업은 다시 뜨지 않는다
- Given 재고 팝업에서 [알림 받기]를 누른다 / When 다음으로 넘어간다 / Then OS 권한 다이얼로그가 노출된다
- Given 온보딩을 완료했다 / When 뒤로가기를 누른다 / Then 온보딩 화면으로 돌아가지 않는다

## 미결 사항

**확정된 것**

| 항목 | 결정 |
|---|---|
| 무료 티어 초기 적립 | **허용.** 무료 티어도 온보딩 초기 적립과 일일 드립(하루 2편)을 모두 받는다 |
| 주제 선택 상한 | **최대 3개.** 드립 편성이 분산되는 것을 막는다. 서버도 함께 검증한다. **`interest-management.md`도 같은 상한을 쓴다** |
| 커리어 수정 경로 | **프로필 화면**(`profile.md` 4.4). 온보딩에서 건너뛰어도 재촉하지 않는다 |
| 추천 0건 처리 | **정상 상태로 두지 않는다.** 콘텐츠 풀이 없는 주제는 관리자가 `is_visible = false`로 내려 애초에 선택지에서 뺀다(`admin.md`) |
| 3단계 추천 구성 | **관심 주제 6건 + 이번 달 인기 3건 = 9건.** 인기 3건은 고른 주제 밖에서 뽑아 관심사를 넓힌다 |
| 인디케이터 단계 수 | **3개.** 완료·알림은 인디케이터 밖에 둔다 |
| 알림 [나중에] 처리 | **재고 팝업 1회.** 두 선택지를 동등한 비중으로 노출한다 |

**남은 것**

- **재고 팝업의 "20%" 근거** — 자체 데이터가 없는 상태로 수치를 단정하면 표시광고법상 실증 책임이 생긴다. 셋 중 하나로 정해야 한다: ① 출시 후 실측해 실제 값으로 교체 ② 수치를 빼고 "알림을 받으면 놓치지 않아요" 같은 정성 문구로 대체 ③ 업계 통계를 출처와 함께 인용. **출시 전에는 ②로 두는 것이 안전하다.**
- **월간 인기 집계의 최소 표본** — 서비스 초기에는 재생 데이터가 적어 "인기"가 우연에 좌우된다. 표본이 부족한 달에는 인기 대신 신규 콘텐츠로 채울지 결정 필요.
