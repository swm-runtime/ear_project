# 온보딩 기능 명세서

> 연결 PRD: FR-03, FR-04, FR-17 / 사용자흐름 5.1

## 1. 목적 & 연결

신규 사용자에게서 드립 편성에 필요한 최소 신호(관심 주제)를 받고, 첫 라이브러리를 비어 있지 않은 상태로 만들어 "열면 들을 게 준비되어 있는" 첫인상(PRD 1.3)을 완성한다.

- PRD FR-03 (P0) 중분류 관심 주제 최소 1개 선택
- PRD FR-04 (P0) 커리어 정보 입력(선택, 이후 수정 가능)
- PRD FR-17 (P0) 콜드스타트 — 신호가 없는 신규 사용자 대체 편성
- PRD 사용자흐름 5.1

## 2. 진입 조건

- 신규 가입 직후(약관 동의 완료 시점)
- 기존 계정이지만 `onboarding_completed == false`인 상태로 앱을 실행했을 때 → `onboarding_step`에 저장된 단계부터 재개
- 온보딩 중에는 라이브러리·탐색 등 다른 탭에 접근할 수 없다

## 3. 입력값

| 단계 | 값 | 필수 |
|---|---|---|
| 1. 관심 주제 | selected_topic_ids: string[] | **필수, 최소 1개 · 최대 3개** |
| 2. 커리어 | job_category: string | 선택 |
| 2. 커리어 | job_title: string | 선택 |
| 2. 커리어 | years_of_experience: enum(0-1/2-3/4-6/7+) | 선택 |
| 3. 콘텐츠 선택 | picked_content_ids: string[] | 선택(0개 허용) |
| (단계 밖) 알림 권한 | OS 권한 응답 | — |

- **주제는 3개까지만 고를 수 있다.** 상한을 두는 이유는 드립 편성 때문이다 — 하루 2편(무료 기준)을 여러 주제에 분산하면 어느 주제도 충분히 쌓이지 않아 "내 관심사가 반영된다"는 느낌이 생기지 않는다. 주제를 넓히는 경로는 3단계의 월간 인기 추천(4.3)과 자동 확장(FR-18)이 따로 맡는다.
- **상한은 서버도 검증한다.** 클라이언트의 선택 제한만으로는 우회된다.
- **3단계의 0개 선택은 허용하되 그대로 끝내지 않는다.** 0개인 경우 완료 화면에 도달하기 전에 자동 드립으로 라이브러리를 채운다(4장 [3]·[완료]) — 담을 것을 못 고른 사용자가 곧바로 빈 라이브러리를 만나면 온보딩의 목적("열면 들을 게 준비되어 있는" 첫인상)이 정확히 그 사용자에게만 깨진다.
- 주제 목록은 서버가 제공한다. **수급 콘텐츠에서 역산한 중분류만 노출**한다(FR-03).
- 노출 여부는 `topics.is_visible`로 결정되며 **이 값은 관리자만 변경한다**(FR-38). **콘텐츠 풀이 없는 주제는 애초에 노출되지 않는다** — 관리자가 관리자 페이지에서 `is_visible`로 제어한다(`admin.md`). 따라서 온보딩에서 "고를 수는 있는데 볼 게 없는 주제"는 존재하지 않는다.

## 4. 처리 로직

### 단계 구성

**진행 인디케이터는 3개다.** 완료 화면과 알림 권한 요청은 **인디케이터 밖**에 둔다.

```
[0] 온보딩 시작 안내(선택 화면 없이 바로 1로 갈 수도 있음)
 → [1] 관심 주제 선택      (1/3) 필수, 건너뛰기 불가
 → [2] 커리어 정보 입력    (2/3) 건너뛰기 가능
 → [3] 추천 콘텐츠 담기    (3/3) 건너뛰기 가능
━━━━━━━━ 인디케이터 종료 ━━━━━━━━
 → [완료 대기] 자동 드립 편성 — **0건 담기 경로에서만**, 인디케이터 없음
 → [완료] 주제 요약 — 인디케이터 없음
 → [알림] 권한 사전 안내   — 인디케이터 없음
 → 라이브러리 진입
```

- **인디케이터에 들어가는 것은 사용자가 값을 입력하는 단계뿐이다.** 완료 화면은 결과 확인이고 알림은 권한 요청이라, 이 둘을 `4/5` · `5/5`로 세면 "아직 두 단계나 남았다"는 인상을 준다. 실제로 입력이 끝난 뒤라 이탈 지점을 하나 더 만드는 셈이다.
- 3단계를 마치면 인디케이터가 사라지고 완료 화면으로 전환된다. **완료·알림 화면에서는 인디케이터를 그리지 않는다.**
- **[완료 대기]도 인디케이터에 넣지 않는다.** 사용자가 입력하는 단계가 아니라 서버 처리를 기다리는 구간이고, 0건 경로에서만 나타나므로 단계 수를 사람마다 다르게 만든다.
- `onboarding_step` enum(`topic | career | pick | done`)은 그대로 쓴다. **[완료 대기]를 위한 새 값을 만들지 않는다** — 완료 요청 시점에 이미 `done`으로 확정되고, 로딩은 그 이후 클라이언트가 편성 결과를 기다리는 구간일 뿐이라 서버가 관리하는 재개 지점이 늘어나지 않는다.

### 단계별 로직

**[1] 관심 주제 선택 (1/3)**
- 서버에서 중분류 주제 목록 조회(`is_visible = true`만, `display_order` 순)
- **최소 1개 · 최대 3개.** 1개 미만이면 [다음] 비활성, 3개를 고른 뒤에는 나머지 칩을 비활성 처리한다
  - 4번째를 탭하면 무시하지 말고 **"관심 주제는 3개까지 선택할 수 있어요"** 토스트로 이유를 알린다. 아무 반응이 없으면 오류로 읽힌다
  - 선택을 바꾸려면 기존 선택을 해제하면 된다
- 선택 즉시 서버에 저장하지 않고, 단계 이탈(뒤로가기 아닌 앱 종료) 대비로 **로컬 임시 저장** → [다음] 탭 시 서버 저장 + `onboarding_step = career`
- 서버는 저장 시 **개수 상한(3개)을 다시 검증**하고 초과분은 저장하지 않는다

**[2] 커리어 정보 (2/3)**
- 전부 선택 항목. [건너뛰기]와 [다음] 모두 제공
- 입력값은 드립 편성의 보조 신호로만 쓰이고, 미입력이어도 편성은 정상 동작해야 한다
- **건너뛰어도 손해가 없다는 것을 화면에서 알린다** — "나중에 프로필에서 언제든 입력할 수 있어요"
  - 커리어 입력·수정은 **프로필 화면**이 담당한다(`profile.md` 4.4). 온보딩에서 못 받은 값을 다시 요구하는 별도 유도 화면은 만들지 않는다
- 저장 후 `onboarding_step = pick`

**[3] 추천 콘텐츠 담기 (3/3)**

서버는 **9건을 두 그룹으로 나눠** 반환한다. 한 덩어리로 주지 않는다 — 그룹이 구분돼야 "내가 고른 주제"와 "새로 만나는 주제"가 화면에서도 나뉜다.

| 그룹 | 건수 | 선정 기준 |
|---|---|---|
| **관심 주제 추천** | **6건** | 1단계에서 고른 주제(최대 3개)의 콘텐츠. 콜드스타트 규칙(FR-17) — 인기·신규 우선 |
| **이번 달 인기** | **3건** | 주제와 무관한 **월간 인기 상위**. 관심사를 넓히는 용도 |

- **월간 인기 3건은 관심 주제 밖에서 고른다.** 목적이 관심사 확장이므로, 이미 고른 주제 안에서 뽑으면 위 6건과 성격이 같아져 의미가 없다.
  - 순위는 **직전 확정 구간**의 월간 집계를 쓴다(5월이면 4월 기준 — README 결정 20번). 진행 중인 달의 미확정 집계를 쓰면 순위가 매일 흔들린다.
  - 6건과 중복되면 인기 쪽에서 빼고 **다음 순위로 채운다.** 9건이라는 수는 유지한다.
- **표본이 부족한 달에는 순위를 쓰지 않고 랜덤으로 3건을 뽑아 같은 자리에 배치한다.** 서비스 초기에는 재생 데이터가 적어 상위 3건이 실력이 아니라 우연으로 정해진다 — 재생 두 건짜리 콘텐츠가 "이번 달 인기"로 올라오면 추천 전체의 신뢰도가 깎인다.
  - 판정 기준: 직전 확정 월의 `content_stats`(`period_type = month`, `is_final = true`) 재생 합계가 **기준값(30건) 미만**이면 표본 부족으로 본다(`domain.md` 5.4).
  - **랜덤이어도 후보 필터는 그대로 지킨다** — 발행 상태·라이선스 유효·회수되지 않음·**관심 주제 밖**·앞의 6건과 중복 아님. 랜덤은 "순위를 정할 근거가 없다"는 뜻이지 "아무거나 내보낸다"는 뜻이 아니다.
  - **뽑기 결과는 사용자·온보딩 세션 단위로 고정한다.** 뒤로가기로 돌아왔을 때 카드가 통째로 바뀌면 방금 보던 콘텐츠를 다시 찾을 수 없고, 담기를 망설인 사용자가 그대로 이탈한다.
  - 이때는 **섹션 제목을 "이번 달 인기"로 쓰지 않는다.** 인기 순위가 아닌 것을 인기라고 부르면 사실과 다른 표시가 된다 → "이런 주제는 어때요?"로 바꾼다(5장).
- **시리즈물은 첫 편만 후보에 올린다**(`episode_no`가 없거나 1). 아직 아무것도 듣지 않은 사용자에게 3편을 권하면, 1·2편의 존재를 모른 채 중간부터 듣게 된다. 편성 쪽의 같은 규칙(`drip-scheduling.md` 7)과 맞춘 것이다. 두 섹션 모두에 적용된다.
- 관심 주제 추천 6건은 **선택한 주제에 고르게 배분한다.** 3개를 골랐으면 2건씩이 기준이고, 특정 주제의 재고가 부족하면 남은 주제에서 채운다.
- 사용자가 카드를 탭해 다중 선택 → [담기] 시 라이브러리에 적립(`source = onboarding`)
- 0개 선택하고 넘어가도 진행 가능. 다만 이 경우 **[건너뛰기] 즉시 자동 드립 트리거가 작동하고, 편성이 끝날 때까지 완료 화면을 띄우지 않는다**([완료] 참조)
  - 이유: 0개 경로는 온보딩이 끝난 시점에 라이브러리가 비어 있는 유일한 경로다. 편성을 기다리지 않고 "매일 새로운 콘텐츠가 도착합니다"를 보여준 뒤 빈 라이브러리로 보내면 그 문장이 도착 즉시 거짓이 된다.
  - **1건 이상 담은 경로에서는 기다리게 하지 않는다.** 라이브러리가 이미 비어 있지 않으므로 첫 드립은 기존대로 비동기로 트리거하고 사용자는 곧바로 완료 화면으로 넘어간다.
- 여기서의 담기는 재생이 아니므로 무료 티어 카운트와 무관하다
- **추천 0건 상태는 존재하지 않는다.** 콘텐츠 풀이 없는 주제는 애초에 선택지에 없기 때문이다(3장). 그럼에도 0건이 반환되면 정상 상태가 아니라 **데이터 정합성 오류**로 다룬다(7장).

**[완료] 주제 요약** — 인디케이터 없음

- 선택한 주제를 요약해 보여주고 "매일 새로운 콘텐츠가 도착합니다" 안내
- 서버는 완료 요청을 받은 시점에 `onboarding_completed = true` 처리 및 **첫 드립 편성을 즉시 트리거**한다(`drip-scheduling.md` 2·4.6)
  - 라이브러리가 비어 있지 않도록, [3]에서 담은 수와 무관하게 첫 드립은 실행한다
  - 중복 적립 방지(FR-16)로 [3]에서 담은 콘텐츠는 드립 대상에서 제외
- **완료 화면을 언제 띄우는지는 [3]에서 담은 수에 따라 갈린다.**
  - **1건 이상 담았다**: 완료 요청과 동시에 완료 화면을 띄운다. 드립 결과를 기다리지 않는다 — 이미 담은 콘텐츠가 있어 라이브러리가 비지 않으므로, 기다리게 하는 것은 이탈 지점만 늘린다.
  - **0건이다**: 완료 요청 직후 **로딩 화면**으로 전환하고, **자동 드립 적립이 끝난 것을 확인한 뒤에만 완료 화면을 띄운다.** 적립 전에 완료 화면을 띄우면 사용자가 [시작하기]를 눌러 도착하는 라이브러리가 비어 있다.
    - 적립은 원자적으로 처리되므로(`drip-scheduling.md` 4.6-4) "일부만 채워진 상태로 완료"는 없다. 성공이거나 실패다.
- **자동 드립 트리거 실패 시 자동 재시도한다.** 재시도 규칙은 새로 만들지 않고 공통 규칙을 따른다(`common-error-handling.md` 4.2) — 화면마다 재시도 정책이 갈리면 오류 동작을 예측할 수 없게 된다.
  - **최대 2회 재시도(총 3회 시도), 백오프 1초 → 3초(지터 ±20%).**
  - 완료 요청과 드립 트리거는 **멱등키**를 붙여 보낸다. 상태를 바꾸는 요청은 멱등키가 있을 때만 자동 재시도 대상이다(`common-error-handling.md` 4.2). 서버 측 최종 방어선은 `library_items (user_id, content_id)` 유니크다(`drip-scheduling.md` 4.6-5).
  - **재시도를 소진하거나 로딩이 상한(기준값: 15초)을 넘으면 로딩 화면을 걷고 완료 화면으로 진행한다.** 사용자를 로딩 화면에 가둬 두는 것이 최악이다 — 온보딩은 이미 서버에서 완료 처리됐는데 앱만 앞으로 못 가는 상태가 된다.
    - 이때 편성은 **서버의 비동기 재시도 큐**로 넘기고, 라이브러리는 "콘텐츠를 준비하고 있어요" 상태로 진입한다(`library.md` 5).
    - 동시에 **운영 알림을 발생시킨다.** 신규 사용자의 첫 편성 실패는 편성 배치 장애의 조기 신호라, 사용자에게 조용히 넘기고 끝내면 아무도 모른다.
  - **완료 처리는 롤백하지 않는다.** 드립 실패를 이유로 `onboarding_completed`를 되돌리면 사용자가 온보딩을 처음부터 다시 하게 되고, 원인인 편성 장애는 재시도해도 그대로다.
- **무료(라이트) 티어도 온보딩 초기 적립과 이후의 일일 자동 드립을 모두 받는다.** 무료 티어의 드립 편수는 하루 2편으로 고정한다(PRD FR-14).

**[알림] 권한 요청** — 인디케이터 없음

- OS 권한 다이얼로그 직전에 사전 안내(프리퍼미션) 화면을 노출한다 — "드립 도착을 알려드릴까요?"
- [나중에]를 누르면 **재고 팝업을 한 번 띄운다.**
  - 문구: "알림을 받는 분들이 평균 **N%** 이상 더 많이 듣고 있어요. 정말 설정하지 않으시겠어요?"
  - 버튼: [알림 받기] / [괜찮아요]
  - **[괜찮아요]는 [알림 받기]와 같은 비중으로 노출한다.** 회색 처리하거나 작게 만들지 않는다 — 거부를 어렵게 만드는 순간 다크패턴이 되고, 스토어 심사에서도 지적 대상이다
  - **이 팝업은 온보딩 전체에서 1회만 뜬다.** 팝업의 [괜찮아요]를 누르면 다시 묻지 않고 라이브러리로 진입한다
  - 팝업에서 [알림 받기]를 누르면 OS 권한 다이얼로그로 진행한다
  - **`N`은 임의로 채우지 않는다. 개발자가 출처 있는 통계를 찾아 그 값을 넣는다.** 자체 실측 데이터가 없는 상태로 수치를 단정하면 표시광고법상 실증 책임이 생기고, 실증을 못 하면 문구를 내려야 한다.
    - **찾은 출처는 문구 리소스와 이 문서에 함께 남긴다.** 코드 어딘가에만 적어두면 다음 사람이 수치를 고칠 때 근거를 처음부터 다시 찾게 되고, 대개는 그냥 감으로 고친다.
    - **끝내 출처를 확보하지 못하면 수치를 빼고 정성 문구로 대체한다** — "알림을 받으면 새 콘텐츠를 놓치지 않아요". 근거 없는 수치를 남겨두는 것보다 설득력이 약한 문구가 낫다.
    - 출시 후 자체 실측이 쌓이면 인용 통계를 실측값으로 교체한다.
- [나중에] → [괜찮아요] 경로에서는 **OS 다이얼로그를 띄우지 않는다**(OS 권한은 한 번 거부되면 재요청이 불가하므로 소진하지 않는다)
- 허용/거부 결과와 무관하게 라이브러리로 진입

| 3 | 정상(월간 표본 부족) | 두 번째 섹션 제목이 **"이런 주제는 어때요?"** 로 바뀌고 랜덤 3건이 같은 자리에 노출. 건수·레이아웃은 동일하고 **표본이 부족하다는 사실은 사용자에게 알리지 않는다**(운영 사정이라 사용자가 할 일이 없다) |

| 알림 | 재고 팝업 | "알림을 받는 분들이 평균 **N%** 이상 더 많이 듣고 있어요. 정말 설정하지 않으시겠어요?" + [알림 받기] / [괜찮아요] — **두 버튼 동등 비중, 1회만.** `N`은 개발자가 확보한 출처의 값을 넣는다(4장 [알림]) |

## 7. 예외 상황

- **1단계에서 주제를 고르다 앱을 강제 종료**: 서버 저장 전이므로 재실행 시 1단계부터. 로컬 임시 저장분을 복원해 선택 상태는 유지한다.
- **로컬 임시 저장분이 3개를 넘는 경우**(상한 도입 이전 버전에서 남은 값): 앞의 3개만 복원한다.
- **2단계 저장 후 종료**: `onboarding_step = pick`이므로 3단계부터 재개.
- **커리어를 건너뛴 사용자**: 재촉하지 않는다. 이후 입력·수정은 프로필에서 한다(`profile.md` 4.4).
- **주제 목록이 비어 있는 경우**(콘텐츠 풀 미구축): 온보딩을 진행할 수 없다. 이 경우 "준비 중입니다" 안내 후 라이브러리 진입을 막지 말고, 기본 주제 세트(하드코딩 폴백)를 노출한다.
- **3단계 추천이 0건으로 반환됨**: **정상 상태가 아니다.** 콘텐츠 풀이 없는 주제는 `is_visible = false`로 노출되지 않기 때문이다(3장). 발생 시 사용자에게는 3단계를 건너뛰되, **담은 것이 0건인 경로이므로 완료 대기 로딩을 거쳐 자동 드립을 받은 뒤 완료 화면으로 보낸다**(4장 [완료]). 동시에 **운영 알림을 발생시켜 `is_visible` 설정과 콘텐츠 풀을 점검하게 한다.** 사용자 화면에 "추천할 콘텐츠가 없어요" 상태를 두지 않는다 — 정상 경로가 아닌 것을 정상 화면으로 만들면 관리자가 문제를 인지하지 못한다.
- **관심 주제 추천 6건을 채우지 못하는 경우**(선택 주제의 재고 부족): 부족분을 월간 인기에서 끌어와 **총 9건은 유지한다.** 두 섹션의 비율(6:3)보다 전체 건수를 우선한다.
- **월간 인기 3건이 전부 이미 고른 주제와 겹치는 경우**: 중복을 뺀 다음 순위로 채운다. 그래도 모자라면 인기 섹션을 줄여서 노출한다(빈 카드를 만들지 않는다).
- **월간 재생 표본이 기준값 미만인 경우**(서비스 초기): 인기 순위 대신 **랜덤 3건**을 같은 자리에 배치하고 섹션 제목을 "이런 주제는 어때요?"로 바꾼다(4장 [3]). 표본이 적을 때의 상위 3건은 인기가 아니라 우연이라, 순위처럼 보여주면 추천 신뢰도만 잃는다.
- **표본도 부족하고 관심 주제 밖 후보 자체가 3건이 안 되는 경우**: 랜덤으로도 채울 수 없으므로 섹션을 줄여서 노출한다(빈 카드를 만들지 않는다). 관심 주제 추천 6건은 그대로 유지한다 — 확장용 섹션보다 사용자가 직접 고른 주제가 우선이다.
- **3단계에서 담기 API 일부 실패**: 성공한 건만 적립하고 실패 건은 토스트로 알린 뒤 진행을 막지 않는다(온보딩 이탈 방지 우선).
- **1건 이상 담은 경로에서 첫 드립 트리거 실패**: 완료 화면을 그대로 띄운다. 온보딩 완료 처리는 롤백하지 않고, 드립은 비동기 재시도 큐로 넘기며 라이브러리는 "콘텐츠를 준비하고 있어요" 상태로 노출한다. 담은 콘텐츠가 있어 라이브러리가 비지 않으므로 사용자를 대기시킬 이유가 없다.
- **0건 경로에서 자동 드립이 재시도까지 모두 실패**(또는 로딩 상한 15초 초과): 로딩 화면을 걷고 완료 화면으로 진행한다. **사용자를 로딩 화면에 남겨두지 않는다** — 서버에서는 이미 완료 처리된 계정이라, 앱만 멈춰 있으면 재실행 말고는 빠져나갈 방법이 없다. 편성은 서버 비동기 재시도 큐로 넘기고 **운영 알림을 발생시킨다.**
- **0건 경로인데 편성할 후보 자체가 없는 경우**(주제 고갈): **재시도 대상이 아니다.** 실패가 아니라 결과가 빈 것이므로 다시 호출해도 같은 결과가 나온다. 즉시 완료 화면으로 진행하고 인기 콘텐츠 대체 편성(`drip-scheduling.md` 7)에 맡기되, 그것도 비면 운영 알림을 발생시킨다.
- **자동 드립 로딩 중 앱 강제 종료**: 완료 요청은 이미 서버에서 처리됐으므로 재실행 시 `onboarding_completed == true`로 판정되어 **라이브러리로 바로 진입한다**(`splash.md` 4). 로딩·완료 화면은 다시 보여주지 않는다. 이 경로에서는 **알림 권한 사전 안내를 건너뛰게 되므로** 별도 대응이 필요하다 → 미결 사항 참조.
- **자동 드립 로딩 중 뒤로가기**: 무시한다. 3단계로 되돌리면 이미 완료 처리된 온보딩을 다시 진행하는 모순 상태가 된다.
- **이미 OS 알림 권한이 허용된 상태**(재설치 등): 알림 단계를 건너뛴다. **재고 팝업도 뜨지 않는다.**
- **재고 팝업을 본 뒤 뒤로가기**: 팝업만 닫고 사전 안내 화면에 머문다. 팝업 노출 이력은 소진된 것으로 처리해 다시 띄우지 않는다.
- **온보딩 도중 로그아웃·세션 만료**: 시작 화면으로 이동. 재로그인 시 저장된 `onboarding_step`부터 재개.
- **뒤로가기로 1단계에서 더 뒤로**: 온보딩 이탈 확인 팝업 없이 아무 동작 안 함(계정은 이미 생성됨). 이탈하려면 설정이 아니라 앱 종료뿐.

## 8. 완료 조건

- Given 신규 가입 직후 사용자 / When 관심 주제를 하나도 선택하지 않는다 / Then [다음] 버튼이 비활성 상태로 유지된다
- Given 관심 주제를 2개 선택했다 / When [다음]을 누른다 / Then 서버에 관심사가 저장되고 커리어 입력 단계로 이동한다
- Given 관심 주제를 3개 선택했다 / When 4번째 주제를 탭한다 / Then 선택되지 않고 **"3개까지 선택할 수 있어요"** 토스트가 노출된다
- Given 클라이언트를 우회해 주제 4개를 서버로 보낸다 / When 저장을 요청한다 / Then 서버가 상한을 검증해 거부한다
- Given 온보딩 1~3단계 / When 각 화면을 본다 / Then 상단 인디케이터가 **`1/3` · `2/3` · `3/3`** 으로 표시된다
- Given 3단계를 마쳤다 / When 완료 화면과 알림 화면으로 넘어간다 / Then **인디케이터가 노출되지 않는다**
- Given 커리어 입력 단계 / When [건너뛰기]를 누른다 / Then 커리어 정보 없이 다음 단계로 이동하고, 이후 드립 편성이 정상 동작한다
- Given 커리어를 건너뛴 사용자 / When 온보딩 완료 후 프로필에 진입한다 / Then 커리어를 입력·수정할 수 있다
- Given 관심 주제를 선택하고 3단계에 진입한다 / When 화면을 본다 / Then **관심 주제 추천 6건과 이번 달 인기 3건이 섹션으로 구분되어** 총 9건이 노출된다
- Given 3단계의 이번 달 인기 3건 / When 각 콘텐츠의 주제를 확인한다 / Then 1단계에서 고른 주제 밖의 콘텐츠가 포함되어 있다
- Given 직전 확정 월의 재생 표본이 기준값 미만이다 / When 3단계에 진입한다 / Then 두 번째 섹션 제목이 **"이런 주제는 어때요?"** 로 바뀌고 랜덤 3건이 노출되며 총 9건은 유지된다
- Given 표본 부족으로 랜덤 3건이 노출됐다 / When 각 콘텐츠를 확인한다 / Then 1단계에서 고른 주제 밖의 발행 상태 콘텐츠만 포함되고 앞의 6건과 중복되지 않는다
- Given 표본 부족으로 랜덤 3건이 노출됐다 / When 뒤로 갔다가 3단계로 되돌아온다 / Then **같은 3건이 그대로 노출된다**
- Given 추천 콘텐츠 단계에서 아무것도 담지 않았다 / When [건너뛰기]를 누른다 / Then 자동 드립 트리거가 작동하고 **로딩 화면이 노출되며 완료 화면은 아직 뜨지 않는다**
- Given 0건 경로의 자동 드립 적립이 성공했다 / When 편성이 끝난다 / Then 로딩 화면이 사라지고 완료 화면이 노출되며, 라이브러리가 비어 있지 않다
- Given 0건 경로에서 자동 드립 트리거가 실패한다 / When 재시도가 수행된다 / Then **최대 2회 자동 재시도(1초 → 3초 백오프)** 가 이뤄지는 동안 로딩 화면이 유지되고 에러 화면은 노출되지 않는다
- Given 0건 경로에서 재시도가 모두 실패했다 / When 로딩 상한을 넘긴다 / Then **로딩 화면에 갇히지 않고 완료 화면으로 진행**하며, 라이브러리에 "콘텐츠를 준비하고 있어요" 배너가 노출되고 운영 알림이 발생한다
- Given 추천 콘텐츠를 1건 이상 담았다 / When [담기]를 누른다 / Then 로딩 화면 없이 완료 화면이 곧바로 노출된다
- Given 추천 콘텐츠 3건을 담았다 / When 온보딩을 완료한다 / Then 첫 드립에는 방금 담은 3건이 중복 적립되지 않는다
- Given 커리어 단계까지 마치고 앱을 종료한 사용자 / When 앱을 재실행한다 / Then 추천 콘텐츠 선택 단계부터 재개된다
- Given 알림 사전 안내에서 [나중에]를 누른다 / When 화면을 본다 / Then **재고 팝업이 1회 노출**되고 [알림 받기]/[괜찮아요] 두 선택지가 동등한 비중으로 표시된다
- Given 재고 팝업에서 [괜찮아요]를 누른다 / When 다음으로 넘어간다 / Then OS 권한 다이얼로그가 뜨지 않고 라이브러리로 진입하며, 팝업은 다시 뜨지 않는다
- Given 재고 팝업에서 [알림 받기]를 누른다 / When 다음으로 넘어간다 / Then OS 권한 다이얼로그가 노출된다
- Given 재고 팝업 문구 / When 배포 빌드를 확인한다 / Then 수치 자리에 **출처가 확인된 값**이 들어가 있거나, 수치 없는 정성 문구로 대체되어 있다(임의의 수치가 남아 있지 않다)
- Given 온보딩을 완료했다 / When 뒤로가기를 누른다 / Then 온보딩 화면으로 돌아가지 않는다

## 미결 사항

**확정된 것**

| 항목 | 결정 |
|---|---|
| 무료 티어 초기 적립 | **허용.** 무료 티어도 온보딩 초기 적립과 일일 드립(하루 2편)을 모두 받는다 |
| 주제 선택 상한 | **최대 3개.** 드립 편성이 분산되는 것을 막는다. 서버도 함께 검증한다. **`interest-management.md`도 같은 상한을 쓴다** |
| 커리어 수정 경로 | **프로필 화면**(`profile.md` 4.4). 온보딩에서 건너뛰어도 재촉하지 않는다 |
| 추천 0건 처리 | **정상 상태로 두지 않는다.** 콘텐츠 풀이 없는 주제는 관리자가 `is_visible = false`로 내려 애초에 선택지에서 뺀다(`admin.md`) |
| 3단계 추천 구성 | **관심 주제 6건 + 이번 달 인기 3건 = 9건.** 인기 3건은 고른 주제 밖에서 뽑아 관심사를 넓힌다 |
| 인디케이터 단계 수 | **3개.** 완료 대기·완료·알림은 모두 인디케이터 밖에 둔다 |
| 알림 [나중에] 처리 | **재고 팝업 1회.** 두 선택지를 동등한 비중으로 노출한다 |
| 재고 팝업의 수치 근거 | **개발자가 출처 있는 통계를 찾아 입력한다.** 출처는 문구 리소스와 이 문서에 함께 남기고, 끝내 못 찾으면 수치를 빼고 정성 문구로 대체한다. 출시 후에는 자체 실측값으로 교체한다 |
| 월간 인기 표본 부족 시 | **랜덤 3건을 같은 자리에 배치한다.** 섹션 제목은 "이런 주제는 어때요?"로 바꾸고, 후보 필터(발행·관심 주제 밖·6건과 중복 제외)는 그대로 적용한다 |
| 3단계 0건 선택 시 | **자동 드립 트리거가 작동하고, 편성이 끝날 때까지 로딩 화면을 유지한 뒤 완료 화면을 띄운다.** 실패 시 자동 재시도하되 사용자를 로딩 화면에 가두지 않는다 |
| 자동 드립 재시도 정책 | **공통 규칙을 그대로 따른다**(`common-error-handling.md` 4.2) — 최대 2회, 백오프 1초 → 3초. 소진 시 완료 화면으로 진행 + 비동기 재시도 큐 + 운영 알림 |

**남은 것**

- **월간 인기 표본 기준값(재생 30건) 확정** — 랜덤으로 넘어가는 문턱이다. 너무 낮으면 우연한 순위를 인기로 내보내고, 너무 높으면 실제로 인기 데이터가 쌓인 뒤에도 계속 랜덤이 나간다. **콘텐츠 풀 규모가 정해지면 첫 달 실데이터로 조정한다.**
- **자동 드립 대기의 재시도 횟수(2회)·백오프(1초 → 3초)·로딩 상한(15초) 확정** — 공통 규칙에서 가져온 기본값이고, 온보딩 완료 직전이라 이탈 비용이 가장 큰 지점이다. 실제 편성 소요 시간을 측정한 뒤 상한을 조정해야 한다. **바꾸더라도 "재시도가 끝나면 반드시 완료 화면으로 진행한다"는 규칙은 유지한다.**
- **시리즈 첫 편 규칙과 9건 유지의 우선순위** — 4 [3]의 "시리즈물은 첫 편만 후보에 올린다"는 **후보 풀을 줄인다.** 초기 콘텐츠 풀이 작은 상황(PRD 8.1)에서 시리즈 비중이 높아지면 9건을 채우기 어려워질 수 있다. 지금은 "총 9건 우선"(7장)이 두 번째 섹션에서 끌어와 메우고 있지만, **시리즈 비중이 커지면 둘 중 무엇을 우선할지 다시 정해야 한다.**
- **랜덤 폴백 섹션의 제목 문구** — "이런 주제는 어때요?"는 잠정안이다. 인기 순위가 아님을 사실대로 말하면서도 사용자에게 "덜 좋은 추천"으로 읽히지 않아야 한다.
- **자동 드립 로딩 중 앱을 종료한 사용자의 알림 권한 요청 경로** — 완료 처리가 이미 끝난 상태라 재실행 시 라이브러리로 직행하고, 알림 사전 안내를 영영 보지 못한다. 라이브러리 최초 진입 시 1회 노출로 이월할지 결정 필요(`notification.md` 4.1과 함께 정해야 한다). **OS 권한은 사후 재요청이 어려워 그냥 넘기면 회수할 수 없는 손실이다.**
