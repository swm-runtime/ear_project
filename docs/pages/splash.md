# 스플래시 · 앱 진입 분기 기능 명세서

> 연결 PRD: FR-35, FR-36 / 사용자흐름 5.1

## 1. 목적 & 연결

앱 실행 시 최소 지원 버전과 인증·온보딩 상태를 판정하여 올바른 첫 화면으로 분기시킨다. 사용자가 "앱을 열면 들을 게 준비되어 있는" 경험(PRD 1.3)의 진입점이며, 잘못된 버전·만료된 세션이 이후 화면으로 새어나가지 않게 막는 관문 역할을 한다.

- PRD FR-35 (앱 실행 시 온보딩 완료 여부로 진입 분기, 버전 체크, 강제 업데이트)
- PRD FR-36 (네트워크 오류 공통 처리·재시도)
- PRD 사용자흐름 5.1 (스플래시 → 시작 화면 → 소셜 로그인 → …)

## 2. 진입 조건

- 앱을 콜드 스타트(프로세스 신규 생성)로 실행할 때
- 백그라운드에서 일정 시간(기준값: 30분) 이상 머문 뒤 포그라운드로 복귀할 때 → 버전 체크·세션 검증만 재수행하고, 화면 분기는 하지 않음(현재 화면 유지)
- 딥링크·푸시 탭으로 진입한 경우에도 스플래시를 먼저 통과한 뒤 목적지로 이동

## 3. 입력값

| 값 | 출처 | 필수 |
|---|---|---|
| app_version | 클라이언트 빌드 정보 | 필수 |
| platform (ios/android) | 클라이언트 | 필수 |
| access_token / refresh_token | 로컬 보안 저장소 | 선택(미로그인 시 없음) |
| deep_link_target | 인텐트·푸시 페이로드 | 선택 |

서버 응답으로 받는 값:

| 값 | 설명 |
|---|---|
| min_supported_version | 이 버전 미만은 강제 업데이트 |
| latest_version | 권장 업데이트 안내 기준 |
| notice | 점검·공지 배너(선택) |
| user.onboarding_completed | 온보딩 완료 여부 |
| user.tier | 구독 티어 |

## 4. 처리 로직

순서대로 판정하며, 앞 단계에서 걸리면 뒤 단계는 실행하지 않는다.

1. **버전 체크** — 서버에서 `min_supported_version` 조회
   - `app_version < min_supported_version` → 강제 업데이트 화면(닫기 불가, 스토어 이동만 가능). **이후 로직 진행 안 함**
   - `min_supported_version <= app_version < latest_version` → 권장 업데이트 안내(닫기 가능), 닫으면 다음 단계 진행
   - 점검 중(`notice.type == maintenance`) → 점검 안내 화면, 이후 로직 진행 안 함
2. **인증 상태 판정**
   - 토큰 없음 → **시작 화면(서비스 소개)** 으로 이동
   - access_token 만료 → refresh_token으로 갱신 시도
     - 갱신 성공 → 3번으로
     - 갱신 실패(만료·폐기·탈퇴 계정) → 로컬 토큰 삭제 후 **시작 화면**으로 이동
3. **온보딩 완료 여부 판정**
   - `onboarding_completed == false` → **온보딩 첫 단계(관심 주제 선택)** 로 이동. 중단 지점부터 재개한다(온보딩 명세 참조)
   - `onboarding_completed == true` → **라이브러리(메인)** 로 이동
4. **딥링크 처리** — 3번에서 도착지가 결정된 뒤, `deep_link_target`이 있으면 해당 화면을 스택 위에 얹는다. 단 온보딩 미완료 사용자는 딥링크를 **보류**했다가 온보딩 완료 후 이동한다.
5. **최소 노출 시간** — 스플래시는 최소 0.8초 노출한다(깜빡임 방지). 판정이 더 빨리 끝나도 유지.

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 판정 중 | 스플래시(로고). 1.5초 이상 지연 시 로딩 인디케이터 추가 노출 |
| 강제 업데이트 | 전면 안내 + [스토어로 이동] 단일 버튼. 뒤로가기·닫기 불가 |
| 권장 업데이트 | 바텀시트 + [업데이트] / [나중에] |
| 점검 중 | 전면 안내(점검 사유·예상 종료 시각) + [다시 시도] |
| 네트워크 오류 | 전면 안내 + [다시 시도]. 3회 연속 실패 시 "잠시 후 다시 시도해주세요" 문구로 전환 |
| 판정 완료 | 시작 화면 / 온보딩 / 라이브러리 중 하나로 전환(스플래시는 스택에서 제거) |

## 6. 데이터 모델

```
AppConfig {
  min_supported_version: string
  latest_version: string
  notice: { type: none|info|maintenance, title, body, until } | null
}

Session {
  access_token: string        // 보안 저장소
  refresh_token: string       // 보안 저장소
  expires_at: datetime
}

User {
  user_id: string
  onboarding_completed: boolean
  onboarding_step: enum(topic|career|pick|done)   // 중단 지점 재개용
  tier: enum(free|light|daily|pro)
}
```

- 로컬 저장: 토큰(암호화 저장소), 마지막 진입 화면, 마지막 권장 업데이트 안내 노출일(하루 1회 제한용)

## 7. 예외 상황

- **버전 체크 API 실패**: 실패했다고 앱을 막지 않는다. 캐시된 `min_supported_version`이 있으면 그걸로 판정하고, 없으면 통과시킨 뒤 다음 단계 진행(가용성 우선). 단 점검 응답은 캐시하지 않는다.
- **오프라인 실행**: 네트워크 없음 → 온보딩 완료 사용자는 캐시된 라이브러리로 진입 허용, 미완료 사용자는 네트워크 오류 화면(온보딩은 서버 저장이 필요하므로).
- **토큰 갱신 요청이 동시에 여러 번 발생**: 갱신 요청은 단일 인플라이트로 묶고 나머지는 결과를 공유한다.
- **탈퇴한 계정의 토큰이 남아 있는 경우**: 갱신 실패로 처리 → 로컬 데이터 전량 삭제 후 시작 화면.
- **강제 업데이트 화면에서 스토어에 해당 버전이 아직 없는 경우**: 스토어 페이지로만 이동시키고 앱은 계속 차단 상태 유지.
- **스플래시 도중 앱을 백그라운드로 보냈다가 복귀**: 판정을 처음부터 다시 수행한다(중간 상태 신뢰 안 함).
- **기기 시각이 크게 어긋난 경우**: 토큰 만료 판정은 로컬 시각이 아니라 서버 401 응답을 기준으로 한다.

## 8. 완료 조건

- Given 앱 버전이 최소 지원 버전보다 낮다 / When 앱을 실행한다 / Then 강제 업데이트 화면이 뜨고 뒤로가기로 빠져나갈 수 없다
- Given 로그인한 적 없는 사용자 / When 앱을 실행한다 / Then 시작 화면(서비스 소개)이 노출된다
- Given 로그인했으나 온보딩을 관심 주제 선택 단계에서 중단한 사용자 / When 앱을 재실행한다 / Then 관심 주제 선택 단계부터 재개된다
- Given 온보딩을 완료한 사용자 / When 앱을 실행한다 / Then 라이브러리 화면으로 바로 진입한다
- Given 버전 체크 API가 실패한다 / When 앱을 실행한다 / Then 앱이 차단되지 않고 정상 진입 분기가 수행된다
- Given 리프레시 토큰이 만료된 사용자 / When 앱을 실행한다 / Then 로컬 토큰이 삭제되고 시작 화면으로 이동한다
