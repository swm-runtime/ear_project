# 팟캐스트 플레이어 기능 명세서

> 연결 PRD: FR-23, FR-24, FR-25, FR-12, FR-15, FR-33, FR-34 / 비기능(재생 즉시성) / 사용자흐름 5.2

## 1. 목적 & 연결

콘텐츠를 실제로 듣는 화면. 통근 맥락(눈·손 비가용 — PRD 3.1)을 전제로, 화면을 보지 않아도 조작 가능해야 하며 백그라운드·잠금화면 재생이 기본이다.

- PRD FR-23 (P0) 즉시 재생, 재생/일시정지, 구간 이동, 배속 조절
- PRD FR-24 (P0) 이어듣기 — 마지막 재생 콘텐츠·위치를 앱 재실행 후에도 유지
- PRD FR-25 (P1) 스크립트 열람(구간 탭 이동), 수면 타이머
- PRD FR-12 (P0) 원저자·출처 고지, 원문 연결 정보
- PRD FR-15 (P0) 소비 신호(완청·스킵) 수집
- PRD FR-33 (P0) 무단 재배포·다운로드 방지 접근 통제
- PRD 7 비기능 — **재생 버튼 탭 후 2초 내 재생 시작**

## 2. 진입 조건

- 라이브러리 아이템 탭 (**이어듣기 카드는 없다** — `library.md` 4.1)
- 탐색 피드 행 탭
- 하단 미니플레이어 탭(전체 화면으로 확대). 앱 실행 직후의 이어듣기도 이 경로다(`library.md` 4.2)
- 푸시 알림 탭(해당 콘텐츠로 진입)
- **선행 조건**: 무료 재생 한도 판정 통과(페이월 명세). 차단 시 플레이어를 열지 않는다.
- **선행 조건**: 차감이 발생하는 재생이면 **재생 확인 팝업에서 [재생하기]를 누른 뒤**에 열린다(`library.md` 4.3). 팝업은 재생을 시작시킨 화면이 띄우며(라이브러리·탐색·딥링크 처리 — `paywall.md` 4.2) 플레이어는 통과한 요청만 받는다.

## 3. 입력값

| 값 | 설명 | 필수 |
|---|---|---|
| content_id | 재생 대상 | 필수 |
| start_position_sec | 시작 위치. 미지정 시 저장된 `playback_progresses.position_sec` | 선택 |
| autoplay | 진입 즉시 재생 여부. **기본 true. 단 미니플레이어 복원(4.3)·푸시 딥링크 진입은 false** — FR-24 자동 재생 금지 | 선택 |

**사용자 조작**: 재생/일시정지, 15초 뒤로 / 30초 앞으로, 시크바 드래그, 배속 선택, 스크립트 열기, 수면 타이머 설정, 더보기(공유·원문 보기·라이브러리에서 삭제)

## 4. 처리 로직

### 4.1 재생 시작

1. 플레이어 화면 진입과 동시에 콘텐츠 메타 + **재생 URL(단기 서명 URL)** 요청
2. 오프라인 저장분이 있으면 로컬 파일을 우선 사용한다(오프라인 저장 명세) *(P1 이연 — FR-26)*
3. 오디오 준비되는 즉시 `start_position_sec`부터 재생
   - **모든 콘텐츠는 사전 변환 완료 상태이므로 생성 대기가 없다**(PRD 1.3, 7). 클라이언트에 "생성 중" 상태는 존재하지 않는다
   - 목표: 탭 후 2초 내 재생 시작. 버퍼링이 2초를 넘으면 로딩 인디케이터 노출
4. 재생이 실제로 시작된 시점에
   - `library_items.status`: `unplayed` → `in_progress`
   - **무료 티어 재생 카운트 +1** — `play_records`에 오늘 서비스 날짜(04시 경계) 기준 행을 upsert (페이월 명세 4.3)
   - `user_signals(action = play)` 기록
   - `drip_excluded_contents(reason = played)` 적재 — 재생한 콘텐츠는 드립 후보에서 제외된다(FR-16)

### 4.2 재생 컨트롤

| 컨트롤 | 동작 |
|---|---|
| 재생/일시정지 | 토글. 일시정지 시 현재 위치 저장 |
| 15초 뒤로 | `max(0, position - 15)` |
| 30초 앞으로 | `min(duration, position + 30)`. 끝에 도달하면 완료 처리 |
| 시크바 | 드래그 중에는 위치 라벨만 갱신, 손을 뗀 시점에 seek |
| 배속 | 0.8 / 1.0 / 1.2 / 1.5 / 2.0. **선택값은 사용자 전역 설정으로 저장**되어 다음 콘텐츠에도 적용 |
| 백그라운드 | 앱을 내려도 재생 유지. 잠금화면·알림 센터 컨트롤(재생/정지/±초) 제공 |
| 이어폰 조작 | 재생/정지, 더블탭 다음 트랙은 지원하지 않음(플레이리스트 없음) |
| 오디오 포커스 | 전화·타 앱 재생 시 자동 일시정지, 종료 후 자동 재개하지 않음(사용자 명시적 재개) |

### 4.3 재생 위치 저장 (FR-24)

- 저장 시점: 5초 주기 / 일시정지 / 화면 이탈 / 앱 백그라운드 진입 / 재생 종료
- 저장 대상은 `playback_progresses`의 `position_sec`과 `max_reached_sec` 두 값이다
- 로컬에 먼저 쓰고 서버에 비동기 동기화(실패 시 큐에 적재, 다음 기회에 재전송)
- 앱 재실행 시 마지막 재생 콘텐츠와 위치를 복원해 **미니플레이어를 일시정지 상태로 노출**한다(자동 재생하지 않음)

### 4.4 완청·스킵 신호 (FR-15)

- **완청**: 재생 위치가 길이의 90% 이상 도달 → `status = completed`, `UserSignal(action = complete)`
- **스킵**: 재생 시작 후 20% 미만 지점에서 재생을 중단하고 다른 콘텐츠로 이동하거나 이탈 → `UserSignal(action = skip)`
- 배속·구간 이동으로 건너뛴 구간은 "들은 것"으로 계산하지 않고, **최대 도달 위치(`max_reached_sec`)** 를 별도로 기록해 완청 판정에 사용한다(2배속으로 끝까지 재생한 것은 완청으로 인정, 시크로 끝까지 점프한 것은 완청으로 인정하지 않음)
- **`seek`·`rate_change`는 신호로 기록하지 않는다.** 추천 스코어링에 쓰이지 않으면서 재생 1회당 수십 건씩 쌓인다. 필요하면 구조화 로그로만 남긴다
- **수동 완료 표시 기능은 없다.** 상태는 실제 재생 결과로만 바뀐다

### 4.4-1 실제 청취 시간 기록 (FR-34, P1 — 단 **원천 로그 수집은 MVP부터 시작**한다)

- FR-34(리포팅)는 P1이지만 **이 절의 원천 로그 수집은 MVP부터 시작한다.** 나중에 소급 집계가 불가능하다(`partner-control.md` 미결 참조)
- 재생 종료(일시정지·이탈·완청·백그라운드 진입) 시점마다 **그 구간에서 재생기가 실제로 소리를 낸 시간**을 `play_records.listened_sec`에 더한다
- 도달 위치가 아니라 실제 경과 시간이다. 10분짜리를 2배속으로 끝까지 들으면 `max_reached_sec = 600`이지만 `listened_sec ≈ 300`이고, 시크로 건너뛴 구간은 포함되지 않는다
- 하루·콘텐츠당 1행이므로 같은 날 여러 번 들으면 같은 행에 누적된다. 날짜 경계를 넘겨 재생하면 **재생 시작 시점의 서비스 날짜** 행에 누적한다
- 이 값이 파트너 정산의 재생 점유율 근거가 된다(`partner-control.md` 4.6)

### 4.5 출처 고지 (FR-12)

- 오디오 자체에 시작·종료 멘트로 출처·저자가 포함된다(제작 단계 책임 — MVP는 업로드 전 수작업)
- 플레이어 화면에도 **저자·출처를 상시 노출**하고, `source_url`이 있으면 [원문 보기] 버튼을 제공한다 → 인앱 브라우저로 열기(파트너 유입 경로 — PRD 8.3 리스크 대응)
- **[원문 보기] 탭 시 원문 유입 클릭 이벤트를 서버에 기록한다** — 적재 테이블은 **`source_link_clicks`**(`domain.md` 6.6 — 확정 2026-08-06. `user_signals`는 스코어링 전용이라 쓰지 않는다). `content_stats.source_link_click_count`의 원천이다(`partner-control.md` 4.6)

### 4.6 스크립트 (FR-25, P1)

- 하단 시트 또는 전체 화면으로 스크립트 노출
- 현재 재생 구간을 하이라이트하고 자동 스크롤
- 구간 탭 → 해당 위치로 seek
- 스크립트는 **텍스트 복사·선택을 차단**한다(FR-33 재배포 방지)

### 4.7 수면 타이머 (FR-25, P1)

- 옵션: 5분 / 10분 / 15분 / 30분 / **이 에피소드 종료 시** / 해제
- 만료 시 페이드아웃 후 일시정지. 앱을 종료하지는 않는다
- 남은 시간을 플레이어에 표시

### 4.8 재배포 방지 (FR-33)

- 오디오 URL은 **짧은 만료 시간의 서명 URL**로 발급하고, 사용자·기기 단위로 발급 이력(`audio_access_logs`)을 남긴다. **서명 URL 자체는 저장하지 않는다** — DB에 남기면 그것이 곧 유출 경로가 된다
- 원본 파일 경로를 클라이언트에 노출하지 않는다
- 안드로이드/iOS 미디어 캐시는 앱 전용 저장소에 두고 외부 접근을 차단한다

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 진입 직후 | 메타 정보 즉시 표시 + 재생 버튼 로딩 |
| 버퍼링(2초 초과) | 재생 버튼 자리에 인디케이터 |
| 재생 중 | 아트워크 / 제목 / 저자·출처 / 시크바·시간 / 컨트롤 / 배속·타이머·스크립트 버튼 |
| 일시정지 | 동일 레이아웃, 버튼만 전환 |
| 완료 | 재생 종료. 화면 자동 이탈하지 않음. "다시 듣기" 버튼으로 전환 |
| 미니플레이어 | 라이브러리·탐색 하단 고정. 썸네일·제목·재생 버튼·진행 바. 탭하면 전체 화면 확대, 스와이프로 종료 |
| 로드 실패 | "재생할 수 없어요" + [다시 시도] |
| 회수된 콘텐츠 | "제공이 종료된 콘텐츠예요" + [닫기]. 라이브러리에서도 제거 |
| 네트워크 끊김(재생 중) | 버퍼 소진까지 재생 유지 → 소진 시 일시정지 + "네트워크를 확인해주세요" |
| 스크립트 열림 | 하단 시트, 현재 구간 하이라이트 |
| 타이머 설정됨 | 상단에 남은 시간 표시 |

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `playback_progresses` — `position_sec` · `max_reached_sec` | 6.2 |
| `play_records` — 페이월 카운트 + **실제 청취 시간(`listened_sec`)** | 6.3 |
| `user_signals` — 플레이어가 기록하는 값은 `play` · `complete` · `skip` · `replay` (전체 action enum은 `domain.md` 6.4 — `save`·`unsave`·`delete`는 탐색·라이브러리가 기록) | 6.4 |
| `audio_access_logs` — 서명 URL **발급 사실만** 기록(URL 자체는 저장 안 함) | 6.5 |
| `content_scripts` | 5.3 |
| `user_settings` — `default_playback_rate` 등 전역 재생 설정 | 3.5 |

- `PlaybackSession`은 폐기됐다. 재생 위치·최대 도달 위치는 `playback_progresses` 하나가 갖는다(domain.md 14장).
- `seek` · `rate_change`는 신호 테이블에 넣지 않는다. 추천 스코어링에 쓰이지 않는다.

## 7. 예외 상황

- **재생 중 서명 URL 만료**: 재생이 끊기기 전에 백그라운드에서 URL을 갱신한다. 갱신 실패 시 일시정지 + 재시도 안내.
- **재생 도중 전화 수신**: 오디오 포커스 상실 → 일시정지. 통화 종료 후 자동 재개하지 않는다.
- **블루투스 이어폰 연결 해제**: 즉시 일시정지(스피커로 갑자기 재생되는 것 방지).
- **앱을 강제 종료했을 때의 위치**: 마지막 5초 주기 저장 값까지만 보존된다. 최대 5초 손실 허용.
- **여러 기기에서 동시 재생**: 차단하지 않는다. 위치는 last-write-wins.
- **재생 위치가 콘텐츠 길이를 초과**(콘텐츠 재발행으로 길이 변경): 위치를 0으로 리셋하고 처음부터 재생.
- **콘텐츠가 재발행되어 오디오가 교체됨**: 재발행은 `content_id`를 유지한 채 `content_version`만 올린다. 클라이언트는 버전이 달라지면 저장된 재생 위치와 오프라인 파일을 폐기한다.
- **수면 타이머 만료와 완청 시점이 겹침**: 완청 처리를 우선한다.
- **2배속으로 끝까지 재생**: 완청으로 인정한다.
- **시크바로 90% 지점까지 점프**: `max_reached_sec`이 연속적으로 도달하지 않았으므로 완청으로 인정하지 않는다.
- **스크립트 데이터 없음**(P1 미구현 또는 생성 실패): 스크립트 버튼을 노출하지 않는다.
- **오프라인 저장분 파일 손상** *(P1)*: 로컬 재생 실패 → 온라인 스트리밍으로 폴백하고, 저장분은 삭제 후 재다운로드를 안내한다.

## 8. 완료 조건

- Given 라이브러리에서 콘텐츠를 탭한다 / When 정상 네트워크 상태다 / Then 2초 내에 재생이 시작된다
- Given 콘텐츠를 5분 지점까지 듣고 앱을 완전히 종료했다 / When 앱을 다시 실행한다 / Then 미니플레이어가 해당 콘텐츠를 5분 지점·일시정지 상태로 복원한다
- Given 재생 중이다 / When 앱을 백그라운드로 보낸다 / Then 재생이 계속되고 잠금화면에서 일시정지·구간 이동이 가능하다
- Given 배속을 1.5로 바꿨다 / When 다른 콘텐츠를 재생한다 / Then 배속 1.5가 그대로 적용된다
- Given 콘텐츠를 2배속으로 끝까지 재생했다 / When 재생이 종료된다 / Then 완청으로 기록된다
- Given 시크바를 끌어 90% 지점으로 점프한 뒤 재생을 종료한다 / When 상태를 확인한다 / Then 완청으로 기록되지 않는다
- Given 재생 시작 후 10% 지점에서 뒤로 나간다 / When 신호를 확인한다 / Then 스킵 신호가 기록된다
- Given 수면 타이머를 10분으로 설정했다 / When 10분이 지난다 / Then 페이드아웃 후 일시정지되고 앱은 종료되지 않는다
- Given 스크립트를 열고 특정 문단을 탭한다 / When 탭한다 / Then 해당 구간으로 재생 위치가 이동한다
- Given 재생 중 네트워크가 끊긴다 / When 버퍼가 소진된다 / Then 일시정지되고 네트워크 확인 안내가 노출된다
- Given 파트너가 회수한 콘텐츠를 재생 시도한다 / When 재생 URL을 요청한다 / Then 403이 반환되고 제공 종료 안내가 노출된다

## 미결 사항

- 배속 옵션 범위(0.8~2.0) 및 기본값 확정
- 완청 판정 90% / 스킵 판정 20% 임계값을 PRD 10 지표 정의와 정합화
- 잠금화면 컨트롤의 ±초 값(15/30) 확정
- 연속 재생(다음 콘텐츠 자동 재생) 도입 여부 — 현재 비범위이나 통근 맥락에서 요구가 나올 가능성 있음
