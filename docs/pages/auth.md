# 소셜 로그인 · 계정 기능 명세서

> 연결 PRD: FR-01, FR-02 / 사용자흐름 5.1

## 1. 목적 & 연결

카카오·구글·네이버 소셜 로그인만으로 가입과 인증을 처리한다. 자체 아이디/비밀번호는 만들지 않는다. 로그아웃·회원 탈퇴도 이 기능에 포함된다.

- PRD FR-01 (P0) 소셜 로그인으로 가입·인증 — 카카오·구글·네이버
- PRD FR-02 (P0) 로그아웃·회원 탈퇴, 탈퇴 시 사용자 데이터 처리
- PRD 7 비기능 (소셜 로그인 기반 인증, 개인정보보호법 준수)

## 2. 진입 조건

- **로그인**: 시작 화면(서비스 소개)에서 [시작하기] 또는 제공자 버튼을 탭할 때
- **재인증**: 토큰 갱신 실패로 세션이 끊겨 시작 화면으로 돌아온 때
- **로그아웃**: 설정 > 계정 > 로그아웃
- **탈퇴**: 설정 > 계정 > 회원 탈퇴

## 3. 입력값

**로그인**

| 값 | 설명 | 필수 |
|---|---|---|
| provider | kakao / google / naver | 필수 |
| provider_token | 제공자 SDK가 반환한 인증 코드 또는 액세스 토큰 | 필수 |
| device_id | 기기 식별자(푸시 토큰 매핑용) | 필수 |
| agreed_terms | 이용약관 동의 + 약관 버전 | 필수(신규 가입 시) |
| agreed_privacy | 개인정보 처리방침 동의 + 방침 버전 | 필수(신규 가입 시) |
| agreed_marketing | 마케팅 수신 동의 | 선택 |

- 동의 3종은 **개정 시점이 서로 다르므로 각각 별개로 기록한다**(`consents.consent_type`). 마케팅 동의만 껐다고 약관 동의 이력이 함께 갱신되면 안 된다.

**탈퇴**

| 값 | 설명 | 필수 |
|---|---|---|
| reason_code | 탈퇴 사유(선택형) | 선택 |
| reason_text | 자유 입력 | 선택 |
| confirm | 안내 확인 체크 | 필수 |

## 4. 처리 로직

### 4.1 로그인·가입

1. 사용자가 제공자 버튼 탭 → 해당 SDK 인증 플로우 실행(앱 전환 또는 웹뷰)
2. 제공자 인증 성공 → `provider_token`을 서버로 전달
3. 서버가 제공자에게 토큰 검증 및 프로필(고유 ID, 이메일, 닉네임) 조회
4. `provider + provider_user_id` 조합으로 기존 계정 조회
   - **기존 계정 있음** → 로그인 처리. `onboarding_completed`에 따라 라이브러리 또는 온보딩으로 분기
   - **기존 계정 없음** → 약관 동의 화면 노출 → 동의 완료 시 계정 생성 → **온보딩 첫 단계**로 이동
5. 서버는 access_token(단기) + refresh_token(장기)을 발급, 클라이언트는 보안 저장소에 저장
6. **동일 이메일 다른 제공자**: 별개 계정으로 처리한다(계정 통합·연동은 MVP 비범위). 단 로그인 화면에서 "이전에 OO로 가입한 이력이 있어요" 안내는 표시하지 않는다 — 개인정보 노출 우려.

### 4.2 로그아웃

1. 확인 팝업 노출
2. 서버에 refresh_token 폐기 요청 → 실패해도 진행
3. 로컬 토큰·캐시(라이브러리 캐시, 재생 위치, 오프라인 저장분) 삭제
4. 푸시 토큰 등록 해제
5. 시작 화면으로 이동(스택 전체 초기화)

### 4.3 회원 탈퇴

1. 탈퇴 안내 화면 — 삭제되는 데이터, 구독 상태, 재가입 제한을 명시
2. **구독 활성 상태 확인**
   - 활성 구독이 있으면 "스토어에서 구독 해지를 먼저 진행해야 결제가 중단된다"는 안내를 노출한다(스토어 구독은 앱 탈퇴로 자동 해지되지 않음)
   - **구독 만료에 동의해야만 탈퇴를 진행할 수 있다.** 동의 체크 없이는 [탈퇴하기]를 활성화하지 않는다
3. 사유 입력(선택) → 최종 확인 체크 → [탈퇴하기]
4. 서버 처리 — **이관과 파기를 하나의 트랜잭션에서 수행한다** (상세: `domain.md` 12.3)
   - **즉시 파기**: 라이브러리·관심사·커리어·재생 위치·재생 기록·소비 신호·설정·기기 토큰·세션·알림 로그·드립 제외 목록
   - **아카이브 후 파기(5년)**: 계정 정보 → `archived_users`, 동의 이력 → `archived_consents`, 구독 이력 → `archived_subscriptions`
     - 보존 범위는 **거래 주체 식별에 필요한 최소치**다 — 전자우편주소·제공자 계정 ID·구독 이력. 닉네임·커리어·관심사는 보존하지 않는다
     - 운영 테이블과 **물리적으로 분리된 스키마**에 저장한다(개인정보보호법 제21조 제3항, 전자상거래법 시행령 제6조의 별도 보존 의무)
   - `users` 행은 아카이브 이관 후 **삭제한다.** `status = withdrawn`으로 남겨두지 않는다
5. 로컬 데이터 전량 삭제 → 시작 화면으로 이동
6. 동일 소셜 계정으로 재가입은 즉시 허용하되, 신규 계정으로 취급한다(이전 데이터 복구 불가)

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 시작 화면 | 서비스 소개 + 카카오/구글/네이버 버튼 3개 |
| 제공자 인증 중 | 외부 앱·웹뷰 전환. 복귀까지 로딩 오버레이 |
| 사용자가 인증 취소 | 시작 화면으로 복귀, 별도 에러 문구 없음 |
| 인증 실패 | 토스트 "로그인에 실패했어요. 다시 시도해주세요" |
| 신규 가입 | 약관 동의 화면(필수 항목 전체 체크해야 [동의하고 시작하기] 활성) |
| 서버 처리 중 | 버튼 로딩 상태, 중복 탭 차단 |
| 로그인 성공 | 온보딩 또는 라이브러리로 전환 |
| 탈퇴 안내 | 삭제 항목 리스트 + 구독 안내(활성 시) + 사유 선택 + 확인 체크박스 |
| 탈퇴 처리 중 | 전체 화면 로딩(취소 불가) |
| 탈퇴 완료 | "탈퇴가 완료되었습니다" 토스트 후 시작 화면 |

## 6. 데이터 모델

## 7. 예외 상황

- **제공자 인증 후 서버 통신 실패**: 제공자 로그인은 성공했지만 서버 등록이 실패한 상태. 재시도 버튼 제공, 재시도 시 같은 `provider_token`이 만료됐을 수 있으므로 제공자 인증부터 다시 수행한다.
- **약관 동의 화면에서 이탈**: 계정을 생성하지 않는다(동의 완료 시점에 생성). 다시 로그인하면 약관 동의부터 재시작.
- **제공자 앱 미설치**: 웹 로그인으로 폴백한다.
- **제공자가 이메일을 제공하지 않는 경우**(카카오 선택 동의 거부): 이메일 없이 계정 생성 허용. 이메일을 필수로 두지 않는다.
- **탈퇴 처리 중 앱 종료**: 서버 트랜잭션은 완료되므로 재실행 시 토큰 갱신이 실패해 시작 화면으로 간다.
- **탈퇴 직후 같은 계정으로 즉시 재로그인**: 신규 계정으로 온보딩부터 시작한다.
- **여러 기기에서 로그인**: 동시 로그인 허용. 로그아웃은 해당 기기 세션만 폐기한다.
- **활성 구독이 있는 상태로 탈퇴 후 재가입**: 스토어 구독이 살아 있으면 영수증 검증으로 새 계정에 티어를 복원한다(구독 명세의 복원 로직 참조).

## 8. 완료 조건

- Given 처음 앱을 쓰는 사용자 / When 카카오 로그인을 완료하고 약관에 동의한다 / Then 계정이 생성되고 온보딩 첫 단계로 이동한다
- Given 이미 온보딩을 마친 사용자 / When 재로그인한다 / Then 온보딩을 건너뛰고 라이브러리로 진입한다
- Given 소셜 인증 창에서 사용자가 취소를 누른다 / When 앱으로 복귀한다 / Then 에러 없이 시작 화면 상태로 돌아온다
- Given 약관 동의 화면에서 앱을 종료한다 / When 다시 로그인한다 / Then 계정이 생성되어 있지 않고 약관 동의부터 다시 시작한다
- Given 활성 구독이 있는 사용자 / When 탈퇴 화면에 진입한다 / Then 스토어에서 구독 해지가 별도로 필요하다는 안내가 노출된다
- Given 탈퇴를 완료한 사용자 / When 같은 소셜 계정으로 다시 로그인한다 / Then 이전 라이브러리·관심사가 없는 신규 계정으로 온보딩이 시작된다

## 미결 사항

- **`archived_users`의 보존 범위** — 현재 전자우편주소·제공자 계정 ID만 보존한다. 전자상거래법상 "계약에 관한 기록"에 그 이상의 식별 정보가 필요한지는 **법무 확인이 필요하다**(`domain.md` 15.1-2).
- 계정 연동(같은 이메일 다른 제공자 통합) 도입 여부 — 현재 비범위로 두었으나 CS 부담 발생 시 재검토
- 재가입 쿨다운(어뷰징 방지) 필요 여부 — 무료 티어 하루 2편 제한을 탈퇴·재가입으로 우회할 수 있음
