# 페이월 기능 명세서

> 연결 PRD: FR-29, FR-30 / 사용자흐름 5.4 / 검증계획 9.1
> `docs/prd/next_doing.md` 3장의 예시 명세를 정식 명세로 확장한 문서

## 1. 목적 & 연결

무료 사용자를 유료로 전환한다. 하루 2편 재생 한도를 소진한 뒤 재생을 시도하는 순간이 유일한 전환 트리거이며, 담기·탐색 등 다른 행동은 막지 않는다.

- PRD FR-29 (P0) 무료 사용자 재생 하루 2편 제한, 소진 후 재생 시도 시 페이월 노출
- PRD FR-30 (P0) 인앱 결제 완료 시 즉시 티어 반영 및 차단 지점 복귀
- PRD 사용자흐름 5.4
- PRD 9.1 정책 로직 단위 테스트 대상

## 2. 진입 조건

페이월 바텀시트는 **아래 한 경우에만** 노출된다.

1. **재생 한도 초과** — `tier == light`(무료)이고 오늘 재생한 고유 콘텐츠 수가 2편 이상인 상태에서 콘텐츠 재생을 시도할 때 (라이브러리·탐색·미니플레이어·푸시 진입 모두 동일)

**재생 확인 팝업(4.2)과 혼동하지 않는다.** 페이월은 한도를 **소진했을 때**, 확인 팝업은 한도가 **남아 있을 때** 뜬다. 둘은 배타적이며 연달아 노출되지 않는다.

아래는 **트리거가 아니다**:
- 담기 (무제한 — PRD 5.4 명시)
- 탐색 피드 열람·검색
- 라이브러리 열람
- **드립 영역 접근** — 무료 티어도 드립을 받으므로(PRD FR-14) 잠금·페이월 대상이 아니다
- 유료 티어 사용자의 한도 초과 → 페이월이 아니라 "오늘 청취 한도를 모두 사용했어요" 안내(업그레이드 유도는 선택적)

## 3. 입력값

| 값 | 출처 | 필수 |
|---|---|---|
| user_id | 토큰 | 필수 |
| tier | 서버(`users.tier`) | 필수 |
| daily_play_count | 서버가 `play_records` 집계로 산출한 **파생값**(컬럼 아님) | 필수 |
| blocked_content_id | 재생 시도한 콘텐츠 | 필수 |
| entry_point | library / explore / miniplayer / push | 필수(전환 분석용) |
| plans | 서버가 내려주는 요금제 목록 + 스토어 상품 ID | 필수 |

## 4. 처리 로직

### 4.1 재생 가능 판정

재생 시도마다 **서버가 판정한다**(클라이언트 카운트는 UI 힌트일 뿐, 최종 판정 근거가 아니다 — 우회 방지).

```
limit = plans[user.tier].daily_play_limit     // null = 무제한

if limit == null                → ALLOW
if daily_play_count < limit     → ALLOW
if user.tier == light (무료)     → BLOCKED (페이월)
else                            → LIMIT_REACHED (한도 안내, 페이월 아님)
```

- 한도는 `plans.daily_play_limit`에서 읽는다. 티어명을 코드에 하드코딩하지 않는다.
- **라이트(무료) = 2편 확정.** 데일리·프로 값은 1~2주 시범 운영 후 결정하며, `plans` 행의 값만 바꾸면 되고 앱 배포가 필요 없다(PRD FR-14).

### 4.2 재생 확인 팝업 — 차감 고지

판정이 `ALLOW`여도 **바로 재생하지 않는다.** 차감이 일어나는 재생이면 그 사실을 먼저 알린다.

```
재생 시도
   ↓
4.1 판정
   ├─ BLOCKED         → 페이월 바텀시트 (팝업 없음)
   ├─ LIMIT_REACHED   → 한도 안내 (팝업 없음)
   └─ ALLOW
        ├─ 차감 발생  → 재생 확인 팝업 → [재생하기] → 플레이어
        └─ 차감 없음  → 팝업 없이 바로 플레이어
```

**팝업을 띄우는 조건**

- **`limit != null`** — 한도가 있는 티어여야 한다. 무제한 티어는 남은 횟수라는 개념이 없어 알릴 내용이 없다.
- **오늘 아직 카운트되지 않은 콘텐츠여야 한다** — 4.3의 카운트 단위가 "오늘 재생한 고유 콘텐츠 수"이므로, 이미 카운트된 콘텐츠를 다시 트는 것은 차감이 없다.
- 두 조건을 모두 만족할 때만 노출한다. 원칙은 **"차감되지 않는데 차감된다고 알리지 않는다"** 이다 — 사실과 다른 고지는 재생을 망설이게 만들고, 한도가 실제보다 빨리 닳는다고 오해하게 한다.

**팝업 내용**

- 남은 횟수와 1회 차감 사실을 함께 알린다: "오늘 N회 남았어요. 재생하면 1회가 차감돼요."
- 버튼은 [취소] / [재생하기]. **[재생하기]를 눌러야 플레이어가 열린다.**
- [취소]는 원래 화면에 머문다. **카운트는 늘지 않는다** — 재생이 시작되지 않았기 때문이다(4.3).

**판정과 팝업의 관계**

- **팝업은 판정이 아니다.** 표시용 남은 횟수는 서버가 내려준 값이지만, 실제 허용 여부는 [재생하기]를 누른 시점에 **서버가 다시 판정한다.**
  - 팝업이 떠 있는 사이에 다른 기기에서 재생해 한도가 소진될 수 있다. **팝업에 표시된 숫자를 믿고 재생을 통과시키면 한도가 새는 구멍이 된다.**
  - 재판정 결과가 `BLOCKED`면 플레이어 대신 페이월로 전환한다.
- **한도를 이미 소진한 경우 팝업을 띄우지 않는다.** "0회 남았어요" 팝업과 페이월을 연달아 보여줄 이유가 없다. 곧바로 페이월이다.
- 진입점(라이브러리·탐색·미니플레이어·푸시)에 따라 규칙이 달라지지 않는다. **차감이 일어나는 재생이면 어디서 시작하든 팝업을 거친다.**
- 팝업을 띄우는 주체는 **재생을 시작시킨 화면**이다(예: `library.md` 4.3). 플레이어는 팝업을 통과한 요청만 받는다.

### 4.3 카운트 시점 — **재생 시작 시점**

> `next_doing.md`가 지목한 결정 포인트. 아래로 확정한다.

- 카운트는 **재생이 실제로 시작된 시점**에 +1 한다(재생 버튼 탭 시점이 아니라, 오디오 재생이 개시된 시점).
  - 이유: 버튼 탭 후 로드 실패·즉시 취소한 경우까지 차감하면 사용자가 손해를 본다.
- **같은 콘텐츠를 같은 날 다시 재생하면 카운트하지 않는다.** 카운트 단위는 "재생 횟수"가 아니라 **"오늘 재생한 고유 콘텐츠 수"** 다.
  - 이유: 이어듣기·되감기가 한도를 갉아먹으면 정상 사용이 불가능해진다.
  - 구현은 `play_records`의 `(user_id, content_id, play_date)` **유니크 제약이 보장한다.** 같은 날 같은 콘텐츠를 다시 재생해도 행이 늘지 않으므로 애플리케이션이 중복을 신경 쓸 필요가 없다
  - 즉 `daily_play_count = COUNT(*) FROM play_records WHERE user_id = ? AND play_date = <오늘의 서비스 날짜>`
- 재생 시작 후 3초 이내에 중단해도 카운트는 유지한다(어뷰징 방지).

### 4.4 카운트 초기화 — 04시 기준

- 매일 **04:00 (Asia/Seoul)** 에 초기화된다(PRD 9.1).
- 배치로 리셋하지 않고, **판정 시점에 "오늘의 서비스 날짜"를 계산**하는 방식으로 구현한다.
  - `서비스 날짜 = 현재 시각이 04:00 이전이면 어제, 이후면 오늘` → `play_records.play_date`에 저장되는 값과 같다
  - `users`에 `daily_play_count`·`count_reset_at` 컬럼을 두지 않는다. 컬럼과 집계가 어긋나면 어느 쪽이 맞는지 판단할 수 없어진다
  - 이렇게 하면 배치 지연·시간대 이슈가 판정에 영향을 주지 않는다.
  - **경계 계산 함수는 한 곳에만 두고 전 모듈이 그것만 호출한다.** `content_stats` 집계가 다른 경계를 쓰면 페이월 카운트와 통계가 영구히 어긋난다.
- 기준 시간대는 **서버의 Asia/Seoul 고정**이다. 기기 시각·기기 시간대를 신뢰하지 않는다.

### 4.5 페이월 노출 → 결제 → 복귀

1. 재생 차단 판정 → 페이월 바텀시트 노출. **플레이어를 열지 않는다**
2. 시트에 제한 안내 + 3티어 비교 + 각 요금제 결제 버튼
3. 결제 버튼 탭 → 스토어 인앱 결제 플로우(구독 명세 4.2 참조)
4. 결제 성공 → 서버 영수증 검증 → `tier` 갱신
5. 시트 자동 닫힘 → **`blocked_content_id`를 자동 재생**한다 (PRD 5.4 "막혔던 지점으로 복귀해 이어 진행")
   - 재생 위치는 저장된 `playback_progresses.position_sec`을 따른다
6. [닫기] 탭 → 원래 화면으로 복귀. 재생은 시작되지 않는다. `blocked_content_id`는 폐기

### 4.6 노출 빈도

- 재생 시도마다 노출한다(빈도 제한 없음). 한도 초과 상태에서 재생을 시도한 것 자체가 명확한 의도이므로.
- 단 같은 세션에서 [닫기] 후 **3초 이내 재시도**는 중복 노출로 보고 무시한다(연타 방지).

## 5. 화면 상태

| 조건 | 동작 |
|---|---|
| 무료 · count < 2 · 오늘 처음 트는 콘텐츠 | **재생 확인 팝업** "오늘 N회 남았어요. 재생하면 1회가 차감돼요." + [취소] / [재생하기] |
| 무료 · count < 2 · 오늘 이미 튼 콘텐츠 | 팝업 없이 즉시 재생(차감 없음) |
| 무제한 티어 | 팝업 없이 즉시 재생 |
| 재생 확인 팝업에서 [취소] | 재생되지 않고 원래 화면 유지. 카운트 변화 없음 |
| 재생 확인 팝업 → [재생하기] 시 재판정 결과 BLOCKED | 팝업을 닫고 **페이월 바텀시트**로 전환 |
| 무료 · count == 2 | 라이브러리·탐색 카드에 잔여 한도 힌트 표시("오늘 재생 0/2 남음") |
| 무료 · count >= 2 · 재생 시도 | **페이월 바텀시트** — 제한 안내 + 3티어 비교표 + 결제 버튼 + [닫기]. **확인 팝업은 뜨지 않는다** |
| 요금제 로딩 중 | 시트 내 스켈레톤 |
| 요금제 조회 실패 | 시트 내 "요금제를 불러올 수 없어요" + [다시 시도] |
| 결제 진행 중 | 전체 버튼 비활성 + 로딩. 시트 닫기 차단 |
| 결제 성공 | 시트 닫힘 → 성공 토스트 → 차단됐던 콘텐츠 자동 재생 |
| 결제 취소 | 시트 유지, 로딩 해제, 에러 문구 없음 |
| 결제 실패 | 시트 유지 + 인라인 에러 + [다시 시도] |
| 영수증 검증 지연 | "구독을 확인하고 있어요" 상태 유지(최대 30초) → 초과 시 "잠시 후 자동 반영됩니다" 안내 후 시트 닫기 |
| [닫기] | 원래 화면 복귀, 재생 시작 안 됨 |

**바텀시트 구성**: 제한 안내 헤드라인 / 3티어 비교(가격·일 청취 편수·드립 편수·광고) / 티어별 [구독하기] / 복원 링크 / 약관·해지 안내 / [닫기]

- 오프라인 저장은 P1 이연이므로 비교표에 넣지 않는다(FR-26).

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `play_records` — **카운트의 유일한 근거**. `daily_play_count` 컬럼은 존재하지 않는다 | 6.3 |
| `plans` — 티어별 한도·드립 편수 | 8.1 |
| `subscriptions` · `users.tier`(캐시) | 8.2 · 3.1 |

- `User.daily_play_count` · `count_reset_at` 컬럼은 **없다.** 판정 시점에 `play_records`를 집계한다.
- `PaywallEvent`는 테이블이 아니라 구조화 로그로 남긴다(domain.md 13.3).

## 7. 예외 상황

- **04시 리셋 경계에 걸친 재생**: 판정 시점의 `count_reset_at`으로 계산하므로, 03:59에 차단됐다가 04:00에 재시도하면 재생된다. 03:59에 재생을 시작해 04:30까지 듣는 경우는 이미 시작된 재생이므로 중단하지 않는다.
- **결제 중 앱을 백그라운드로 보냈다가 복귀**: 스토어 결제는 앱 밖에서 완결된다. 복귀 시 미처리 트랜잭션을 조회해 검증하고, 성공이면 시트를 닫고 티어를 반영한다. `blocked_content_id`는 세션 메모리가 아니라 **로컬에 저장**해 복귀 후에도 자동 재생이 가능하게 한다.
- **결제 버튼 빠르게 두 번 탭**: 첫 탭 즉시 버튼 비활성 + 인플라이트 플래그. 스토어 SDK도 중복 구매를 거부하지만 클라이언트에서 1차 차단한다.
- **결제는 성공했는데 서버 검증 API가 실패**: 티어를 무료로 두지 않는다. 영수증을 로컬 큐에 보관하고 재시도한다. 사용자에게는 "결제는 완료되었고 반영 중"으로 안내한다.
- **클라이언트 카운트와 서버 카운트 불일치**: 항상 서버 판정을 따른다. 클라이언트는 재생 시도 응답으로 카운트를 갱신한다.
- **기기 시각을 앞뒤로 조작**: 서버 시각 기준이라 영향 없다.
- **오프라인 상태에서 저장분 재생**(무료 사용자는 해당 없음): 유료 전용 기능이므로 무료 티어 판정과 무관.
- **한도 소진 상태에서 이미 듣던 콘텐츠 이어듣기**: 4.3 규칙에 따라 오늘 이미 카운트된 콘텐츠라면 재생 허용. 오늘 처음 여는 콘텐츠라면 차단. **확인 팝업도 뜨지 않는다**(차감이 없으므로).
- **재생 확인 팝업이 떠 있는 사이 다른 기기에서 한도를 소진**: [재생하기] 시점의 서버 재판정이 최종이다. 팝업을 닫고 페이월로 전환한다.
- **재생 확인 팝업에서 [취소] 후 곧바로 다시 탭**: 카운트가 늘지 않았으므로 같은 팝업이 다시 뜬다. 연타 방지 외의 억제 규칙은 두지 않는다.
- **팝업의 [재생하기]를 눌렀으나 오디오 로드에 실패**: 재생이 시작되지 않았으므로 카운트하지 않는다(4.3). 팝업에서 차감을 고지했더라도 실제 차감은 재생 시작 시점에만 일어난다.
- **재생 확인 팝업 노출 중 앱 종료**: 아무 것도 기록하지 않는다. 재진입 시 다시 팝업부터 시작한다.
- **탈퇴 후 재가입으로 한도 초기화**: 어뷰징 가능. → 미결 사항.
- **결제 완료 직후 차단됐던 콘텐츠가 회수된 경우**: 자동 재생 대신 "제공이 종료된 콘텐츠예요" 안내 후 원래 화면 복귀.

## 8. 완료 조건

- Given 무료 사용자가 오늘 1편을 재생했다 / When 새 콘텐츠 재생을 시도한다 / Then **"오늘 1회 남았어요. 재생하면 1회가 차감돼요" 확인 팝업**이 뜨고, [재생하기]를 눌러야 재생된다
- Given 재생 확인 팝업이 떠 있다 / When [취소]를 누른다 / Then 재생되지 않고 카운트도 늘지 않는다
- Given 무료 사용자가 오늘 이미 재생한 콘텐츠 / When 다시 재생을 시도한다 / Then 확인 팝업 없이 즉시 재생된다
- Given 무제한 티어 사용자 / When 재생을 시도한다 / Then 확인 팝업 없이 즉시 재생된다
- Given 재생 확인 팝업이 떠 있는 사이 다른 기기에서 한도가 소진됐다 / When [재생하기]를 누른다 / Then 서버 재판정으로 페이월이 노출되고 재생은 시작되지 않는다
- Given 확인 팝업에서 [재생하기]를 눌렀으나 오디오 로드에 실패했다 / When 카운트를 확인한다 / Then 차감되지 않았다
- Given 무료 사용자가 오늘 2편을 재생 완료했다 / When 3번째 콘텐츠 재생을 시도한다 / Then **확인 팝업 없이 페이월이 바로** 뜨고 재생은 시작되지 않는다
- Given 페이월이 뜬 상태 / When 결제를 완료한다 / Then 티어가 즉시 바뀌고 원래 시도했던 콘텐츠가 자동 재생된다
- Given 무료 사용자가 오늘 이미 2편을 재생했다 / When 콘텐츠를 담기만 한다 / Then 페이월 없이 정상적으로 담긴다
- Given 무료 사용자가 오늘 1편만 재생했다 / When 그 콘텐츠를 다시 재생한다 / Then 카운트가 늘지 않고 여전히 1편으로 집계된다
- Given 무료 사용자가 03:59에 한도를 소진했다 / When 04:01에 재생을 시도한다 / Then 카운트가 초기화되어 재생된다
- Given 페이월에서 결제 중 앱을 백그라운드로 보냈다 / When 결제를 완료하고 앱으로 복귀한다 / Then 티어가 반영되고 차단됐던 콘텐츠가 자동 재생된다
- Given 페이월이 떠 있다 / When [닫기]를 누른다 / Then 원래 화면으로 돌아가고 재생은 시작되지 않는다
- Given 무료 사용자 / When 라이브러리의 드립 영역을 탭한다 / Then 페이월 없이 드립 콘텐츠가 정상 노출된다(무료도 드립 대상)
- Given 프로 티어 사용자 / When 하루에 20편을 재생한다 / Then 페이월이 한 번도 노출되지 않는다
- Given 결제 버튼을 빠르게 두 번 탭한다 / When 결제가 진행된다 / Then 결제 요청은 1건만 발생한다

## 미결 사항

- ~~티어 명칭 불일치~~ → **확정: 라이트 / 데일리 / 프로. 라이트가 무료 티어다.**
- ~~재생 전 차감 고지~~ → **확정: 재생 확인 팝업(4.2).** 차감이 발생하는 재생에만 노출하고, 한도 소진 시에는 페이월이 대신한다.
- **확인 팝업의 마찰** — 무료는 하루 최대 2번이라 부담이 적지만, 데일리·프로에 한도가 생기면 매 재생마다 팝업을 보게 된다. "오늘 다시 보지 않기" 같은 완화 장치가 필요한지는 **유료 티어 한도 값이 정해진 뒤** 판단한다(아래 항목과 함께 결정).
- 데일리·프로의 일 청취 편수·가격은 1~2주 시범 운영 후 결정(PRD 4.1) — `plans` 행의 값만 바꾸면 되므로 코드 변경·마이그레이션이 필요 없다
- 무료 티어 광고(PRD 4.1 "광고 제공")의 형태·삽입 지점 미정 — 오디오 프리롤인지 배너인지에 따라 플레이어 명세 개정 필요
- 탈퇴·재가입을 통한 한도 우회 방지책 필요 여부
