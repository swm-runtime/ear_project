# 콘텐츠 파이프라인 기능 명세서 (대본생성 → QA → 발행)

> 연결 PRD: FR-07 ~ FR-13 / 비기능(재생 즉시성·콘텐츠 신뢰성·저작권) / 사용자흐름 5.6 / 검증계획 9.1·9.2

> `next_doing.md` 1장 2번: **"제일 어려운 부분(콘텐츠 파이프라인)을 화면보다 먼저 설계"** — 이 서비스에서 유일하게 검증되지 않은 영역이다.

## ⚠️ 범위 상태 — **자동화는 P1 이연**

**MVP는 이 파이프라인을 시스템으로 운영하지 않는다.**

- 대본 생성·QA 대조·TTS 변환은 **팀이 앱 밖에서 수행**하고, 완성된 오디오를 **관리자 계정으로 업로드하면 즉시 발행**된다(PRD FR-37 → [`admin.md`](admin.md)).
- 업로드 이전 단계의 상태를 시스템에서 관리하지 않으므로 `SourceDocument` · `Episode` · `Script` · `QaReport` · `PipelineRun` 테이블을 **만들지 않는다**(`domain.md` 14장).
- `Content.status`는 `published` · `withdrawn` · `expired` **3값뿐**이다. `qa_passed` · `partner_review` 같은 중간 상태는 존재하지 않는다.

**이 문서는 자동화 도입 시점을 대비한 설계 문서이자, MVP 수작업의 제작 기준(4.2~4.5의 분할·생성·QA 규칙)으로 쓴다.** 사람이 수행해도 지켜야 하는 규칙이기 때문이다.

자동화 도입 조건: 콘텐츠 볼륨이 수작업 한계를 넘는 시점(PRD 4.2).

## 1. 목적 & 연결

파트너 원문과 AI 생성 소스를 **단일 표준 에피소드**로 바꿔 카탈로그에 올린다. 사람이 매건 검수하지 않아도 되도록 QA를 파이프라인 안에 내장하는 것이 장기 목표이며, 이것이 성립해야 "일일 발행"이 성립한다(PRD 2.1). **MVP는 그 전 단계로, 사람이 제작·검수하고 관리자 업로드로 발행한다.**

- FR-07 (P0) 파트너 원문은 공식 제공 경로로만 수급, 협의된 주기로 최신성 유지
- FR-08 (P0) 원문·AI 대본을 단일 표준 에피소드 형태로 변환. 변형(버전) 없음
- FR-09 (P0) 원문·소스에 없는 사실을 생성·추가·변형하지 않음
- FR-10 (P0) 발행 전 QA로 사실관계 대조 — **MVP는 업로드 전 수동 검수**, 자동 대조·재생성은 P1
- FR-11 (P0) AI 생성용 소스 수집은 적법 범위로 한정
- FR-12 (P0) 원저자·출처 고지, 원문 연결 정보 제공
- FR-13 (P0) 권장 길이 10~15분, 완결성 우선 분할

**사용자에게 노출되지 않는 백그라운드·운영 기능이다**(PRD 5.6). 아래 5장은 화면 대신 **상태 전이와 운영 콘솔 노출**을 정의한다.

## 2. 진입 조건

| 트리거 | 설명 |
|---|---|
| 파트너 수급 배치 | 협의된 갱신 주기(예: 매일 03:00)로 파트너 공식 API·피드 폴링 |
| 파트너 수동 인입 | 운영자가 파트너 제공 파일·목록을 업로드 |
| AI 생성 배치 | 주제 커버리지 부족 감지 시(드립 명세의 고갈 신호) 또는 정기 배치 |
| 재생성 트리거 | QA 실패로 자동 재생성 |
| 재발행 트리거 | 원문 갱신 감지, 오디오 재생성 필요 |

## 4. 처리 로직

### 4.0 전체 파이프라인

```
[인입]        파트너 수급 / AI 소스 수집
   ↓
[정규화]      원문 정제·메타 추출·중복 판정
   ↓
[분할 판정]   길이 기반 에피소드 분할 (FR-13)
   ↓
[대본 생성]   라디오 형식 대본 생성 (FR-08, FR-09)
   ↓
[QA 대조]  ←─────┐  실패 시 재생성 (FR-10)
   ↓ 통과        │
[오디오 생성]  상용 TTS + 고지 멘트 (FR-12)
   ↓
[오디오 QA]   오독·길이·무음 검사
   ↓
[발행]        카탈로그 편입 → 드립·탐색 노출
```

### 4.1 인입 (FR-07, FR-11)

- **파트너 원문은 공식 제공 경로로만 수급한다.** 스크래핑·크롤링 코드는 저장소에 존재해서도 안 된다(PRD 2.2 절대 조항).
- AI 생성용 소스 수집은 수집 정책 체크를 통과해야 한다: robots.txt 확인, 이용약관 확인, 인용 범위 제한. 체크 실패 소스는 파이프라인에 진입시키지 않는다.
- `(partner_id, external_id)`로 중복 인입을 판정한다. 원문 `updated_at`이 변경된 경우에만 재처리한다.

### 4.2 정규화·분할 (FR-13)

- 원문에서 본문·저자·출처·발행일을 추출하고 광고·네비게이션 등 비본문을 제거한다.
- **분할 판정**
  - 예상 낭독 시간 = 글자 수 / 분당 낭독 속도(한국어 기준값: 350자/분, 1.0배속)
  - 10~15분 범위면 단일 에피소드
  - 15분 초과면 분할하되, **완결성을 우선한다**(FR-13) — 문단·소제목 경계에서만 자르고, 문장 중간에서 자르지 않는다
  - 분할 결과 각 편이 5분 미만이 되면 인접 편과 병합한다
  - 분할된 에피소드는 `series_id`로 묶고 `episode_no`를 부여한다. **이 값들은 `contents` 테이블에 직접 들어간다**(별도 `Episode` 테이블 없음). 분할되지 않은 단일 콘텐츠는 `series_id = NULL`이다
- 분할은 **대본 생성 전**에 결정한다(생성 후 자르면 도입·마무리 멘트가 어긋난다).

### 4.3 대본 생성 (FR-08, FR-09)

- **입력**: 정규화된 원문(또는 AI 소스 세트) + 표준 대본 템플릿
- **출력**: 라디오 형식 대본 — 도입 멘트 / 본문 / 마무리 멘트
- **단일 표준 형태**(FR-08): 콘텐츠별·사용자별 변형을 만들지 않는다. 템플릿은 하나이며, 같은 원문은 항상 같은 대본으로 수렴해야 한다.
- **환각 금지 규칙**(FR-09) — 생성 제약으로 명시한다
  - 원문에 없는 수치·인용·사례·인물·연도를 추가하지 않는다
  - 원문의 주장 강도를 바꾸지 않는다(추정 → 단정 금지)
  - 원문에 없는 결론·조언을 덧붙이지 않는다
  - 연결어·구어체 전환은 허용한다(사실 정보를 바꾸지 않는 범위에서)
- **고지 멘트**(FR-12): 도입에 "이 콘텐츠는 OO에 실린 OOO 님의 글을 바탕으로 합니다", 마무리에 출처·원문 안내를 **템플릿으로 강제 삽입**한다. 생성 모델이 이 부분을 창작하지 않도록 고정 문구로 조립한다.
- **AI 자체 생성 콘텐츠**도 동일하다. 다만 고지 멘트는 "참고한 자료" 형태로 소스를 명시한다.

### 4.4 QA 대조 (FR-10) — 파이프라인의 핵심

발행 전 반드시 통과해야 하는 게이트다.

**검사 항목**

| 항목 | 내용 | 실패 처리 |
|---|---|---|
| 사실 일치 | 대본의 각 사실 주장이 원문에 근거하는지 문장 단위 대조 | 재생성 |
| 미근거 정보 | 원문에 없는 수치·고유명사·인용 검출 | 재생성 |
| 주장 강도 왜곡 | 추정→단정, 부분→전체 일반화 검출 | 재생성 |
| 누락 | 원문의 핵심 논지가 빠졌는지 | 재생성 |
| 고지 멘트 | 도입·마무리 출처 고지가 규격대로 포함됐는지 | 자동 보정 후 재검사 |
| 금칙 | 욕설·차별 표현·특정인 비방 | 재생성, 3회 실패 시 보류(아래 재생성 정책의 "최대 3회"와 동일 한도) |
| 길이 | 예상 낭독 시간이 규격 범위인지 | 재생성 |

- **MVP는 이 표의 항목을 `admin.md` 4.2-1의 수동 체크리스트로 이행하며, PRD 9.1의 검증 대상은 체크리스트 이행률이다**(합의 2026-08-06).

**재생성 정책**

- QA 실패 시 실패 사유를 프롬프트에 피드백해 **자동 재생성**한다
- **최대 3회**. 3회 모두 실패하면 `status = qa_failed`로 두고 **운영 검토 큐**에 넣는다. 자동 발행하지 않는다
- 재생성 이력은 전부 보존한다(QA 통과율·재생성 발생률 지표 — PRD 10)

**QA 판정 주체**: 원문-대본 대조는 자동화한다. 다만 **파트너 콘텐츠의 첫 N건(예: 초기 50건)은 사람이 병행 검수**해 자동 QA의 검출률을 실측한 뒤 무검수 비율을 올린다. **"초기 50건 병행 검수"와 검출률 실측은 PRD가 아니라 이 문서의 제안이다** — PRD 9.1의 실제 검증 항목은 "체크리스트 이행률"이다.

### 4.5 오디오 생성

- 승인된 대본을 상용 TTS로 합성한다(MVP는 상용 TTS 고정 — PRD 4.2)
- 발음 사전을 운영한다: 영어 약어·전문 용어·인명의 한국어 발음 규칙
- **오디오 QA**
  - 길이가 대본 예상 시간과 크게 다르면 실패(합성 누락 의심)
  - 비정상 무음 구간 검출
  - 파일 무결성·비트레이트 확인
  - (선택) STT 역변환 후 대본과 대조해 오독 검출 — 정확도·비용 확인 후 도입
- 실패 시 재합성. 3회 실패 시 운영 검토 큐(4.4 재생성 정책의 "최대 3회"와 통일)

### 4.6 발행

- 오디오 파일을 스토리지에 업로드하고 **직접 접근 불가**하게 설정한다(서명 URL로만 접근 — FR-33)
- `Content` 레코드 생성 → `status = published`
- 카탈로그 편입 → 탐색 피드·드립 편성 대상에 포함
- **발행 시점부터 재생 즉시성이 보장되어야 한다**(PRD 7): 사용자에게 노출되는 모든 콘텐츠는 오디오 생성이 완료된 상태여야 한다. 발행 전 콘텐츠는 어떤 노출면에도 나타나지 않는다.

### 4.7 재발행·갱신

- 원문이 수정되면 재처리해 새 `content_version`을 만든다
- 재발행 시 기존 재생 위치는 폐기한다(`player.md` 예외 처리)
- 오디오만 교체되는 경우에도 버전을 올린다

### 4.8 라이선스 만료·회수

- `license_scope.expires_at`이 지난 콘텐츠는 자동으로 노출에서 제외한다
- 파트너 회수 요청은 `partner-control.md`가 처리한다

## 5. 상태 전이 · 운영 노출

**콘텐츠 상태 머신**

```
ingested → normalized → script_generated → qa_passed → audio_generated → published
              │              │                              │
              │              └── qa_failed ──(3회 실패)──→ review_required
              └── ingest_failed                              │
                                                    published → withdrawn (파트너 회수)
                                                             → expired  (라이선스 만료)
                                                             → superseded (재발행)
```

> **P1 자동 파이프라인의 내부 단계 설계안이다 — 현재의 `Content.status`(`published`·`withdrawn`·`expired` 3값)가 아니다(6장).** `ingested`~`qa_passed`·`superseded` 등은 자동화 도입 시점에 다시 정의한다. 재발행은 현재 `superseded` 상태 없이 같은 행의 `content_version`을 올린다(6장).

**운영 콘솔에서 봐야 하는 것** (MVP는 최소 기능으로)

| 화면 | 내용 |
|---|---|
| 파이프라인 대시보드 | 단계별 건수, 오늘 발행 수, QA 통과율, 재생성 발생률 |
| 검토 큐 | `review_required` 목록 — 원문·대본 나란히 비교, [승인 발행] / [폐기] / [재생성] |
| 콘텐츠 목록 | 상태·파트너·주제 필터, 개별 상세(원문·대본·오디오·QA 리포트) |
| 실패 로그 | 인입 실패·TTS 실패·업로드 실패 |

- 사용자 앱에는 파이프라인 상태가 **일절 노출되지 않는다**. "생성 중" 같은 상태는 클라이언트에 존재하지 않는다(PRD 1.3).

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

**이 기능은 P1 이연이므로 파이프라인 테이블을 만들지 않는다.** `SourceDocument` · `Episode` · `Script` · `QaReport` · `PipelineRun`은 전부 폐기됐다(domain.md 14장). 자동화를 도입할 때 다시 정의한다.

| MVP에서 사용하는 것 | domain.md |
|---|---|
| `contents` — **업로드 시점에 `published`로 생성**. `series_id` · `episode_no` · `total_episodes`가 여기 흡수됐다 | 5.1 |
| `content_topics` | 5.2 |
| `content_scripts` | 5.3 |

- `Content.status`는 `published` · `withdrawn` · `expired` **3값뿐**이다. `draft` · `partner_review` · `qa_failed` 같은 파이프라인 상태는 존재하지 않는다.
- 재발행은 새 행을 만들지 않고 같은 행의 `content_version`을 올린다. `superseded` 상태는 없다.

## 7. 예외 상황

- **원문이 너무 짧음**(3분 미만): 단독 에피소드로 만들지 않는다. 같은 주제·저자의 다른 원문과 묶거나 보류한다.
- **원문이 매우 김**(60분 초과): 다편 시리즈로 분할하되, 편수 상한(예: 6편)을 넘으면 운영 검토 큐로 보낸다.
- **원문에 표·이미지·코드 블록이 있음**: 오디오로 전달 불가능한 요소는 대본에서 "자세한 표는 원문에서 확인하세요" 형태로 안내하고, 임의로 내용을 지어내지 않는다(FR-09).
- **원문이 외국어**: MVP 범위 밖. 인입 단계에서 거른다.
- **QA가 계속 실패하는 특정 원문 유형**: 검토 큐에 쌓이는 패턴을 모니터링해 템플릿·프롬프트를 개선한다. 개별 건을 강제 통과시키지 않는다.
- **TTS 제공자 장애**: 파이프라인을 중단하지 않고 큐에 적재해 복구 후 재개한다. 발행 지연은 드립 편성이 기존 카탈로그로 흡수한다.
- **TTS 비용 급증**: 일일 합성 상한을 두고 초과 시 배치를 다음 날로 이월한다.
- **같은 원문이 파트너 A와 B 양쪽에서 인입**: `content_hash`로 중복을 검출해 먼저 인입된 쪽만 처리한다.
- **파트너 원문이 삭제됨**: 회수와 동일하게 처리한다(`partner-control.md`).
- **AI 생성 소스가 사후에 접근 불가**(링크 소멸): 이미 발행된 콘텐츠는 유지하되 소스 스냅샷을 보관해 근거를 남긴다.
- **발행 직전 라이선스 기간 만료**: 발행하지 않는다.
- **오디오는 생성됐는데 업로드 실패**: `audio_generated` 상태로 남고 재시도 대상이 된다. 절반만 발행되는 상태가 없어야 한다(발행은 원자적으로 처리).

## 8. 완료 조건

> **(P1 — 자동 파이프라인 도입 시의 수용 기준이다. MVP 수용 기준이 아니다.** MVP의 수용 기준은 `admin.md` 8장이다.)

- Given 파트너 원문 1건이 공식 경로로 인입된다 / When 파이프라인이 실행된다 / Then 대본 생성 → QA 통과 → TTS → 발행까지 자동으로 진행되어 카탈로그에 편입된다
- Given 25분 분량의 원문이 인입된다 / When 분할 판정이 수행된다 / Then 문단 경계에서 2편으로 나뉘고 각 편이 10~15분 범위이며 같은 `series_id`로 묶인다
- Given 생성된 대본에 원문에 없는 통계 수치가 포함되어 있다 / When QA를 수행한다 / Then 미근거 정보로 검출되어 발행되지 않고 자동 재생성된다
- Given QA가 3회 연속 실패한다 / When 재생성 한도에 도달한다 / Then 자동 발행되지 않고 운영 검토 큐로 이동한다
- Given 대본이 생성된다 / When 도입·마무리 멘트를 확인한다 / Then 원저자와 출처가 규격대로 포함되어 있다
- Given 발행된 콘텐츠 / When 앱에서 재생을 시도한다 / Then 생성 대기 없이 즉시 재생된다
- Given 발행된 콘텐츠의 오디오 파일 / When 서명 URL 없이 스토리지에 직접 접근을 시도한다 / Then 접근이 거부된다
- Given 파트너 원문이 수정되었다 / When 다음 수급 배치가 실행된다 / Then 재처리되어 새 `content_version`으로 재발행된다
- Given 라이선스 기간이 만료된 콘텐츠 / When 노출면을 확인한다 / Then 탐색·드립·라이브러리에서 제외된다
- Given 로봇 배제 정책을 위반하는 소스 / When AI 생성 파이프라인에 진입시킨다 / Then 수집 정책 체크에서 차단되어 진입하지 못한다
- Given TTS 제공자가 장애 상태다 / When 파이프라인이 실행된다 / Then 작업이 큐에 보존되고 복구 후 자동 재개된다

## 미결 사항

- **자동 QA의 사실 대조 방식 확정** — LLM 판정 / 규칙 기반 / 하이브리드. 검출률을 실측해야 무검수 비율을 정할 수 있다(검출률 실측은 이 문서의 제안 — PRD 9.1의 검증 항목은 "체크리스트 이행률"이다)
- 초기 병행 인간 검수 규모(잠정 50건 — PRD가 아니라 이 문서의 제안값)와 무검수 전환 기준 확정
- 분당 낭독 속도 기준값(350자/분) 실측 필요 — 분할 판정의 정확도가 여기에 달려 있다
- 오디오 QA에 STT 역변환을 도입할지 (비용·정확도 검증 필요)
- 대본 생성 모델·프롬프트 버전 관리 정책 — `prompt_version` 변경 시 기존 콘텐츠 재생성 여부
- 운영 콘솔의 구현 범위 — MVP 2주 일정(PRD 8.1)에서 어디까지 만들지
- AI 자체 생성 콘텐츠의 주제 선정 기준 — 드립 명세의 고갈 신호와 연결 방식 확정 필요
