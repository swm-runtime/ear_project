# 푸시 알림 기능 명세서

> 연결 PRD: FR-19 (P1) / 사용자흐름 5.1

## 1. 목적 & 연결

드립이 도착했음을 알려 다음 접속을 유도한다. "앱을 열면 들을 게 준비되어 있는" 경험(PRD 1.3)을 사용자가 인지하게 만드는 유일한 아웃바운드 채널이다.

- PRD FR-19 (P1) 드립 도착을 푸시로 알리고, 알림 수신 여부를 설정할 수 있다
- PRD 사용자흐름 5.1 (온보딩 마지막 단계에서 알림 권한 요청)

> **우선순위 P1.** MVP 일정에서 밀릴 경우, 푸시 발송은 빼더라도 **권한 요청 단계와 설정 토글의 자리는 남겨두는 것**을 권장한다(OS 권한은 사후 재요청이 어렵다).

## 2. 진입 조건

**권한 요청**
- 온보딩 마지막 단계(사전 안내 후 OS 다이얼로그)
- 설정에서 알림 토글을 켤 때(권한이 없으면 OS 설정으로 안내)

**푸시 발송**
- 드립 편성이 완료되어 라이브러리에 신규 콘텐츠가 적립된 시점

## 3. 입력값

**단말 등록**

| 값 | 설명 |
|---|---|
| device_token | FCM / APNs 토큰 |
| platform, app_version, device_id | 단말 정보 |
| os_permission_granted | OS 권한 허용 여부 |

**발송 페이로드**

| 값 | 설명 |
|---|---|
| type | drip_arrival (MVP에서는 이 하나) |
| title, body | 알림 문구 |
| deep_link | 이동 대상 (라이브러리 또는 특정 콘텐츠) |
| content_count | 도착한 편수 |

## 4. 처리 로직

### 4.1 권한 요청

- 온보딩 5단계에서 **사전 안내(프리퍼미션)** 를 먼저 보여준다. [알림 받기] 선택 시에만 OS 다이얼로그를 띄운다.
  - 이유: OS 권한은 한 번 거부되면 앱에서 다시 요청할 수 없다. 사전 안내로 거부율을 낮춘다.
- [나중에] 선택 시 OS 다이얼로그를 띄우지 않고 넘어간다. 이후 설정에서 켤 수 있다.
- 권한 허용 시 즉시 device_token을 발급받아 서버에 등록한다.

### 4.2 수신 설정 (앱 내 토글)

- OS 권한과 앱 내 설정은 **분리**된 두 단계다.
  - OS 권한 없음 → 어떤 경우에도 발송하지 않는다
  - OS 권한 있음 + 앱 토글 OFF → 발송하지 않는다
  - OS 권한 있음 + 앱 토글 ON → 발송한다
- 앱 포그라운드 복귀 시마다 OS 권한 상태를 확인해 서버에 동기화한다(설정에서 권한을 끈 경우 발송 낭비 방지).

### 4.3 발송 규칙

| 규칙 | 내용 |
|---|---|
| 시점 | 드립 편성 완료 직후. 단 **방해금지 시간(22:00~08:00 KST)** 에는 발송하지 않고 08:00으로 지연 |
| 빈도 | 하루 최대 1회. 드립이 2편이어도 알림은 1건으로 묶는다 |
| 대상 | **전 티어**(무료 포함) + OS 권한 허용 + 앱 토글 ON |
| 문구 | "오늘의 콘텐츠 N편이 도착했어요" + 대표 콘텐츠 제목 |
| 딥링크 | 1편이면 해당 콘텐츠 플레이어, 2편 이상이면 라이브러리 |

- **무료(라이트) 티어도 드립을 받으므로 알림 대상이다**(PRD FR-14). 티어로 발송 대상을 가르지 않는다.

### 4.4 알림 탭 처리

1. 알림 탭 → 앱 실행 → **스플래시 판정을 먼저 통과**(`splash.md` 4번)
2. 온보딩 미완료 사용자는 딥링크를 보류했다가 온보딩 완료 후 이동
3. 콘텐츠 딥링크인 경우 플레이어를 열되, **무료 재생 한도 판정을 거친다**(차단 시 페이월)
4. 딥링크 대상 콘텐츠가 회수·삭제된 경우 라이브러리로 폴백

### 4.5 포그라운드 수신

- 앱이 포그라운드일 때는 OS 알림 배너를 띄우지 않고, **인앱 배너**("새 콘텐츠 N개 도착")로 대체한다.
- 라이브러리 화면이면 배너 대신 목록을 조용히 갱신한다.

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 온보딩 사전 안내 | "드립 도착을 알려드릴까요?" + [알림 받기] / [나중에] |
| OS 다이얼로그 | 시스템 UI |
| 권한 허용 | 별도 화면 없이 라이브러리 진입 |
| 권한 거부 | 별도 안내 없이 라이브러리 진입(거부를 다시 조르지 않는다) |
| 설정 토글 ON(권한 있음) | 토글 켜짐, 즉시 저장 |
| 설정 토글 ON 시도(권한 없음) | "기기 설정에서 알림을 허용해주세요" + [설정 열기]. 토글은 꺼진 상태 유지 |
| 백그라운드 수신 | OS 알림 배너 |
| 포그라운드 수신 | 인앱 배너(탭하면 라이브러리 갱신·이동) |
| 딥링크 대상 없음 | 라이브러리로 폴백, 토스트 "콘텐츠를 찾을 수 없어요" |

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `device_tokens` — `is_os_permission_granted`는 여기에만 존재 | 3.6 |
| `notification_logs` — 중복 발송 방지. **탈퇴 시 즉시 파기** | 9.1 |
| `user_settings.is_drip_notification_enabled` | 3.5 |

- `skip_reason`에 `free_tier`는 **없다.** 무료 티어도 드립을 받으므로 이 사유가 발생하지 않는다.

## 7. 예외 상황

- **device_token 만료·무효**: 발송 실패 응답(FCM `UNREGISTERED`, APNs `410`)을 받으면 토큰을 무효화하고 다음 앱 실행 시 재등록한다.
- **여러 기기 로그인**: 활성 토큰 전부에 발송한다.
- **로그아웃**: 해당 기기 토큰을 무효화해 다른 사용자에게 알림이 가지 않게 한다.
- **탈퇴**: 모든 토큰 삭제. `notification_logs`도 함께 즉시 파기한다 — 보존할 법령 근거가 없고, 중복 발송 방지라는 목적이 탈퇴자에게는 성립하지 않는다(`domain.md` 12.3).
- **방해금지 시간에 편성 완료**: 08:00으로 지연 발송한다. 지연 중 사용자가 이미 앱을 열어 콘텐츠를 확인했다면 발송을 취소한다.
- **드립 편성은 됐는데 콘텐츠가 곧바로 회수됨**: 발송 직전 유효성을 재확인한다. 남은 콘텐츠가 0이면 발송하지 않는다.
- **같은 날 드립이 두 번 편성됨**(재시도 등): 하루 1회 캡으로 두 번째는 발송하지 않는다.
- **알림 권한은 있으나 사용자가 OS 설정에서 이 앱의 알림을 껐다**: 발송해도 표시되지 않는다. 포그라운드 복귀 시 권한 동기화로 대상에서 제외한다.
- **앱 미설치 상태로 오래 지난 토큰**: 30일 이상 발송 실패한 토큰은 정리한다.

## 8. 완료 조건

- Given 온보딩 마지막 단계 / When [나중에]를 누른다 / Then OS 권한 다이얼로그가 뜨지 않고 라이브러리로 진입한다
- Given 알림 권한을 허용한 사용자(무료 포함) / When 드립 2편이 편성된다 / Then "오늘의 콘텐츠 2편이 도착했어요" 알림이 1건만 발송된다
- Given 알림을 탭한다 / When 앱이 실행된다 / Then 버전 체크·인증 판정을 거친 뒤 라이브러리로 이동한다
- Given 드립 1편이 도착해 콘텐츠 딥링크 알림을 받았다 / When 알림을 탭한다 / Then 해당 콘텐츠 플레이어가 열린다
- Given 무료 사용자가 콘텐츠 딥링크 알림을 탭했고 오늘 한도를 소진했다 / When 플레이어 진입을 시도한다 / Then 페이월이 노출된다
- Given 앱 내 알림 토글이 OFF다 / When 드립이 편성된다 / Then 푸시가 발송되지 않는다
- Given 23:00에 드립 편성이 완료된다 / When 발송 시점을 확인한다 / Then 다음 날 08:00으로 지연 발송된다
- Given 앱이 포그라운드 상태다 / When 드립 알림이 수신된다 / Then OS 배너 대신 인앱 배너가 노출된다
- Given 로그아웃한 기기 / When 이전 사용자에게 드립이 편성된다 / Then 해당 기기로 알림이 가지 않는다

## 미결 사항

- 방해금지 시간(22:00~08:00) 및 발송 기준 시각 확정
- 통근 시간대(예: 07:30) 고정 발송으로 바꿀지 검토 — 타깃이 통근 사용자(PRD 3.1)이므로 편성 직후보다 통근 직전 발송이 효과적일 수 있음
- 마케팅·리텐션 알림(휴면 사용자 리마인드 등) 도입 여부 — 현재 드립 도착 알림만 정의
