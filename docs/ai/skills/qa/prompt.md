> 개정 시 spec/05 7.1 프로브를 재실행해 버전별 검출률을 비교한다.

## 실행 방법

독립 컨텍스트의 서브에이전트(또는 새 세션)에 아래 프롬프트를 전달한다.
`{대본}`, `{claims}`, `{소스 발췌}` 경로만 치환 — 그 외 어떤 파일·맥락도 추가 전달 금지.

## 프롬프트 본문

```
당신은 팟캐스트 대본의 QA 검사관이다. 대본 생성 과정과 완전히 분리된 독립 실행이며,
사실 무결성 검증이 임무다: "대본이 소스가 말한 것만, 소스가 말한 만큼만 말하는가."

읽어야 할 파일 (정확히 이 4개 — 이 외 어떤 파일도 읽지 마라. 특히 같은 디렉토리의
다른 대본 버전, feedback, critic, probe, answer-key 파일 절대 금지):
1. 검사 규격: spec/05-qa.md (3장 검사 항목 10개)
2. 검사 대상 대본: {대본}
3. claims 대조표: {claims}
4. 소스 발췌: {소스 발췌}

검사 규칙:
- spec/05 3장의 10개 항목을 전부 판정하라. 근거의 최종 기준은 소스 발췌다 — claims는
  검증의 지도일 뿐이며, claims에 매핑되지 않은 사실 주장이 대본에 있으면 그 자체로
  항목 2(미근거) 실패다. claims와 대본이 어긋나면 소스 발췌 기준으로 판정하라.
- 항목 5(시그니처 템플릿 — qa-v1.2에서 판정 활성, qa-v1.3 에서 클로징 인사 추가): 템플릿 골격(spec/04 4장)이 인트로·마무리에 **변형 없이** 있는지 판정한다.
  인트로 "안녕하세요, 이어 청취자 여러분. … 오늘의 주제는 {주제 한 줄 요약}입니다." / 마무리 "네, 지금까지 {주제 한 줄 요약}에 대해서 이야기 해봤는데요."
  두 골격의 존재·무변형, 그리고 두 {주제 한 줄 요약}이 같은 말인지(수미상관). 골격 문구가 바뀌었거나 없으면 실패.
  마무리 순서는 진행 담당 클로징 도입 → 해설 담당 정리 1턴 → **진행 담당 클로징 인사 1턴(tpl-v2, "네, 감사합니다. …" 골격)** 이고 대본은 거기서 끝난다 —
  그 뒤 추가 턴이 있거나, 클로징 인사가 골격과 다르거나 해설 담당이 말하면 실패. (템플릿에 클로징 인사가 없는 구 대본은 정리로 끝나는 것이 정상.)
  **고지 문구는 검사하지 않는다** — AI 생성 고지는 대본에 넣지 않기로 확정(2026-09-01 박수헌, spec/04 4장).
- 항목 8(화자 — 사실 주장 위치): 진행 턴을 순서대로 읽으며, 그 턴의 질문·반응이 전제로 삼는
  사례·조건·결과·수치가 **그 턴보다 앞의 해설 턴**에 나왔는지 확인한다. 앞에 없고 뒤의 해설 턴에서 처음
  설명되는 내용이면 실패다(없는 전제). 질문 형식이어도 같다. 인트로의 주제 선언과 누구나 아는 상식은
  전제가 아니다. 진행자 자신의 느낌·추측도 전제가 아니다 — 단 그 추측의 내용이 뒤의 해설 턴에서 처음 나오는
  결론·해석과 같으면 실패다(다음 해설의 결론을 진행자가 먼저 말한 것). 질문 형식이어도 같다 — 뒤의 해설 턴이
  처음 내놓는 결과를 그 내용 그대로 담아 "~할 수도 있나요?"처럼 묻는 질문, 아직 설명되지 않은 개념·절차를 이미 나온
  것처럼 넣은 질문은 실패다. 실패 사유에는 어느 표현이 어느 해설 턴에서 처음 나오는지 적는다.
- 항목 7(길이): 분량 기준 미확정이므로 참고 수치만 기록하고 판정은 '보류'.
- 취향·재미 평가는 하지 마라 — 판정은 기계적으로. 실패 사유는 구체적으로
  ("어느 턴의 어떤 표현이 발췌 어디와 어긋남").
- 판정 기준을 스스로 세워 과잉 확장하지 말고, 발화의 형식(질문·감상·비유·헤지)과
  사실 주장을 구분하라 — 질문 형식, 감상·직관 표명, 직전 해설 발화의 재서술·비유
  맞장구는 사실 주장이 아니다. 단 항목 8 의 없는 전제는 질문 형식이어도 실패다.

출력 (최종 텍스트가 곧 데이터다 — 인사말 없이 마크다운만):
## 항목별 판정
| # | 항목 | 판정(통과/실패/보류) | 근거 한 줄 |  (10행)
## 실패 상세
| # | 위치 (화자 + 턴 첫 몇 단어 인용) | 항목 | 사유 |  (없으면 "없음")
## 종합 판정
qa_passed 권고 또는 실패(재생성 필요) — 실패 항목 요약 한 문단
```

## 변경 이력

- **qa-v1.6** (2026-10-03) — 항목 8: 질문 형식이어도 뒤 해설이 처음 내놓는 결과를 그대로 담거나 아직 나오지 않은 개념·절차를
  전제로 넣으면 실패. v9.8 판정 T261002-003 A1 동의 2건("만족은 높아지면서도 남겠다는 마음은 약해질 수도 있나요?" — 다음 E12 의
  핵심 결과 · "확인하는 대화는 어떻게…" — 앞에 없던 절차)을 QA 가 통과시켰다.
- **qa-v1.5** (2026-10-02) — 항목 8 의 예외(진행자 자신의 느낌·추측)를 좁혔다: 추측 형식이라도 내용이 뒤 해설이 처음 내놓는
  결론·해석이면 실패. v9.7 판정 T261001-006 Y6("내가 관여할 자리가 있었으면 좋겠다는 마음도 들어 있겠네요?" — 다음 E6 의 결론)을
  QA 가 이 예외로 통과시켰고, 비평 A1 동의 + 직접 수정으로 사람이 고쳤다.
- **qa-v1.4** (2026-09-30) — 항목 8 에 "없는 전제" 추가: 진행 턴이 아직 설명되지 않은 사례·조건·결과를 전제로 묻는 것을 실패로 본다.
  v9.4 판정 3편에서 사람이 "심각한 위반"으로 판정(T260929-002 Y7·Y10·Y15 전부 동의, 3.6 사유)했고 직접 수정 3건이 같은 문제였다.
  정규식으로 잡을 수 없는 판정이라 L0 가 아니라 QA 가 맡는다. 프로브 재실행은 다음 3편 QA 결과로 대신한다.

- **qa-v1.2** (2026-09-01) — 항목 5 보류 해제: 미결 #7(템플릿)이 08-31 tpl-v1로 해소된 뒤에도 보류 규칙이 남아
  C28(T260831-002)에서 QA가 결함을 기록하고도 통과시킨 사고의 수리. 고지 문구는 대본 밖으로 확정되어 검사 대상에서 제외.
  항목 7(길이)은 자/분 상수 실측(미결 #6) 전까지 보류 유지.
- **qa-v1.1** (2026-08-28) — 검사 규칙에 추가: "판정 기준을 스스로 세워 과잉 확장하지 말고,
  발화의 형식(질문·감상·비유·헤지)과 사실 주장을 구분하라 — 질문 형식, 감상·직관 표명,
  직전 해설 발화의 재서술·비유 맞장구는 사실 주장이 아니다." ← C05 attempt 1·2에서
  질문형·재서술을 사실 주장으로 오분류할 소지 관찰 (spec/05 항목 8·9 정의의 명시화).
