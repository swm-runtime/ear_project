> 갱신: 2026-08-23 · 이 문서가 파이프라인 명세의 **인덱스이자 기준**이다.
> 단계별 세부 규칙은 [spec/](spec/) 문서에, 실행 현황은 [PIPELINE-STATUS.md](PIPELINE-STATUS.md)에 둔다.

## 1. 개요

**자기계발을 원하는 2030 직장인**(편도 30분 통근 상황 기준)을 위한 오디오 콘텐츠를,
공개된 소스에 근거해 **고정 진행자 2인(윤아·이음)의 대화형 팟캐스트**로 제작하는 파이프라인이다.

- **표준 포맷: 편당 15분 본편.** 한 후보(주제+소스 묶음) = 한 편이 기본이며, 한 편에 완결되지 않는
  군집은 분할 반환한다 ([spec/03](spec/03-backlog.md) 5.1).
- 숏폼(1분~1분 30초)은 정규 포맷이 아니다 — 테스트·데모용으로 제작했고, 추후 유튜브 홍보용
  파생 포맷으로 쓸 여지만 남겨둔다 ([spec/04](spec/04-script.md)).

핵심 성격 세 가지:

- **소스 우선** — 주제를 먼저 정하고 근거를 찾는 것이 아니라, 확보 가능한 소스에서 주제가 도출된다.
- **사람이 결정, AI가 준비** — 주제 승인과 최종 검수는 사람만 한다. AI는 후보 준비·대본 생성·검증을 담당한다.
- **공유 상태** — 풀·후보·진행 상태는 운영 DB(Supabase)에 있고 팀 전체가 같은 것을 본다.

### 주제 체계

| 대분류 | 중분류 | AI 생성 |
|---|---|---|
| 돈 | 재테크, 경제 상식 | 대상 |
| 배움 | 데이터·AI, 심리학, 인문·교양, 글쓰기 | 대상 |
| 일 | 커리어, 생산성, 리더십, 커뮤니케이션 | **배제** (합의 2026-08-09) |

> 이 주제 체계는 **언제든 업데이트될 수 있다.** 단일 진실 원천은 **`topics` 테이블**이며
> (중분류 추가·변경 = 행 편집, AI 생성 배제 여부·해설 페르소나도 여기서 관리), 위 표는 그 반영이다.
> 변경 시 소스 풀의 `topic_coverage`, 페르소나 관할([spec/04](spec/04-script.md))도 함께 갱신한다.

## 2. 전체 흐름

```
[상시]  소스 풀 관리 ──── 사람의 도메인 판정 (LLM 무관)
   │
[수집]  스윕 ──────────── 풀 안의 원천에서 메타데이터만 수집 (원문 미열람)
   ↓
[발굴]  군집화 ────────── "자료 여러 건이 하나의 이야기로 묶이면" 에피소드 후보
   ↓
[대기]  백로그 적재 ───── 후보 = 주제 + 소스 묶음 + 중복 대조 결과
   ↓  ★게이트 1 — 사람이 "주제+소스 묶음"을 승인
[제작]  집기 → 대본 ───── 승인된 소스 원문을 건당 열람 → 2인 대화체 대본 + claims 대조표
   ↓
[검증]  L0 기계 검사 → L1 지시 준수 → QA(사실) → 비평(품질 100점) → L3 이해도 — 앞 층 실패 시 재생성 (spec/09 v2, 최대 3회)
   ↓
[출고]  패키지 ─────────── 업로드 메타 산출
   ↓  ★게이트 2 — 사람 최종 검수
[음성]  TTS ───────────── ElevenLabs 합성 + 오디오 후처리
   ↓
[발행]  업로드·기록 ────── 발행 기록이 이후 중복 대조의 원천이 된다
```

**상태 전이** (backlog.status — DB가 단일 진실 원천):

```
proposed ─승인→ approved ─집기→ claimed → drafted → qa_passed → packaged ─업로드→ published
   │               │                            │
   └ rejected      └ expired          qa_failed ─(3회)→ review_required → qa_passed | rejected
   └ held (사람 판단 보류)
```

## 3. 불변 원칙

이 7개는 단계 명세가 바뀌어도 유지되는 상위 규칙이다. 괄호는 집행 위치.

1. **소스 우선** — 후보는 실소스 군집에서 태어난다. 근거 없는 주제 제안 없음. (spec/03)
2. **풀 안에서만 수집** — 풀 밖 원천은 수집이 아니라 편입 후보 제안만. 차단 계층은 예외 없이 배제. (spec/01·02)
3. **스윕은 메타데이터만, 원문은 승인 후 건당** — 대량 본문 수집을 하지 않는 깔때기 구조가 적법성의 근간. (spec/02·04)
4. **환각 금지 + claims 대조** — 대본의 모든 사실 주장은 열람한 원문에 근거하고, 주장→소스 대조표를 남긴다. (spec/04·05)
5. **소스 3건 하한** — 미만이면 대본을 쓰지 않는다. 단일 소스를 뼈대로 삼지 않는다. (spec/03·04)
6. **사람 게이트 2개** — 주제 승인(게이트 1)과 발행 전 검수(게이트 2)는 사람만 전환한다. 승인자·시각을 기록한다. (spec/03·07)
7. **QA 독립 실행** — 대본을 만든 컨텍스트와 분리된 실행에서, 소스 발췌·대본·claims만으로 판정한다. (spec/05)

## 4. 시스템 구성

```
┌─ Supabase (가동 중) ──────────────┐   ┌─ S3 (도입 예정) ─────────────┐
│ domains  출처 풀 + 계층 판정        │   │ 대본·claims·발췌(비공개)      │
│ sources  스윕 링크+메타데이터       │   │ 오디오 (중간·최종)            │
│ backlog  후보 + 상태 + 승인 기록    │   │ 스윕 원본 아카이브            │
│ runs     실행 기록 (계측 원천)      │   └──────────────────────────────┘
└───────────────────────────────────┘      규칙: DB 행에는 경로만
        ▲ REST/MCP
┌─ 실행기 ──────────────────────────────────────────────────────────────┐
│ 현재:   버전 관리되는 스킬 + 사람 트리거 (Claude Code 세션)             │
│ 로드맵: API 워커(Claude Agent SDK — 스킬 그대로 승계) → 선택 즉시 생성   │
│         TTS: ElevenLabs API                                           │
└───────────────────────────────────────────────────────────────────────┘
        ▲
┌─ 관리 UI ─────────────────────────────────────────────────────────────┐
│ 현재: Supabase 테이블 에디터 (팀원 각자 계정) · 계획: 웹 UI (spec/08)   │
└───────────────────────────────────────────────────────────────────────┘
```

- Supabase: 프로젝트 `akckswokvlosgmzawjuq` (서울 ap-northeast-2). 스키마 원본 [pipeline/supabase/schema.sql](../../pipeline/supabase/schema.sql).
- 접근: 사람 = 각자 계정(승인 기록의 신원), 에이전트 = secret key + `executed_by` 기록.
- 제품 인프라(AWS ECS·RDS)와 **완전 분리**. 발행 오디오의 제품 이관 경로만 S3에서 접속.
