# spec/01 — 소스 풀

> 상위: [PIPELINE.md](../PIPELINE.md) · 관련: [spec/02 스윕](02-sweep.md) · 저장: `domains` 테이블
> 원칙: **풀 안에서는 자유롭게, 풀 밖은 수집이 아니라 편입 제안만.**

## 1. 풀이란

소스로 사용할 수 있는 원천(도메인)의 목록이며, 각 도메인에는 **사람이 판정한 계층**이 붙는다.
적법성 판단을 실행 시점의 LLM 자기 판단이 아니라 **사전 판정된 데이터**로 만드는 장치다.
풀은 사전에 완성하는 목록이 아니라 **운영하며 자라는 자산**이고, 판정 이력 자체가 적법 수집의 증적이 된다.

## 2. 계층 정의

`domains.tier` 값과 1:1 대응한다.

| tier | 계층 | 기준 | 사용 범위 |
|---|---|---|---|
| `allow_open` | 1군 — 자동 허용 | 재사용이 라이선스로 명시 허용(공공누리 KOGL·CC·오픈액세스)되거나, 공공성 기관·기업의 공식 발행물(공식 기술블로그·문서·보도자료) | 제한 없음. **대본의 뼈대 소스 가능** |
| `allow_support` | 2군 — 조건부 | 일반 상업 매체·개인 전문 블로그 중 약관이 AI 재사용을 금지하지 않는 곳 | **보조 근거·사실 교차 확인만.** 뼈대 금지 |
| `blocked` | 차단 — 절대 배제 | 파트너·협의 대상 도메인, 페이월·로그인 뒤 콘텐츠, 약관의 AI 재사용 명시 금지, 기술적 수집 차단(403 등)을 우회해야 접근 가능한 곳 | 검색·스윕 결과에 나와도 채택 금지. **예외 없음** |
| `hold` | 보류 | 판정이 애매한 곳 | 사용 금지. 애매한 원천을 근거로 쓰지 않는다 — 2군으로 내리지 않고 보류한다 |
| `candidate` | 편입 후보 | 발견됐으나 아직 사람이 판정하지 않은 곳 | 사용 금지. 판정 전에는 소스가 될 수 없다 |

- 판정 기준은 "좋은 매체인가"(주관)가 아니라 **"인용되라고 만들어진 원천인가"(객관)** — 판정을 빠르게 한다.
- 계층은 판정의 결과다. 스윕·군집화가 표시하는 계층은 항상 "제안"이며 효력이 없다.

## 3. 도메인 등록 규칙

- **표기 단위는 호스트**다 (`toss.tech`, `techblog.woowahan.com` — `www.` 제거).
- **공유 호스트는 첫 경로 세그먼트까지**로 구분한다 — 발행 주체가 다르기 때문이다.
  예: `medium.com/daangn`, `medium.com/musinsa-tech`, `aws.amazon.com/ko/blogs/korea`.
- 필수 필드: `domain` · `publisher`(발행처명) · `tier` · `category` · `topic_coverage[]`(커버 중분류).
- 수집 경로가 있으면 `feed_url`(RSS/Atom)을 기록한다 — 스윕([spec/02](02-sweep.md))의 입력이다.

## 4. 편입 워크플로

```
[발견]  경로는 셋 중 하나
        ① 시드 리스트업 (사람)  ② 스윕 중 풀 밖 원천 발견 (AI)  ③ 주제 탐색 검색 결과 (AI)
   ↓      AI는 자동 채택하지 않는다 — tier=candidate 행 생성까지만
[판정]  사람이 확인: 라이선스 종류 / 약관의 AI·재사용 조항 / robots / 기관·발행 주체 성격
   ↓
[기록]  tier 확정 + license_basis(판정 근거) + decided_by + decided_at 기입
   ↓
[편입]  다음 실행부터 풀 안에서 사용됨 (allow_open·allow_support만)
```

- 판정·기입은 **사람만** 한다. 도구는 Supabase 테이블 에디터(행 편집) — LLM 세션이 필요 없는 작업이다.
- 약관·robots 확인은 **판정 시점에 1회** 수행한다. 실행 시점의 LLM 판단으로 대체하지 않는다.
- 재판정: 약관 변경·수집 차단 발생 등 사유가 생기면 사람이 계층을 조정하고 `note`에 사유를 남긴다.
  기술적 차단(403 등)이 확인된 도메인은 우회하지 않고 `blocked` 또는 `hold`로 내린다.

### 4.1 판정 체크리스트 — 무엇을 확인하는가

"이 도메인을 소스로 써도 되는가"를 네 가지 확인으로 쪼갠다. 도메인당 5~10분.

| # | 확인 항목 | 어디서 보나 | 판정 영향 |
|---|---|---|---|
| ① | **라이선스 표기** — 재사용 명시 허용 여부 | 사이트 푸터·소개 페이지 (공공누리 마크, CC 표기, 오픈액세스 정책) | 있으면 `allow_open` 확정 근거 |
| ② | **발행 주체 성격** — 공식 발행 채널인가 | 사이트 정체 (공공기관·기업 공식 채널 vs 상업 매체·개인) | 공공·기업 공식 → `allow_open` 방향 / 상업·개인 → `allow_support` 방향 |
| ③ | **약관 금지 조항** — AI 학습·재사용·자동수집 금지 여부 | 이용약관 페이지 (푸터의 약관·Terms) | 명시 금지 → `blocked`. 조항 없음 → 2군 가능 |
| ④ | **접근 구조** — 공개 접근 가능 여부 | 실제 접근 + `도메인/robots.txt` | 페이월·로그인 뒤 → `blocked`. robots 수집 거부 → 강등 신호 |

- 네 확인의 결론으로 **tier 하나를 고르는 것**이 판정이다. 판단이 애매하면 `allow_support`로 내리지 말고 `hold`.
- 공공기관(한국은행 등)은 보통 ①에서 끝난다. 기업 기술블로그는 ②+③, 상업 매체는 ③+④가 관건이다.

### 4.2 판정 작업 절차 — 어디서 어떻게

Supabase 테이블 에디터에서 `candidate` 행을 열어:

1. 체크리스트 ①~④ 확인 (사이트·약관·robots 열람)
2. `tier` 선택
3. `license_basis`에 확인 내용을 구체로 기입 — 예: `"기업 공식 기술블로그. 약관 확인 2026-08-24, 자동수집·AI 재사용 금지 조항 없음"`, `"공공누리 1유형"`, `"CC BY 4.0"`
4. `decided_by`(본인 이름) · `decided_at`(판정일) 기입 — 이 세 필드가 채워져야 판정 완료다

`license_basis + decided_by + decided_at`이 적법 수집 확인의 증적을 겸한다.

### 4.3 판정 보조 (AI 허용 범위)

- AI는 판정에 필요한 **증거 수집까지** 할 수 있다 — robots.txt 내용, 약관 페이지 링크·관련 조항 유무,
  라이선스 표기 발견 여부를 도메인별로 정리해 `note`에 첨부하는 것 (판정 보조 시트).
- 증거가 준비되면 사람의 작업은 "증거를 보고 tier를 고르는 결정"으로 줄어든다 (도메인당 1~2분).
- **tier·decided_by·decided_at의 기입은 어떤 경우에도 AI가 하지 않는다.**

## 5. 법적 안전 규칙

> 일반적 정보이며 법률 자문이 아니다. 변호사 검토 1회는 미결(PIPELINE.md 7장 #1).

기본 구도: 저작권은 **표현**을 보호하고 **사실·아이디어**는 보호하지 않는다. 문제는 구도가 아니라
"어떤 소스를, 얼마나 깊이" 쓰는가이며, 아래 규칙이 그 선이다.

| 규칙 | 이유 | 집행 위치 |
|---|---|---|
| 수집은 풀 안에서만, 공식 제공 경로(RSS 등) 우선 | 약관·부정경쟁 리스크를 판정 시점으로 이동 | spec/02 |
| 스윕은 메타데이터만, 원문은 승인 후 건당 열람 | 대량 복제 회피 — TDM 면책 미입법 환경의 안전선 | spec/02·04 |
| 다중 소스 종합 — 3건 하한, 단일 소스 뼈대 금지 | 한 글의 구성·전개를 따라가면 2차적저작물(번안) 소지. 가장 중요한 법적 완충 — 절대 완화하지 않는다 | spec/03·04 |
| 뼈대 소스는 1군만 | 리스크의 중심을 라이선스 허용 원천에 묶는다 | spec/03·04 |
| 직접 인용은 짧게 + 반드시 귀속 표기 | 인용은 정당한 범위 내에서만 | spec/04 |
| 표현은 전부 재서술 | "사실은 소스에서, 문장은 우리가" | spec/04·05 |
| 페이월·로그인 뒤 콘텐츠 배제 | 접근 통제 우회는 약관·부정경쟁 리스크 직결 | 본 문서(차단 계층) |
| 발췌는 내부 증적으로만 보관, 재배포 금지 | 근거 소멸 대비용 보존이되 발행물에는 재서술만 | spec/04·08(비공개 버킷) |
| 소스 발행일을 대본에 명시 (시의성 주제) | 오래된 재생 시점의 오정보 방지 | spec/04 |

## 6. 현재 상태

- `domains` 49행 등록됨 (2026-08 파일럿 스윕 — 데이터·AI 중분류 중심). **전부 `candidate` — 판정 대기**가
  현재의 최대 운영 부채다 (PIPELINE.md 7장 #2). 제안 계층·수집 실패 사유는 각 행 `note`에 있다.
- 다른 중분류(재테크·경제 상식·심리학 등)의 시드 리스트업은 미착수. 시드 후보 방향은
  구 제안 문서 archive/02(레포 외 보존) 2장의 표를 참조한다 (한국은행·KOSIS·금감원·KDI 등).

## 7. 완료 조건

- Given 1군 도메인의 소스만으로 후보가 구성된다 / When 후보가 백로그에 오른다 / Then 적법성 추가 확인 없이 게이트 1로 진행된다
- Given 2군 소스가 후보의 뼈대로 배정된다 / When 후보를 검증한다 / Then 뼈대 부적격으로 걸려 1군 소스로 교체되거나 반려된다
- Given 차단 도메인이 스윕·검색 결과에 나타난다 / When 소스를 선별한다 / Then 채택되지 않고 편입 후보로도 올라가지 않는다
- Given 풀에 없는 도메인의 자료가 발견된다 / When 스윕이 끝난다 / Then `candidate` 행으로만 기록되고 판정 전에는 사용되지 않는다
- Given 판정이 이뤄진다 / When 행을 확인한다 / Then tier·license_basis·decided_by·decided_at이 채워져 있다
- Given `candidate`·`hold` 도메인의 소스 / When 군집화가 후보를 구성한다 / Then 소스 묶음에 포함되지 않는다
