# spec/02 — 스윕

> 상위: [PIPELINE.md](../PIPELINE.md) · 앞: [spec/01 소스 풀](01-source-pool.md) · 뒤: [spec/03 군집화·백로그](03-backlog.md)
> 저장: `sources` 테이블 · 실행 주체: AI
> 원칙: **메타데이터만 수집한다. 원문 열람은 스윕의 일이 아니다** (게이트 1 승인 후, 대본 단계에서 건당 — [spec/04](04-script.md)).

## 1. 스윕이란

풀 안의 원천에서 **소스의 존재를 발견해 링크+메타데이터를 `sources`에 적재**하는 단계다.
후보 발굴(군집화)의 재료를 만드는 것이 목적이며, 콘텐츠 본문은 수집하지 않는다.

이 "메타데이터만" 원칙은 품질 규칙이 아니라 **적법성 구조의 핵심**이다 — 넓게 훑는 단계는 얕게(발행처가
배포하는 정보만), 깊이 읽는 단계는 좁게(승인된 후보의 소스만 건당). 이 깔때기가 대량 복제를 구조적으로 배제한다.

## 2. 스윕 대상

- `domains`에서 `tier IN (allow_open, allow_support)`인 도메인만. **candidate·hold·blocked는 스윕하지 않는다.**
- 모드 A는 그중 `feed_url`이 있는 도메인을 돈다.
- 파일럿 예외: 풀 판정이 완료되기 전(전부 candidate인 현재)에는 제안 계층 기준으로 스윕하되,
  그 결과로 만든 후보는 게이트 1 전에 판정 완료가 선행돼야 한다 ([spec/01](01-source-pool.md) 6장).

## 3. 두 가지 모드

### 모드 A — 정기 스윕 (RSS/Atom)

- 각 도메인의 `feed_url`을 **1회 요청**해 피드가 담고 있는 항목 전량을 수집한다.
- RSS는 발행처가 "프로그램으로 구독하라"고 공개한 공식 배포 채널이다 — 제공 취지대로의 이용이며,
  페이지 순회(크롤링)가 발생하지 않는다.
- 피드가 주는 만큼만 가져온다(보통 최근 10~25건). 신선도 필터링은 스윕이 아니라 군집화·승인에서 판단한다.

### 모드 B — 주제 탐색 (검색)

- 특정 중분류·주제 키워드로 **풀 도메인 화이트리스트를 걸어** 검색한다. 모드 A가 못 보는
  과거 아카이브와 피드 없는 원천을 메운다.
- 용도: ① 소스 3건 하한 미달 후보의 보강(버릴 후보를 살린다) ② 시의성 주제의 기획 검색
  (주제 가설은 사람이 세우되 근거는 풀 안에서 — 소스 우선 원칙과 충돌하지 않는다)
  ③ RSS가 없거나 죽은 도메인의 소스 발견.
- 검색 결과에서 가져오는 것은 **링크·제목·스니펫뿐**이다. 검색 엔진이 만든 요약 텍스트는
  어떤 산출물의 근거로도 쓰지 않는다 (근거는 승인 후 원문 열람으로만 — 불변 원칙 4).
- 검색 결과에 풀 밖 도메인이 나오면 채택하지 않고 `candidate` 행 생성까지만 한다 ([spec/01](01-source-pool.md) 4장).
- 검색 엔진 선택은 미결(PIPELINE.md 7장 #3) — 1차는 Claude `web_search`(allowed_domains)로 시작한다.

## 4. 수집 규약 (공통)

| 항목 | 규칙 |
|---|---|
| 수집 필드 | `url`(필수) · `title`(필수) · `summary`(피드/검색이 제공한 요약만) · `author` · `published` · `swept_at` |
| 본문 | 수집·저장하지 않는다. 요약 필드에 본문 발췌를 넣지 않는다 |
| 요청 규모 | 모드 A: 도메인당 피드 1회. 모드 B: 질의당 검색 1회. 본문 페이지 요청 없음 |
| 요청 간격 | 자동화(배치) 실행 시 도메인당 최소 1초 간격, 재시도 최대 1회 |
| User-Agent | 통상 브라우저 UA 사용 가능. 단 **기술적 차단(403 등)을 만나면 우회 시도 금지** — 실패로 기록하고 도메인 재판정 제안 |
| 실패 처리 | 피드 오류·차단·빈 피드는 도메인 `note`에 사유 기록. 3회 연속 실패 시 `hold` 강등을 사람에게 제안 |

## 5. 적재 규약

- 적재 대상: `sources` 테이블. `url`이 유니크 키다 — 이미 있는 URL은 갱신(upsert)하고 새 행을 만들지 않는다.
- 각 행은 `domain_id`로 풀과 연결한다. 풀에 없는 도메인의 소스는 **적재하지 않는다** (candidate 제안만).
- 같은 소스가 여러 경로에서 발견돼도(피드+검색, 크로스리스팅) 행은 하나다.
- 스윕 원본(피드 응답의 구조화 덤프)은 아카이브 파일로 보관한다 — S3 예정, 행에는 경로만 (spec/08).

## 6. 실행 시점·트리거·기록

모드는 사람이 고르는 옵션이 아니라 **트리거가 다른 두 진입점**이다 — A는 시간, B는 필요 발생.

| 모드 | 트리거 | 시점 | 현재 운영 | 자동화 후 (spec/08) |
|---|---|---|---|---|
| A | 시간 (주기) | 주 1~2회 — 피드 최신 창(10~25건)이 넘치기 전 | 사람이 정기 실행 | 스케줄러 배치 |
| B-① | 군집화 보강 | 후보 소스가 3건 미만일 때, 군집화가 조건부 호출. 보강해도 미달이면 후보 폐기 | 군집화 절차에 포함 | 파이프라인 자동 호출 |
| B-② | 기획 검색 | 사람이 시의성 주제를 정했을 때 | 사람이 실행 | **사람 트리거 유지** (UI 버튼) |
| B-③ | 편입 시딩 | RSS 없는 도메인이 풀에 편입된 직후 1회 | 편입 후 사람이 실행 | 편입 이벤트에 자동 연결 |

- 인터페이스: `/sweep <중분류>` (모드 A) · `/sweep <중분류> --search "<주제 키워드>"` (모드 B).
- 실행마다 `runs`에 기록한다: `phase=sweep`, `result`(**모드·트리거 사유** + 성공/실패 피드 수·적재 건수),
  `prompt_version`, `artifacts`(원본 아카이브 경로), `executed_by`.
  모드별 기록이 "검색이 실제로 후보를 살리는가" 같은 집계의 원천이 된다.
- `일` 대분류의 중분류가 지정되면 배제 사유를 밝히고 진행하지 않는다 (PIPELINE.md 1장 주제 체계).

## 7. 완료 조건

- Given 풀이 준비된 중분류 / When 모드 A를 실행한다 / Then 1·2군 도메인의 피드만 요청되고, 링크+메타데이터가 `sources`에 적재되며, 본문 요청은 발생하지 않는다
- Given 이미 적재된 URL이 다시 발견된다 / When 적재한다 / Then 새 행이 생기지 않는다 (upsert)
- Given 차단(blocked) 도메인 / When 스윕 대상을 고른다 / Then 요청 자체가 발생하지 않는다
- Given 모드 B 검색 결과에 풀 밖 도메인이 나온다 / When 적재한다 / Then `sources`에 들어가지 않고 `domains`에 `candidate` 행만 생성된다
- Given 피드가 403을 반환한다 / When 스윕이 처리한다 / Then 우회 없이 실패로 기록되고 도메인 `note`에 사유가 남는다
- Given 스윕이 끝난다 / When `runs`를 조회한다 / Then 실행 1건이 결과 요약·실행자와 함께 기록되어 있다
- Given `일` 대분류 주제가 지정된다 / When 스윕을 시작한다 / Then 배제 사유를 밝히고 진행하지 않는다
