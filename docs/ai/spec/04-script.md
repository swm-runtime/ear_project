# spec/04 — 대본 생성

> 상위: [PIPELINE.md](../PIPELINE.md) · 앞: [spec/03 백로그](03-backlog.md) · 뒤: [spec/05 QA](05-qa.md) · 음성 규격: [spec/06](06-audio.md)
> 실행 주체: AI · 입력: `approved` 후보 · 출력: 대본 + claims + 발췌 (S3) · 상태: `claimed` → `drafted`
> 포맷 승계: 구 07-format-persona (2026-08-20 확정 — 레포 외 archive 보존). 포맷·페르소나의 현행 기준은 이 문서 3장이다.

## 1. 이 단계의 역할

승인된 후보의 소스 **원문을 정독**하고(파이프라인에서 원문을 읽는 유일한 지점),
**15분 분량의 2인 대화체 대본**과 근거 대조표(claims)를 생성한다.

## 2. 절차

```
① 집기      approved 확인 → claimed 전환 (claimed_by 기록. 이미 claimed면 중단)
② 원문 정독  소스 묶음의 URL을 건당 열람. 접근 거부(403 등)는 우회하지 않고 해당 소스 제외
③ 발췌 저장  근거 구간을 내부 증적으로 보존 (재배포 금지 — S3 비공개)
④ 재검증    정독 결과 군집이 성립하는가
              ├─ 불성립 → rejected + 사유 기록, 대본 쓰지 않음
              ├─ 한 편에 완결 불가 → 분할 반환 (spec/03 5.1), 대본 쓰지 않음
              ├─ 소스 탈락으로 3건 미만 → 모드 B-① 보강, 그래도 미달이면 반려
              └─ 성립 → 진행
⑤ 배정      중분류의 topics.explainer가 해설, 다른 한 명이 진행 (에피소드 안에서 불변)
⑥ 설계      구성안(outline.md) 작성 — 축·역할표·구간·전환 장치·연결 목록 (2.1)  ← 여기까지가 1단계(원문 있음)
⑦ 작성      새 컨텍스트에서 대본 생성 — 원문 없이 발췌·claims·구성안만으로 (2.1)  ← 2단계(원문 없음, 단발 호출)
⑧ 저장      산출물 업로드(8장) → status = drafted → runs 기록
```

②에서 원문에 근거해 판단이 바뀌는 것(④)은 오류가 아니라 예정된 검증이다 —
메타데이터 군집화의 한계를 이 단계가 흡수한다.

### 2.1 초안 2단계 — 설계와 작성의 분리 (2026-09-08, "축이 이끄는 파이프라인" ③)

구 방식은 한 실행이 정독부터 대본까지 했다. 그 결과 대본이 소스를 순서대로 설명하는 순회형이 되고,
원문을 보면서 쓰다 보니 발췌 밖 주장(귀속 확장·헤지 제거·장면 덧붙임·세부 확정)이 생겨 QA가 3회차까지
갔다(완료 19편 중 1회차 통과 4). 실험(C28, 2026-09-08)에서 설계·작성을 분리하고 규칙을 넣자 같은 소스로
QA 실패가 5→2로 줄었고, 남은 2건도 "발췌보다 구체적으로 쓴" 표현 층위였다.

| 단계 | 컨텍스트 | 입력 | 산출물 | 실행 형태 |
|---|---|---|---|---|
| **1 설계** | 원문 있음 (파이프라인에서 원문을 읽는 유일한 지점) | 소스 본문(코드가 가져와 문단 ID 부여) · guidelines · spec/04 · 골드 **전부 인라인** | `sources.md`(넉넉한 발췌 — 소스당 10~20항목, **모델이 문단 ID 를 고르면 워커가 원문 그대로 옮긴다**) · `claims.md` · `outline.md`(구성안) · `pronunciations.json` | **단발 호출** (도구 없음, 기본) — `DESIGN_MODE=agent` 면 구 방식(WebFetch · 파일 쓰기 루프) |
| **2 작성** | 원문 없음 — 새 프로세스 | 1단계 산출물 + 규칙·골드·템플릿 **전부 인라인** | `script.md` · `script-notes.md`(새 연결·비유 · 자기 점검 · 턴별 claims) | **단발 호출** (도구 없음) — 대본을 완료 보고로 돌려주고 파일은 워커가 쓴다 |

- **구성안은 계약이다.** 축(대립·역설·재정의 중 하나 — "X란 무엇인가"형은 축이 아니다) · 착지 구간 · 역할표(근거 앵커·사례·반론·수치·역사) ·
  구간 4~6개(각 구간에 소스 2개 이상 — 소스 단위 구간 금지) · 구간별 진행자 질문·전환 장치 · 연결·비유 목록 · 마무리 한 줄.
  2단계는 구간 순서·목적·재료를 그대로 실행하고, 워커의 L0가 구간 수·순서와 분량 하한을 기계로 검사한다.
- **2단계가 쓸 수 있는 사실은 claims 뿐이다.** claims 를 옮길 때 헤지·귀속 주체를 그대로 두고, 소스 예시에 장면을 덧붙여 소스 귀속 문장에
  넣지 않으며, **발췌보다 구체적으로 쓰지 않는다**(성별·관계·순서·위치·수량). 소스 사이를 잇는 해석·비유는 사실이 아니라 대본이 만드는
  것이며 `script-notes.md`에 전부 기록한다 — QA 대상이 아니고 비평이 본다.
- **분량**: 설계가 재료 총량으로 예상 분량을 적는다. 13분 미만이면 구성안을 만들지 않고 반려 사유를 보고한다. 26분 이상이면 각 편 13분
  이상이 되는 분할안을 보고하되 구성안은 한 편으로 만든다 — 분할은 사람이 결정한다(spec/03 5.1).
- **소스 본문은 코드가 가져온다** (2026-09-08 비용 절감 ③): Readability 와 article/main 블록 추출 중 큰 쪽, 문단마다 `S{n}-{NN}` ID.
  403·429·robots 는 우회하지 않고 그 소스를 제외한다(불변 원칙 2). 발췌 본문을 모델이 쓰지 않으므로 인용 환각이 구조적으로 없고
  설계 출력 토큰이 claims·구성안만으로 준다.
- **반입 범위 (2026-09-09 프롬프트 슬림화)**: 두 단계 모두 이 문서는 **규격 장만** 넣는다 — 작성은 3~6장, 설계는 3·4·6·7장 (절차·산출물·숏폼·완료 조건은
  모델이 볼 이유가 없다). 골드는 그 에피소드와 **같은 역할 배치 1편**만(이음 해설 → 골드 A, 윤아 해설 → 골드 B). guidelines 를 요약해 되풀이하던
  리마인드 블록은 없앴다 — 규칙은 guidelines 한 곳에만 있다. 대본 프롬프트의 규칙 몫 33K자 → 22K자.
- **차단 도메인은 가져오지 않는다** (2026-09-10): 후보 소스의 도메인 tier 가 `blocked`(사람 판정)면 페이지가 열려도 fetch 하지 않고 "차단 도메인"으로 제외한다 — 접근 실패와 같은 경로(3건 하한 → 자동 반려). 소스 풀에서 지워도 후보 행의 URL 사본은 남기 때문이다.
- **이미 쓴 문단은 제외한다** (2026-09-10, T260910-005↔013): 후보의 소스를 **다른 후보의 편**이 이미 썼으면 그 편의 `sources.md` 발췌와 같은 문단은
  설계 프롬프트에서 본문을 빼고 자리(⛔)만 남긴다 — 모델은 고를 수 없고 남은 대목으로 다른 이야기를 쓰거나 그 소스를 제외한다. 제외 문단을 excerpt_ids·claims 에
  넣으면 설계 실패. 소스(URL) 단위로 막지 않는 이유: 풀이 작은 대분류는 소스 금지가 곧 편수 제한이다. 같은 소스를 두 편이 써도 같은 문단을 같은 방식으로 두 번 풀 수는 없게 하는 것이 목적이다.
  `sources.md` 머리와 완료 보고 self_check 에 제외 문단 수를 적는다.
- 워커 토글 `DRAFT_MODE`(기본 `two-stage`, `single`로 구 방식). `prompt_version`에 `+2stage`를 붙여 방식별 통과율·비용을 집계한다.
  단계별 모델은 `DRAFT_DESIGN_MODEL`·`DRAFT_WRITE_MODEL`.

## 3. 포맷 — 2인 대화체

모든 정규 에피소드는 **고정 진행자 2인의 대화형 팟캐스트**다. 1인 낭독은 채택하지 않는다.

### 페르소나 (고정 자산 — 변경은 리브랜딩급 결정)

| | **윤아** | **이음** |
|---|---|---|
| 프로필 | 20대 여성, 문과(인문·사회) 출신 | 20대 남성, 이과(공학·데이터) 출신 |
| 관할 (해설 담당) | `topics.explainer = '윤아'`인 중분류 — **심리·마음 · 인문·교양** 대분류 전체(+ 자격증·시험의 한능검) | `topics.explainer = '이음'`인 중분류 — **그 외 전부**(돈·경제 · 비즈니스 · 과학·기술 · 자격증·시험) |
| 해설일 때 | 개념을 이야기·맥락으로 풀어냄. 수치·인용은 소스 귀속("~라고 합니다") | 구조·원리부터 잡는 설명. 숫자에 강하고 비유로 환산("월급으로 치면 ~") |
| 진행일 때 | 청취자 눈높이 질문, 공감 리액션, 화제 전환 | 꼬리 질문("그게 왜 그렇게 돼요?"), 정리 습관("그러니까 요점은…") |
| 말투 | 구어체, 부드러운 문장, 과장 없는 리액션 | 구어체, 간결한 문장, 담백한 톤 |

### 역할 규칙

- 에피소드의 중분류 관할자가 **해설**, 다른 한 명이 **진행**. 역할은 한 에피소드 안에서 바뀌지 않는다.
- 대본 메타에 `해설: 윤아|이음`을 명시하고, 턴은 `[윤아]` / `[이음]` 라벨로 표기한다.
- 질문의 방향은 고정하지 않는다 — 에피소드당 1~2회, 해설 담당이 진행 담당에게 되묻는
  **역질문**을 둘 수 있다 (full-v3). 이때도 진행 담당의 답변은 감상·직관·경험적 추측까지만
  (금지 규칙 1·2는 역질문 답변에도 적용).

### 금지 규칙 (환각 방지·품질 방어)

1. **사실 주장(수치·인용·고유명사·인과)은 해설 담당의 턴에서만** — claims 매핑을 한 화자로 모은다.
2. 진행 담당의 리액션은 놀람·공감·질문·요약 요청까지. **주장 강도를 올리는 리액션 금지** ("와, 그럼 무조건 ~겠네요" 류).
3. **개인 경험 서사 금지** — 가공의 사담·일화는 소스에 없는 사례 추가다. 페르소나의 배경은 설명 방식의 색깔이지 경험담의 소재가 아니다.
4. **시점 고정 표현 금지** ("지금·요즘·최근·오늘") — 오디오는 발행 후에도 계속 재생된다. 날짜는 절대 표기.
5. **유도 질문 금지** (full-v2) — 진행자의 질문은 답을 모르는 사람의 진짜 궁금증이어야 하며, 다음 해설을 셋업하는 티가 나면 안 된다.
6. **진행자는 관찰자 시점** (full-v2) — 내용의 당사자가 아니다. 감정·판단은 추측형("~것 같은데요?")으로 하고, 단순 복창 맞장구를 연발하지 않는다.

## 4. 에피소드 구조·분량

```
[인트로]   고정 시그니처 멘트 (tpl-v1 골격 고정, {슬롯}만 채움)
[도입]     주제 선언 직후 청취자가 "대화에 앉는" 짧은 구간 — 질문 + 두세 턴 (full-v5.1 규칙 13, 구 "본론 직행 금지" 폐기)
[본문]     진행 질문 ↔ 해설 턴 반복. 소제목 경계마다 진행 담당이 화제 전환
[마무리]   진행 담당 클로징 도입 → 해설 담당 정리 1턴 → 진행 담당 클로징 인사 1턴 (tpl-v2, 2026-09-09 — 마지막 턴은 진행 담당)
```

### 줄 문법 — TTS 파서 계약 (2026-09-03 명문화)

대본은 그대로 TTS 입력의 원본이다(표기 이원화, 5장). 아래 문법이 변환 파서(spec/06 4장)와의
계약이며, 위반은 L0 형식 검사(spec/09 6.2 "대본 형식 계약")가 draft 직후 기계로 잡아
재생성 연쇄(spec/05 4장)로 보낸다.

| 요소 | 문법 | 예 |
|---|---|---|
| 구역 헤더 | `## [구역명]` — 구역명은 위 구조의 4개 그대로. `[콜드오픈]` 구역은 **폐지**(2026-09-07) — 있으면 L0 위반 | `## [본문]` |
| 번호 턴 | `[화자] {E\|Y}{n} · 문장` — 화자 라벨이 먼저, 번호 뒤 구분자는 **가운뎃점(·)** | `[윤아] E1 · 오늘 이야기는…` |

- 해설 턴은 `E{n}`, 진행 턴은 `Y{n}` — 각각 1부터 연번.
- `E1.`(마침표)·`E1 [윤아]`(번호 선행) 같은 변형 금지 — 2026-09-03 실측(T260903-001·003)에서
  이 변형이 TTS 파싱 실패와 잔존 오탐을 냈다. 파서는 방어적으로 일부 변형을 수용하지만
  계약의 기준은 이 표다.

- **대본 말미의 출처 나열은 하지 않는다** (full-v2) — 출처 고지는 서비스 화면이 담당한다.
  대본에서는 직접 인용 직전의 귀속("~에 따르면", "~라고 합니다")만 한다.

- 턴 길이: 해설 1턴 = 2~5문장, 진행 1턴 = 1~2문장을 **에피소드 평균**으로 유지하되,
  구간별 변주를 허용한다 (full-v3) — 짧은 턴이 빠르게 오가는 구간(사례·놀람)과 해설이
  길게 이어지는 구간(원리·맥락)을 교차시킨다. 긴 독백 금지는 유지.
- **AI 생성 고지는 대본에 넣지 않는다** (2026-09-01 박수헌 확정) — 출처 고지와 마찬가지로 서비스 화면이 담당한다.
  인트로/마무리에는 tpl-v1 시그니처 골격만 들어간다.
- **시그니처 템플릿 확정** (tpl-v1, 2026-08-31 박수헌 — 구 미결 #7 해소). 골격은 고정이고 `{슬롯}`만 에피소드별로 채운다.
  단일 진실 원천은 `settings` 테이블의 `templates` 행이며(웹 UI 설정 화면에서 편집), 대본 생성 시 워커가 주입한다.

  ```
  [인트로 — 진행 담당 1턴]
  안녕하세요, 이어 청취자 여러분. {대주제 한 줄} 오늘의 주제는 {주제 한 줄 요약}입니다.
  {이후 주제와 관련된 질문으로 시작}

  [마무리 — 진행 담당 → 해설 담당 → 진행 담당]
  네, 지금까지 {주제 한 줄 요약}에 대해서 이야기 해봤는데요. {요약에 앞선 진행자의 한마디}
  {이후 해설 담당이 내용 정리}
  {클로징 인사 — tpl-v2 (2026-09-09 박수헌): 인트로처럼 고정 골격 + {슬롯}. settings templates.closing_signoff. 대본의 마지막 턴}
  ```

  - `{대주제 한 줄}`은 **대분류별 고정 문구**다 (settings `templates.major_lines`) — 채널 아이덴티티이므로 에피소드마다 바꾸지 않는다.
  - `{주제 한 줄 요약}`은 인트로와 마무리에서 **같은 말**로 쓴다 (수미상관).
  - `{…질문}`·`{…한마디}`는 매번 새로 쓴다 — 예시 문구 복제 금지 (골드 관용구 복제가 4편 연속 지적된 사안).
  - **클로징 인사** (tpl-v2, 2026-09-09 박수헌 — "오프닝처럼 닫는 인사가 있어야 한다"): 해설 담당의 정리 턴 뒤에 진행 담당이 고정 골격으로
    한 턴 더 말하고 끝난다. 골격은 settings `templates.closing_signoff` 가 진실이고(한 줄에 하나 — **여러 골격이면 에피소드마다 돌아가며** 쓴다, 도입 방식과
    같은 방식), 비어 있으면 tpl-v1(정리로 끝). L0 가 "마지막 턴 = 진행 담당 + 골격 머리 문구"를 기계로 검사하고, QA 항목 5 가 골격 무변형을 본다. 골드 3편은 tpl-v1 이라 이 턴이 없다 — 템플릿이 골드보다 우선한다.
- **콜드 오픈은 폐지** (2026-09-07 박수헌 — 구 미결 #9 최종 해소). 2026-08-28 채택(롤모델 3/3 쇼 공통, 발췌 방식) 후
  오디오 파일럿 청취를 거쳐 쓰지 않기로 확정했다. 대본은 **인트로부터 시작**하고, `[콜드오픈]` 구역이 있으면 L0 형식
  위반으로 재생성한다. 오디오는 앞뒤 2초 무음으로 여백을 만든다(spec/06 7장). guidelines 규칙 11은 폐지 표기로 남긴다.
- **분량 (2026-09-08 확정, 박수헌): 하한 13분은 필수, 15분은 평균 목표, 상한 없음.** 재료가 길면 늘어나도 되며
  채우기 잡담·반복만 금지한다. 글자 수 환산은 공백·기호 제외 350자/분(13분 ≈ 4,000자) — 워커 L0가 하한을 검사한다.
  분할은 나눈 편이 모두 13분 이상일 때만(23분이면 한 편, 26분 이상이라야 두 편 — spec/03 5.1).

## 5. 낭독 규격 (TTS 방어)

| 규칙 | 예 |
|---|---|
| 표·URL·괄호 주석·마크다운 장식 금지 | 참조는 말로 풀어서 |
| 숫자는 읽는 대로 표기 | "백칠 분", "백팔십팔만 달러" |
| **표기 이원화** (full-v2, 2026-09-12 개정) — 대본은 가독 표기(AI, HuggingFace, 17,000번), 음차 변환은 TTS 입력 생성 시 치환 테이블이 수행. **인명은 원문 표기**(Hemingway), **기관·지명·매체는 한국어 관용 표기**(플로리다 주립대, 뉴욕 연준) | 인명을 한글로 음차하지 않는다. 기관을 원문 그대로 읽으면 기계 같다(박수헌). 치환 규칙은 [spec/06](06-audio.md) 6장 |
| 일시정지는 말줄임표(…)로 | 연출 태그로 속도·정지를 조절하지 않는다 |
| 연출 태그(감정 등)는 [spec/06](06-audio.md) 규격을 따름 | `[curious]` 등 — 최소 사용 |

어색하게 합성되는 단어의 음차 보정은 TTS 변환층의 전역 사전에서 관리한다 (spec/06 6장).
대본에 등장하는 비한글 표기(영문 용어·인명·기관·매체)는 생성 시 `pronunciations.json`에
한글 발음을 함께 등재한다 (8장) — 전역 사전과 겹치면 병합에서 전역 사전이 우선하므로 겹침은 무해하다.

## 6. 소스 사용 규칙

- 근거는 **정독한 원문에서만** — 검색 요약·메타데이터 요약을 근거로 쓰지 않는다.
- 뼈대 소스(1군)가 서사의 중심 — 단 **에피소드의 축은 주제(개념·원리·질문)**다 (2026-08-28 원칙:
  이어는 소식 전달 서비스가 아니다). 사건성 소스는 축을 설명하는 사례로 쓰며, 에피소드 전체가
  하나의 사건의 전말을 추적하는 구성은 금지.
- 직접 인용은 짧게, 반드시 화자 귀속("~라고 합니다")과 함께. 표현은 전부 재서술.
- **귀속은 두 등급이다** (2026-09-09, guidelines 규칙 20~22): 직접 인용·수치·특정인 의견·논쟁적 주장은 **필수 귀속**, 개념·원리·정의·널리 알려진 사실은
  **귀속 불필요** — 해설자가 자기 말로 설명한다. 사실 검증은 claims 대조표(7장)로 하므로 문장에 출처가 없어도 QA 대상이 아니다.
  매체명·저자명은 근거 앵커의 첫 소개·직접 인용·특정인 의견에만 쓰고(소스당 최대 2회, 이름이 나오는 소스 2~3곳), 나머지는 익명 귀속.
  소스는 한 번만 소개하고 "아까 그 기사"식 되돌림을 쓰지 않는다. L0 가 귀속 표현이 있는 해설 턴 비율을 재어 60% 초과면 재생성한다
  (개정 전 실측: 3편 모두 70~76% — 대본이 주제가 아니라 소스를 소개하는 것처럼 들린 원인).
- 시의성 주제는 소스 발행일을 대본에 명시한다.
- 원문에서 확인하지 못한 사실은 **뺀다** — 요약·발췌만으로 맥락이 불확실한 주장(오귀속 위험)은
  사용하지 않고, 뺐다는 사실을 claims에 기록한다.

## 7. claims 근거 대조표

- 매핑 단위: **발화 턴** (해설 턴 E1…, 진행 턴 Y1…). 2단계 초안의 claims 표에는 **귀속 등급 열**(필수/불필요, 6장)이 있다 — 설계가 표시하고 대본이 따른다.
- 각 사실 주장에 대해: 주장 → 소스(발췌 번호) → 근거 구간·재서술 방식.
- 함께 기록할 것: 화자 규칙 점검 결과(진행 턴에 사실 주장 없음, 리액션 강도), 주장 강도가
  소스보다 세지지 않았는지 자기 점검, 의도적으로 뺀 사실과 사유, 시점 표현 점검.
- claims는 QA([spec/05](05-qa.md))의 입력이다 — 검사 가능하게 쓴다.

## 9. 숏폼 파생 (비정규 포맷)

- 숏폼(1분~1분 30초)은 정규 파이프라인의 산출물이 아니다 — 테스트·데모용으로 제작했고,
  추후 유튜브 홍보용으로 쓸 여지만 남긴다.
- 파생 제작 시 규칙: **본편의 claims 범위 안에서만** 압축한다 (새로운 사실 주장 추가 금지).
  포맷·낭독 규격·금지 규칙은 본편과 동일하게 적용하며, 발행 전 사람 검수를 거친다.

## 10. 완료 조건

- Given `approved`가 아닌 후보 / When 대본 생성을 시도한다 / Then 시작되지 않는다
- Given 정독 결과 군집 불성립 / When 처리한다 / Then 대본 없이 반려되고 사유가 기록된다
- Given 한 편에 완결 불가한 군집 / When 처리한다 / Then 분할 반환되고 대본이 생성되지 않는다 (spec/03 5.1)
- Given 재테크 주제의 대본 / When 메타와 턴을 검사한다 / Then `해설: 이음`이고, 수치·인용·고유명사가 이음의 턴에만 존재한다
- Given 심리학 주제의 대본 / When 역할을 확인한다 / Then 윤아가 해설, 이음이 진행이다
- Given 완성 대본 / When 발화 텍스트를 검사한다 / Then 표·URL·시점 고정 표현이 없다 (영문은 가독 표기로 허용 — 음차는 TTS 변환층 검사, spec/06)
- Given 대본의 모든 사실 주장 / When claims를 대조한다 / Then 각 주장이 발췌의 근거 구간으로 연결된다
- Given 인트로·마무리 / When 시그니처를 확인한다 / Then 템플릿(tpl-v2) 골격이 변형 없이 포함되고 {슬롯}만 채워져 있으며, 고지 문구가 없고 마지막 턴은 진행 담당의 클로징 인사다(템플릿에 클로징 인사가 비어 있으면 해설 정리로 끝난다)
- Given 서로 다른 에피소드 2편 / When 페르소나를 비교한다 / Then 이름·말투·역할 규칙이 동일하다
- Given 생성된 대본 / When 구역 헤더를 검사한다 / Then `[인트로]`·`[도입]`·`[본문]`·`[마무리]` 4개뿐이고 `[콜드오픈]` 구역이 없다 (2026-09-07 폐지)
