# spec/06 — 오디오 (TTS·후처리)

> 상위: [PIPELINE.md](../PIPELINE.md) · 앞: [spec/07 발행](07-publish.md)의 게이트 2 **통과 후** 실행 · 대본 규격: [spec/04](04-script.md)
> 실행 주체: AI + 사람(청취 확인) · 입력: 검수 통과 대본 · 출력: 오디오 (S3)
> 엔진: **ElevenLabs Eleven v3** (2026-08 파일럿 기준 채택. 비용 대안 비교는 archive/06 참조)

## 1. 이 단계의 역할

게이트 2를 통과한 대본을 **두 화자의 음성**으로 합성하고, 후처리를 거쳐 발행 가능한
오디오 파일을 만든다. 대본 내용의 수정은 이 단계의 일이 아니다 — 합성 중 대본 결함이
발견되면 수정하지 않고 검수(게이트 2)로 되돌린다.

## 2. 보이스 — 채널 아이덴티티

- **보이스 확정 (2026-09-02 박수헌 — 구 미결 #8)**: 윤아 = **Annie** (`Lb7qkOn5hF8p7qfCDH8q`, ko·female·professional) · 이음 = **Yohan Koo** (`4JJwo477JUAx3HV0T7n7`, ko·male·professional). 코드 기본값은 `apps/worker/src/config.ts` — env(`TTS_VOICE_*`)로 덮을 수 있으나 보이스 변경은 리브랜딩급 결정이다.
  보이스 변경은 리브랜딩급 결정이다 — 에피소드마다 바뀌지 않는다.
- 선정 기준: **한국어 네이티브 보이스** (외래어를 자연스러운 한국식 발음으로 읽는 것이 필수) ·
  두 화자의 톤 대비 확보 · 전문 보이스 클론(PVC)은 v3 미최적화로 회피.
- 발화 속도 설정값(speed)도 보이스 ID와 함께 확정·고정한다 — 속도는 채널 아이덴티티에 속한다.

## 3. 합성 방식

**다중화자 1콜(Text to Dialogue) 확정** (2026-09-02 박수헌 — 구 미결 #8). 구현: `apps/worker/src/stages/tts.ts` — 요청당 ~1,800자(문서 권장 2,000자)로 턴 경계 분할, seed 는 에피소드 고정. 예외 하나: **콜드오픈 발췌 원본 턴만 단독 합성**(with-timestamps)해 그 오디오를 본편과 콜드오픈 절단에 공용한다 — 7장 "별도 합성 금지"를 지키기 위해서다.

| | 다중화자 1콜 (Text to Dialogue) | 턴별 합성 + 이어붙이기 |
|---|---|---|
| 방법 | 턴 배열 `{text, voice_id}`을 한 요청으로 | 턴마다 단일 TTS 호출 → 무음 갭 삽입 → 연결 |
| 장점 | 화자 간 톤 연속성·자연스러운 주고받기 | `speed` 설정 사용 가능 · **턴 타임스탬프 부산물** (스크립트 싱크 대비) · 길이 제약 없음 |
| 제약 | 요청당 권장 글자 수 제한 → **15분 대본은 분할 호출 필수** · 설정이 stability뿐 (speed 없음) | 턴 사이 간격·톤 연속성을 직접 관리 |

- 15분 본편(약 5,000자)은 어느 방식이든 단일 호출로 끝나지 않는다 — 분할 지점은 반드시
  **턴 경계**로 한다 (문장 중간 분할 금지).
- 재합성 여유를 예산에 반영한다 (발음·태그 문제로 부분 재합성 발생 — 파일럿 실측 전 가정 30%).

## 4. 대본 → TTS 입력 변환

- **정규화는 이 단계의 별도 전처리다** (2026-09-01, CoreaSpeech NeurIPS'25 근거): 숫자·영어 차용어·코드 스위칭·특수문자를 한글 발음으로 바꾸는 정규화기(N2gk+ 방식)가 TTS 아키텍처와 무관하게 품질을 올린다. 대본은 가독 표기를 유지하고(spec/04 5장 표기 이원화) 여기서만 치환한다 — QA 항목 6이 영문 표기를 위반으로 잡던 것은 검사 위치가 틀렸던 것. 숫자 발음이 첫 실패 지점일 가능성이 높으므로 클린/노이즈/숫자 세트로 나눠 검수한다(8장).


| 대본 표기 | 처리 |
|---|---|
| `[윤아]` `[이음]` 화자 라벨 | **TTS 입력 텍스트에 포함하지 않는다** — voice_id 매핑으로 소거 |
| `[curious]` 등 오디오 태그 | 텍스트에 포함해 전달 (5장 규격) |
| `{인트로 템플릿}` 등 플레이스홀더 | 변환 전 **반드시 실제 템플릿 문구로 치환 완료**되어 있어야 한다 — 남아 있으면 합성 중단 |
| 가독 표기 (AI, HuggingFace, 숫자 등) | **병합 사전으로 음차 치환** ("AI→에이아이", "17,000→만 칠천") — 전역 사전 + 에피소드 발음 맵 (6장). 대본은 원표기, TTS 입력만 음차 (표기 이원화, spec/04 5장) |
| 말줄임표(…) | 그대로 전달 (일시정지 연출) |

변환 전 검증: 사전 적용 **후** 잔존 영문·표·URL이 없는지 기계 검사한다 — 잔존 영문은 사전 누락이므로 합성을 중단한다. 처리는 웹에서 한다(코드 배포 불필요): 에피소드 발음 맵(에피소드 상세 "발음" 탭) 또는 전역 사전(`/assets`)에 추가하고 재시도한다 (6장).

## 5. 오디오 태그 규격

- 형식: 영문 소문자 대괄호. **문서 확인 태그만 기본 사용**: `[curious]` `[surprised]` `[sighs]` `[exhales]` `[laughs]` `[whispers]` `[excited]`.
- 검증 대기 목록: `[chuckles]` (골드 예시에서 사용 — 파일럿 반응 확인 후 승격/제거).
- 미확인(커뮤니티 통용) 태그는 파일럿에서 보이스별 반응을 확인한 뒤 이 목록에 추가한다.
  반응 없는 태그는 대본에서 제거한다.
- 최소 사용 원칙: 턴당 최대 1개 수준 — 페르소나의 "과장 없는 리액션"(spec/04)이 태그에도 적용된다.
- 속도·일시정지를 태그로 조절하지 않는다 — 속도는 6장, 정지는 말줄임표.
- 태그는 연출 지시이며 사실 주장이 아니다 — claims 대상은 아니나, 리액션 태그의 강도는
  QA 화자 항목(spec/05 9번)의 검토 범위다.

## 6. 속도·발음

**속도** — 공식 속도 태그는 없다. 조절 수단은 우선순위대로:

1. 턴별 합성 시: voice settings `speed` (0.7~1.2) — 화자별 고정값
2. 다중화자 1콜 시: 설정 불가 → 후처리 배속 (ffmpeg atempo 1.05~1.1 — 이 범위는 음질 영향 미미)
3. 텍스트 구조 (문장 길이·말줄임표) — 미세 조정용

**발음** — 표기 이원화(spec/04 5장)에 따라 음차는 이 단계의 **병합 사전**이 전담한다. 사전은 두 층이다 (2026-09-03 확정 — 이전의 "코드 내 치환 테이블" 방식을 대체):

- **전역 사전 (표준 음차 사전)** — 진실은 DB `prompt_assets`의 `skills/tts/pronunciation.json` (규약은 spec/10 3.2와 동일: 웹 `/assets`에서 새 버전(draft) → 활성화, git `docs/ai/skills/tts/pronunciation.json`은 export 스냅샷). 형식은 `{"표기": "발음"}` JSON 객체. 프롬프트 번들과 달리 **에피소드에 고정되지 않는다** — TTS 단계는 항상 active를 읽으므로, 사전을 고치면 같은 에피소드 재합성에 즉시 적용된다. 어색하게 합성되는 항목의 보정(띄어쓰기 등)도 여기서 갱신해 다음 에피소드부터 재사용한다.
- **에피소드 발음 맵** — 대본 단계가 대본 속 비한글 표기의 발음을 `pronunciations.json`으로 함께 산출한다(spec/04 5장·8장). 웹 에피소드 상세 "발음" 탭에서 확인·수정한다. 에피소드마다 새로 나오는 고유명사(인명·기관·매체)는 이 층이 흡수하고, 전역 사전에는 재등장하는 일반 항목만 승격해 쌓는다.
- 병합 규칙: **겹치는 표기는 전역 사전이 이긴다** — 사람이 다듬은 표준이 자동 생성값보다 우선. 에피소드별 예외 발음이 필요하면 전역 사전에서 해당 표기를 빼거나 대본 표기를 바꾼다.
- 규모 확대 시 ElevenLabs 발음 사전(alias 치환: "AI→에이아이")을 등록해 대본에 영문이
  잔존해도 합성 단계에서 잡는 안전망을 둔다 (음소 규칙은 v3 제약이 있으나 alias는 무관).

## 7. 후처리·파일 규격

- 배속: 6장 규칙 외의 임의 배속은 하지 않는다. 화자별 선택 배속(피치 분리 후처리)은
  데모용 예외 도구였다 — 정규 경로는 합성 설정에서 해결한다.
- 라우드니스 정규화: 배포 전 음량을 일정 기준으로 정규화한다 (기준값은 파일럿에서 확정).
- 파일: **마스터(무손실 wav)와 배포본(mp3 128kbps)을 모두 보관**한다 — 재처리는 항상 마스터에서.
- **콜드 오픈은 재합성하지 않는다** (2026-08-28, 박수헌 — T260828-002 판정 #1 사유): 콜드 오픈과
  본편의 해당 대목은 같은 문장이지만 TTS가 매번 다르게 읽을 수 있다. 콜드 오픈은 발췌라는
  정체성상 완전히 동일하게 들려야 하므로, **본편 합성 오디오에서 해당 구간을 잘라 붙여** 만든다
  (별도 합성 금지). ※ 콜드 오픈 채택 자체는 오디오 파일럿 청취 후 확정 유보 상태 (미결 #9).

## 8. 검수·기록

- 합성 후 **사람이 청취 확인**한다 (발행 전 마지막 사람 개입): 발음 오류 · 태그 오반응 ·
  속도 체감 · 화자-보이스 매핑 오류. 문제 시 해당 턴만 부분 재합성한다.
- 대본 결함(내용·사실)이 발견되면 재합성이 아니라 **게이트 2로 반환**한다 (1장).
- 산출물 S3 업로드: 마스터·배포본·(턴별 합성 시) 타임스탬프. 경로를 `runs.artifacts`에.
- `runs` 기록: `phase=tts`, `result`(합성 방식·재합성 여부), `executed_by`.

## 9. 완료 조건

- Given 게이트 2를 통과하지 않은 대본 / When 합성을 시도한다 / Then 시작되지 않는다
- Given 플레이스홀더(`{…}`)가 남은 대본 / When 변환을 시작한다 / Then 합성이 중단되고 사유가 기록된다
- Given 완성 오디오 / When 화자 보이스를 확인한다 / Then 이 문서에 고정된 보이스 ID와 일치한다
- Given 15분 대본 / When 분할 합성한다 / Then 모든 분할 지점이 턴 경계에 있다
- Given 발음 보정이 발생한다 / When 처리한다 / Then 표준 음차 사전에 기록되어 다음 에피소드에 재사용된다
- Given 정규화 후 영문이 잔존한다 / When 합성한다 / Then 합성이 중단되고, 웹에서 발음 맵·전역 사전 추가만으로(코드 배포 없이) 재시도할 수 있다
- Given 전역 사전과 에피소드 발음 맵에 같은 표기가 있다 / When 병합한다 / Then 전역 사전 값이 적용된다
- Given 합성 중 대본의 사실 결함 발견 / When 처리한다 / Then 오디오 단계에서 수정하지 않고 게이트 2로 반환된다
- Given 발행된 에피소드의 재처리 필요 / When 재처리한다 / Then 마스터(무손실)에서 수행된다
