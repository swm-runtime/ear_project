# spec/06 — 오디오 (TTS·후처리)

> 상위: [PIPELINE.md](../PIPELINE.md) · 앞: [spec/07 발행](07-publish.md)의 게이트 2 **통과 후** 실행 · 대본 규격: [spec/04](04-script.md)
> 실행 주체: AI + 사람(청취 확인) · 입력: 검수 통과 대본 · 출력: 오디오 (S3)
> 엔진: **ElevenLabs Eleven v3** (2026-08 파일럿 기준 채택. 비용 대안 비교는 archive/06 참조)

## 1. 이 단계의 역할

게이트 2를 통과한 대본을 **두 화자의 음성**으로 합성하고, 후처리를 거쳐 발행 가능한
오디오 파일을 만든다. 대본 내용의 수정은 이 단계의 일이 아니다 — 합성 중 대본 결함이
발견되면 수정하지 않고 검수(게이트 2)로 되돌린다.

## 2. 보이스 — 채널 아이덴티티

- **보이스 확정 (2026-09-02 박수헌 — 구 미결 #8)**: 윤아 = **Annie** (`Lb7qkOn5hF8p7qfCDH8q`, ko·female·professional) · 이음 = **Yohan Koo** (`4JJwo477JUAx3HV0T7n7`, ko·male·professional). 코드 기본값은 `apps/worker/src/config.ts` — env(`TTS_VOICE_*`)로 덮을 수 있으나 보이스 변경은 리브랜딩급 결정이다.
  보이스 변경은 리브랜딩급 결정이다 — 에피소드마다 바뀌지 않는다.
- 선정 기준: **한국어 네이티브 보이스** (외래어를 자연스러운 한국식 발음으로 읽는 것이 필수) ·
  두 화자의 톤 대비 확보 · 전문 보이스 클론(PVC)은 v3 미최적화로 회피.
- 발화 속도 설정값(speed)도 보이스 ID와 함께 확정·고정한다 — 속도는 채널 아이덴티티에 속한다.

## 3. 합성 방식

**다중화자 1콜(Text to Dialogue) 확정** (2026-09-02 박수헌 — 구 미결 #8). 구현: `apps/worker/src/stages/tts.ts` — 요청당 ~1,800자(문서 권장 2,000자)로 턴 경계 분할, seed 는 에피소드 고정. (콜드오픈 발췌 원본 턴 단독 합성 예외는 콜드오픈 폐지(2026-09-07)로 함께 사라졌다.)

| | 다중화자 1콜 (Text to Dialogue) | 턴별 합성 + 이어붙이기 |
|---|---|---|
| 방법 | 턴 배열 `{text, voice_id}`을 한 요청으로 | 턴마다 단일 TTS 호출 → 무음 갭 삽입 → 연결 |
| 장점 | 화자 간 톤 연속성·자연스러운 주고받기 | `speed` 설정 사용 가능 · **턴 타임스탬프 부산물** (스크립트 싱크 대비) · 길이 제약 없음 |
| 제약 | 요청당 권장 글자 수 제한 → **15분 대본은 분할 호출 필수** · 설정이 stability뿐 (speed 없음) | 턴 사이 간격·톤 연속성을 직접 관리 |

- 15분 본편(약 5,000자)은 어느 방식이든 단일 호출로 끝나지 않는다 — 분할 지점은 반드시
  **턴 경계**로 한다 (문장 중간 분할 금지).
- **분할 지점은 글자 수가 차는 자리가 아니라 이음새가 덜 들리는 자리로 고른다** (2026-09-21 박수헌 — 요청 사이는 모델이
  앞 요청을 모르고 무음으로만 붙는 유일한 이음새라 청취 시 "멈췄다 다시 시작"으로 들린다. Text to Dialogue 에는 요청 간
  연속성 파라미터가 없어 자리 선택으로 감춘다). 구현: `apps/worker/src/tts/script.ts` `chunkTurns` — 요청당 1,800자 이하 묶음들
  중 [요청 수 × 4 + 경계마다 비용(단락 헤더 다음 0 · 서술 뒤 1 · 질문 뒤 5)] 최소를 동적 계획법으로 고른다. 요청 수는
  질문과 대답을 가르는 것을 피할 때만 는다. 실측(대본 7편): 요청 수 동일, "질문 뒤" 경계 10곳 → 0곳. 실행 기록에
  경계 종류 요약(`경계 단락 3·문장 1`)을 남기고 "질문 뒤"가 있으면 청취 확인 때 그 지점을 듣는다.
- 재합성 여유를 예산에 반영한다 (발음·태그 문제로 부분 재합성 발생 — 파일럿 실측 전 가정 30%).

## 4. 대본 → TTS 입력 변환

- **정규화는 이 단계의 별도 전처리다** (2026-09-01, CoreaSpeech NeurIPS'25 근거): 숫자·영어 차용어·코드 스위칭·특수문자를 한글 발음으로 바꾸는 정규화기(N2gk+ 방식)가 TTS 아키텍처와 무관하게 품질을 올린다. 대본은 가독 표기를 유지하고(spec/04 5장 표기 이원화) 여기서만 치환한다 — QA 항목 6이 영문 표기를 위반으로 잡던 것은 검사 위치가 틀렸던 것. 숫자 발음이 첫 실패 지점일 가능성이 높으므로 클린/노이즈/숫자 세트로 나눠 검수한다(8장).


| 대본 표기 | 처리 |
|---|---|
| `[윤아]` `[이음]` 화자 라벨 | **TTS 입력 텍스트에 포함하지 않는다** — voice_id 매핑으로 소거 |
| `[curious]` 등 오디오 태그 | 텍스트에 포함해 전달 (5장 규격) |
| `{인트로 템플릿}` 등 플레이스홀더 | 변환 전 **반드시 실제 템플릿 문구로 치환 완료**되어 있어야 한다 — 남아 있으면 합성 중단 |
| 가독 표기 (AI, HuggingFace, 숫자 등) | **병합 사전으로 음차 치환** ("AI→에이아이", "17,000→만 칠천") — 전역 사전 + 에피소드 발음 맵 (6장). 대본은 원표기, TTS 입력만 음차 (표기 이원화, spec/04 5장) |
| 말줄임표(…) | 그대로 전달 (일시정지 연출) |

변환 전 검증: 사전 적용 **후** 잔존 영문·표·URL이 없는지 기계 검사한다 — 잔존 영문은 사전 누락이므로 합성을 중단한다. 처리는 웹에서 한다(코드 배포 불필요): 에피소드 발음 맵(에피소드 상세 "발음" 탭) 또는 전역 사전(`/assets`)에 추가하고 재시도한다 (6장).

## 5. 오디오 태그 규격

- 형식: 영문 소문자 대괄호. **문서 확인 태그만 기본 사용**: `[curious]` `[surprised]` `[sighs]` `[exhales]` `[laughs]` `[whispers]` `[excited]`.
- 검증 대기 목록: `[chuckles]` (골드 예시에서 사용 — 파일럿 반응 확인 후 승격/제거).
- 미확인(커뮤니티 통용) 태그는 파일럿에서 보이스별 반응을 확인한 뒤 이 목록에 추가한다.
  반응 없는 태그는 대본에서 제거한다.
- 최소 사용 원칙: 턴당 최대 1개 수준 — 페르소나의 "과장 없는 리액션"(spec/04)이 태그에도 적용된다.
- 속도·일시정지를 태그로 조절하지 않는다 — 속도는 6장, 정지는 말줄임표.
- 태그는 연출 지시이며 사실 주장이 아니다 — claims 대상은 아니나, 리액션 태그의 강도는
  QA 화자 항목(spec/05 9번)의 검토 범위다.

## 6. 속도·발음

**속도** — 공식 속도 태그는 없다. 조절 수단은 우선순위대로:

1. 턴별 합성 시: voice settings `speed` (0.7~1.2) — 화자별 고정값 (현행 경로 아님)
2. **다중화자 1콜 시(현행): 설정 불가 → 화자별 후처리 배속** (2026-09-07 박수헌 — "윤아가 너무 느리다"). 요청을
   `/text-to-dialogue/with-timestamps`로 보내 글자 단위 정렬로 **턴 경계 시각**을 잡고, 화자 구간만 ffmpeg `atempo`
   (피치 유지)로 배속한 뒤 이어 붙인다. 값은 워커 env `TTS_SPEED_YUNA`(기본 **1.2**)·`TTS_SPEED_EUM`(기본 1.0).
   1.05~1.1은 음질 영향이 미미하고, 1.2는 청취 확인 대상이다. 정렬에서 턴 경계를 못 찾거나 with-timestamps가
   실패한 요청은 **원속으로 폴백**하고 실행 기록에 "원속 폴백 N요청"으로 남긴다 — 합성 실패로 취급하지 않는다.
   구현: `apps/worker/src/tts/elevenlabs.ts` `synthDialogueWithTimestamps`·`locateTurnStarts`, `tts/audio.ts` `retimePieces`.
3. 텍스트 구조 (문장 길이·말줄임표) — 미세 조정용

**발음** — 표기 이원화(spec/04 5장)에 따라 음차는 이 단계의 **병합 사전**이 전담한다. 사전은 두 층이다 (2026-09-03 확정 — 이전의 "코드 내 치환 테이블" 방식을 대체):

- **전역 사전 (표준 음차 사전)** — 진실은 DB `prompt_assets`의 `skills/tts/pronunciation.json` (규약은 spec/10 3.2와 동일: 웹 `/assets`에서 새 버전(draft) → 활성화, git `docs/ai/skills/tts/pronunciation.json`은 export 스냅샷). 형식은 `{"표기": "발음"}` JSON 객체. 프롬프트 번들과 달리 **에피소드에 고정되지 않는다** — TTS 단계는 항상 active를 읽으므로, 사전을 고치면 같은 에피소드 재합성에 즉시 적용된다. 어색하게 합성되는 항목의 보정(띄어쓰기 등)도 여기서 갱신해 다음 에피소드부터 재사용한다.
- **에피소드 발음 맵** — 대본 단계가 대본 속 비한글 표기의 발음을 `pronunciations.json`으로 함께 산출한다(spec/04 5장·8장). 웹 에피소드 상세 "발음" 탭에서 확인·수정한다. 에피소드마다 새로 나오는 고유명사(인명·기관·매체)는 이 층이 흡수하고, 전역 사전에는 재등장하는 일반 항목만 승격해 쌓는다.
- 병합 규칙: **겹치는 표기는 전역 사전이 이긴다** — 사람이 다듬은 표준이 자동 생성값보다 우선. 에피소드별 예외 발음이 필요하면 전역 사전에서 해당 표기를 빼거나 대본 표기를 바꾼다.
- 규모 확대 시 ElevenLabs 발음 사전(alias 치환: "AI→에이아이")을 등록해 대본에 영문이
  잔존해도 합성 단계에서 잡는 안전망을 둔다 (음소 규칙은 v3 제약이 있으나 alias는 무관).

## 7. 후처리·파일 규격

- 배속: 6장의 화자별 배속(타임스탬프 정렬 + atempo) 외의 임의 배속은 하지 않는다. 마스터·배포본 모두 배속 적용본이다
  (원속이 필요하면 env 를 1로 두고 재합성).
- 라우드니스 정규화: 배포 전 음량을 일정 기준으로 정규화한다 (기준값은 파일럿에서 확정).
- 파일: **마스터(무손실 wav)와 배포본(mp3 128kbps)을 모두 보관**한다 — 재처리는 항상 마스터에서.
- **앞뒤 무음 2초** (2026-09-07 박수헌): 조립 시 첫 세그먼트 앞과 마지막 세그먼트 뒤에 각 2초 무음을 넣는다 —
  재생 시작 직후 첫 음절이 잘리지 않고, 끝에 여백이 생긴다. 라우드니스 정규화 전에 넣으며 재생 길이에 포함된다.
  구현: `apps/worker/src/tts/audio.ts` `assemble` (`leadSec`·`tailSec` 기본 2).
- **분할 요청 이음새** (2026-09-21~22 박수헌, KAN-87 — 멘토 청취 "중간에 끊긴다"): 종전에는 요청 사이에 0.35초 디지털 무음만 넣었다.
  X260919-001 실측으로 원인을 확정했다 — ElevenLabs 출력은 마지막 음절 뒤 약 20ms 만에 끝나 **−19dB 에서 0 으로 뚝 떨어지고**,
  같은 요청 안의 자연스러운 턴 사이 쉼은 약 100ms 에 걸쳐 −73dB 바닥으로 감쇠하며 **약 1초** 이어지고, 다음 요청은 대화의 첫 문장처럼
  시작한다(모델이 앞 요청을 모른다). 절단 제거(페이드)·쉼 연장·바닥 소음 채움을 먼저 시험했으나 경계가 여전히 구분됐고, 요청 안 화자
  교대에 같은 처리를 넣은 가짜 경계와 종류가 달라 남은 단서는 생성 불연속으로 확정 → 그 셋은 제외하고 **문맥 겹침** 하나로 처리한다.
  **문맥 겹침**: 요청마다 **앞 요청 마지막 턴의 끝 문장(≤140자)과 뒤 요청 첫 턴의 첫 문장(≤140자)을 함께 생성**하고, 양쪽 다 문맥 턴과의
  쉼 한가운데에서 잘라 버린다. **절단점은 오디오에서 찾는다** — ElevenLabs 정렬은 글자가 빈틈없이 이어져 쉼이 앞 턴 마침표나 뒤 턴 첫 글자의
  길이에 흡수되므로(실측 2026-09-22) 타임스탬프로는 위치가 안 나온다. [문맥 턴 마지막 글자 시작, 본문 첫 글자 끝] 창에서 −50dB 이하
  0.15초 이상 무음 중 가장 긴 것의 가운데를 자른다(`audio.ts` `findPauseCut`). 요청 끝은 뒤에 말이 있는 상태로 자연히 감쇠하고, 요청 시작은 앞말에 이어지는 억양으로 나오며,
  그 경계에는 무음을 넣지 않는다(앞 반쪽 쉼 + 뒤 반쪽 쉼이 오디오에 있다). 본문 상한을 1,700자로 낮춰 문맥을 더해도 2,000자 안.
  안전장치 — 창에 무음 없음·경계 미발견·문맥 턴 말 속도가 원 요청과 40% 넘게 다름 → 그 요청만 문맥 없이 재합성하고, 그 경계에만
  0.9초 무음(같은 요청 안 턴 사이 쉼 실측 0.9~1.1초)을 넣는다. 실행 기록에 `문맥 겹침 5/5경계(+1,120자)`, 폴백이 있으면
  `폴백 경계 무음 0.9초`로 남긴다. 글자 비용 약 +8%. 디버그: `payload.debug_alignment` 로 요청별 정렬 원본을 `audio/debug-align/` 에,
  `payload.chunk_chars` 로 샘플을 여러 요청으로 쪼갤 수 있다.
  구현: `stages/tts.ts` `synthChunk` · `audio.ts` `findPauseCut` · `segments.ts` `contextExcerpt` · `elevenlabs.ts` `locateTurnSpans`.
  분할 위치는 3장(단락 > 서술 뒤 > 질문 뒤). Text to Dialogue 에는 요청 간
  연속성 파라미터가 없다(2026-09-21 API 문서 확인). 구현: `audio.ts` `toWav`(페이드)·`roomToneWav`·`measureNoiseFloorDb`, `segments.ts` `naturalGapSec`.
- 콜드 오픈 관련 규칙(재합성 금지·본편 오디오 절단, 2026-08-28)은 **콜드 오픈 폐지(2026-09-07, spec/04 4장)로 삭제**했다.
- **대본 세그먼트 `script-segments.json`** (2026-09-19, KAN-72 — 앱 자막·대본 패널용): 합성 단계가 배포본과 함께
  `episodes/{id}/script-segments.json`을 만든다. 형식은 `[{ "start_sec", "end_sec", "speaker", "text" }]` — 단위는 턴,
  25초를 넘는 턴은 문장 경계에서 나눈다(원문과 합성용 표기의 문장 수가 같을 때만). **시각은 배포본(`dist.mp3`) 기준**이다 —
  6장의 배속 정렬(배속 전 요청 시각)을 조각별 atempo 비율로 옮기고, 앞 무음 2초·요청 사이 이음새 쉼(7장, assemble 과 같은 값)·앞 요청들의 실측 길이를
  더한다. `text`는 TTS 표기(음차·발음 맵 적용 전)가 아니라 **사람이 읽는 원문**, `speaker`는 "윤아"·"이음" 그대로.
  **한 요청이라도 원속 폴백(턴 경계 없음)이면 파일을 만들지 않고** 실행 기록에 "자막 세그먼트 없음(사유)"로 남긴다 — 틀린
  자막보다 없는 편이 낫다(앱은 없으면 대본 버튼을 숨긴다). 배속을 끄면(env 둘 다 1) 정렬을 요청하지 않으므로 역시 없다.
  샘플 합성은 만들지 않는다. 발행 화면이 이 파일을 `script_file`로 첨부한다(spec/07 2장 · `admin-api.md` 4.6).
  구현: `apps/worker/src/tts/segments.ts` (단위 테스트 `segments.test.ts`).
  **기존 발행분 소급 — `script_align` 작업**(2026-09-20, 0022): 배속 정렬을 저장한 편이 없어(85편 중 0) 발행본 `dist.mp3`와 대본을
  ElevenLabs **강제 정렬**(`POST /v1/forced-alignment`)에 넣어 글자 시각을 받고 같은 `script-segments.json`을 만든다. 정렬에 보내는 글은 합성
  때와 같은 정규화 표기(음차 사전 + 발음 맵), 세그먼트 `text`는 원문. 정렬 시각이 곧 배포본 시각이라 배속·무음 계산이 없다. 턴 경계를
  못 찾으면 실패(세그먼트 없음). 오디오를 다시 만들지 않으므로 반영은 `script_file` 단독 PATCH — 콘텐츠 버전 무변경·재생 위치 보존
  (`admin-api.md` 4.10). 대상은 **서비스에 발행된 콘텐츠만** — 발행 목록 자막 셀 [자막 뽑기] → [반영], "자막 없는 것 전부 뽑기".
  ElevenLabs 키가 있는 워커(서버)만 집는다(claim_job 게이트). 구현: `stages/script-align.ts`, `tts/elevenlabs.ts` `forcedAlignment`.

## 8. 검수·기록

- 합성 후 **사람이 청취 확인**한다 (발행 전 마지막 사람 개입): 발음 오류 · 태그 오반응 ·
  속도 체감 · 화자-보이스 매핑 오류. 문제 시 해당 턴만 부분 재합성한다.
- 대본 결함(내용·사실)이 발견되면 재합성이 아니라 **게이트 2로 반환**한다 (1장).
- 산출물 S3 업로드: 마스터·배포본·(턴별 합성 시) 타임스탬프. 경로를 `runs.artifacts`에.
- `runs` 기록: `phase=tts`, `result`(합성 방식·재합성 여부), `executed_by`.
