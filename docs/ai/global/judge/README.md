# 에이전트 판정 — 절차와 기록 형식

> 글로벌판 명세 `PIPELINE.md` 6.10의 실행 절차. 2026-10-16 결정 — 팀에 영어 대본의 질을 판단할 사람이 없어, 한국판의 사람 판정(spec/09 3.1)을 에이전트 판정이 대신한다.
> 이 디렉토리는 `skills/`가 아니다 — DB `prompt_assets`로 시딩하지 않고, 판정을 돌리는 세션(파일럿은 Claude Code)이 직접 읽는다.

## 1. 구성

| 파일 | 읽는 쪽 | 역할 |
|---|---|---|
| `editor.md` + `scoring.md` | 원어민 편집자 에이전트 | 듣기 경험·영어 구어·말버릇·장면과 소리. 12항목 점수의 주인 |
| `korea-check.md` + `house-style.md` | 한국어·사실 검토 에이전트 | 발췌·취재 노트 대조, 한국어 뜻·문화 맥락, 표기·배제 주제·원칙 8·9. 필수 수정 재대조의 주인 |
| 이 문서 | 판정을 돌리는 세션 | 입력 정리·순서·병합·비평 대조·저장·규칙 대조 |

- 모델은 대본·QA·비평(GPT)과 다른 계열인 Claude를 쓴다.
- **작성자 눈가림**(2026-10-17) — 검토자는 대본이 어떻게 만들어졌는지 모른다. AI 생성·대본 규칙·구성안·QA·비평·파이프라인을 알리는 말과 파일을 주지 않는다. "우리 팟캐스트에 들어온 원고"로만 받는다. 지시문·입력 파일·띄우는 프롬프트 모두 같다.
- `scoring.md`는 `skills/critic/rubric-v2.md` 3장의 12항목·배점·구간을 눈가림용으로 옮긴 것이다. 루브릭이 항목·배점·구간 경계를 바꾸면 같이 고친다. 플래그·기계 검사·AI 문체처럼 제작을 드러내는 말은 옮기지 않는다.
- `house-style.md`는 `PIPELINE.md` 2.1·5장 원칙 8·9·6.4 표기를 옮긴 것이다. 셋이 바뀌면 같이 고친다.
- 지시문은 모델이 읽는 글이다. 단문·기능 서술로 쓰고, 예시 문장을 넣지 않는다. 고친 이유는 이 문서 끝의 기록에 남긴다.

## 2. 순서

1. **입력 내려받기** — 글로벌 버킷에서 그 편의 `script.md`·`claims.md`·`sources.md`·`pronunciations.json`·`critic-report-v2.md`를 판정 세션 작업 디렉토리로 받는다.
2. **입력 정리** — 검토자에게 줄 사본을 검토자별 새 디렉토리에 만든다. 디렉토리 이름에도 제작 흔적을 두지 않는다.
   - `script.md`: 첫 줄 메타(규칙 버전·생성 방식·출처 목록)를 `<제목> · <주제>`로 바꾼다. 나머지는 그대로.
   - `claims.md` → `notes.md`: 머리말 인용 블록(귀속·축 소스·구간 배정 설명)과 `## QA attempt …` 절 이하를 지운다. 제목은 `# Research notes`.
   - `sources.md`: 머리말의 수집·선정 방식 설명 줄과 `Gist:` 줄을 지운다. 발췌는 그대로.
   - 편집자 디렉토리: `script.md`·`scoring.md`. 한국어·사실 디렉토리: `script.md`·`notes.md`·`sources.md`·`pronunciations.json`·`house-style.md`.
   - 정리한 사본에 `GPT`·`AI`·`model`·`prompt`·`pipeline`·`QA`·`critic`·`guidelines`·`full-en` 이 남았는지 찾아 본다. 대본 내용으로 쓰인 것은 둔다.
3. **판정** — 두 검토자를 따로 새로 띄운다. 띄우는 프롬프트는 지시문 파일·작업 디렉토리·출력 형식(3장)만 알린다. 각자 출력을 낸다.
4. **병합** — 판정 세션이 두 출력을 합친다.
   - `must_fix`는 합집합이다. 같은 턴·같은 문제는 하나로 합친다.
   - `publishable`은 둘 다 `true`일 때만 `true`다. 사유는 둘을 이어 적는다.
   - 같은 턴에 두 검토자의 수정안이 있으면 하나로 합쳐 다시 쓰고, 재대조에 넘긴다.
5. **필수 수정 반영** — `must_fix`의 수정안을 대본 턴에 반영한다(S3 덮어쓰기는 버저닝으로 이전 본이 남는다). `human_edits`에 `by: agent:<모델 id>`로 남긴다. 반영 뒤 L0를 다시 돌린다.
6. **재대조** — 한국어·사실 검토자에게 수정된 턴만 다시 준다. 통과한 항목을 `fixed`로 넘긴다. 실패한 항목은 `open`으로 남기고 수정안을 다시 받는다. 두 번 실패하면 `publishable: false`로 내린다.
7. **비평 대조** — 판정 세션이 판정 뒤에 한다. 비평 플래그·⭐마다 검토자 지적·점수와 대본을 대조해 동의·부분동의·비동의를 매기고, 비평이 놓친 지적을 적는다. 점수·`publishable`은 바꾸지 않는다. 비평 보정의 원천이다.
8. **규칙 대조** — 판정 세션이 지적마다 해당 규칙 번호(guidelines·루브릭·명세·QA·L0)를 붙이고, 규칙이 없거나 지켜지지 않은 것을 승격 후보로 적는다(5장).
9. **저장** — 4장의 형식으로 `episodes.critic_verdicts`를 쓰고, 한국어 요약 리포트를 `agent-verdict.md`로 에피소드 산출물 옆에 올린다.
10. **보고** — 사용자에게 한국어로 요약을 보고한다: 발행 가능 여부, 필수 수정과 반영 결과, 규칙으로 올릴 후보.

`publishable`의 뜻은 **"필수 수정을 반영하면 발행해도 된다"**이다. 발행 버튼은 `publishable: true`이고 `must_fix`가 전부 `fixed`일 때만 열린다.

## 3. 검토자 출력 (JSON)

두 검토자 모두 마지막에 JSON 블록 하나를 낸다. 사유·문제 설명은 한국어, 대본 인용은 원문 그대로 쓴다.

```json
{
  "scores": { "3.1": { "score": 0, "reason": "" } },
  "retell": "",
  "findings": [
    { "turn": "E14", "turns": ["E14", "E19"], "quote": "", "problem": "", "kind": "must_fix | should_fix", "evidence": "사실 지적이면 발췌·노트 인용" }
  ],
  "edits": [ { "turn": "E14", "after": "턴 전체 새 문장", "fixes": [0], "reason": "" } ],
  "other_changes": [ { "file": "script.md 소제목 | pronunciations.json", "before": "", "after": "", "fixes": [0], "reason": "" } ],
  "publishable": true,
  "publishable_reason": "",
  "summary_ko": ""
}
```

- `scores`·`retell`은 편집자만 낸다. 항목 키와 만점은 `scoring.md`의 12항목이다.
- `turns`는 여러 턴에 걸친 패턴일 때만 쓴다. `other_changes`는 턴 밖의 변경(소제목·발음 사전 표제어)이 있을 때만 쓴다.
- `findings[].kind`
  - `must_fix` — 발행 전에 반드시 고친다. 사실 오류, 오해를 부르는 뜻풀이, 깨진 영어, 표기·배제 주제·원칙 8·9 위반이 여기에 든다.
  - `should_fix` — 고치면 좋지만 발행을 막지 않는다.
- 규칙 번호는 검토자가 아니라 판정 세션이 붙인다(2장 8번).
- `edits[].fixes`는 그 수정이 해결하는 `findings`의 순번이다. `must_fix`에는 수정안이 있어야 한다. 수정안을 만들 수 없는 `must_fix`(노트·발췌에 없는 재료가 필요하다)는 `edits` 없이 두고, `publishable: false`로 판단한다.
- 재대조 출력은 `{ "results": [ { "id": "", "fixed": true, "reason": "" } ] }`이다.

## 4. 저장 형식 — `episodes.critic_verdicts`

사람 판정(판정 화면)과 같은 키를 쓰고, 에이전트 블록을 덧붙인다. 판정 화면이 그대로 읽는다.

```json
{
  "flags":  { "1": { "verdict": "동의", "reason": "" } },
  "stars":  { "1": { "verdict": "부분동의", "reason": "" } },
  "scores": { "3.1": { "human": "6", "reason": "" } },
  "extra": "비평이 놓친 문제 요약 (한국어)",
  "judged_by": "agent:claude-opus-5-5",
  "judged_at": "ISO 시각",
  "agent": {
    "publishable": true,
    "publishable_reason": "",
    "must_fix": [ { "id": "M1", "turn": "E14", "issue": "", "by": "editor | korea", "status": "open | fixed", "edit_at": "ISO 시각 또는 null" } ],
    "report_key": "s3:<에피소드 경로>/agent-verdict.md",
    "reviewers": { "editor": "editor.md 커밋", "korea": "korea-check.md 커밋" }
  }
}
```

- `scores.*.human`은 판정 화면 호환을 위해 이름을 그대로 둔다. 값은 에이전트 점수다. 사람 판정과는 `judged_by`로 가른다.
- 사람이 판정 화면에서 저장하면 `judged_by`가 사람 이메일로 바뀌고 `agent` 블록은 남는다. 발행 조건은 `agent` 블록만 본다.

## 5. 규칙 승격

- 판정 묶음(새 규칙 버전 3편)마다 한국판과 같은 승격 절차를 밟는다. 원천은 비평 대조(2장 7번)의 동의율·기각·부분동의 사유, 규칙 대조(2장 8번), 에이전트 직접 수정이다.
- 비평이 틀린 것은 루브릭을 좁히고, 비평이 놓친 것은 guidelines·QA·L0를 신설한다.
- 승격 PR은 사람이 승인한다. 승격안은 한국어로 설명한다.

## 6. 기록

- 2026-10-17 작성자 눈가림 — 검토자에게 대본이 AI로 만들어졌다는 것과 제작 과정(규칙·구성안·QA·비평)을 알리지 않는다(박수헌 결정: 알면 "AI치고는 괜찮다"로 후하게 볼 수 있다). 편집자는 대본과 점수표(`scoring.md`)만, 한국어·사실 검토자는 대본·취재 노트·발췌·발음 목록·편집 방침(`house-style.md`)만 받는다. 2차 비평 대조와 `rule_note`는 검토자에게서 빼 판정 세션 몫(2장 7·8번)으로 옮겼다. 종전 판정(G261015-001 · G261017-001~006)은 비평·규칙·구성안을 본 판정이라, 004~006 을 새 방식으로 다시 판정해 기준선을 잡는다. 재판정 결과(편집자 총점): 004 54→46 · 005 55→51 · 006 51→42, 평균 53.3→46.3(−7.0). 비평은 69·67·61로 눈가림 편집자보다 16~23점 높다. 필수 수정은 편집자 6·10·7건, 한국어·사실 1·1·3건이고 사실 쪽 지적 위치는 종전과 거의 같다. 4회차부터 이 눈가림 점수를 기준선으로 쓴다. DB 의 종전 판정 기록은 바꾸지 않았다.
- 2026-10-17 scoring.md 3.4 — 보도 속 인물을 이름·나이·장소만으로 전한 것은 장면이 아니라는 문장을 비평 critic-en-v0.7 과 같이 넣었다(G261017-009~011 판정에서 비평이 그것을 장면으로 세 3.4 를 4~5점으로 매김). 편집자는 이미 그렇게 판정했다.
- 2026-10-17 korea-check — 템플릿 인사말(annyeonghaseyo·gamsahamnida)은 뜻풀이·말 단계 지적에서 뺀다(guidelines full-en-v0.7 규칙 48과 같은 예외). G261017-002·003 에서 같은 rule_note 가 반복됐고 템플릿 문구라 대본이 고칠 수 없다.

- 2026-10-16 첫 판 — G261015-001을 두 에이전트에게 검토시켰을 때 QA·비평이 놓친 문제를 찾았다(oppa의 화자 조건 누락, 반말 미표기, 장면·소리 부재). 그 두 역할을 그대로 지시문으로 옮겼다.
- 2026-10-16 시험 운용 반영 — 같은 편 1차 시험에서 두 검토자가 짚은 애매한 점 14개를 정리했다. 점수 기준은 수정 전 대본에 적용, `must_fix` 경계(뜻을 잘못 잡거나 놓치는 줄 · 범위 확대 · 로마자 표기), 여러 턴 패턴의 `turns`, 다른 턴 수정 허용, 턴 밖 변경의 `other_changes`, 규칙이 없으면 `없음`, 말 단계 표시 위치, 발췌 두 개를 엮는 수정 허용, 둘 다 `true`일 때만 발행 가능.
