# 에이전트 판정 — 절차와 기록 형식

> 글로벌판 명세 `PIPELINE.md` 6.10의 실행 절차. 2026-10-16 결정 — 팀에 영어 대본의 질을 판단할 사람이 없어, 한국판의 사람 판정(spec/09 3.1)을 에이전트 판정이 대신한다.
> 이 디렉토리는 `skills/`가 아니다 — DB `prompt_assets`로 시딩하지 않고, 판정을 돌리는 세션(파일럿은 Claude Code)이 직접 읽는다.

## 1. 구성

| 파일 | 읽는 쪽 | 역할 |
|---|---|---|
| `editor.md` + `scoring.md` | 원어민 편집자 에이전트 | 듣기 경험·영어 구어·말버릇·장면과 소리. 12항목 점수의 주인 |
| `korea-check.md` + `house-style.md` | 한국어·사실 검토 에이전트 | 발췌·취재 노트 대조, 한국어 뜻·문화 맥락, 표기·배제 주제·원칙 8·9. 필수 수정 재대조의 주인 |
| 이 문서 | 판정을 돌리는 세션 | 입력 정리·순서·병합·비평 대조·저장·규칙 대조 |

- 모델은 대본·QA·비평(GPT)과 다른 계열인 Claude를 쓴다. **2026-10-22 개정** — 운영 판정은 워커 단계 `judge_loop`(6장)가 서버 API(GPT)로 한다. Claude 는 루프 밖 **표본 채점**(이 문서 2장의 절차, 판정 세션)으로 GPT 기준값(6.3)을 보정할 때만 쓴다(박수헌: "운영은 서버 API 만으로 돌아야 한다").
- **작성자 눈가림**(2026-10-17) — 검토자는 대본이 어떻게 만들어졌는지 모른다. AI 생성·대본 규칙·구성안·QA·비평·파이프라인을 알리는 말과 파일을 주지 않는다. "우리 팟캐스트에 들어온 원고"로만 받는다. 지시문·입력 파일·띄우는 프롬프트 모두 같다.
- `scoring.md`는 `skills/critic/rubric-v2.md` 3장의 12항목·배점·구간을 눈가림용으로 옮긴 것이다. 루브릭이 항목·배점·구간 경계를 바꾸면 같이 고친다. 플래그·기계 검사·AI 문체처럼 제작을 드러내는 말은 옮기지 않는다.
- `house-style.md`는 `PIPELINE.md` 2.1·5장 원칙 8·9·6.4 표기를 옮긴 것이다. 셋이 바뀌면 같이 고친다.
- 지시문은 모델이 읽는 글이다. 단문·기능 서술로 쓰고, 예시 문장을 넣지 않는다. 고친 이유는 이 문서 끝의 기록에 남긴다.

## 2. 순서

> 2026-10-22 — 이 절차는 **Claude 표본 채점**(GPT 기준값 보정·규칙 승격 원천) 용이다. 발행을 가르는 운영 판정은 6장의 워커 단계가 같은 지시문·같은 눈가림 정리로 서버에서 한다.

1. **입력 내려받기** — 글로벌 버킷에서 그 편의 `script.md`·`claims.md`·`sources.md`·`pronunciations.json`·`critic-report-v2.md`를 판정 세션 작업 디렉토리로 받는다.
2. **입력 정리** — 검토자에게 줄 사본을 검토자별 새 디렉토리에 만든다. 디렉토리 이름에도 제작 흔적을 두지 않는다.
   - `script.md`: 첫 줄 메타(규칙 버전·생성 방식·출처 목록)를 `<제목> · <주제>`로 바꾼다. 나머지는 그대로.
   - `claims.md` → `notes.md`: 머리말 인용 블록(귀속·축 소스·구간 배정 설명)과 `## QA attempt …` 절 이하를 지운다. 제목은 `# Research notes`.
   - `sources.md`: 머리말의 수집·선정 방식 설명 줄과 `Gist:` 줄을 지운다. 발췌는 그대로.
   - 편집자 디렉토리: `script.md`·`scoring.md`. 한국어·사실 디렉토리: `script.md`·`notes.md`·`sources.md`·`pronunciations.json`·`house-style.md`.
   - 정리한 사본에 `GPT`·`AI`·`model`·`prompt`·`pipeline`·`QA`·`critic`·`guidelines`·`full-en` 이 남았는지 찾아 본다. 대본 내용으로 쓰인 것은 둔다.
3. **판정** — 두 검토자를 따로 새로 띄운다. 띄우는 프롬프트는 지시문 파일·작업 디렉토리·출력 형식(3장)만 알린다. 각자 출력을 낸다.
   - 편집자는 같은 입력으로 **세 번** 따로 띄운다. 한 번 판정의 합계가 4점까지 흔들린다(7장 2026-10-21).
4. **병합** — 판정 세션이 두 출력을 합친다.
   - 편집자 점수는 항목마다 세 번의 가운데 값이다. 합계는 그 합이다. 세 번의 합계를 `extra`에 함께 적는다.
   - 편집자의 `retell`·`findings`·`edits`·`publishable`은 합계가 가운데인 한 번의 출력을 쓴다. 합계가 같은 번이 둘 이상이면 앞의 번을 쓴다. 가운데 값 합계가 60 미만이면 편집자 `publishable`은 `false`다.
   - `must_fix`는 합집합이다. 같은 턴·같은 문제는 하나로 합친다.
   - `publishable`은 둘 다 `true`일 때만 `true`다. 사유는 둘을 이어 적는다.
   - 같은 턴에 두 검토자의 수정안이 있으면 하나로 합쳐 다시 쓰고, 재대조에 넘긴다.
5. **필수 수정 반영** — `must_fix`의 수정안을 대본 턴에 반영한다(S3 덮어쓰기는 버저닝으로 이전 본이 남는다). `human_edits`에 `by: agent:<모델 id>`로 남긴다. 반영 뒤 L0를 다시 돌린다.
6. **재대조** — 한국어·사실 검토자에게 수정된 턴만 다시 준다. 통과한 항목을 `fixed`로 넘긴다. 실패한 항목은 `open`으로 남기고 수정안을 다시 받는다. 두 번 실패하면 `publishable: false`로 내린다.
7. **비평 대조** — 판정 세션이 판정 뒤에 한다. 비평 플래그·⭐마다 검토자 지적·점수와 대본을 대조해 동의·부분동의·비동의를 매기고, 비평이 놓친 지적을 적는다. 점수·`publishable`은 바꾸지 않는다. 비평 보정의 원천이다.
8. **규칙 대조** — 판정 세션이 지적마다 해당 규칙 번호(guidelines·루브릭·명세·QA·L0)를 붙이고, 규칙이 없거나 지켜지지 않은 것을 승격 후보로 적는다(5장).
9. **저장** — 4장의 형식으로 `episodes.critic_verdicts`를 쓰고, 한국어 요약 리포트를 `agent-verdict.md`로 에피소드 산출물 옆에 올린다.
10. **보고** — 사용자에게 한국어로 요약을 보고한다: 발행 가능 여부, 필수 수정과 반영 결과, 규칙으로 올릴 후보.

`publishable`의 뜻은 **"필수 수정을 반영하면 발행해도 된다"**이다. 발행 버튼은 `publishable: true`이고 `must_fix`가 전부 `fixed`일 때만 열린다.

## 3. 검토자 출력 (JSON)

두 검토자 모두 마지막에 JSON 블록 하나를 낸다. 사유·문제 설명은 한국어, 대본 인용은 원문 그대로 쓴다.

```json
{
  "scores": { "3.1": { "score": 0, "reason": "" } },
  "retell": "",
  "findings": [
    { "turn": "E14", "turns": ["E14", "E19"], "quote": "", "problem": "", "kind": "must_fix | should_fix", "evidence": "사실 지적이면 발췌·노트 인용" }
  ],
  "edits": [ { "turn": "E14", "after": "턴 전체 새 문장", "fixes": [0], "reason": "" } ],
  "other_changes": [ { "file": "script.md 소제목 | pronunciations.json", "before": "", "after": "", "fixes": [0], "reason": "" } ],
  "publishable": true,
  "publishable_reason": "",
  "summary_ko": ""
}
```

- `scores`·`retell`은 편집자만 낸다. 항목 키와 만점은 `scoring.md`의 12항목이다.
- `turns`는 여러 턴에 걸친 패턴일 때만 쓴다. `other_changes`는 턴 밖의 변경(소제목·발음 사전 표제어)이 있을 때만 쓴다.
- `findings[].kind`
  - `must_fix` — 발행 전에 반드시 고친다. 사실 오류, 오해를 부르는 뜻풀이, 깨진 영어, 표기·배제 주제·원칙 8·9 위반이 여기에 든다.
  - `should_fix` — 고치면 좋지만 발행을 막지 않는다.
- 규칙 번호는 검토자가 아니라 판정 세션이 붙인다(2장 8번).
- `edits[].fixes`는 그 수정이 해결하는 `findings`의 순번이다. `must_fix`에는 수정안이 있어야 한다. 수정안을 만들 수 없는 `must_fix`(노트·발췌에 없는 재료가 필요하다)는 `edits` 없이 두고, `publishable: false`로 판단한다.
- 재대조 출력은 `{ "results": [ { "id": "", "fixed": true, "reason": "" } ] }`이다.

## 4. 저장 형식 — `episodes.critic_verdicts`

사람 판정(판정 화면)과 같은 키를 쓰고, 에이전트 블록을 덧붙인다. 판정 화면이 그대로 읽는다.

```json
{
  "flags":  { "1": { "verdict": "동의", "reason": "" } },
  "stars":  { "1": { "verdict": "부분동의", "reason": "" } },
  "scores": { "3.1": { "human": "6", "reason": "" } },
  "extra": "비평이 놓친 문제 요약 (한국어)",
  "judged_by": "agent:claude-opus-5-5",
  "judged_at": "ISO 시각",
  "agent": {
    "publishable": true,
    "publishable_reason": "",
    "must_fix": [ { "id": "M1", "turn": "E14", "issue": "", "by": "editor | korea", "status": "open | fixed", "edit_at": "ISO 시각 또는 null" } ],
    "report_key": "s3:<에피소드 경로>/agent-verdict.md",
    "reviewers": { "editor": "editor.md 커밋", "korea": "korea-check.md 커밋" }
  }
}
```

- `scores.*.human`은 판정 화면 호환을 위해 이름을 그대로 둔다. 값은 에이전트 점수다. 사람 판정과는 `judged_by`로 가른다.
- 사람이 판정 화면에서 저장하면 `judged_by`가 사람 이메일로 바뀌고 `agent` 블록은 남는다. 발행 조건은 `agent` 블록만 본다.

## 5. 규칙 승격

- 판정 묶음(새 규칙 버전 3편)마다 한국판과 같은 승격 절차를 밟는다. 원천은 비평 대조(2장 7번)의 동의율·기각·부분동의 사유, 규칙 대조(2장 8번), 에이전트 직접 수정이다.
- 비평이 틀린 것은 루브릭을 좁히고, 비평이 놓친 것은 guidelines·QA·L0를 신설한다.
- 승격 PR은 사람이 승인한다. 승격안은 한국어로 설명한다.

## 6. 재작성 루프 — 판정을 수정 신호로 쓰는 절차 (2026-10-22 채택)

판정 결과를 재작성 지시로 되먹여 대본을 올리고, 그 최고판을 판정하는 절차다. **루프 안의 신호와 최종 판정은 전부 서버 API(GPT)다** — 편집자 3회·한국어·사실 검토·중단·최고판 선택·발행 가능 판정을 GPT가 한다. Claude 는 루프 밖에서 표본을 채점하는 외부 기준점이고, 루프의 어떤 결정에도 쓰지 않는다(박수헌 2026-10-22: 운영은 서버 API 만으로 돌아야 하고, Claude 판정은 대본의 질이 일정 수준에 올랐는지 재는 외부 잣대다). **구현은 워커 단계 `judge_loop`**(`pipeline/apps/worker/src/stages/judge-loop.ts`, 마이그레이션 0033) — 비평이 끝나면 워커가 스스로 건다(10장 #15 해소). 실험 원본 `pipeline/.work/global-infra/rewrite-loop-server.mts`.

### 6.1 입력

- 그 편의 `script.md`(현재 판) · `claims.md` · `sources.md` · `pronunciations.json`.
- 0회차 판정 — 현재 판에 2장과 같은 눈가림 정리를 한 뒤 GPT 편집자 세 번과 GPT 한국어·사실 검토 한 번. 세 번의 항목별 가운데 값 합계가 그 회차의 점수다. **구조 점수** = 3.1 + 3.5 + 3.6 + 3.7(32점).

### 6.2 회차 — 최대 3회

1. **재작성** (GPT, effort high) — 현재 판 · 편집자 세 번의 읽기(가운데 값 읽기를 먼저) · 한국어·사실 검토 · 앞 회차에 수리한 턴 목록 · 발음 사전을 주고 전체를 다시 쓴다. 인트로 턴(Y1) · 마무리 인사 턴 · 구간 머리 · 화자 이름은 그대로. 단계가 둘이다.
   - **구조 단계** — 먼저 계획을 쓴다: 축 질문의 답 한 문장, 본문 구간마다 그 답의 어느 단계인지 · 실어 나르는 claim · 들려줄 순간(사람·장소·행동·구체 하나, 없으면 none) · 마지막 턴이 다음 구간에 남기는 질문, 오프닝의 익숙한 그림, 클로징의 새 말로 된 답. 그 계획대로 구간의 claim 배정(구성안의 구간 안에서) · 구간 시작 · 진행 턴 · 정리를 바꾼다.
   - **세부 단계** — 구조 잠금. 구간의 답 단계 · claim · 오프닝 그림 · 클로징 답은 그대로 두고 턴만 고친다: 장면의 구체, 진행 턴(한 턴 한 일 · 형식 섞기 · 다음 설명의 방향을 바꾸는 턴 둘 이상), B2 청자 기준 구어 문장, 지적된 must_fix · should_fix.
2. **L0** — 위반이 있으면 한 번만 "위반만 고치고 다른 것은 바꾸지 말라"로 되돌린다.
3. **한국어·사실 검토** (GPT) — 2장과 같은 눈가림 정리로 `korea-check.md` 를 돌린다. `must_fix` 가 있으면 **지적된 턴만** 가장 작은 변경으로 수리한다(조건으로 좁히기 · 견해 주체를 역할로 복원 · 근거 없는 사실 삭제 · 문장 삭제). 수정안은 참고일 뿐 근거가 아니다. 수리 뒤 L0 를 다시 돈다. **0회차 원판에도 같은 수리를 건다**(judge-loop-v1.3, 2026-10-23) — 종전에는 회차 안에서만 수리해, 최고판이 원판에 머문 편(G261023-010·018·020, 60~61점)이 점수는 넘고도 must_fix 미수리로만 막혔다. 원판 수리본의 L0 는 초안의 `script-notes.md`(턴별 claims)로 돌리고, L0 위반이 나오면 수리를 버리고 원판을 둔다. 원판이 최고판이어도 수리본이면 `script.md` 를 덮어쓴다.
4. **편집자 세 번** (GPT, 눈가림) — 항목별 가운데 값으로 합계와 구조 점수를 낸다. **3과 4는 같은 판(수리 전)에 동시에 돌린다** (2026-10-23) — 직렬이면 회차당 16~17분, 편당 1시간이었다. must_fix 수리는 지적된 턴만의 최소 변경이라 점수에 반영하지 않는다.
5. **단계 전환 · 중단 · 최고판**
   - 합계가 지금까지의 최고를 넘으면 그 판이 최고판이다.
   - 구조 단계에서 구조 점수가 최고판보다 1점 이상 오르지 않으면 구조를 잠그고 세부 단계로 간다.
   - 세부 단계에서 합계가 오르지 않으면 멈춘다. **2회차부터는 단계와 무관하게 합계가 오르지 않으면 멈춘다** (2026-10-23 — G261023-001 이 1회차 66 → 2회차 66 → 3회차 64 로, 세 번째 회차는 20분과 $0.5 만 썼다).
   - 다음 회차의 바탕은 "점수가 올랐거나 아직 구조 단계면 이번 판, 아니면 최고판"이다.

### 6.3 출력과 기록

- 최고판 대본과 회차마다의 대본 · 계획 · 한국어 검토 · 편집자 세 번 · 점수표. 어느 회차가 최고판인지 적는다.
- 최고판을 고르는 데도, 발행 가능 판정에도 GPT 점수만 쓴다. **발행 가능 = 최고판의 편집자 중앙값 ≥ 기준 · 한국어·사실 검토 발행 가능 · 한국어 must_fix 전부 수리.** 기준은 `settings.automation.judge_threshold`, **기본 60**(2026-10-23 박수헌 — 종전 65, 2026-10-22). 65 는 GPT 편집자가 같은 판을 Claude 보다 6~11점 후하게 보는 것(7장)을 보정한 값이었다. 첫 운영 배치(C69~C97, 28편)에서 6편만 65 를 넘었고, 60~64 편의 편집자 평이 "필수 수정 없이 발행 가능 · 장면보다 설명이 많다"로 66~70 편과 같은 지적(정확성이 아니라 연출 밀도)이어서 60 을 하한으로 정했다. 57~59 편은 "구조를 다시 연결해야 출판 수준"으로 어조가 다르다. 이미 저장된 판정은 재판정 없이 새 기준으로 다시 셌다(`apply-threshold.mts`, 한국어 must_fix 미수리 편은 그대로 차단). Claude 표본 채점으로 주기적으로 다시 맞춘다. 편집자 must_fix 는 점수에 녹아 있으므로 관문이 아니라 기록(`agent.editor_findings`)이다. 판정은 4장 형식으로 `critic_verdicts` 에 저장(`judged_by agent:<GPT 모델>`), 최고판은 `script.md`·`pronunciations.json` 에 덮어쓴다(S3 버저닝). 발행 준비 자동 스위치가 켜져 있으면 **판정 루프가 끝나는 자리에서 한 번** tts 연쇄를 건다(한국판 비평 끝과 같은 함수, 2026-10-23 — 종전 1분 폴링은 폐기). 판정 저장 직전에 **발음 관문**(judge-loop-v1.4)을 지난다: 발음 맵의 빈 읽기를 GPT 한 호출로 채우고, 남으면 발행 불가. **회차 체크포인트**(judge-loop-v1.5, 2026-10-23): 회차가 끝날 때마다 `judge/checkpoint.json`(회차 기록·기준판·최고판·단계·비용)을 S3 에 올리고, 배포 등으로 끊긴 작업이 다시 집히면 같은 입력(script.md·pronunciations.json 해시)·같은 루프 버전·12시간 안일 때 그 다음 회차부터 잇는다. 루프가 끝나면 done 으로 바꿔 재판정은 처음부터 돈다. 근거: 2026-10-23 배포 6회에 루프 10회가 처음부터 다시 돌았다(약 $15).
- **시간 단축**(judge-loop-v1.7, 2026-10-23 박수헌 "루프 시간이 말이 안 된다") — 첫 배치 실측 편당 24~41분(회차당 8~10분). 세부 회차 재작성과 한국어·사실 검토를 effort **medium** 으로(구조 회차 재작성만 high), **회차 상한 2**(20루프 중 3회차가 최고판을 올린 건 1편). 단계별 시간(재작성·L0 수정·검토·수리)을 `rounds[].ms` 와 로그에 남겨 다음 조정의 근거로 쓴다. env `JUDGE_REWRITE_EFFORT_STRUCTURE`·`JUDGE_REWRITE_EFFORT_DETAIL`·`JUDGE_KOREA_EFFORT`·`JUDGE_MAX_ROUNDS` 로 배포 없이 되돌린다. 목표: 편당 15~20분.
- 비용은 편당 3회차에 약 $1.7~2.3(GPT), 회차당 10~12분(검토·채점 병렬, 2026-10-23 — 그 전 16~17분). 워커는 글로벌 인스턴스에 4개를 띄워(`WORKER_GLOBAL_REPLICAS`) 판정 중에도 TTS·초안이 돈다. 루프의 OpenAI 호출은 **백그라운드 모드**(`background: true` → `GET /responses/{id}` 조회)다 — 재작성 한 호출이 10분을 넘으면 동기 요청은 연결이 끊겨 같은 편이 번번이 실패했다(2026-10-23 G261023-013·016, 두 번 다 1회차 재작성에서 `fetch failed`, 편당 65~99분 낭비). 배경 모드로 바꾼 뒤 드러난 두 번째 실패는 **생각 폭주**다 — 원판 채점이 13분 만에 출력 상한 65,536 토큰에 닿고(G261023-003·016), 편집자 채점이 20분을 넘겼다(015). 그래서 채점·검토·수리 호출은 출력 상한을 24,576 으로 낮춰 몇 분 안에 끊고 한 번 다시 부르며(재작성은 65,536 그대로), 상한 도달·시간 초과도 한 번 재시도한다(judge-loop-v1.2). 외부 Claude 채점을 함께 돌리면 편당 Claude 호출이 회차마다 3회 더 든다 — 기준점 측정 때만 켠다.
