# 라이브러리(메인) 기능 명세서

> 연결 PRD: FR-20, FR-16, FR-24, FR-32 / 사용자흐름 5.2

## 1. 목적 & 연결

앱의 첫 화면이자 핵심 루프의 시작점. 자동 드립으로 적립된 콘텐츠와 사용자가 직접 담은 콘텐츠를 하나의 목록으로 보여주고, 탭 한 번으로 즉시 재생에 도달하게 한다.

**라이브러리는 하나다.** 드립과 담기를 별개의 보관함으로 나누지 않는다. 드립만 따로 보고 싶을 때를 위해 **필터 시트의 출처 옵션**을 두지만, 기본은 통합 목록이다.

- PRD FR-20 (P0) 드립·담은 콘텐츠 통합 목록, 필터, 미청취/완료 상태 관리, 삭제
- PRD FR-24 (P0) 이어듣기 — 마지막 재생 콘텐츠·위치 유지. **진입점은 이어듣기 카드가 아니라 미니플레이어다**(4.2)
- PRD FR-16 (P0) 중복 적립 방지
- PRD FR-32 (P0) 파트너 회수 콘텐츠 즉시 제외
- PRD 사용자흐름 5.2

## 2. 진입 조건

- 온보딩 완료 사용자가 앱을 실행할 때(기본 진입 화면)
- 하단 탭에서 [라이브러리] 탭을 선택할 때
- 플레이어·프로필 등에서 뒤로가기로 복귀할 때

**하단 탭은 3개다** — `라이브러리 / 탐색 / 프로필`

- 설정은 **하단 탭에 두지 않는다.** 프로필 화면 우상단의 설정 아이콘으로 들어간다(`profile.md`).
  - 이유: 설정은 진입 빈도가 가장 낮은데 탭을 차지하면 매일 쓰는 세 화면의 폭이 줄어든다. 계정에 관한 것은 프로필에 모여 있으므로 설정도 그 안에 있는 편이 찾기 쉽다.
- 라이브러리가 기본 탭이다. 앱을 실행하면 항상 여기로 들어온다.

## 3. 입력값

**조회 요청**

| 값 | 설명 | 필수 |
|---|---|---|
| user_id | 인증 토큰에서 도출 | 필수 |
| filter | all / unplayed / completed — **상태 전용**(상단 탭) | 선택(기본 all) |
| source_filter | drip / save — 출처(필터 시트). `save`는 `save + onboarding` | 선택 |
| topic_filter | 주제 id 목록 (필터 시트에서 선택) | 선택 |
| sort | added_desc(기본) / added_asc | 선택 |
| cursor | 페이지네이션 커서 | 선택 |

**사용자 조작**

| 조작 | 입력 |
|---|---|
| 아이템 탭 | content_id → 즉시 재생 |
| 아이템 삭제 | content_id (스와이프 또는 더보기 메뉴) |
| 원문 보기 | content_id (더보기 시트 — `source_url` 있는 콘텐츠만 노출, 확정 2026-08-10) → 인앱 브라우저로 원문 열기 + 원문 유입 클릭 기록(`player.md` 4.5와 같은 규칙 — `source_link_clicks`) |
| 상태 변경 | content_id, target_status |
| 당겨서 새로고침 | — |
| 잔여 재생 표시 탭(소진 상태) | — → 페이월 바텀시트 |
| 재생 확인 팝업의 [오늘은 그만 보기] | — → 재생 + 오늘 팝업 억제(4.3) |

**서버가 목록 응답에 함께 실어 보내는 표시값 — 잔여 재생 횟수**

| 값 | 설명 | 필수 |
|---|---|---|
| daily_play_limit | `plans.daily_play_limit`. **null이면 무제한** | 필수 |
| daily_play_count | 서버가 `play_records`를 집계한 **파생값**(컬럼이 아니다 — `domain.md` 1.4) | `daily_play_limit != null`일 때 필수 |
| service_date | 서버가 계산한 오늘의 서비스 날짜(04:00 KST 경계 — `domain.md` 1.2) | 필수 |

- **잔여 횟수는 목록 조회 응답에 얹어 받는다.** 별도의 카운트 API를 따로 호출하지 않는다.
  - 이유: 화면 한 번 그리는 데 왕복이 두 번이면 목록과 잔여 표시의 시점이 어긋난다. "3회 남음"을 보면서 탭했는데 페이월이 뜨는 상황이 그렇게 만들어진다.
- **`service_date`를 함께 받는 이유는 팝업 억제(4.3)의 유효 기간을 기기 시각이 아니라 서버 날짜로 판단하기 위해서다.** 기기 시각을 믿으면 시각을 되돌려 억제를 무한정 연장할 수 있고, 반대로 04시가 지났는데도 억제가 풀리지 않는 일이 생긴다(`paywall.md` 4.4).

## 4. 처리 로직

### 4.1 목록 구성

1. `LibraryItem`을 `added_at` 내림차순으로 조회한다. 드립과 담기를 **출처로 구분하지 않고 하나의 목록**으로 섞는다(FR-20 "통합 목록").
   - **카드에 출처 배지를 두지 않는다**(개편 2026-08-07). 출처는 카드마다 반복할 정보가 아니라 필터로 다루는 축이다 — 출처별로 보고 싶은 요구는 필터 시트의 출처 섹션이 받는다(4.1-1).
2. **이어듣기 카드는 두지 않는다.** 목록 맨 위를 카드 하나가 차지하면 정작 새로 도착한 콘텐츠가 밀려 내려가고, 미니플레이어와 같은 일을 두 군데서 하게 된다. 이어듣기 진입점은 **미니플레이어 하나로 통일한다**(4.2).
3. 페이지네이션은 커서 기반 20건 단위 무한 스크롤.

### 4.1-1 필터 — 상단 탭 3개(상태) + 필터 시트(출처·주제)

> **개편 2026-08-07** — 탭 4개 중 [이어 PICK]을 필터 시트의 출처 옵션으로 옮겼다. 탭은 **상태만** 가른다.

**상단 탭 — 상태 전용**

| 탭 | 조건 |
|---|---|
| **전체** | 통합 목록(기본) |
| **미청취** | 아직 완청하지 않은 것 — `unplayed` + `in_progress` |
| **완료** | `completed` |

- **탭에 출처를 섞지 않는다.** 상태와 출처가 한 줄에서 배타적으로 경쟁하면 "미청취 + 드립"처럼 두 축을 동시에 거는 보기를 만들 수 없다. 축이 다른 것은 컨트롤을 나눈다.
- **"미청취"에 `in_progress`를 포함한다.** 듣다 만 콘텐츠는 사용자 입장에서 아직 안 들은 것이다. 진행률 바로 구분되므로 탭을 따로 팔 이유가 없다.
- 탭은 서로 배타적이다. 한 번에 하나만 선택된다.

**필터 시트 — 출처 + 주제**

탭 우측의 **필터 아이콘**을 탭하면 **필터 바텀시트**가 올라온다. 구성은 `출처 섹션 + 주제 섹션 + [초기화] + [적용]`이다.

| 섹션 | 선택 방식 | 옵션 |
|---|---|---|
| **출처** | 단일 선택(재탭 해제) | **이어 PICK** = `source = drip` / **내가 담은 콘텐츠** = `source IN (save, onboarding)` |
| **주제** | 다중 선택 | 라이브러리에 실제로 담긴 콘텐츠의 주제 |

- **출처를 탭이 아니라 필터에 둔다.** 드립만 모아 보고 싶은 요구는 여기가 받는다. 컨트롤 위치는 바뀌었지만 **"담기 전용 보관함을 따로 만들지 않는다"는 원칙은 그대로다** — 라이브러리는 여전히 하나이고 기본 화면이 통합 목록이며, 출처는 같은 목록을 거르는 조건일 뿐이다.
- **"내가 담은 콘텐츠"에 온보딩 적립분을 포함한다.** 온보딩의 [담기]도 사용자가 직접 고른 것이다. `source = onboarding`을 따로 기록하는 것은 유입 경로 분석용이지 사용자에게 제3의 출처를 보여주기 위해서가 아니다.
- **출처 라벨을 "추천"으로 두지 않는다.** 탐색의 추천 피드와 같은 단어를 쓰면 두 화면에서 같은 단어가 서로 다른 것을 가리킨다. 서비스 이름을 붙인 **"이어 PICK"** 은 "이어가 골라 보내준 것"이라는 출처를 라벨 자체가 말하고, 내부 용어인 "드립"을 노출하지 않는다.
- 주제 선택은 **탭 줄에 칩으로 늘어놓지 않는다.** 주제 칩을 상단에 펼치면 가로 스크롤이 생기고 탭과 섞여 무엇이 상태이고 무엇이 주제인지 구분되지 않는다.
  - 주제는 **사용자의 관심 주제가 아니라 라이브러리에 실제로 담긴 콘텐츠의 주제**를 노출한다. 담긴 게 없는 주제를 보여줘야 소용이 없다.
- **적용 중인 필터는 아이콘에 배지로 표시한다.** 배지 숫자는 **출처 + 주제 선택 개수의 합**이다. 시트를 닫으면 무엇이 걸려 있는지 보이지 않으므로, 배지가 없으면 "왜 목록이 비었지"가 된다.
- **탭·출처·주제는 AND 조합이고, 선택한 주제끼리만 OR다.** 예: [미청취] 탭 + 출처 `이어 PICK` + 주제 `커리어` → 커리어 주제의, 드립으로 받은, 아직 안 들은 콘텐츠.

**카드의 상태 표현 — 3번째 줄을 두지 않는다**

카드는 `썸네일 / 제목 / 출처·저자·길이` 2줄이다. 출처 배지와 상태 텍스트를 없앤 자리에 상태는 다음으로 표현한다.

| 상태 | 표현 |
|---|---|
| `unplayed` | **표시 없음.** 기본 상태가 곧 미청취다 |
| `in_progress` | 진행률 바만(텍스트 없음). 접근성 라벨로 "N% 들음"을 제공한다 |
| `completed` | **썸네일 좌상단 체크 마킹** |

- **완청을 회색 제목으로 표현하지 않는다.** 색이 유일한 단서가 되면 색각 이상·고대비 모드에서 구분이 사라진다(`library-uiux.md` 7장 — 색만으로 상태를 구분하지 않는다).

### 4.1-2 잔여 재생 횟수 표시

**오늘 남은 재생 횟수를 앱바 우측에 상시 노출한다.** 재생 확인 팝업은 탭한 뒤에야 뜨므로, 그것만으로는 **탭하기 전에** 남은 횟수를 알 방법이 없다.

- 자리는 **화면 상단 앱바("라이브러리" 타이틀 줄)의 우측 한 곳**이다.
  - **카드마다 붙이지 않는다.** 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다. 카드마다 같은 숫자를 반복하면 콘텐츠별 제한처럼 읽히고, 한 편을 재생할 때마다 목록에 떠 있는 숫자가 전부 동시에 바뀐다.
  - **탭 줄에 넣지 않는다.** 탭과 필터 아이콘이 쓰는 줄이고, 상태 필터와 하루 잔여량은 성격이 다르다. 같은 줄에 두면 숫자가 네 번째 탭처럼 읽힌다.
- 문구는 **"오늘 재생 N/M 남음"** 이다(N = 남은 횟수, M = `daily_play_limit`). `paywall.md` 5장이 규정한 힌트와 **같은 문자열을 쓴다** — 두 문서가 각자 문구를 만들면 같은 값이 화면마다 다른 말로 표시된다.

| 조건 | 표시 |
|---|---|
| `daily_play_limit != null` (무료·한도 있는 유료) | 앱바 우측에 **"오늘 재생 N/M 남음"** |
| `daily_play_limit == null` (무제한) | **아무것도 표시하지 않는다.** 자리를 비우고 "무제한" 배지도 두지 않는다 |
| N == 0 (소진) | **"오늘 재생 0/M 남음"** 을 주의색으로 유지한다. 숨기지 않는다 |

- **무제한 티어에 카운터를 두지 않는 이유는 확인 팝업을 띄우지 않는 이유와 같다**(4.3). 셀 것이 없는데 숫자를 보여주면 없는 한도가 있는 것처럼 읽히고, "무제한" 배지를 대신 두면 매 화면마다 요금제를 광고하는 꼴이 된다.
- **0일 때 숨기지 않는다.** 0이야말로 알려야 할 상태다. 숨기면 탭한 뒤 페이월이 뜨고 나서야 소진 사실을 알게 된다.
  - 0인 상태에서 이 표시를 탭하면 **페이월 바텀시트를 연다**(`paywall.md` 4.5). 이미 소진한 사용자에게는 이 자리가 가장 가까운 전환 경로다. **최상위 티어는 페이월 대신 한도 안내를 띄운다**(`paywall.md` 4.1).
- 갱신 시점: **목록을 조회할 때마다 서버 값으로 덮어쓴다.** 당겨서 새로고침·포그라운드 복귀(4.6)·플레이어에서 라이브러리로 복귀할 때가 여기 해당한다.
  - **단 무조건 덮어쓰지는 않는다.** 탭·필터 조합별 캐시와 지연 응답 때문에 여러 시점의 값이 섞여 도착하므로, 어느 값을 믿을지는 `paywall.md` 5장의 **신선도 규칙**(같은 날짜·같은 한도면 `daily_play_count`가 큰 쪽을 믿는다)을 따른다. 그 규칙이 없으면 재생 직후 탭을 옮길 때 차감 전 숫자가 역행한다.
  - **클라이언트가 임의로 1을 빼지 않는다.** 차감은 재생이 실제로 시작된 시점에만 일어나므로(`paywall.md` 4.3), 재생 버튼을 누른 것만으로 숫자를 줄이면 오디오 로드에 실패했을 때 실제보다 적게 표시된다.
  - **초기화 경계는 자정이 아니라 04:00 KST다**(`domain.md` 1.2, `paywall.md` 4.4). 배치로 리셋되는 값이 아니라 서버가 판정 시점에 서비스 날짜로 집계한 값이다.
  - **클라이언트가 시계를 보고 스스로 숫자를 되돌리지 않는다.** 앱을 켜 둔 채 04시를 넘겼다면 다음 재조회 때 갱신된다. 기기 시각으로 리셋을 판단하면 시각 조작만으로 한도가 초기화된 것처럼 보인다.
- **이 숫자는 판정이 아니라 힌트다.** 재생 허용 여부는 탭한 시점에 서버가 다시 판정한다(`paywall.md` 4.1). 표시된 숫자를 근거로 재생을 통과시키면 한도가 새는 구멍이 된다.
- 같은 규칙을 **탐색 화면에도 동일하게 적용한다**(`explore.md`). 두 화면이 다른 숫자를 보여주면 어느 쪽이 맞는지 사용자가 판단하게 된다.

### 4.2 앱 실행 시 미니플레이어 복원

**앱을 실행하면 가장 최근에 듣던 콘텐츠를 미니플레이어에 띄운다.**

- 대상은 **완청하지 않은 콘텐츠 중 `last_played_at`이 가장 최근인 1건**이다. 완료된 콘텐츠는 띄우지 않는다 — 이미 끝난 것을 이어들 자리는 없다.
- **자동으로 재생하지 않는다.** 일시정지 상태로 표시만 하고, 사용자가 탭하거나 재생 버튼을 눌러야 소리가 난다.
  - 이유: 앱을 열자마자 소리가 나면 공공장소에서 문제가 된다. 이어듣기는 제안이지 실행이 아니다.
- 미니플레이어에는 썸네일 · 제목 · 진행률 · 재생 버튼을 둔다. 본문을 탭하면 전체 플레이어로 확장된다.
- 대상이 없으면(신규 사용자, 완청만 있는 사용자) **미니플레이어를 띄우지 않는다.** 빈 미니플레이어를 두지 않는다.
- 미니플레이어에서 재생을 시작할 때도 **재생 확인 팝업(4.3)과 재생 제한 판정을 동일하게 거친다.** 진입점이 다르다고 규칙이 달라지지 않는다.
- 재생 위치는 `playback_progresses.position_sec`이 소유한다(`library_items`에 위치 컬럼 없음).

### 4.3 아이템 탭 → 재생 확인 팝업 → 재생

카드 본문 탭 = **즉시 재생**(PRD 5.2). 상세 화면을 거치지 않는다. 다만 **재생 전에 확인 팝업을 한 번 거친다.**

팝업의 조건·문구·버튼·억제 규칙은 `paywall.md` 4.2가 소유하며, 이 절은 라이브러리 화면에의 적용만 서술한다.

```
아이템 탭
   ↓
재생 한도 판정 (paywall.md 4.1~4.2)
   ├─ 한도 소진        → 페이월 바텀시트 (팝업 없음.
   │                     **최상위 티어는 페이월 대신 한도 안내** — paywall.md 4.1)
   ├─ 차감이 발생함
   │     ├─ 오늘 팝업이 억제됨   → 팝업 없이 바로 플레이어
   │     └─ 억제되지 않음        → 재생 확인 팝업 → [재생하기] → 플레이어
   └─ 차감이 없음      → 팝업 없이 바로 플레이어
```

**재생 확인 팝업**

- 내용: **오늘 남은 재생 횟수**와 **이 재생으로 1회가 차감된다는 사실**을 알린다
  - 예: "오늘 3회 남았어요. 재생하면 1회가 차감돼요." + [취소] / [재생하기]
- [재생하기]를 눌러야 플레이어로 이동한다. [취소]는 라이브러리에 그대로 머문다.
- **차감이 실제로 일어나는 재생에만 띄운다.** 아래 두 경우는 팝업 없이 바로 재생한다.
  - **재생 한도가 없는 티어**(무제한): 남은 횟수라는 개념 자체가 없어 알릴 내용이 없다
  - **재청취 창 내 콘텐츠**: 재생 카운트는 `(사용자, 콘텐츠, 날짜)` 기준 1회이고(README 결정 22번), 차감일로부터 **15일간은 재청취가 차감되지 않는다**(`paywall.md` 4.3-1 — 확정 2026-08-10). 듣던 것을 이어듣거나 다시 트는 것은 차감되지 않는다
  - 원칙은 **"차감되지 않는데 차감된다고 알리지 않는다"** 이다. 사실과 다른 고지는 재생을 망설이게 만든다.
- 한도를 이미 소진했다면 팝업이 아니라 **페이월 바텀시트**를 띄운다(`paywall.md`). 남은 횟수 0을 알리는 팝업과 페이월을 연달아 띄우지 않는다.
- 통과 시 플레이어를 열고 `playback_progresses.position_sec`부터 재생(0이면 처음부터). 재생 위치는 목록 조회 시 조인해 가져온다.

**[오늘은 그만 보기] — 팝업 억제**

팝업 하단에 **[오늘은 그만 보기] 텍스트 버튼**을 둔다. [취소] / [재생하기]와 나란히 세우지 않는다.

- 이유: 주 동작은 여전히 재생과 취소다. 같은 크기의 버튼을 셋 두면 무엇이 기본 동작인지 흐려지고, 잘못 눌러 하루치 고지를 끄게 된다.
- **누르면 팝업을 닫고 그대로 재생한다.** 재생하지 않고 닫히면 [취소]와 구분되지 않고, 사용자는 다시 탭해야 하는데 그때는 팝업이 없어 방금 무엇이 바뀐 건지 알 수 없다.
  - 이 버튼을 누르는 맥락은 "알겠으니 그냥 틀어달라"이다. 차감 고지는 이미 눈앞에 떠 있는 상태에서 누르는 것이므로 **고지 없이 재생되는 경우가 생기지는 않는다.**
- **억제 범위는 재생 확인 팝업 하나뿐이다.** 페이월·한도 안내·회수 안내는 억제되지 않고, 차감도 그대로 일어난다.
  - **억제한 것은 고지이지 판정이 아니다.** 판정은 `paywall.md` 4.1이 소유하며 클라이언트의 표시 설정이 그것을 건드리지 못한다.
- **유효 기간은 오늘의 서비스 날짜까지다** — 자정이 아니라 **04:00 KST 경계**에서 풀린다(`domain.md` 1.2).
  - 한도 리셋과 같은 경계를 써야 한다. 경계가 다르면 "한도는 이미 리셋됐는데 고지는 계속 억제된" 구간이 매일 생긴다.
  - 저장하는 값은 만료 타이머가 아니라 **억제한 서비스 날짜 자체**다. 서버가 응답에 실어준 `service_date`(3장)와 다르면 억제가 풀린 것으로 본다 — 기기 시각을 신뢰하지 않기 위해서다.
- **억제 상태는 기기 로컬에 저장한다. 서버에 저장하지 않는다.**
  - 팝업은 판정이 아니라 표시 UI이므로 서버 상태로 만들 이유가 없다. 서버에 두면 **파생값도 아닌 새 컬럼**이 하나 생기고, 그 컬럼과 실제 판정이 어긋날 여지가 다시 생긴다(`domain.md` 1.4의 문제와 같은 종류다).
  - 기기를 바꾸면 다시 뜬다. **의도된 동작이다** — 처음 쓰는 기기에서는 차감 고지를 한 번은 봐야 한다.
- **억제는 그 기기의 모든 진입점에 적용된다** — 라이브러리 카드·미니플레이어·탐색·푸시 어디서 눌렀든 같다(`paywall.md` 4.2와 동일한 4개 진입점). 같은 날 화면마다 다시 묻는다면 억제할 이유가 없다.
- **별도의 해제 수단은 두지 않는다.** 최대 하루짜리 상태를 설정 화면에 항목으로 남기면, 하루면 사라질 것을 사용자가 계속 관리하게 된다.

### 4.4 상태 관리

- `unplayed` → 재생 시작 시 `in_progress`로 전환
- `in_progress` → **완청 판정**을 만족하면 `completed`
  - 완청 기준: **최대 도달 위치(`max_reached_sec`)** 기준으로 콘텐츠 길이의 **90% 이상** — 시크로 점프한 구간은 도달로 치지 않는다(`player.md` 4.4)
- **수동 완료 표시 기능은 제공하지 않는다.** 상태는 실제 재생 결과로만 바뀐다 — 신호의 의미를 흐리지 않기 위해서다
- 완료된 아이템은 목록에서 자동 제거하지 않는다(재청취 지표 수집 — PRD 10). 재청취는 차감일로부터 15일간 한도 소모가 없다(`paywall.md` 4.3-1)

### 4.5 삭제

- 스와이프 또는 더보기 > [라이브러리에서 삭제]
- **재생 중인 콘텐츠를 삭제해도 플레이어와 재생에는 영향이 없다**(확정 2026-08-10 — `player.md` 7장). 삭제 결과는 스낵바로만 알린다
- 확인 팝업 없이 즉시 삭제 + **[실행 취소] 스낵바 5초**
- 삭제는 `library_items`만 소프트 삭제하며 콘텐츠 자체·**재생 이력(`playback_progresses`)은 남긴다**
- 삭제 시 서버가 **`user_signals(action = delete)`를 적재한다**(FR-15 — `domain.md` 6.4 action enum, `drip-scheduling.md` 4.3의 입력)
- 삭제된 콘텐츠는 `drip_excluded_contents`에 적재되어 **드립 재적립 대상에서 영구 제외**된다(FR-16). 단 탐색에서 사용자가 직접 다시 담는 것은 허용한다
  - **삭제 경로를 구분하지 않는다.** 라이브러리 삭제든 탐색 담기 해제든 결과는 동일하게 영구 제외다

**영구 제외 사실은 사용자에게 알리지 않는다**

- 삭제 시 "이 콘텐츠는 다시 추천되지 않아요" 같은 **안내 문구·확인 팝업을 노출하지 않는다.** 스낵바는 "삭제했어요" + [실행 취소]만 둔다.
  - 이유: 삭제는 목록 정리에 가까운 가벼운 조작인데, 영구적이라는 고지가 붙는 순간 결정처럼 무거워진다. 지우기를 망설이면 라이브러리가 정리되지 않고, 그 상태가 쌓이면 라이브러리 자체를 안 열게 된다.
  - 되돌릴 수단은 남아 있다 — 탐색에서 직접 다시 담으면 라이브러리로 돌아온다. **되돌릴 수 없는 조작이 아니므로 경고할 사안이 아니다.**
- 동작 자체는 그대로다. 알리지 않을 뿐 **제외는 영구적으로 적용된다.**
- 오프라인 저장분이 있으면 로컬 파일도 함께 삭제한다 *(오프라인 저장은 P1 이연 — FR-26)*

### 4.6 새로고침·드립 반영

- 당겨서 새로고침 시 서버에서 최신 목록 재조회
- 앱 포그라운드 복귀 시에도 조용히 재조회(로딩 인디케이터 없음)
- 새로 도착한 드립이 있으면 상단에 "새 콘텐츠 N개 도착" 배너를 노출한다
  - **배너가 알리는 사건은 드립 도착 하나다.** 담기·온보딩 적립·탐색 재생의 자동 적립(`explore.md` 4.4)은 배너 대상이 아니다 — 사용자가 스스로 한 조작이고, 그 결과는 조작한 화면이 이미 알렸다. 자기가 방금 담은 것을 "도착했어요"로 다시 알리면 사용자는 자기가 하지 않은 일이 일어났다고 읽는다
  - 판정은 클라이언트가 하되 **드립만 세고, 세는 방식은 `spec/api/library-api.md` 4.1이 정한다**

### 4.7 회수 콘텐츠 처리

- 파트너 회수(FR-32)된 콘텐츠는 서버 응답에서 제외되어 목록에서 사라진다
- 이미 화면에 떠 있는 상태에서 재생을 시도하면 서버가 403을 반환 → "제공이 종료된 콘텐츠예요" 안내 후 목록에서 제거

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 로딩 | 스켈레톤 카드 5개 |
| 정상 | 앱바(타이틀 + 우측 잔여 재생 표시) + **탭 3개(전체·미청취·완료) + 필터 아이콘** + 아이템 리스트 + 하단 미니플레이어 |
| 잔여 재생 — 한도 있는 티어 | 앱바 우측에 **"오늘 재생 N/M 남음"** |
| 잔여 재생 — 무제한 티어 | **표시하지 않음.** 자리를 비운다("무제한" 배지도 없음) |
| 잔여 재생 — 소진(N=0) | **"오늘 재생 0/M 남음"** 을 주의색으로 유지. 탭하면 페이월 바텀시트 |
| 잔여 재생 — 캐시 목록·값 없음 | **표시하지 않음**(낡은 숫자를 확신 있게 보여주지 않는다 — 7장) |
| 앱 실행 직후 | 최근에 듣던 콘텐츠가 **미니플레이어에 일시정지 상태로** 노출 |
| 이어들을 콘텐츠 없음 | 미니플레이어를 띄우지 않음(빈 미니플레이어 없음) |
| 필터 미적용 | 필터 아이콘 기본 상태 |
| 필터 적용 중 | 필터 아이콘에 **배지(출처 + 주제 선택 개수의 합)** |
| 필터 시트 | 바텀시트 — **출처 단일 선택** + 주제 다중 선택 + [초기화] / [적용] |
| 재생 확인 팝업 | "오늘 N회 남았어요. 재생하면 1회가 차감돼요." + [취소] / [재생하기] + 하단 **[오늘은 그만 보기]** 텍스트 버튼 |
| 재생 확인 팝업 억제 중(오늘·이 기기) | 차감이 발생해도 팝업 없이 바로 플레이어. 잔여 표시·페이월은 그대로 동작 |
| 빈 상태 — 신규 | "곧 첫 콘텐츠가 도착해요" + [탐색 둘러보기] 버튼 |
| 빈 상태 — 필터 결과 없음 | "조건에 맞는 콘텐츠가 없어요" + [필터 초기화] |
| 빈 상태 — 출처 필터 = 이어 PICK | "아직 도착한 이어 PICK이 없어요" |
| 빈 상태 — 전부 삭제 | "라이브러리가 비어 있어요" + [탐색 둘러보기] |
| 드립 준비 중·고갈 | 상단 안내 배너 **"콘텐츠를 준비하고 있어요" + [관심 주제 추가하기]** → 관심사 관리(`interest-management.md`). 온보딩 직후 트리거 실패·지연, 드립 후보 고갈, 주제 해제로 갱신이 멈춘 경우 모두 이 배너 하나로 안내한다(`drip-scheduling.md` 5와 문구 통일). **이 배너가 라이브러리의 관심사 관리 진입점이다**(합의 2026-08-06 — PRD 5.5의 프로필·설정 경로에 **더해** 추가한 팀 결정이며 PRD 원문에 라이브러리 경로는 없다. 상시 메뉴가 아니라 배너 노출 시에만) |
| 네트워크 오류 | 캐시된 목록 + 상단 오프라인 배너. 캐시도 없으면 에러 화면 + [다시 시도] |
| 추가 로딩 | 리스트 하단 스피너 |
| 삭제 직후 | 아이템 제거 애니메이션 + **"삭제했어요" + [실행 취소]** 스낵바 (재추천 관련 문구 없음) |
| 재생 차단(무료 소진) | 페이월 바텀시트 오버레이 (재생 확인 팝업은 뜨지 않음) |

**아이템 카드 구성**: 썸네일(완청 시 좌상단 체크) / 제목 / 출처·저자·길이 / 진행률 바(`in_progress`만) / 더보기 버튼 — **출처 배지와 상태 텍스트는 두지 않는다**(4.1-1)

**하단 탭**: 라이브러리 / 탐색 / 프로필 3개. 설정은 프로필 화면 안의 아이콘으로 진입한다.

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `library_items` — 소프트 삭제, `(user_id, content_id)` 유니크가 중복 적립 방어선 | 6.1 |
| `playback_progresses` — **재생 위치의 단독 소유자**(`library_items`에 위치 컬럼 없음) | 6.2 |
| `contents` | 5.1 |
| `drip_excluded_contents` — 삭제 시 여기에 적재 | 7.1 |
| `play_records` — **잔여 재생 횟수의 유일한 근거**. 집계로 구하며 카운트 컬럼은 존재하지 않는다 | 6.3 |
| `plans` — `daily_play_limit`(null = 무제한). 잔여 표시의 분모 | 8.1 |

- **잔여 재생 횟수를 저장하는 컬럼을 새로 만들지 않는다.** 판정 시점의 `play_records` 집계로만 구한다(`domain.md` 1.4 — 파생값은 컬럼으로 두지 않는다). 이 화면은 서버가 계산해 내려준 값을 표시만 한다.
- 클라이언트 로컬 캐시: 최근 목록 1페이지, 재생 위치(서버 동기화 실패 대비), **재생 확인 팝업 억제 플래그 + 억제한 서비스 날짜**(4.3 — 서버에 저장하지 않는 기기 로컬 값이다)

## 7. 예외 상황

- **삭제 후 [실행 취소]를 눌렀는데 서버 삭제가 이미 반영된 경우**(오프라인 큐 지연 등으로 서버 반영이 실행 취소보다 먼저 끝난 때 — 공통 규칙은 스낵바 소멸 후에 서버 요청을 보내므로 온라인 정상 경로에서는 생기지 않는다, `common-error-handling.md` 4.4): 재적립(`deleted_at = null`)으로 복구하며, 원래 `added_at`을 유지해 목록 순서가 바뀌지 않게 한다.
- **여러 기기에서 같은 콘텐츠 재생**: 재생 위치는 `updated_at`이 최신인 값이 이긴다(last-write-wins). 충돌 UI는 두지 않는다.
- **재생 중인 콘텐츠를 라이브러리에서 삭제**: 재생은 중단하지 않는다. 미니플레이어는 유지하되, 재생 종료 시 진행률을 저장하지 않는다.
- **완청 판정 경계**(90% 도달 후 뒤로 되감아 다시 들음): 한 번 `completed`가 되면 되감아도 상태를 되돌리지 않는다. 단 `playback_progresses.position_sec`은 갱신한다.
- **콘텐츠 길이 정보가 없거나 0인 경우**: 완청 판정 불가 → 재생 종료 이벤트로만 `completed` 처리. (`admin.md` 4.2의 업로드 검증이 길이 0·추출 실패를 거부하므로 정상 경로에서는 발생하지 않는 방어적 처리다.)
- **오프라인 상태에서 삭제**: 로컬에서만 제거하고 큐에 넣어 온라인 복귀 시 동기화한다.
- **드립과 사용자 담기가 동시에 같은 콘텐츠를 적립**: `(user_id, content_id)` 유니크 제약으로 1건만 남기고, `source`는 먼저 적립된 값을 유지한다.
- **필터가 걸린 상태에서 새 드립 도착**: 배너는 노출하되 탭·출처·주제 필터를 유지한다.
- **미니플레이어에 뜬 콘텐츠를 라이브러리에서 삭제**: 미니플레이어를 내린다. 재생 중이었다면 재생은 중단하지 않는다(아래 항목과 동일).
- **미니플레이어에 뜬 콘텐츠가 파트너 회수된 경우**: 미니플레이어를 내리고, 탭했다면 "제공이 종료된 콘텐츠예요"를 안내한다.
- **앱 실행 시 이어들을 콘텐츠는 있는데 재생 위치가 0인 경우**: 처음부터 듣는 것과 같으므로 미니플레이어를 띄우지 않는다.
- **미니플레이어에서 재생 시도 → 한도 소진**: 라이브러리 카드 탭과 동일하게 페이월을 띄운다. 미니플레이어는 그대로 둔다.
- **재생 확인 팝업을 띄운 사이에 한도가 소진된 경우**(다른 기기에서 재생): [재생하기]를 누르는 시점에 서버가 다시 판정해 페이월로 전환한다. **팝업에 표시된 남은 횟수를 신뢰해 재생을 통과시키지 않는다.**
- **앱바의 잔여 표시와 실제 한도가 어긋난 경우**(다른 기기에서 재생): 표시는 마지막 조회 시점의 값이다. 탭 시점에 서버가 다시 판정하므로 **표시된 숫자를 근거로 재생을 통과시키지 않는다.** 재판정이 소진이면 페이월로 간다.
- **앱을 켜 둔 채 04:00을 넘긴 경우**: 클라이언트가 기기 시각을 보고 숫자를 되돌리지 않는다. 다음 재조회(포그라운드 복귀·당겨서 새로고침) 때 서버 값으로 갱신된다. 기기 시각을 신뢰하면 시각 조작만으로 한도가 초기화된 것처럼 보인다.
- **네트워크 오류로 캐시된 목록을 보여주는 경우**: **잔여 표시를 노출하지 않는다.** 캐시된 숫자는 이미 낡았을 수 있고, 틀린 숫자를 확신 있게 보여주면 팝업·페이월과 어긋난다.
- **응답에 `daily_play_count`가 없는 경우**: 표시를 생략한다. **0으로 가정하지 않는다** — 아직 남아 있는 사용자에게 소진 표시를 띄우는 쪽이 훨씬 나쁘다.
- **결제로 무제한 티어가 된 직후**: 시트가 닫히는 즉시 잔여 표시를 제거한다(`paywall.md` 4.5). 방금 결제한 화면에 남은 횟수가 그대로 있으면 결제가 반영되지 않은 것으로 읽힌다.
- **[오늘은 그만 보기]로 억제한 뒤 한도를 소진**: 페이월은 그대로 노출된다. 억제한 것은 **고지이지 판정이 아니다.**
- **억제 중 04:00을 넘김**: 억제는 서비스 날짜 단위이므로 자동으로 풀린다. 다음 차감 재생에서 확인 팝업이 다시 뜬다.
- **억제 상태에서 앱을 재설치하거나 다른 기기로 로그인**: 억제는 기기 로컬 값이라 사라지고 팝업이 다시 뜬다. **의도된 동작이다**(4.3).
- **출처 필터를 [이어 PICK]으로 건 상태에서 아이템을 삭제**: 통합 목록에서도 함께 사라진다. 필터는 같은 데이터의 다른 보기일 뿐 별도 보관함이 아니다.
- **필터를 적용한 채 앱을 종료**: 다음 실행 시 탭·출처·주제를 모두 **초기화한다.** 필터가 걸린 줄 모르고 "콘텐츠가 안 온다"고 오해하는 것을 막는다.

## 미결 사항

**확정된 것**

| 항목 | 결정 |
