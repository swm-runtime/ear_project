# 공통 오류 처리 · 재시도 기능 명세서

> 연결 PRD: FR-36, FR-35 / 비기능(안정성) / 제약 8.1

## 1. 목적 & 연결

네트워크 오류·서버 오류·인증 만료를 화면마다 제각각 처리하지 않고 하나의 규칙으로 통일한다. 3인 팀이 2주 안에 MVP를 만들어야 하는 제약(PRD 8.1)에서, 각 화면이 오류 UX를 따로 설계하지 않게 하는 것이 이 명세의 목적이다.

- PRD FR-36 (P0) 네트워크 오류 등 공통 오류 처리와 재시도
- PRD FR-35 (P0) 최소 지원 버전 미달 시 강제 업데이트 (→ `splash.md`)
- PRD 7 비기능 — 안정성

**이 문서는 화면이 아니라 횡단 규칙이다.** 각 기능 명세의 "네트워크 오류" 상태는 모두 여기를 따른다.

## 2. 진입 조건

모든 서버 통신·미디어 로드에 적용된다. 화면 단위 진입 조건은 없다.

## 3. 입력값

| 값 | 설명 |
|---|---|
| http_status | 200 / 4xx / 5xx |
| error_code | 서버 정의 에러 코드(문자열). 값의 전체 목록은 **9장** |
| error_message | 서버가 내려준 사용자 노출용 문구(선택) |
| network_reachable | OS 네트워크 상태 |
| request_context | foreground_blocking / background_silent |

## 4. 처리 로직

### 4.1 오류 분류와 대응

| 분류 | 조건 | 대응 |
|---|---|---|
| **네트워크 없음** | OS가 미연결 보고, 또는 DNS·연결 실패 | 오프라인 UI. 캐시가 있으면 캐시 + 오프라인 배너, 없으면 전체 에러 화면. **예외: 탐색 피드는 현재 캐시를 쓰지 않는다**(합의 2026-08-06, `explore.md` — 에러 화면 + [다시 시도]. 추후 캐시 피드 도입 가능성은 열어둔다) |
| **타임아웃** | 응답 없음(기본 10초, 미디어 20초) | 재시도 가능 에러로 처리 |
| **인증 만료 (401)** | access_token 만료 | 토큰 갱신 후 **원 요청 자동 1회 재시도**. 갱신 실패 시 로그아웃 → 시작 화면 |
| **권한 없음 (403)** | 티어 부족·콘텐츠 회수 | 자동 재시도 없음. 상황별 안내(페이월 / "제공이 종료된 콘텐츠예요") |
| **없음 (404)** | 콘텐츠·리소스 삭제 | 목록에서 제거 + "찾을 수 없어요" |
| **상태 충돌 (409)** | 요청 형식은 맞지만 현재 상태가 전이 조건을 만족하지 않음 | 자동 재시도 없음. **같은 요청을 다시 보내도 결과가 같다.** 사용자가 시작하지 않은 전이는 조용히 무시하고(4.3), 사용자가 시작한 전이는 상태를 다시 읽어 화면을 맞춘다 |
| **요청 과다 (429)** | 레이트 리밋 | `Retry-After` 만큼 대기 후 자동 재시도(최대 2회) |
| **서버 오류 (5xx)** | 서버 장애 | 지수 백오프 자동 재시도 후 실패 시 에러 UI |
| **점검 중 (503 + maintenance)** | 계획 점검 | 점검 안내 전체 화면. 재시도 버튼만 제공 |
| **버전 미달** | 서버가 강제 업데이트 코드 반환 | 강제 업데이트 화면(`splash.md`) |
| **클라이언트 오류 (400)** | 잘못된 요청 | 사용자에게 재시도를 권하지 않는다. "일시적인 오류" 안내 + 로그 수집 |

### 4.2 자동 재시도 정책

**자동 재시도 대상**: 타임아웃, 5xx, 429, 네트워크 일시 단절

```
재시도 횟수: 최대 2회 (총 3회 시도)
백오프: 1초 → 3초 (지터 ±20%)
```

**자동 재시도 금지 대상** — 중복 실행 부작용이 있는 요청:
- 결제·영수증 검증 — **즉시 자동 재시도는 하지 않는다**(중복 결제 방지). **오프라인 큐·백그라운드 재검증 경로의 재시도는 허용**한다(멱등키 보호 — 4.5의 영수증 무기한 재시도와 모순이 아니다)
- 담기/삭제 등 상태 변경 요청 → **멱등키 또는 서버 유니크 제약으로 멱등이 보장되는 요청만** 재시도 허용(탐색 담기는 `library_items (user_id, content_id)` 유니크로 보장 — `explore.md` 7장)
- 회원 탈퇴

GET 요청은 기본 자동 재시도 대상, POST/PUT/DELETE는 멱등키 또는 서버 유니크 제약으로 멱등이 보장될 때만.

### 4.3 UI 표현 규칙

| 요청 성격 | 실패 시 표현 |
|---|---|
| **화면 진입 조회**(차단형) | 전체 화면 에러 + [다시 시도] |
| **추가 로딩**(무한 스크롤) | 리스트 하단 인라인 에러 + [다시 시도]. 기존 목록 유지 |
| **사용자 액션**(담기·저장·토글) | 토스트 또는 인라인 에러. 화면은 유지 |
| **백그라운드 동기화**(재생 위치, 신호 전송) | **사용자에게 알리지 않는다.** 큐에 적재해 다음 기회에 재전송 |
| **결제** | 시트 내 인라인 에러 + [다시 시도]. 절대 조용히 실패시키지 않는다 |

원칙: **사용자가 시작하지 않은 실패는 알리지 않는다.**

### 4.4 낙관적 UI와 롤백

- 토글·담기·삭제는 낙관적으로 즉시 반영한다
- 실패 시 원상 복구 + 토스트
- 삭제는 [실행 취소] 스낵바를 제공하므로, 스낵바가 사라진 뒤에 서버 요청을 보낸다(불필요한 요청 방지)

### 4.5 오프라인 큐

온라인 복귀 시 재전송해야 하는 요청을 로컬 큐에 적재한다.

| 대상 | 재전송 규칙 |
|---|---|
| 재생 위치 | 같은 콘텐츠는 최신 1건만 유지(덮어쓰기) |
| 소비 신호(play/complete/skip) | 전부 보존, 순서대로 전송 |
| 담기·삭제 | 마지막 상태만 유지 |
| 설정 토글(`settings.md` 7장) | 마지막 상태만 유지 |
| 영수증 검증 | 성공할 때까지 무기한 재시도 — **즉시 자동 재시도는 하지 않되**(4.2, 중복 결제 방지) **오프라인 큐·백그라운드 재검증 경로의 재시도는 허용**(멱등키 보호) |

- **단일 값 토글은 큐 적재 대상이고, 폼 제출(관심사·커리어 저장)은 큐에 넣지 않는다** — 즉시 실패 + [다시 시도]로 처리하고 편집 상태를 유지한다(`interest-management.md` 7장, `career.md` 7장)
- 큐는 앱 재실행 후에도 보존된다(로컬 DB)
- 큐 항목에는 발생 시각을 함께 기록해 서버가 순서를 판정할 수 있게 한다

### 4.6 에러 문구 원칙

- 기술 용어·에러 코드를 사용자에게 노출하지 않는다. 단 문의 대응을 위해 화면 구석에 코드를 작게 표기할 수 있다
- 서버가 `error_message`를 내려준 경우 그것을 우선 사용한다(운영 중 문구 조정 가능)
- 기본 문구
  - 네트워크: "인터넷 연결을 확인해주세요"
  - 서버: "일시적인 오류가 발생했어요. 잠시 후 다시 시도해주세요"
  - 알 수 없음: "문제가 발생했어요"

### 4.7 로깅·모니터링

- 4xx/5xx, 타임아웃, 재시도 소진을 수집한다(요청 경로·에러 코드·재시도 횟수)
- 개인정보·토큰·영수증 본문은 로그에 남기지 않는다
- 재생 실패율·결제 검증 실패율은 별도 지표로 관측한다

공통 컴포넌트로 제공한다.

| 컴포넌트 | 구성 |

| 로딩 | 스켈레톤(목록) / 스피너(액션). 0.3초 미만이면 표시하지 않아 깜빡임 방지 |

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

이 문서가 다루는 것은 **서버 응답 규격과 클라이언트 로컬 큐**이며, DB 테이블이 아니다(domain.md 13.1·13.2).

> **`error_code`에 들어갈 값의 목록은 이 장이 아니라 9장이다.** 여기는 필드 규격만 정한다.

```
ApiError      { error_code, message, retryable, retry_after_sec }   // 서버 응답 규격
PendingRequest{ request_id(멱등키), type, payload, created_at, retry_count, last_attempt_at }  // 로컬 큐
NetworkState  { reachable, connection_type }                        // 클라이언트 전역
```

## 7. 예외 상황

- **재시도 중 사용자가 화면을 이탈**: 진행 중 요청을 취소한다. 단 백그라운드 큐 항목은 취소하지 않는다.
- **401 갱신 재시도가 다시 401**: 무한 루프를 막기 위해 갱신 재시도는 요청당 1회로 제한하고, 실패 시 즉시 로그아웃한다.
- **여러 요청이 동시에 401**: 토큰 갱신은 단일 인플라이트로 묶고 나머지는 결과를 공유한다.
- **오프라인 큐가 과도하게 쌓임**: 상한(예: 1,000건)을 두고 초과 시 오래된 소비 신호부터 폐기한다. 결제·영수증은 절대 폐기하지 않는다.
- **서버 시각과 클라이언트 시각 불일치**: 만료 판정은 항상 서버 응답 기준.
- **재시도로 중복 생성**(담기 등): 멱등키로 서버에서 중복을 흡수한다.
- **네트워크는 연결됐지만 캡티브 포털**(카페 Wi-Fi 로그인 필요): OS는 연결됨으로 보고하지만 요청이 실패한다. 네트워크 상태만 믿지 말고 실제 응답으로 판정한다.
- **점검 중 응답을 캐시**: 점검 응답은 절대 캐시하지 않는다.
- **에러 화면에서 [다시 시도] 연타**: 인플라이트 요청이 있으면 무시한다.

## 8. 완료 조건

- Given 네트워크가 끊긴 상태 / When 라이브러리를 연다 / Then 캐시된 목록과 오프라인 배너가 노출되고 앱이 크래시하지 않는다
- Given 서버가 500을 반환한다 / When 화면 진입 조회가 실패한다 / Then 최대 2회 자동 재시도 후 전체 화면 에러와 [다시 시도]가 노출된다
- Given access_token이 만료되었다 / When API를 호출한다 / Then 토큰이 자동 갱신되고 원래 요청이 성공하며 사용자는 아무것도 인지하지 못한다
- Given refresh_token까지 만료되었다 / When API를 호출한다 / Then 자동 로그아웃되어 시작 화면으로 이동한다
- Given 오프라인 상태에서 콘텐츠를 5분 지점까지 들었다 / When 온라인으로 복귀한다 / Then 재생 위치가 서버에 동기화된다
- Given 오프라인 상태에서 담기를 눌렀다 / When 온라인으로 복귀한다 / Then 담기가 서버에 반영되고 중복 생성되지 않는다
- Given 서버가 `CONTENT_WITHDRAWN`을 반환한다 / When 재생을 시도한다 / Then 제공 종료 안내가 노출되고 목록에서 해당 항목이 제거된다
- Given 백그라운드 소비 신호 전송이 실패한다 / When 사용자가 앱을 사용 중이다 / Then 어떤 에러 UI도 노출되지 않는다
- Given 로딩이 0.2초 만에 끝난다 / When 화면을 본다 / Then 로딩 인디케이터가 깜빡이지 않는다
- Given 결제 영수증 검증이 실패한다 / When 재시도가 수행된다 / Then 성공할 때까지 큐에 남아 있고 폐기되지 않는다

## 9. 에러 코드 표

> **이 표가 원본이고 `spec/api/*-api.md` 5장은 해당 화면분의 발췌다.** 두 곳이 어긋나면 이 표가 기준이다.
> 코드를 추가·변경하면 **enum(`architecture.md` 7.5) → 이 표 → 해당 api 문서 5장** 순서로 갱신한다. 이미 배포된 코드의 의미는 바꾸지 않고 새 코드를 추가한다.
>
> 6장(데이터 모델)이 정하는 것은 `ApiError`의 **필드 규격**이고, 이 장이 정하는 것은 그 `error_code` 필드에 들어갈 **값의 목록과 클라이언트 동작**이다. 둘은 다른 것이라 절을 나눈다.

**클라이언트가 분기해야 하는 상황은 상태 코드가 아니라 `error_code`로 구분한다.** 예를 들어 403 하나에 페이월·한도 안내·콘텐츠 회수가 겹치는데, 세 상황의 화면이 전부 다르다.

### 9.1 공통 — 기반 코드

도메인과 무관하며 모든 엔드포인트에서 나올 수 있다. HTTP 상태와 1:1로 대응하므로 별도 분기 없이 4.1의 분류대로 처리한다.

| error_code | HTTP | retryable | 클라이언트 동작 |
|---|---|---|---|
| `VALIDATION_FAILED` | 400 | false | 재시도를 권하지 않는다. 인라인 오류 또는 일반 오류 안내 + 로그 수집(4.1) |
| `UNAUTHORIZED` | 401 | false | 토큰 갱신 후 원 요청 1회 재시도. 갱신 실패 시 로그아웃 → 시작 화면(4.1) |
| `FORBIDDEN` | 403 | false | 상황별 안내. **화면이 갈리는 403은 아래 도메인 코드로 내려온다** |
| `NOT_FOUND` | 404 | false | 목록에서 제거 + "찾을 수 없어요" |
| `CONFLICT` | 409 | false | 상태를 다시 읽어 화면을 맞춘다(4.1) |
| `TOO_MANY_REQUESTS` | 429 | **true** | `Retry-After`만큼 대기 후 자동 재시도(최대 2회) |
| `INTERNAL_ERROR` | 500 | **true** | 4.2 규칙대로 자동 재시도 → 소진 시 전체 화면 에러 + [다시 시도]. **서버는 내부 사유를 노출하지 않고 항상 이 코드로 고정한다** |
| `EXTERNAL_SERVICE_ERROR` | 502 | **true** | 외부 연동 실패(AI 서버·스토어·스토리지). 4.2 규칙대로 자동 재시도 |

### 9.2 공통 — 콘텐츠

**특정 화면에 속하지 않는다.** 라이브러리·탐색·온보딩·플레이어가 같은 코드를 쓰므로 여기 한 번만 등재한다.

| error_code | HTTP | retryable | 클라이언트 동작 |
|---|---|---|---|
| `CONTENT_NOT_FOUND` | 404 · **담기에서는 `—`** | false | 해당 카드를 목록에서 제거 |
| `CONTENT_WITHDRAWN` | 403 · **담기에서는 `—`** | false | "제공이 종료된 콘텐츠예요" + 목록에서 제거, 미니플레이어면 내린다 |

- **HTTP 열이 두 값인 것은 오타가 아니다.** 재생·조회에서는 응답 상태로 오지만, 여러 건을 한 번에 담는 요청(`POST /onboarding/picks`)에서는 **요청 전체가 실패한 것이 아니므로** 200 응답 본문의 `failed[]` 항목으로 전달된다.

| error_code | HTTP | retryable | 클라이언트 동작 |
|---|---|---|---|
| `LIBRARY_CURSOR_INVALID` | 400 | false | 커서를 버리고 첫 페이지부터 재조회. **사용자에게 노출하지 않는다** |
| `LIBRARY_ITEM_NOT_FOUND` | 404 | false | 목록에서 해당 항목 제거 |
| `LIBRARY_COMPLETION_NOT_REACHED` | 409 | false | **조용히 무시.** 상태를 바꾸지 않는다 |
| `PLAY_LIMIT_EXCEEDED` | 403 | false | **페이월 바텀시트**(`paywall.md` 4.5) |
| `PLAY_LIMIT_REACHED` | 403 | false | "오늘 청취 한도를 모두 사용했어요" 안내. **페이월 아님** |

- **`PLAY_LIMIT_EXCEEDED`와 `PLAY_LIMIT_REACHED`를 합치지 않는다.** 한도 티어는 결제 유도, 최상위 티어는 안내다 — 더 팔 것이 없는 사용자에게 페이월을 띄우지 않는다.
- **`LIBRARY_ITEM_NOT_FOUND`는 남의 항목에도 나간다.** 403을 주면 "그 항목이 존재한다"를 알려주게 되어, id를 넣어보는 것만으로 남의 라이브러리 구성을 탐지할 수 있다(`library-api.md` 7장).

### 9.8 이 표를 읽는 규칙

- **`retryable: true`는 5xx·429·외부 연동 실패뿐이다.** 나머지는 전부 형식·상태·권한 문제라 같은 요청을 다시 보내도 결과가 같다. 자동 재시도 대상은 4.2가 정한다.
- **설정(`settings-api.md`)은 고유 코드가 없다.** `VALIDATION_FAILED`만 쓰며 9.1을 따른다.
- **api 문서가 아직 없는 화면**(플레이어·구독·알림 등)의 코드는 그 문서를 작성할 때 여기에 함께 등재한다.
- **`EXPLORE_CURSOR_INVALID` · `STATS_WEEK_OUT_OF_RANGE`는 계약만 있고 서버 enum에는 아직 없다.** 탐색·프로필이 구현되지 않았기 때문이며, 구현 시 enum에 추가한다. 나머지 40개는 `error-code.enum.ts`와 1:1로 일치한다.
