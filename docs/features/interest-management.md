# 관심사 관리 기능 명세서

> 연결 PRD: FR-05, FR-06, FR-18 / 사용자흐름 5.5 / 검증계획 9.1·9.2
> **커리어 정보는 별도 화면·별도 문서다**(합의 2026-08-06 — `career.md`). 이 문서는 관심 주제 편집만 소유한다.

## 1. 목적 & 연결

온보딩에서 받은 관심 주제를 사용자가 언제든 바꿀 수 있게 한다. 변경은 드립 편성과 추천에 즉시 반영되며, **주제 해제는 이미 받은 미청취 콘텐츠를 지우지 않는다**는 점이 이 기능의 핵심 규칙이다.

- PRD FR-05 (P0) 관심 주제 일괄 편집, 변경 즉시 반영 — 추가=드립 편성 대상, 해제=신규 적립 중단(기존 미청취분 유지)
- PRD FR-06 (P1) 주제 자동 확장 허용 여부 설정
- PRD FR-18 (P1) 자동 확장 — 토글이 여기서 제어됨
- PRD 사용자흐름 5.5
- 커리어 정보 수정(FR-04)은 `career.md`

## 2. 진입 조건

- 프로필 > [관심 주제 관리] 카드 (`profile.md` 4.4)
- 설정 > 콘텐츠 > 관심 주제 관리 (`settings.md` 4.1)
- 라이브러리의 드립 안내 배너에서 **[관심 주제 추가하기]** 탭(합의 2026-08-06 — PRD 5.5의 프로필·설정 경로에 **더해** 추가된 진입점. `library.md` 5장)

## 3. 입력값

| 값 | 설명 | 필수 |
|---|---|---|
| selected_topic_ids | 편집 후 최종 주제 목록 | **필수, 최소 1개 · 최대 3개** |
| auto_expand_enabled | 자동 확장 허용 (FR-06) | 선택(기본 true) |

- 편집은 **일괄(batch)** 방식이다. 화면에서 여러 개를 켜고 끈 뒤 [저장]을 눌러야 반영된다.
- 자동 확장 토글만 예외적으로 즉시 저장한다(단일 값이라 일괄 편집 대상이 아님).
- **주제는 최소 1개, 최대 3개다.** 온보딩(`onboarding.md` 3장)과 **같은 상한을 쓴다** — 온보딩에서 3개로 막아놓고 여기서 더 고를 수 있으면 상한을 둔 이유(드립 편성 분산 방지)가 사라진다.
- **상한은 서버도 검증한다.** 클라이언트가 보낸 목록이 3개를 넘으면 저장 자체를 거부한다.

## 4. 처리 로직

### 4.1 화면 구성

```
[관심 주제]  — 전체 중분류 목록, 선택된 것 강조. "N/3 선택" 표시
[자동 확장]   — 토글 + 설명 "관심 주제와 가까운 주제도 자동으로 찾아드려요" (P1)
[저장]        — 변경 사항이 있을 때만 활성
```

- 주제 목록은 온보딩과 동일하게 `is_visible = true`인 주제만 노출한다(FR-03). **이 값은 관리자가 관리자 페이지에서 직접 제어하며 시스템이 자동으로 바꾸지 않는다**(FR-38)
- 선택 개수는 항상 **`N/3`** 형태로 보여준다. 3개를 채우면 미선택 칩을 비활성 처리하고, 4번째를 탭하면 **"관심 주제는 3개까지 선택할 수 있어요"** 토스트로 이유를 알린다(온보딩과 같은 문구)
  - 주제를 바꾸려면 기존 선택을 해제하면 된다. **비활성 상태에서 아무 반응이 없으면 오류로 읽힌다**
- 자동 확장(FR-18)으로 추가된 주제는 목록에서 "자동 추가됨" 배지로 구분한다. 사용자가 해제할 수 있고, 해제하면 자동 확장이 같은 주제를 다시 추가하지 않는다

### 4.2 저장 시 분기 — 변경 확인 팝업

저장을 누른 시점에 변경 내용을 판정한다.

- **추가만 있음** → 확인 팝업 없이 바로 저장
- **해제가 포함됨** → **변경 확인 팝업**을 노출한다(PRD 5.5)
  - 문구: "‘OO’ 주제를 해제하면 이 주제의 새 콘텐츠가 더 이상 도착하지 않아요. 이미 받은 콘텐츠는 그대로 남아 있어요."
  - [취소] / [변경하기]
- **마지막 1개까지 해제 시도** → 저장 자체를 막는다. "관심 주제는 1개 이상 선택해야 해요"
- **3개를 넘겨 선택 시도** → 애초에 4번째 선택이 되지 않으므로 저장 단계까지 오지 않는다. 서버는 방어적으로 한 번 더 검증한다(3장)

### 4.3 변경 반영 규칙 (FR-05 — 가장 중요한 로직)

| 변경 | 반영 |
|---|---|
| 주제 **추가** | 즉시 드립 편성 대상에 포함. 다음 편성 주기부터 해당 주제 콘텐츠가 적립됨 |
| 주제 **해제** | 해당 주제의 **신규 적립만 중단**. 이미 라이브러리에 있는 콘텐츠는 **청취 여부와 무관하게 유지**(미청취분 포함) |
| 자동 확장 OFF | 자동 확장 배치가 이 사용자를 대상에서 제외. 이미 자동 추가된 주제는 유지(사용자가 직접 해제해야 사라짐) |
| 자동 확장 ON | 다음 배치부터 대상 포함 |

- 저장 성공 시 서버는 **추천 캐시를 무효화**하고, 다음 드립 편성 시점부터 새 관심사를 사용한다
- 이미 편성이 확정되어 오늘 적립될 예정인 콘텐츠는 되돌리지 않는다(중복 처리·혼란 방지)

**상한 3개와 자동 확장의 관계** (P1)

- **자동 추가된 주제도 3개 상한에 포함해서 센다.** `source`가 `manual`이든 `auto`든 구분하지 않는다.
  - 이유: 상한의 목적은 드립 편성이 흩어지는 것을 막는 데 있다. 편성은 주제가 어떻게 추가됐는지 모르므로, 출처별로 상한을 따로 두면 목적을 달성하지 못한다.
- 결과적으로 **자동 확장은 주제가 3개 미만인 사용자에게만 동작한다.** 1~2개만 고른 사용자의 편성 폭을 넓혀주는 기능으로 남고, 이미 3개를 채운 사용자에게는 아무 일도 하지 않는다.
- 자동 확장이 주제를 채운 뒤 사용자가 직접 다른 주제를 고르려면 **기존 주제를 해제해야 한다.** 이때 자동 추가분을 해제하면 `is_user_removed = true`가 서므로 같은 주제가 다시 들어오지 않는다(4.4).
- **MVP에서는 이 규칙이 작동할 일이 없다.** 자동 확장(FR-18)이 P1이라 배치가 돌지 않기 때문이다. P1 도입 시점에 재확인이 필요하다 → 미결 사항.

### 4.4 저장 처리

1. [저장] 탭 → (해제 포함 시) 확인 팝업 → [변경하기]
2. 서버에 최종 주제 목록 전체를 전송한다(델타가 아니라 전체 목록 — 멱등)
3. 서버는 diff를 계산해 `UserInterest`를 갱신
   - 추가된 주제: `is_active = true`, `source = manual`
   - 해제된 주제: `is_active = false`, `is_user_removed = true` (레코드 삭제하지 않음 — 재선택 이력 추적, 자동 확장 재추가 금지)
4. 추천·편성 캐시 무효화
5. 성공 토스트 "관심사가 변경되었어요" → 이전 화면으로 복귀

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 로딩 | 주제 칩 스켈레톤 |
| 정상 | 주제 그리드(선택 강조) + **"N/3 선택"** + 자동 확장 토글 + 하단 고정 [저장] |
| 변경 없음 | [저장] 비활성 |
| 변경 있음 | [저장] 활성 + 상단에 "변경 사항 N개" 표시 |
| 3개 선택 완료 | **"3/3 선택"** + 미선택 칩 비활성 처리 |
| 4번째 선택 시도 | 선택되지 않음 + 토스트 "관심 주제는 3개까지 선택할 수 있어요" |
| 상한 초과 상태(기존 사용자) | 초과 개수 그대로 표시 + 안내 "관심 주제는 3개까지예요. N개를 해제하면 다시 추가할 수 있어요". 추가만 막고 해제·저장은 허용 |
| 마지막 1개 해제 시도 | 해당 칩 해제 불가 + 토스트 "관심 주제는 1개 이상 선택해야 해요" |
| 해제 포함 저장 | 확인 팝업 |
| 저장 중 | [저장] 로딩, 화면 조작 차단 |
| 저장 성공 | 토스트 후 이전 화면 복귀 |
| 저장 실패 | 인라인 에러 + [다시 시도]. 편집 상태는 유지 |
| 뒤로가기(변경 있음) | "변경 사항을 저장하지 않고 나갈까요?" 팝업 |
| 주제 목록 조회 실패 | 에러 상태 + [다시 시도] |
| 자동 확장 토글(P1 미구현) | 섹션 자체를 노출하지 않음 |

## 7. 예외 상황

- **주제를 해제했다가 같은 저장 안에서 다시 선택**: 변경 없음으로 취급, 확인 팝업도 뜨지 않는다.
- **3개를 채운 상태에서 다른 주제로 바꾸고 싶은 경우**: 기존 선택을 해제하면 곧바로 다른 주제를 고를 수 있다. 한 번의 저장 안에서 해제와 추가가 함께 일어나므로, 해제가 포함되었으니 **변경 확인 팝업은 뜬다**(4.2).
- **이미 3개를 넘게 보유한 사용자**(상한 도입 이전 가입자, 자동 확장으로 늘어난 경우): **강제로 줄이게 하지 않는다.** 현재 목록을 그대로 노출하고 **추가만 막는다.** 해제는 자유롭게 할 수 있고, 3개 이하로 내려간 뒤부터 상한이 정상 적용된다.
  - 이유: 이미 쓰고 있던 사용자에게 "N개를 지워야 저장할 수 있습니다"를 강요하면, 관심사와 무관한 이유로 라이브러리 편성이 바뀌는 것을 감수하게 된다. 상한은 앞으로의 선택을 제한하는 규칙이지 기존 상태를 되돌리는 규칙이 아니다.
  - 서버의 상한 검증도 **"기존 개수보다 늘어나지 않으면 통과"** 로 둔다. 초과 상태 그대로의 재저장(해제 없이 다른 변경만 저장)도 허용한다.
- **해제한 주제를 나중에 다시 추가**: `is_active = true`, `user_removed = false`로 복원. 과거 삭제한 라이브러리 콘텐츠는 복구되지 않는다.
- **해제한 주제의 콘텐츠가 이미 오늘 드립으로 편성 확정된 상태**: 그대로 적립된다. 사용자에게는 자연스러운 지연으로 보이므로 별도 안내하지 않는다.
- **저장 도중 앱 종료**: 서버 트랜잭션 단위로 전부 반영 또는 전부 미반영. 부분 반영이 없어야 한다.
- **오프라인 상태에서 저장 시도**: 저장 실패 처리와 동일 — 인라인 에러 + [다시 시도], 편집 상태 유지(`career.md` 7장과 동일. 폼 제출은 오프라인 큐 대상이 아니다 — `common-error-handling.md` 4.5).
- **여러 기기에서 동시에 관심사 편집**: 마지막 저장이 최종(전체 목록 전송 방식이라 자동으로 last-write-wins).
- **관리자가 주제를 숨긴 경우**(`is_visible = false`): 목록에서 사라지지만 `user_interests` 레코드는 유지한다. 관리자가 다시 노출로 바꾸면 그대로 되살아난다. **자동 복구는 없다** — 노출 판단은 전적으로 관리자 몫이다.
- **자동 확장으로 추가된 주제를 사용자가 해제**: `user_removed = true`를 세워 자동 확장 배치가 같은 주제를 다시 넣지 않게 한다.
- **관심 주제 해제로 라이브러리가 사실상 갱신되지 않는 상태**: 라이브러리에 "콘텐츠를 준비하고 있어요" 배너 + [관심 주제 추가하기]가 노출된다(`library.md` 5장 — 문구·진입점 통일, 합의 2026-08-06).

## 8. 완료 조건

- Given 관심 주제 3개를 선택한 사용자 / When 1개를 추가하고 저장한다 / Then 확인 팝업 없이 저장되고 다음 드립부터 추가 주제 콘텐츠가 적립된다
- Given 관심 주제 3개 중 1개를 해제한다 / When [저장]을 누른다 / Then 변경 확인 팝업이 노출된다
- Given 해제 확인 팝업에서 [변경하기]를 누른다 / When 저장이 완료된다 / Then 해당 주제의 신규 적립이 중단되고, **이미 라이브러리에 있던 미청취 콘텐츠는 그대로 남아 있다**
- Given 관심 주제가 1개뿐인 사용자 / When 그 주제를 해제하려 한다 / Then 해제되지 않고 최소 1개 안내가 노출된다
- Given 관심 주제 3개를 선택한 사용자 / When 4번째 주제를 탭한다 / Then 선택되지 않고 **"3개까지 선택할 수 있어요"** 토스트가 노출된다
- Given 관심 주제 3개를 선택한 사용자 / When 1개를 해제하고 다른 주제를 고른다 / Then 정상적으로 선택되고, 해제가 포함되었으므로 저장 시 변경 확인 팝업이 노출된다
- Given 클라이언트를 우회해 주제 4개를 서버로 보낸다 / When 저장을 요청한다 / Then 서버가 상한을 검증해 거부한다
- Given 이미 주제를 5개 보유한 기존 사용자 / When 화면에 진입한다 / Then 5개가 그대로 노출되고 추가만 막히며, 해제와 저장은 정상 동작한다
- Given 자동 확장 토글을 끈다 / When 다음 자동 확장 배치가 실행된다 / Then 해당 사용자에게 새 주제가 추가되지 않는다
- Given 자동으로 추가된 주제를 사용자가 해제했다 / When 이후 자동 확장 배치가 실행된다 / Then 같은 주제가 다시 추가되지 않는다
- Given 변경 사항이 있는 상태 / When 뒤로가기를 누른다 / Then 저장하지 않고 나갈지 확인하는 팝업이 노출된다
- Given 주제를 해제해 저장한 뒤 다시 추가한다 / When 저장한다 / Then 해당 주제의 편성이 재개된다

## 미결 사항

**확정된 것**

| 항목 | 결정 |
|---|---|
| 주제 선택 개수 상한 | **최소 1개 · 최대 3개.** 온보딩(`onboarding.md` 3장)과 같은 값을 쓰고, 서버도 검증한다 |
