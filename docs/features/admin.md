# 관리자 페이지 기능 명세서

> 연결 PRD: FR-37, FR-38 / 범위 4.1(운영) / 사용자흐름 5.6 / 검증계획 9.1

## 1. 목적 & 연결

MVP는 자동 콘텐츠 파이프라인을 운영하지 않는다(PRD 4.2). 대본 생성·QA 대조·TTS 변환은 팀이 앱 밖에서 수행하고, **완성된 오디오를 사람이 업로드하는 것이 유일한 발행 경로**다. 이 화면이 그 경로이며, 동시에 주제(카탈로그 분류) 운영 창구다.

- PRD FR-37 (P0) 관리자 계정으로 콘텐츠 업로드. **업로드 시점에 즉시 발행 상태**가 되며 이전 단계 상태는 관리하지 않는다
- PRD FR-38 (P0) 주제 추가·삭제·노출 제어
- PRD 4.1 운영(관리자) 범위
- 제작 기준(분할·환각 금지·출처 고지)은 [`content-pipeline.md`](content-pipeline.md) 4.2~4.5를 따른다 — 사람이 수행해도 지켜야 하는 규칙이다

**이 문서는 일반 사용자에게 노출되지 않는 운영 화면을 다룬다.**

## 2. 진입 조건

- `users.role == 'admin'` 계정으로 로그인한 상태
- 앱 내 진입점: 설정 하단에 **관리자 계정에만** [관리자] 항목이 노출된다
- 일반 계정은 진입점이 보이지 않을 뿐 아니라, 서버가 모든 관리자 API를 403으로 거부한다(UI 은닉에 의존하지 않는다)

**관리자 계정은 별도 인증 체계를 두지 않는다.** 일반 사용자와 동일한 소셜 로그인(카카오·네이버·구글)을 쓰고 `role`로만 구분한다 — `auth.md` 4.1이 "자체 아이디/비밀번호는 만들지 않는다"고 규정하므로 관리자만 예외를 두면 인증 경로가 두 벌이 된다.

## 3. 입력값

### 3.1 콘텐츠 업로드

| 값 | 설명 | 필수 |
|---|---|---|
| audio_file | 오디오 파일(mp3/m4a) | 필수 |
| title | 제목 | 필수 |
| description | 설명 | 필수 |
| topic_ids[] | 주제 (복수 선택) | **필수, 최소 1개** |
| author_name | 원저자 | **파트너 콘텐츠 필수** (FR-12) / `origin == ai_generated`는 **선택** |
| source_name | `origin == partner`: **파트너명** / `origin == ai_generated`: **"참고한 자료" 소스 표기(복수 가능)** | 필수 |
| source_url | 원문 링크 | **파트너 콘텐츠 필수** (FR-12) / `origin == ai_generated`는 **선택** |
| origin | partner / ai_generated | 필수 |
| partner_id | `origin == partner`일 때 | 조건부 필수 |
| license_expires_at | 라이선스 만료일 | 선택 (파트너 콘텐츠는 필수) |
| thumbnail | 썸네일 이미지 | 필수 |
| series_id | 시리즈 묶음 (기존 선택 또는 신규 생성) | 선택 |
| episode_no / total_episodes | 시리즈 내 순서 | `series_id` 있으면 필수 |
| script_segments | 스크립트 `[{start_sec, end_sec, text}]` | 선택 (FR-25, P1) |
| 검수 완료 확인(체크) | 수동 검수 체크리스트(4.2-1) 이행 확인 | **필수** (합의 2026-08-06 — 미체크 시 업로드 거부. **저장 컬럼은 두지 않는다**: 발행된 모든 행에서 항상 참이 되는 값이라 정보를 더하지 않으며, 이행 증적은 `audit_logs` 업로드 기록이 담당 — `domain.md` 5.1 확정 2026-08-06) |

- `duration_sec`은 업로드된 오디오에서 **서버가 추출**한다. 수동 입력받지 않는다(불일치 시 완청 판정이 깨진다).
- **출처 필드는 `origin`으로 분기한다**(합의 2026-08-06 — `domain.md` 5.1 반영 완료: NULL 허용 + `chk_contents_partner_disclosure` CHECK로 파트너 필수 고지를 DB에서 이중 방어). 파트너 콘텐츠는 기존대로 author_name·source_name·source_url 전부 필수이고, `ai_generated`는 source_name에 "참고한 자료" 소스 표기(복수 가능)만 필수, source_url·author_name은 선택이다 — 근거 소스가 단일 원문·단일 저자가 아니기 때문이다(`content-pipeline.md` 4.3의 AI 생성 고지 멘트와 같은 기준).

## 4. 처리 로직

### 4.1 권한 판정

- 모든 관리자 API는 **서버에서 `role == 'admin'`을 검증**한다. 클라이언트가 화면을 숨기는 것은 편의일 뿐 통제 수단이 아니다.
- 관리자 행위(업로드·회수·주제 변경)는 전부 `audit_logs`에 기록한다 — 누가·언제·무엇을 바꿨는지 남지 않으면 파트너 분쟁에 대응할 수 없다.
- 관리자 계정 부여는 **앱에서 하지 않는다.** DB 직접 변경 또는 마이그레이션으로만 처리한다(앱에 권한 승격 경로를 만들면 그 자체가 공격면이 된다).

### 4.2 콘텐츠 업로드 → 즉시 발행 (FR-37)

```
[입력]  메타 + 오디오 + 썸네일 (+ 스크립트)
   ↓
[검증]  필수값 · 파일 형식 · 라이선스 기간 · 주제 유효성
   ↓
[저장]  오디오를 비공개 스토리지에 업로드 → audio_path 확보
   ↓
[발행]  contents(status = published, published_at = now) 생성
   ↓
[연결]  content_topics · content_scripts 생성
```

- **`draft` 상태를 두지 않는다.** 업로드 = 발행이다(`domain.md` 5.1). 중간 상태가 없으므로 "발행 버튼"도 따로 없다.
- 업로드 전 검증에서 막는 것:
  - 라이선스 기간이 지났거나 오디오화 허용 범위 밖인 콘텐츠 → **업로드 거부**(`partner-control.md` 4.4)
  - 출처·저자·원문 링크 누락 → **파트너 콘텐츠는 거부** (FR-12는 예외 없는 필수 고지다). `origin == ai_generated`는 source_name의 "참고한 자료" 표기 누락만 거부하고 source_url·author_name은 선택이다(3.1의 분기 — 합의 2026-08-06, `domain.md` 5.1 반영 완료)
  - 검수 완료 확인(체크) 누락 → 거부 (4.2-1의 수동 검수를 거치지 않은 업로드를 막는다)
  - `is_visible = false`인 주제에는 배정할 수 있다(관리자가 준비 중인 주제에 콘텐츠를 미리 쌓는 경우)
- 발행 즉시 탐색 피드·드립 후보 풀에 편입된다. 별도 반영 작업이 없다.
- **업로드는 원자적으로 처리한다.** 오디오만 올라가고 `contents` 행이 없는 상태를 만들지 않는다. 실패 시 업로드된 파일도 정리한다.

### 4.2-1 업로드 전 수동 검수 체크리스트 (MVP QA)

업로드 = 즉시 발행이므로(4.2), **업로드 전에 사람이 아래 4가지를 확인한다**(합의 2026-08-06) — `content-pipeline.md` 4.4의 QA 항목을 MVP에서는 사람이 이행하는 것이다. 중간 상태가 없어 검수 없는 업로드는 그대로 전 사용자에게 노출된다.

1. **대본↔원문 사실관계 대조** — 원문에 없는 수치·인용·사례가 없는지, 주장 강도가 왜곡되지 않았는지 (FR-09·FR-10)
2. **금칙** — 욕설·차별 표현·특정인 비방
3. **출처 고지 멘트** — 오디오의 시작·종료에 출처 고지 멘트가 포함되어 있는지 (FR-12)
4. **오디오 품질** — 오독·비정상 무음·파일 무결성

- 이행 여부는 3.1의 **검수 완료 확인(체크)** 으로 확인한다. 별도 저장 컬럼은 없고 **`audit_logs`의 업로드 기록이 증적을 담당한다**(`domain.md` 5.1 확정 2026-08-06).
- PRD 9.1의 검증 대상은 이 체크리스트의 **이행률**이다(`content-pipeline.md` 4.4).

**적법 수집 확인 (FR-11) — `origin == ai_generated`**

- `ai_generated` 콘텐츠는 업로드 전에 **근거 소스의 저작권·이용약관·수집 정책 준수를 확인한다**(합의 2026-08-06 — `content-pipeline.md` 4.1의 수집 정책 체크를 MVP에서는 사람이 수행). 확인을 통과하지 못한 소스에 근거한 콘텐츠는 업로드하지 않는다.
- 근거 소스 목록·정책 확인 기록을 시스템 필드로 남길지는 **미결**이다(`domain.md` 15.1 결정 항목 #8로 등록됨).

### 4.3 재발행 (콘텐츠 수정)

- 오디오나 메타를 고칠 때 **새 행을 만들지 않고 같은 행의 `content_version`을 올린다**(`domain.md` 5.1).
- `content_id`가 유지되므로 `library_items` · `playback_progresses` · `content_stats` 참조가 끊기지 않는다.
- 클라이언트는 `content_version`이 달라지면 저장된 재생 위치와 오프라인 파일을 폐기한다(`player.md` 7).
- **오디오 길이가 바뀌면 재생 위치가 콘텐츠 길이를 넘을 수 있다.** 이 경우 클라이언트가 위치를 0으로 리셋한다.

### 4.4 회수 (FR-32)

- 관리자가 직접 회수하거나, 파트너 요청(`content_control_requests`)을 대행해 처리한다.
- 처리 절차와 노출면별 반영은 [`partner-control.md`](partner-control.md) 4.3을 그대로 따른다. **이 화면은 그 로직의 실행 창구일 뿐 별도 규칙을 갖지 않는다.**
- **MVP에서는 파트너 포털을 만들지 않는다.** 파트너 요청을 운영자가 받아 이 화면에서 대행한다(`partner-control.md` 2).

### 4.5 주제 관리 (FR-38)

- 주제 추가·수정·노출 토글·정렬을 제공한다.
- **`is_visible`은 관리자만 바꾼다. 시스템이 자동으로 내리거나 올리지 않는다.**
  - 콘텐츠가 다시 생겨도 자동으로 되살아나지 않는다 — 관리자가 다시 켜야 한다
  - 갱신 주체를 한 곳으로 고정해야 값이 어긋나지 않는다(`domain.md` 4.1)
- **주제 노출 통제(`is_visible`)는 신규 주제의 공개 전 단계에만 쓴다**(합의 2026-08-06 — 콘텐츠가 충분히 수급된 뒤 노출을 시작한다). 이미 선택한 사용자가 있는 주제를 숨기는 운영은 하지 않는다. 품질 문제 콘텐츠는 숨김이 아니라 **회수**(4.4)로 처리한다.
- **주제 신규 생성 시 기본 `is_visible = false`다**(합의 2026-08-06 — 콘텐츠 수급 후 노출을 시작한다. `domain.md` 4.1 반영 완료).
- **콘텐츠 0건인 주제의 노출을 켜려 하면 경고 확인을 거친다.** PRD 8.1의 "0건 주제 선택 불가" 전제(온보딩에서 "고를 수는 있는데 볼 게 없는 주제"는 존재하지 않는다 — `onboarding.md` 3장)를 보호한다.
- **주제별 콘텐츠 건수는 조회 시 집계해 표시한다.** `topics`에 `content_count` 컬럼을 두지 않는다 — 파생값이므로 컬럼과 집계가 어긋날 수 있다.
- **주제 삭제는 콘텐츠가 0건일 때만 허용한다.** 콘텐츠가 있으면 삭제 대신 `is_visible = false`를 안내한다(FK 위반 방지).
- 사용자가 이미 선택한 주제를 숨겨도 `user_interests` 레코드는 유지된다(`interest-management.md` 7).

### 4.6 운영 현황 조회

읽기 전용 대시보드. 별도 테이블을 만들지 않고 기존 데이터를 집계한다.

| 항목 | 원천 |
|---|---|
| 발행 콘텐츠 수 / 주제별 분포 | `contents` + `content_topics` |
| 콘텐츠별 재생·완청·담기 | `content_stats` (주간·월간·전체) |
| 드립 배치 실행 현황 | `drip_batch_runs` |
| 주제별 콘텐츠 부족 경고 | 활성 관심 주제 대비 발행 건수 — **제작 우선순위 판단용** |
| 검수 반려·재제작 건수 | **운영 로그 수동 집계** — PRD 10장 제작 품질 지표 |

- 드립 자동 확장(FR-18, P1)이 후보를 못 찾은 경우도 여기에 표시한다. MVP에는 자동 생성 파이프라인이 없으므로 **팀이 직접 해당 주제 콘텐츠를 제작한다**(`drip-scheduling.md` 4.5).

## 5. 화면 상태

| 화면 | 상태 | 표시 |
|---|---|---|
| 진입 | 일반 계정 | 설정에 [관리자] 항목이 보이지 않음 |
| 진입 | 관리자 계정 | 설정 하단 [관리자] 노출 |
| 업로드 | 기본 | 메타 입력 폼 + 파일 선택 + [업로드] (필수값 미충족 시 비활성) |
| 업로드 | 업로드 중 | 진행률 + 화면 이탈 차단(중단 시 부분 업로드 정리) |
| 업로드 | 검증 실패 | 필드별 인라인 에러 — 어느 값이 왜 막혔는지 명시 |
| 업로드 | 성공 | "발행되었습니다" + 콘텐츠 상세로 이동 |
| 콘텐츠 목록 | 정상 | 제목·주제·파트너·발행일·상태·재생 수. 상태·주제·파트너 필터 |
| 콘텐츠 상세 | 정상 | 메타 + 오디오 미리듣기 + [수정(재발행)] / [회수] |
| 콘텐츠 상세 | 회수됨 | 회수 사유·시각 표시 + [복구] |
| 주제 관리 | 정상 | 주제 목록 + 콘텐츠 건수(집계) + 노출 토글 + 정렬 |
| 주제 관리 | 삭제 시도(콘텐츠 있음) | "콘텐츠가 N건 있어 삭제할 수 없어요. 숨김 처리를 권장합니다" |
| 현황 | 정상 | 발행 수·주제별 분포·배치 현황·부족 주제 경고 |

**관리자 화면은 UI 완성도보다 정확성이 우선이다.** 잘못 업로드하면 전 사용자에게 즉시 노출된다(중간 상태가 없으므로).

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `users.role` — `user \| admin`. 관리자 판정의 유일한 근거 | 3.1 |
| `contents` — 업로드 시 `status = published`로 생성 | 5.1 |
| `content_topics` — 주제 배정 | 5.2 |
| `content_scripts` — 스크립트(P1) | 5.3 |
| `content_stats` — 현황 대시보드 | 5.4 |
| `topics` — `is_visible`은 **여기서만** 변경된다 | 4.1 |
| `partners` · `content_control_requests` — 회수 대행 | 10.1 · 10.2 |
| `audit_logs` — 모든 관리자 행위 기록 | 10.3 |
| `drip_batch_runs` — 배치 현황 | 7.3 |

- 관리자 전용 테이블은 **없다.** 별도 `admins` 테이블을 만들지 않고 `users.role`로 구분한다.
- `SourceDocument` · `Episode` · `Script` · `QaReport` · `PipelineRun`은 폐기됐다(`domain.md` 14장). 시리즈 정보는 `contents.series_id` · `episode_no`에 직접 들어간다.

## 7. 예외 상황

- **업로드 중 네트워크 끊김**: 부분 업로드된 오디오 파일을 정리하고 `contents` 행은 생성하지 않는다. 재시도는 처음부터.
- **같은 콘텐츠를 두 번 업로드**: 시스템이 자동 판별하지 않는다. 중복 방지 키가 없으므로 **목록에서 제목·원문 링크로 확인하는 것이 운영 책임**이다. → 미결 사항
- **오디오 길이가 0이거나 추출 실패**: 업로드를 거부한다. 길이를 모르면 완청 판정(90%)이 불가능하다(`library.md` 7).
- **주제를 숨긴 뒤 그 주제만 가진 콘텐츠**: 상정하지 않는다. 주제 노출 통제(`is_visible`)는 **신규 주제의 공개 전 단계에만** 쓰고(4.5 — 합의 2026-08-06), 이미 선택한 사용자가 있는 주제를 숨기는 운영은 하지 않으므로 숨김이 기존 사용자의 드립 편성에 영향을 주는 상황이 없다(드립 후보 필터에 `is_visible` 조건이 없는 것과 정합 — `drip-scheduling.md` 4.2). 품질 문제 콘텐츠는 회수로 처리한다.
- **관리자가 자기 계정의 `role`을 바꾸려 시도**: 앱에 권한 변경 경로 자체를 두지 않는다.
- **회수한 콘텐츠를 복구**: `status = published`로 되돌아가지만 **삭제된 `library_items`는 복구되지 않는다**(`partner-control.md` 4.3).
- **라이선스 만료일이 지난 콘텐츠를 수정**: 만료 상태에서는 재발행을 막는다. 계약 갱신 후 만료일을 먼저 연장해야 한다.
- **시리즈 중간 편만 회수**: 남은 편들의 `total_episodes`를 자동 조정하지 않는다. 편성 순서에 구멍이 생기므로 운영자가 시리즈 전체를 검토해야 한다. → 미결 사항

## 8. 완료 조건

- Given 일반 사용자 계정 / When 설정 화면을 연다 / Then [관리자] 항목이 노출되지 않는다
- Given 일반 사용자 계정 / When 관리자 API를 직접 호출한다 / Then 403이 반환된다
- Given 관리자 계정 / When 오디오와 필수 메타를 채워 업로드한다 / Then 콘텐츠가 즉시 `published` 상태로 생성되고 탐색 피드에 노출된다
- Given 관리자가 업로드한 콘텐츠 / When 다음 드립 배치가 실행된다 / Then 해당 콘텐츠가 후보 풀에 포함된다
- Given **파트너 콘텐츠**의 출처 링크를 비운 채 업로드를 시도한다 / When [업로드]를 누른다 / Then 검증 실패로 막히고 어떤 필드가 문제인지 표시된다 (`origin == ai_generated`는 source_url이 선택이므로 이 검증을 적용하지 않는다 — 3.1·4.2)
- Given 라이선스 만료일이 지난 파트너 콘텐츠 / When 업로드를 시도한다 / Then 거부된다
- Given 발행된 콘텐츠의 오디오를 교체한다 / When 재발행한다 / Then `content_id`는 그대로이고 `content_version`만 증가한다
- Given 콘텐츠가 3건 배정된 주제 / When 삭제를 시도한다 / Then 삭제되지 않고 숨김 처리를 안내한다
- Given 주제의 노출을 끈다 / When 사용자가 온보딩 주제 목록을 조회한다 / Then 해당 주제가 노출되지 않는다
- Given 콘텐츠가 0건이던 주제에 콘텐츠를 업로드한다 / When 사용자 목록을 확인한다 / Then 주제는 **자동으로 노출되지 않고**, 관리자가 노출을 켜야 보인다
- Given 콘텐츠가 0건인 주제 / When 노출 토글을 켠다 / Then **경고 확인을 거쳐야 켜지며**, 확인 없이 즉시 켜지지 않는다(4.5)
- Given 관리자가 콘텐츠를 회수한다 / When 사용자가 라이브러리를 새로고침한다 / Then 해당 콘텐츠가 사라진다
- Given 관리자가 업로드·회수·주제 변경을 수행한다 / When 감사 로그를 조회한다 / Then 행위자·시각·변경 내용이 기록되어 있다

## 미결 사항

- **관리자 계정 부여 절차** — DB 직접 변경으로 가정했다. 운영 인원이 늘면 절차·승인 경로를 문서화해야 한다
- **`ai_generated`의 근거 소스 목록·정책 확인 기록 필드 도입 여부** — 현재는 업로드 전 수동 확인(4.2-1)만 있고 확인 기록이 시스템에 남지 않는다. `domain.md` 15.1 결정 항목 #8로 등록됨
- ~~검수 완료 확인(체크)의 이행 기록 필드~~ → **확정(2026-08-06): 저장 컬럼을 두지 않는다.** 업로드 검증이 미체크를 거부하므로 발행 행에서 항상 참인 값이며, 증적은 `audit_logs`가 담당한다(`domain.md` 5.1)
- **중복 업로드 방지 키 도입 여부** — 현재는 운영 책임. `(partner_id, source_url)` 유니크를 걸지 결정 필요
- **시리즈 편집 UX** — 중간 편 회수·순서 변경 시 `episode_no` 재조정 방식 미정
- **업로드 대상 파일 규격** — 비트레이트·샘플레이트·최대 용량 상한 확정 필요
- **관리자 화면의 형태** — 앱 내 화면으로 가정했으나(PRD 4.1 "앱 내 제한 기능"), 업로드 편의상 웹 콘솔이 나을 수 있다. 파일 업로드·메타 입력이 많아 모바일 입력이 불리하다
- **스크립트 입력 방식** — 수동 입력인지 파일(SRT/VTT) 업로드인지 미정 (FR-25가 P1이므로 함께 결정)
