# 온보딩 기능 명세서

> 연결 PRD: FR-03, FR-04, FR-17 / 사용자흐름 5.1

## 1. 목적 & 연결

신규 사용자에게서 드립 편성에 필요한 최소 신호(관심 주제)를 받고, 첫 라이브러리를 비어 있지 않은 상태로 만들어 "열면 들을 게 준비되어 있는" 첫인상(PRD 1.3)을 완성한다.

- PRD FR-03 (P0) 중분류 관심 주제 최소 1개·최대 3개 선택
- PRD FR-04 (P0) 커리어 정보 입력(선택, 이후 수정 가능)
- PRD FR-17 (P0) 콜드스타트 — 신호가 없는 신규 사용자 대체 편성
- PRD 사용자흐름 5.1

## 2. 진입 조건

- 신규 가입 직후(약관 동의 완료 시점)
- 기존 계정이지만 `onboarding_completed == false`인 상태로 앱을 실행했을 때 → `onboarding_step`에 저장된 단계부터 재개
- 온보딩 중에는 라이브러리·탐색 등 다른 탭에 접근할 수 없다

## 3. 입력값

| 단계 | 값 | 필수 |
|---|---|---|
| 1. 관심 주제 | selected_topic_ids: string[] | **필수, 최소 1개 · 최대 3개** |
| 2. 커리어 | job_category: string | 선택 |
| 2. 커리어 | job_title: string | 선택 |
| 2. 커리어 | years_of_experience: enum(0-1/2-3/4-6/7+) | 선택 |
| (단계 밖) 알림 권한 | OS 권한 응답 | — |

- **주제는 3개까지만 고를 수 있다.** 상한을 두는 이유는 드립 편성 때문이다 — 하루 2편(무료 기준)을 여러 주제에 분산하면 어느 주제도 충분히 쌓이지 않아 "내 관심사가 반영된다"는 느낌이 생기지 않는다. 주제를 넓히는 경로는 자동 확장(FR-18)이 따로 맡는다.
- **상한은 서버도 검증한다.** 클라이언트의 선택 제한만으로는 우회된다.
- **온보딩에 콘텐츠 담기 단계는 없다**(2026-10-11 — 종전 3단계 "추천 콘텐츠 담기" 제거). **라이브러리의 첫 채움은 첫 드립이 전담한다.** 2단계 저장 뒤 완료 요청이 나가고, 자동 드립 적립이 끝나기 전에는 완료 화면에 도달하지 않는다(4장 [완료]) — 사용자가 곧바로 빈 라이브러리를 만나면 온보딩의 목적("열면 들을 게 준비되어 있는" 첫인상)이 깨진다.
- 주제 목록은 서버가 제공한다. **수급 콘텐츠에서 역산한 중분류만 노출**한다(FR-03).
- 노출 여부는 `topics.is_visible`로 결정되며 **이 값을 켜는 것은 관리자만 한다**(FR-38). **콘텐츠 풀이 없는 주제는 애초에 노출되지 않는다** — 노출 가능 콘텐츠가 0건인 주제는 서버가 켜기를 거부하고, 노출 중 0건이 되면 자동으로 숨긴다(`admin.md` 4.5, 개정 2026-09-17). 따라서 온보딩에서 "고를 수는 있는데 볼 게 없는 주제"는 존재하지 않는다.

## 4. 처리 로직

### 단계 구성

**진행 인디케이터는 2개다**(2026-10-11 — 종전 3단계 "추천 콘텐츠 담기" 제거). 완료 대기·완료 화면과 알림 권한 요청은 **인디케이터 밖**에 둔다. 인디케이터는 `1/2 · 2/2` 텍스트 라벨이다.

```
[0] 온보딩 시작 안내(선택 화면 없이 바로 1로 갈 수도 있음)
 → [1] 관심 주제 선택      (1/2) 필수, 건너뛰기 불가
 → [2] 커리어 정보 입력    (2/2) 건너뛰기 가능 — 저장 성공 뒤 곧바로 완료 요청
━━━━━━━━ 인디케이터 종료 ━━━━━━━━
 → [완료 대기] 자동 드립 편성 — **모든 경로**, 인디케이터 없음
 → [완료] 자동 통과(화면 없음 — `onboarding-uiux.md` 4.6) — 인디케이터 없음
 → [알림] 권한 사전 안내   — 인디케이터 없음
 → 착지 화면(탐색) 진입
```

- **인디케이터에 들어가는 것은 사용자가 값을 입력하는 단계뿐이다.** 완료 화면은 결과 확인이고 알림은 권한 요청이라, 이 둘을 `3/4` · `4/4`로 세면 "아직 두 단계나 남았다"는 인상을 준다. 실제로 입력이 끝난 뒤라 이탈 지점을 하나 더 만드는 셈이다.
- 2단계를 마치면 인디케이터가 사라지고 완료 대기로 전환된다. **완료 대기·완료·알림 화면에서는 인디케이터를 그리지 않는다.**
- **[완료 대기]도 인디케이터에 넣지 않는다.** 사용자가 입력하는 단계가 아니라 서버 처리를 기다리는 구간이다.
- `onboarding_step` enum(`topic | career | pick | done`)은 그대로 쓴다(서버 계약 불변). `pick`은 담기 단계 제거 뒤 클라이언트가 머무는 단계가 아니며, **재개 진입에서 `pick`·`done`은 모두 완료 대기로 바로 간다.** **[완료 대기]를 위한 새 값을 만들지 않는다** — 완료 요청 시점에 이미 `done`으로 확정되고, 로딩은 그 이후 클라이언트가 편성 결과를 기다리는 구간일 뿐이라 서버가 관리하는 재개 지점이 늘어나지 않는다.

### 단계별 로직

**[1] 관심 주제 선택 (1/2)**
- 서버에서 중분류 주제 목록 조회(`is_visible = true`만, `display_order` 순)
- **최소 1개 · 최대 3개.** 1개 미만이면 [다음] 비활성, 3개를 고른 뒤에는 나머지 칩을 비활성 처리한다
  - 4번째를 탭하면 무시하지 말고 **"관심 주제는 3개까지 선택할 수 있어요"** 토스트로 이유를 알린다. 아무 반응이 없으면 오류로 읽힌다
  - 선택을 바꾸려면 기존 선택을 해제하면 된다
- 선택 즉시 서버에 저장하지 않고, 단계 이탈(뒤로가기 아닌 앱 종료) 대비로 **로컬 임시 저장** → [다음] 탭 시 서버 저장 + `onboarding_step = career`
- 서버는 저장 시 **개수 상한(3개)을 다시 검증**하고 초과분은 저장하지 않는다

**[2] 커리어 정보 (2/2)**
- 전부 선택 항목. [건너뛰기]와 [다음] 모두 제공
- **직군 선택지 목록은 서버가 제공한다**(확정 2026-08-10 — 커리어 정보 화면 `career.md`와 공용 목록. 클라이언트 상수로 두지 않는다). 직무는 자유 입력(100자 상한)이라 목록이 없다
- 입력값은 드립 편성의 보조 신호로만 쓰이고, 미입력이어도 편성은 정상 동작해야 한다
- **건너뛰어도 손해가 없다는 것을 화면에서 알린다** — "나중에 프로필에서 언제든 입력할 수 있어요"
  - 커리어 입력·수정은 **커리어 정보 화면**(`career.md`, 프로필·설정에서 진입)이 담당한다. 온보딩에서 못 받은 값을 다시 요구하는 별도 유도 화면은 만들지 않는다
- 저장 후 서버는 `onboarding_step = pick`으로 기록한다(계약 불변). **클라이언트는 저장 성공 직후 곧바로 완료 요청(`POST /onboarding/complete`)을 보내고 [완료 대기]로 간다**(2026-10-11 — 담기 단계 제거. 호출 순서는 종전 [건너뛰기](0건) 경로와 같다: career 저장 → complete).

**[3] 추천 콘텐츠 담기 — 제거(2026-10-11)**

종전 3단계(관심 주제 추천 6건 + 이번 달 인기 3건, 카드 다중 선택 → [담기] 적립 `source = onboarding`)는 **없다.** 가입 직후 단계를 줄이기 위한 PM 결정이며, 첫 드립이 라이브러리를 채우므로 담기 없이도 빈 라이브러리로 떨어지지 않는다. 종전 규칙은 `changes/archive/remove-onboarding-pick-step.md` 참조. 추천 조회·담기 엔드포인트는 서버에 남아 있으나 클라이언트가 호출하지 않는다(`onboarding-api.md` 4.5·4.6).

**[완료] 완료 처리** — 인디케이터 없음

- 완료 요청은 2단계 저장 성공 직후 나간다. 완료 화면은 자동 통과한다(화면·안내 순서는 `onboarding-uiux.md` 4.6)
- 서버는 완료 요청을 받은 시점에 `onboarding_completed = true` 처리 및 **첫 드립 편성을 즉시 트리거**한다(`drip-scheduling.md` 2·4.6)
  - 온보딩에 담기 단계가 없으므로 **라이브러리의 첫 채움은 첫 드립이 전담한다.** 첫 드립은 반드시 실행한다
  - `picked_count`는 늘 0이고 `awaits_first_drip` 판정은 서버가 한다(`onboarding-api.md` 4.7)
- **완료 요청 직후 로딩 화면([완료 대기])으로 전환하고, 자동 드립 적립이 끝난 것을 확인한 뒤에만 완료로 넘어간다.** 적립 전에 넘기면 사용자가 도착하는 라이브러리가 비어 있다.
  - 적립은 원자적으로 처리되므로(`drip-scheduling.md` 4.6-4) "일부만 채워진 상태로 완료"는 없다. 성공이거나 실패다.
- **자동 드립 트리거 실패 시 자동 재시도한다.** 재시도 규칙은 새로 만들지 않고 공통 규칙을 따른다(`common-error-handling.md` 4.2) — 화면마다 재시도 정책이 갈리면 오류 동작을 예측할 수 없게 된다.
  - **최대 2회 재시도(총 3회 시도), 백오프 1초 → 3초(지터 ±20%).**
  - 완료 요청과 드립 트리거는 **멱등키**를 붙여 보낸다. 상태를 바꾸는 요청은 멱등키가 있을 때만 자동 재시도 대상이다(`common-error-handling.md` 4.2). 서버 측 최종 방어선은 `library_items (user_id, content_id)` 유니크다(`drip-scheduling.md` 4.6-5).
  - **재시도를 소진하거나 로딩이 상한(기준값: 15초)을 넘으면 로딩 화면을 걷고 완료 화면으로 진행한다.** 사용자를 로딩 화면에 가둬 두는 것이 최악이다 — 온보딩은 이미 서버에서 완료 처리됐는데 앱만 앞으로 못 가는 상태가 된다.
    - 이때 편성은 **서버의 비동기 재시도 큐**로 넘기고, 라이브러리는 "콘텐츠를 준비하고 있어요" 상태로 진입한다(`library.md` 5).
    - 동시에 **운영 알림을 발생시킨다.** 신규 사용자의 첫 편성 실패는 편성 배치 장애의 조기 신호라, 사용자에게 조용히 넘기고 끝내면 아무도 모른다.
  - **완료 처리는 롤백하지 않는다.** 드립 실패를 이유로 `onboarding_completed`를 되돌리면 사용자가 온보딩을 처음부터 다시 하게 되고, 원인인 편성 장애는 재시도해도 그대로다.
- **무료(라이트) 티어도 온보딩 초기 적립과 이후의 일일 자동 드립을 모두 받는다.** 무료 티어의 드립 편수는 하루 2편으로 고정한다(PRD FR-14).

**[알림] 권한 요청** — 인디케이터 없음

- OS 권한 다이얼로그 직전에 사전 안내(프리퍼미션) 화면을 노출한다 — "새 콘텐츠가 도착하면 알려드릴까요?" ("드립"은 내부 용어라 카피에 쓰지 않는다)
- [나중에]를 누르면 **추가 팝업 없이 곧바로 닫는다**(되짚기 팝업 폐지 2026-09-06).
  - 되짚기는 전환율을 올리지만 **거절을 한 번 무르는 상호작용**이다. 1회로 제한해도 "닫으려는데 또 뜬다"는 인상이 남는다.
  - **되돌릴 구조가 이미 있다.** [나중에]는 OS 다이얼로그를 띄우지 않으므로 권한이 **미결정**으로 남고, 설정 알림 섹션의 유도 배너가 회수 경로를 맡는다((b)안, `notification.md` 4.1 · `settings.md` 4.3).
  - 두 버튼은 **가로 배치·동등 비중**으로 둔다 — [나중에] 왼쪽(면·테두리 없음), [알림 받기] 오른쪽(면 채움). 거부를 어렵게 만드는 순간 다크패턴이고 스토어 심사 지적 대상이다.
- **[나중에] 경로에서는 OS 다이얼로그를 띄우지 않는다** — OS 권한은 한 번 거부되면 재요청이 불가하므로 소진하지 않는다
- 허용/거부 결과와 무관하게 라이브러리로 진입

## 5. 화면 상태

| 단계 | 상태 | 화면 |
|---|---|---|
| 1~2 | 진행 표시 | 상단 스텝 인디케이터 **`N/2`**(텍스트 라벨), 뒤로가기로 이전 단계 이동 가능 |
| 완료 대기·완료·알림 | 진행 표시 | **인디케이터 없음** |
| 1 | 로딩 | 주제 목록 스켈레톤 |
| 1 | 미선택 | [다음] 비활성 + "관심 주제를 1개 이상 선택해주세요" |
| 1 | 선택됨 (1~2개) | 선택 칩 강조 + **"N/3 선택"** + [다음] 활성 |
| 1 | 3개 선택 완료 | **"3/3 선택"** + 미선택 칩 비활성 처리 + [다음] 활성 |
| 1 | 4번째 선택 시도 | 토스트 "관심 주제는 3개까지 선택할 수 있어요" |
| 1 | 목록 조회 실패 | 에러 상태 + [다시 시도] (온보딩은 서버 저장 필수라 오프라인 진행 불가) |
| 2 | 기본 | 입력 필드 + 안내 "나중에 프로필에서 언제든 입력할 수 있어요" + [건너뛰기](텍스트 버튼) / [다음] — 어느 쪽이든 저장 뒤 완료 요청 → 완료 대기 |
| 완료 대기 | 자동 드립 편성 중 (**모든 경로**) | 전체 화면 로딩 "첫 콘텐츠를 준비하고 있어요" — **인디케이터 없음, 뒤로가기 차단.** 0.3초 미만이면 표시하지 않는다(`common-error-handling.md` 5) |
| 완료 대기 | 재시도 중 | **같은 로딩 화면을 그대로 유지한다.** 재시도 중이라는 사실을 노출하지 않는다 — 사용자가 할 수 있는 일이 없는데 실패를 알리면 불안만 만든다 |

## 7. 예외 상황

- **1단계에서 주제를 고르다 앱을 강제 종료**: 서버 저장 전이므로 재실행 시 1단계부터. 로컬 임시 저장분을 복원해 선택 상태는 유지한다.
- **로컬 임시 저장분이 3개를 넘는 경우**(상한 도입 이전 버전에서 남은 값): 앞의 3개만 복원한다.
- **2단계 저장 후 종료**: `onboarding_step = pick`(또는 `done`)이므로 **완료 대기로 바로 간다**(2026-10-11 — 담기 단계 제거).
- **커리어를 건너뛴 사용자**: 재촉하지 않는다. 이후 입력·수정은 커리어 정보 화면에서 한다(`career.md`, 프로필·설정에서 진입).
- **주제 목록이 비어 있는 경우**(콘텐츠 풀 미구축): **발생하지 않는 것이 원칙이다**(합의 2026-08-06) — 주제 풀은 서비스 시작 시 콘텐츠와 함께 준비되며, 정해진 주제 풀 전체를 노출한다. 그럼에도 목록이 0건이면 **데이터 정합성 오류**로 다루어 운영 알림을 발생시키고, 사용자에게는 **재시도할 수 있는 "준비 중" 안내를 노출한다**(전체 화면 + [다시 시도] — 화면·확정 카피는 `onboarding-uiux.md` 4.2). **폴백 주제를 만들지 않는다**(PRD 8.1·FR-38 정합, 개정 2026-09-09 — 서버 폴백 세트 제거).
- **자동 드립이 재시도까지 모두 실패**(또는 로딩 상한 15초 초과): 로딩 화면을 걷고 완료 화면으로 진행한다. **사용자를 로딩 화면에 남겨두지 않는다** — 서버에서는 이미 완료 처리된 계정이라, 앱만 멈춰 있으면 재실행 말고는 빠져나갈 방법이 없다. 편성은 서버 비동기 재시도 큐로 넘기고 **운영 알림을 발생시킨다.**
- **편성할 후보 자체가 없는 경우**(주제 고갈): **재시도 대상이 아니다.** 실패가 아니라 결과가 빈 것이므로 다시 호출해도 같은 결과가 나온다. 즉시 완료 화면으로 진행하고 인기 콘텐츠 대체 편성(신규 사용자 콜드스타트 전용 — `drip-scheduling.md` 4.4·7, FR-17)에 맡기되, 그것도 비면 운영 알림을 발생시킨다.
- **자동 드립 로딩 중 앱 강제 종료**: 완료 요청은 이미 서버에서 처리됐으므로 재실행 시 `onboarding_completed == true`로 판정되어 **라이브러리로 바로 진입한다**(`splash.md` 4). 로딩·완료 화면은 다시 보여주지 않는다. 이 경로에서는 **알림 권한 사전 안내를 건너뛰게 되므로**, 설정 알림 섹션의 유도 배너로 재진입한다((b)안 확정, 합의 2026-08-06 — `notification.md` 4.1, `settings.md` 4.3).
- **자동 드립 로딩 중 뒤로가기**: 무시한다. 2단계로 되돌리면 이미 완료 처리된 온보딩을 다시 진행하는 모순 상태가 된다.
- **이미 OS 알림 권한이 허용된 상태**(재설치 등): 알림 단계를 건너뛴다.
- **온보딩 도중 로그아웃·세션 만료**: 시작 화면으로 이동. 재로그인 시 저장된 `onboarding_step`부터 재개.
- **뒤로가기로 1단계에서 더 뒤로**: 온보딩 이탈 확인 팝업 없이 아무 동작 안 함(계정은 이미 생성됨). 이탈하려면 설정이 아니라 앱 종료뿐.

## 8. 완료 조건

- Given 신규 가입 직후 사용자 / When 관심 주제를 하나도 선택하지 않는다 / Then [다음] 버튼이 비활성 상태로 유지된다
- Given 관심 주제를 2개 선택했다 / When [다음]을 누른다 / Then 서버에 관심사가 저장되고 커리어 입력 단계로 이동한다
- Given 관심 주제를 3개 선택했다 / When 4번째 주제를 탭한다 / Then 선택되지 않고 **"3개까지 선택할 수 있어요"** 토스트가 노출된다
- Given 클라이언트를 우회해 주제 4개를 서버로 보낸다 / When 저장을 요청한다 / Then 서버가 상한을 검증해 거부한다
- Given 온보딩 1~2단계 / When 각 화면을 본다 / Then 상단 인디케이터가 **`1/2` · `2/2`** 텍스트 라벨로 표시된다
- Given 2단계를 마쳤다 / When 완료 대기·완료·알림 화면으로 넘어간다 / Then **인디케이터가 노출되지 않는다**
- Given 커리어 입력 단계 / When [건너뛰기]를 누른다 / Then 커리어 정보 없이 다음 단계로 이동하고, 이후 드립 편성이 정상 동작한다
- Given 커리어를 건너뛴 사용자 / When 온보딩 완료 후 프로필에 진입한다 / Then 커리어를 입력·수정할 수 있다
- Given 커리어 단계 / When [다음] 또는 [건너뛰기]를 누른다 / Then 저장 성공 뒤 완료 요청이 나가고 자동 드립 트리거가 작동하며 **로딩 화면이 노출되고 완료 화면은 아직 뜨지 않는다**
- Given 자동 드립 적립이 성공했다 / When 편성이 끝난다 / Then 로딩 화면이 사라지고 완료로 넘어가며, 라이브러리가 비어 있지 않다
- Given 자동 드립 트리거가 실패한다 / When 재시도가 수행된다 / Then **최대 2회 자동 재시도(1초 → 3초 백오프)** 가 이뤄지는 동안 로딩 화면이 유지되고 에러 화면은 노출되지 않는다
- Given 재시도가 모두 실패했다 / When 로딩 상한을 넘긴다 / Then **로딩 화면에 갇히지 않고 완료 화면으로 진행**하며, 라이브러리에 "콘텐츠를 준비하고 있어요" 배너가 노출되고 운영 알림이 발생한다
- Given 커리어 단계까지 마치고 앱을 종료한 사용자(`onboarding_step = pick`) / When 앱을 재실행한다 / Then 완료 대기로 바로 가고 담기 화면은 나타나지 않는다
- Given 알림 사전 안내에서 [나중에]를 누른다 / When 화면을 본다 / Then **추가 팝업 없이 닫히고** OS 권한은 미결정으로 남는다
- Given 알림 사전 안내에서 [알림 받기]를 누른다 / When 다음으로 넘어간다 / Then OS 권한 다이얼로그가 노출된다
- Given 알림 사전 안내 / When 두 버튼을 본다 / Then 가로로 나란히 있고 [나중에]가 회색·소형으로 축소되어 있지 않다
- Given 온보딩을 완료했다 / When 뒤로가기를 누른다 / Then 온보딩 화면으로 돌아가지 않는다
