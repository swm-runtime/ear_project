# 콘텐츠 상세 기능 명세서

> 연결 PRD: FR-40, FR-12 / 사용자흐름 5.3 (작성 2026-08-23)

## 1. 목적 & 연결

콘텐츠의 메타데이터(제목·소개·오디오 길이·발행일·출처·주제 등)를 한 화면에서 확인하고, **[재생]·[담기/삭제]로 바로 행동할 수 있는 화면**(개정 2026-08-23 — 표시 전용 폐기). 행 본문 탭 = 즉시 재생 원칙(PRD 5.2·5.3)은 그대로 두고, 재생하기 전에 "이게 무엇인지" 확인하고 싶은 요구를 더보기 시트 경유의 별도 화면으로 해소한다.

- PRD FR-40 (P0) 더보기 시트의 [상세 정보]로 콘텐츠 상세 화면에 진입한다
- PRD FR-12 (P0) 원저자·출처 고지 — 상세 화면은 재생 멘트 밖에서 출처를 확인할 수 있는 노출면이다
- 종전 합의(2026-08-06)의 "상세 화면은 두지 않는다 — 명세 추가 후 개발"을 이 문서로 해소한다(합의 2026-08-23)

## 2. 진입 조건

- **라이브러리** 아이템의 더보기 시트 > [상세 정보] (`library.md` 3)
- **탐색** 행의 더보기 시트 > [상세 정보] (`explore.md` 3)
- **플레이어** 더보기 시트 > [상세 정보] (`player.md` 3 — 확정 2026-08-23, [원문 보기]와 같은 세 화면 더보기 통일 원칙(README 결정 44))
- 진입 시 더보기 시트는 닫히고 상세 화면으로 이동한다. 뒤로가기로 원 화면에 복귀하며, 목록 스크롤 위치는 유지된다. 플레이어에서 진입한 경우 **재생은 유지**되고 뒤로가기로 플레이어에 복귀한다

## 3. 입력값

| 값 | 설명 | 필수 |
|---|---|---|
| content_id | 더보기 시트를 연 콘텐츠 | 필수 |

## 4. 처리 로직

### 4.1 조회

- 진입 시 **콘텐츠 단건 상세를 서버에서 조회한다.** 목록 응답을 재사용하지 않는다 — 회수(FR-32)는 전 노출면 즉시 반영이 원칙이고, 상세 화면도 노출면이다. 조회 시점에 최신 `status`를 확인해야 한다
- `status ≠ published`(회수·만료)면 상세를 그리지 않고 안내 후 원 화면으로 복귀한다(7장)

### 4.2 화면 구성·표시 항목 (개정 2026-08-23)

**구성 순서** — 위에서 아래로, 구분선 두 개로 세 영역을 가른다.

1. **헤더** — 썸네일 · 제목 · 주제 태그 · **액션 버튼([재생] · [담기]/[삭제] — 4.4)**
2. **소개** — `description`
3. ― 구분선 ―
4. **메타** — 오디오 길이 · 발행일 · 시리즈 정보(조건부)
5. ― 구분선 ―
6. **출처** — 4.3

| 항목 | 값의 원본 (`domain.md` 5.1) | 규칙 |
|---|---|---|
| 제목 | `title` | 항상 표시 |
| 주제 태그 | `content_topics` | 항상 표시 — "왜 나에게 왔는가"(드립 편성 근거)가 보인다 |
| 소개 | `description` | 항상 표시 — 재생 전에 내용을 가늠할 유일한 수단 |
| 오디오 길이 | `duration_sec` | 항상 표시. **초 단위까지 표기한다**(예: "14분 32초" — 확정 2026-08-23). 목록 행의 분 단위 표기와 달리 상세는 정확한 값을 보여주는 자리다 |
| 발행일 | `published_at` | 항상 표시 |
| 시리즈 정보 | `series_id` · `episode_no` · `total_episodes` | **조건부** — 아래 4.3-1 |
| 출처 | `origin` 분기 | 아래 4.3 — partner는 저자·제공·[원문 보기], ai_generated는 **소스 목록 전체 나열** |

**두지 않는 것** — 나의 청취 상태(진행률·완청). 검토 후 제외 확정(2026-08-23) — 진행률·완청 마킹은 라이브러리 카드·미니플레이어가 이미 보여주는 값이라 상세에서 반복하지 않는다.

### 4.3 출처 표시 — origin 분기 (개정 2026-08-23)

`domain.md` 5.1의 고지 규칙을 따르되, **두 경우의 구성이 다르다.**

| origin | 구성 |
|---|---|
| `partner` (원문) | **저자**(`author_name`) · **제공**(`source_name` — 파트너명) · **[원문 보기]**(`source_url`) — 셋 다 필수라 항상 표시된다(체크 제약이 이중 방어). [원문 보기]는 더보기 시트와 같은 동작 — 인앱 브라우저 + `source_link_clicks` 기록 |
| `ai_generated` (소스) | **참고한 소스 목록을 전부 나열한다 — 소스마다 제목 + 저자를 표시**하고, "외 N건" 같은 생략 표기를 쓰지 않는다(확정 2026-08-23). **URL 문자열은 화면에 노출하지 않는다** — 링크가 있는 소스는 **항목 자체를 탭하면 인앱 브라우저로 연다**(개정 2026-08-23). 링크 없는 소스는 탭 대상이 아니다 |

> ⚠️ **소스 목록 나열은 현재 스키마로 불가능하다 — 백엔드 티켓 발행(2026-08-23).** `contents.source_name`은 표기 문자열 하나이고, domain.md 5.1이 "복수 소스를 별도 테이블·배열로 정규화하지 않는다"로 결정해둔 상태다(당시 용도가 고지 문구 표시 하나였기 때문). 이 화면이 소스 단위 표시(제목·저자·링크)를 요구하므로 그 전제가 깨졌다 — `tickets/backend/pending/content-sources-structured-list.md`. **FE는 `[{title, author|null, url|null}]`을 가정한 mock으로 선행 개발한다.**

### 4.3-1 조건부 항목 — 응답 값의 null 여부 하나로 판정한다

**클라이언트가 별도 조건을 계산하지 않는다.** 서버 응답에 값이 있으면 그리고, `null`이면 그 줄(블록)을 통째로 생략한다. 자리를 비워두거나 "없음"으로 채우지 않는다.

| 항목 | 판정 | 표시 |
|---|---|---|
| 시리즈 정보 | `series_id != null` | "N부작 중 M화"(`total_episodes` · `episode_no`). 단일 콘텐츠는 셋 다 `null`이다(`domain.md` 5.1 — "조회 코드는 이 분기를 처리해야 한다") |
| 소스의 저자 | 소스별 저자 유무 (`ai_generated`) | 저자가 없는 소스는 제목만 표시한다(4.3) |
| 소스의 링크 | 소스별 링크 유무 (`ai_generated`) | 링크가 없는 소스는 **탭 대상이 아니다** — 목록에서 빼지 않고 표시만 한다(4.3). partner의 [원문 보기]는 항상 있으므로 조건부가 아니다 |

### 4.4 액션 — [재생] · [담기]/[삭제] (확정 2026-08-23 — 표시 전용 폐기)

헤더에 액션 버튼 두 개를 둔다(4.2). **규칙은 소유 문서의 것을 그대로 재사용하고, 이 화면은 진입점 하나가 늘어난 것뿐이다** — 조건·문구·판정을 다시 정하지 않는다.

**[재생]**

- 행 탭과 **동일한 재생 판정 경로**를 거친다(`paywall.md` 4.1~4.2 — 한도 판정 → 확인 팝업/페이월/즉시 재생). 진입점이 다르다고 규칙이 달라지지 않는다
- 재생이 실제로 시작되면 미담김 콘텐츠는 **라이브러리에 자동 적립**된다(`explore.md` 4.4와 동일 — `source = save`, 팝업 [취소]·페이월 차단 시 적립 없음)
- **현재 재생 중인 콘텐츠**(플레이어에서 진입한 경우)면 새 재생을 시작하지 않고 플레이어로 복귀한다

**[담기] / [삭제]** — 담김 여부로 분기하며, 버튼 상태는 상세 응답의 담김 여부로 그린다

- 미담김 → **[담기]**: `explore.md` 4.3과 동일 — `LibraryItem(source = save)` 생성, `user_signals(save)` 적재, 토스트 "라이브러리에 담았어요". 성공 시 버튼이 [삭제]로 전환된다
- 담김 → **[삭제]**: `library.md` 4.5와 동일한 결과 — 소프트 삭제 + 드립 영구 제외(고지하지 않음), `user_signals(delete)` 적재. 성공 시 버튼이 [담기]로 전환된다. 재생 중인 콘텐츠를 삭제해도 재생은 유지된다(`player.md` 7과 동일)
- 담기·삭제에는 어떤 티어에서도 페이월이 뜨지 않는다(PRD 5.4)
- 처리 중에는 버튼을 비활성화해 중복 탭을 막고, 서버는 유니크 제약으로 멱등 처리한다(`explore.md` 7)

| 상태 | 표시 |
|---|---|
| 로딩 | 스켈레톤 — 0.3초 미만은 표시하지 않는다(`common-error-handling.md` 5장) |
| 정상 | 4.2의 구성 — 헤더(썸네일·제목·태그·[재생]·[담기]/[삭제]) / 소개 / 구분선 / 메타 / 구분선 / 출처 |
| [재생] 탭 | 재생 판정 결과에 따라 확인 팝업·페이월·즉시 재생(4.4 — 규칙은 `paywall.md`) |
| 담기·삭제 처리 중 | 버튼 로딩(중복 탭 차단). 성공 시 버튼 상태 전환 |
| 조회 실패 | 전면 에러 + [다시 시도] |
| 회수·만료 | 안내 후 원 화면 복귀(7장) |

화면 ID·레이아웃·카피·접근성은 `spec/uiux/`가 소유한다(작성 예정).

## 6. 데이터 모델

`domain.md` 5.1 `contents` · 5.2 `content_topics` · 6.1 `library_items`(담김 여부·담기/삭제) 참조.

- **`ai_generated`의 소스 목록(제목·저자·URL 배열)은 스키마에 없다** — 백엔드 티켓 `tickets/backend/pending/content-sources-structured-list.md`(4.3). 이것 외의 표시 항목은 기존 컬럼으로 성립한다
- 상세 응답에는 **담김 여부**([담기]/[삭제] 분기 근거)가 함께 실려야 한다
- [원문 보기]의 클릭 기록은 `source_link_clicks`(기존 규칙 재사용). 담기·삭제의 신호 적재는 `user_signals`(explore 4.3 · library 4.5와 동일)

## 7. 예외 상황

- **조회 시점에 회수·만료된 콘텐츠**: 상세를 그리지 않고 안내 토스트 후 원 화면으로 복귀한다. 라이브러리에서 진입했다면 목록도 갱신된다(`library.md` — 회수 동기화 규칙)
- **네트워크 오류**: `common-error-handling.md`의 공통 규약(전면 에러 + 재시도)
- **단일 콘텐츠**(`series_id = null`): 시리즈 줄을 노출하지 않는다(4.3-1)
- **링크 없는 소스**(`ai_generated`): 제목·저자만 표시하고 탭 대상이 아니다(4.3-1). 목록에서 빼지 않는다 — 나열은 전수다
- **[재생] 탭 시점에 한도 소진**: 행 탭과 동일 — 확인 팝업 대신 페이월(최상위 티어는 한도 안내)이 뜬다. 표시된 화면 상태를 근거로 재생을 통과시키지 않는다(`paywall.md` 4.1)
- **[삭제] 후 뒤로가기**: 라이브러리에서 진입했다면 목록에서 해당 아이템이 사라져 있다(스크롤 위치는 유지). 탐색에서 진입했다면 행은 그대로다(탐색은 담김 여부로 목록을 거르지 않는다)
- **담기·삭제 연타**: 버튼 비활성화 + 서버 멱등 처리(`explore.md` 7과 동일)

## 8. 완료 조건

- Given 라이브러리 아이템의 더보기 시트 / When [상세 정보]를 탭한다 / Then 상세 화면이 헤더(썸네일·제목·태그·[재생]·[담기]/[삭제]) → 소개 → 구분선 → 메타(길이·발행일·시리즈) → 구분선 → 출처 순서로 열린다
- Given 861초짜리 콘텐츠 / When 상세의 길이를 본다 / Then "14분 21초"로 초 단위까지 표시된다
- Given 탐색 행·플레이어의 더보기 시트 / When [상세 정보]를 탭한다 / Then 같은 상세 화면이 열린다(세 진입 경로가 같은 화면을 쓴다)
- Given 재생 중 플레이어의 더보기 시트에서 [상세 정보]로 진입했다 / When 뒤로가기 한다 / Then 재생이 유지된 채 플레이어로 복귀한다
- Given 상세 화면 / When 뒤로가기 한다 / Then 원 화면의 목록 스크롤 위치가 유지된 채 복귀한다
- Given 무료 사용자가 오늘 1회를 남기고 상세를 연다 / When [재생]을 탭한다 / Then 행 탭과 동일한 재생 확인 팝업이 뜨고, [재생하기]로 재생이 시작되면 미담김 콘텐츠는 라이브러리에 자동 적립된다
- Given 한도를 소진한 무료 사용자 / When 상세의 [재생]을 탭한다 / Then 확인 팝업 대신 페이월이 뜬다
- Given 현재 재생 중인 콘텐츠의 상세(플레이어에서 진입) / When [재생]을 탭한다 / Then 새 재생 없이 플레이어로 복귀한다
- Given 미담김 콘텐츠의 상세 / When [담기]를 탭한다 / Then 라이브러리에 담기고 버튼이 [삭제]로 전환된다
- Given 담긴 콘텐츠의 상세 / When [삭제]를 탭한다 / Then 소프트 삭제·드립 영구 제외가 적용되고(고지 없음) 버튼이 [담기]로 전환된다
- Given `origin = ai_generated`이고 참고 소스가 4건인 콘텐츠 / When 출처 영역을 본다 / Then 4건 전부가 제목·저자로 나열되고, "외 N건" 생략 표기와 URL 문자열은 화면에 없다
- Given 링크 있는 소스 항목 / When 항목을 탭한다 / Then 인앱 브라우저로 그 소스의 링크가 열린다
- Given 링크 없는 소스가 섞인 `ai_generated` 콘텐츠 / When 출처 영역을 본다 / Then 그 소스는 제목·저자만 표시되고 탭해도 아무 일도 일어나지 않으며, 목록에서 빠지지 않는다
- Given 시리즈 콘텐츠(`series_id != null`) / When 상세를 본다 / Then "N부작 중 M화" 시리즈 줄이 표시된다
- Given 단일 콘텐츠(`series_id = null`) / When 상세를 본다 / Then 시리즈 줄이 노출되지 않는다
- Given `origin = partner` 콘텐츠의 상세 / When 출처 영역을 본다 / Then 저자·제공·[원문 보기]가 표시되고, [원문 보기]를 탭하면 인앱 브라우저로 원문이 열리며 원문 유입 클릭이 기록된다
