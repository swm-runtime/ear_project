# 푸시 알림 기능 명세서

> 연결 PRD: FR-19 (P1) / 사용자흐름 5.1

## 1. 목적 & 연결

드립이 도착했음을 알려 다음 접속을 유도한다. "앱을 열면 들을 게 준비되어 있는" 경험(PRD 1.3)을 사용자가 인지하게 만드는 유일한 아웃바운드 채널이다.

- PRD FR-19 (P1) 드립 도착을 푸시로 알리고, 알림 수신 여부를 설정할 수 있다
- PRD 사용자흐름 5.1 (온보딩 마지막 단계에서 알림 권한 요청)

> **우선순위 P1.** MVP 일정에서 밀릴 경우, 푸시 발송은 빼더라도 **권한 요청 단계와 설정 토글의 자리는 남겨두는 것**을 권장한다(OS 권한은 사후 재요청이 어렵다).

## 2. 진입 조건

**권한 요청**
- 온보딩 마지막 단계(사전 안내 후 OS 다이얼로그)
- 설정에서 알림 토글을 켤 때(권한이 없으면 OS 설정으로 안내)

**푸시 발송**
- 드립 편성이 완료되어 라이브러리에 신규 콘텐츠가 적립된 시점

## 3. 입력값

**단말 등록**

| 값 | 설명 |
|---|---|
| device_token | **Expo 푸시 토큰**(`ExponentPushToken[...]` — Expo Push, 개정 2026-09-17) |
| platform, app_version, device_id | 단말 정보 |
| os_permission_granted | OS 권한 허용 여부 |

**발송 페이로드**

| 값 | 설명 |
|---|---|
| type | `drip_arrival`(드립 도착 — 탐험 편도 별도 종류 없이 여기에 합친다, 4.3) · `retention.<규칙>.<변형>`(저녁 리텐션 알림, 4.6 — 2026-10-26) |
| title, body | 알림 문구 — title "오늘의 콘텐츠 N편이 도착했어요", body 대표 콘텐츠 제목(4.3) |
| deep_link | 이동 대상 — **`ear://library`**(2편 이상) 또는 **`ear://contents/{content_id}`**(1편). 앱 스킴(`app.json` `scheme: ear`)이다 — 라이브러리는 웹 주소가 없고 앱 안 이동이라 공유 링크를 거치지 않는다(확정 2026-09-17, KAN-68) |
| content_count | 도착한 편수 — **정규 + 탐험** |

- 앱은 위 값을 푸시의 **`data`** 필드에서 읽는다: `{ "type": "drip_arrival", "deep_link": "...", "content_count": 3 }`. title·body는 OS 알림 표시용이다.

## 4. 처리 로직

### 4.1 권한 요청

- 온보딩의 **[알림] 화면**에서 **사전 안내(프리퍼미션)** 를 먼저 보여준다. [알림 받기] 선택 시에만 OS 다이얼로그를 띄운다.
  - 이유: OS 권한은 한 번 거부되면 앱에서 다시 요청할 수 없다. 사전 안내로 거부율을 낮춘다.
  - **"5단계"로 부르지 않는다.** 온보딩 인디케이터는 **입력 단계 3개뿐**이고, 완료·알림 화면은 인디케이터 밖이다(`onboarding.md` 4 단계 구성). 단계 번호로 참조하면 인디케이터 구성이 바뀔 때마다 이 문서가 어긋난다.
- [나중에] 선택 시 OS 다이얼로그를 띄우지 않고 **곧바로 닫는다.** 이후 설정에서 켤 수 있다.
  - **되짚기 팝업은 두지 않는다**(폐지 2026-09-06). 되짚기는 전환율을 올리지만 **거절을 한 번 무르는 상호작용**이라 "닫으려는데 또 뜬다"는 인상이 남는다. 우리에게는 되돌릴 구조가 이미 있다 — [나중에]는 OS 다이얼로그를 띄우지 않아 권한이 **미결정**으로 남고, 아래 설정 유도 배너가 회수 경로를 맡는다.
- **여는 시점** — **온보딩 완료 → 착지 화면이 뜨고 400ms 뒤**다(2026-10-11 — 첫 사용 코치마크 제거, `changes/archive/remove-first-run-tutorial.md`. 종전에는 코치마크가 끝난 뒤 열었다). 곧바로 띄우면 화면 전환과 팝업이 겹쳐 읽힌다.
  - 온보딩 밖 진입(설정 유도 배너 등)도 같은 지연 규칙으로 연다. 게이트에 걸려 영영 못 뜨는 경로를 만들지 않는다.
- 권한 허용 시 즉시 device_token을 발급받아 서버에 등록한다.

**권한 요청을 건너뛰게 되는 경로가 하나 있다** (`onboarding.md` 4 [완료 대기])

- 모든 사용자는 완료 화면 전에 자동 드립 편성을 기다리는데(완료 대기 — 담기 단계 제거 2026-10-11 로 종전 "0건 담기" 경로가 유일한 경로다), 이 시점에는 **`onboarding_completed = true`가 이미 기록돼 있다.** 로딩 중에 앱을 강제 종료하면 재실행 시 스플래시가 라이브러리로 직행하고, **알림 사전 안내 화면을 영영 보지 못한다.**
  - `onboarding_completed`를 나중에 찍는 방법은 쓸 수 없다. 그러면 편성이 끝내 실패한 사용자가 온보딩에 갇힌다.
- **따라서 온보딩에서 사전 안내를 보지 못한 사용자에게 진입 경로를 하나 남긴다.** **(b)안 채택(합의 2026-08-06): 설정의 알림 섹션에 유도 배너를 상시 노출한다**(`settings.md` 4.3). OS 권한이 미결정인 동안 노출하고, 권한이 결정되면(허용·거부) 숨긴다. 배너 탭 → 사전 안내 → [알림 받기]에서 OS 다이얼로그.
  - (a)안(라이브러리 첫 진입 시 1회 노출)은 기각 — 첫 진입 화면에 일회성으로 끼어들면 놓치는 순간 경로가 다시 사라진다.
- **OS 다이얼로그를 대신 띄우는 방식은 쓰지 않는다.** 사전 안내 없이 바로 띄우면 거부율이 올라가고, 거부되면 앱에서 되돌릴 수 없다.

### 4.2 수신 설정 (앱 내 토글)

- 설정 화면의 토글 명칭(사용자 노출)은 **"이어 PICK 알림"** 이다(합의 2026-08-06 — "드립"은 내부 용어라 화면에 노출하지 않는다, `settings.md` 4.1).
- OS 권한과 앱 내 설정은 **분리**된 두 단계다.
  - OS 권한 없음 → 어떤 경우에도 발송하지 않는다
  - OS 권한 있음 + 앱 토글 OFF → 발송하지 않는다
  - OS 권한 있음 + 앱 토글 ON → 발송한다
- 앱 포그라운드 복귀 시마다 OS 권한 상태를 확인해 서버에 동기화한다(설정에서 권한을 끈 경우 발송 낭비 방지).

### 4.3 발송 규칙

| 규칙 | 내용 |
|---|---|
| 시점 | **편성은 05:00, 알림은 07:00 KST에 보낸다**(변경 2026-10-14 — 종전 "편성 완료 직후(05:00)"). 05:00 배치는 적립만 하고 알리지 않는다. 07:00에 **그날 배치가 적립한 편(정규 + 탐험)을 DB에서 다시 읽어** 사용자당 1건으로 보낸다 — 범위는 **그 그룹 실행 기록이 생긴 시각부터 배치 종료까지**라, 배치가 재개로 이어졌어도 앞 구간이 빠지지 않고 같은 날 먼저 돈 다른 그룹의 적립분은 섞이지 않는다. **07:00 전에 지운 편은 알리지 않는다**(소프트 삭제 제외 — 전부 지웠으면 알림 없음). 배치가 07:00까지 끝나지 않았으면(재시작 뒤 재개 등) 07:00 크론은 건너뛰고 **배치가 끝나는 즉시** 보낸다. **발송 그룹**(2026-10-14 — KAN-191, `global-api.md` 2.4): GLOBAL 사용자는 그룹 기준 시간대의 **현지 07:00에 그 그룹 실행이 적립한 것만** 받는다(KR = 07:00 KST). 서버 스위치 `DRIP_TIMEZONE_GROUPS_ENABLED`가 켜졌을 때만 그룹이 갈리고, 꺼져 있으면(기본) 전원 07:00 KST다(`drip-scheduling.md` 2). 첫 드립(온보딩 직후)은 종전처럼 도착 알림을 보내지 않는다 — 단 05:00~배치 종료 사이에 온보딩한 사용자의 첫 드립은 07:00 알림에 함께 실린다(드묾). **야간 발송 제한(방해금지)은 두지 않는다** |
| 빈도 | 하루 최대 1회. 정규 2편 + 탐험 1편이어도 알림은 **1건으로 묶는다** — 탐험 전용 알림을 따로 보내지 않는다 |
| 대상 | **전 티어**(무료 포함) + OS 권한 허용 + 앱 토글 ON |
| 문구 | "오늘의 콘텐츠 N편이 도착했어요" + 대표 콘텐츠 제목. **N = 그날 적립된 정규 + 탐험 편수**, N ≥ 1이면 보낸다(정규 0편 · 탐험 1편도 보낸다). 대표는 정규 첫 편, 정규가 0편이면 탐험 편. **GLOBAL 시장 사용자는 영어**(`global-api.md` 2.3 — 언어는 기기 언어가 아니라 `users.market`으로 고른다): 1편이면 `Your episode for today is here`, N ≥ 2면 `Your N episodes for today are here`. 본문(대표 콘텐츠 제목)은 콘텐츠 그대로 |
| 딥링크 | 1편이면 해당 콘텐츠 플레이어, 2편 이상이면 라이브러리 |
| **보관 시한** | Expo `ttl` = **그 그룹의 다음 편성 배치(기준 시간대 현지 05:00)까지**(신설 2026-09-26 · 그룹 기준으로 개정 2026-10-15 — 종전 "다음 05:00 KST까지"는 KR에만 맞아, 현지 07:00이 KST 21~22시인 americas 알림이 7~8시간 만에 만료됐다. asia·스위치 꺼짐은 종전과 같은 값). 07:00 발송이면 약 22시간, 늦게 보낸 알림은 그만큼 짧게. 하한 1시간. 다음 배치가 새 알림을 보내므로 그 뒤의 전달은 의미가 없다 — 꺼져 있던 기기에 지난 날짜의 "오늘"이 쌓이지 않는다. 종전에는 `ttl`이 없어 제공자 기본값(약 4주)으로 보관됐다 |
| **발송 요청 재시도** | 429·5xx(종전) + **연결이 성립하기 전의 네트워크 오류**(`ECONNREFUSED`·`ENOTFOUND`·`EAI_AGAIN`·`EHOSTUNREACH`·`ENETUNREACH`·연결 타임아웃, 추가 2026-09-26) — 요청이 나가지 않았으니 다시 보내도 중복이 없다. 1초·3초 두 번. **응답 타임아웃(10초)과 보낸 뒤 끊김(`ECONNRESET`)은 재시도하지 않는다** — Expo가 이미 접수했을 수 있어 다시 보내면 같은 알림이 두 번 간다 |

- **탐험 편을 알림에 포함한다**(결정 2026-09-17 — `changes/archive/push-expo-and-discovery-in-drip-alert.md`). 탐험 편도 "이어가 보내준 것"이고, 라이브러리 도착 배너가 이미 탐험 편을 카운트에 넣는다(`library.md` 4.6) — 알림과 배너가 같은 사건을 다른 숫자로 세지 않는다. 정규 직후에 보내면 탐험 편이 알림 뒤에 조용히 쌓여 취향 밖 콘텐츠의 노출 기회가 줄어든다.
- **발송 수단은 Expo Push다**(결정 2026-09-17). 서버가 사용자별로 대상을 판정해 Expo Push API로 보낸다 — FCM 토픽 같은 일괄 구독 발송은 쓰지 않는다(판정은 서버).
- **무료(라이트) 티어도 드립을 받으므로 알림 대상이다**(PRD FR-14). 티어로 발송 대상을 가르지 않는다.
- **방해금지 개념 자체를 폐기했다**(합의 2026-08-06). 종전의 "22:00~08:00 전역 방해금지"도, 사용자별 방해금지 설정도 두지 않는다 — 드립 도착은 순수 정보성 알림이므로 야간 제한 없이, **알림 수신에 동의한(OS 권한 + 앱 토글 ON) 사용자 전원에게 07:00 KST(그룹은 현지 07:00)에 발송한다**(2026-10-14 — 종전 "편성 직후").

### 4.4 알림 탭 처리

1. 알림 탭 → 앱 실행 → **스플래시 판정을 먼저 통과**(`splash.md` 4번)
2. 온보딩 미완료 사용자는 딥링크를 보류했다가 온보딩 완료 후 이동
3. 콘텐츠 딥링크인 경우 **한도 판정과 재생 확인 팝업 규칙(`paywall.md` 4.2)을 동일하게 거친다**(차단 시 페이월) — 딥링크 재생도 팝업 규칙의 예외가 아니다. 다만 **순서는 발급이 먼저다**(개정 2026-09-20, KAN-86 — `changes/archive/push-confirm-after-issue.md`): **발급(`audio-urls`) → (차감될 재생이면) 확인 팝업 → 재생 → 플레이어.** 푸시는 그 콘텐츠가 아직 있는지도, 오늘 들었는지도 모르는 채로 들어오므로, 팝업을 먼저 띄우면 없는 콘텐츠에 차감 동의를 받아 놓고 거절하는 순서가 된다. 발급은 차감하지 않아(`player-api.md` 4.1) 앞서도 "동의 없이 차감하지 않는다"를 어기지 않는다
   - 발급 시점의 한도 403이면 팝업 없이 페이월·한도 안내. **플레이어는 발급이 성공한 뒤에만 연다**
   - 팝업 여부의 힌트(`is_counted_today`)는 푸시에 실려 오지 않는다 — 발급 뒤 재생 목록(라이브러리 첫 페이지, `sort=queue`)에서 찾고, 못 찾으면 "아직 안 들었다"로 본다(팝업이 한 번 더 뜰 뿐, 차감 판정은 서버가 한다). 이미 재생 중인 같은 콘텐츠를 이어 듣는 경우는 묻지 않는다. 팝업에서 [취소]하면 받아 둔 세션을 내린다
4. 딥링크 대상 콘텐츠가 회수(403)·삭제(404)된 경우 **팝업 없이** 라이브러리로 폴백 + "콘텐츠를 찾을 수 없어요"

### 4.5 포그라운드 수신

- 앱이 포그라운드일 때는 OS 알림 배너를 띄우지 않고, **하단 라이브러리 탭의 새 콘텐츠 숫자 배지**로 대체한다(개정 2026-10-11).
- 어느 탭에서든 목록을 조용히 갱신하고, 필터 없는 목록의 새 편성 수로 배지를 갱신한다. 푸시의 편수를 다시 더하지 않는다. 라이브러리 탭을 누르면 확인 처리한다(`library.md` 4.6).
- **저녁 리텐션 알림(4.6)은 포그라운드면 아무것도 보여 주지 않는다**(2026-10-27 박준현 — KAN-273). OS 배너를 숨기고 앱 안 대체 표시(배지)도 없다 — 앱으로 다시 오게 하는 알림이라 이미 쓰는 사람에겐 필요 없고, 듣는 중의 "(광고)" 배너는 방해만 된다. 앱이 켜져 있는지는 기기만 알아서 앱이 거른다(서버는 그대로 보낸다). 숨긴 것은 `push_foreground_suppressed`로 남긴다(`analytics.md`).

### 4.6 저녁 리텐션 알림 *(신설 2026-10-26 — KAN-272)*

**다른 사용자와의 비교·자기 기록으로 퇴근길에 다시 듣게 만드는 두 번째 알림 종류다.** 드립 도착 알림(4.3)과 따로 센다.

- **광고성 정보로 취급한다**(결정 2026-10-26 박준현). 재방문을 권하는 문구라 광고성으로 판단될 여지가 크다(정보통신망법 50조 · KISA 불법스팸 방지 안내서 — 앱 푸시 허용은 광고 수신 동의가 아니다). 그래서 **마케팅 수신 동의자에게만** 보내고, 모든 문구에 광고 표시와 수신거부 방법을 붙인다. 수신 설정은 새 토글 없이 **설정의 "마케팅 수신 동의" 토글**이 맡는다(`settings.md` 4.1). 18:00은 광고성 앱 푸시의 야간 금지(21~08시) 밖이다.
- **규칙·문구·기준값은 서버 코드 한 곳에 둔다**(`backend/src/modules/retention-push/retention-push.rules.ts`). DB·어드민 편집은 두지 않는다 — 3인 팀이라 배포 없이 문구를 자주 바꿀 사람이 없고, 끄는 것은 서버 스위치로 충분하며, 문구 변수와 판정이 한 파일에 있어야 테스트가 어긋남을 잡는다. PM이 직접 자주 바꾸게 되면 그때 같은 표를 DB로 옮긴다.

| 시점 | 그룹 기준 시간대 **현지 18:00**(드립 발송 그룹과 같은 정의 — `DRIP_TIMEZONE_GROUPS_ENABLED`가 꺼져 있으면 전원 18:00 KST) |

## 7. 예외 상황

- **device_token 만료·무효**: Expo Push의 발송 결과는 **receipt를 나중에 조회해야** 알 수 있다. receipt가 `DeviceNotRegistered`면 토큰을 무효화(`device_tokens.invalidated_at`)하고 다음 앱 실행 시 재등록한다. Expo 푸시 토큰 형식이 아닌 값은 발송 전에 거른다.
- **여러 기기 로그인**: 활성 토큰 전부에 발송한다.
- **로그아웃**: 해당 기기 토큰을 무효화해 다른 사용자에게 알림이 가지 않게 한다.
- **탈퇴**: 모든 토큰 삭제. `notification_logs`도 함께 즉시 파기한다 — 보존할 법령 근거가 없고, 중복 발송 방지라는 목적이 탈퇴자에게는 성립하지 않는다(`domain.md` 12.3).
- **발송 전에 사용자가 이미 앱을 열어 콘텐츠를 확인한 경우**(재시도 등으로 발송이 늦어진 사이): 발송을 취소한다 — 이미 본 것을 알리지 않는다. **(미구현 2026-09-26 — 발송 구현 KAN-68 처리 기록 참조)**
- **드립 편성은 됐는데 콘텐츠가 곧바로 회수됨**: 발송 직전 유효성을 재확인한다. 남은 콘텐츠가 0이면 발송하지 않는다. **(미구현 2026-09-26 — 발송 구현 KAN-68 처리 기록 참조)**
- **같은 날 드립이 두 번 편성됨**(재시도 등): 하루 1회 캡으로 두 번째는 발송하지 않는다.
- **알림 권한은 있으나 사용자가 OS 설정에서 이 앱의 알림을 껐다**: 발송해도 표시되지 않는다. 포그라운드 복귀 시 권한 동기화로 대상에서 제외한다.
- **앱 미설치 상태로 오래 지난 토큰**: 30일 이상 발송 실패한 토큰은 정리한다. **(미구현 2026-09-26 — 발송 구현 KAN-68 처리 기록 참조)**
- **발송 요청 실패(네트워크)**: 4.3의 재시도(1초·3초) 뒤에도 실패하면 그 청크(메시지 최대 100건)의 사용자는 `failed`로 남고, **그날 재발송은 없다**(2026-09-26). 배치가 도중에 중단된 날만 재시작 시 재개가 다시 보낸다(`drip-scheduling.md` 7장).
- **발송 오류 사유 기록**: ticket·receipt 오류 중 `DeviceNotRegistered`가 아닌 것(`InvalidCredentials` 등)은 사유별 건수를 error 로그로 남긴다(2026-09-26) — Slack ERROR 감시가 받는다.

## 8. 완료 조건

- Given 알림 사전 안내 / When [나중에]를 누른다 / Then 추가 팝업 없이 곧바로 닫히고, OS 권한은 **미결정**으로 남는다
- Given 온보딩을 마치고 착지 화면이 뜬 직후다 / When 화면을 본다 / Then 알림 사전 안내가 아직 뜨지 않는다

- Given 2단계 저장 뒤 완료 대기(자동 드립 로딩) 중이다 / When 앱을 강제 종료하고 재실행한다 / Then 라이브러리로 진입하며 알림 사전 안내를 보지 못한 사용자로 남는다 — **설정 알림 섹션의 유도 행("새 콘텐츠 알림 받기")으로 재진입할 수 있다**((b)안, `settings.md` 4.3)
- Given 사전 안내를 보지 못했고 OS 권한이 미결정인 사용자 / When 설정에 진입한다 / Then 알림 섹션에 유도 배너가 노출되고, 탭하면 사전 안내가 뜬다

- Given 알림 권한을 허용한 사용자 / When 정규 2편과 탐험 1편이 편성된다 / Then 탐험 편성이 끝난 뒤 "오늘의 콘텐츠 3편이 도착했어요" 알림이 **1건만** 발송된다
- Given 정규 후보가 없어 탐험 1편만 편성된 사용자 / When 편성이 끝난다 / Then 탐험 편을 대표로 1편 알림이 발송되고 딥링크는 그 콘텐츠다

- Given 드립 1편이 도착해 콘텐츠 딥링크 알림을 받았다 / When 알림을 탭한다 / Then 해당 콘텐츠 플레이어가 열린다
- Given 무료 사용자가 콘텐츠 딥링크 알림을 탭했고 오늘 한도를 소진했다 / When 플레이어 진입을 시도한다 / Then 페이월이 노출된다
- Given 앱 내 알림 토글이 OFF다 / When 드립이 편성된다 / Then 푸시가 발송되지 않는다
- Given 알림 수신에 동의한 사용자에게 05:00 드립 편성이 완료된다 / When 발송 시점을 확인한다 / Then 05:00에는 발송되지 않고 07:00 KST에 그날 편성분을 다시 읽어 사용자당 1건 발송된다(2026-10-14)
- Given 배치가 07:00까지 끝나지 않았다 / When 배치가 끝난다 / Then 07:00 크론은 건너뛰었고 배치 종료 즉시 발송된다
- Given 07:00 전에 그날 편성분을 전부 지운 사용자 / When 07:00이 된다 / Then 알림이 발송되지 않는다
- Given `DRIP_TIMEZONE_GROUPS_ENABLED`가 켜져 있고 GLOBAL 사용자가 americas 그룹이다 / When 그 그룹 기준 시간대 현지 07:00이 된다 / Then 그 그룹 실행이 적립한 것만 알림이 가고, `ttl`은 그 그룹의 다음 편성 배치(현지 05:00)까지다(KAN-191)
- Given 앱이 포그라운드이고 편성 관측 기준값이 있다 / When 드립 알림 뒤 목록 재조회에 새 편성 2건이 있다 / Then OS·인앱 도착 배너 없이 라이브러리 탭 배지에 2가 표시된다
- Given 로그아웃한 기기 / When 이전 사용자에게 드립이 편성된다 / Then 해당 기기로 알림이 가지 않는다
