# 페이월 기능 명세서

> 연결 PRD: FR-29, FR-30 / 사용자흐름 5.4 / 검증계획 9.1
> `docs/prd/next_doing.md` 3장의 예시 명세를 정식 명세로 확장한 문서

## 1. 목적 & 연결

무료 사용자를 유료로 전환한다. 하루 2편 재생 한도를 소진한 뒤 재생을 시도하는 순간이 **핵심 전환 트리거**이며(진입 경로 전체는 2장 — 잔여 표시 탭 포함), 담기·탐색 등 다른 행동은 막지 않는다.

- PRD FR-29 (P0) 무료 사용자 재생 하루 2편 제한, 소진 후 재생 시도 시 페이월 노출
- PRD FR-30 (P0) 인앱 결제 완료 시 즉시 티어 반영 및 차단 지점 복귀
- PRD 사용자흐름 5.4
- PRD 9.1 정책 로직 단위 테스트 대상

## 2. 진입 조건

페이월 바텀시트는 **아래 두 경우에만** 노출된다.

1. **재생 한도 초과** — 한도가 있는 티어(`daily_play_limit != null`, 무료 포함)이면서 **최상위 티어가 아닌** 사용자가, 오늘 재생한 고유 콘텐츠 수가 `daily_play_limit` 이상인 상태에서 콘텐츠 재생을 시도할 때 (라이브러리·탐색·미니플레이어·푸시 진입 모두 동일)
2. **잔여 표시(0/M) 탭** — 소진 상태의 잔여 횟수 상시 표시를 탭했을 때 (5장, `library.md` 4.1-2, `explore.md` 4.4-1)

**재생 확인 팝업(4.2)과 혼동하지 않는다.** 페이월은 한도를 **소진했을 때**, 확인 팝업은 한도가 **남아 있을 때** 뜬다. 둘은 배타적이며 연달아 노출되지 않는다.

아래는 **트리거가 아니다**:
- 담기 (무제한 — PRD 5.4 명시)
- 탐색 피드 열람·검색
- 라이브러리 열람
- **드립 영역 접근** — 무료 티어도 드립을 받으므로(PRD FR-14) 잠금·페이월 대상이 아니다
- **최상위 티어** 사용자의 한도 초과 → 페이월이 아니라 "오늘 청취 한도를 모두 사용했어요" 안내만 띄운다(합의 2026-08-06 — 더 올라갈 티어가 없어 팔 것이 없다). **최상위가 아닌 한도 티어(무료 포함)는 페이월을 띄우되, 시트 안에 같은 한도 안내 문구를 포함한다**(4.1·5장)

## 3. 입력값

| 값 | 출처 | 필수 |
|---|---|---|
| user_id | 토큰 | 필수 |
| tier | 서버(`users.tier`) | 필수 |
| daily_play_count | 서버가 `play_records` 집계로 산출한 **파생값**(컬럼 아님) | 필수 |
| blocked_content_id | 재생 시도한 콘텐츠 | 필수 |
| entry_point | library / explore / miniplayer / push | 필수(전환 분석용) |
| plans | 서버가 내려주는 요금제 목록 + 스토어 상품 ID | 필수 |

## 4. 처리 로직

### 4.1 재생 가능 판정

재생 시도마다 **서버가 판정한다**(클라이언트 카운트는 UI 힌트일 뿐, 최종 판정 근거가 아니다 — 우회 방지).

```
limit = plans[user.tier].daily_play_limit     // null = 무제한

if limit == null                → ALLOW
if 재청취 창 내 콘텐츠(4.3-1)    → ALLOW  // 차감 없음 — 한도 소진 상태에서도 허용
if daily_play_count < limit     → ALLOW
if 최상위 티어                    → LIMIT_REACHED (한도 안내만, 페이월 없음)
else (무료 포함 한도 티어)         → BLOCKED (페이월 — 시트 안에 한도 안내 문구 포함)
```

- **한도 소진 처리는 티어의 위치로 가른다**(합의 2026-08-06). 최상위 티어를 제외한 한도 티어(무료 포함)는 페이월을 띄우되 시트 안에 **"오늘 청취 한도를 모두 사용했어요"** 안내 문구를 포함하고, 최상위 티어는 페이월 없이 같은 한도 안내 문구만 띄운다.

- 한도는 `plans.daily_play_limit`에서 읽는다. 티어명을 코드에 하드코딩하지 않는다.
- **라이트(무료) = 2편 확정.** 데일리·프로 값은 1~2주 시범 운영 후 결정하며, `plans` 행의 값만 바꾸면 되고 앱 배포가 필요 없다(PRD FR-29).

### 4.2 재생 확인 팝업 — 차감 고지

판정이 `ALLOW`여도 **바로 재생하지 않는다.** 차감이 일어나는 재생이면 그 사실을 먼저 알린다.

```
재생 시도
   ↓
4.1 판정
   ├─ BLOCKED         → 페이월 바텀시트 (팝업 없음)
   ├─ LIMIT_REACHED   → 한도 안내 (팝업 없음)
   └─ ALLOW
        ├─ 차감 발생
        │    ├─ 오늘 억제됨  → 팝업 없이 바로 플레이어
        │    └─ 억제 안 됨   → 재생 확인 팝업 → [재생하기] → 플레이어
        └─ 차감 없음  → 팝업 없이 바로 플레이어
```

**팝업을 띄우는 조건**

- **`limit != null`** — 한도가 있는 티어여야 한다. 무제한 티어는 남은 횟수라는 개념이 없어 알릴 내용이 없다.
- **재청취 창(4.3-1) 밖의 콘텐츠여야 한다** — 오늘 이미 카운트됐거나 최근 15일 내 차감 이력이 있는 콘텐츠를 다시 트는 것은 차감이 없다.
- **오늘 억제되지 않았어야 한다**(아래 [오늘은 그만 보기]).
- 세 조건을 모두 만족할 때만 노출한다. 원칙은 **"차감되지 않는데 차감된다고 알리지 않는다"** 이다 — 사실과 다른 고지는 재생을 망설이게 만들고, 한도가 실제보다 빨리 닳는다고 오해하게 한다.

**팝업 내용**

- 남은 횟수와 1회 차감 사실을 함께 알린다: "오늘 N회 남았어요. 재생하면 1회가 차감돼요."
- 버튼은 [취소] / [재생하기]. **[재생하기]를 눌러야 플레이어가 열린다.**
- 하단에 **[오늘은 그만 보기] 텍스트 버튼**을 둔다. 세 버튼을 같은 크기로 나란히 세우지 않는다 — 주 동작은 여전히 재생과 취소이고, 같은 무게로 두면 잘못 눌러 하루치 고지를 끄게 된다.
- [취소]는 원래 화면에 머문다. **카운트는 늘지 않는다** — 재생이 시작되지 않았기 때문이다(4.3).

**[오늘은 그만 보기] — 고지 억제**

- **누르면 팝업을 닫고 그대로 재생한다.** 재생하지 않고 닫히면 [취소]와 구분되지 않고, 사용자는 다시 탭해야 하는데 그때는 팝업이 없어 방금 무엇이 바뀐 건지 알 수 없다.
  - 누르는 맥락은 "알겠으니 그냥 틀어달라"이다. **차감 고지가 눈앞에 떠 있는 상태에서 누르는 것이므로 고지 없이 차감되는 경우는 생기지 않는다.**
- **억제 대상은 이 팝업 하나뿐이다.** 페이월·한도 안내·회수 안내는 억제되지 않으며, **차감은 그대로 일어난다.**
  - **억제한 것은 고지이지 판정이 아니다.** `BLOCKED` · `LIMIT_REACHED`는 이 설정과 무관하게 그대로 동작한다. 클라이언트의 표시 설정이 4.1의 판정을 건드리지 못한다.
- **유효 기간은 오늘의 서비스 날짜까지다** — 자정이 아니라 **04:00 (Asia/Seoul)** 에 풀린다(4.4).
  - 한도 리셋과 **같은 경계를 써야 한다.** 경계가 다르면 "한도는 이미 리셋됐는데 고지는 계속 억제된" 구간이 매일 생긴다.
  - 저장하는 값은 만료 타이머가 아니라 **억제한 서비스 날짜 자체**다. 서버가 내려준 서비스 날짜와 다르면 억제가 풀린 것으로 본다 — 기기 시각을 신뢰하지 않기 위해서다(4.4).
- **기기 로컬에 저장한다. 서버에 저장하지 않는다.**
  - 팝업은 판정이 아니라 표시 UI이므로 서버 상태로 만들 이유가 없다. 서버에 두면 **파생값도 아닌 새 컬럼**이 하나 생기고, 그 컬럼과 실제 판정이 어긋날 여지가 다시 생긴다(`domain.md` 1.4와 같은 종류의 문제다).
  - 기기를 바꾸면 다시 뜬다. **의도된 동작이다** — 처음 쓰는 기기에서는 차감 고지를 한 번은 봐야 한다.
- **억제는 그 기기의 모든 진입점에 적용된다** — 라이브러리·탐색·미니플레이어·푸시 어디서 눌렀든 같다. 같은 날 화면마다 다시 묻는다면 억제할 이유가 없다.
- **별도의 해제 수단은 두지 않는다.** 최대 하루짜리 상태를 설정 화면 항목으로 남기면, 하루면 사라질 것을 사용자가 계속 관리하게 된다.

**판정과 팝업의 관계**

- **팝업은 판정이 아니다.** 표시용 남은 횟수는 서버가 내려준 값이지만, 실제 허용 여부는 [재생하기]를 누른 시점에 **서버가 다시 판정한다.**
  - 팝업이 떠 있는 사이에 다른 기기에서 재생해 한도가 소진될 수 있다. **팝업에 표시된 숫자를 믿고 재생을 통과시키면 한도가 새는 구멍이 된다.**
  - 재판정 결과가 `BLOCKED`면 플레이어 대신 페이월로 전환한다.
- **한도를 이미 소진한 경우 팝업을 띄우지 않는다.** "0회 남았어요" 팝업과 페이월을 연달아 보여줄 이유가 없다. 곧바로 페이월이다.
- 진입점(라이브러리·탐색·미니플레이어·푸시)에 따라 규칙이 달라지지 않는다. **차감이 일어나는 재생이면 어디서 시작하든 팝업을 거친다.**
- 팝업을 띄우는 주체는 **재생을 시작시킨 화면**이다(예: `library.md` 4.3). 플레이어는 팝업을 통과한 요청만 받는다.

### 4.3 카운트 시점 — **재생 시작 시점**

> `next_doing.md`가 지목한 결정 포인트. 아래로 확정한다.

- 카운트는 **재생이 실제로 시작된 시점**에 +1 한다(재생 버튼 탭 시점이 아니라, 오디오 재생이 개시된 시점).
  - 이유: 버튼 탭 후 로드 실패·즉시 취소한 경우까지 차감하면 사용자가 손해를 본다.
- **같은 콘텐츠를 같은 날 다시 재생하면 카운트하지 않는다.** 카운트 단위는 "재생 횟수"가 아니라 **"오늘 재생한 고유 콘텐츠 수"** 다.
  - 이유: 이어듣기·되감기가 한도를 갉아먹으면 정상 사용이 불가능해진다.
  - 구현은 `play_records`의 `(user_id, content_id, play_date)` **유니크 제약이 보장한다.** 같은 날 같은 콘텐츠를 다시 재생해도 행이 늘지 않으므로 애플리케이션이 중복을 신경 쓸 필요가 없다
  - 즉 `daily_play_count = COUNT(*) FROM play_records WHERE user_id = ? AND play_date = <오늘의 서비스 날짜>`
- 재생 시작 후 3초 이내에 중단해도 카운트는 유지한다(어뷰징 방지).

### 4.3-1 재청취 창 — 차감일로부터 15일 (확정 2026-08-10)

한 번 차감이 발생한 콘텐츠는 **이미 한도 1회를 지불한 콘텐츠**다. 그 소비를 날짜가 바뀌었다고 다시 청구하지 않는다.

- **차감이 발생한 서비스 날짜로부터 15일간(당일 포함), 그 콘텐츠의 재청취는 차감도 차단도 없다.** 4.1 판정에서 한도 검사보다 먼저 `ALLOW`가 되므로, **한도를 소진한 상태에서도 재청취는 허용된다.**
- 차감이 없으므로 **재생 확인 팝업(4.2)도 뜨지 않는다** — "차감되지 않는데 차감된다고 알리지 않는다"는 원칙 그대로다.
- **창이 지난 뒤의 재청취는 새 차감이다.** 그 시점의 한도 판정을 그대로 거치고, 새 차감이 발생하면 그 날짜부터 15일 창이 다시 열린다.
- **기준은 차감 발생이지 완청이 아니다.** 완청 여부·라이브러리 보유 여부와 무관하게 차감 이력(`play_records`)만 본다. `library.md` 4.4가 완료 아이템을 목록에 유지하는 전제(재청취 지표 수집 — PRD 10)와 정합한다.
- 4.3의 "같은 날 재청취 무료"는 이 창의 특수한 경우가 된다.
- **판정은 서버 소유다**(4.1). 서버가 차감 이력으로 판정하며 클라이언트는 표시만 한다.
- **파급(계약·스키마)**: 차감 행 구분은 `domain.md` 6.3에 반영됐다(`play_records.is_counted` — 2026-08-10). 목록 응답의 차감 힌트(`library-api.md` 4.1 `is_counted_today`)가 "창 내 여부"를 표현하도록 하는 계약 개정만 남았다 — spec 최신화 단계에서 백엔드 협의와 함께(`changes/archive/paywall-completed-replay-limit(fe).md` 처리 기록 참조).

### 4.4 카운트 초기화 — 04시 기준

- 매일 **04:00 (Asia/Seoul)** 에 초기화된다(PRD 9.1).
- 배치로 리셋하지 않고, **판정 시점에 "오늘의 서비스 날짜"를 계산**하는 방식으로 구현한다.
  - `서비스 날짜 = 현재 시각이 04:00 이전이면 어제, 이후면 오늘` → `play_records.play_date`에 저장되는 값과 같다
  - `users`에 `daily_play_count`·`count_reset_at` 컬럼을 두지 않는다. 컬럼과 집계가 어긋나면 어느 쪽이 맞는지 판단할 수 없어진다
  - 이렇게 하면 배치 지연·시간대 이슈가 판정에 영향을 주지 않는다.
  - **경계 계산 함수는 한 곳에만 두고 전 모듈이 그것만 호출한다.** `content_stats` 집계가 다른 경계를 쓰면 페이월 카운트와 통계가 영구히 어긋난다.
- 기준 시간대는 **서버의 Asia/Seoul 고정**이다. 기기 시각·기기 시간대를 신뢰하지 않는다.

### 4.5 페이월 노출 → 결제 → 복귀

1. 재생 차단 판정 → 페이월 바텀시트 노출. **플레이어를 열지 않는다**
2. 시트에 제한 안내 + 3티어 비교 + 각 요금제 결제 버튼
3. 결제 버튼 탭 → **인증된 이메일 확인(FR-39)** — 인증된 이메일이 없으면 이메일 등록·인증 화면(`auth.md` 4.4)을 먼저 완료해야 결제가 시작된다. 인증 완료 후 이 흐름으로 복귀한다 → 스토어 인앱 결제 플로우(구독 명세 4.2 참조)
4. 결제 성공 → 서버 영수증 검증 → `tier` 갱신
5. 시트 자동 닫힘 → **`blocked_content_id`를 자동 재생**한다 (PRD 5.4 "막혔던 지점으로 복귀해 이어 진행")
   - 재생 위치는 저장된 `playback_progresses.position_sec`을 따른다
6. [닫기] 탭 → 원래 화면으로 복귀. 재생은 시작되지 않는다. `blocked_content_id`는 폐기

### 4.6 노출 빈도

- 재생 시도마다 노출한다(빈도 제한 없음). 한도 초과 상태에서 재생을 시도한 것 자체가 명확한 의도이므로.
- 단 같은 세션에서 [닫기] 후 **3초 이내 재시도**는 중복 노출로 보고 무시한다(연타 방지).
- **[오늘은 그만 보기]는 페이월에 적용되지 않는다.** 억제 대상은 재생 확인 팝업 하나뿐이다(4.2) — 결제 유도 화면을 사용자가 하루치로 끌 수 있게 만들지 않는다.

## 5. 화면 상태

| 조건 | 동작 |
|---|---|
| 무료 · count < 2 · 오늘 처음 트는 콘텐츠 · 억제 안 됨 | **재생 확인 팝업** "오늘 N회 남았어요. 재생하면 1회가 차감돼요." + [취소] / [재생하기] + **[오늘은 그만 보기]** |
| 무료 · count < 2 · 오늘 처음 트는 콘텐츠 · **오늘 억제됨** | 팝업 없이 즉시 재생. **차감은 그대로 일어난다** |
| 무료 · **재청취 창 내** 콘텐츠(오늘 이미 튼 것 포함) | 팝업 없이 즉시 재생(차감 없음 — 4.3-1). **한도 소진 상태여도 재생된다** |
| 무제한 티어 | 팝업 없이 즉시 재생 |
| 재생 확인 팝업에서 [취소] | 재생되지 않고 원래 화면 유지. 카운트 변화 없음 |
| 재생 확인 팝업에서 **[오늘은 그만 보기]** | 팝업을 닫고 **그대로 재생**. 오늘의 서비스 날짜 동안 이 팝업만 억제(4.2) |
| 재생 확인 팝업 → [재생하기] 시 재판정 결과 BLOCKED | 팝업을 닫고 **페이월 바텀시트**로 전환 |
| **한도가 있는 티어 (`limit != null`)** | 라이브러리 **앱바 우측**·탐색 **검색창 줄 우측**에 잔여 횟수 상시 표시("오늘 재생 N/M 남음"). 카드가 아니라 **화면당 한 곳**이다 |
| **무제한 티어 (`limit == null`)** | **잔여 횟수를 표시하지 않는다.** "무제한" 배지도 두지 않는다 |
| 무료 · count == 2 (소진) | 같은 자리에 **"오늘 재생 0/2 남음"** 을 주의색으로 유지한다. 숨기지 않으며, 탭하면 **페이월 바텀시트**를 연다 |
| 무료 · count >= 2 · 재생 시도 | **페이월 바텀시트** — 제한 안내 + 3티어 비교표 + 결제 버튼 + [닫기]. **확인 팝업은 뜨지 않는다** |
| 요금제 로딩 중 | 시트 내 스켈레톤 |
| 요금제 조회 실패 | 시트 내 "요금제를 불러올 수 없어요" + [다시 시도] |
| 결제 진행 중 | 전체 버튼 비활성 + 로딩. 시트 닫기 차단 |
| 결제 성공 | 시트 닫힘 → 성공 토스트 → 차단됐던 콘텐츠 자동 재생 |
| 결제 취소 | 시트 유지, 로딩 해제, 에러 문구 없음 |
| 결제 실패 | 시트 유지 + 인라인 에러 + [다시 시도] |
| 영수증 검증 지연 | "구독을 확인하고 있어요" 상태 유지(최대 30초) → 초과 시 "잠시 후 자동 반영됩니다" 안내 후 시트 닫기 |
| [닫기] | 원래 화면 복귀, 재생 시작 안 됨 |

**바텀시트 구성**: 제한 안내 헤드라인(**"오늘 청취 한도를 모두 사용했어요"** 문구 포함 — 4.1) / 3티어 비교(가격·일 청취 편수·드립 편수·광고) / 티어별 [구독하기] / 복원 링크 / 약관·해지 안내 / [닫기]

- 오프라인 저장은 P1 이연이므로 비교표에 넣지 않는다(FR-26).

**잔여 횟수 상시 표시**

- **탭하기 전에 남은 횟수를 알 수 있어야 한다.** 재생 확인 팝업은 탭한 뒤에야 뜨고, [오늘은 그만 보기]로 억제할 수도 있으므로 팝업만으로는 고지가 성립하지 않는다.
- **카드가 아니라 화면당 한 곳**이다. 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다 — 카드마다 같은 숫자를 반복하면 콘텐츠별 제한처럼 읽히고, 한 편을 재생할 때마다 화면의 숫자가 전부 동시에 바뀐다.
- 문구는 **한 문자열만 쓴다** — `"오늘 재생 N/M 남음"`(N = 남은 횟수, M = `plans.daily_play_limit`). **`M`을 2로 하드코딩하지 않는다.** 유료 티어에 한도가 생기면 그대로 깨진다.
- **이 숫자는 판정이 아니라 힌트다.** 허용 여부는 탭한 시점에 서버가 다시 판정한다(4.1·4.2). 표시된 숫자를 근거로 재생을 통과시키면 한도가 새는 구멍이 된다.
- **클라이언트가 임의로 1을 빼지 않는다.** 차감은 재생이 실제로 시작된 시점에만 일어나므로(4.3), 버튼을 누른 것만으로 숫자를 줄이면 오디오 로드에 실패했을 때 실제보다 적게 표시된다.

**신선도 — 여러 시점의 응답 중 어느 값을 믿는가**

"조회할 때마다 서버 값으로 덮어쓴다"만으로는 부족하다. **클라이언트에는 여러 시점의 응답이 섞여 도착한다** — 탭·필터 조합별 캐시가 재조회 완료 전에 먼저 렌더되고, 먼저 보낸 요청이 늦게 도착하기도 한다. 규칙이 없으면 구현이 "마지막에 도착한 값"을 그대로 쓰게 되고, **재생 직후 화면을 옮기면 차감 전 숫자가 잠시 역행한다.**

보관 중인 값과 새로 받은 값을 아래 순서로 비교한다.

| # | 조건 | 처리 |
|---|---|---|
| 1 | `service_date`가 다르다 | **무조건 새 값으로 덮어쓴다** — 04:00 경계를 넘었다 |
| 2 | `daily_play_limit`이 다르다 | **새 값으로 덮어쓴다** — 티어가 바뀌었다(결제·만료) |
| 3 | 날짜·한도가 같다 | `daily_play_count`가 보관값 **이상일 때만** 덮어쓴다. 작으면 **차감 전의 낡은 응답이므로 버린다** |

- **3번의 근거는 스키마 성질이다.** 같은 서비스 날짜 안에서 `daily_play_count`는 **단조 증가**한다 — `play_records`는 추가만 되고, 라이브러리에서 삭제해도 재생 이력은 남는다(`library.md` 4.5 · `domain.md` 6.3). 여러 기기에서 재생해도 늘기만 한다. 줄어드는 유일한 경우가 04:00인데 그때는 `service_date` 자체가 바뀌어 1번이 받는다.
- **기기 시각·응답 도착 시각을 판정에 쓰지 않는다.** 시각 기반 비교는 시계 조작과 응답 순서 역전에 깨진다. 이 규칙은 판정에 기기 시각을 쓰지 않는다는 원칙과도 정합한다(4.4).
- **한도가 있는 티어에만 적용한다.** 무제한 티어는 `daily_play_limit` · `daily_play_count`가 모두 `null`이라 3번의 비교가 성립하지 않으며, 애초에 표시하지 않는 상태다.
- **재조회 중 로딩·숨김 처리를 하지 않는 규칙은 그대로다.** 이 규칙 덕분에 재조회 중 유지되는 값이 곧 "알고 있는 가장 최신 값"이 된다.

- 화면별 배치는 각 명세가 소유한다 — 라이브러리는 앱바 우측(`library.md` 4.1-2), 탐색은 앱바가 없으므로 별도 배치(`explore.md` 4.4-1). **규칙은 이 문서가, 자리는 각 화면이 정한다.** 위 신선도 규칙도 규칙이므로 두 화면에 그대로 적용된다.

## 7. 예외 상황

- **04시 리셋 경계에 걸친 재생**: 판정 시점의 서비스 날짜(04시 경계)로 계산하므로(4.4), 03:59에 차단됐다가 04:00에 재시도하면 재생된다. 03:59에 재생을 시작해 04:30까지 듣는 경우는 이미 시작된 재생이므로 중단하지 않는다.
- **결제 중 앱을 백그라운드로 보냈다가 복귀**: 스토어 결제는 앱 밖에서 완결된다. 복귀 시 미처리 트랜잭션을 조회해 검증하고, 성공이면 시트를 닫고 티어를 반영한다. `blocked_content_id`는 세션 메모리가 아니라 **로컬에 저장**해 복귀 후에도 자동 재생이 가능하게 한다.
- **결제 버튼 빠르게 두 번 탭**: 첫 탭 즉시 버튼 비활성 + 인플라이트 플래그. 스토어 SDK도 중복 구매를 거부하지만 클라이언트에서 1차 차단한다.
- **결제는 성공했는데 서버 검증 API가 실패**: 티어를 무료로 두지 않는다. 영수증을 로컬 큐에 보관하고 재시도한다. 사용자에게는 "결제는 완료되었고 반영 중"으로 안내한다.
- **클라이언트 카운트와 서버 카운트 불일치**: 항상 서버 판정을 따른다. 클라이언트는 재생 시도 응답으로 카운트를 갱신한다.
- **기기 시각을 앞뒤로 조작**: 서버 시각 기준이라 영향 없다.
- **오프라인 상태에서 저장분 재생**(무료 사용자는 해당 없음): 유료 전용 기능이므로 무료 티어 판정과 무관.
- **한도 소진 상태에서 이미 듣던 콘텐츠 이어듣기**: 재청취 창(4.3-1) 내 콘텐츠라면 재생 허용. 창 밖 콘텐츠(15일이 지났거나 차감 이력이 없는 것)라면 차단. **확인 팝업도 뜨지 않는다**(차감이 없으므로).
- **재생 확인 팝업이 떠 있는 사이 다른 기기에서 한도를 소진**: [재생하기] 시점의 서버 재판정이 최종이다. 팝업을 닫고 페이월로 전환한다.
- **재생 확인 팝업에서 [취소] 후 곧바로 다시 탭**: 카운트가 늘지 않았으므로 같은 팝업이 다시 뜬다. [취소]는 억제가 아니다 — 억제는 [오늘은 그만 보기]로만 걸린다(4.2).
- **[오늘은 그만 보기]로 억제한 뒤 두 번째 재생**: 팝업 없이 재생되고 **차감은 그대로 일어난다.** 무료 티어는 하루 2편이므로, 첫 재생에서 억제하면 두 번째 재생은 팝업 고지 없이 차감된다. **이 경우의 고지는 화면에 상시 노출된 잔여 횟수(5장)가 맡는다** — 억제 버튼과 상시 표시는 한 쌍으로 설계된 것이며, 상시 표시가 빠지면 고지 수단이 아예 없어진다.
- **억제 중에 한도를 소진**: 억제와 무관하게 **페이월이 뜬다.** 억제 대상은 재생 확인 팝업 하나뿐이다(4.2·4.6).
- **억제한 채로 04시를 넘김**: 억제가 풀린다. 한도 리셋과 같은 경계를 쓰므로 "한도는 리셋됐는데 고지는 억제된" 구간이 생기지 않는다(4.4).
- **억제한 뒤 다른 기기에서 재생**: 그 기기에서는 팝업이 뜬다. 억제는 기기 로컬 상태다(4.2). 처음 쓰는 기기에서 차감 고지를 한 번 보는 것은 의도된 동작이다.
- **앱 재설치 후 재생**: 억제가 사라져 팝업이 다시 뜬다. 로컬 상태이므로 복원하지 않는다.
- **잔여 횟수 표시와 서버 판정이 어긋남**: 서버 판정이 최종이다(4.1). 표시값은 마지막 목록 조회 시점의 값이라 다른 기기의 재생이 반영되지 않았을 수 있다.
- **앱을 켜 둔 채 04시를 넘김**: 표시된 숫자는 다음 목록 재조회 때 갱신된다. **클라이언트가 시계를 보고 스스로 되돌리지 않는다** — 기기 시각으로 리셋을 판단하면 시각 조작만으로 한도가 초기화된 것처럼 보인다.
- **팝업의 [재생하기]를 눌렀으나 오디오 로드에 실패**: 재생이 시작되지 않았으므로 카운트하지 않는다(4.3). 팝업에서 차감을 고지했더라도 실제 차감은 재생 시작 시점에만 일어난다.
- **재생 확인 팝업 노출 중 앱 종료**: 아무 것도 기록하지 않는다. 재진입 시 다시 팝업부터 시작한다.
- **탈퇴 후 재가입으로 한도 초기화**: 어뷰징 가능. → 미결 사항.
- **결제 완료 직후 차단됐던 콘텐츠가 회수된 경우**: 자동 재생 대신 "제공이 종료된 콘텐츠예요" 안내 후 원래 화면 복귀.

## 8. 완료 조건

- Given 무료 사용자가 오늘 1편을 재생했다 / When 새 콘텐츠 재생을 시도한다 / Then **"오늘 1회 남았어요. 재생하면 1회가 차감돼요" 확인 팝업**이 뜨고, [재생하기]를 눌러야 재생된다
- Given 재생 확인 팝업이 떠 있다 / When [취소]를 누른다 / Then 재생되지 않고 카운트도 늘지 않는다
- Given 무료 사용자가 오늘 이미 재생한 콘텐츠 / When 다시 재생을 시도한다 / Then 확인 팝업 없이 즉시 재생된다
- Given 무료 사용자가 10일 전 재생(차감)한 콘텐츠가 있고 오늘 한도를 모두 소진했다 / When 그 콘텐츠를 다시 재생한다 / Then 페이월 없이 재생되고 카운트도 늘지 않는다
- Given 무료 사용자가 16일 전 차감된 콘텐츠를 재생한다 / When 한도 판정을 거친다 / Then 새 차감으로 판정된다(한도가 남았으면 확인 팝업, 소진했으면 페이월)
- Given 무제한 티어 사용자 / When 재생을 시도한다 / Then 확인 팝업 없이 즉시 재생된다
- Given 재생 확인 팝업이 떠 있는 사이 다른 기기에서 한도가 소진됐다 / When [재생하기]를 누른다 / Then 서버 재판정으로 페이월이 노출되고 재생은 시작되지 않는다
- Given 확인 팝업에서 [재생하기]를 눌렀으나 오디오 로드에 실패했다 / When 카운트를 확인한다 / Then 차감되지 않았다
- Given 무료 사용자가 오늘 2편을 재생 완료했다 / When 3번째 콘텐츠 재생을 시도한다 / Then **확인 팝업 없이 페이월이 바로** 뜨고 재생은 시작되지 않는다
- Given 페이월이 뜬 상태 / When 결제를 완료한다 / Then 티어가 즉시 바뀌고 원래 시도했던 콘텐츠가 자동 재생된다
- Given 무료 사용자가 오늘 이미 2편을 재생했다 / When 콘텐츠를 담기만 한다 / Then 페이월 없이 정상적으로 담긴다
- Given 무료 사용자가 오늘 1편만 재생했다 / When 그 콘텐츠를 다시 재생한다 / Then 카운트가 늘지 않고 여전히 1편으로 집계된다
- Given 무료 사용자가 03:59에 한도를 소진했다 / When 04:01에 재생을 시도한다 / Then 카운트가 초기화되어 재생된다
- Given 페이월에서 결제 중 앱을 백그라운드로 보냈다 / When 결제를 완료하고 앱으로 복귀한다 / Then 티어가 반영되고 차단됐던 콘텐츠가 자동 재생된다
- Given 페이월이 떠 있다 / When [닫기]를 누른다 / Then 원래 화면으로 돌아가고 재생은 시작되지 않는다
- Given 무료 사용자 / When 라이브러리의 드립 영역을 탭한다 / Then 페이월 없이 드립 콘텐츠가 정상 노출된다(무료도 드립 대상)
- Given 무제한 티어(`daily_play_limit == null`) 사용자 / When 하루에 20편을 재생한다 / Then 페이월이 한 번도 노출되지 않는다
- Given 결제 버튼을 빠르게 두 번 탭한다 / When 결제가 진행된다 / Then 결제 요청은 1건만 발생한다
- Given 무료 사용자가 라이브러리·탐색을 연다 / When 화면 상단을 본다 / Then **"오늘 재생 N/M 남음"** 이 화면당 한 곳에 노출되고, 카드에는 표시되지 않는다
- Given 무제한 티어 사용자 / When 라이브러리·탐색을 연다 / Then **잔여 횟수도 "무제한" 배지도 노출되지 않는다**
- Given 무료 사용자가 오늘 2편을 재생했다 / When 라이브러리를 연다 / Then **"오늘 재생 0/2 남음"** 이 주의색으로 유지되고, 탭하면 페이월 바텀시트가 열린다
- Given 재생 확인 팝업이 떠 있다 / When [오늘은 그만 보기]를 누른다 / Then **그대로 재생되고 1회가 차감되며**, 같은 날 다시 재생해도 팝업이 뜨지 않는다
- Given [오늘은 그만 보기]로 억제한 사용자가 한도를 소진했다 / When 재생을 시도한다 / Then **페이월이 정상적으로 노출된다** — 억제는 팝업에만 적용된다
- Given [오늘은 그만 보기]로 억제한 상태에서 04시를 넘겼다 / When 재생을 시도한다 / Then 억제가 풀려 확인 팝업이 다시 노출된다
- Given 한 기기에서 [오늘은 그만 보기]를 눌렀다 / When 다른 기기에서 재생을 시도한다 / Then 그 기기에서는 확인 팝업이 노출된다

## 미결 사항

- ~~티어 명칭 불일치~~ → **확정: 라이트 / 데일리 / 프로. 라이트가 무료 티어다.**
- ~~재생 전 차감 고지~~ → **확정: 재생 확인 팝업(4.2).** 차감이 발생하는 재생에만 노출하고, 한도 소진 시에는 페이월이 대신한다.
- ~~확인 팝업의 마찰~~ → **확정: [오늘은 그만 보기](4.2).** 팝업 하단 텍스트 버튼으로 두고, 누르면 재생하면서 오늘의 서비스 날짜 동안 이 팝업만 억제한다. 기기 로컬 상태이며 판정·페이월에는 영향을 주지 않는다.
- ~~잔여 횟수 힌트의 노출 조건~~ → **확정: 한도가 있는 티어에 상시 표시(5장).** 소진 시에만 띄우지 않고, 카드가 아니라 화면당 한 곳에 둔다.
- ~~완청 콘텐츠 재청취의 한도 적용~~ → **확정(2026-08-10): 차감일로부터 15일 재청취 창(4.3-1).** 기준은 완청이 아니라 차감 발생이다. 계약·스키마 파급은 4.3-1 참조 (`changes/archive/paywall-completed-replay-limit(fe).md`)
- **무료 티어에서 확인 팝업을 유지할지 재검토** — 억제 버튼과 상시 표시가 함께 들어오면서 팝업의 역할이 상당 부분 겹쳤다. 무료는 하루 2편이라 억제 없이도 마찰이 최대 2회였고, 첫 재생에서 억제하면 팝업은 **사용자당 사실상 한 번만** 뜬다. 잔여 횟수가 상시 노출되는 지금은 **무료 티어에서 팝업 자체를 빼고 유료 한도 티어에만 두는 쪽**이 더 단순할 수 있다. 유료 티어 한도 값이 정해질 때 함께 판단한다.
- 데일리·프로의 일 청취 편수·가격은 1~2주 시범 운영 후 결정(PRD 4.1) — `plans` 행의 값만 바꾸면 되므로 코드 변경·마이그레이션이 필요 없다
- 무료 티어 광고(PRD 4.1 "광고 제공")의 형태·삽입 지점 미정 — 오디오 프리롤인지 배너인지에 따라 플레이어 명세 개정 필요
- 탈퇴·재가입을 통한 한도 우회 방지책 필요 여부
