# 콘텐츠 후기 · 후기 참여 프로모션 기능 명세서

> 연결 PRD: **FR-49**(P1 — 제안, PM 확인 대기) / 관련 FR-41(추천 별점) · FR-28(티어) · FR-10(QA)
> 기획 티켓: KAN-278(`tickets/ai/pending/content-rating-feedback-planning.md`) · 후속 KAN-279(BE) · KAN-280(FE)
> 상태: **담당 확정 2026-10-28 · PM 검토 대기**
> 통신 계약: `spec/api/content-review-api.md`(2026-10-28 — KAN-279) · 화면: `spec/uiux/`(미작성) · 스키마: `backend/domain.md` 3.5 · 6.8 · 8.5 · 8.6 · 8.7
> 짝 문서: `drip-feedback.md`(추천 별점 — 알고리즘 평가). 이 문서는 **편 자체**의 평가다.

## 1. 목적 & 연결

**모든 편에 별점과 글 후기를 받는다. 조건을 채우면 Pro 7일 프로모션을 한 번 준다.** 사용자 피드백을 직접 받는 통로다(10월 5주차 계획, 2026-10-26).

- 지금 있는 편 단위 신호는 행동(완청·담기·삭제)뿐이다. 추천 별점(FR-41)은 "알고리즘이 잘 골랐나"를 잰다. **"이 편이 왜 좋았나·왜 별로였나"를 알 길이 없다.**
- 쓰임은 둘이다.
  1. **파이프라인 품질 루프의 실사용자 신호** — 편별 평균·글을 사람이 읽고 저평점 편의 원인을 찾아 규칙 개정 후보로 삼는다(4.7).
  2. **전환 계기** — 보상으로 Pro(무제한 재생·무손실 음질)를 써 보게 한다.
- **하지 않는 것**
  - 평균 별점·다른 사람의 후기를 사용자에게 공개하지 않는다 — 표본이 작고, 공개하면 저평점 편의 노출이 줄어든다.
  - 후기를 추천 입력에 쓰지 않는다(4.8).
  - 스토어 평점·리뷰 요청과 엮지 않는다 — 보상을 스토어 평가와 엮으면 두 스토어의 보상성 리뷰 금지에 걸릴 소지가 있다.
  - Pro 구독자의 결제일을 연장하지 않는다 — 프로모션을 보관했다가 구독이 끝난 뒤 쓴다(결정 2026-10-28).
  - 보상은 반복하지 않는다 — **계정당 전체 1회**(결정 2026-10-28).

## 2. 진입 조건

### 2.1 후기 쓰기

- **상시 진입점**: 라이브러리(L4)·탐색(E12)·플레이어(PL7) 더보기 시트의 [상세 정보] 아래 **[후기]**, 콘텐츠 상세의 **"내 후기"** 줄.
- 후기 시트를 열 때 서버에 **쓸 수 있는 편인지 · 내 후기 · 발급까지의 진행**을 묻는다. 쓸 수 없는 편이면 시트 대신 안내를 띄운다(5장).
- **먼저 묻는 시트**: 라이브러리 진입 시 서버의 `show`가 true일 때만 띄운다(4.3).
- **플레이어 화면과 완청 순간에는 묻지 않는다.** `spec/uiux/player-uiux.md` 4장의 "90% 도달 시점·완료 상태에 화면이 개입하지 않는다"를 그대로 지킨다. 통근 중에는 화면을 보지 않고 듣는 경우가 대부분이라 끝나는 순간에 띄워도 보이지 않는다.
- 후기 기능 스위치가 꺼져 있으면(4.9) 앱은 [후기]·"내 후기"를 그리지 않고 먼저 묻지도 않는다.

### 2.2 프로모션 쓰기

- 설정 › 콘텐츠 섹션의 **[프로모션]**(S12 개편 — 4.6)에서 쓴다.
- 발급 순간의 안내 시트 [지금 쓰기]도 S12로 간다.

### 2.3 계약 골격 (경로·필드 이름은 `spec/api`가 정한다)

| 용도 | 가칭 |
|---|---|
| 후기 시트 열기 | `GET /contents/:contentId/review` — 쓸 수 있는지 · 내 후기 · 발급까지의 진행 |
| 후기 저장 | `PUT /contents/:contentId/review` — 응답에 이번 저장으로 발급된 프로모션 |
| 먼저 묻기 판정 | `GET /users/me/content-review/prompt` |
| 닫기 · 이번 주 그만 보기 | `POST /users/me/content-review/prompt/dismiss` · `…/mute` |
| 프로모션 화면 | `GET /users/me/promotions` — 이용 중 지급 · 사용 가능한 프로모션(쓸 수 있는지 · 사유 · 사용 기한) · 발급까지의 진행 |
| 프로모션 사용 | `POST /users/me/promotions/:id/redeem` — 응답은 초대 코드 입력(`subscription-api.md` 4.8)과 같은 본문 |
| 운영 | `GET /admin/content-reviews/summary` · `GET /admin/content-reviews` |

## 3. 입력값

**후기**

| 값 | 설명 | 필수 |
|---|---|---|
| `content_id` | 후기를 남길 편 | 필수 |
| `stars` | 1~5 정수 | 필수 |
| `text` | 앞뒤 공백을 뺀 0~500자. 빈 값 = 글 없음 | 선택 |

- 후기는 **사용자·편 쌍당 하나**다. 다시 보내면 덮어쓴다(수정). 글을 지우려면 빈 값으로 보낸다.

**프로모션 사용**

| 값 | 설명 | 필수 |
|---|---|---|
| 프로모션 id | 쓸 프로모션 | 필수 |

## 4. 처리 로직

### 4.1 후기를 쓸 수 있는 편 (서버 판정)

- 그 사용자가 **재생을 시작한 적 있는** 편이어야 한다. 안 들은 편의 별점은 품질 신호가 아니다.
- 지금 볼 수 있는 편이어야 한다 — 시장 격리(FR-43)로 이미 걸러지는 조건이다. 시장을 바꾼 사용자의 이전 시장 편은 숨겨져 진입점 자체가 없다.
- **회수된 편**은 새 후기·수정을 거부한다. 이미 받은 후기는 남긴다.

### 4.2 후기 저장

- 후기 시점의 **완청 여부**와 **`content_version`**을 함께 남긴다. 재발행(오디오 교체) 전후의 후기를 갈라 재합성 효과를 잰다.
- 후기를 고치면 두 값도 그 시점 값으로 다시 적는다.
- 작성·수정 시각을 남긴다.

### 4.3 먼저 묻는 시트 (서버 판정)

1. 후기 기능 스위치가 꺼져 있으면 `show=false`(4.9).
2. **최근 14일 안에 끝까지 들었고 아직 후기가 없는 편**이 있어야 한다. 그중 가장 최근에 끝까지 들은 편 **하나**를 묻는다. 없으면 `show=false`.
3. **마지막으로 물은 날에서 2 서비스 날짜가 지나야** 다시 묻는다(결정 2026-10-30 — 종전 5, 2026-10-28). 어제 물었으면 오늘은 쉬고 내일 라이브러리에 들어올 때 묻는다. 닫든 보내든 "물었다"로 친다 — 계약에서는 시트가 닫힐 때 앱이 `dismiss`(또는 `mute`)를 한 번 보내고, 저장은 "물었다"를 적지 않는다(`content-review-api.md` 4.4 · 4.5).
4. [이번 주 그만 보기]를 눌렀으면 그 서비스 주(월 05:00 KST 시작 — `domain.md` 1.2)에는 묻지 않는다.
5. **같은 세션에 추천 별점 팝업(L16)이 떴으면 띄우지 않는다.** 두 판정은 각각 서버가 하고, 한 세션에 하나만 띄우는 순서는 앱의 표시 규칙이다(추천 별점 우선).

- 상수: `CONTENT_REVIEW_PROMPT_INTERVAL_DAYS = 2` · `CONTENT_REVIEW_PROMPT_RECENT_DAYS = 14`. 값은 서버 소유다.
- "끝까지 들은 시각"은 라이브러리 행의 완청 시각(지운 행 포함, 여러 행이면 가장 늦은 값), 없으면 그 편 완청 신호의 가장 늦은 시각이다. 위치만 90%를 넘고 완청 신호가 없는 편은 시각이 없어 묻지 않는다(2026-10-29 서버 결정 — `content-review-api.md` 4.3).
- 프로모션을 이미 받은 계정에게도 묻는다 — 목적은 후기이고 보상은 계기다. 그때는 보상 줄을 그리지 않는다.

### 4.4 프로모션 발급

- **보상으로 치는 후기** = **끝까지 들은 편**에 남긴, **별점과 글(공백 빼고 10자 이상)이 있는** 후기.
- **서로 다른 편 3개**가 채워지는 순간 **후기 참여 프로모션(Pro 7일) 1장**을 발급한다.
- **계정당 전체 1회**다(결정 2026-10-28). 소멸했든 썼든 한 번 받은 계정에는 다시 주지 않는다.
- 발급 뒤 후기를 고치거나 글을 지워도 거두지 않는다.
- **Pro 구독자도 발급받는다** — 구독 중에는 쓸 수 없고(4.5), 사용 기한 안에 구독이 끝나면 쓸 수 있다.
- **사용 기한 = 발급 후 3개월**(결정 2026-10-28). 발급한 서비스 날짜의 3개월 뒤 같은 날짜 05:00 KST에 소멸한다. 그 달에 같은 날짜가 없으면 그 달 마지막 날 05:00이다. 화면에는 쓸 수 있는 마지막 서비스 날짜를 서버가 내려준다.
  - 예: 10/28 발급 → 2027-01-28 05:00 소멸, 화면 표시 "1월 27일까지 사용".
  - 소멸 판정은 조회·사용 시점에 서버가 한다. 배치가 필요 없다.
- 문턱 값은 서버 상수다: `CONTENT_REVIEW_REWARD_REQUIRED = 3` · `CONTENT_REVIEW_REWARD_MIN_TEXT = 10`.
- 발급 스위치가 꺼져 있으면 새로 발급하지 않는다(4.9).

### 4.5 프로모션 사용 (서버 판정 — 쓰는 순간)

| 쓰는 순간 계정 상태 | 결과 |
|---|---|
| 무료 | 바로 Pro 7일 |
| 무료 · 가입 체험 중 | 쓸 수 있다. 확인 팝업에 체험과 겹친다는 안내를 더한다 — 체험은 재생 한도만 풀어 주므로(`subscription.md` 4.8) 겹치는 동안 Pro로 더 얻는 것은 무손실 음질뿐이다 |
| 데일리 구독 중 | 바로 Pro 7일 → 끝나면 데일리. 쓸 때 이미 있던 구독은 갱신·변경돼도 지급을 끝내지 않는다(`subscription.md` 4.9) |
| 프로 구독 중(해지 예약 · 결제 유예 · 다운그레이드 예약 포함) | **쓸 수 없다.** 사유 `pro_subscribed` |
| 다른 프로모션 이용 중(초대 코드 지급 등) | **쓸 수 없다.** 사유 `grant_active` — 계정당 지급은 동시에 하나다(`subscription.md` 4.9) |
| 사용 기한 지남 | **쓸 수 없다.** 목록에서 사라진다 |
| 이미 사용함 | **쓸 수 없다.** 두 기기의 동시 요청도 한 번만 지급된다 |

- **지급 방식**: 초대 코드 기간 지급(`subscription.md` 4.9)과 **같은 경로**를 쓴다. 새 지급 규칙을 만들지 않는다.
  - 지급 중에는 Pro의 모든 권한(재생 한도 · 음질 · 광고 · 드립)이 적용된다.
  - `users.tier` 캐시는 결제 반영 경로 한 곳이 구독과 지급 중 높은 쪽으로 맞춘다. **`users.tier`를 직접 `pro`로 올리지 않는다.**
  - 끝나면 기존 지급 만료 배치(10분 간격)가 캐시를 되돌린다.
- **기간**: 쓴 서비스 날짜를 1일째로 **7개 서비스 날짜**. 05:00 경계에 끝난다.
- **표시 이름**: 응답 `plan.grant.name`은 **"후기 참여"**다(영어 "Review"). 세 곳(설정·프로필·요금제 관리)의 기존 문자열 "{이름} 프로모션 이용 중 · {요금제} · N월 N일까지"에 들어가 **"후기 참여 프로모션 이용 중 · Pro · 11월 3일까지"**가 된다. 이름을 "후기 참여 프로모션"으로 두면 "프로모션 프로모션"이 된다.
- **쓰는 중에 결제하면**: `subscription.md` 4.9 그대로 — 쓸 때 구독이 없던 계정이 결제하면 지급이 끝나고 결제한 요금제가 된다. 프로모션은 쓴 것으로 남는다. 결제 전 확인은 기존 "{이름} 프로모션이 끝나요" 팝업(`subscription-uiux.md` 4장)이 맡는다.

### 4.6 프로모션 화면 (S12 개편)

- **행 이름** [프로모션 코드 입력] → **[프로모션]**(영어 "Promotions"). 결제 UI 플래그와 무관하게 늘 있는 자리라 **콘텐츠 섹션 마지막 행에 그대로 둔다**(`settings-uiux.md` 4.8).
- **화면 구성**(위에서 아래로)
  1. **이용 중** — `plan.grant`가 있을 때만. 기존 문자열 그대로.
  2. **사용 가능한 프로모션** — 카드 "후기 참여 프로모션 · Pro 7일 · {N월 N일}까지 사용" + [사용하기]. 쓸 수 없으면 버튼을 흐리게 하고 서버가 준 사유를 한 줄로 적는다(5장).
  3. **아직 받지 않았을 때** — 후기 기능 · 발급 스위치가 모두 켜져 있고 받은 적이 없으면 "끝까지 들은 편 3개에 후기를 남기면 Pro 7일 프로모션을 드려요 · 지금 N/3".
  4. **코드 입력** — 지금 그대로. **코드는 즉시 적용**이다(보관하지 않는다 — 진행 중인 PoC 동작을 바꾸지 않는다).
- [사용하기] → 확인 팝업에 끝나는 날짜("오늘부터 7일 · 11월 3일까지")를 보여 준다. 날짜는 서버가 준다.
- **화면 문구에 "쿠폰"을 쓰지 않는다.** 코드로 받은 것도 후기로 받은 것도 "프로모션"이다.
- **찾기 어려운 자리를 보완한다**
  - 발급 순간 안내 시트에 [지금 쓰기]/[나중에]를 둔다.
  - 쓰지 않은 프로모션이 있으면 설정의 [프로모션] 행에 점 배지를 단다.

### 4.7 운영 열람

- **관리자 콘솔**(admin API)
  - 편별: 후기 수 · 평균 · 1~5 분포 · 글 수. 파이프라인 발행 상세에서 함께 본다.
  - 글 목록(편별 · 최신순): 별점 · 글 · 작성 서비스 날짜 · 시장 · 완청 여부 · `content_version`.
  - **작성자 계정(`user_id`) · 닉네임은 응답에 싣지 않는다.**
  - 프로모션: 발급 수 · 사용 수 · 소멸 수(건수만).
- **일일 Slack 보고**: 건수와 평균만. 앱 안 후기는 공개 글이 아니라 스토어 리뷰(VoC)처럼 원문을 채널에 올리지 않는다.
- 원문을 **파이프라인 Supabase로 복사하지 않는다.** 콘솔은 필요할 때 API로 읽는다. 원문을 Slack · Jira · 문서 · 커밋에 옮겨 적지 않는다(CLAUDE.md 개인정보 원칙).
- **쓰임**: 저평점 편의 글을 사람이 읽고 판정→규칙 승격 루프의 재료로 쓴다. 자동 반영은 없다.

### 4.8 추천과의 관계

- **후기는 추천 입력이 아니다.** 추천 별점(FR-41)과 같은 이유다 — 반영하면 평점 변화가 알고리즘 덕인지 반영 덕인지 가를 수 없고, 알고리즘 버전별 비교가 흐려진다. 개인화 신호는 종전대로 완청 · 담기 · 삭제(`drip-scheduling.md` 4.3)다.
- 추천 별점(`drip_feedbacks`)과 **표 · 집계 · 팝업을 모두 따로 둔다.** 같은 편에 둘 다 있어도 서로를 대신하지 않는다.

### 4.9 서버 스위치

| 스위치 | 끄면 | 운영 |
|---|---|---|
| `CONTENT_REVIEW_ENABLED` | 저장 거부 · 먼저 묻기 `show=false` · 앱은 [후기] · "내 후기"를 그리지 않는다. 받은 후기와 프로모션은 그대로다 | **개인정보 처리방침 시행일 이후에 켠다**(선행 — 반영 범위). 앱 출시와 시행일을 떼어 놓기 위해 서버 스위치로 둔다. 켜짐 여부는 서버가 내려준다 — 먼저 묻기 판정(`GET /users/me/content-review/prompt`)의 `enabled`, 시트 열기 · 프로모션 화면에도 같은 값(`content-review-api.md` 2.1) |
| `CONTENT_REVIEW_REWARD_ENABLED` | 새 발급만 멈춘다. 이미 받은 프로모션은 사용 기한까지 쓸 수 있다 | **상시 운영**(결정 2026-10-28) — 켜 둔다 |

## 7. 예외 상황

- **두 기기에서 동시에 3번째 후기**: 프로모션 유니크로 1장만 발급된다.
- **두 기기에서 동시에 [사용하기]**: 한 번만 지급되고 나머지는 "이미 사용함"으로 거부된다.
- **재발행(오디오 교체)**: 이전 후기는 그대로 두고 `content_version`으로 가른다. 사용자가 다시 쓰면 덮어쓰며 새 버전이 찍힌다.
- **시장 전환**: 이전 시장 편은 숨겨져 후기를 쓸 수 없다. 받은 후기 · 발급까지의 셈 · 가진 프로모션은 유지한다(구독 · 체험이 그대로인 것과 같다).
- **Pro 구독을 사용 기한(3개월)보다 오래 이어 감**: 쓰지 못하고 소멸한다. 결제일 연장을 하지 않기로 한 결과다(1장 "하지 않는 것").
- **다른 프로모션 이용 중에 사용 기한이 끝남**: 소멸한다. 기한은 발급 때 정해지고 늘리지 않는다.
- **사용 기한 마지막 날 사용**: 7일이 온전히 지급된다. 기한은 "쓸 수 있는 마지막 날"이지 지급 끝이 아니다.
- **새벽(04:50 등)에 사용**: 첫날이 짧다. 초대 코드와 같은 05:00 경계 규칙이고 확인 팝업이 끝나는 날짜를 보여 준다.
- **탈퇴 후 재가입**: 다시 받을 수 있다. 탈퇴 계정은 식별자를 파기해 같은 사람인지 알 수 없다 — 가입 체험(`subscription.md` 4.8)과 같은 한계로 받아들인다.
- **글에 개인정보가 들어옴**: 공개하지 않으므로 검수하지 않는다. 운영 열람 범위(4.7)로 통제한다.
- **회수된 편**: 새 후기 · 수정 불가. 먼저 묻는 시트에서도 뺀다. 기존 후기는 콘솔 집계에 회수 표시와 함께 남는다.
- **후기 기능 스위치를 끔**: [후기]가 사라지고 먼저 묻지 않는다. 가진 프로모션은 S12에서 그대로 쓸 수 있다.

## 8. 완료 조건

- Given 들어 본 편 / When 별 4개를 보낸다 / Then 저장되고 다시 열면 내 후기가 채워져 있다
- Given 들어 본 적 없는 편 / When [후기]를 누른다 / Then 안내가 뜨고 서버도 저장을 거부한다
- Given 끝까지 들은 편 2개에 별점과 10자 이상 글을 남겼다 / When 3번째 편에 같은 후기를 보낸다 / Then 후기 참여 프로모션 1장이 발급되고 발급 안내가 뜬다
- Given 별점만 남긴 후기, 또는 끝까지 듣지 않은 편의 후기 / Then 발급 셈에 들어가지 않는다
- Given 프로모션을 받은 적 있는 계정(사용 · 소멸 포함) / When 후기를 더 쓴다 / Then 저장만 되고 다시 발급되지 않는다
- Given 무료 계정이 프로모션을 가졌다 / When S12에서 [사용하기]를 누르고 확인한다 / Then Pro 7일이 시작되고 세 곳에 "후기 참여 프로모션 이용 중 · Pro · N월 N일까지"가 뜬다
- Given 프로 구독 중인 계정 / When S12를 연다 / Then 프로모션은 보이지만 [사용하기]가 흐리고 사유가 적혀 있으며, 서버도 사용을 거부한다
- Given 초대 코드 프로모션 이용 중 / When 후기 참여 프로모션을 쓰려 한다 / Then 서버가 거부하고 사유가 표시된다
- Given 데일리 구독자가 사용했다 / When 7일이 지난다 / Then 데일리로 돌아가고, 그사이 구독 갱신이 있어도 지급은 끊기지 않는다
- Given 10/28에 발급받고 쓰지 않았다 / When 2027-01-28 05:00이 지난다 / Then S12에서 사라지고 사용도 거부된다
- Given 끝까지 들었고 후기 없는 편이 있고 그저께(서비스 날짜) 시트를 닫았다 / When 오늘 라이브러리에 들어온다 / Then 먼저 묻는 시트가 뜬다. 같은 세션에 추천 별점이 떴다면 뜨지 않는다
- Given 어제(서비스 날짜) 먼저 묻는 시트를 닫았다 / When 오늘 라이브러리에 들어온다 / Then 끝까지 들은 후기 없는 편이 있어도 뜨지 않는다
- Given [이번 주 그만 보기]를 눌렀다 / When 이번 주 안에 다시 들어온다 / Then 뜨지 않고, 다음 주 월요일 05:00 이후 조건이 맞으면 다시 뜬다
- Given 발급 스위치를 껐다 / Then 새 발급이 멈추고 이미 가진 프로모션은 기한까지 쓸 수 있다
- Given 후기 기능 스위치가 꺼져 있다 / Then 더보기 시트에 [후기]가 없고 서버는 저장을 거부한다
- Given 관리자 콘솔 글 목록 / Then 응답에 작성자 계정이 없다
- Given 후기를 남겼다 / Then 그 사용자의 드립 편성 · 추천 점수가 바뀌지 않는다
