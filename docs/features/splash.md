# 스플래시 · 앱 진입 분기 기능 명세서

> 연결 PRD: FR-35, FR-36 / 사용자흐름 5.1

## 1. 목적 & 연결

앱 실행 시 최소 지원 버전과 인증·온보딩 상태를 판정하여 올바른 첫 화면으로 분기시킨다. 사용자가 "앱을 열면 들을 게 준비되어 있는" 경험(PRD 1.3)의 진입점이며, 잘못된 버전·만료된 세션이 이후 화면으로 새어나가지 않게 막는 관문 역할을 한다.

- PRD FR-35 (앱 실행 시 온보딩 완료 여부로 진입 분기, 버전 체크, 강제 업데이트)
- PRD FR-36 (네트워크 오류 공통 처리·재시도)
- PRD 사용자흐름 5.1 (스플래시 → 시작 화면 → 소셜 로그인 → …)

## 2. 진입 조건

- 앱을 콜드 스타트(프로세스 신규 생성)로 실행할 때
- 백그라운드에서 일정 시간(기준값: 30분) 이상 머문 뒤 포그라운드로 복귀할 때 → 버전 체크·세션 검증만 재수행하고, 화면 분기는 하지 않음(현재 화면 유지)
- 딥링크·푸시 탭으로 진입한 경우에도 스플래시를 먼저 통과한 뒤 목적지로 이동

## 3. 입력값

| 값 | 출처 | 필수 |
|---|---|---|
| app_version | 클라이언트 빌드 정보 | 필수 |
| platform (ios/android) | 클라이언트 | 필수 |
| access_token / refresh_token | 로컬 보안 저장소 | 선택(미로그인 시 없음) |
| deep_link_target | 인텐트·푸시 페이로드 | 선택 |

서버 응답으로 받는 값:

| 값 | 설명 |
|---|---|
| min_supported_version | 이 버전 미만은 강제 업데이트 |
| latest_version | 권장 업데이트 안내 기준 |
| notice | 점검·공지 배너(선택) |
| user.onboarding_completed | 온보딩 완료 여부 |
| user.tier | 구독 티어 |

## 4. 처리 로직

순서대로 판정하며, 앞 단계에서 걸리면 뒤 단계는 실행하지 않는다.

1. **버전 체크** — 서버에서 `min_supported_version` 조회
   - `app_version < min_supported_version` → 강제 업데이트 화면(닫기 불가, 스토어 이동만 가능). **이후 로직 진행 안 함**
   - `min_supported_version <= app_version < latest_version` → 권장 업데이트 안내(닫기 가능), 닫으면 다음 단계 진행
   - 점검 중(`notice.type == maintenance`) → 점검 안내 화면, 이후 로직 진행 안 함
2. **인증 상태 판정**
   - 토큰 없음 → **시작 화면(서비스 소개)** 으로 이동
   - access_token 만료 → refresh_token으로 갱신 시도
     - 갱신 성공 → 3번으로
     - 갱신 실패(만료·폐기·탈퇴 계정) → 로컬 토큰 삭제 후 **시작 화면**으로 이동
3. **재동의 필요 여부 판정** (추가 2026-09-07)
   - 서버가 준 `pending_consents`가 비어 있지 않음 → **재동의 화면(A20)** 으로 이동. 동의를 마치기 전에는 뒤 단계로 가지 않는다(`auth.md` 7 · `auth-uiux.md` 4.3-1)
   - **온보딩 판정보다 앞에 둔다.** 약관에 동의하지 않은 사용자를 온보딩으로 들여보내면, 관심사·커리어를 입력받은 뒤에야 동의를 묻게 된다
   - **로그인 직후에만 잡지 않는 이유가 이 단계다.** 이미 로그인된 세션으로 앱을 다시 열면 로그인 응답을 받지 않으므로, 관문에 두지 않으면 그 경로가 그대로 새 나간다
   - 사용자가 거절하면 **로그아웃**하고 시작 화면으로 간다(탈퇴가 아니다 — `auth-uiux.md` 4.3-1)
4. **온보딩 완료 여부 판정**
   - `onboarding_completed == false` → **온보딩 첫 단계(관심 주제 선택)** 로 이동. 중단 지점부터 재개한다(온보딩 명세 참조)
   - `onboarding_completed == true` → **4-1로**
4-1. **마지막 탭 복원 판정** (신설 2026-09-15 — `changes/archive/splash-restore-last-tab.md`)
   - 기기 로컬에 마지막으로 본 탭 기록이 있고 **그 탭을 떠난 뒤 30분 이내** → **그 탭**(라이브러리·탐색·프로필 중 하나)으로 이동
   - 기록이 없거나 만료 → **라이브러리(메인)** 로 이동
   - 복원 범위는 **탭까지만**이다. 콘텐츠 상세·설정 하위·검색 결과 같은 스택은 되살리지 않는다 — 상세를 보다 종료했으면 **그 상세가 속한 탭**으로 간다. 상세는 그 사이 회수·삭제로 사라질 수 있고, 설정 하위는 "내가 이걸 왜 보고 있지"가 된다
   - 30분인 이유: 잠깐 다른 앱에 갔다 돌아오는 경우를 살리는 것이 목적이다. 어제 본 탭이 오늘 뜨면 편의가 아니라 어색함이다
   - 판정은 **기기 시각**으로 한다. 정책 판정(한도·만료·서비스 날짜)이 아니라 화면 복원이라 서버 판정 대상이 아니며, 시계가 어긋나도 최악은 현행과 같은 "라이브러리로 간다"다
   - 기록은 서버에 보내지 않고(기기마다 다른 것이 자연스럽다) **로그아웃 시 지운다** — 다음 사용자가 앞 사용자의 탭에서 시작하면 안 된다
5. **딥링크 처리** — 4번(4-1 포함)에서 도착지가 결정된 뒤, `deep_link_target`이 있으면 해당 화면을 스택 위에 얹는다(복원한 탭 위에 얹힌다 — 딥링크가 이긴다). 단 온보딩 미완료 사용자는 딥링크를 **보류**했다가 온보딩 완료 후 이동한다.
6. **최소 노출 시간 — 로고 모션 영상이 완성된 뒤 0.8초**(개정 2026-09-17 — `changes/archive/splash-logo-animation.md`. 종전 "최소 0.8초"). 스플래시는 흰 화면에서 로고의 선이 그려져 완성되는 영상(`assets/splash-logo.mp4`, 4.03초, 소리 없음·음소거·다른 앱 재생을 끊지 않음)을 화면 폭 70% 박스에 튼다. 선은 **2.23초**에 다 그려지고 나머지는 완성 로고로 머문다.
   - 선이 다 그려지기 전에 화면이 바뀌면 그리다 만 로고가 잘린다. 판정이 더 빨리 끝나도 완성 후 0.8초 머문 뒤 전환한다 — 영상이 바로 시작되면 총 약 3.0초.
   - **시계가 아니라 영상의 재생 위치로 판정한다.** 영상 시작은 기기·망에 따라 0.3~1초 늦어질 수 있어 마운트 시각에서 세면 그리다 만 채로 잘린다. 재생 위치 2.23초를 넘긴 시점을 관문에 올리고, 관문은 그 뒤 0.8초에 넘어간다.
   - **모션 축소 설정**이면 영상 대신 정지 로고(`splash-icon.png`)를 두고 종전 0.8초를 유지한다.
   - **안전장치 6초** — 영상이 시작조차 못 하면(디코더 오류·자산 누락) 마운트 6초 뒤 무조건 넘어간다. 스플래시에 갇히는 것이 그리다 만 로고보다 나쁘다.
   - 스피너를 두지 않는다 — 그려지는 선 자체가 진행 중임을 보인다. `expo-video`는 네이티브 모듈이라 runtimeVersion `2` 빌드부터 적용된다(`frontend/architecture.md` 2.1).
7. **첫 화면 미리 받기** (신설 2026-09-20 — `changes/archive/splash-prefetch-first-screen.md`) — 세션이 **로그인 완료(+ 온보딩 완료)**로 확정되는 순간 라이브러리 첫 화면(전체·필터 없음)의 첫 페이지를 화면과 같은 캐시 키로 받고, 그 썸네일을 디스크 캐시로 미리 받는다. 콜드 스타트에서는 이 시점이 로고 모션 도중이라 어차피 기다리는 시간을 쓴다.
   - **관문을 붙잡지 않는다.** 미리 받기가 늦거나 실패해도 스플래시는 위 조건(세션 판정 · 로고 모션 · 마지막 탭)으로만 넘어가고, 못 받았으면 화면이 평소대로 받는다. 실패를 알리지 않는다.
   - 판정은 없다 — 표시용 데이터를 일찍 받을 뿐이고 재생 한도·만료 판정은 그대로 서버가 한다. 온보딩 미완료 사용자는 미리 받지 않는다. 탐색 탭 착지(4-1)의 피드·미니플레이어 복원 대상은 범위 밖이다.

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 판정 중 | 스플래시(로고 모션 영상 — 2.2초에 완성, 이후 완성 로고 유지. 모션 축소 설정이면 정지 로고). 완성 후 1.5초 이상 지연 시 로딩 인디케이터 추가 노출(인디케이터는 미구현) |
| 강제 업데이트 | 전면 안내 + [스토어로 이동] 단일 버튼. 뒤로가기·닫기 불가 |
| 권장 업데이트 | 바텀시트 + [업데이트] / [나중에] |
| 점검 중 | 전면 안내(점검 사유·예상 종료 시각) + [다시 시도] |
| 네트워크 오류 | 전면 안내 + [다시 시도]. 3회 연속 실패 시 "잠시 후 다시 시도해주세요" 문구로 전환 |
| 판정 완료 | 시작 화면 / 온보딩 / 라이브러리 중 하나로 전환(스플래시는 스택에서 제거) |

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `users` — `onboarding_completed` · `onboarding_step` · `tier` | 3.1 |
| `sessions` — 토큰 검증 | 3.3 |

**`AppConfig`는 테이블이 아니다.** 최소 지원 버전·최신 버전·점검 공지는 **배포 설정에서 관리**하고 서버가 조회 API로 내려준다(domain.md 13.3). 플랫폼별로 값이 다르다.

- **버전 조회 API는 `platform`(`ios` / `android`)을 필수로 받는다.** 값 집합과 규칙은 `settings-api.md` 4.1과 같다 — 설정 화면과 스플래시가 같은 배포 설정을 원천으로 쓰므로 입력도 같아야 한다. **강제 업데이트는 안내가 아니라 차단이라 위험이 더 크다**: 한쪽 스토어 심사가 밀리는 동안 단일 값으로 판정하면 아직 배포되지 않은 플랫폼의 사용자 전원이 업데이트할 수 없는 화면에 갇힌다.

## 7. 예외 상황

- **버전 체크 API 실패**: 실패했다고 앱을 막지 않는다. 캐시된 `min_supported_version`이 있으면 그걸로 판정하고, 없으면 통과시킨 뒤 다음 단계 진행(fail-open, 합의 2026-08-06 — **가용성 우선 트레이드오프 확정.** 신규 설치+서버 장애 조합에서 강제 업데이트가 지연될 수 있음을 감수한다). 단 점검 응답은 캐시하지 않는다.
- **오프라인 실행**: 네트워크 없음 → 온보딩 완료 사용자는 캐시된 라이브러리로 진입 허용, 미완료 사용자는 네트워크 오류 화면(온보딩은 서버 저장이 필요하므로).
- **토큰 갱신 요청이 동시에 여러 번 발생**: 갱신 요청은 단일 인플라이트로 묶고 나머지는 결과를 공유한다.
- **탈퇴한 계정의 토큰이 남아 있는 경우**: 갱신 실패로 처리 → 로컬 데이터 전량 삭제 후 시작 화면.
- **강제 업데이트 화면에서 스토어에 해당 버전이 아직 없는 경우**: 스토어 페이지로만 이동시키고 앱은 계속 차단 상태 유지.
- **스플래시 도중 앱을 백그라운드로 보냈다가 복귀**: 판정을 처음부터 다시 수행한다(중간 상태 신뢰 안 함).
- **기기 시각이 크게 어긋난 경우**: 토큰 만료 판정은 로컬 시각이 아니라 서버 401 응답을 기준으로 한다.

## 8. 완료 조건

- Given 앱 버전이 최소 지원 버전보다 낮다 / When 앱을 실행한다 / Then 강제 업데이트 화면이 뜨고 뒤로가기로 빠져나갈 수 없다
- Given 로그인한 적 없는 사용자 / When 앱을 실행한다 / Then 시작 화면(서비스 소개)이 노출된다
- Given 로그인했으나 온보딩을 관심 주제 선택 단계에서 중단한 사용자 / When 앱을 재실행한다 / Then 관심 주제 선택 단계부터 재개된다
- Given 온보딩을 완료한 사용자 / When 앱을 실행한다 / Then 라이브러리 화면으로 바로 진입한다
- Given 버전 체크 API가 실패한다 / When 앱을 실행한다 / Then 앱이 차단되지 않고 정상 진입 분기가 수행된다
- Given 리프레시 토큰이 만료된 사용자 / When 앱을 실행한다 / Then 로컬 토큰이 삭제되고 시작 화면으로 이동한다
