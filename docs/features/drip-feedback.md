# 추천 별점(온라인 평가) 기능 명세서

> 연결 PRD: FR-41 (P0 — 신설 2026-09-30) / 사용자흐름 5.3(라이브러리 진입)
> 짝 문서: `backend/recommendation-evaluation.md`(배포 **전** 오프라인 평가). 이 문서는 배포 **후** 실사용자 평가다.
> 통신 계약: `spec/api/drip-feedback-api.md` · 어드민 집계: `spec/api/admin-api.md` 4.19 · 스키마: `backend/domain.md` 6.1·6.7·3.5

## 1. 목적 & 연결

**추천 알고리즘 자체**를 실사용자의 평가로 잰다. 사용자가 앱에 들어오면 "어제 추천 어떠셨나요?"와 함께 **가장 최근에 받은 정규 편성분**(드립 2편 — 보통 어제)을 **그 편성분에 대해 한 번만** 보여주고 별 1~5를 받는다(4.1). 편성분마다 **어떤 알고리즘 버전이 골랐는지**를 남겨 두므로, 알고리즘을 바꿔 가며 버전별 평점이 어떻게 움직이는지 어드민에서 본다.

- **별점은 추천 입력이 아니다**(PM 결정 2026-09-30). 그 사용자의 다음 편성에 반영하지 않는다 — 반영하면 "평점이 오른 게 알고리즘 덕인지 반영 덕인지" 구분이 안 된다. 개인화 신호는 종전대로 완청·담기·삭제(`drip-scheduling.md` 4.3)다.
- 배포 전 오프라인 평가(KAN-108)가 "코드가 규칙을 깨지 않았나·지난 버전보다 나빠지지 않았나"를 걸러 준다면, 이 기능은 "사용자가 실제로 좋아했나"를 버전별로 답한다. 별점이 쌓이면 오프라인 백테스트의 정답으로도 쓴다.

## 2. 진입 조건

- 앱 첫 화면(라이브러리) 진입 시 클라이언트가 `GET /users/me/drip-feedback/prompt`를 부르고 **`show=true`일 때만** 팝업을 띄운다. 판정 전부가 서버다 — 클라이언트는 어느 편성분이 최근인지, 이번 주가 언제 끝나는지 계산하지 않는다.
- **한 편성분(같은 날 정규 2편)에 대해 한 번만 묻는다**(개정 2026-09-30). 별점을 보내든 닫든 그 편성분은 끝이고, 그 뒤 **새 편성이 없으면 다시 묻지 않는다.** 닫기는 `POST …/dismiss`로 서버에 알린다 — 앱을 그냥 종료하면(둘 다 안 함) 다음 진입에 다시 묻는다.

## 3. 입력값

| 값 | 설명 | 필수 |
|---|---|---|
| ratings[].content_id | 별점을 매길 편성분 | 필수(1~10건) |
| ratings[].stars | 1~5 정수 | 필수 |

- 팝업의 두 편 중 **하나만 평가하고 보내도 된다.** 안 보낸 편은 다음 진입에 다시 묻는다(4.1 — 미평가분만 묻는다).

## 4. 처리 로직

### 4.1 노출 판정 — 무엇을 묻는가

1. `user_settings.drip_feedback_muted_until`이 있고 **오늘 서비스 날짜가 그 전**이면 `show=false`(4.3).
2. **가장 최근 정규 편성분** = 오늘(서비스 날짜, 04:00 KST 경계) **전**에 적립된 마지막 `library_items(source = drip)`의 서비스 날짜. 보통 어제다. 오늘 아침 편성분은 아직 듣기 전이라 내일 묻는다. 며칠 만에 열어도 **쌓인 날짜마다 묻지 않고 이 마지막 편성분 하나만** 묻는다. 편성분이 한 번도 없으면 `show=false`.
3. 그 편성분을 **이미 물었으면**(`drip_feedback_last_prompted_date` ≥ 그 날짜 — 별점을 보냈거나 닫았다) `show=false`. 그 뒤 새 편성이 생겨야 다시 묻는다.
4. 그 날짜 구간의 정규 편(`drip`)만 고른다 — **탐험 편(`discovery`)은 묻지 않는다.** 탐험은 "취향 밖을 하나 보여주는" 슬롯이라 별점이 낮은 것이 정상이고, 섞으면 정규 평점이 흐려진다. 사용자가 **삭제한 편은 뺀다** — 이미 반응한 것이다.
5. 그중 **아직 평가하지 않은** 편을 최대 2편(정규 편수) 한 팝업에 돌려준다. 0편이면 `show=false`.

### 4.2 별점 저장

- 대상은 **그 사용자의 편성분(드립·탐험)이고 편성 뒤 7일 안**이어야 한다. 팝업은 가장 최근 편성분만 묻지만, 오프라인 큐로 늦게 도착하는 전송을 받기 위해 접수 기간을 둔다. 하나라도 대상이 아니면 **전부 거부**한다(`DRIP_FEEDBACK_NOT_RATEABLE`) — 부분 저장은 화면의 선택과 서버 상태를 어긋나게 한다.
- 같은 콘텐츠의 재전송은 **덮어쓴다**(멱등, `(user_id, content_id)` 유니크). 멱등키는 쓰지 않는다.
- 저장 행에는 편성 시점의 `algorithm_version`·`source`·편성 서비스 날짜를 함께 남긴다(6장). **버전이 바뀐 뒤 옛 편성분을 평가해도 옛 버전에 쌓인다** — 행의 버전은 오늘의 상수가 아니라 `library_items.algorithm_version`이다.
- 별점을 보내면 평가한 편성분 날짜까지 "물었다"로 남겨(`drip_feedback_last_prompted_date`) 같은 편성분을 다시 묻지 않는다. 닫기(`POST …/dismiss { placed_date }`)도 같다. 값은 뒤로 가지 않는다.

### 4.3 이번 주 그만 보기

- **이번 주** = 서비스 주(월요일 04:00 KST 시작 — `domain.md` 1.2). 누르면 `drip_feedback_muted_until` = 다음 주 월요일 라벨. 그 날부터 다시 묻는다.
- 그만 보기는 팝업만 막는다. 이미 보낸 별점은 그대로다. "다시 묻지 않음"(4.1-3)과 별개다 — 그만 보기는 기간 억제, 4.1-3은 편성분 단위다.

### 4.4 알고리즘 버전 태깅

- 편성 배치가 적립할 때 `library_items.algorithm_version`에 서버 상수 `DRIP_ALGORITHM_VERSION`(형식 `YYYY-MM-DD.n`)을 남긴다. 담기·온보딩 행은 NULL이다.
- **올리는 규칙(백엔드 소유)**: 편성 결과가 달라질 수 있는 변경 — 축·항목 가중치, 후보 필터, 다양성 선정(MMR), 취향 계산식, 자동 확장 판정, 탐험 선정 — 이면 올린다. 로그·표시·성능처럼 결과가 같은 변경은 올리지 않는다. 올리지 않고 결과를 바꾸면 서로 다른 알고리즘의 별점이 한 버전에 섞인다. 배포 전 체크리스트(`recommendation-evaluation.md` 7장)에 포함한다.
- 버전 도입 전 편성분은 NULL 버전으로 묶여 어드민 표의 맨 뒤에 놓인다.

### 4.5 어드민 집계

- 어드민 콘솔(추천 검증)에 **버전 역순**으로 편성 수·편성 사용자 수·첫/마지막 편성 시각·평가 수·평가 사용자 수·평균 별점·1~5 분포를 보인다(`admin-api.md` 4.19). 응답률 = 평가 수 / 편성 수.
- 버전 간 비교는 사람이 한다. 표본이 작을 때(평가 20건 미만) 평균만 보고 판단하지 않는다.

## 5. 화면 상태 (요약 — 확정 카피·화면 ID는 `spec/uiux` 개정 시)

| 상태 | 화면 |
|---|---|
| 팝업 | 제목 "어제 추천 어떠셨나요?"(편성 날짜가 어제가 아니면 "지난 추천") · 편성분 카드 1~2개(썸네일·제목) 각각 별 1~5 · [보내기] · [이번 주 그만 보기] · 닫기(→ `dismiss`) |
| 한 편만 평가 | [보내기]는 평가한 편만 전송. **그 편성분은 끝이다** — 나머지 한 편을 나중에 다시 묻지 않는다(4.1-3). 화면은 한 편만 매기고 보내기 전에 이를 알 필요는 없다 |
| 전송 성공 | 팝업 닫힘. 토스트 없음(가벼운 상호작용) |
| 전송 실패 | 인라인 에러 + 재시도. 오프라인이면 큐에 넣어 재전송(7일 접수 기간 안) |
| 그만 보기 | 즉시 닫힘. 서버 저장 실패 시에도 이번 세션은 닫아 두고 재시도 |

## 7. 예외 상황

- **편성분이 한 번도 없음**(가입 첫날 등): `show=false`. 팝업 없음.
- **어제만 편성이 없었음**(재고 스킵·고갈): 그 전 마지막 편성분을 아직 묻지 않았으면 그것을 묻고, 이미 물었으면 `show=false`다(4.1-2·3 — 기준은 "어제"가 아니라 "오늘 전 마지막 편성분"이다).
- **가장 최근 편성분을 이미 삭제함**: 묻지 않는다(4.1). 삭제는 그 자체가 반응이다.
- **아직 안 들은 편**: 그래도 묻는다 — "추천이 마음에 드는가"는 듣기 전에도 답할 수 있고, 안 들은 것 자체가 정보다. 화면은 `library_status`로 "아직 안 들음"을 보조 표시할 수 있다.
- **회수된 콘텐츠**: 편성분 행은 남으므로 묻힐 수 있다. 회수 콘텐츠는 목록에서 숨겨지듯 팝업에서도 뺀다 — 서버가 `contents.status`를 보고 제외한다(구현 시 확인 — 미결).
- **탈퇴**: `drip_feedbacks`는 즉시 파기(`domain.md` 12.3).

## 8. 완료 조건

- Given 가장 최근 정규 편성분(보통 어제) 2편을 받고 아직 그 편성분을 묻지 않은 사용자 / When 앱에 진입한다 / Then `show=true`와 2편이 오고 팝업이 뜬다
- Given 그중 1편만 별점을 보냈다(또는 닫았다) / When 다시 진입한다 / Then 새 편성이 없으면 묻지 않는다
- Given 며칠 안 열어 편성분이 여러 날 쌓였다 / When 진입한다 / Then 가장 최근 편성분 2편만 한 번 묻는다
- Given 알고리즘 버전이 올라간 뒤 / When 이전 버전 편성분(7일 안)에 별점을 보낸다 / Then 이전 버전 행에 쌓인다
- Given [이번 주 그만 보기]를 눌렀다 / When 이번 주 안에 다시 진입한다 / Then 팝업이 뜨지 않고, 다음 주 월요일 04:00 이후 다시 뜬다
- Given 별점을 보냈다 / When 어드민 버전 표를 본다 / Then 그 편성분의 알고리즘 버전 행에 평가 수·평균이 반영된다
- Given 편성 배치가 돈다 / Then 적립된 행에 `algorithm_version`이 남는다
- Given 스코어링 가중치를 바꾸는 PR / Then `DRIP_ALGORITHM_VERSION`이 올라간다(체크리스트)

## 미결 사항

- 회수된 콘텐츠의 팝업 제외 처리(7장) — 구현 시 `contents.status`로 거를지 확정
- 탐험 편 별점을 따로 묻는 화면(별도 문구)을 둘지 — 지금은 정규만
- 팝업 세션 내 1회 규칙·카피 확정 → `spec/uiux/library-uiux.md` 개정(FE 티켓)
