# 드립 편성 · 추천 기능 명세서

> 연결 PRD: FR-14 ~ FR-19, FR-05 / 사용자흐름 5.2·5.6 / 검증계획 9.1·9.2

## 1. 목적 & 연결

"앱을 열면 들을 것이 준비되어 있는" 경험(PRD 1.3)을 만드는 엔진. 콘텐츠 자체는 전 사용자 동일하므로, **개인화는 전부 여기서 일어난다**(무엇을 언제 누구에게 보여줄지 — PRD 1.3 "피드 레벨 개인화").

- FR-14 (P0) 관심사 기반 콘텐츠를 정해진 편수로 라이브러리에 자동 적립. **정규 2편과 별개로 탐험 1편("이런 주제는 어떠신가요?")을 추가 편성**(개정 2026-08-27 — 4.8)
- FR-15 (P0) 소비 신호(완청·저장·삭제)를 편성·추천 갱신에 반영 (스킵 신호는 폐기 — 개정 2026-08-10). **스코어링은 대본 임베딩 유사도 + 신호 기반 선호 + 메타데이터 규칙의 3축 하이브리드로 고도화**(개정 2026-08-26 — 4.2)
- FR-16 (P0) 동일 콘텐츠 중복 적립 방지
- FR-17 (P0) 신규 사용자 콜드스타트 — 인기·신규 기반 대체 편성
- FR-18 (P1) 주제 고갈 감지 시 인접·심화 주제 자동 확장(백그라운드, 사용자 비노출)
- FR-19 (P1) 드립 도착 푸시 → `notification.md`
- FR-05 (P0) 관심사 변경 반영 → `interest-management.md`

**사용자에게 로직이 노출되지 않는 백그라운드 기능이다**(PRD 5.6).

## 4. 처리 로직

### 4.1 편성 대상 판정 (FR-14)

```
if active_interests == 0   → 편성하지 않음 + 라이브러리에 관심사 추가 안내
else                       → 편성 실행 (편수 = plans[tier].daily_drip_count)
```

- `active_interests == 0` 분기는 **방어적 처리다(정상 경로에서는 도달 불가)** — 온보딩·관심사 관리 모두 최소 1개를 강제한다(`onboarding.md` 3, `interest-management.md` 4.2). 합의로 explore의 같은 시나리오도 삭제됐다.
- **티어로 편성 대상을 가르지 않는다.** 무료(라이트) 티어도 드립을 받는다(PRD FR-14). 초기 정책이던 "무료: 드립 없음"은 폐기됐다.
- **전 티어 하루 2편으로 확정**이다(PRD 1.3·FR-14). 티어는 드립 편수가 아니라 재생 한도를 가른다. 조정이 필요하면 `plans.daily_drip_count` 값만 바꾸면 된다 — 편수는 티어별 차등값이 아니라 **배포 없이 조정할 정책값**이라 컬럼에 둔다(`domain.md` 8.1).
- 편성은 **미청취 재고를 고려한다**: 라이브러리에 미청취 콘텐츠가 일정 수(기준값: 5편) 이상 쌓여 있으면 그날 적립을 건너뛴다.
  - 이유: 계속 쌓이기만 하면 라이브러리가 부담스러워지고 완청률(PRD 10 핵심 지표)이 떨어진다.

### 4.2 후보 선정

1. **필터** — 아래를 모두 만족하는 콘텐츠만 후보
   - `status == published`
   - 라이선스 유효 기간 내
   - 회수되지 않음 (FR-32)
   - `topic_ids`가 사용자의 활성 관심 주제와 교집합
   - **중복 방지**(FR-16) — 아래 두 조건 중 하나라도 해당하면 제외한다
     ```
     library_items 에 행이 존재 (deleted_at 여부 무관)
     OR drip_excluded_contents 에 행이 존재
     ```
     `drip_excluded_contents`에는 담기 해제(`unsave`) · 라이브러리 삭제(`library_delete`) · 재생(`played`) · 드립 적립(`dripped`)이 모두 적재되므로, 위 두 줄이 "이미 라이브러리에 있거나 / 들은 적 있거나 / 한 번 준 적 있는" 세 조건을 전부 덮는다
     - **삭제 경로를 구분하지 않는다.** 라이브러리 삭제든 탐색 담기 해제든 결과는 동일하게 영구 제외다
2. **스코어링** — 후보에 점수를 매긴다. **세 축의 가중 합**이다(고도화 2026-08-26 — 대본 임베딩만으로는 수준·형식·수명 같은 속성을 구분하지 못하고, 룰만으로는 주제 경계를 넘는 내용 유사성을 잡지 못한다. 서로 다른 것을 재는 축을 결합한다).

```
score = w_e × [① 임베딩 유사도 축] + w_s × [② 신호 선호 축] + w_m × [③ 메타 규칙 축]
```

- 각 축의 점수는 0~1로 정규화해 합산한다. 축 결합 가중치(`w_e`·`w_s`·`w_m`)와 축 내 항목 가중치의 초기값은 서버 구현이 소유하며 시범 운영 데이터로 튜닝한다(미결 사항 — 계수를 문서에 박으면 튜닝마다 문서 개정이 필요해진다. `explore.md` 4.5-5와 같은 원칙).
- **입력이 없는 축은 빼고 나머지 축의 가중치를 재정규화한다.** 임베딩·추천 메타가 NULL인 콘텐츠(`domain.md` 5.1·5.6 — 파이프라인 미경유)나 취향 벡터가 없는 사용자도 후보에서 탈락하지 않는다 — 축 하나가 비었다고 편성이 막히면 안 된다.
- 축 구분은 문서상의 정리이며, 구현이 세 함수로 쪼개질 필요는 없다.

**① 임베딩 유사도 축** — 대본 내용의 의미적 근접 (신설 2026-08-26)

| 요소 | 방향 |
|---|---|
| 취향 벡터 유사도 | 사용자 취향 벡터(4.3-1)와 콘텐츠 임베딩(`content_embeddings`)의 **코사인 유사도**. "완청한 것과 비슷한 내용"을 주제·키워드 경계와 무관하게 잡는다 |

**② 신호 기반 선호 축** — `user_signals` 집계(`user_preference_vectors`)에서 학습된 취향의 룰 반영

| 요소 | 방향 |
|---|---|
| 주제·저자·출처 선호 | 완청한 콘텐츠와 유사한 주제·저자·출처에 가점 (기존 "신호 기반 선호") |
| 키워드 일치 | 완청·저장 콘텐츠의 세부 키워드와 후보의 `contents.keywords` 교집합에 가점 (신설 2026-08-26) — 주제(수십 개 단위)가 놓치는 세밀한 취향을 룰 축에서 잡는다 |
| 형식 선호 | 완청이 잦은 콘텐츠 형식(`contents.format`)에 가점 (신설 2026-08-26) |
| 길이 선호 | 완청 길이 분포(`duration_pref`)에 가까운 `duration_sec`에 가점 (신설 2026-08-26 — 스키마 변경 없음) |
| 부정 신호 회피 | 담기 해제·삭제가 잦았던 주제·저자·키워드에 감점 (스킵 감점은 신호 제거로 폐기 — 이탈 기반 감점 재도입 여부는 미결) |

**③ 메타데이터 규칙 축** — 프로필·콘텐츠 속성 기반 규칙 (소비 이력 학습과 무관하게 동작 — 콜드스타트에서도 살아 있는 축)

| 요소 | 방향 |
|---|---|
| 주제 적합도 | 사용자 관심 주제와의 일치도. 여러 관심 주제에 걸치면 가점 |
| 신선도 | `published_at`이 최근일수록 가점. **`is_evergreen`으로 정밀화**(개정 2026-08-26): 시의성 콘텐츠(`false`)는 감쇠를 세게, 에버그린(`true`)은 오래돼도 감점하지 않음. NULL은 종전 단일 감쇠 유지 |
| 인기도 | `content_stats(period_type = all)`의 완청률·재생 수 가점 (콜드스타트에서 비중 확대). **완청률은 베이지안 스무딩을 거친다**(개정 2026-08-27): `(완청수 + C×전체 평균 완청률) / (재생수 + C)` — 표본이 작을수록 전체 평균으로 끌어당겨, 재생 3회·완청 3회(100%)가 재생 1,000회·완청 850회(85%)를 이기는 왜곡을 막는다. 상수 `C`는 서버 구현이 소유 |
| 커리어 적합도 | 직군·연차와 맞는 콘텐츠에 소폭 가점 |
| 난이도 적합도 | 콜드스타트는 `difficulty = beginner` 우선(4.4 — 확정 2026-08-26). 이후에는 완청 이력의 난이도 분포와 매칭 (신설 2026-08-26) |
| 시리즈 연속성 | 이미 1편을 완청한 시리즈의 다음 편에 강한 가점 |
| 노출 피로 | 최근 편성에서 반복된 주제에 감점 |

3. **다양성 제약** — 2편을 뽑을 때 같은 주제·같은 저자만 나오지 않도록 한다
   - **임베딩이 있으면 MMR로 판정한다**(개정 2026-08-27): 첫 편은 스코어 최상위, 다음 편은 `스코어 − λ × (이미 뽑은 편과의 임베딩 코사인 유사도 최댓값)`으로 재계산해 뽑는다. "주제는 다른데 내용이 사실상 같은 두 편"을 이산 규칙(주제·저자 비교)이 못 잡기 때문이다. `λ`는 서버 구현이 소유
   - 어느 한 편이라도 임베딩이 없으면 그 비교는 종전 이산 규칙(같은 주제·같은 저자 금지)으로 폴백한다
   - 단 시리즈 연속 편은 예외(1편 완청 → 2편 적립이 자연스럽다) — MMR 감점도 적용하지 않는다
   - 탐험 편(4.8)도 MMR 비교 대상에 포함한다 — 정규 2편과 내용이 겹치는 탐험 편은 탐험의 목적에 반한다

### 4.3 소비 신호 반영 (FR-15)

| 신호 | 해석 | 반영 |
|---|---|---|
| complete (완청) | 강한 긍정 | 해당 주제·저자·출처 가중치 상승 |
| save (담기) | 긍정 | 주제 가중치 상승 (완청보다 약하게) |
| unsave / 라이브러리 삭제 | 부정 | 해당 콘텐츠 재적립 **영구 제외**(`drip_excluded_contents` 적재) + 주제 소폭 감점 |
| 재청취 | 강한 긍정 | 주제·저자 가중치 상승 |

- 신호는 **최근성 가중**을 둔다(오래된 신호일수록 영향 감소).
- 반영 주기: 편성 배치 시점에 최신 신호를 읽어 계산한다. 실시간 재계산은 하지 않는다. 집계 결과는 `user_preference_vectors`에 캐시되며, 탐색 피드 랭킹(4.7)도 같은 캐시를 읽는다.
- **신호 해석 표는 고도화(2026-08-26)로 바뀌지 않았다.** 바뀐 것은 집계의 출력이다 — 주제·저자 가중치에 더해 **키워드·형식 가중치, 길이 분포, 취향 벡터(4.3-1)** 를 함께 산출한다(`domain.md` 7.2). 추천 메타가 NULL인 콘텐츠는 해당 집계에서 제외한다.
- **스킵 신호는 제거됐다**(확정 2026-08-10 — `player.md` 4.4, README 결정 36). 종전 "play 후 skip(20% 미만 이탈) = 부정" · "중간 이탈(20~90%) = 약한 중립" 행을 폐기했고, 부정 신호는 `unsave`·`delete`가 맡는다. **초반·중간 이탈을 감점에 다시 쓸지는 미결**이다 — 쓴다면 원천은 신호가 아니라 `playback_progresses.max_reached_sec`(상태)이며, 채택 시 이 표와 4.2 스코어링 표에 항목을 되살린다(미결 사항 참조).

### 4.3-1 취향 벡터 도출 (신설 2026-08-26)

임베딩 유사도 축(4.2 ①)의 사용자 쪽 입력이다. `user_preference_vectors.taste_embedding`에 캐시한다.

```
taste_embedding = normalize( Σ 최근성가중(신호) × embedding(콘텐츠) )
                  단, 신호 ∈ { complete, save, replay } 이고 해당 콘텐츠에 임베딩이 있는 것만
```

- **긍정 신호만 쓴다.** `unsave`·`delete`를 벡터에서 빼는 연산은 하지 않는다 — 부정 취향의 반영은 룰 축(4.2 ②의 부정 신호 회피)이 담당한다. 벡터 뺄셈은 결과를 해석 불가능하게 만들고, 같은 부정을 두 축이 이중 반영하게 된다.
- 최근성 가중은 4.3의 신호 가중과 같은 감쇠를 쓴다.
- 갱신 주기도 4.3과 같다 — 편성 배치 시점 재계산, 실시간 없음.
- 긍정 신호 콘텐츠에 임베딩이 하나도 없으면 `taste_embedding = NULL`이고, 스코어링은 임베딩 축을 제외한다(4.2의 재정규화 규칙).

### 4.4 콜드스타트 (FR-17)

신호가 부족한 사용자(기준값: 완청 3건 미만)에게 적용한다.

- 스코어링에서 **인기도·신선도 비중을 높이고**, 신호 기반 항목은 사실상 0으로 둔다 — 임베딩 유사도 축(4.2 ①)·신호 선호 축(②)은 취향 벡터·신호가 없으므로 자연히 빠지고, 메타 규칙 축(③)만으로 스코어링된다(4.2의 재정규화 규칙과 같은 동작)
- 선택한 관심 주제 안에서 **입문·개괄 성격의 콘텐츠를 우선**한다 — `contents.difficulty = beginner` 우선 (**확정 2026-08-26** — 난이도 태그가 추천 메타로 신설되며 종전 미결 해소. `difficulty` NULL 콘텐츠는 우선도 중립)
- 온보딩에서 담은 콘텐츠가 있으면 그 주제를 우선 신호로 사용한다
- 완청 3건이 쌓이면 일반 스코어링으로 전환한다

### 4.5 주제 고갈 감지 · 자동 확장 (FR-18, P1)

**고갈 판정**

- 사용자의 활성 관심 주제 안에서 **적립 가능한 후보가 임계치 미만**(기준값: 5편 — 4.1의 미청취 재고 상한 5편과는 **별개의 값**이다, 우연히 같은 숫자)으로 떨어진 상태
- 또는 편성 배치에서 목표 편수를 채우지 못한 날이 연속 2회 발생

**확장 처리**

1. `auto_expand_enabled == false`인 사용자는 대상에서 제외한다(FR-06)
2. 인접 주제를 선정한다
   - 주제 간 인접 관계(공동 소비 기반 또는 사전 정의 그래프)에서 가까운 주제
   - 사용자가 직접 해제한 주제(`user_removed = true`)는 제외
3. 선정된 주제를 `UserInterest(source = auto_expand)`로 추가한다
4. **사용자에게 알리지 않는다**(FR-18 "사용자 노출 없는 백그라운드 처리"). 다만 관심사 관리 화면에서는 "자동 추가됨" 배지로 확인할 수 있다
5. 확장으로도 후보가 없으면 **운영 콘솔에 주제별 콘텐츠 부족을 알린다.** 자동 파이프라인이 P1 이연이므로 MVP에서는 팀이 직접 해당 주제 콘텐츠를 제작·업로드한다(FR-37)

**확장 상한**: 1회 배치당 최대 1개 주제. **자동 추가분도 관심 주제 총량 상한(3개)에 포함해 센다**(`interest-management.md` 4.3과 동일 — 결과적으로 3개 미만 보유자에게만 동작하며 자동 추가는 최대 2개).

### 4.6 적립 실행

1. 선정된 콘텐츠로 `library_items(source = drip, status = unplayed)` 생성
2. `drip_excluded_contents(reason = dripped)` 적재 — 재적립 방지 근거. **`DripSchedule` 테이블은 폐기됐다**(편성 이력은 `library_items.source = drip`으로 확인한다)
3. 편성 완료 이벤트 → 푸시 발송 대상에 등록 (`notification.md`) — **(FR-19, P1 — 미도입 시 이 단계 생략)**
4. 적립은 **원자적**으로 처리한다. 2편 중 1편만 적립되는 상태를 만들지 않는다
5. 배치 중복 실행은 `drip_batch_runs.run_date` 유니크로, 사용자 단위 중복은 `library_items (user_id, content_id)` 유니크로 막는다

### 4.7 탐색 추천과의 관계

- 탐색 피드 랭킹(`explore.md` 4.1)은 같은 스코어링 함수를 재사용하되, **중복 방지 필터를 적용하지 않는다**(이미 담은 콘텐츠도 노출하되 표시만 다르게 함)
- 드립은 "2편을 골라 밀어주는 것", 탐색은 "순위대로 보여주는 것"으로 목적이 다르다

### 4.8 탐험 편성 — "이런 주제는 어떠신가요?" (신설 2026-08-27)

정규 편성(취향 최적화)만 돌리면 두 가지가 굳는다: **신규·저노출 콘텐츠는 통계가 없어 편성이 안 되고 → 통계가 영영 안 쌓이며**(콘텐츠 콜드스타트), 사용자 신호도 "듣던 것과 비슷한 것"으로만 쌓여 3축 스코어링의 학습 재료가 좁아진다(필터 버블). 이를 풀기 위해 **정규 2편과 별개로 매일 1편을 탐험 슬롯으로 추가 편성한다**(협의 2026-08-27).

**사용자에게 정규 드립과 구분해 보여준다** — 취향 밖 콘텐츠가 정규 드립에 섞이면 "나 이런 거 관심 없는데 왜 왔지?"가 되므로, 라이브러리의 [이어 PICK] 필터 뷰에서는 **"이런 주제는 어떠신가요?" 구획**으로, 전체 목록에서는 **행 배지**로 구분한다(확정 2026-08-27 — 표시 규칙은 `library.md` 4.6-1이 소유, 카피 확정은 spec/uiux 개정 시).

**편수** — `plans.daily_discovery_count`(전 티어 1편 — `domain.md` 8.1). 정규 편수(`daily_drip_count`)와 같은 이유로 배포 없이 조정할 정책값이다.

**후보 선정** (혼합 — 협의 2026-08-27)

1. **주제 범위**: 활성 관심 주제 **밖**(인접 주제 — `topic_adjacencies`, 그래프 구축 전에는 공개(`is_visible = true`) 주제 전체) 콘텐츠를 우선하되, **관심 주제 안의 저노출 콘텐츠도 후보에 포함**한다. 4.2 필터의 "관심 주제 교집합" 조건만 예외이고 **나머지 필터(발행·라이선스·회수·중복 방지)는 동일 적용**한다.
2. **저노출·신규 우선**: 전 사용자 기준 편성 이력이 적거나 `published_at`이 최근인 콘텐츠에 가점 — 이 슬롯의 존재 이유다.
3. **품질 최소선**: 스무딩 완청률(4.2 ③)이 하한 미만인 콘텐츠는 제외한다 — 탐험 슬롯이 "안 듣는 콘텐츠 처리장"이 되면 타이틀의 신뢰가 죽는다. 하한·구체 선정식은 서버 구현이 소유한다.
4. 사용자가 직접 해제한 주제(`user_removed = true`)의 콘텐츠는 후보에서 제외한다.

**정규 편성과의 관계**

- 미청취 재고 스킵(4.1 — 5편 이상)에 **탐험 편도 함께 스킵**되고, 재고 계산에도 포함된다. 재고 부담을 줄이려는 규칙을 탐험이 우회하면 안 된다.
- 적립·중복 방지·삭제 규칙은 정규 드립과 동일하다 — `library_items(source = discovery)`로 적립하고(`domain.md` 6.1), `drip_excluded_contents(reason = dripped)`를 적재하며, 삭제 시 영구 제외도 같다.
- **원자성은 정규 2편끼리만이다**(4.6-4). 탐험 1편은 정규 편성 뒤에 별도로 처리하고, 실패해도 정규 편성을 롤백하지 않는다 — 부가 슬롯이 본편을 막으면 안 된다.
- 콜드스타트 사용자(4.4)에게도 동일 적용한다.
- **`auto_expand_enabled` 토글과 무관하다.** 토글이 다스리는 것은 관심 주제의 **자동 추가**(FR-18·FR-06)이고, 탐험 편성은 주제를 추가하지 않고 콘텐츠 1편을 보여줄 뿐이다.
- 탐험 편의 소비 신호는 정규와 동일하게 스코어링에 반영된다 — 탐험으로 나간 인접 주제 콘텐츠의 완청이 쌓이면 자동 확장(4.5)의 근거 데이터도 된다. 탐험은 씨앗이고 확장은 수확이다.

## 5. 상태 전이 · 운영 노출

**편성 배치 상태**

```
scheduled → running → completed
                   → partial   (일부 사용자 실패)
                   → failed    (배치 전체 실패)

사용자 단위: pending → candidates_selected → items_created → notified (P1 — 푸시 미도입 시 completed 종료)
                    → skipped (관심사 0 / 재고 충분 / 탈퇴)
                    → no_candidates (고갈)
```

- **`notified` 종단은 P1(FR-19 푸시)이다.** 푸시 미도입 시 사용자 단위 처리는 `items_created`에서 끝나고 배치는 `completed`로 종료한다(4.6-3의 발송 등록 단계 생략과 정합).

- **`skipped` 사유에 티어가 없다.** 무료(라이트) 티어도 편성 대상이다(4.1). 티어는 `plans.daily_drip_count`로 **편수만** 가르며, 편성 여부를 가르지 않는다.

**사용자 앱에서 보이는 것**

| 상황 | 앱 표현 |
|---|---|
| 정상 편성 | 라이브러리에 새 아이템 + "새 콘텐츠 N개 도착" 배너 |
| 탐험 편성 (4.8 — 신설 2026-08-27) | [이어 PICK] 필터 뷰에서 **"이런 주제는 어떠신가요?" 구획**으로 분리, 전체 목록에서는 행 배지(`library.md` 4.6-1). 도착 배너는 기존 "새 콘텐츠 N개 도착" 하나에 합산 — 전용 배너 없음 |
| 재고 충분으로 건너뜀 | 아무 표시 없음 |
| 후보 없음(고갈) | "콘텐츠를 준비하고 있어요" 안내(`library.md` 5와 통일) + [관심 주제 추가하기]. **FR-18의 "사용자 비노출"은 자동 확장 동작에 한한다 — 이 배너는 별개 안내다**(합의 2026-08-06) |
| 편성 실패 | "콘텐츠를 준비하고 있어요" (실패를 노출하지 않음) |

**운영 콘솔**

| 항목 | 내용 |
|---|---|
| 배치 실행 현황 | 대상 수 / 성공 / 건너뜀 / 실패, 소요 시간 |
| 고갈 사용자 수 | 자동 확장 발생 건수, AI 생성 요청 건수 |
| 편성 품질 | 드립 콘텐츠 재생률·완청률 (PRD 10 "추천 콘텐츠 재생률") |
| 추천 입력 결손 (신설 2026-08-26) | 임베딩·추천 메타 미부여 콘텐츠 수, 재발행 후 임베딩 미갱신 건수(`content_embeddings.content_version` ≠ `contents.content_version`) — 메타데이터 부여 파이프라인(`ai/metadata-pipeline.md`) 재실행 대상 목록이 된다 |

## 7. 예외 상황

- **관심 주제에 해당하는 콘텐츠가 아예 없음**(초기 콘텐츠 풀 부족 — PRD 8.1): 자동 확장(P1) 도입 전까지는 **그날 적립을 건너뛴다**(합의 2026-08-06 — 인기 대체 편성은 신규 사용자 콜드스타트(FR-17) 전용이다). 사용자 안내는 라이브러리 배너(5장)가 맡는다.
- **적립하려는 콘텐츠가 편성 직후 회수됨**: 회수 처리가 `LibraryItem`을 제거한다. 그날 재편성은 하지 않는다(다음 배치에서 채워진다).
- **관심사를 방금 변경한 사용자**: 오늘 이미 편성이 확정된 건은 그대로 둔다(`interest-management.md` 4.3).
- **사용자가 드립 콘텐츠를 삭제**: 재적립하지 않는다(FR-16, `library.md` 4.5). 소프트 삭제 레코드가 근거다.
- **같은 콘텐츠가 드립과 사용자 담기로 동시 적립**: `(user_id, content_id)` 유니크로 1건만 남는다.
- **배치 도중 실패**: 사용자 단위로 처리해 실패한 사용자만 재시도한다. 전체 롤백하지 않는다.
- **배치가 중복 실행됨**: `drip_batch_runs.run_date` 유니크(배치 단위) + `library_items (user_id, content_id)` 유니크(사용자 단위)로 멱등 처리해 하루에 두 번 적립되지 않게 한다(4.6-5).
- ~~**결제 직후 편성 + 당일 정기 배치**: 하루 상한을 초과하지 않도록 같은 날짜 카운트를 공유한다.~~ → **폐기** — 결제 완료는 더 이상 편성 트리거가 아니다(2장. 편수는 전 티어 동일 — 4.1).
- **자동 확장으로 추가된 주제가 사용자 취향과 전혀 안 맞음**: 부정 신호(담기 해제·삭제)로 가중치가 떨어지고, 사용자가 직접 해제하면 재추가되지 않는다.
- **시리즈 중간 편만 후보에 남음**: 1편을 듣지 않은 사용자에게 3편을 적립하지 않는다. `episode_no` 순서를 지킨다.
- **미청취 재고가 계속 쌓여 몇 주간 편성이 건너뛰어짐**: 사용자가 이탈 중일 가능성이 높다. 리텐션 대응은 별도 과제로 두되, 편성 로직에서는 계속 건너뛴다.
- **탈퇴한 사용자**: 배치 대상에서 제외.
- **임베딩·추천 메타가 없는 콘텐츠**(파이프라인 미경유·재발행 후 미갱신): 후보에서 제외하지 않는다. 해당 축·항목만 빼고 스코어링한다(4.2). 임베딩의 재발행 후 미갱신은 `content_embeddings.content_version` 대조로 검출해 운영 콘솔에 노출한다(5장).
- **임베딩 모델이 교체됨**: 구·신 모델 벡터를 섞어 스코어링하지 않는다. 전량 재생성이 끝날 때까지 배치는 임베딩 축을 통째로 제외한다(`domain.md` 5.6).

## 8. 완료 조건

- Given 관심 주제 2개를 가진 유료 사용자 / When 일일 편성 배치가 실행된다 / Then 관심 주제에 해당하는 콘텐츠가 최대 2편 라이브러리에 적립된다
- Given 관심 주제 2개를 가진 **무료(라이트) 티어** 사용자 / When 일일 편성 배치가 실행된다 / Then **`plans.daily_drip_count`에 따라 하루 2편이 적립된다** — 티어는 편수만 가르고 편성 여부를 가르지 않는다(4.1)
- Given 온보딩에서 추천 콘텐츠를 **하나도 담지 않은** 무료 티어 신규 사용자 / When 자동 드립 트리거가 발동한다 / Then 무료 티어여도 편성이 실행되어 완료 화면 전에 라이브러리가 채워진다(`onboarding.md` 4)
- Given 이미 라이브러리에 있는 콘텐츠 / When 편성이 실행된다 / Then 해당 콘텐츠는 후보에서 제외되어 중복 적립되지 않는다
- Given 드립으로 받았다가 삭제한 콘텐츠 / When 다음 편성이 실행된다 / Then 다시 적립되지 않는다
- Given 미청취 콘텐츠가 5편 이상 쌓인 사용자 / When 배치가 실행된다 / Then 그날 적립은 건너뛰어진다
- Given 완청 신호가 3건 미만인 신규 사용자 / When 편성이 실행된다 / Then 인기·신규 기반 콜드스타트 편성이 적용된다
- Given 특정 주제 콘텐츠를 3회 연속 완청한 사용자 / When 다음 편성이 실행된다 / Then 해당 주제 콘텐츠의 편성 비중이 높아진다
- Given 특정 저자 콘텐츠를 반복해서 삭제(또는 담기 해제)한 사용자 / When 다음 편성이 실행된다 / Then 해당 저자 콘텐츠의 편성 비중이 낮아진다
- Given 관심 주제의 후보 콘텐츠가 5편 미만으로 떨어졌다 / When 배치가 실행된다 / Then 인접 주제가 자동으로 추가되고 사용자에게는 알림이 가지 않는다
- Given 자동 확장 토글을 끈 사용자 / When 주제가 고갈된다 / Then 주제가 자동 추가되지 않는다
- Given 시리즈 1편을 완청한 사용자 / When 다음 편성이 실행된다 / Then 같은 시리즈 2편이 우선 적립된다
- Given 편성 배치가 같은 날 두 번 실행된다 / When 두 번째 실행이 끝난다 / Then 하루 적립 편수가 상한을 넘지 않는다
- Given 관심 주제가 0개인 사용자(방어적 처리 — 정상 경로에서는 도달 불가, 4.1) / When 배치가 실행된다 / Then 편성이 실행되지 않는다
- Given 완청 이력이 충분한 사용자와, 완청한 콘텐츠들과 대본 내용이 유사한(취향 벡터 코사인 유사도가 높은) 미청취 후보 / When 편성이 실행된다 / Then 주제·키워드가 겹치지 않아도 해당 후보의 스코어가 임베딩 유사도 축만큼 높아진다 (신설 2026-08-26)
- Given 임베딩·추천 메타가 모두 NULL인 발행 콘텐츠 / When 스코어링이 실행된다 / Then 해당 콘텐츠는 후보에서 탈락하지 않고, 빠진 축·항목을 제외한 나머지 가중치가 재정규화되어 점수가 계산된다 (신설 2026-08-26)
- Given 특정 형식(`format`)의 콘텐츠만 반복 완청한 사용자 / When 다음 편성이 실행된다 / Then 같은 형식 후보의 편성 비중이 높아진다 (신설 2026-08-26)
- Given 콜드스타트 사용자와 같은 주제의 `difficulty = beginner` · `advanced` 후보 / When 편성이 실행된다 / Then `beginner` 후보가 우선 적립된다 (신설 2026-08-26)
- Given `is_evergreen = false`(시의성)이고 발행 6개월이 지난 콘텐츠와, 같은 조건의 에버그린 콘텐츠 / When 스코어링이 실행된다 / Then 시의성 콘텐츠의 신선도 감점이 에버그린보다 크다 (신설 2026-08-26)
- Given 재생 3회·완청 3회인 콘텐츠와 재생 1,000회·완청 850회인 콘텐츠 / When 인기도를 계산한다 / Then 스무딩 완청률은 후자가 더 높다 (신설 2026-08-27)
- Given 정규 편성이 완료된 사용자 / When 같은 배치에서 탐험 편성이 실행된다 / Then 정규 2편과 별개의 1편이 `library_items(source = discovery)`로 적립되고, 라이브러리에서 정규 드립과 구분 표시된다([이어 PICK] 뷰 구획·전체 목록 배지 — `library.md` 4.6-1) (신설 2026-08-27)
- Given 활성 관심 주제가 '재테크'뿐인 사용자 / When 탐험 편성이 실행된다 / Then 관심 주제 교집합 필터를 우회한 후보(관심 밖 주제 또는 관심 주제 안 저노출 콘텐츠)가 선정되고, 나머지 필터(발행·라이선스·중복 방지)는 동일하게 적용된다 (신설 2026-08-27)
- Given 미청취 재고가 5편 이상인 사용자 / When 배치가 실행된다 / Then 정규 편성과 함께 탐험 편성도 건너뛰어진다 (신설 2026-08-27)
- Given 탐험 편성이 실패한 배치 / When 배치가 끝난다 / Then 정규 2편의 적립은 롤백되지 않고 유지된다 (신설 2026-08-27)
