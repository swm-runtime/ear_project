# 탐색 · 검색 기능 명세서

> 연결 PRD: FR-21, FR-22, FR-15, FR-27 / 사용자흐름 5.3

## 1. 목적 & 연결

드립으로 받는 것 외에 사용자가 직접 콘텐츠를 발견하고 담을 수 있는 능동 경로. 무료(라이트) 사용자의 주 사용 경로이기도 하다 — 무료도 드립을 받지만 재생이 하루 2편으로 제한되므로, **담기 무제한인 탐색이 실질적인 소비 경로**가 된다(PRD 4.1).

- PRD FR-21 (P0) 추천 피드·주제 필터로 발견하고 담기. 담기는 무제한
- PRD FR-22 (P0) 키워드 검색 — **MVP 포함으로 격상**(합의 2026-08-23, 4.5)
- PRD FR-15 (P0) 소비 신호를 추천에 반영
- PRD FR-27 (P1) OS 공유 시트로 공유 — **MVP 제외 확정**(합의 2026-08-06, 4.6)
- PRD 사용자흐름 5.3

## 2. 진입 조건

- 하단 탭에서 [탐색] 선택
- 라이브러리 빈 상태에서 [탐색 둘러보기] 탭

## 3. 입력값

**피드 조회**

| 값 | 설명 | 필수 |
|---|---|---|
| user_id | 토큰에서 도출 | 필수 |
| topic_filter | 주제 id 목록 | 선택 |
| cursor | 페이지네이션 커서 | 선택 |

**검색 (FR-22)**

| 값 | 설명 | 필수 |
|---|---|---|
| query | 키워드 | 필수, 2자 이상 |
| topic_filter | 주제 필터 | 선택 |
| cursor | 페이지네이션 커서(피드와 동일한 20건 단위) | 선택 |

**서버가 피드 응답에 함께 실어 보내는 표시값**

| 값 | 설명 |
|---|---|
| daily_play_limit | `plans.daily_play_limit`. `null`이면 무제한 티어 |
| daily_play_count | 오늘의 서비스 날짜 기준 재생 수. **파생값이며 컬럼이 아니다**(`domain.md` 1.4) |
| service_date | 서버가 계산한 오늘의 서비스 날짜(05:00 KST 경계 — 개정 2026-10-07 — 2026-10-12 05:00 KST 적용, KAN-149) |

- **라이브러리 응답과 같은 값을 같은 이름으로 싣는다**(`library.md` 3). 두 화면이 각자 계산하거나 다른 필드명을 쓰면 같은 사용자에게 서로 다른 숫자가 표시된다.
- **잔여 횟수 전용 API를 따로 두지 않는다.** 피드를 여는 시점이 곧 이 값을 갱신해야 하는 시점이라, 호출을 나누면 화면과 숫자가 어긋나는 구간이 생긴다.
- `service_date`를 서버에서 받는 이유는 **억제 만료 판정(4.4)에 기기 시각을 쓰지 않기 위해서**다.

**사용자 조작**: 행 탭(즉시 재생) / [더보기] > 담기·제거·원문 보기·상세 정보(공유는 P1 — MVP 미노출, 4.6) / 잔여 횟수 표시 탭(소진 시 페이월) / 재생 확인 팝업의 [오늘은 그만 보기]

- **상세 화면 도입 확정(합의 2026-08-23)** — 더보기 시트의 [상세 정보]로 진입한다. 규칙은 `content-detail.md`가 소유하며, **행 본문 탭 = 즉시 재생은 그대로다**(상세는 더보기 경유로만 진입한다).

## 4. 처리 로직

### 4.1 추천 피드 구성

서버가 섹션 단위로 피드를 구성해 내려준다. 섹션 순서·구성은 서버 제어(클라이언트 하드코딩 금지).

| 섹션 | 규칙 |
|---|---|
| 관심사 기반 추천 | 사용자 `UserInterest` + 소비 신호(FR-15) 기반 랭킹 |
| 새로 나온 콘텐츠 | `published_at` 최신순 |
| 인기 콘텐츠 | `content_stats`의 **직전 확정 구간** 재생·완청 수 기준. **사용자가 주간·월간·전체 중 하나를 골라 본다**(합의 2026-08-07 — 4.1-1). 진행 중인 구간을 쓰면 주초·월초에 표본이 부족해 랭킹이 무너진다. **직전 확정 구간이 없는 배포 첫 주에는** 섹션을 숨기지 않고, 표본 크기와 무관하게 같은 선정 기준으로 정렬한 상위를 보여준다(합의 2026-08-06) — 모든 콘텐츠의 값이 같아도 정렬상 앞서는 콘텐츠가 존재한다 |
| 주제별 모아보기 | 사용자 관심 주제별 묶음 |

- 콘텐츠는 **타일**(정사각 아트워크 + 제목 2줄 + 길이)로 나열한다. 섹션형 피드(E1)의 섹션은 가로 캐러셀이고, **주제 필터 결과(4.2)·검색 결과(4.5-3)는 세로로 스크롤되는 두 칸 격자**다(개정 2026-09-18 — `changes/archive/explore-results-thumbnail-grid.md`. 라이브러리 격자 `library.md` 4.1과 같은 모양·같은 정보량). 필터·검색 결과가 가로 캐러셀이 아닌 이유 — 개수가 정해져 있지 않다. 타일에는 담기 버튼을 두지 않는다(4.3)
- **완청 여부의 시각 표식은 두지 않는다**(개정 2026-09-22 — `changes/archive/explore-no-completed-check.md`. 종전 "썸네일 좌상단 체크" 합의 2026-08-07 폐기). 낭독기 라벨에만 "완청"을 전한다. 라이브러리는 진행률 바 100%가 완청을 대신하지만 탐색에는 진행률 바가 없으므로 표식 없이 둔다 — 탐색은 청취 여부와 무관하게 전부 노출하는 화면이고, "다시 들을 필요가 있는가"는 라이브러리 탭 필터가 답한다
- 소비 신호가 부족한 신규 사용자는 인기·신규 섹션 비중을 높인다(콜드스타트, FR-17)
- **이미 라이브러리에 있는 콘텐츠는 피드에서 제외하지 않는다.** 초기 콘텐츠 풀이 작아(PRD 8.1) 제외하면 피드가 비어버린다. **담김 여부는 노출·순서에도, 행 표시에도 나타나지 않는다**(합의 2026-08-07) — 확인 수단은 더보기 시트의 담기/제거 분기 하나다
- 파트너 회수 콘텐츠(FR-32)는 서버 단계에서 제외
- **시리즈 카드**(추가 2026-10-17 — KAN-134, **서버 스위치 `SERIES_EXPLORE_CARDS_ENABLED`가 켜졌을 때만**). 탐색에서 시리즈는 하나의 요소다(결정 2026-10-09) — 켜져 있으면 피드 섹션·주제 필터 결과(4.2)·인기 목록(4.1-1)·검색 결과(4.5)에서 **같은 시리즈 편들이 시리즈 카드 하나로 접힌다**(목록 항목에 `type: "content" | "series"` — `explore-api.md` 4.1-1). 카드 자리는 그 목록의 정렬 규칙을 바꾸지 않고 **그 시리즈 편 중 순위가 가장 높은 편의 자리**이며, 한 목록(페이지를 넘어도)에 한 번이다. 피드는 섹션마다 따로 접는다(같은 시리즈가 두 섹션에 각각 나올 수 있다). 주제 필터·검색은 편 단위로 걸고 접는다 — 맞는 편이 하나라도 있으면 카드가 나온다. 표지는 노출 중인 가장 앞 편(보통 1화)의 썸네일이다. **꺼져 있으면 종전 그대로 편마다 한 줄이다**(행에 `content.series` 정보만 더해진다).
  - **켜는 순서** — 1.2.x 앱은 카드를 그리지 못하므로: ① `dev → main` 배포(스위치 끈 채) → ② 스토어 1.3.0 공개(`runtimeVersion` 36) → ③ 최소 지원 버전 1.3.0 상향(②가 끝나기 전에는 올리지 않는다) → ④ 스위치 켬. 절차는 `explore-api.md` 4.1-1 · `infra/runbook.md`
  - 라이브러리는 시리즈로 묶지 않는다(편 단위 그대로)
  - **카드 표시**(2026-10-19 — KAN-225 코드 반영): 단일 타일과 **같은 크기·같은 자리**에 들어간다 — 사각 타일 줄·두 칸 격자에서는 사각 타일 크기, 인기 섹션 줄에서는 대표 카드 크기. 표지(1화 썸네일) · 시리즈 제목 · `#주제 · N편`(주제는 카드의 `topic_ids` 최대 2개, 편수는 노출 중인 편 수 — 계획보다 적으면 `M/N편`) · 사진 아래 변의 **"시리즈" 글자**(단일 편과 가르는 형태 단서 — 사진 위 알약 배지는 쓰지 않는다). **더보기(⋯)는 없다** — 담기·제거는 편 단위라 시리즈 화면의 편 행이 가진다. 화면 문법은 `explore-uiux.md` 4.11
  - **모르는 항목 종류는 건너뛴다**(`explore-api.md` 4.1-1) — 그 항목만 빠지고 목록은 그대로 그린다. `type` 키가 없는 항목(스위치 꺼짐)은 콘텐츠 행이다

### 4.1-1 인기 콘텐츠의 구간 선택

**인기 섹션만 사용자가 집계 구간을 고른다.** 다른 세 섹션에는 구간 개념이 없다 — 관심사는 소비 신호, 신규는 발행 시각, 주제별은 주제가 축이다.

| 구간 | 대상 |
|---|---|
| 주간 | 직전 확정 주(지난주 월요일 05:00 ~ 이번 주 월요일 04:59) |
| 월간 | 직전 확정 월 — **기본값** |
| 전체 | 누적 집계 |

- **기본값은 월간이다.** 주간은 초기에 표본이 너무 적고, 온보딩 추천이 이미 직전 확정 월을 쓰고 있어(`onboarding.md` 4 [3]) 두 화면의 "인기"가 같은 구간을 보게 된다.
- **주간·월간은 확정된 구간만 쓴다**(`domain.md` 5.4 — `is_final`). **전체 구간에는 이 규칙이 적용되지 않는다** — 끝나는 시점이 없어 확정·진행 중 구분 자체가 없다.
- **배포 첫 주·첫 달에도 탭을 숨기지 않는다.** 확정 구간이 없으면 그 구간의 집계가 전부 비어 동점이 되고, 뒤의 정렬 키(신선도)가 순서를 정한다 — 2026-08-06 합의("섹션을 숨기지 않는다")를 세 구간 각각에 그대로 적용한 것이다. 탭이 조건부로 사라지면 클라이언트가 서버 상태를 추측해야 한다.
- **구간 전환은 인기 섹션만 갈아끼운다.** 피드 전체를 다시 만들지 않는다 — 구간만 바꿨는데 관심사 섹션 랭킹까지 재계산될 이유가 없다(계약은 `spec/api/explore-api.md` 4.2-1).
- **주제 필터를 걸면 섹션 구조가 사라지므로 토글도 사라진다**(4.2). 칩을 전부 해제해 섹션형으로 돌아오면 **직전에 고른 구간을 유지한다** — 되돌아온 화면이 조작 이전과 달라지면 사용자는 무엇이 바뀐 것인지 추적해야 한다.
- **고른 구간은 서버에 저장하지 않는다.** 사용자의 상태가 아니라 화면의 상태다(`paywall.md` 4.2의 억제 플래그와 같은 성격). 유지 범위는 클라이언트가 정한다.

### 4.2 주제 필터

- 상단 가로 스크롤 칩. 사용자의 관심 주제를 앞쪽에 배치하고 나머지 주제를 뒤에 붙인다
- **정렬은 서버가 정해 내려주고 클라이언트는 재배열하지 않는다**(계약은 `spec/api/explore-api.md` 4.2-2). 관심 주제끼리는 **사용자가 선택한 순서**, 나머지는 주제의 노출 순서다
- **숨겨진 주제(`is_visible = false`)는 관심 주제여도 칩에서 제외한다**(결정 2026-08-11 — 숨김 주제는 모든 사용자에게서 제거된다. "숨긴 뒤에도 칩에 남는다"던 합의 2026-08-07을 뒤집었다 — 보유자 예외의 구현 복잡도가 이유다). 관심 주제가 아닌 숨겨진 주제도 당연히 노출하지 않는다(FR-38)
- **발행 콘텐츠가 0건인 주제도 칩으로 노출한다.** 거르면 콘텐츠가 들어올 때마다 칩이 나타났다 사라진다. 고른 결과가 비면 "이 주제의 콘텐츠는 아직 없어요"가 받아 준다
- 필터 선택 시 섹션 구조를 버리고 **단일 행 목록**으로 전환한다
- **칩은 하나만 고른다**(개정 2026-10-09 PM — 종전 다중 선택 OR). 다른 칩을 누르면 그 주제로 전환되고, 고른 칩을 다시 누르면 해제돼 섹션형으로 돌아간다. 서버 계약(`topic_ids` 목록·OR)은 그대로다

### 4.3 담기 · 제거 — 더보기 시트 소유

**담기/제거 버튼은 더보기 시트만 가진다**(합의 2026-08-06). 행에는 담기 버튼이 없고, 행 탭은 재생이다(4.4).

- 담기지 않은 행의 더보기 시트: **[라이브러리에 담기]** → `LibraryItem(source = save)` 생성
- 담긴 행의 더보기 시트: **[라이브러리에서 제거]** — 출처와 무관하게(save·drip·onboarding 모두 — `domain.md` 6.1 source enum) 허용한다
- 시트에는 담기/제거와 함께 **[원문 보기]**를 둔다(확정 2026-08-10 — 라이브러리·플레이어 더보기와 통일). `source_url`이 있는 콘텐츠만 노출하고, 탭하면 인앱 브라우저로 열며 원문 유입 클릭을 기록한다(`player.md` 4.5와 같은 규칙 — `source_link_clicks`)
- **횟수 제한 없음. 무료 티어에서도 페이월을 노출하지 않는다**(PRD 5.4 명시)
- 담기 성공 시 토스트 "라이브러리에 담았어요" + [보러가기]. **행의 모양은 바뀌지 않는다** — 결과는 시트를 다시 열었을 때의 [라이브러리에서 제거]로 확인된다
- 제거는 토스트 없이 시트가 닫히는 것으로 피드백한다. **제거에도 드립 재적립 제외가 적용된다** — 제거는 "관심 없음" 신호이므로 라이브러리 삭제 경로와 동일하게 `drip_excluded_contents`에 적재한다(FR-16)
- **담기 시 서버가 `user_signals(action = save)`를, 제거 시 `unsave`를 적재한다**(FR-15 — `drip-scheduling.md` 4.3의 입력)

### 4.4 행 탭 → 재생 확인 팝업 → 재생

행 탭 = 즉시 재생(PRD 5.3). 담기 여부와 무관하다. 다만 **재생 전에 확인 팝업을 한 번 거친다.**

- **예외 — 시리즈 카드 탭은 재생이 아니라 시리즈 화면을 연다**(추가 2026-10-17 — KAN-134, 스위치 `SERIES_EXPLORE_CARDS_ENABLED`가 켜졌을 때만 카드가 있다 — 4.1). 시리즈 화면(`GET /series/:series_id` — `explore-api.md` 4.7)은 노출 중인 편을 번호순으로 보여주고, 편 행의 탭·담기·삭제는 이 절과 4.3의 편 단위 규칙 그대로다. 카드 자체에는 편 단위 상태(담김·오늘 카운트)가 없다

```
행 탭
   ↓
재생 한도 판정 (paywall.md 4.1~4.2)
   ├─ 한도 소진        → 페이월 바텀시트 (팝업 없음.
   │                     **최상위 티어는 페이월 대신 한도 안내** — paywall.md 4.1)
   ├─ 차감이 발생함
   │     ├─ 오늘 팝업이 억제됨   → 팝업 없이 바로 플레이어
   │     └─ 억제되지 않음        → 재생 확인 팝업 → [재생하기] → 플레이어
   └─ 차감이 없음      → 팝업 없이 바로 플레이어
```

- **팝업 규칙은 `paywall.md` 4.2가 소유한다.** 이 문서는 그것을 탐색 화면에 적용할 뿐이며 조건·문구·버튼을 다시 정하지 않는다.
- **진입점이 다르다고 규칙이 달라지지 않는다**(`paywall.md` 4.2). 라이브러리에서 트든 탐색에서 트든 같은 팝업을 거친다 — 화면마다 다르면 사용자는 탐색이 더 싸다고 오해한다.
- **[오늘은 그만 보기] 억제는 라이브러리와 공유한다.** 라이브러리에서 눌렀으면 탐색에서도 뜨지 않고, 그 반대도 같다. 억제는 **기기 단위 상태**이지 화면 단위가 아니다(`paywall.md` 4.2).
- **탐색에서 재생해도 라이브러리에 담지 않는다**(개정 2026-10-23 PM "시청하면 왜 자동으로 라이브러리에 담겨? 없애") — 라이브러리에 들어가는 길은 사용자의 담기(4.3·시리즈 담기)와 드립뿐이다. 탐색 홈·검색·시리즈 화면·콘텐츠 상세 어디서 틀어도 같다.
  - 재생 위치(`playback_progresses`)는 담김과 무관하게 저장된다 — 나중에 담으면 이어듣기가 그 위치에서 이어진다.
  - ~~탐색에서 재생한 콘텐츠는 라이브러리에 자동 적립한다(`source = save`, 2026-08-06)~~ — 폐기. 완청 상태·`complete` 신호가 라이브러리 행을 전제하는 서버 규칙(`player-api.md` 4.3)의 정리는 `changes/pending/explore-play-no-auto-save.md`.

### 4.4-1 잔여 재생 횟수 표시

**규칙은 `paywall.md` 5장이 소유하고, 이 문서는 탐색 화면에서의 자리만 정한다.** 문구·티어별 노출 조건·갱신 규칙은 그쪽을 따른다.

- 자리는 **iOS 26 시스템 탭 바 갈래에서는 큰 제목 줄("탐색") 오른쪽, 그 외(iOS 26 미만·Android)에서는 검색창 줄의 우측**이다(개정 2026-09-25 — `changes/archive/explore-native-header-search-tab.md`). iOS 26 갈래의 제목 줄은 목록과 함께 스크롤하는 콘텐츠이고, 그 외 갈래에는 라이브러리 같은 앱바가 없어(검색창 + 주제 칩) 배치가 그대로 옮겨오지 않는다.
  - **주제 칩 줄에 넣지 않는다.** 칩은 가로 스크롤이라 숫자가 스크롤을 따라 사라진다. 상시 노출이 목적인 값을 스크롤 영역에 두면 목적을 잃는다.
  - **카드마다 붙이지 않는다.** 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다(`paywall.md` 5장).
- 필터를 걸어 **단일 행 목록으로 전환해도(4.2) 표시는 유지한다.** 검색창 줄은 두 모드 모두에 남아 있다.
- **검색 중의 표시는 갈래로 가른다**(개정 2026-09-27 — `changes/archive/explore-search-shows-remaining.md`. 종전 "검색 화면으로 전환한 동안에는 표시하지 않는다").
  - **제자리 검색 갈래(iOS 26·Android — 4.5-1)는 표시를 유지한다.** 큰 제목 "탐색" 줄 오른쪽에 **[잔여 링 | 닫기 ✕]** 한 캡슐로 둔다. 검색이 탐색 화면 안 제자리로 바뀌면서 제목 줄이 그대로 남고, 검색 필드는 그 밑 줄에서 폭을 다 쓴다 — 숨길 이유(검색창이 그 줄을 다 쓴다)가 사라졌다. 검색 결과에서도 재생을 시작하므로 남은 횟수를 알릴 이유는 피드와 같다.
  - **스택 검색 화면 갈래(iOS 26 미만·웹)는 종전대로 숨긴다.** 검색창이 입력 상태로 그 줄을 다 쓴다. 숨긴 것은 표시이지 규칙이 아니다(7장).
  - 소진 상태의 링 탭은 검색 중에도 피드와 같다(페이월 — 구독 UI 플래그 꺼짐이면 한도 안내, `paywall.md` 4.5).
- **라이브러리와 같은 숫자를 보여야 한다.** 두 화면이 다른 값을 표시하면 어느 쪽이 맞는지 사용자가 판단하게 된다 — 그래서 각자 계산하지 않고 3장의 서버 값을 그대로 쓴다.

### 4.5 검색 (FR-22)

- **MVP 포함으로 격상**(합의 2026-08-23) — 종전 "P1 유지, 검색창 비활성 노출"(합의 2026-08-06)을 폐기한다. 검색창 탭 시 검색 화면으로 전환하며, 아래 규칙이 MVP부터 적용된다.

#### 4.5-1 진입·이탈

- 검색 필드를 탭하면 검색 화면으로 전환하고 키보드를 올린다. **갈래**(개정 2026-09-30): iOS 26·Android는 탐색 피드 위의 **제자리 검색**이다. 제목 "탐색"과 [잔여 링 | 닫기 ✕]를 유지하고 채움 검색 필드·최근 검색어·결과를 표시한다. Android도 탭 바·기존 미니플레이어를 유지한다. iOS 26 미만·웹은 종전 스택 검색 화면이며 잔여 표시는 숨긴다. 탭 바 옆 검색 탭은 2026-09-26 뺐다(입구가 둘). 닫기·뒤로가기로 복귀하며 Android에서 키보드가 열린 경우 첫 뒤로가기는 OS가 키보드를 닫을 수 있다.
  - **제자리 검색의 [잔여 링 | 닫기 ✕] 자리는 큰 제목 "탐색" 줄 오른쪽이다**(2026-09-27 — `changes/archive/explore-search-shows-remaining.md`). 링과 닫기 ✕를 한 유리 캡슐에 묶고(라이브러리의 [링 | 필터] 캡슐과 같은 문법), 검색에 들어오면 링 옆에서 닫기 칸이 자라난다. 잔여 표시가 없는 사용자(무제한·값 없음 — 4.4-1)는 닫기 ✕만 남는다. **검색 필드는 그 밑 줄에서 폭을 다 쓴다** — 종전의 필드 옆 [취소]는 제자리 검색에 없다.
  - **검색 필드 안의 지우기 ✕는 라이브러리 검색창과 같은 모양이다** — 필드 오른쪽 끝 고정 자리(44)에 두고, 글자가 없을 때는 자리만 남기고 보이지 않는다(입력 칸 폭이 변하지 않게).
- **태그 탭으로도 들어온다**(추가 2026-10-17 — KAN-219). 인기 대표 카드(콘텐츠 해시태그만 — 주제 이름 대체 표기는 제외)·콘텐츠 상세 헤더의 `#태그`를 탭하면 검색이 열리고 `#태그`로 **즉시 검색**한다(디바운스 없이 [검색] 제출과 같은 경로). 상세는 어느 탭 위에 있든 상세를 걷고 탐색 탭으로 전환한 뒤 연다. 제자리 검색 갈래는 피드 위에 검색을 덮고, 스택 검색 갈래는 검색 화면을 그 질의와 함께 쌓는다. 피드 상태는 유지된다. 사각 타일의 태그는 탭 동작이 없다(`explore-uiux.md` 4.1)
- [취소](스택 검색)·닫기 ✕(제자리 검색)·뒤로가기로 피드에 복귀한다. **피드의 상태(필터·구간·스크롤 위치)는 전환 전 그대로 유지**된다
- **복귀 시 검색 상태(검색어·결과)는 버린다.** 재진입하면 검색 초기 화면부터다 — 다시 찾는 경로는 최근 검색어가 맡는다(4.5-4)
- 검색 화면에서도 하단 미니플레이어는 유지된다

#### 4.5-2 질의 규칙

- **2자 이상 입력 시 300ms 디바운스로 자동 검색**한다. 키보드의 [검색] 제출은 디바운스를 기다리지 않고 즉시 실행한다
- 앞뒤 공백은 무시하고, 특수문자·이모지만인 입력은 검색을 실행하지 않는다("검색어를 입력해주세요" 유지 — 7장)
- **연속 입력 중 응답 순서가 뒤바뀌면 최신 질의의 응답만 반영한다.** 이전 질의의 늦은 응답으로 화면을 덮지 않는다
- 검색 대상은 **제목·설명·저자·주제명·해시태그(`contents.tags`)**다(해시태그 추가 2026-10-16 — KAN-218)
- **`#`으로 시작하면 태그 전용 검색이다.** 트림한 뒤 **앞의 `#` 하나**를 떼고 다시 트림한다. 2자 규칙은 뗀 값에 적용한다 — `#`만이나 `#a`는 검색하지 않는다(서버도 `VALIDATION_FAILED`). `##태그`는 앞의 `#`만 떼므로 남은 `#`이 검색어에 들어가 매칭되지 않는다(태그에는 `#`이 없다). 인기 대표 카드·콘텐츠 상세 헤더의 태그를 탭하면 `#태그`로 이 검색을 즉시 연다(KAN-219, 2026-10-17 — 4.5-1). 사각 타일의 태그는 탭 동작이 없다(`explore-uiux.md` 4.1). 검색창에 직접 친 `#`도 트림 외 가공 없이 그대로 보내며, 클라이언트 검증은 서버와 같다(`#`을 뗀 값이 2자 미만이면 요청하지 않는다)
- **`exact` 토글**(추가 2026-10-22 — KAN-238): 교정 안내(4.5-3)의 "원본 검색 ‘OO’"를 탭하면 **교정을 끄고(`exact=true`) 원문 그대로** 같은 검색을 다시 한다. 그 결과는 교정 없는 하이브리드다(키워드 0 + 의미 결과 → 4.5-3의 "관련 결과", 둘 다 0 → 빈 결과). 최근 검색어 저장 규칙은 그대로다 — 입력 그대로 저장하고 교정어를 저장하지 않는다(사용자가 친 말이 "다시 찾는 경로"다)

#### 4.5-3 결과 목록

- **정렬은 서버가 정하고 클라이언트는 재배열하지 않는다**(피드·주제 칩과 같은 원칙). 기준은 관련도(매칭 필드 가중)이며 매칭·랭킹 규칙은 4.5-5가 정한다
- 페이지네이션은 피드와 동일한 **커서 기반 20건 무한 스크롤**
- 결과는 **주제 필터 결과와 같은 두 칸 썸네일 격자**다(4.1, 개정 2026-09-18) — 정사각 아트워크·제목 2줄·길이·더보기 ⋯. 타일 탭 = 재생 판정(4.4), 더보기 시트 = 담기/제거·원문 보기·상세 정보(4.3, `content-detail.md`) 전부 동일하게 동작한다
- 파트너 회수 콘텐츠(FR-32)는 피드와 동일하게 서버 단계에서 제외된다
- **빈 결과 UX가 중요하다**(초기 콘텐츠 풀 작음 — PRD 8.1): "‘OO’ 검색 결과가 없어요"(입력한 검색어를 그대로 되비춘다) + 관련 주제 칩(탭하면 그 주제의 단일 행 목록으로 이동 — 4.2) + 인기 콘텐츠 노출. 두 엔진 모두 0건이고 교정어도 없을 때만이다(4.5-5)
- **안내 2종**(추가 2026-10-22 — KAN-238, 화면 표현은 `explore-uiux.md`):
  - **교정됨**(`corrected_from`가 있음): 격자 위 **가운데 한 줄** — **"‘커리어’로 대신 검색했어요"** + 옆에 버튼 **"원본 검색 ‘커리오’"**(탭 가능 — 4.5-2의 `exact`. 좁으면 버튼이 다음 줄로 접힌다. 개정 2026-10-22 PM — 종전 두 줄 "혹시 ‘커리오’로 검색하고 싶나요?"). 격자는 교정어의 하이브리드 결과다
  - **관련 결과**(`match: "related"` — 교정 없이 첫 페이지에 키워드로 맞은 편이 0, 의미 결과만): **"‘커리오’와 관련된 결과예요"** 한 줄
  - 둘이 같이 뜨는 경우는 없다 — 교정은 **교정어로 키워드 결과가 1건 이상일 때만** 적용하므로(4.5-5) 교정된 응답은 항상 `match: "keyword"`다
  - 격자·타일·⋯ 시트·커서 로딩은 그대로다. **태그 전용 검색(`#태그`)은 종전대로** 태그 정확 일치만이다 — 교정도 의미 엔진도 없다

#### 4.5-4 최근 검색어 · 추천 키워드 (검색 초기 화면)

- **최근 검색어는 기기 로컬 10건**이다. 서버에 보내지 않는다(`SearchHistory`는 테이블이 아니다 — `domain.md` 13.1). 개별·전체 삭제를 제공한다
- **저장 시점은 "검색이 사용자 행동으로 이어진 때"다** — 키보드 [검색] 제출, 결과 행 탭(재생·더보기), 또는 **태그 탭으로 연 검색**(`#태그` 그대로 저장 — 추가 2026-10-17, KAN-219). 디바운스 자동 검색마다 저장하면 타이핑 중간어("커리", "커리어 성")가 쌓여 목록이 오염된다
- 같은 검색어는 중복 저장하지 않고 최신으로 끌어올린다. 10건 초과 시 가장 오래된 것부터 밀어낸다
- **추천 키워드는 서버가 내려주는 주제명 목록**이다 — 사용자의 관심 주제를 앞에 배치한다(4.2의 칩 정렬과 같은 서버 정렬 재사용). 탭하면 그 키워드로 즉시 검색을 실행한다(주제 필터 적용이 아니라 검색이다 — 이 화면은 검색 흐름 안에 있다)

#### 4.5-5 매칭·랭킹 (확정 2026-08-23 · 교정·하이브리드 개정 2026-10-22 — KAN-238)

- **흐름**(2026-10-22): ① 정규화(NFC·소문자·트림) → `#` 질의는 아래 태그 전용 경로(교정·의미 없음) → ② **하이브리드**(키워드 엔진 + 의미 엔진) → ③ `exact`가 아니고 **키워드 엔진이 0건**이면 교정어를 찾는다 → 교정어가 있고 **교정어로 키워드 1건 이상**이면 교정어로 ②를 다시 돌려 그 결과를 낸다(`query_used` = 교정어, `corrected_from` = 원문). 아니면 ②의 원문 결과 그대로(의미 결과만 있으면 `related`).
- **키워드 엔진**: 아래의 `ILIKE` 부분 일치(제목 > 태그 > 저자 > 주제명 > 설명, 시리즈 제목은 스위치 켜짐일 때)·가중 합산·동점 해소가 **엔진 안의 순위**다.
- **의미 엔진**: `query_used`의 임베딩(AI 서버 `POST /embeddings`, 저장 벡터와 같은 모델) vs `content_embeddings.embedding` 코사인 ≥ 임계값, 상위 K. `model` 현행·`content_version` 일치 행만이다(재발행 후 미갱신 벡터 제외 — `domain.md` 5.6). 임베딩 없는 콘텐츠는 이 엔진에서 빠진다.
- **합산 = RRF**: 편마다 Σ 1/(k + 엔진 내 순위). **k·임계값·K는 서버 구현이 소유한다**(가중 계수와 같은 원칙 — 시작 k=60·코사인 임계·K=50, 로그로 조정). 동점은 인기(직전 확정 구간) → `published_at` DESC → id. 클라이언트는 재배열하지 않는다. 의미 엔진이 없으면 RRF는 키워드 순위의 단조 함수라 결과·순서가 종전 키워드 검색과 같다.
- **교정어 선택**: 어휘 = 사용자 시장의 발행 콘텐츠에서 **태그 항목 · 주제명 · 시리즈 제목(스위치 켜짐) · 제목 토큰**(공백·문장부호로 나누고 끝의 조사 — 을/를/이/가/은/는/의/에/로/와/과/도 — 를 뗀 것, 2자 이상). 그중 **글자 수가 원문 ±1 안**(길이 가드)인 말만 후보이고, 점수는 **자모 편집 유사도**(`1 − 자모 편집 거리 / 긴 쪽 자모 수` — 대칭)다. 점수 ≥ 임계값에서 최대값 하나, 동점은 태그·주제명 우선(깨끗한 명사) → 빈도 → 글자 수 차이가 작은 말. 원문과 같은 말은 교정어가 아니다. **임계값은 서버 구현이 소유한다**(시작 0.7 — 틀린 자모가 긴 쪽 자모 수의 30% 이하일 때만 고친다 — 자모 4~6개인 말은 하나, 7~9개는 둘, 10개 이상은 셋까지). 여러 단어 질의("커리어 없는말")는 길이 가드 때문에 **통째로 닮은 어휘(시리즈 제목·띄어 쓴 태그)가 있을 때만** 고친다 — 질의 안의 한 단어로 줄여 고치지 않는다(개정 2026-10-22 — 종전 `word_similarity ≥ 0.5`는 비대칭이라 "겅제"를 "경제"가 아니라 "거의"로 고쳤다). 자모 분해는 **SQL 함수 `hangul_to_jamo(text)`**(후보를 자모 트라이그램 `similarity`로 줄일 때)와 `search-text.util.ts` `toJamo`(편집 거리 재채점)이고 두 구현은 같은 규칙이다(겹모음 ㅘ=ㅗ+ㅏ·겹받침 ㄺ=ㄹ+ㄱ, 치는 순서대로 — `domain.md` 5.1, e2e가 동치를 대조한다). 한글은 자모 하나가 틀리면 음절이 통째로 바뀌어("커리오"↔"커리어") 음절 단위로는 유사도가 안 나오고, 자모 트라이그램만으로도 다섯 자 안팎의 말에서는 틀린 자모 수가 구분되지 않는다("겅제"에 대해 경제·거의 모두 0.333).
- **AI 서버 결손**(타임아웃 예산 초과·오류·모델 불일치): 그 요청은 의미 엔진 없이 키워드만으로 응답하고 `engines`에 `semantic`이 없다. 교정 흐름은 영향 없다 — 검색은 AI 서버 때문에 실패하지 않는다.
- **성능 메모**: 의미 엔진은 후보 전수 코사인이다(ANN 없음 — `domain.md` 5.6의 기존 결정, 수천 편까지 충분, 그 위로 가면 HNSW를 그때 본다). 교정어 어휘도 질의 시 전수 비교다(수백 편 규모 — 수만 항목으로 커지면 `search_terms` 뷰 + trgm 인덱스).

- **매칭은 PostgreSQL `pg_trgm` 기반 부분 문자열 일치다.** 형태소 분석은 도입하지 않는다 — 검색 대상이 짧은 메타데이터(제목·설명·저자·주제명·해시태그)라 부분 일치("커리" → "커리어를 바꾸는 법")가 조사·활용 문제를 우회하고, PG 확장 하나로 끝나 별도 검색 인프라가 필요 없다(비동기 큐 미도입과 같은 기준 — 규모 대비 운영 비용, `architecture.md`).
- **랭킹은 매칭 필드 가중 합산이다.** 우선순위는 **제목 > 태그 > 저자 > 주제명 > 설명**(태그 추가 2026-10-16 — 태그는 내용을 요약해 붙인 값이라 저자보다 관련도 신호가 강하다). 태그는 항목 하나라도 부분 일치하면 매칭이다. 동점은 제목 유사도(`word_similarity`) → 인기(직전 확정 구간 — `domain.md` 5.4) → `published_at` 최신순으로 푼다. **가중 계수 값은 서버 구현이 소유한다** — 계수를 문서에 박으면 랭킹 튜닝마다 문서 개정이 필요해진다. 이 문서가 확정하는 것은 우선순위와 동점 해소 순서다.
- **태그 전용 검색(`#태그`)은 태그 항목과 정확히 같은 콘텐츠만 낸다**(NFC + 소문자 통일, 안쪽 공백은 그대로). 매칭 자체가 정확 일치라 필드 가중을 쓰지 않고 동점 규칙(제목 유사도 → 인기 → `published_at`)만 쓴다. 빈 결과의 대체 콘텐츠(4.5-3)는 같은 모양이고, 관련 주제는 `#`을 뗀 검색어로 찾는다. 커서·검색 로그는 `#`을 남긴 질의(`#` + 검색어)로 다뤄 부분 일치 검색과 섞이지 않는다.
- **시리즈 제목 일치**(추가 2026-10-17 — KAN-134, **스위치 `SERIES_EXPLORE_CARDS_ENABLED`가 켜졌을 때만**) — 켜져 있으면 시리즈 제목(`series.title`)이 맞는 편도 결과에 들고(가중은 제목과 같다) 그 편들의 대표 하나가 시리즈 카드가 된다(4.1). 태그 전용 검색(`#태그`)은 종전대로 태그만 본다. 꺼져 있으면 시리즈 제목을 보지 않는다.
- **질의·저장 텍스트 모두 NFC 정규화 + 소문자 통일 후 비교한다.** NFD 분해형 입력(ㅋ+ㅓ)이 NFC 저장 텍스트와 매칭되지 않는 것을 막는다. 공백 처리(앞뒤 무시)는 4.5-2가 정한 대로다.
- **지원하지 않는 것**(개정 2026-10-22): 초성 검색(ㅋㄹㅇ — 자모 트라이그램이 초성열과 거의 겹치지 않는다) · 형태소 어간 변형 매칭("달리기" ↔ "달렸다"). 오타는 교정이, 동의어·주제 연관은 의미 엔진이 흡수한다(위). 종전 "검색 쿼리 로그로 미스율을 확인한 뒤 재검토"는 **임계값·k 조정의 근거**로 역할이 바뀌었다 — **그 로그는 서버가 남긴다**(신설 2026-10-01): 첫 페이지 검색마다 정규화 질의·첫 페이지 건수·다음 페이지 유무·주제 필터 수를 `search_query_logs`(`domain.md` 5.7)에 적재한다(디바운스 중간 입력은 서버가 접는다). 최근 검색어(4.5-4)와 별개다 — 사용자에게 되돌려 주지 않고 운영 분석에만 쓴다 — 형태소 분석·외부 검색 엔진 도입 판단도 그때 한다. 추측이 아니라 실측으로 결정한다.
- **인덱스는 GIN(`gin_trgm_ops`)이다. 정의는 `domain.md`가 기준**이므로 이 문서에는 두지 않는다(해시태그는 인덱스 없이 순차 비교 — `domain.md` 5.1, 2026-10-16) — `domain.md` 5장 보강이 개정 대상이다(`explore-api.md` 미결 사항의 "검색 인덱스" 항목을 pg_trgm으로 확정).
- **2자 질의는 트라이그램 인덱스를 타지 못한다**(트라이그램은 3자 단위). 초기 콘텐츠 풀 규모(PRD 8.1)에서는 순차 탐색으로 충분하다. 성능 임계에 도달해도 **최소 길이(4.5-2의 2자)를 올리는 방식으로 풀지 않는다** — 한국어는 2자 검색어("이직"·"면접")가 흔해 최소 길이를 올리면 검색 자체가 죽는다. 인덱스 전략을 재검토한다.

- **머리** — 표지(노출 중인 가장 앞 편의 썸네일 — 따로 표지가 없다) · 시리즈 제목 · 편수 · 연재 상태(`ongoing` 연재 중 / `completed` 완결 — 표시용) · 소개(빈 문자열이면 문단을 그리지 않는다)

  - **탐색 행의 "담김 표시 없음"(4.1 · 합의 2026-08-07)의 예외다** — 시리즈 화면은 "어디까지 들었나"를 보는 자리라 담음·완청·재생 위치를 보인다(티켓 결정 — KAN-225). 탐색 피드·격자의 행은 그대로 표시가 없다

- **머리 [재생]**(추가 2026-10-22 PM — KAN-225의 "다음 화 듣기" 보류를 이 꼴로 푼다) — 아직 다 듣지 않은 가장 앞 편 **한 편**을 편 행 탭과 같은 재생 판정(4.4)으로 튼다. 듣다 만 편이면 서버 재생 위치에서 이어지고, 전부 완청이면 1화. 끝난 뒤 다음 편으로 넘어가지 않는다
- **앱바 ⋯ → 시리즈 시트의 [공유]**(추가 2026-10-22 PM · 앱바 공유 아이콘은 같은 날 PM 지시로 뺐다 — 공유 입구는 시트 하나) — [공유]는 시리즈 전용 링크가 아직 없어 **노출 중인 가장 앞 편의 공유 링크**(`share.md` 4.2)에 시리즈 제목을 싣는다(받는 사람은 그 편 상세의 시리즈 줄로 온다). ⋯ = 시리즈 시트(공유 · 소개 전체 보기). 소개 문단은 머리에서 빠지고 이 시트에서 본다
- **아래 가로 목록 두 줄**(추가 2026-10-22 PM — 애플 뮤직 앨범 화면 아래, "iTunes 구입" 같은 줄은 두지 않는다): 편 목록·합계 줄 아래에 **"다른 시리즈 더보기"**(같은 주제 목록 `explore-api.md` 4.2 첫 페이지 → 탐색 피드 4.1 섹션의 시리즈 카드 순, 지금 시리즈 제외, 최대 10) · **"좋아할 만한 다른 항목"**(관련 콘텐츠 `player-api.md` 4.8을 가장 앞 편 기준으로, 이 시리즈 편 제외, 최대 10). 새 API 없음. 칸은 탐색 타일 그대로 — 시리즈 카드 탭 = 그 시리즈 화면(같은 스택에 쌓는다), 콘텐츠 탭 = 탐색과 같은 재생 판정(재생 목록 = 그 줄). 보조 목록이라 실패·빈 결과는 알리지 않고 줄째 숨긴다.
- **셔플 · 시리즈 담기**(추가 2026-10-22 PM — PM "셔플 버튼, 시리즈 라이브러리 추가 버튼 넣자", 종전 "두지 않는 것"에서 옮김):
  - **셔플** = 노출 편을 무작위로 섞어 **맨 앞 편을 재생**하고, 재생 목록 패널의 맥락 스냅샷도 그 섞인 순서다(`player.md` 4.2-1). **자동 다음 재생은 여전히 없다**(FR-24) — 셔플은 "어느 편부터"와 "목록 순서"만 바꾼다. 판정·팝업은 편 행 탭과 같다.
  - **시리즈 담기** = 시리즈 단위 요청 한 번(`POST /series/:series_id/save` — `explore-api.md` 4.8, 개정 2026-10-22 PM KAN-245 — 종전 "편 담기를 편 수만큼, 새 API 없음"). 서버가 **시리즈째 담기를 기록하고**(`library_series`) 노출 편 중 라이브러리에 없는 편을 **편 담기 규칙 그대로**(`explore-api.md` 4.3 · 횟수 제한·페이월 없음) 전부 담는다. 라이브러리는 여전히 편 단위다 — 시리즈 한 덩어리로 들어가지 않는다.
    - **시리즈째 담으면 이후 공개되는 편이 라이브러리에 자동으로 들어온다**(맨 위 — `source = save`, 푸시 알림 없음. PM 2026-10-22 14:57 — 종전의 "새 편은 따라오지 않음 — 시리즈 구독 보류" 규칙을 폐기). 따라오기의 근거는 시리즈째 담기 하나다 — 편을 하나씩 다 담은 것·드립 적립은 따라오기가 아니다.
    - **편을 라이브러리에서 따로 빼도 시리즈째 담기는 유지된다**(새 편은 계속 온다). 다만 사용자가 뺀 편은 다시 넣지 않는다.
    - 담기 원의 판정은 **`series.is_saved`**(`explore-api.md` 4.7)다 — 편이 전부 담겼는지가 아니다. 담겨 있으면 버튼이 **빼기**(휴지통)다.
    - **빼기 = 시리즈째 빼기**(`DELETE /series/:series_id/save` — 4.9): 담긴 편 전부 + 시리즈 담기 기록을 함께 뺀다 → 더 따라오지 않는다. 편마다 편 해제 규칙(`explore-api.md` 4.4 — 소프트 삭제·드립 영구 제외·신호)을 그대로 따른다. 여러 편이 한 번에 빠지므로 토스트에 **[실행 취소]**를 단다 — 누르면 `POST /series/:series_id/restore`(4.10)로 뺀 편을 빼기 전 자리·순서 그대로 되살리고 시리즈째 담기도 되살린다.
- **두지 않는 것** — 연속 재생(보류 — KAN-225 결정), 시리즈 단위 진행률, 새 편 푸시 알림(KAN-245 범위 밖)
- **재생 목록 패널의 맥락**(추가 2026-10-22 — KAN-241, `player.md` 4.2-1): 이 화면의 편 목록에서 재생을 시작하면 **그 편 목록이 재생 목록 패널의 스냅샷**이 된다(손잡이 "시리즈 · <제목>"). 패널은 열람·선택 전용이라 위 "다음 화 듣기" 유도가 아니다 — 유도로 읽히면 시리즈 화면만 라이브러리 맥락으로 되돌린다(PM 확인 항목)
- **404**(없는 시리즈 · 다른 시장 시리즈 · 노출 중인 편이 하나도 없는 시리즈) — "시리즈를 찾을 수 없어요" + [돌아가기]. 다시 시도해도 결과가 같아 [다시 시도]를 두지 않는다. 그 밖의 실패는 전체 화면 에러 + [다시 시도](E10과 같은 표현)
- 플레이어·상세에서 돌아오면 조용히 다시 받는다(편의 재생 위치·완청이 바뀌었을 수 있다). 시리즈 화면의 캐시는 탐색 캐시 아래라 탐색의 재생·담기 뒤 무효화가 함께 닿는다

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `contents` · `content_topics` — 주제 필터는 조인 테이블로 조회 | 5.1 · 5.2 |
| `content_stats` — 인기 섹션(직전 확정 구간 사용) | 5.4 |
| `library_items` — 담기 | 6.1 |
| `user_signals` — 추천 갱신 입력 | 6.4 |
| `drip_excluded_contents` — 담기 해제 시 적재 | 7.1 |
| `play_records` — 잔여 재생 횟수 집계(4.4-1) | 6.3 |
| `plans` — `daily_play_limit` | 8.1 |

- `ExploreFeed`는 응답 DTO이고 `SearchHistory`는 클라이언트 로컬 전용이다. 테이블이 아니다(domain.md 13.1·13.2).
- **시장 격리**(추가 2026-10-14 — KAN-188, `global-api.md` 4.5·4.7): 피드·필터 목록·인기·검색(fallback 포함)·주제 칩은 **사용자 시장의 콘텐츠·주제만** 내려준다(`contents.market`·`topics.market` = `users.market`). 다른 시장 콘텐츠를 ID로 담으려 하면 `CONTENT_NOT_FOUND`(404)다. 콘텐츠 객체에는 `language`(`ko` | `en`)가 실리지만 **표시 전용**이다 — 클라이언트는 이 값으로 거르지 않는다(필터는 서버).
- **잔여 횟수 컬럼을 새로 만들지 않는다.** `play_records` 집계로 매번 구한다(`domain.md` 1.4 — 파생값을 컬럼으로 두지 않는다). `users.daily_play_count`는 이미 폐기된 개체다(`domain.md` 14장).
- **[오늘은 그만 보기] 억제 플래그는 클라이언트 로컬 전용**이며 서버에 저장하지 않는다(`paywall.md` 4.2). 라이브러리와 **같은 로컬 키를 공유한다** — 화면별로 따로 두면 한 화면에서 억제해도 다른 화면에서 다시 뜬다.

## 7. 예외 상황

- **담기 요청 중복 탭**: 클라이언트에서 버튼을 즉시 비활성화하고, 서버는 `(user_id, content_id)` 유니크 제약으로 멱등 처리한다.
- **담기 → 즉시 제거 연타**: 마지막 요청 상태를 최종으로 삼되, 서버 응답 순서가 뒤바뀔 수 있으므로 요청에 클라이언트 시퀀스를 실어 오래된 응답은 무시한다.
- **재생 시도했으나 페이월로 차단됨**: 라이브러리에 담기지 않는다(재생이 시작돼도 담기지 않는다 — 4.4 개정 2026-10-23).
- **재생 확인 팝업에서 [취소]**: 재생도 적립도 하지 않는다. 카운트도 늘지 않는다(`paywall.md` 4.3).
- **라이브러리에서 [오늘은 그만 보기]를 누른 뒤 탐색에서 재생**: 팝업이 뜨지 않는다. 억제는 기기 단위이며 화면 단위가 아니다(4.4).
- **오프라인 상태로 탐색에 진입**: 캐시된 피드를 노출하지 않는다(합의 2026-08-06 — 오프라인 캐시 피드 폐기). 에러 화면과 [다시 시도]만 보여준다.
- **응답에 `daily_play_count`가 없는 경우**: 표시를 생략한다. **0으로 가정하지 않는다** — 남은 횟수가 있는 사용자에게 소진 상태를 보여주면 재생을 포기하게 만든다.
- **무제한 티어로 업그레이드 직후**: 다음 피드 조회에서 `daily_play_limit`이 `null`로 내려오므로 표시가 사라진다. 결제 직후 화면에 카운터가 남지 않도록 **복귀 시 피드를 재조회한다**(`paywall.md` 4.5).
- **앱을 켜 둔 채 05시를 넘김**: 표시값은 다음 피드 재조회 때 갱신된다. 클라이언트가 기기 시각으로 스스로 되돌리지 않는다(`paywall.md` 4.4).
- **검색 화면에서 결과를 탭해 재생**: 스택 검색 화면 갈래에는 잔여 횟수가 없지만(제자리 검색 갈래는 제목 줄에 유지 — 4.4-1, 개정 2026-09-27) **판정과 팝업은 어느 갈래든 동일하게 거친다**(4.4). 표시를 숨긴 것이지 규칙을 뺀 것이 아니다.
- **검색어에 특수문자·이모지만 입력**: 검색을 실행하지 않고 "검색어를 입력해주세요" 유지.
- **검색 중 네트워크 끊김**: 이전 결과를 유지하고 상단 배너로 알린다.
- **연속 입력으로 응답 순서가 뒤바뀜**: 최신 질의의 응답만 반영한다(4.5-2). 늦게 도착한 이전 질의 응답은 무시한다.
- **검색 결과의 콘텐츠가 화면에 뜬 사이 회수됨**: 피드와 동일 — 재생 시 403 → "제공이 종료된 콘텐츠예요" 후 목록에서 제거.
- **피드 스크롤 도중 콘텐츠가 회수됨**: 재생 시 403 → "제공이 종료된 콘텐츠예요" 후 목록에서 제거.
