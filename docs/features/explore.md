# 탐색 · 검색 기능 명세서

> 연결 PRD: FR-21, FR-22, FR-15, FR-27 / 사용자흐름 5.3

## 1. 목적 & 연결

드립으로 받는 것 외에 사용자가 직접 콘텐츠를 발견하고 담을 수 있는 능동 경로. 무료(라이트) 사용자의 주 사용 경로이기도 하다 — 무료도 드립을 받지만 재생이 하루 2편으로 제한되므로, **담기 무제한인 탐색이 실질적인 소비 경로**가 된다(PRD 4.1).

- PRD FR-21 (P0) 추천 피드·주제 필터로 발견하고 담기. 담기는 무제한
- PRD FR-22 (P1) 키워드 검색
- PRD FR-15 (P0) 소비 신호를 추천에 반영
- PRD FR-27 (P1) OS 공유 시트로 공유 — **MVP 제외 확정**(합의 2026-08-06, 4.6)
- PRD 사용자흐름 5.3

## 2. 진입 조건

- 하단 탭에서 [탐색] 선택
- 라이브러리 빈 상태에서 [탐색 둘러보기] 탭

## 3. 입력값

**피드 조회**

| 값 | 설명 | 필수 |
|---|---|---|
| user_id | 토큰에서 도출 | 필수 |
| topic_filter | 주제 id 목록 | 선택 |
| cursor | 페이지네이션 커서 | 선택 |

**검색 (FR-22, P1)**

| 값 | 설명 | 필수 |
|---|---|---|
| query | 키워드 | 필수, 2자 이상 |
| topic_filter | 주제 필터 | 선택 |

**서버가 피드 응답에 함께 실어 보내는 표시값**

| 값 | 설명 |
|---|---|
| daily_play_limit | `plans.daily_play_limit`. `null`이면 무제한 티어 |
| daily_play_count | 오늘의 서비스 날짜 기준 재생 수. **파생값이며 컬럼이 아니다**(`domain.md` 1.4) |
| service_date | 서버가 계산한 오늘의 서비스 날짜(04:00 KST 경계) |

- **라이브러리 응답과 같은 값을 같은 이름으로 싣는다**(`library.md` 3). 두 화면이 각자 계산하거나 다른 필드명을 쓰면 같은 사용자에게 서로 다른 숫자가 표시된다.
- **잔여 횟수 전용 API를 따로 두지 않는다.** 피드를 여는 시점이 곧 이 값을 갱신해야 하는 시점이라, 호출을 나누면 화면과 숫자가 어긋나는 구간이 생긴다.
- `service_date`를 서버에서 받는 이유는 **억제 만료 판정(4.4)에 기기 시각을 쓰지 않기 위해서**다.

**사용자 조작**: 행 탭(즉시 재생) / [더보기] > 담기·제거·원문 보기(공유는 P1 — MVP 미노출, 4.6) / 잔여 횟수 표시 탭(소진 시 페이월) / 재생 확인 팝업의 [오늘은 그만 보기]

- **"상세" 화면은 두지 않는다** — 명세를 추후 추가한 뒤 개발한다(합의 2026-08-06). 그 전까지 더보기 시트에 상세 항목이 없다.

## 4. 처리 로직

### 4.1 추천 피드 구성

서버가 섹션 단위로 피드를 구성해 내려준다. 섹션 순서·구성은 서버 제어(클라이언트 하드코딩 금지).

| 섹션 | 규칙 |
|---|---|
| 관심사 기반 추천 | 사용자 `UserInterest` + 소비 신호(FR-15) 기반 랭킹 |
| 새로 나온 콘텐츠 | `published_at` 최신순 |
| 인기 콘텐츠 | `content_stats`의 **직전 확정 구간** 재생·완청 수 기준. **사용자가 주간·월간·전체 중 하나를 골라 본다**(합의 2026-08-07 — 4.1-1). 진행 중인 구간을 쓰면 주초·월초에 표본이 부족해 랭킹이 무너진다. **직전 확정 구간이 없는 배포 첫 주에는** 섹션을 숨기지 않고, 표본 크기와 무관하게 같은 선정 기준으로 정렬한 상위를 보여준다(합의 2026-08-06) — 모든 콘텐츠의 값이 같아도 정렬상 앞서는 콘텐츠가 존재한다 |
| 주제별 모아보기 | 사용자 관심 주제별 묶음 |

- 콘텐츠는 **세로 행(row) 목록**으로 나열한다 — 라이브러리 아이템 행과 같은 문법(썸네일·제목·출처·저자·길이). 행에는 담기 버튼을 두지 않는다(4.3)
- **완청한 콘텐츠는 썸네일 좌상단에 체크를 붙인다**(합의 2026-08-07) — 라이브러리 카드와 같은 마킹이며 판정 근거는 `library.status`다. 탐색은 청취 여부와 무관하게 전부 노출하므로, 단서가 없으면 "다시 들을 필요가 있는가"를 행에서 알 수 없다
- 소비 신호가 부족한 신규 사용자는 인기·신규 섹션 비중을 높인다(콜드스타트, FR-17)
- **이미 라이브러리에 있는 콘텐츠는 피드에서 제외하지 않는다.** 초기 콘텐츠 풀이 작아(PRD 8.1) 제외하면 피드가 비어버린다. **담김 여부는 노출·순서에도, 행 표시에도 나타나지 않는다**(합의 2026-08-07) — 확인 수단은 더보기 시트의 담기/제거 분기 하나다
- 파트너 회수 콘텐츠(FR-32)는 서버 단계에서 제외

### 4.1-1 인기 콘텐츠의 구간 선택

**인기 섹션만 사용자가 집계 구간을 고른다.** 다른 세 섹션에는 구간 개념이 없다 — 관심사는 소비 신호, 신규는 발행 시각, 주제별은 주제가 축이다.

| 구간 | 대상 |
|---|---|
| 주간 | 직전 확정 주(지난주 월요일 04:00 ~ 이번 주 월요일 03:59) |
| 월간 | 직전 확정 월 — **기본값** |
| 전체 | 누적 집계 |

- **기본값은 월간이다.** 주간은 초기에 표본이 너무 적고, 온보딩 추천이 이미 직전 확정 월을 쓰고 있어(`onboarding.md` 4 [3]) 두 화면의 "인기"가 같은 구간을 보게 된다.
- **주간·월간은 확정된 구간만 쓴다**(`domain.md` 5.4 — `is_final`). **전체 구간에는 이 규칙이 적용되지 않는다** — 끝나는 시점이 없어 확정·진행 중 구분 자체가 없다.
- **배포 첫 주·첫 달에도 탭을 숨기지 않는다.** 확정 구간이 없으면 그 구간의 집계가 전부 비어 동점이 되고, 뒤의 정렬 키(신선도)가 순서를 정한다 — 2026-08-06 합의("섹션을 숨기지 않는다")를 세 구간 각각에 그대로 적용한 것이다. 탭이 조건부로 사라지면 클라이언트가 서버 상태를 추측해야 한다.
- **구간 전환은 인기 섹션만 갈아끼운다.** 피드 전체를 다시 만들지 않는다 — 구간만 바꿨는데 관심사 섹션 랭킹까지 재계산될 이유가 없다(계약은 `spec/api/explore-api.md` 4.2-1).
- **주제 필터를 걸면 섹션 구조가 사라지므로 토글도 사라진다**(4.2). 칩을 전부 해제해 섹션형으로 돌아오면 **직전에 고른 구간을 유지한다** — 되돌아온 화면이 조작 이전과 달라지면 사용자는 무엇이 바뀐 것인지 추적해야 한다.
- **고른 구간은 서버에 저장하지 않는다.** 사용자의 상태가 아니라 화면의 상태다(`paywall.md` 4.2의 억제 플래그와 같은 성격). 유지 범위는 클라이언트가 정한다.

### 4.2 주제 필터

- 상단 가로 스크롤 칩. 사용자의 관심 주제를 앞쪽에 배치하고 나머지 주제를 뒤에 붙인다
- **정렬은 서버가 정해 내려주고 클라이언트는 재배열하지 않는다**(계약은 `spec/api/explore-api.md` 4.2-2). 관심 주제끼리는 **사용자가 선택한 순서**, 나머지는 주제의 노출 순서다
- **숨겨진 주제(`is_visible = false`)는 관심 주제여도 칩에서 제외한다**(결정 2026-08-11 — 숨김 주제는 모든 사용자에게서 제거된다. "숨긴 뒤에도 칩에 남는다"던 합의 2026-08-07을 뒤집었다 — 보유자 예외의 구현 복잡도가 이유다). 관심 주제가 아닌 숨겨진 주제도 당연히 노출하지 않는다(FR-38)
- **발행 콘텐츠가 0건인 주제도 칩으로 노출한다.** 거르면 콘텐츠가 들어올 때마다 칩이 나타났다 사라진다. 고른 결과가 비면 "이 주제의 콘텐츠는 아직 없어요"가 받아 준다
- 필터 선택 시 섹션 구조를 버리고 **단일 행 목록**으로 전환한다
- 다중 선택은 OR 조합

### 4.3 담기 · 제거 — 더보기 시트 소유

**담기/제거 버튼은 더보기 시트만 가진다**(합의 2026-08-06). 행에는 담기 버튼이 없고, 행 탭은 재생이다(4.4).

- 담기지 않은 행의 더보기 시트: **[라이브러리에 담기]** → `LibraryItem(source = save)` 생성
- 담긴 행의 더보기 시트: **[라이브러리에서 제거]** — 출처와 무관하게(save·drip·onboarding 모두 — `domain.md` 6.1 source enum) 허용한다
- 시트에는 담기/제거와 함께 **[원문 보기]**를 둔다(확정 2026-08-10 — 라이브러리·플레이어 더보기와 통일). `source_url`이 있는 콘텐츠만 노출하고, 탭하면 인앱 브라우저로 열며 원문 유입 클릭을 기록한다(`player.md` 4.5와 같은 규칙 — `source_link_clicks`)
- **횟수 제한 없음. 무료 티어에서도 페이월을 노출하지 않는다**(PRD 5.4 명시)
- 담기 성공 시 토스트 "라이브러리에 담았어요" + [보러가기]. **행의 모양은 바뀌지 않는다** — 결과는 시트를 다시 열었을 때의 [라이브러리에서 제거]로 확인된다
- 제거는 토스트 없이 시트가 닫히는 것으로 피드백한다. **제거에도 드립 재적립 제외가 적용된다** — 제거는 "관심 없음" 신호이므로 라이브러리 삭제 경로와 동일하게 `drip_excluded_contents`에 적재한다(FR-16)
- **담기 시 서버가 `user_signals(action = save)`를, 제거 시 `unsave`를 적재한다**(FR-15 — `drip-scheduling.md` 4.3의 입력)

### 4.4 행 탭 → 재생 확인 팝업 → 재생

행 탭 = 즉시 재생(PRD 5.3). 담기 여부와 무관하다. 다만 **재생 전에 확인 팝업을 한 번 거친다.**

```
행 탭
   ↓
재생 한도 판정 (paywall.md 4.1~4.2)
   ├─ 한도 소진        → 페이월 바텀시트 (팝업 없음.
   │                     **최상위 티어는 페이월 대신 한도 안내** — paywall.md 4.1)
   ├─ 차감이 발생함
   │     ├─ 오늘 팝업이 억제됨   → 팝업 없이 바로 플레이어
   │     └─ 억제되지 않음        → 재생 확인 팝업 → [재생하기] → 플레이어
   └─ 차감이 없음      → 팝업 없이 바로 플레이어
```

- **팝업 규칙은 `paywall.md` 4.2가 소유한다.** 이 문서는 그것을 탐색 화면에 적용할 뿐이며 조건·문구·버튼을 다시 정하지 않는다.
- **진입점이 다르다고 규칙이 달라지지 않는다**(`paywall.md` 4.2). 라이브러리에서 트든 탐색에서 트든 같은 팝업을 거친다 — 화면마다 다르면 사용자는 탐색이 더 싸다고 오해한다.
- **[오늘은 그만 보기] 억제는 라이브러리와 공유한다.** 라이브러리에서 눌렀으면 탐색에서도 뜨지 않고, 그 반대도 같다. 억제는 **기기 단위 상태**이지 화면 단위가 아니다(`paywall.md` 4.2).
- 탐색에서 재생한 콘텐츠는 라이브러리에 자동 적립한다(`source = save`) — 재생 이력이 라이브러리에서 이어듣기로 이어져야 하므로.
  - **적립은 재생이 실제로 시작된 뒤다.** 팝업에서 [취소]했거나 페이월로 막힌 경우에는 적립하지 않는다(7장).
  - **이미 라이브러리에 있는 콘텐츠에는 다시 적립하지 않는다**(합의 2026-08-06). 라이브러리에서 시작한 재생에 자동 담기가 동작하지 않는 것과 같은 이유다 — 이미 담겨 있다.

### 4.4-1 잔여 재생 횟수 표시

**규칙은 `paywall.md` 5장이 소유하고, 이 문서는 탐색 화면에서의 자리만 정한다.** 문구·티어별 노출 조건·갱신 규칙은 그쪽을 따른다.

- 자리는 **검색창 줄의 우측**이다. 탐색에는 라이브러리 같은 앱바가 없으므로(검색창 + 주제 칩) 배치가 그대로 옮겨오지 않는다.
  - **주제 칩 줄에 넣지 않는다.** 칩은 가로 스크롤이라 숫자가 스크롤을 따라 사라진다. 상시 노출이 목적인 값을 스크롤 영역에 두면 목적을 잃는다.
  - **카드마다 붙이지 않는다.** 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다(`paywall.md` 5장).
- 필터를 걸어 **단일 행 목록으로 전환해도(4.2) 표시는 유지한다.** 검색창 줄은 두 모드 모두에 남아 있다.
- 검색 화면으로 전환한 동안에는 **표시하지 않는다.** 그 화면에서는 재생을 시작하지 않으므로 알릴 이유가 없고, 검색창이 입력 상태로 그 줄을 다 쓴다.
- **라이브러리와 같은 숫자를 보여야 한다.** 두 화면이 다른 값을 표시하면 어느 쪽이 맞는지 사용자가 판단하게 된다 — 그래서 각자 계산하지 않고 3장의 서버 값을 그대로 쓴다.

### 4.5 검색 (FR-22, P1)

- **MVP에서는 검색창을 비활성 상태로 노출한다**(합의 2026-08-06 — 검색은 P1 유지). 검색창은 자리에 있지만 탭해도 검색 화면으로 전환하지 않는다. 아래 규칙은 P1 도입 시 활성화된다.
- 검색창은 상단 고정. 탭하면 검색 화면으로 전환
- 2자 이상 입력 시 300ms 디바운스로 자동 검색
- 제목·설명·저자·주제명을 대상으로 검색
- 최근 검색어 로컬 10건 저장, 개별·전체 삭제 가능
- **빈 결과 UX가 중요하다**(초기 콘텐츠 풀 작음 — PRD 8.1): "‘OO’ 검색 결과가 없어요" + 관련 주제 추천 + 인기 콘텐츠 노출

### 4.6 공유 (FR-27, P1)

- **MVP 제외**(합의 2026-08-06): **더보기 시트에 공유 항목을 노출하지 않는다.** P1 도입 시 아래 규칙을 활성화한다.
- 더보기 > [공유] → OS 공유 시트
- 공유 텍스트: 콘텐츠 제목 + 저자·출처 + 링크
- 링크는 MVP에서 **스토어 링크**로 대체한다(PRD 4.2 — 수신자용 웹 랜딩 비범위)

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 로딩 | 섹션별 스켈레톤 |
| 정상(필터 없음) | 검색창(**우측에 잔여 재생 표시**) + 주제 칩 + 섹션형 피드(세로 행 목록) |
| 정상(필터 있음) | 검색창(잔여 재생 표시 유지) + 선택 칩 강조 + 단일 행 목록 |
| 검색창(MVP) | **비활성 상태로 노출** — 탭해도 검색 화면으로 전환하지 않는다 |
| 잔여 재생 — 한도 있음 | 검색창 우측에 **"오늘 재생 N/M 남음"** |
| 잔여 재생 — 무제한 티어 | **표시하지 않는다.** "무제한" 배지도 두지 않는다 |
| 잔여 재생 — 소진(N == 0) | **"오늘 재생 0/M 남음"** 을 주의색으로 유지. 탭하면 페이월 바텀시트 (**최상위 티어는 페이월 대신 한도 안내** — `paywall.md` 4.1) |
| 잔여 재생 — 값 없음(응답 누락) | **표시하지 않는다.** 0으로 가정하지 않는다 |
| 검색 화면 전환 중 | 잔여 재생 표시 **숨김** (재생 진입점이 아니고 검색창이 그 줄을 다 쓴다) |
| 인기 구간 토글 | 인기 섹션 제목 줄에 **주간 · 월간 · 전체** 3택. 기본은 **월간**이며 선택 구간을 강조한다(4.1-1) |
| 인기 구간 전환 중 | **그 섹션만** 인라인 로딩. 다른 섹션·검색창 줄·칩 줄은 그대로 유지한다 |
| 인기 구간 전환 실패 | 직전 구간의 목록을 유지하고 인라인 에러 + [다시 시도]. **섹션을 비우지 않는다** |
| 피드 비어 있음 | "준비된 콘텐츠가 곧 늘어나요" + [라이브러리로 가기] |
| 필터 결과 없음 | "이 주제의 콘텐츠는 아직 없어요" + [필터 해제] |
| 검색 초기 | 최근 검색어 + 추천 키워드 |
| 검색 중 | 인라인 로딩 |
| 검색 결과 없음 | 안내 + 관련 주제 칩 + 인기 콘텐츠 리스트 |
| 담기·제거 처리 중 | 시트 버튼 로딩(중복 탭 차단) |
| 담기 완료 | 토스트 "라이브러리에 담았어요" + [보러가기]. **행에는 표시 변화가 없다** |
| 제거 완료 | 토스트 없이 시트가 닫힌다 |
| 완청한 콘텐츠 | 썸네일 좌상단에 **체크 마킹**(라이브러리 카드와 동일) |
| 재생 확인 팝업 | "오늘 N회 남았어요. 재생하면 1회가 차감돼요." + [취소] / [재생하기] + **[오늘은 그만 보기]** (`paywall.md` 4.2) |
| 재생 확인 팝업 억제 중 | 팝업 없이 즉시 재생. **차감은 그대로 일어난다** |
| 재생 차단 | 페이월 바텀시트 |
| 네트워크 오류·오프라인 | 에러 화면 + [다시 시도]. **캐시 피드를 노출하지 않는다**(합의 2026-08-06) |
| 재생 중 | 하단 미니플레이어 유지 |

## 6. 데이터 모델

> **스키마는 [`docs/backend/domain.md`](../backend/domain.md)가 유일한 기준이다.** 이 문서에 테이블·컬럼을 중복 기재하지 않는다 — 두 벌을 유지하면 반드시 어긋나고, 수정 비용이 두 배가 된다.
> 컬럼을 추가·변경해야 하면 `domain.md`를 먼저 고치고 이 문서에는 동작 규칙만 남긴다.

| 사용하는 것 | domain.md |
|---|---|
| `contents` · `content_topics` — 주제 필터는 조인 테이블로 조회 | 5.1 · 5.2 |
| `content_stats` — 인기 섹션(직전 확정 구간 사용) | 5.4 |
| `library_items` — 담기 | 6.1 |
| `user_signals` — 추천 갱신 입력 | 6.4 |
| `drip_excluded_contents` — 담기 해제 시 적재 | 7.1 |
| `play_records` — 잔여 재생 횟수 집계(4.4-1) | 6.3 |
| `plans` — `daily_play_limit` | 8.1 |

- `ExploreFeed`는 응답 DTO이고 `SearchHistory`는 클라이언트 로컬 전용이다. 테이블이 아니다(domain.md 13.1·13.2).
- **잔여 횟수 컬럼을 새로 만들지 않는다.** `play_records` 집계로 매번 구한다(`domain.md` 1.4 — 파생값을 컬럼으로 두지 않는다). `users.daily_play_count`는 이미 폐기된 개체다(`domain.md` 14장).
- **[오늘은 그만 보기] 억제 플래그는 클라이언트 로컬 전용**이며 서버에 저장하지 않는다(`paywall.md` 4.2). 라이브러리와 **같은 로컬 키를 공유한다** — 화면별로 따로 두면 한 화면에서 억제해도 다른 화면에서 다시 뜬다.

## 7. 예외 상황

- **담기 요청 중복 탭**: 클라이언트에서 버튼을 즉시 비활성화하고, 서버는 `(user_id, content_id)` 유니크 제약으로 멱등 처리한다.
- **담기 → 즉시 제거 연타**: 마지막 요청 상태를 최종으로 삼되, 서버 응답 순서가 뒤바뀔 수 있으므로 요청에 클라이언트 시퀀스를 실어 오래된 응답은 무시한다.
- **재생 시도했으나 페이월로 차단됨**: 라이브러리 자동 적립(4.4)은 수행하지 않는다. 재생이 실제로 시작된 경우에만 적립한다.
- **재생 확인 팝업에서 [취소]**: 재생도 적립도 하지 않는다. 카운트도 늘지 않는다(`paywall.md` 4.3).
- **라이브러리에서 [오늘은 그만 보기]를 누른 뒤 탐색에서 재생**: 팝업이 뜨지 않는다. 억제는 기기 단위이며 화면 단위가 아니다(4.4).
- **오프라인 상태로 탐색에 진입**: 캐시된 피드를 노출하지 않는다(합의 2026-08-06 — 오프라인 캐시 피드 폐기). 에러 화면과 [다시 시도]만 보여준다.
- **응답에 `daily_play_count`가 없는 경우**: 표시를 생략한다. **0으로 가정하지 않는다** — 남은 횟수가 있는 사용자에게 소진 상태를 보여주면 재생을 포기하게 만든다.
- **무제한 티어로 업그레이드 직후**: 다음 피드 조회에서 `daily_play_limit`이 `null`로 내려오므로 표시가 사라진다. 결제 직후 화면에 카운터가 남지 않도록 **복귀 시 피드를 재조회한다**(`paywall.md` 4.5).
- **앱을 켜 둔 채 04시를 넘김**: 표시값은 다음 피드 재조회 때 갱신된다. 클라이언트가 기기 시각으로 스스로 되돌리지 않는다(`paywall.md` 4.4).
- **검색 화면에서 결과를 탭해 재생**: 검색 화면에는 잔여 횟수가 없지만 **판정과 팝업은 동일하게 거친다**(4.4). 표시를 숨긴 것이지 규칙을 뺀 것이 아니다.
- **검색어에 특수문자·이모지만 입력**: 검색을 실행하지 않고 "검색어를 입력해주세요" 유지.
- **검색 중 네트워크 끊김**: 이전 결과를 유지하고 상단 배너로 알린다.
- **피드 스크롤 도중 콘텐츠가 회수됨**: 재생 시 403 → "제공이 종료된 콘텐츠예요" 후 목록에서 제거.
- **공유 시트에서 사용자가 취소** *(P1 — 공유 활성화 이후)*: 아무 동작 없음. 공유 신호도 기록하지 않는다(시트 오픈만으로는 공유가 아님).

## 8. 완료 조건

- Given 관심 주제가 설정된 사용자 / When 탐색 탭에 진입한다 / Then 관심사 기반 섹션이 상단에 포함된 피드가 노출된다
- Given 무료 사용자가 오늘 이미 2편을 재생했다 / When 더보기 시트에서 [라이브러리에 담기]를 탭한다 / Then 페이월 없이 정상적으로 담긴다
- Given 탐색의 더보기 시트에서 [라이브러리에서 제거]를 한 콘텐츠가 있다 / When 다음 드립이 편성된다 / Then 그 콘텐츠는 드립 후보에서 제외된다
- Given 드립으로 적립된 콘텐츠가 탐색 목록에 있다 / When 더보기 시트를 연다 / Then [라이브러리에서 제거]가 노출되고 출처와 무관하게 제거할 수 있다
- Given 무료 사용자가 오늘 이미 2편을 재생했다 / When 탐색에서 행을 탭해 재생을 시도한다 / Then 페이월이 노출되고 라이브러리에도 적립되지 않는다
- Given 탐색에서 콘텐츠를 탭해 재생했다 / When 라이브러리로 이동한다 / Then 해당 콘텐츠가 라이브러리에 담겨 있고 재생 위치가 유지된다
- Given 이미 라이브러리에 있는 콘텐츠 / When 탐색 피드에서 본다 / Then 담김 배지 없이 목록에 그대로 노출되고, 더보기 시트를 열면 [라이브러리에서 제거]가 보인다
- Given 완청한 콘텐츠가 탐색 피드에 있다 / When 행을 본다 / Then 썸네일에 라이브러리 카드와 같은 체크 마킹이 보인다
- Given 무료 사용자가 탐색에 진입한다 / When 상단을 본다 / Then 검색창 우측에 **"오늘 재생 N/M 남음"** 이 노출되고, 라이브러리에 표시된 값과 같다
- Given 무제한 티어 사용자 / When 탐색에 진입한다 / Then 잔여 횟수도 "무제한" 배지도 노출되지 않는다
- Given 무료 사용자가 오늘 1편을 재생했다 / When 탐색에서 새 콘텐츠 행을 탭한다 / Then **재생 확인 팝업**이 뜨고 [재생하기]를 눌러야 재생된다
- Given 탐색의 재생 확인 팝업에서 [취소]를 누른다 / When 라이브러리를 확인한다 / Then 재생도 자동 적립도 일어나지 않았다
- Given 라이브러리에서 [오늘은 그만 보기]를 눌렀다 / When 같은 날 탐색에서 행을 탭한다 / Then 팝업 없이 재생되고 1회가 차감된다
- Given 주제 필터를 걸어 행 목록으로 전환했다 / When 상단을 본다 / Then 잔여 재생 표시가 그대로 유지된다
- Given 검색 화면으로 전환했다 / When 상단을 본다 / Then 잔여 재생 표시는 숨겨지지만, 결과를 탭해 재생하면 확인 팝업과 한도 판정은 동일하게 적용된다
- Given 오프라인 상태로 탐색에 진입한다 / When 화면을 본다 / Then 캐시 피드 없이 에러 화면과 [다시 시도]가 노출된다
- Given MVP 빌드의 탐색 화면 / When 검색창을 탭한다 / Then 검색 화면으로 전환되지 않는다(비활성)
- Given 주제 필터를 2개 선택한다 / When 목록을 본다 / Then 두 주제 중 하나라도 해당하는 콘텐츠가 노출된다
- Given 결과가 없는 키워드로 검색한다 / When 결과 화면을 본다 / Then 빈 결과 안내와 함께 관련 주제·인기 콘텐츠가 대체 노출된다
- Given MVP 빌드의 더보기 시트 / When 시트를 연다 / Then [공유] 항목이 노출되지 않는다(4.6 — MVP 제외)
- Given `source_url`이 있는 콘텐츠의 더보기 시트 / When [원문 보기]를 탭한다 / Then 인앱 브라우저로 원문이 열리고 원문 유입 클릭이 기록된다(4.3)
- Given 더보기 시트에서 [공유]를 누른다 *(P1 활성화 이후)* / When OS 공유 시트가 열린다 / Then 제목·저자·스토어 링크가 포함된 텍스트가 전달된다
