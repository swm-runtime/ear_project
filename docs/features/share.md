# 공유 기능 명세서

> 연결 PRD: FR-27 / 사용자흐름 5.3 (작성 2026-08-25 — 종전 `explore.md` 4.6의 규칙을 이 문서로 소유 이전)

## 1. 목적 & 연결

콘텐츠를 **OS 표준 공유 시트**로 앱 밖에 전달한다. 공유 전용 화면은 없다 — 이 기능의 전부는 **진입점(공유 버튼) + OS 공유 시트 + 수신자 링크 처리**다.

- PRD FR-27 (P1) 콘텐츠를 OS 공유 시트로 공유한다. **MVP 제외 확정**(합의 2026-08-06 — README 결정 42). 이 문서의 규칙은 P1 활성화 시점의 것이다
- PRD 4.2 — 공유 수신자용 웹 랜딩은 비범위. 앱 미설치 수신자에게는 **스토어 링크로 대체**한다
- 종전 소유자였던 `explore.md` 4.6은 이 문서로의 포인터만 남는다(이전 2026-08-25). 공유가 화면 하나의 부속이 아니라 **네 진입점(라이브러리·탐색·플레이어·콘텐츠 상세)에 걸친 횡단 동작**이 되면서 층을 분리했다

**개정 2026-08-25 — 공유 링크는 콘텐츠 상세로 연결된다.** 종전 확정(2026-08-06)의 "링크 = 스토어 링크"를 개정한다. 스토어 링크만 보내면 수신자가 앱을 설치해도 **어느 콘텐츠가 공유됐는지 링크가 기억하지 못한다.** 공유 링크는 해당 콘텐츠의 상세 화면으로 연결되는 링크 하나이며, 앱 미설치 수신자에 한해 스토어로 폴백한다(4.2).

## 2. 진입 조건

**P1 활성화 이후에만 노출한다.** MVP 빌드에서는 아래 어느 진입점에도 공유가 보이지 않는다(README 결정 42 — 이 조건이 이 문서의 다른 모든 규칙에 우선한다).

| 진입점 | 위치 | 근거 |
|---|---|---|
| 라이브러리 더보기 시트 | [공유] 행 — 담기/제거류 항목 아래 | `library.md` 3 |
| 탐색 더보기 시트 | 동일 | `explore.md` 3 (E12) |
| 플레이어 더보기 시트 | 동일 — 공유해도 **재생은 유지**된다 | `player.md` 3 |
| 콘텐츠 상세 화면 | 상단 바 우측 [공유] 아이콘 (신설 2026-08-25) | `content-detail.md` 4.2 |

- 네 진입점의 동작은 **완전히 동일하다.** 진입점마다 규칙을 다시 정하지 않는다([원문 보기]·[상세 정보]와 같은 통일 원칙 — README 결정 44)
- 공유는 **어떤 티어에서도 페이월이 뜨지 않는다**(담기와 같은 원칙 — PRD 5.4). 공유 대상 콘텐츠를 재생했는지·차감했는지와도 무관하다

## 3. 입력값

| 값 | 설명 | 필수 |
|---|---|---|
| content_id | 공유할 콘텐츠 | 필수 |

공유 텍스트 조립에 쓰는 제목·저자·출처는 **진입점 화면이 이미 들고 있는 응답 값**을 그대로 쓴다. 공유를 위해 서버를 다시 호출하지 않는다.

## 4. 처리 로직

### 4.1 공유 실행

- 진입점 탭 → **OS 표준 공유 시트를 연다.** 앱이 자체 공유 UI(수신 대상 선택·미리보기 등)를 그리지 않는다 — 시트의 모양·대상 목록은 OS 소유다
- 더보기 시트에서 진입한 경우, [상세 정보]와 동일하게 **더보기 시트는 닫히고** OS 공유 시트가 열린다
- 공유 시트에 전달하는 내용: **텍스트 + 링크**
  - 텍스트: **콘텐츠 제목 + 저자·출처**. 저자가 없는 콘텐츠(`ai_generated`의 `author_name = null`)는 출처(`source_name`)만 싣는다 — "저자 없음"으로 채우지 않는다(`content-detail.md` 4.3-1과 같은 원칙)
  - 링크: 4.2의 공유 링크
- **조립은 전부 클라이언트가 한다. 서버 엔드포인트는 없다**(`explore-api.md` 1장 — P1에도 없다). 공유 텍스트 형식(줄바꿈·순서)은 uiux 작성 시 확정한다

### 4.2 공유 링크 — 콘텐츠 상세로 연결한다 (개정 2026-08-25)

- 공유 링크는 **해당 콘텐츠의 상세 화면으로 연결되는 링크 하나**다. 수신자의 상태로 목적지가 갈린다:

| 수신자 | 링크 탭 결과 |
|---|---|
| 앱 설치됨 | 앱이 열리고 **그 콘텐츠의 상세 화면**(`content-detail.md`)으로 이동 |
| 앱 미설치 | **스토어로 폴백**(PRD 4.2 — 웹 랜딩 비범위) |

- **디퍼드 딥링크는 하지 않는다** — 미설치 수신자가 스토어에서 설치한 뒤 첫 실행에 공유된 콘텐츠를 복원해 주지 않는다. 어트리뷰션 인프라 없이는 성립하지 않고, 미설치 수신자에 대한 링크의 역할은 설치 유도까지다
- 링크의 기술 방식(유니버설 링크/App Links용 도메인 확보 vs 커스텀 스킴 + 스토어 링크 병기)은 **미결**이다(9장). 이 문서가 확정하는 것은 **목적지(상세 화면)와 폴백(스토어)** 이다
- 링크에 **`content_id` 외의 값을 싣지 않는다.** 보낸 사용자의 식별자·토큰을 담지 않는다 — 수신자의 조회 스코프는 언제나 수신자 자신의 토큰이 정한다(`explore-api.md` 7장의 커서 원칙과 동일)

### 4.3 수신자 처리 — 관문을 우회하지 않는다

- 링크로 앱이 열려도 **스플래시 실행 관문(`splash.md`)을 그대로 거친다.** 버전 체크·로그인·온보딩 판정의 어느 것도 딥링크라고 건너뛰지 않는다
- **관문을 전부 통과한 상태(온보딩 완료)의 사용자만 상세 화면으로 이동한다.** 미로그인·온보딩 미완 사용자는 **링크 목적지를 버리고 정상 진입 분기를 따른다** — 로그인·온보딩을 마친 뒤 상세로 복원해 주지 않는다(디퍼드 딥링크와 같은 이유로 두지 않는다)
- 상세 화면에 도착한 뒤의 규칙은 **전부 `content-detail.md`의 것이다** — 단건 상세 재조회, 회수·만료 시 "제공이 종료된 콘텐츠예요" 안내 후 복귀(복귀할 원 화면이 없으므로 **라이브러리로 이동**), [재생]·[담기] 판정 포함. 이 문서는 진입 경로 하나가 늘어난 것뿐이다
- 수신자의 재생은 **수신자 자신의 티어·한도로 판정한다**(`paywall.md`). 공유받은 콘텐츠라고 차감·판정이 달라지지 않는다

### 4.4 기록하지 않는 것

- **공유는 신호가 아니다.** 시트 오픈·취소·완료 어느 것도 기록하지 않는다 — `user_signals`에 `share`가 없다(`domain.md` 6.4). 시트 오픈만으로는 공유가 아니고, OS는 완료 여부를 신뢰할 수 있게 알려주지 않는다
- 공유 횟수 집계·유입 어트리뷰션을 도입하려면 `domain.md` 개정이 선행되어야 한다(9장)

## 5. 화면 상태

| 상태 | 화면 |
|---|---|
| MVP 빌드 | 네 진입점 어디에도 공유가 노출되지 않는다 |
| P1 — 더보기 시트 | [공유] 행이 담기/제거류 아래에 노출 |
| P1 — 콘텐츠 상세 | 상단 바 우측 [공유] 아이콘 |
| 공유 시트 열림 | **OS 소유 UI** — 앱은 텍스트·링크를 전달할 뿐 시트를 그리지 않는다 |
| 공유 시트 취소 | 아무 동작 없음. 토스트·안내도 없다 |
| 수신자 — 링크 탭(설치·온보딩 완료) | 관문 통과 후 콘텐츠 상세 화면 |
| 수신자 — 링크 탭(미설치) | 스토어 |

화면 ID·카피·접근성은 `spec/uiux/`가 소유한다(P1 활성화 시 작성 — 9장).

## 6. 데이터 모델

**신설 테이블·컬럼이 없다.** 공유 텍스트는 목록·상세 응답의 기존 값(`title`·`author_name`·`source_name`)으로 조립하고, 수신자의 상세 진입은 기존 콘텐츠 단건 상세 조회를 재사용한다. `user_signals`에 `share`를 추가하지 않는다(4.4).

## 7. 예외 상황

- **공유 시트에서 취소**: 아무 동작 없음. 신호도 기록하지 않는다(4.4)
- **회수·만료된 콘텐츠의 링크를 수신자가 탭**: 상세 진입 규칙 그대로 — 상세를 그리지 않고 "제공이 종료된 콘텐츠예요" 안내 후 라이브러리로 이동한다(`content-detail.md` 7)
- **존재하지 않는 `content_id`의 링크**(조작된 링크): 회수·만료와 동일하게 처리한다 — 별도 문구를 만들지 않는다
- **화면에 떠 있던 콘텐츠가 공유 직전 회수됨**: 공유 조립은 로컬이라 시트는 열린다. 수신자 쪽에서 위 규칙으로 걸러진다 — 보낸 쪽에서 공유 시점에 재검증하지 않는다
- **미로그인·온보딩 미완 수신자**: 링크 목적지를 버리고 정상 진입 분기를 따른다(4.3)
- **플레이어에서 공유**: 재생은 유지된다. OS 공유 시트가 닫히면 플레이어로 복귀한다

## 8. 완료 조건

- Given MVP 빌드 / When 네 진입점(라이브러리·탐색·플레이어 더보기 시트, 콘텐츠 상세)을 연다 / Then 공유가 어디에도 노출되지 않는다
- Given P1 빌드의 더보기 시트 / When [공유]를 탭한다 / Then 더보기 시트가 닫히고 OS 공유 시트가 열리며, 제목·저자·출처 텍스트와 상세 연결 링크가 전달된다
- Given P1 빌드의 콘텐츠 상세 / When 상단 바 [공유] 아이콘을 탭한다 / Then 더보기 시트 진입과 동일한 내용으로 OS 공유 시트가 열린다
- Given `author_name = null`인 콘텐츠 / When 공유한다 / Then 텍스트에 저자 없이 제목·출처만 실린다
- Given OS 공유 시트 / When 사용자가 취소한다 / Then 아무 동작·기록이 없다
- Given 재생 중 플레이어의 더보기 시트 / When [공유] 후 시트를 닫는다 / Then 재생이 유지된 채 플레이어로 복귀한다
- Given 앱이 설치되고 온보딩을 마친 수신자 / When 공유 링크를 탭한다 / Then 실행 관문을 거쳐 그 콘텐츠의 상세 화면이 열린다
- Given 앱 미설치 수신자 / When 공유 링크를 탭한다 / Then 스토어로 이동한다
- Given 온보딩 미완 수신자 / When 공유 링크를 탭한다 / Then 상세로 가지 않고 정상 진입 분기(로그인·온보딩)를 따른다
- Given 회수된 콘텐츠의 공유 링크 / When 수신자가 탭한다 / Then 상세 대신 "제공이 종료된 콘텐츠예요" 안내 후 라이브러리로 이동한다
- Given 무료 수신자가 오늘 한도를 소진했다 / When 공유받은 상세에서 [재생]을 탭한다 / Then 수신자 자신의 판정대로 페이월이 뜬다
- Given 공유 실행 전 과정 / When 서버 로그를 본다 / Then 공유 전용 호출이 없다 — 수신자의 상세 조회만 기존 API로 남는다

## 미결 사항

- **링크 기술 방식** — 유니버설 링크/App Links(https 도메인 확보 필요 — 미설치 폴백이 링크 하나로 성립) vs 커스텀 스킴 + 스토어 링크 병기(도메인 불요하나 텍스트에 링크 두 개). P1 활성화 결정 시점에 도메인 확보 여부로 확정한다
- **스토어 링크 확정값** — 스토어 등록 후 실제 URL로 확정한다
- **공유 집계·유입 어트리뷰션** — 현재는 미기록 확정(4.4). 성장 단계에 필요해지면 `domain.md`(`user_signals` 또는 별도 테이블) 개정이 선행 사안이다
- **spec 작성** — `spec/uiux/`(시트 행·아이콘·공유 텍스트 형식·화면 ID), `spec/api/`는 "엔드포인트 없음" 경계 표기만(현행 `explore-api.md` 1장 유지). P1 활성화 시 작성한다
- 와이어프레임 `wireframe/share.html`의 화면 ID(SH 계열)는 **제안이며 uiux 미채택 상태**다
