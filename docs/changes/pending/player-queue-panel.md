# [문서] 플레이어 재생 목록 패널의 원천을 정한다 — "플레이리스트 없음" 결정 개정

| 항목 | 값 |
|---|---|
| 대상 문서 | `features/player.md` 4장(이어폰 조작 표)·8장(미결) · `spec/uiux/player-uiux.md` 4.6·6장·8장 |
| 요청 파트 | 문서(FE 구현은 `feat(fe)/player-queue-library-source`에서 선반영) |
| 발행 날짜 | 2026-09-17 |
| 발견 시점 | FE 워크트리(별도 에이전트)가 "유튜브 뮤직처럼 재생목록을 끌어올리면 플레이어가 압축되게" 지시로 만든 패널을 dev 의 플레이어 개편(`player-controls-redesign.md`)에 통합하면서 — 패널 자체는 개편에 이미 있었고, **목록의 원천과 선택 동작**이 이 문서의 몫이다 |

## 자리·전환 (2026-09-17 PM 확정 — 유튜브 뮤직 방식, `player-controls-redesign.md` 4.6 의 "히어로 압축 패널"에서 개정)

재생 목록은 스크립트와 **다른 전환**이다. 스크립트는 히어로가 가로 헤더로 압축되고 그 아래(컨트롤 위)에 패널이 서지만, 재생 목록은:

- **아래에서 올라오는 시트**다. 닫힘엔 화면 바닥에 손잡이("재생 목록")만 보인다.
- 손잡이를 끌어올리면 **손가락이 곧 진행값**이다 — 시트가 올라온 만큼 위의 플레이어가 **세로 구조(아트워크 → 제목·카테고리 → 시크바 → 컨트롤) 그대로** 공백을 접으며 압축된다. 앨범 사진이 **화면 가로를 꽉 채우는 배경**(앱바 위부터 시크바 시간 라벨까지, 어두운 오버레이 0.45)이 되고, 앱바 아이콘·제목·카테고리·시크바는 그 위에 **흰색**으로 얹힌다(유튜브 뮤직). 제목은 사진 아래쪽 가장자리, 시크바는 사진의 맨 아래 띠. 컨트롤 줄은 사진 밖 흰 바탕에 그대로 남는다.
- 목록은 **컨트롤 아래**, 손잡이 밑에 선다. 시트가 열린 위치 = 압축된 플레이어(앱바 + 배너 히어로 + 컨트롤) 바로 아래.
- 놓으면 이동 비율 35% 또는 속도 0.5dp/ms 로 열림/닫힘 확정(제안값, 실기기 검증 대상). 탭은 토글. 목록 위 오른쪽 스와이프는 닫힘.
- 스크립트 패널과 동시에 열리지 않는다 — 하나를 열면 다른 하나가 닫힌다.

## 관계 — `player-controls-redesign.md` 와의 분담

- 손잡이 자리·좌우 스와이프 문법은 `changes/pending/player-controls-redesign.md` 4.2·4.6 과 같다. **재생 목록의 전환은 위 "자리·전환" 절이 우선한다**(4.6 의 압축 패널 설명은 스크립트에만 해당).
- 이 문서는 **목록이 무엇인지, 줄을 누르면 무엇이 되는지, 카피**를 정한다. `player-controls-redesign.md` 의 계약 요청 3("재생 목록 정의 — 어느 문서에도 없다")은 이 문서로 **해소**된다.

## 짚어둘 구분 — 재생 목록 패널 ≠ 연속 재생

| | 이번 도입 | 여전히 비범위 |
|---|---|---|
| 목록 열람·선택 | **들어왔다**(패널) | — |
| 완청 후 자동 다음 재생 | — | 그대로 비범위 |
| 이어폰 더블탭 다음 트랙 | — | 그대로 미지원 |
| 완료 화면의 다음 콘텐츠 유도 | — | 그대로 넣지 않는다 |

FR-24(자동 재생 금지)는 **건드리지 않았다.** 사용자가 직접 고른 편만 재생된다.

## 수정 내용

### 1. `features/player.md` 4장 — 재생 목록 규칙

> **재생 목록 패널** — 목록은 **필터를 걸지 않은 라이브러리 첫 페이지**(`library-api.md` 4.1)다. 라이브러리 화면의 복제가 아니므로 검색·탭·주제 필터·페이지네이션을 두지 않는다.
> - **패널을 열었을 때만 조회하고, 열 때마다 새로 받는다.** 플레이어는 목록 없이도 제 몫을 하는 화면이다.
> - **전환도 재생 시작이므로 단일 게이트를 지난다**(`paywall.md` 4.2). 한도 확인 팝업이 뜨는 조건은 다른 진입점과 같고, 진입점 값은 목록의 정체를 따라 `library`다.
> - 지금 재생 중인 줄을 다시 눌러도 **아무 일도 하지 않는다** — 재시작이 아니라 오조작이다. 패널만 닫힌다.
> - **완청 후 자동으로 다음 줄을 재생하지 않는다.** 연속 재생은 여전히 비범위다(8장).
> - 실서버 계약: 새 엔드포인트가 필요 없다 — 클라이언트가 라이브러리 첫 페이지 조회를 재사용한다(FE 는 `app/bootstrap` 이 주입하는 브리지로 library → player 역방향 의존 없이 받는다).

이어폰 조작 표의 "(플레이리스트 없음)"을 **"(연속 재생 비범위 — 재생 목록 패널은 열람·선택 전용이다)"** 로 바꾼다.

### 2. `features/player.md` 8장 미결

"연속 재생 도입 여부 — 현재 비범위"는 유지하고 한 줄 덧붙인다: "재생 목록 패널(2026-09-17)은 이 미결과 **별개다** — 목록을 보고 고르는 수단일 뿐, 자동 다음 재생은 도입하지 않았다."

### 3. `spec/uiux/player-uiux.md`

- 4.6 "연속 재생은 비범위다"는 유지하되 "재생 목록 패널(열람·선택)은 별개"를 덧붙인다.
- 8장 "이어폰 조작은 재생/정지만 지원한다(플레이리스트가 없다)"의 괄호를 **"(연속 재생이 비범위다 — 패널은 열람·선택 전용)"** 으로 바꾼다.
- 지금 재생 중인 줄은 **색만으로 구분하지 않는다** — 제목 굵기 + 낭독 꼬리표("재생 중"). 완청한 줄은 낭독에 "완청함".
- 상태: 로딩(인디케이터) / 빈 목록 / 조회 실패(+[다시 시도]) 세 가지를 패널 안에서 그린다. 전면 오류로 바꾸지 않는다 — 플레이어는 계속 동작한다.

### 4. 확정 카피 — 6장

| 자리 | 문자열 |
|---|---|
| 손잡이 라벨 | `재생 목록` (`player-controls-redesign.md` 와 같음) |
| 패널 제목 | `재생 목록` |
| 재생 중 줄 낭독 꼬리표 | `재생 중` |
| 완청 줄 낭독 꼬리표 | `완청함` |
| 줄 낭독 | `{제목}, {N}분(, 재생 중)(, 완청함)` |
| 빈 목록 | `라이브러리가 비어 있어요` |
| 조회 실패 | `목록을 불러오지 못했어요` + `다시 시도` |

## 추가(2026-09-18) — 순서 변경

재생 목록 행 **오른쪽에 손잡이(가로줄 두 개)** 를 두고, 잡고 끌어 순서를 바꾼다(PM 요청).

- 끄는 행은 손가락을 따라가고 지나친 행은 한 칸씩 비켜 준다. 놓으면 목표 칸에 앉은 뒤 순서가 확정된다. 끄는 동안 목록 스크롤·플레이어 끌어내리기·시트 끌기는 반응하지 않는다. 목록 밖으로는 끌리지 않는다.
- 본문 탭 = 재생(종전 그대로), 손잡이 = 순서 — 영역이 갈려 있다. 손잡이 히트 영역 44pt.
- 낭독기: 손잡이는 adjustable, 라벨 `"<제목> 순서 변경, N개 중 M번째"`, 액션 "위로 이동"·"아래로 이동"이 끌기의 대체 수단이다.
- 눌림·끌기 표현은 애플 뮤직의 재생 대기 목록을 따른다: 줄에 카드 배경이 없고, **누르는 동안만 줄 전체(손잡이 포함)가 화면 끝에서 끝까지 옅은 흰색(8%)** 으로 밝아진다. 선택 상태는 따로 없다 — 재생 중 표시는 굵은 제목뿐이다. 끄는 줄은 살짝 커지고(1.03) 그림자와 불투명 밝은 면으로 떠 보인다(반투명이면 빠르게 지나갈 때 밑의 제목이 비쳐 섞였다).
- 계정 단위 저장은 BE 티켓 `tickets/backend/pending/queue-order-sync.md`(KAN-70)로 요청했다.
- **순서는 기기에만 저장한다**(`player.queue_order`, `library_items.id` 나열). 재생 목록의 원천이 "필터 없는 라이브러리 첫 페이지"라 서버에 순서를 둘 자리가 없다. 저장된 순서에 없는 새 항목은 서버 순서 그대로 **맨 위**에 온다. 다른 기기·재설치에는 따라가지 않는다 — 계정 단위로 맞추려면 BE 계약(순서 저장)이 필요하다(미결).
- **짚어둘 것**: 연속 재생이 없으므로(위 "재생 목록 패널 ≠ 연속 재생") 순서는 "다음에 뭐가 재생되나"를 바꾸지 않는다. 지금은 사용자가 들을 순서를 스스로 정리해 두는 용도다. 연속 재생이 생기면 이 순서를 그대로 쓴다.
- 구현: 끌기 라이브러리(reanimated·gesture-handler)는 네이티브 모듈이라 새 빌드가 필요해 쓰지 않았다. 행 높이를 고정하고 PanResponder 로 직접 구현해 OTA 로 나간다. 끄는 행이 뷰포트 위·아래 끝 56px 안에 들어오면 **목록이 그쪽으로 자동 스크롤**된다(끝에 깊이 들어갈수록 빠르게) — 한 번의 끌기로 보이지 않는 칸까지 옮긴다.

## 완료 조건

- Given 재생 목록이 열려 있다 / When 첫 줄의 손잡이를 잡아 두 칸 아래로 끌고 놓는다 / Then 그 줄이 셋째 자리에 앉고 사이의 줄들이 한 칸씩 올라온다
- Given 순서를 바꿨다 / When 재생 목록을 접었다 다시 열거나 앱을 다시 켠다 / Then 바꾼 순서가 유지된다
- Given 순서를 바꾼 뒤 새 콘텐츠가 담겼다 / When 재생 목록을 연다 / Then 새 항목이 맨 위에 있고 그 아래는 내가 정한 순서다
- Given 낭독기 사용자 / When 손잡이에서 "아래로 이동"을 실행한다 / Then 그 줄이 한 칸 내려간다

- Given 개정된 `player.md` 4장 / When 재생 목록 규칙을 찾는다 / Then 목록의 출처(라이브러리 첫 페이지)·게이트 통과·자동 다음 재생 금지·재생 중 줄 무반응이 적혀 있다
- Given 개정된 `player.md`·`player-uiux.md` / When "플레이리스트 없음"을 검색한다 / Then 남아 있지 않고 "연속 재생 비범위"로 좁혀져 있다
- Given 개정된 `player-uiux.md` 6장 / When 패널 카피를 찾는다 / Then 위 표와 `player.copy.ts` 의 `queuePanel` 블록이 문자열까지 일치한다
- Given 플레이어에서 재생 목록의 다른 줄을 누른다 / When 오늘 차감이 필요한 콘텐츠다 / Then 라이브러리에서 눌렀을 때와 같은 확인 팝업이 뜬다
