## 현재 규칙

`player-uiux.md` 4.1은 골격을 **앱바 / 아트워크 / 제목 / [원문 보기] / 시크바 / 컨트롤 줄 / 보조 줄(배속·타이머·스크립트 칩)** 로 못박는다. 4.6은 스크립트를 **하단 시트(핸들 + 제목 + 문단)** 로, 4.8은 축소를 **화면이 손가락을 따라 내려오는 이동**으로 적는다. 재생 목록(다음 재생)은 어느 문서에도 없다.

## 수정 내용

### 4.1 화면 골격 (개정)

```
앱바        좌: 셰브론(축소) / 우: 타이머 아이콘(P1 — 아이콘 자리만, 시트는 4.6) · 더보기 ⋯
히어로      아트워크(정사각) / 제목(한 줄, 넘치면 가로 스크롤) / 카테고리(주제명 최대 2개 "·" 연결)
시크바      + 시간 라벨
컨트롤 줄   배속(텍스트 "1.0×") · [10초 뒤로] · 재생/일시정지 · [10초 앞으로] · 스크립트 토글
하단 핸들   "재생 목록" — 위로 끌면 재생 목록 패널이 펼쳐진다
```

- **보조 줄을 없앤다.** 배속은 컨트롤 줄 왼쪽 끝에 **배경 없는 텍스트**로 두고, 타이머는 앱바로 올린다. 컨트롤이 한 줄에 모여 손끝 위치가 하나로 고정된다(4.1 "손끝 위치" 원칙 유지).
- **[원문 보기] 칩을 제거한다.** 원문은 더보기 시트(4.7)의 [원문 보기]만 남긴다 — 플레이어 본문에 같은 진입점이 둘 있을 이유가 없다. `source_link_clicks`(`player.md` 4.5) 계약은 더보기 경로가 그대로 쓴다.
- **제목이 넘치면 가로 스크롤(marquee)한다.** 두 줄로 접지 않는다 — 히어로 높이가 제목 길이에 따라 흔들리면 컨트롤 위치가 움직인다. 36dp/s, 1.8초 정지 후 순환, 모션 축소 설정에서는 말줄임으로 대체.
- **제목 아래 카테고리 줄을 둔다.** 콘텐츠의 주제(`topics`) 이름을 최대 2개 "·"로 잇는다. 주제가 없으면 줄 자체를 그리지 않는다.
- ±10초 아이콘은 **원형 화살표 안에 숫자 10**(4.2 "숫자 병기" 유지). 선 굵기 1.8.

### 4.2 컨트롤 표 (행 교체·추가)

| 컨트롤 | 표시·반응 |
|---|---|
| 배속 | 컨트롤 줄 왼쪽 끝. 텍스트만("1.0×"). 탭 → PL4 시트 |
| 스크립트 토글 | 컨트롤 줄 오른쪽 끝, 말풍선 두 개 아이콘(2인 대화체). 탭 → 스크립트 패널 열림/닫힘. 열려 있으면 primary 색 |
| 재생 목록 핸들 | 화면 하단 고정. 위로 24dp 이상 끌면 열림, 아래로 24dp 이상 끌면 닫힘, 탭은 토글 |

### 4.6 스크립트 — 시트가 아니라 **인라인 패널**이다 (개정)

- 스크립트를 열면 별도 시트가 덮는 게 아니라 **히어로가 압축된다**: 아트워크 56dp 썸네일 + 제목(lg)이 한 줄로 붙고, 그 아래 공간을 스크립트가 채운다. 시크바·컨트롤은 **위치 그대로**다 — 압축 전환 중에도 컨트롤이 움직이지 않는다(320ms, ease-out).
- 히어로에서 **왼쪽 스와이프 → 스크립트 열림, 오른쪽 스와이프 → 닫힘.** 패널 안 오른쪽 스와이프도 닫힘이다.
- 현재 구간 하이라이트(배경 + 굵기)·자동 스크롤·구간 탭 seek·텍스트 선택 차단은 기존 규칙 그대로.
- 스크립트 데이터가 없으면 **토글 아이콘 자체를 그리지 않는다**(기존 "칩 미노출" 규칙의 자리 이동).
- 재생 목록은 **이 압축 문법을 쓰지 않는다**(개정 2026-09-17 PM) — 아래에서 올라오는 시트이며, 위의 플레이어는 세로 구조 그대로 공백만 접고, 앨범 사진이 화면 가로를 꽉 채우는 배경이 되어 앱바·제목·시크바가 그 위에 흰색으로 얹힌다. 규칙은 `changes/pending/player-queue-panel.md` "자리·전환". 스크립트와 재생 목록은 **동시에 열리지 않는다**.

### 4.8 축소 — 미니플레이어로 **이어지는 모션** (개정)

- 축소(셰브론·뒤로가기·아래 스와이프)와 확대(미니플레이어 본문 탭)는 **같은 경로의 역재생**이다: 시트가 미니플레이어 카드 사각형 ↔ 전체 화면으로 늘고 줄며, 아트워크는 미니플레이어 썸네일(44dp) ↔ 히어로 아트워크, 제목은 미니플레이어 제목(sm) ↔ 히어로 제목(xl)로 크기·위치가 함께 움직인다. 열림 420ms, 닫힘 340ms.
- **아래 스와이프는 화면을 밀어 내리는 것이 아니라 이 모션의 진행값을 손가락이 잡는 것이다.** 끌어내린 만큼 아트워크가 줄고 시트가 오므라든다. 놓을 때 임계(화면 높이 20% 또는 500dp/s — 기존 제안값 유지)를 넘으면 그 자리에서 이어서 내려앉고, 미달이면 스프링으로 되돌아온다(1을 넘지 않음).
  - 종전 "화면이 손가락을 따라 내려온다" 방식은 놓는 순간 원위치에서 축소가 다시 시작돼 위로 튀었다(2026-09-16 시연에서 확인).
- 패널(스크립트·재생 목록)이 열린 채 축소하면 압축된 히어로(56dp 썸네일·lg 제목) 좌표에서 모션이 출발한다.
- **교차 페이드를 쓰지 않는다**(PM 2026-09-17 — "애플처럼"). 미니플레이어 쪽 끝에서 모션 레이어를 투명하게 하면 뒤의 진짜 미니플레이어와 몇 px 어긋난 잔상이 겹쳐 보였다. 모션 레이어는 착지까지 불투명하고, 착지 좌표는 미니플레이어 썸네일·제목의 **실측값**(measureInWindow)이며, 풀 화면 쪽 좌표도 히어로 실측·같은 수식으로 맞춘다. 컨트롤·시크바·앱바는 시트와 함께 아래로 내려가며 중간(45~80%)에 사라진다 — 카드가 통째로 접히는 느낌. 미니플레이어 ▶ 버튼은 시트가 자라는 첫 12%에서 사라지고 닫힐 때 같은 구간에서 나타난다.
- 구현 메모(architecture 대상 아님, 기록만): 플레이어 라우트는 투명 모달(`transparentModal`, 내비게이션 전환 없음)이고 미니플레이어가 자기 화면 좌표를 스토어에 올려 도착·출발 지점으로 쓴다.

## 계약 요청 (BE — `player-api.md`)

FE는 스크립트만 `IS_PLAYER_API_MOCKED`일 때 mock을 쓰고 실서버에서는 스크립트 토글을 그리지 않는다(데이터 null → 아이콘 미노출). 재생 목록은 라이브러리 첫 페이지라 실서버에서도 동작한다(2026-09-17).

1. **재생 시작 응답에 `content.topics`** — 카테고리 줄의 원천. 지금은 진입 화면(라이브러리·탐색·상세)이 가진 `topicIds`를 route 파라미터로 넘겨 쓴다. 상세 없이 딥링크로 들어오면 비어 있다. `POST /contents/:id/play` 응답(4.2)에 `topics: [{ id, name }]`를 실어 주면 진입 경로와 무관해진다.
2. **스크립트 조회** — `GET /contents/:id/script` 제안. 응답 `{ segments: [{ start_sec, end_sec, speaker, text }] }`. 대본은 윤아·이음 2인 대화체(`ai/PIPELINE.md`)이므로 `speaker`가 필요하다. AI 생성 실패 콘텐츠는 404가 아니라 `segments: []`로 — FE는 빈 배열도 "없음"으로 취급해 토글을 그리지 않는다.
3. ~~**재생 목록("다음 재생") 정의**~~ → **해소(2026-09-17)**: 필터 없는 라이브러리 첫 페이지. 새 엔드포인트 없음 — `changes/pending/player-queue-panel.md`. 손잡이는 실서버에서도 그린다.

## 추가(2026-09-18) — 미니플레이어를 끌어올려 열기 (`player-uiux.md` 4.8)

미니플레이어(PL11)를 **잡고 위로 끌면 전체 플레이어가 손가락을 따라 펼쳐진다.** 끌어내려 축소하는 것의 반대 방향이고 같은 "드래그 = 진행값" 규칙을 쓴다.

- 시작: 위로 10dp 이상 + 수직 이동이 수평의 1.5배 이상. 왼쪽 스와이프(종료)·탭과는 시작 방향으로 갈린다.
- 시작하는 순간 탭과 같은 경로로 플레이어(투명 모달)를 띄운다 — **재생을 시작시키지 않는다**(본문 탭과 동일). 복원 스냅샷 상태에서도 같다.
- 진행도 = 끌어올린 거리 ÷ (화면 높이 × 0.7). 플레이어의 열림 진행값에 그대로 들어가 썸네일·제목·시트가 손을 따라 커진다.
- 놓을 때: 진행도 25% 초과 또는 움직이던 중 위로 0.5dp/ms 이상 튕김 → 끝까지 연다. 아니면 미니플레이어 자리로 되감고 화면을 걷는다. 끌어올린 뒤 **멈췄다 놓으면 튕김으로 치지 않는다**(속도 값이 남아 있어도).
- 터치를 빼앗기면(시스템 제스처 등) 닫지 않고 끝까지 연다 — 탭한 것과 같은 결과.
- 구현: 제스처는 미니플레이어(탭 화면), 모션은 플레이어 화면이 그려 `player-open-gesture.store`로 진행도를 넘긴다.

## 완료 조건

- Given 미니플레이어가 보인다 / When 잡고 위로 화면의 1/3쯤 끌어올린다 / Then 썸네일·제목이 손을 따라 커지며 시트가 올라오고, 놓으면 전체 플레이어로 끝까지 열린다(재생 상태는 그대로)
- Given 같은 상태 / When 조금(진행도 25% 이하)만 올렸다 멈추고 놓는다 / Then 미니플레이어 자리로 되돌아가고 플레이어 화면이 걷힌다

- Given `player-uiux.md` 4.1 / When 골격을 읽는다 / Then 보조 줄·[원문 보기] 칩이 없고 배속 텍스트·앱바 타이머·카테고리 줄·재생 목록 핸들이 적혀 있다
- Given 4.6 / When 스크립트 절을 읽는다 / Then "시트"가 아니라 "히어로 압축 인라인 패널"이고 좌우 스와이프 규칙이 있다
- Given 4.8 / When 축소 절을 읽는다 / Then 미니플레이어 ↔ 전체 화면 연결 모션과 "드래그 = 진행값" 규칙이 있다
- Given `frontend/architecture.md` 4.4 / When player 행을 읽는다 / Then `interest` 의존이 사유와 함께 있다
- Given `player-api.md` 9장 / When 미결을 읽는다 / Then `content.topics`·스크립트 조회·재생 목록 정의 3건이 등재돼 있다
- Given 실서버 빌드(mock 꺼짐) / When 플레이어를 연다 / Then 스크립트 토글·재생 목록 핸들이 보이지 않는다
