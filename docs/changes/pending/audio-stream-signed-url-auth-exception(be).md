## 어긋난 지점

`convention.md` 3.3이 못박고 있다.

> **금지** — `userId`를 요청 바디·쿼리로 받지 않는다. 인증 토큰에서 꺼낸다(architecture.md 9.2, IDOR 방지).

그런데 오디오 스트리밍 라우트는 쿼리로 `user`를 받는다.

```
GET /api/v1/audio/:contentId?user=<userId>&expires=<epoch초>&signature=<HMAC>
```

문서에 예외가 기록돼 있지 않으므로, `architecture.md` 운용 원칙("이 문서와 충돌하는 구현은 리뷰에서 반려한다")상 이 코드는 **반려 대상으로 보인다.** 실제로 코드 리뷰(2026-08-11)가 이 지점을 지적했다.

## 왜 이 라우트만 예외인가

**규칙의 전제가 성립하지 않는다.** "토큰에서 꺼낸다"는 요청에 `Authorization` 헤더가 실린다는 전제인데, 이 라우트의 호출자는 앱 코드가 아니라 **네이티브 미디어 재생기**(ExoPlayer·AVPlayer)다. 재생기는 URL 문자열 하나만 받아 요청하며 우리 인증 헤더를 붙일 수 없다 — 그래서 `architecture.md` 9.4가 정한 **단기 서명 URL 자체가 인증**이다.

**그리고 IDOR가 성립하지 않는다.** 규칙이 막으려는 공격은 "남의 `userId`를 넣어 남의 리소스에 접근"인데, 이 라우트의 `user`는 스코프 입력이 아니라 **서명된 페이로드의 일부**다.

```
signature = HMAC(AUDIO_URL_SIGNING_KEY, contentId : userId : expiresAtSec)
```

- 세 값 중 **하나라도 바꾸면 서명 검증이 깨진다** — `user`를 남의 것으로 바꾸는 순간 403이다
- 남의 URL을 통째로 가져다 써도 그 URL은 원래 주인에게 발급된 것이라 접근 범위가 넓어지지 않는다 — 유출 위험은 서명 URL 일반의 성질이고, 만료(수 분)가 그 상한이다(9.4)
- 서명 비교는 상수 시간이다(타이밍 공격 방지)

**실 서버 확인**(2026-08-10~11): 서명 변조 → 403, 다른 사용자 id로 교체 → 403(단위 테스트), 만료 연장 시도 → 403. 발급 사실은 `audio_access_logs`에 남는다.

## 기록할 내용

### 1. `convention.md` 3.3 금지 불릿에 예외 한 문장

> **금지** — `userId`를 요청 바디·쿼리로 받지 않는다. 인증 토큰에서 꺼낸다(architecture.md 9.2, IDOR 방지). **예외는 오디오 스트리밍 라우트 하나다**(`GET /audio/:contentId`) — 호출자가 네이티브 재생기라 토큰을 실을 수 없어 서명 URL이 인증을 대신하며, `user`는 서명된 페이로드라 변조하면 검증이 깨진다(architecture.md 9.4).

### 2. `architecture.md` 9.4에 스트리밍 인증 모델 불릿 추가

> - **스트리밍 라우트는 JWT Guard를 쓰지 않는다.** 네이티브 재생기는 URL만 받아 요청하므로 인증 헤더를 붙일 수 없다 — 서명(HMAC, `contentId:userId:expires` 전체를 덮음)이 인증이며, 값 하나만 바꿔도 검증이 깨져 IDOR가 성립하지 않는다. 이것이 convention.md 3.3 금지 규칙의 유일한 예외다. **오브젝트 스토리지·CDN 전환 시 이 라우트와 예외가 함께 사라진다** — 그때 두 문서의 예외 문구도 걷어낸다.

## 함께 확인할 것

- **한시적 예외다.** 오브젝트 스토리지가 확정되면 스트리밍 라우트가 CDN 서명 URL로 대체되어(검증 주체가 CDN) 이 예외 자체가 소멸한다. 예외 문구에 그 소멸 조건을 함께 적어, 전환 후 문서에 죽은 예외가 남지 않게 한다.
- **레이트 리밋 미결과 무관하다.** 서명 URL 발급 경로의 리밋(`architecture.md` 9.6)은 별도 미결 항목이며 이 요청의 범위 밖이다.

- Given `convention.md` 3.3의 금지 불릿을 읽는다 / When 예외를 확인한다 / Then 스트리밍 라우트가 유일한 예외로 명시돼 있고, 사유(재생기가 토큰을 못 실음 · 서명이 인증)와 근거(9.4)가 적혀 있다
