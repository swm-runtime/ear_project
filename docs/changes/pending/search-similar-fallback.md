## 배경

`explore.md` 4.5-5는 오타 교정·초성·어간 매칭을 **지원하지 않는 것**으로 두고 "검색 쿼리 로그로 미스율을 확인한 뒤 재검토"라고 적는다. 로그(`search_query_logs`)와 요약(`admin-api.md` 4.21)은 2026-10-01부터 쌓이고 있다. PM이 2026-10-22에 **오타형 미스는 지금 막기로** 정했다 — 다만 "교정"이 아니라 **폴백**이다. 서버가 교정어를 만들어 되묻지 않고, 부분 일치가 0건일 때만 **글자가 비슷한 결과를 그대로 내고 한 줄로 알린다**.

왜 자모인가: 한글은 자모 하나가 틀리면 음절이 통째로 바뀐다("커리오"↔"커리어" — 마지막 음절이 다름). 음절 단위 트라이그램으로는 유사도가 거의 안 나온다. 자모로 풀면(ㅋㅓㄹㅣㅇㅗ ↔ ㅋㅓㄹㅣㅇㅓ) 한 자모 차이가 되어 `pg_trgm`이 잡는다. 덤으로 2자 질의("이직" → 자모 5~6자)도 트라이그램 길이를 넘어 인덱스를 탄다(4.5-5의 "2자 질의는 인덱스를 타지 못한다" 제약이 유사 검색에서는 풀린다).

**방안 B(임베딩)와의 경계**: A는 "글자가 비슷한 것", B는 "뜻이 비슷한 것"을 잡는다. "이직" 질의에 제목이 "퇴사"인 편은 A로 안 나온다 — 그건 B의 몫이고, 로그의 0건 질의가 오타형이 아닌 정상 단어로 많이 남을 때 다시 본다. **초성 검색(ㅋㄹㅇ)도 이 변경으로 되지 않는다** — 초성만 적은 별도 컬럼이 필요하다. 범위 밖.

## 수정 내용

### 1. `explore.md` 4.5-3 결과 목록 — 유사 결과 상태 추가

- 추가: **부분 일치(4.5-5)가 첫 페이지 0건이면 서버가 유사 결과(자모 트라이그램)로 대신 채운다.** 응답 `match: "similar"`이고, 화면은 격자 위에 **"‘OO’와 비슷한 결과예요"** 한 줄을 더해 보여 준다(검색어는 입력 그대로 되비춘다 — 빈 결과 문구와 같은 규칙). 격자·타일·⋯ 시트·커서 로딩은 일반 결과와 같다. 유사 결과도 0건이면 종전의 빈 결과(관련 주제 칩 + 인기)다.
- **태그 전용 검색(`#태그`)에는 폴백이 없다** — 정확 일치가 그 검색의 약속이다.

### 2. `explore.md` 4.5-5 매칭·랭킹 — "지원하지 않는 것" 개정

- 종전: "지원하지 않는 것: 초성 검색 · 오타 교정 · 형태소 어간 변형 매칭. P1에 검색 쿼리 로그로 미스율을 확인한 뒤 재검토한다"
- 개정: **오타는 "교정"이 아니라 유사 결과 폴백으로 흡수한다**(2026-10-22). 부분 일치 첫 페이지 0건 → 자모로 푼 질의와 `contents.search_jamo`(제목+태그)·주제명·시리즈 제목(스위치 켜짐일 때)의 `word_similarity` ≥ 임계값. **임계값은 서버 구현이 소유**(가중 계수와 같은 이유 — 시작 0.5, 로그로 조정). 정렬: 유사도 → 인기(직전 확정 구간) → `published_at`. 설명·저자 필드는 유사 매칭 대상이 아니다(긴 글은 유사도가 소음이 되고, 저자 오타는 드물다).
- 자모 분해는 **SQL 함수 `hangul_to_jamo(text)` 하나**로 질의·저장 양쪽을 푼다 — 분해 규칙(겹모음 ㅘ=ㅗ+ㅏ, 겹받침 ㄺ=ㄹ+ㄱ, 치는 순서대로)이 양쪽에 두 벌이면 매칭이 갈라진다. `search-text.util.ts`의 자모 분해(로그 묶음 판정용 — `domain.md` 5.7)는 그대로 두되 규칙을 같게 유지한다.
- 여전히 지원하지 않는 것: **초성 검색 · 형태소 어간 변형 · 의미 유사(동의어)**. 의미 유사는 로그의 0건 질의가 정상 단어로 많이 남을 때 임베딩(`content_embeddings`)으로 재검토한다.

### 3. `explore-api.md` 4.5 `GET /explore/search`

- 응답 최상위에 **`match: "exact" | "similar"`** 추가. 모든 200 응답에 싣는다(`items`가 비면 `"exact"`). **덧붙이는 필드라 옛 앱(1.2.x·1.3.0)은 무시하고 유사 결과를 일반 결과처럼 그린다** — 0건보다 낫다고 보고 호환으로 둔다.
- 커서에 모드가 들어간다 — 유사 결과의 `next_cursor`로 조회하면 같은 모드로 이어진다. 발급 시점과 모드가 다르면 `EXPLORE_CURSOR_INVALID`.
- 폴백 조건·대상 필드·임계값은 4.5-5가 소유하고 이 문서는 재정의하지 않는다(가중 계수와 같은 원칙).
- 예시 JSON에 `"match": "exact"` / `"match": "similar"` 추가.

### 4. `explore-uiux.md` 4.5 — E7 앞에 "유사 결과" 표시

- **결과 격자 위 안내 한 줄** — ko **"‘커리오’와 비슷한 결과예요"**, en **"Showing similar results for “커리오”"**. 보조 글자색, 격자와 같은 좌우 여백, 격자 첫 행 위에 한 줄. 상태 ID는 새로 두지 않는다(E2 격자 + 안내 줄 — 빈 상태가 아니다).
- 접근성: 결과 도착 때 안내 줄을 **한 번** 낭독한다(커서로 격자가 늘어날 때 다시 읽지 않는다).
- 교정어 되묻기("‘커리어’로 검색할까요?")는 두지 않는다 — 서버가 교정어를 만들지 않는다.

### 5. `domain.md` 5.1 `contents`

- 함수 **`hangul_to_jamo(text) RETURNS text IMMUTABLE`** — 완성형 음절(U+AC00~U+D7A3)을 초·중·종성으로 풀고 나머지 문자는 그대로. 겹모음·겹받침은 치는 순서대로 푼다.
- 컬럼 **`search_jamo text GENERATED ALWAYS AS (hangul_to_jamo(lower(title) || ' ' || coalesce(tags::text, ''))) STORED`** — 유사 검색 전용 파생 컬럼. "파생값을 컬럼으로 두지 않는다"(1.5)의 예외로 적는다 — 인덱스가 필요한 파생값이고 생성 컬럼이라 어긋날 수 없다. `tags::text`의 괄호·따옴표는 트라이그램 소음이지만 유사도에 미치는 영향이 작아 따로 펼치지 않는다.
- 인덱스 **`idx_contents_search_jamo_trgm GIN (search_jamo gin_trgm_ops)`** ★유사 검색.
- 2008행 근처 요약표의 "검색 매칭·인덱스" 행에 유사 폴백 한 줄 추가.

### 6. `domain.md` 5.7 `search_query_logs` · `admin-api.md` 4.21

- 컬럼 **`similar_count smallint NULL`** — 유사 폴백이 돌았을 때 첫 페이지 건수. NULL = 폴백이 돌지 않았다(부분 일치 결과가 있었거나 태그 전용·옛 행). **`result_count`는 종전처럼 부분 일치 건수** — 미스율 정의(`misses` = 부분 일치 0건)가 바뀌지 않아야 도입 전후를 비교할 수 있다.
- 묶음 덮어쓰기 때 `similar_count`도 마지막 질의 값으로 덮는다.
- 4.21 응답: `totals.rescued`(misses 중 `similar_count > 0`), `missed[].similar_count`(그 질의의 마지막 값). "폴백이 몇 건을 살렸는가"와 "폴백도 못 살린 질의"를 가르는 축이다 — 후자가 방안 B 판단 근거.
