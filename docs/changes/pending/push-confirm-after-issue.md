# 푸시 딥링크 재생은 발급 뒤에 확인 팝업을 정한다

| 항목 | 값 |
|---|---|
| 대상 문서 | `features/paywall.md` 4.2(확인 팝업 시점) · `features/notification.md` 4.4(알림 탭 처리) · `frontend/architecture.md` 5.2(재생 시작 게이트) |
| 발행 날짜 | 2026-09-20 |
| 발견 시점 | KAN-69·KAN-81 실기기 확인 — 없는 콘텐츠의 알림에도 "오늘 N회 남았어요"가 먼저 떴다(KAN-86) |
| 코드 | PR `feat(fe)/push-confirm-after-issue` — `player/hooks/usePlayGate.ts` · `player/services/playback.service.ts` |

## 수정 내용

- **푸시 딥링크에 한해** 재생 시작 게이트의 순서를 바꾼다: **발급(`audio-urls`) → (차감될 재생이면) 확인 팝업 → 재생.** 목록·탐색·미니플레이어 진입은 종전대로 팝업 → 발급이다.
- 근거: 발급은 차감하지 않는다(`player-api.md` 4.1 — 차감은 소리가 난 시점의 `POST /play`). 팝업보다 앞서도 "동의 없이 차감하지 않는다"(`paywall.md` 4.2)를 어기지 않는다.
- 발급이 404(없음)·403(회수)이면 **팝업 없이** 라이브러리 + "콘텐츠를 찾을 수 없어요". 발급 시점의 한도 403 이면 팝업 없이 페이월·한도 안내.
- **플레이어는 발급이 성공한 뒤에만 연다.** 없는 콘텐츠로 네이티브 모달을 띄웠다 곧바로 닫으면 iOS 에서 화면이 굳는다(2026-09-20 실기기).
- 팝업 여부의 힌트(`is_counted_today`)는 푸시에 실려 오지 않는다 — 발급 뒤에 재생 목록(라이브러리 첫 페이지, `sort=queue`)에서 찾는다. 못 찾으면 "아직 안 들었다"로 본다(팝업이 한 번 더 뜰 뿐, 차감 판정은 서버가 한다). 이미 재생 중인 같은 콘텐츠의 세션을 이어 듣는 경우는 묻지 않는다.
- 팝업에서 [취소]하면 받아 둔 세션을 내린다 — 듣지 않기로 한 콘텐츠가 미니플레이어에 남지 않는다.

## 사유

푸시는 그 콘텐츠가 아직 있는지도, 오늘 들었는지도 모르는 채로 들어온다. 종전 순서로는 없는 콘텐츠에 "재생하면 1회가 차감돼요"를 먼저 묻고, [재생하기]를 누른 뒤에야 "콘텐츠를 찾을 수 없어요"가 돌아왔다 — 동의를 받아 놓고 거절하는 순서다. 오늘 이미 들은 콘텐츠의 알림에도 차감이 없는데 팝업이 떴다.
