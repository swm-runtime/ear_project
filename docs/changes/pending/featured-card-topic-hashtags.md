# [문서] 인기 대표 카드 하단 줄 — 저자 → 주제 해시태그

| 항목 | 값 |
|---|---|
| 대상 문서 | `spec/uiux/explore-uiux.md` 5장 공통 컴포넌트 규칙(콘텐츠 타일 행) · 인기 섹션 절의 대표 카드 서술 |
| 요청 파트 | 문서(구현은 프론트엔드 `feat(fe)/featured-card-hashtags`) |
| 발행 날짜 | 2026-09-28 |
| 발견 시점 | 2026-09-28 00:55~01:06 PM — "차라리 조회수나 해시태그 같은 걸 넣지 저거 플레이 버튼은 왜 넣은 거야" → "해시태그 ㄱㄱ" |

## 무엇을 고치는가

인기 대표 카드(`ExploreFeaturedCard`) 하단 줄의 보조 글자를 **`저자 · N분` → `#주제 … · N분`**(주제 최대 2개)로 바꾼다. 주제를 못 찾으면 **길이만** 적는다.

## 사유

- **저자는 정보가 거의 없다.** 콘텐츠 제작 구조상 진행자가 윤아·이음 두 값뿐이라, 카드마다 같은 글자가 반복됐다.
- **작은 타일과 어긋났다.** `ExploreTile` 은 애초에 길이만 적는데 대표 카드만 저자를 보여 줬다 — 같은 타일 문법이라는 5장 규칙과 맞지 않았다.
- **주제는 탐색에서 고르는 축이다.** 주제 칩·필터·검색 추천 키워드가 모두 주제로 돌아가므로, 카드에서 주제를 보여 주면 "이 칩을 눌렀을 때 뭐가 나오는가"가 이어진다.
- 같은 자리에 있던 **재생 버튼은 걷어냈다**(PR #885) — 타일의 히트 영역은 본문 탭·⋯ 둘뿐이라는 5장 규칙 위반이었다. 그 자리를 정보로 채운 것이 이 변경이다.

## 구현 메모

- 서버 응답의 콘텐츠에는 **주제 id 만** 있다(`ExploreContent.topicIds`). 이름은 **화면이 이미 받아 둔 주제 목록**(칩 줄용)으로 푼다 — **서버 계약 변경 없음**.
- 못 찾은 id 는 버린다(목록 미도착·삭제된 주제). 플레이어 제목 줄의 `queueCategoryOf` 와 같은 규칙이다.
- 최대 2개 — 그 이상은 길이를 밀어낸다.
- 해시태그 서식은 `EXPLORE_COPY.row.hashtags` 가 갖는다. **이름 사이 공백은 붙이지 않는다**(`#경제 상식`) — 붙여 쓰면 칩·필터에 보이는 이름과 달라져 같은 주제로 안 읽힌다.

## 같이 검토했고 하지 않은 것 — 조회수

PM 이 대안으로 든 **조회수(재생 수)는 지금 넣을 수 없다.** 인기 정렬은 서버가 "그 구간의 재생 수 → 완청 수 → 신선도"로 하지만(`explore-api.md` 4.2-1) **그 숫자를 응답에 내려주지 않는다.** 응답의 `daily_play_count` 는 **그 사용자의 오늘 재생 수**라 다른 값이다. 넣으려면 콘텐츠 응답에 집계 필드를 더하는 **BE 계약 추가**가 선행돼야 한다(별도 요청·티켓).

## 완료 조건

- Given `explore-uiux.md` 5장·인기 섹션 절 / When 읽는다 / Then 대표 카드 하단 줄이 "주제 해시태그(최대 2) + 길이"로 적혀 있고, 저자 서술이 없다
- Given 주제를 못 찾는 콘텐츠 / When 대표 카드를 본다 / Then 길이만 보이고 빈 해시태그 자리가 남지 않는다
- Given 대표 카드 / When 히트 영역을 센다 / Then 본문 탭·⋯ 둘뿐이다(재생 버튼 없음)
