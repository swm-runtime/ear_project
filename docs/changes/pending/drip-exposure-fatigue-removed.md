## 왜 뺐나

- **변별이 0이었다.** 관심 주제가 최대 3개라 후보 300편이 전부 그 주제 안에 있고, 드립을 2주 받았으면 그 주제는 다 "최근 편성 주제"다. 모든 후보가 같은 비율로 깎이면 순위는 바뀌지 않는다.
- **단위를 저자·키워드로 바꾸는 안은 폐기했다.** 좋아하는 저자를 연달아 주는 것은 ② 신호 선호 축(저자 +)이 시키는 일이다. 거기에 "같은 저자 반복 −"를 붙이면 두 축이 싸워 "좋아하는 저자를 적당히 덜 준다"는 어정쩡한 결과가 된다.
- **원래 잡으려던 것("반복해서 줬는데 반응이 없다")은 무시 신호가 사용자 반응으로 판정한다**(`changes/pending/drip-ignore-signal.md`, 2026-09-24). 같은 저자 3편을 줬는데 안 열면 −0.3 × 3, 다 들었으면 +1 × 3. 반응을 보지 않고 반복 자체를 벌주는 항목은 필요가 없어졌다. 하루 안에 비슷한 두 편이 함께 오는 것은 MMR(4.2-3)이 막는다.

## 넣을 내용

### 4.2 ③ 표
"노출 피로 | 최근 편성에서 반복된 주제에 감점" 행을 **삭제**하고 표 아래에 한 줄: "종전 노출 피로 항목(최근 2주 편성 주제 반복 감점)은 2026-09-25 폐기 — 관심 주제 상한(3개) 안에서는 변별이 없고, 반복에 대한 판정은 4.3의 무시 신호가 사용자 반응으로 한다."

### 가중치(서버 소유 — 문서에는 방향만)
항목 비중 0.1을 주제 적합도·인기도에 나눴다(0.25 → 0.30 씩). 콜드스타트 인기도 0.45 → 0.50. 4.4의 "인기도·신선도 비중을 높이고" 서술은 그대로 맞다.

### 편성 미리보기(admin)
`exposure_fatigue` 필드는 응답에 남는다 — 정규 편성은 항상 `null`(항목 빠짐), 탐험 편성은 종전대로 저노출 가점. "최근 편성 주제" 표시도 남는다(정보 표시일 뿐 스코어링 입력이 아니다). `admin-api.md` 편성 미리보기 절에 이 두 줄을 덧붙인다.

## 완료 조건

- Given `drip-scheduling.md` 4.2 ③ 표 / When 읽는다 / Then 노출 피로 행이 없고 폐기 사유·대체(무시 신호·MMR)가 한 줄로 적혀 있다
- Given 편성 미리보기 응답 / When 정규 편 breakdown 을 본다 / Then `exposure_fatigue` 가 `null` 이고 탐험 편은 저노출 값이다
- Given 같은 주제 후보만 있는 사용자 / When 편성 배치가 돈다 / Then 종전과 같은 순위가 나온다(항목이 전 후보를 같은 값으로 깎던 것이라 결과 불변)
