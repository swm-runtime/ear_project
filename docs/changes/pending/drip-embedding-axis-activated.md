## 수정 내용

미결 사항의 임베딩 모델 항목이 이렇게 끝난다:

> 스코어링의 임베딩 축 활성화(벡터 마이그레이션·`content_embeddings` 신설·소급 부여)는
> `tickets/backend/pending/metadata-pipeline-after-script-quality.md`의 순서대로 진행한다 —
> **그 전까지 4.2는 임베딩 축 제외 재정규화로 동작**

마지막 문장을 현행화한다:

> 스코어링의 임베딩 축(4.2 ①)·취향 벡터(4.3-1)·MMR 다양성 판정(4.2-3)은 **2026-09-07 활성화됐다.**
> 스코어링은 현재 모델(`text-embedding-3-small`)·현재 `content_version`과 일치하는
> `content_embeddings` 행만 읽으므로 모델 혼용·재발행 후 미갱신 행은 자연히 축 제외된다
> (`domain.md` 5.6의 "model 단일성 확인"의 구현). 다만 **임베딩 데이터 유입 경로(관리자
> 업로드의 `enrichment_file` 파싱·저장, 기존 발행분 소급 부여)가 아직 없어**, 행이 채워지기
> 전까지 실제 스코어링은 종전(4.2의 결여 축 재정규화)과 동일하게 동작한다 — 남은 진행은
> 같은 티켓의 순서를 따른다.

## 사유

- 문서가 "임베딩 축 제외로 동작"이라고 말하는 동안 구현은 축을 켰다. 미결 문구를 두면 다음
  작업자가 축이 없다는 전제로 코드를 읽게 된다.
- 5장 "추천 입력 결손" 운영 콘솔 노출(재발행 후 미갱신 검출 목록)은 **여전히 미구현**이라
  이 수정에 포함하지 않는다.

## 완료 조건

- Given `drip-scheduling.md` 미결 사항 / When 임베딩 모델 항목을 읽는다 / Then 축 활성화 완료와 "데이터 유입 전까지 종전과 동일 동작"이 적혀 있고, "그 전까지 임베딩 축 제외로 동작" 문구가 없다
