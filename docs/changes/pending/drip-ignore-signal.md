## 넣을 내용

### 4.3 신호 해석 표에 한 행 추가

| 신호 | 해석 | 반영 |
|---|---|---|
| **무시** (드립·탐험 편성분이 **7일**이 지나도 `unplayed`, 삭제도 안 됨) | 약한 부정 | 해당 주제·저자·키워드·형식 가중치 **−0.3**(삭제 −0.6의 절반). 취향 벡터(4.3-1)·길이 분포에는 넣지 않는다 |

- **`user_signals` 행이 아니다.** 편성 배치가 취향 캐시를 재계산할 때 `library_items(source IN (drip, discovery), status = unplayed, deleted_at IS NULL, added_at < now − 7일)`에서 **파생**한다. 저장하지 않고 배치마다 다시 계산한다 — 스키마 변경 없음.
- **신호 시각은 판정 시각(적립 + 7일)** 이다. 그날부터 다른 신호와 같은 반감기(14일)로 흐려진다. 나중에 재생하면 `unplayed`가 아니어서 자동으로 빠진다.
- **삭제분은 제외한다** — 삭제는 이미 `delete`(−0.6)로 잡히므로 같은 항목을 두 번 벌주지 않는다.
- 왜 −0.3인가: "싫다"가 아니라 "관심이 안 갔다"이고, 바빠서 못 들은 경우가 섞인다. 삭제의 절반.
- 왜 7일인가: 통근 사용자가 주말을 포함해 한 번은 라이브러리를 볼 시간. 값은 서버 상수(`DRIP_IGNORE_AFTER_DAYS`)가 소유하며 시범 운영으로 조정한다.
- 목적: 신호가 드문 초기에 ② 신호 선호 축이 중립(0.5) 근처에 몰리는 것을 푼다 — 들은 주제 0.88 / 무시한 주제 0.35 / 모름 0.5 로 폭이 두 배가 된다.

### 4.3-1 취향 벡터
"긍정 신호만 쓴다" 문장에 **무시도 부정이라 벡터에 들어가지 않는다**를 덧붙인다.

### `domain.md` 7.2
`user_preference_vectors`의 입력 서술에 "무시 신호(라이브러리 파생, 저장 없음)"를 한 줄 추가한다.

## 완료 조건

- Given `drip-scheduling.md` 4.3 / When 신호 표를 읽는다 / Then "무시" 행이 있고 가중치·판정 기간·파생 원천·삭제 제외가 적혀 있다
- Given 4.3-1 / When 읽는다 / Then 무시가 취향 벡터에 들어가지 않는다는 것이 적혀 있다
- Given 사용자가 10일 전 받은 드립을 열지 않았다 / When 편성 배치가 돈다 / Then 그 콘텐츠의 주제 가중치가 −0.3 × 감쇠만큼 내려가고, 같은 콘텐츠를 삭제했다면 무시로 세지 않는다
