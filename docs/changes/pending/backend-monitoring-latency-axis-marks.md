# [문서] 응답시간 그래프의 축 상한 규칙과 표식 2종을 적는다

| 항목 | 값 |
|---|---|
| 대상 문서 | `features/backend-monitoring.md` 대시보드 행 |
| 요청 파트 | 문서(pipeline 구현은 `fix(ai)/latency-graph-visibility`에서 선반영) |
| 발행 날짜 | 2026-09-08 (2026-09-09 보강 — 버킷 경계·범위별 칸 폭 추가) |
| 발견 시점 | "30분에서는 조각 3개가 보이는데 6시간으로 바꾸면 오히려 사라진다"는 제보를 따라가다 |
| 심각도 | 중 — 표식의 뜻을 문서가 안 적으면 화면의 ▲·점을 아무도 해석할 수 없다 |

## 왜 필요한가

문서는 응답시간 그래프를 "버킷별 p50/p95 선"으로만 적는다. 그런데 선만으로는 두 경우에
**데이터가 있는데도 화면에서 사라진다.**

1. **앞뒤가 빈 고립된 칸** — SVG subpath 가 `moveto` 하나뿐이면 길이가 0이라 기본
   `stroke-linecap: butt` 에서 아무것도 그려지지 않는다. 한산한 시간대일수록 자주 생긴다.
2. **느린 요청 하나가 축을 끌어올릴 때** — 표본이 적은 버킷의 p95 는 곧 그 버킷의
   최댓값이다(1분 버킷·표본 4건이면 항상). 2,400ms 요청 하나면 y축이 2,400ms 가 되고
   40ms 대 p50 선은 y 108/110 으로 x축에 붙어 보이지 않는다.

## 수정 내용

대시보드 행에 응답시간 그래프의 규칙을 덧붙인다.

| 항목 | 규칙 |
|---|---|
| y축 상한 | 버킷별 p95 들의 **중앙값 × 4**. 단 실제 최댓값을 넘지 않고 최소 50ms. 이상치가 없으면 최댓값과 같다 |
| ▲ (주황 삼각형) | 그 버킷의 p95 가 축 상한을 넘어 **위에서 잘렸다**는 표시. 값은 툴팁이 늘 실제값으로 보여준다 |
| 점 (선 없이 찍힌 원) | 앞뒤 칸이 모두 비어 **선으로 이을 상대가 없는** 칸. 값이 없다는 뜻이 아니다 |
| 선 끊김 | 요청이 없는 칸. 없는 값을 이어 그려 없던 추세를 만들지 않는다 |
| 버킷 경계 | **벽시계**(칸 폭의 배수)에 맞춘다. 화면을 연 시각에 붙이면 새로고침만 해도 칸과 라벨이 통째로 밀려 같은 시각의 값이 매번 달라졌다 |
| 범위별 칸 폭 | 30분→1분 · 1시간→2분 · 3시간→5분 · 6시간→10분. **범위를 바꾸면 같은 시각의 p50/p95 가 달라지는 것이 정상이다** — 10분 칸은 5분 칸 두 개를 합친 표본의 백분위다 |

## 완료 조건

- Given `features/backend-monitoring.md` / When 대시보드 행을 읽는다 / Then y축 상한 산출 규칙이 적혀 있다
- Given 같은 문서 / When ▲ 를 찾는다 / Then 축 상한 초과로 잘렸다는 뜻과 툴팁이 실제값을 준다는 점이 적혀 있다
- Given 같은 문서 / When 선 없이 찍힌 점을 찾는다 / Then 고립된 칸이라는 뜻이 적혀 있고 선 끊김과 구분된다
- Given 같은 문서 / When 버킷 경계 규칙을 찾는다 / Then 벽시계에 맞춘다는 점과 그 이유(새로고침 안정성)가 적혀 있다
- Given 같은 문서 / When "3시간과 6시간의 값이 왜 다른가"를 찾는다 / Then 칸 폭이 달라 표본 집합이 다르기 때문이라고 적혀 있다
