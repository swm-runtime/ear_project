# 알림 사전 안내 — 되짚기 팝업 폐지 · 버튼 가로 배치 (문서 반영 요청)

| 항목 | 값 |
|---|---|
| 발행 날짜 | 2026-09-06 |
| 발행자 | FE |
| 대상 문서 | `features/notification.md` 4.1 · `spec/uiux/onboarding-uiux.md` 4.8(되짚기 팝업 O11 잔재) |
| 관련 코드 | `frontend/src/features/notification/components/NotificationPrePromptModal.tsx` · `ReconsiderDialog.tsx`(삭제) |

## 확정 내용

1. **[나중에]는 되묻지 않고 바로 닫는다.** 되짚기 팝업(ReconsiderDialog)을 폐지하고 컴포넌트·카피를 함께 지웠다.
2. **사전 안내의 두 버튼을 가로로 둔다** — [나중에] 왼쪽(면·테두리 없음), [알림 받기] 오른쪽(면 채움). 동등 비중.
3. 다이얼로그·바텀시트의 모서리를 `radius.xl`(24)로 올렸다. 토큰을 새로 추가해 8곳을 한 번에 맞췄다.

## 왜 폐지했나

되짚기는 전환율을 올리지만 **거절을 한 번 무르는 상호작용**이다. 한 번으로 제한해도 "닫으려는데 또 뜬다"는 인상이 남는다. 우리에게는 **거절해도 되돌릴 수 있는 구조가 이미 있다** — [나중에]는 OS 다이얼로그를 띄우지 않으므로 권한이 "미결정"으로 남고, 설정의 알림 유도 배너((b)안, `notification.md` 4.1)가 회수 경로를 맡는다. 팝업을 한 번 더 띄워 얻는 것보다 잃는 인상이 크다고 판단했다.

**OS 다이얼로그를 [알림 받기]에서만 띄우는 규칙은 그대로다.** 그것이 이 화면의 존재 이유다.

## 수정 요청

- `notification.md` 4.1에서 되짚기 팝업 서술을 제거하고, [나중에]가 곧바로 닫는다는 것과 회수 경로가 설정 배너라는 점만 남겨 달라.
- `onboarding-uiux.md` 4.8에 O11(되짚기) 잔재가 있으면 함께 정리해 달라.
- 사전 안내의 버튼 배치(가로·순서·[나중에]는 면 없음)를 uiux에 반영해 달라.

## 완료 조건 (Given/When/Then)

- Given `notification.md` 4.1을 열었을 때, When 반영이 끝나면, Then 되짚기 팝업 서술이 없고 [나중에]가 즉시 닫는다고 적혀 있다.
- Given 사전 안내 화면에서, When [나중에]를 누르면, Then 추가 팝업 없이 닫히고 OS 권한은 미결정으로 남는다.
- Given 권한이 미결정인 사용자가 설정에 들어갔을 때, When 알림 섹션을 보면, Then 유도 배너가 노출된다(기존 규칙 불변).
