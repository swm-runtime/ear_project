## 수정 내용

- 세션이 **로그인 완료(+ 온보딩 완료)** 로 확정되는 순간 라이브러리 첫 화면(전체 탭·필터 없음)의 첫 페이지를 받아 화면과 **같은 캐시 키**에 넣고, 그 응답의 썸네일을 디스크 캐시로 미리 받는다(`expo-image` `Image.prefetch`).
- 콜드 스타트에서는 이 시점이 **로고 모션 도중**이다. 관문은 모션이 끝날 때까지 어차피 기다리므로(4-6) 그 시간을 쓴다.
- **관문을 붙잡지 않는다.** 미리 받기가 늦거나 실패해도 스플래시는 종전 조건(세션 판정 · 로고 모션 · 마지막 탭 읽기)으로만 넘어간다. 못 받았으면 화면이 평소대로 받는다. 실패를 사용자에게 알리지 않는다.
- 미리 받은 직후 화면이 같은 목록을 또 받지 않도록 목록 조회에 5초의 신선 구간을 둔다. 삭제·담기·포그라운드 복귀의 무효화는 종전대로 즉시 다시 받는다.
- 판정은 없다 — 표시용 데이터를 일찍 받을 뿐이고 재생 한도·만료 판정은 그대로 서버가 한다.

## 사유

스플래시의 1~2초는 사용자가 어차피 기다리는 시간인데 네트워크는 놀고 있었다. 라이브러리가 뜬 뒤에야 목록을 받고, 목록이 온 뒤에야 썸네일을 받아서 첫 화면이 "빈 화면 → 스켈레톤 → 글자 → 그림" 순으로 채워졌다.

## 범위 밖

- 탐색 탭으로 착지하는 경우(마지막 탭 복원)의 탐색 피드 — 구간이 여럿이라 따로 본다.
- 미니플레이어 복원 대상 — 목록 첫 페이지에 같은 썸네일이 들어 있는 경우가 대부분이다.

## 완료 조건

- Given 로그인된 사용자가 앱을 콜드 스타트한다 / When 스플래시가 끝나 라이브러리가 뜬다 / Then 목록이 스켈레톤 없이 곧바로 그려지고, 목록 조회는 스플래시 중의 1회뿐이다
- Given 미리 받기가 실패하거나 늦다 / When 스플래시의 종전 조건이 충족된다 / Then 스플래시는 그대로 넘어가고 라이브러리가 평소대로 목록을 받는다
- Given 온보딩을 마치지 않은 사용자 / When 앱을 실행한다 / Then 미리 받기를 하지 않는다
