# [문서] 주제 목록 빈 응답은 폴백이 아니라 O6이다 — 폴백 전제 문단 전면 개정

| 항목 | 값 |
|---|---|
| 대상 문서 | `spec/uiux/onboarding-uiux.md` 2·3·4.2·8장 · `features/onboarding.md` 7 · `spec/api/onboarding-api.md` 4.2·9 · `spec/uiux/interest-management-uiux.md` 4.7·9 |
| 요청 파트 | 문서(FE 구현은 `fix(fe)/onboarding-empty-topic-list`에서 선반영) |
| 발행 날짜 | 2026-09-09 |
| 발견 시점 | KAN-41(`tickets/frontend/pending/onboarding-empty-topic-list-state.md`) 처리 중 — 빈 목록을 O6으로 그리라는 요청이 uiux의 **명시적 금지 항목**과 정면으로 충돌했다 |
| 심각도 | **중** — 지금 문서대로 구현하면 서버가 만들지 않는 폴백을 클라이언트가 기다린다 |

## 왜 필요한가

BE가 2026-09-09 `fix(be)/audit-followups-0909`에서 **숨김 주제 폴백을 제거했다.** 종전에는 노출
주제가 0건이면 `is_visible`을 무시하고 전체를 내려줬는데, **그 목록은 저장할 수 없었다** — 저장
API가 같은 `is_visible`로 거부하므로 사용자는 고를 수는 있는데 [다음]에서 400을 받고, 재조회해도
같은 목록을 다시 봤다. 빠져나갈 수 없는 화면이었다.

지금 서버는 `items: []`를 200으로 내려주고 운영 알림을 올린다
(`backend/src/modules/interest/services/topic.service.ts`).

그런데 **문서 세 곳이 아직 폴백을 전제로 서 있고, 그중 하나는 이 티켓이 요구하는 처리를 금지한다.**

## 수정 내용

### 1. `spec/uiux/onboarding-uiux.md` — 폴백 전제 문단 4곳

| 위치 | 현행 | 개정 |
|---|---|---|
| 2장 "화면을 만들지 않는 상태" 표 | "주제 목록이 빈 배열 / 에러가 아니다. **O1을 기본 주제 세트(하드코딩 폴백)로 그린다**" | **행 삭제.** 빈 배열은 O6으로 그린다 — 만들지 않는 화면이 아니다 |
| 3장 화면 흐름도 | `└─ 목록 빈 배열 ──> O1 (기본 주제 세트 · 에러 아님)` | `└─ 목록 빈 배열 ──> O6 ──[다시 시도]──> O1` |
| 4.2 마지막 두 불릿 | "**목록이 빈 배열로 오는 것은 실패가 아니다.** O6을 띄우지 말고 기본 주제 세트로 O1을 그린다" + 그 이유("[다시 시도]를 눌러도 영원히 같은 결과") | 아래 **"O6 — 0건 변형"** 로 대체 |
| 8장 금지 사항 | "목록 빈 응답을 **조회 실패(O6)로 처리**하는 것 — 기본 주제 세트 폴백이다" | **항목 삭제**, 대신 "빈 응답에 **폴백 주제를 클라이언트가 만들어 그리는 것**"을 금지로 넣는다(`onboarding.md` 7 정합) |

**4.2에 넣을 문단(안):**

> - **목록이 빈 배열로 오면 O6을 그린다.** 응답은 200이지만 사용자가 할 수 있는 일이 [다시 시도]
>   하나로 조회 실패와 같고, 1단계에는 [건너뛰기]가 없어 여기서 그리지 않으면 **앱을 껐다 켜도
>   같은 빈 화면으로 돌아온다.**
> - **다만 카피는 다르다.** 불러오기는 성공했으므로 "불러오지 못했어요"라고 말하지 않는다.
>   `onboarding.md` 7이 이 상태에 "준비 중입니다" 안내를 지정해 뒀다.
>   - 문구(FE 선반영, **확정 필요**): **"아직 준비 중이에요"** + "주제를 준비하고 있어요.\n잠시 후 다시 시도해주세요"
> - **클라이언트가 폴백 주제를 만들지 않는다.** 하드코딩한 `topic_id`는 `user_interests`의 FK를
>   만족하지 못한다(`onboarding-api.md` 4.2). 운영이 `is_visible`을 켜는 순간 같은 재시도가 통과한다.

> **왜 종전 이유("[다시 시도]를 눌러도 영원히 같은 결과")가 더는 성립하지 않는가** — 그 판단은
> 폴백 목록이 저장 가능하다는 전제 위에 있었다. 실제로는 저장이 거부돼 **폴백을 그리는 쪽이**
> 영원히 같은 결과였다. 0건은 운영이 노출을 켜면 해소되는, 재시도가 실제로 통하는 상태다.

### 2. `features/onboarding.md` 7 — 문구 지정을 uiux로 넘긴다

현행 176행은 "사용자에게는 **"준비 중입니다" 안내만 노출**한다(진입은 막지 않되 폴백 주제를
만들지 않는다)"이다. 규칙(폴백 금지·운영 알림)은 그대로 두되, **확정 카피는 uiux 소유**이므로
`"준비 중입니다"`를 예시가 아닌 규칙으로 읽지 않게 다음으로 바꾼다.

> 그럼에도 목록이 0건이면 **데이터 정합성 오류**로 다루어 운영 알림을 발생시키고, 사용자에게는
> **재시도할 수 있는 "준비 중" 안내를 노출한다**(전체 화면 + [다시 시도] — 화면·확정 카피는
> `onboarding-uiux.md` 4.2). **폴백 주제를 만들지 않는다.**

"진입은 막지 않되"는 삭제한다 — 주제가 0건이면 저장할 값이 없어 1단계를 통과할 방법이 없고,
문구만 남으면 [건너뛰기]를 되살리려는 시도를 부른다(8장 금지 항목과 충돌).

### 3. `spec/api/onboarding-api.md` — `is_fallback` 사문화 명시

계약 필드는 **유지한다**(제거하면 배포 순서에 따라 클라이언트가 깨진다). 다만 값이 항상 `false`가
됐으므로 4.2의 설명 셋을 고친다.

| 위치 | 개정 |
|---|---|
| 필드 표 `is_fallback` | "관리자가 설정한 노출 주제가 없어 기본 주제 세트를 내려보낸 상태" → **"레거시. 서버가 폴백 세트를 만들지 않으므로 항상 `false`다. 계약 호환을 위해 필드만 남는다"** |
| "기본 주제 세트는 서버가 내려준다" 불릿 | **삭제** — 내려주지 않는다 |
| "`is_fallback = true`는 정상 상태가 아니다" 불릿 | **"노출 주제가 0건이면 `items: []`를 200으로 반환하고 서버가 운영 알림을 발생시킨다"** 로 대체 |
| 9장 미결 "주제 목록이 비었을 때의 기본 세트" | **미결에서 내린다** — 기본 세트를 두지 않기로 확정됐다 |

### 4. `spec/uiux/interest-management-uiux.md` 4.7·9 — 미결의 선택지 (a) 소멸

9장은 빈 목록 처리를 미결로 두고 **(a) 온보딩과 같은 폴백 세트 (b) 조회 실패(IM9)와 동일**
두 선택지를 적어 놨다. 폴백이 사라졌으므로 **(a)는 자동 탈락**이다. 미결 항목을 다음으로 좁힌다.

> **주제 목록이 빈 배열로 오는 경우의 처리** — 폴백 세트 선택지는 소멸했다(서버가 만들지 않는다).
> 남은 선택지는 **(b) 조회 실패(IM9)와 동일하게 그린다** vs **(c) 그대로 빈 칩 영역을 둔다**이다.
> IM은 앱바 뒤로가기가 있어 온보딩과 달리 **갇히지는 않는다** — 그래서 온보딩만큼 급하지 않다.
> **동작 규칙이므로 `features/interest-management.md`가 정해야 한다.**

## 완료 조건

- Given 개정된 `onboarding-uiux.md` / When 8장 금지 사항을 읽는다 / Then 빈 응답을 O6으로 그리는 것이 금지 항목에 없고, 클라이언트 폴백 생성이 금지로 적혀 있다
- Given 개정된 `onboarding-uiux.md` 4.2 / When 0건 상태의 카피를 찾는다 / Then 확정 카피가 적혀 있고 `frontend/src/features/onboarding/onboarding.copy.ts`의 `emptyTitle`·`emptyDescription`과 문자열까지 일치한다
- Given 개정된 `onboarding-api.md` 4.2 / When `is_fallback`을 읽는다 / Then 항상 false인 레거시 필드임이 적혀 있고, 9장 미결에서 기본 세트 항목이 빠져 있다
- Given 개정된 `interest-management-uiux.md` 9장 / When 빈 목록 미결을 읽는다 / Then 폴백 선택지가 빠지고 남은 결정이 features 소유로 명시돼 있다

## 남은 결정 항목

- **0건 상태의 확정 카피.** FE는 "아직 준비 중이에요" / "주제를 준비하고 있어요.\n잠시 후 다시 시도해주세요"로 선반영했다(사용자 확인 2026-09-09). uiux 반영 시 이 문자열을 그대로 쓸지 다듬을지 결정한다 — 다듬으면 `onboarding.copy.ts`도 함께 고친다.
- **IM 화면의 빈 목록 처리.** 이번 FE 작업 범위에서 제외했다(사용자 결정 2026-09-09 — 갇히는 화면이 아니라 급하지 않다). `features/interest-management.md`가 규칙을 정한 뒤 별도 티켓으로 처리한다.
