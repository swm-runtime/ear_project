## 수정 내용

라이브러리(L1) 목록을 **세로 행 카드(썸네일 72 + 제목·길이)** 에서 **두 칸 썸네일 격자**로 바꿨다.

- 타일 = 정사각 아트워크(타일 폭 그대로, 라운드 lg) + 아래 제목 2줄 + 길이. 정보량은 종전 행과 같다(출처·저자는 상세에서만 — 2026-09-15 결정 유지).
- 아트워크 위 상태 표식: 완청 체크(좌상단), 진행률 바(아래 변, 흰 반투명 트랙), 더보기 ⋯(우상단 반투명 검정 원, 히트 44pt), 탐험 편 표식("새로운 주제", **사진 아래 변의 검정 그라데이션(투명→75%, 56pt) 위 흰 글자**, 전체 목록에서만). 배지를 제목 위에 두면 그 타일만 글 블록이 밀려 옆 타일과 줄이 어긋나 사진 위로 옮겼다(2026-09-18 PM). 처음엔 흰 알약이었는데 사진 위에서 스티커처럼 떠 보여 알약을 빼고 그라데이션+글자로 바꿨다(2026-09-22 PM). **완청한 탐험 편에는 배지를 그리지 않는다** — 제안 성격은 이미 다했고 사진 위 표식 셋이 붐빈다.
- [이어 PICK] 뷰의 탐험 구획 헤더는 전체 폭 한 행으로 끼어들고, 그 앞뒤로 짝이 끊기면 마지막 타일은 혼자(왼쪽) 남는다. `numColumns`를 쓰지 않고 행을 직접 짝지어 그린다.
- 좌우 여백 md(검색 줄과 같은 선), 타일 사이 12, 행 사이 lg.
- 스켈레톤(L11)도 격자 3행 6장으로 바꿔 로딩이 끝날 때 목록이 튀지 않게 했다.
- 첫 실행 튜토리얼의 라이브러리 모형도 같은 격자로 그린다.
- 탭 = 즉시 재생 판정, ⋯ = 더보기 시트, 삭제·실행 취소·검색·필터·페이지네이션 동작은 그대로. `LibraryItemCard`는 제거했다(다른 사용처 없음).

## 사유

PM 지시(2026-09-18): "라이브러리도 리스트뷰가 아니라 썸네일 뷰로". 콘텐츠가 아트워크 중심이라 한 화면에 더 많은 편이 보이고 훑기 쉽다.

## 문서에 반영할 것

- library.md 4.1 "탐색의 세로 카드와 같은 문법(두 화면의 행이 같아야 한다)" — 라이브러리는 격자, 탐색 검색 결과는 행. 두 화면의 카드가 같아야 한다는 규칙을 "정보량·상태 표식이 같아야 한다"로 좁힌다.
- library-uiux.md L1의 행 구성 설명·L11 스켈레톤 수, wireframe/library.html 을 격자 기준으로 갱신.

## 완료 조건

- Given 항목 5개(전체 목록), When 라이브러리를 열면, Then 두 칸 격자 3행(마지막 행은 왼쪽 한 장)으로 보이고 각 타일은 정사각 아트워크·제목 2줄·길이를 가진다.
- Given 완청 1편·듣던 중 1편, When 목록을 보면, Then 완청 타일 좌상단에 체크, 듣던 중 타일 아트워크 아래 변에 진행률 바가 있고 낭독기는 각각 "완청한 콘텐츠" / "N% 들음"을 읽는다.
- Given [이어 PICK] 뷰, When 탐험 구획이 있으면, Then 구획 제목이 전체 폭 한 행으로 들어가고 그 앞 구획의 마지막 타일이 홀수여도 전체 폭으로 늘지 않는다.
- Given 최초 로딩 0.3초 초과, When 목록을 기다리면, Then 격자 모양 스켈레톤이 보이고 로딩이 끝나도 위치가 튀지 않는다.
