# [문서] 실행 관문이 마지막으로 본 탭으로 복귀한다

| 항목 | 값 |
|---|---|
| 대상 문서 | `features/splash.md` 4장(처리 로직) · `spec/uiux/splash-uiux.md` |
| 요청 파트 | 문서(FE 구현은 `feat(fe)/restore-last-tab`에서 선반영) |
| 발행 날짜 | 2026-09-15 |
| 발견 시점 | 사용자 요청 — 앱을 껐다 켜면 항상 라이브러리로 떨어지는 것이 불편하다 |
| 심각도 | 하 — 편의 개선. 지금 동작이 틀린 것은 아니다 |

## 현재 규칙

`splash.md` 4장 4단계가 도착지를 못박는다.

> `onboarding_completed == true` → **라이브러리(메인)** 로 이동

탐색 탭을 보다 앱을 종료해도 다시 켜면 라이브러리다.

## 수정 내용

4단계의 도착지를 **마지막으로 본 탭**으로 바꾼다. 4단계와 5단계(딥링크) 사이에 판정을 둔다.

```
4.   온보딩 완료 여부 판정
     - false → 온보딩 첫 단계
     - true  → 4-1 로
4-1. 마지막 탭 복원 판정          ← 신설
     - 기록 있고 30분 이내 → 그 탭
     - 없거나 만료         → 라이브러리
5.   딥링크 처리
```

### 복원 범위는 **탭까지만**이다

라이브러리·탐색·프로필 셋 중 하나로만 복귀한다. **콘텐츠 상세·설정 하위·검색 결과는 복원하지 않는다.**

- 스택까지 되살리면 사용자가 열지 않은 화면이 떠 있는 것처럼 읽힌다. 특히 설정 하위 화면은 "내가 이걸 왜 보고 있지"가 된다
- 상세 화면은 **그 사이 사라질 수 있다**(회수·삭제). 되살리려면 존재 판정과 실패 시 대체 경로가 따로 필요해지는데, 얻는 편의보다 예외가 많다
- 탭은 사라지지 않는다 — 판정이 단순하고 틀릴 자리가 없다

콘텐츠 상세를 보다 껐다면 **그 상세가 속한 탭**으로 간다.

### 유효 기간은 30분이다

마지막으로 그 탭을 떠난 시각에서 30분이 지나면 복원하지 않고 라이브러리로 간다.

- 잠깐 다른 앱 갔다 돌아오는 경우를 살리는 것이 목적이다
- 어제 본 탭이 오늘 뜨면 그건 편의가 아니라 **어색함**이다. 사용자는 그 사이 의도가 바뀌었다
- **기기 시각으로 판정한다.** 정책 판정(한도·만료·서비스 날짜)이 아니라 화면 복원이라 서버 판정 대상이 아니다. 시계가 어긋나도 최악은 "라이브러리로 간다"이며 이는 현행 동작과 같다

### 딥링크가 이긴다

5단계 딥링크는 그대로다. 딥링크가 있으면 복원한 탭 **위에** 얹는다 — 순서상 복원이 먼저다.

### 저장 위치

**기기 로컬**이다. 세션(메모리)에 두면 앱 종료와 함께 사라져 목적을 달성하지 못한다.
서버에 보내지 않는다 — 기기마다 마지막으로 본 탭이 다른 것이 자연스럽다.

로그아웃 시 지운다. 다음 사용자가 앞 사용자의 탭에서 시작하면 안 된다.

## 완료 조건

- Given 탐색 탭을 보다 앱을 종료했다 / When 30분 안에 다시 연다 / Then 탐색 탭으로 시작한다
- Given 같은 상황 / When 30분이 지난 뒤 연다 / Then 라이브러리로 시작한다
- Given 콘텐츠 상세를 보다 종료했다 / When 다시 연다 / Then 그 상세가 아니라 **그 상세가 속한 탭**으로 간다
- Given 마지막 탭 기록이 있다 / When 딥링크로 앱이 열린다 / Then 딥링크 목적지가 보인다
- Given 로그아웃한다 / When 다른 계정으로 로그인한다 / Then 앞 사용자의 탭이 아니라 라이브러리로 간다
- Given `splash.md` 4장 / When 도착지 규칙을 읽는다 / Then 탭 복원과 30분 만료가 적혀 있다
