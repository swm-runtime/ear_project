---

## 어긋난 지점

`is_counted_today`는 두 화면이 같은 필드로 쓰는 값인데, 정의가 갈라져 있다.

**`library-api.md` 4.1 — 개정 완료 (2026-08-10):**

> 이 콘텐츠가 **재청취 창 안**에 있는가 — 최근 15일(당일 포함) 내 차감 행(`play_records.is_counted = true`)이 있어, 재생해도 차감이 없는 상태(개정 2026-08-10 — `paywall.md` 4.3-1. **필드명은 유지하고 의미를 "오늘 카운트됨"에서 "창 안"으로 확장했다**)

**`explore-api.md` 4.1 (158행) — 개정 전 문장 그대로:**

> **오늘의 서비스 날짜에 `play_records` 행이 있는가** — 재생 확인 팝업을 탭 즉시 띄우기 위한 힌트(`library-api.md` 4.1과 같은 필드, 같은 이유)

같은 줄이 "`library-api.md` 4.1과 **같은 필드, 같은 이유**"라고 스스로 참조하고 있는데, 참조 대상이 개정되면서 **참조하는 쪽만 옛 정의로 남았다.** `paywall.md` 4.3-1의 재청취 창 확정(2026-08-10)이 `library-api.md`에는 반영되고 `explore-api.md`에는 반영되지 않은 것으로 보인다.

## 무엇이 잘못되나

이 필드의 용도는 하나다 — **재생 확인 팝업을 띄울지 판단하는 힌트.** 원칙은 `paywall.md` 4.2의 **"차감되지 않는데 차감된다고 알리지 않는다"** 이다.

옛 정의(오늘 행 존재)대로 서버가 내려주면 이런 일이 생긴다.

| 상황 | 실제 차감(서버 판정) | 옛 정의의 힌트 | 화면 동작 |
|---|---|---|---|
| 오늘 튼 콘텐츠를 다시 탭 | 없음 | `true` | 팝업 없음 ✅ |
| **3일 전 차감, 창 안인 콘텐츠를 탭** | **없음** | **`false`** | **"1회 차감돼요" 팝업** ❌ |

[재생하기]를 누르면 서버는 창 안이라 차감 없이 허용하므로 **재생·한도는 정상**이다. 틀리는 것은 고지다 — 사용자가 거짓 차감 안내를 보고 재생을 망설이거나, 한도가 실제보다 빨리 닳는다고 오해한다.

## 서버 구현 상태 — 개정된 의미로 이미 동작한다

플레이어 백엔드 구현(`feat(be)/player`)에서 함께 반영했다.

- 라이브러리 목록·복원(`library-api.md` 4.1·4.3)과 탐색 피드·목록(`explore-api.md` 4.1~4.5)이 **같은 조립 함수를 쓰므로 두 화면 모두 창 기준으로 내려간다** — 화면마다 다른 의미가 나갈 수 없는 구조다.
- 목록 힌트와 재생 시점 판정(`paywall.md` 4.1)이 **같은 창 시작일 계산**을 공유한다 — 힌트와 판정이 다르면 팝업 없이 차감되거나 거짓 고지가 나간다.
- 실 DB 확인: 5일 전 차감 콘텐츠 `true` / 20일 전 차감 `false` / 미재생 `false`.

## FE 코드 수정 — **없다**

FE는 이 값을 불리언으로 읽어 팝업 분기에만 쓴다(`탐색 행 탭 → is_counted_today면 팝업 생략`). **값의 의미가 넓어져도 분기 코드는 그대로 맞다** — "true = 차감 없음 = 팝업 생략"이라는 계약이 유지되고, true가 되는 경우가 넓어졌을 뿐이다. mock 데이터에 창 안 시나리오를 더할지는 FE 판단이다.

## 기록할 내용

`explore-api.md` 4.1 응답 필드 표의 `is_counted_today` 설명을 `library-api.md` 4.1 개정본과 같은 문장으로 교체한다.

> | `is_counted_today` | 이 콘텐츠가 **재청취 창 안**에 있는가 — 최근 15일(당일 포함) 내 차감 행(`play_records.is_counted = true`)이 있어, 재생해도 차감이 없는 상태(개정 2026-08-10 — `paywall.md` 4.3-1 · `library-api.md` 4.1과 같은 필드, 같은 정의). 재생 확인 팝업을 **탭 즉시** 띄우기 위한 힌트다 |

- **필드명은 바꾸지 않는다.** `library-api.md` 개정이 이미 "필드명은 유지하고 의미를 확장했다"로 확정했다 — 두 문서가 같은 결정을 따른다.
- 8장(데이터 모델)의 "`is_counted_today`는 `play_records` 집계다" 서술이 있다면 창 기준임을 함께 맞춘다.

## 함께 확인할 것
