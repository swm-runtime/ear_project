# [BE] admin.md — `ai_generated` 업로드 입력에 구조화 소스 목록 추가

| 항목 | 값 |
|---|---|
| 대상 문서 | `docs/features/admin.md` |
| 위치 | 3.1 콘텐츠 업로드(입력 필드 표) · 4.2(업로드 검증) |
| 요청 파트 | 백엔드 |
| 발행 날짜 | 2026-08-24 |
| 관련 작업 | `content_sources` 테이블 확정 (`domain.md` 5.5 — 티켓 `tickets/backend/archive/content-sources-structured-list.md`) |

## 어긋난 지점

`content_sources` 확정(2026-08-24)으로 `ai_generated` 콘텐츠는 참고 소스를 **소스 단위(제목·저자·링크)로 저장**하고, 콘텐츠 상세 화면(FR-40)이 이를 전수 나열한다(`content-detail.md` 4.3). 그런데 `admin.md` 3.1의 업로드 입력은 소스를 **`source_name` 표기 문자열 하나**로만 받는다 — 구조화 소스를 입력받는 필드가 없어, 업로드된 `ai_generated` 콘텐츠의 상세 화면 출처 영역이 빌 수 있다.

## 요청 내용

1. **3.1 입력 필드 표에 소스 목록 항목 추가** — `ai_generated` 전용. 소스마다 `제목(필수) · 저자(선택) · 링크(선택)`, 입력 순서가 곧 표시 순서(`content_sources.position`). `source_name`(고지 문구 표기)은 별도 입력으로 **유지**한다 — 목록이 고지 문구를 대체하지 않는다(`domain.md` 5.5).
2. **4.2 검증에 추가** — `origin == ai_generated`이고 소스 목록이 비어 있으면 거부(상세 화면의 전수 나열이 성립하지 않는다). 소스 항목의 제목 누락도 거부.
3. **기존 발행 콘텐츠의 백필** — 관리자 업로드가 아직 미구현이라 현재 데이터는 개발 시드뿐이며, 시드 재실행이 백필을 수행하도록 반영 완료(운영 데이터 백필 절차는 업로드 기능 구현 시 함께 정의).

## 완료 조건

- Given `admin.md` 3.1을 읽는다 / When `ai_generated`의 입력 필드를 확인한다 / Then 구조화 소스 목록(제목 필수·저자/링크 선택·순서 유지) 항목과 `source_name` 유지가 명시되어 있다
- Given `origin == ai_generated`이고 소스 목록이 빈 업로드를 시도한다 / When 4.2 검증 규칙을 대조한다 / Then 거부 사유로 명시되어 있다

## 처리 기록 (반영 날짜 2026-08-24 — 브랜치 `feat(be)/content-detail`)

- `admin.md` 3.1: 입력 필드 표에 `sources[]` 행 추가(`ai_generated` 필수·최소 1개, 제목 필수·저자/링크 선택, 입력 순서 = 표시 순서) + `source_name` 고지 문구 유지 bullet 추가
- `admin.md` 4.2: 검증 목록에 "소스 목록 비어 있음·항목 제목 없음 → 거부" 추가, [연결] 단계에 `content_sources(ai_generated)` 추가
- `admin.md` 4.2-1·미결 사항: "근거 소스 목록" 미결을 해소 표기로 개정 — 정책 확인 **기록**만 미결로 남김(`domain.md` 15.1 #8과 정합)
- 백필(요청 3): 개발 시드가 재실행 시 백필하도록 반영 완료(코드 측 — 티켓 처리 기록 참조). 운영 백필 절차는 업로드 기능 구현 시 정의
