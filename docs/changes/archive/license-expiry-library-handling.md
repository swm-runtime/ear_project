## 구현된 것 (2026-09-09 코드 선반영)

- 일일 배치: `license_expires_at < now() AND status = 'published'` → `status = 'expired'` 전환(4.4 "만료 자동 처리").
- 재생·서명 URL 발급 게이트(`getPublishedById`)가 `expired`를 회수와 같은 `CONTENT_WITHDRAWN` 계열로 차단.

## 결정이 필요한 것 1 — 만료 콘텐츠의 라이브러리 잔존분 (4.4 미결)

4.4는 "만료는 회수와 달리 `LibraryItem`을 즉시 삭제할지 여부가 계약에 따라 다를 수 있다 → 미결"로 둔다.
**구현은 미결을 그대로 존중해 라이브러리를 건드리지 않았다** — 즉 만료 콘텐츠는 목록에 남되 재생 시
"제공이 종료된 콘텐츠예요"로 막힌다(회수의 "재생 시도" 표현과 동일).

선택지:
- (a) 회수와 동일 — 만료 시 `library_items` 즉시 삭제 (사용자 목록이 깔끔, 계약상 안전)
- (b) 현행(구현) — 목록 유지 + 재생 차단 (사용자가 "왜 사라졌지"를 겪지 않지만 눌러도 안 되는 항목이 남음)

**권장: (a)** — 회수 처리 순서 3번을 재사용하면 되고, 파트너 계약상 "제공 종료 후 노출"이 문제될 소지를 없앤다.
결정되면 배치에 `library_items` 삭제를 추가한다.

## 결정이 필요한 것 2 — domain.md 5.1 문구와 조회 필터의 어긋남

5.1은 "노출 조건은 `status = published` 하나"라고 적었으나, 코드의 `applyVisibility`(탐색·검색·드립 후보)는
**`license_expires_at > now` 조건을 함께** 건다(만료 배치 부재 시절의 방어). 만료 배치가 생긴 지금 두 선택지:
- 5.1을 "status = published 이고 `license_expires_at`이 지나지 않은 것"으로 고쳐 현행 코드를 인정 (배치 사이 시간대의 방어 유지)
- 코드에서 조건을 빼고 배치에만 의존

**권장: 전자** — 배치는 하루 1회라 그 사이 만료분이 몇 시간 노출되는 것을 필터가 막아준다. 문서만 현행화하면 된다.

## 완료 조건

- Given `partner-control.md` 4.4 / When 미결을 읽는다 / Then 라이브러리 잔존분 처리가 (a)/(b) 중 하나로 확정돼 있다
- Given `domain.md` 5.1 / When 노출 조건을 읽는다 / Then 코드의 `applyVisibility`와 같은 조건이 적혀 있다

## 처리 기록 (반영 날짜: 2026-09-10)

두 결정 모두 **권장안대로 확정**했다(사용자 확정).

### 결정 1 — 라이브러리 잔존분: **(a) 회수와 동일, 즉시 삭제**

`partner-control.md` 4.4의 미결을 지우고 확정을 적었다. **코드도 함께 반영했다** — 문서만 고치면 그 자리에서 문서와 코드가 어긋난다.

- `expireLicensed`가 건수 대신 **전환된 `content_id` 목록**을 돌려주도록 바꿨다(`RETURNING id`)
- 만료 배치가 상태 전환과 라이브러리 삭제를 **한 트랜잭션에서** 한다. 나눠 하면 전환만 되고 삭제가 실패한 상태가 남는데, **재실행해도 그 콘텐츠는 이미 `expired`라 조건에 걸리지 않아 영영 정리되지 않는다**
- 삭제는 회수와 같은 **soft delete**다. 행이 남아야 드립 후보 필터(`deleted_at`을 보지 않는다)가 재적립을 계속 막는다 — 라이선스가 갱신돼 다시 발행돼도 이미 받았던 사용자에게 두 번 가지 않는다
- **취향 신호는 건드리지 않는다.** `user_signals` · `play_records` · `content_stats` · `user_preference_vectors` 전부 그대로라, 그 콘텐츠를 들으며 쌓인 추천 입력이 사라지지 않는다
- 되돌리기 규칙도 회수와 같다 — 삭제된 `library_items`는 복구하지 않는다(4.3)

### 결정 2 — `domain.md` 5.1: **전자(문서를 코드에 맞춘다)**

"노출 조건은 `status = published` 단 하나"를 **"`published`이고 `license_expires_at`이 지나지 않은 것"**으로 고쳤다.

상태 하나로 충분하지 않은 이유를 함께 적었다 — **만료 전환이 일일 배치라**, 만료일이 지난 뒤 배치가 돌기까지 몇 시간 동안 상태는 아직 `published`인데 라이선스는 끝나 있다. 조회 필터가 기간을 함께 보면 그 창을 막는다. **둘 중 하나가 빠져도 노출되지 않는 이중 방어**임을 명시했다.
