## 왜 기록하는가

`player.md` 5장은 완료 상태를 **"재생 종료. 화면 자동 이탈하지 않음. '다시 듣기' 버튼으로
전환"**으로 정의한다. 와이어프레임 검토(2026-08-09)에서 **별도 버튼으로의 전환을 없애고
컨트롤 레이아웃을 유지**하기로 결정했다.

- **레이아웃이 상태에 따라 바뀌지 않는다** — 완료는 일시정지와 같은 화면에 위치만 끝(100%)인
  상태다. 버튼 전환은 화면 모드를 하나 늘리는 비용 대비 얻는 것이 없다.
- **▶ = 처음부터 재생은 팟캐스트 플레이어의 표준 관례**라 학습이 필요 없다.
- 컨트롤이 남아 있으므로 [15초 뒤로]로 **끝부분만 되짚는 조작**도 자연스럽게 된다 — 버튼 전환
  방식에서는 불가능했던 동선이다.

유지되는 규칙: 화면 자동 이탈 없음, 재청취의 `user_signals(replay)` 기록, 완청 콘텐츠 재청취의
한도 게이트 경유(차감 여부는 `changes/pending/paywall-completed-replay-limit(fe).md`의 팀 결정
대기 — 이 변경과 독립).

## 기록할 내용 (반영 완료 2026-08-09)

1. **5장 "완료" 행** — "재생 종료. 화면 자동 이탈하지 않음. '다시 듣기' 버튼으로 전환" 을
   **"재생 종료. 화면 자동 이탈하지 않음. 컨트롤 레이아웃 유지(시크바 100%·▶ 표시),
   ▶ 탭 시 처음(위치 0)부터 재생하며 `replay` 신호를 기록한다"** 로 교체한다.
2. **4.2 컨트롤 표의 "재생/일시정지" 행**에 완료 상태 분기를 덧붙인다 —
   "완료 상태에서 ▶는 위치 0부터 재생(재청취 시작)".

## 완료 조건

- Given 이 요청이 통합 과정에서 반영된다 / When `player.md` 5장·4.2를 읽는다 / Then 완료
  상태가 컨트롤 유지 + ▶ = 처음부터 재생으로 기재되어 있고 "다시 듣기 버튼" 서술이 남아 있지 않다
- Given 콘텐츠를 끝까지 들은 사용자 / When ▶를 탭한다 / Then 위치 0부터 재생이 시작되고
  `replay` 신호가 기록된다(한도 게이트 규칙은 paywall 결정에 따름)
