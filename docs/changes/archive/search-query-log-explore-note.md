## 문제

4.5-5는 매칭 방식(`pg_trgm` 부분 일치)의 재검토 조건을 "검색 쿼리 로그로 미스율 확인"으로 두었지만, 그 로그의 존재·위치·내용이 어느 문서에도 없었다. 백엔드가 `search_query_logs` 표(`domain.md` 5.7, 신설 2026-10-01)로 적재를 시작했으므로 기능 문서가 그 사실을 가리켜야 한다.

같은 절의 4.5-4 "최근 검색어는 서버에 보내지 않는다"와 혼동될 수 있다 — 두 개는 다른 것이다(최근 검색어는 사용자에게 되돌려 주는 로컬 이력, 쿼리 로그는 운영 분석 원천).

## 수정 내용

4.5-5의 "지원하지 않는 것" 항목 끝에 한 문장을 덧붙인다.

> **그 로그는 서버가 남긴다**(신설 2026-10-01): 첫 페이지 검색마다 정규화 질의·첫 페이지 건수·다음 페이지 유무·주제 필터 수를 `search_query_logs`(`domain.md` 5.7)에 적재한다. 최근 검색어(4.5-4)와 별개다 — 사용자에게 되돌려 주지 않고 운영 분석에만 쓴다.

클라이언트가 할 일은 없다. 같은 엔드포인트(`explore-api.md` 4.5)를 그대로 부르면 서버가 남긴다.

## 완료 조건

- Given `explore.md` 4.5-5 / When "재검토" 문장을 읽는다 / Then 로그를 서버가 `search_query_logs`에 남긴다는 것과 `domain.md` 5.7 참조가 있다
- Given 같은 절 / When 4.5-4의 최근 검색어와 대조한다 / Then 둘이 다른 것임이 적혀 있다

## 처리 기록

- 2026-10-01 반영. `explore.md` 4.5-5 "지원하지 않는 것" 항목 끝에 위 문장을 덧붙였다. 코드(`search_query_logs`)와 같은 PR(`feat(be)/search-query-logs`)에서 처리.
