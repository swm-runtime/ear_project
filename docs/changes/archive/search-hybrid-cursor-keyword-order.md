## 배경

하이브리드 커서의 RRF 점수는 **행 자기 값이 아니라 매칭 집합 안의 순위**에서 나온다(Σ 1/(k + 순위)). 페이지 사이에 앞쪽에 편이 발행되면 같은 행의 순위가 밀려 RRF가 작아지고, 키셋 `(rrf, 인기, published_at, id) < 커서`에 경계 행이 다시 걸린다(중복). 앞쪽 편이 지워지면 반대로 건너뛴다(누락). 종전 키워드 키셋(가중 합·제목 유사도·인기·`published_at`·id)은 전부 행 자기 값이라 이 흔들림이 없다. 로컬 재현: 1쪽(limit 2) 뒤 맨 앞 편 1건 발행 → 2쪽에 1쪽 끝 편이 다시 나옴, 1쪽 두 편 삭제 → 3번째 편 누락(수정 전 코드).

현행 문서 두 곳은 이 경우를 다르게 말한다.

- `explore.md` 4.5-5: "의미 엔진이 없으면 RRF는 키워드 순위의 단조 함수라 결과·순서가 종전 키워드 검색과 같다" — 한 시점의 정렬로는 맞지만, 페이지를 넘기는 사이 발행·삭제가 끼면 RRF 키셋은 종전 키셋과 다른 행을 낸다.
- `explore-api.md` 4.5 "커서": "미세한 순서 흔들림을 감수한다"는 **질의 벡터 캐시 소실·AI 서버 결손** 경우만 적고, 페이지 사이 발행·삭제에 따른 RRF 키셋 흔들림은 적지 않는다.

KAN-242 수정: 질의 벡터 없이 시작한 검색은 **종전 키워드 쿼리에 그대로 맡기고**, 커서도 종전 키워드 정렬 키를 담는다(커서 `v: 3`). 의미 엔진을 쓴 검색만 RRF 키셋(`v: 2`)이다.

## 수정 내용

### 1. `explore-api.md` 4.5 "커서" 항목 끝에 한 줄

- 추가: "의미 엔진 없이 시작한 검색(첫 페이지 `engines: ["keyword"]`)의 커서는 **종전 키워드 정렬 키셋**을 담는다 — 결과·순서·페이지 경계가 종전 키워드 검색과 같고, 페이지 사이 발행·삭제에도 중복·누락이 없다. 의미 엔진을 쓴 검색의 RRF 키셋은 순위에서 나오므로 **페이지 사이 발행·삭제로 경계가 한 행 안팎 흔들릴 수 있다 — 감수한다**."

### 2. `explore.md` 4.5-5 "합산 = RRF" 항목의 끝 문장 교체

- 종전: "의미 엔진이 없으면 RRF는 키워드 순위의 단조 함수라 결과·순서가 종전 키워드 검색과 같다."
- 개정: "의미 엔진이 없으면 서버는 **종전 키워드 검색 그대로** 줄 세우고 이어 읽는다(결과·순서·커서 키셋이 같다 — KAN-242). RRF 키셋은 순위에서 나와 페이지 사이 발행·삭제로 경계가 미세하게 흔들릴 수 있고, 의미 엔진을 쓴 검색에서는 이를 감수한다."
