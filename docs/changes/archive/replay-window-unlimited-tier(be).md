## 어긋난 지점 — 문서가 다루지 않는 경우

재청취 창의 기산점을 두 문서가 이렇게 정하고 있다.

`paywall.md` 4.3-1:

> **기준은 차감 발생이지 완청이 아니다.** 완청 여부·라이브러리 보유 여부와 무관하게 차감 이력(`play_records`)만 본다.

`domain.md` 6.3 (`is_counted`):

> **차감이 발생한 재생의 행은 `true`**, 재청취 창 안의 재생(차감 없음)으로 다른 날짜에 만들어진 행은 `false`다.

**한도 없는 티어에는 차감이라는 개념 자체가 없다.** 이 문장들만 따르면 그 재생의 `is_counted`는 `false`가 되고, 창의 기산점이 되지 못한다 — 실제로 최초 구현이 이 문장을 근거로 그렇게 판단했다.

## 무엇이 잘못되나 — 강등 시나리오

한도 없는 티어가 도입됐다고 하자. 그 구독자가 콘텐츠를 듣고, 며칠 뒤 구독이 만료돼 무료(하루 2편)로 내려온다.

| 기산점 여부 | 강등 후 15일 안의 재청취 |
|---|---|
| 아니다 (기존 문장대로) | 창 밖 → **한도 판정 → 소진 시 페이월.** 구독 중 들은 콘텐츠를 이어 듣지 못한다 |
| **이다 (결정 2026-08-11)** | 창 안 → **차감·차단 없이 허용.** 무료 사용자가 어제 차감으로 얻는 권리와 같다 |

**무료 사용자는 한도 1회로 15일 권리를 사는데, 구독자는 구독료를 내고도 그 권리가 없는** 역전이 생긴다. 팀 결정은 이것을 막는 쪽이다 — 유료 재생은 구독으로 지불된 재생이므로 같은 권리를 지급한다.

## 서버 구현 상태 — 결정대로 반영 완료 (`feat(be)/player`)

판정 결과를 **두 값으로 분리**해 구현했다. 하나의 불리언로는 아래 조합을 표현할 수 없다.

| 경우 | 차감 발생 (응답 `counted`) | 창 기산점 (행 `is_counted`) |
|---|---|---|
| 한도 티어 · 창 밖 | `true` | `true` |
| 한도 티어 · 창 안 | `false` | `false` — 기산점이면 창이 재청취마다 늘어나 닫히지 않는다 |
| **한도 없는 티어** | **`false`** — 차감 개념이 없다 | **`true`** — 이번 결정 |

- **`library-api.md` 4.4의 `counted` 정의("이 요청으로 차감이 발생했는가")는 그대로 지켜진다** — 한도 없는 티어의 응답은 `false`다. 계약 수정 없음.
- 단위 테스트 + 실 DB 검증: 한도 없는 요금제(limit `null`)로 재생 → 행 `is_counted = true` · 응답 `counted = false`, 무료 강등 + 당일 한도 소진 상태에서 3일 전 콘텐츠 재청취 → 차감 없이 허용.

## 기록할 내용

### 1. `paywall.md` 4.3-1 — 불릿 하나 추가

> - **한도가 없는 티어(`plans.daily_play_limit = null`)가 도입되는 경우, 그 재생도 창의 기산점이 된다**(결정 2026-08-11 — 유료 결제 티어도 15일 재청취 권리를 똑같이 지급한다). 차감은 없지만 구독으로 지불된 재생이다 — 기산점이 아니면 강등 직후 구독 중 들은 콘텐츠가 무료 한도에 막혀, 한도 1회로 같은 권리를 얻는 무료 사용자와 역전된다. 그런 티어의 도입 여부 자체는 미정이다(PRD 4.1).

### 2. `domain.md` 6.3 — `is_counted` 정의 보정

현재 문장을 이렇게 넓힌다(첫 문장만 교체, 나머지 불릿 유지).

> `is_counted`는 **재청취 창의 기산점이 되는 행**인가다 — 차감이 발생한 재생, 그리고 **한도 없는 티어의 재생**(차감은 없지만 구독으로 지불된 재생 — 결정 2026-08-11)이 `true`이고, 재청취 창 안의 재생(차감 없음)으로 만들어진 행만 `false`다.

- **`daily_play_count` 집계식은 바뀌지 않는다**(`is_counted = true`만 센다). 한도 없는 티어는 그 집계를 쓰지 않으므로 지금은 무관하다.
- **알려진 파급 하나** — 같은 서비스 날짜 안에 한도 없는 티어에서 한도 티어로 강등되면, 강등 전의 재생(`true`)이 그날의 카운트에 포함된다. 그날 이미 들은 만큼이 한도에서 차감된 것으로 보이는 동작인데, 재청취 창이 그 콘텐츠들을 다시 열어 주므로 실사용 피해는 없다. 정의를 기록할 때 이 파급도 한 줄 남겨 두면 좋다.

## 왜 지금 기록하는가 — 도입이 미정인데도

**기존 문장이 코드를 되돌릴 근거가 되기 때문이다.** 실제로 최초 구현이 `domain.md` 6.3의 "차감이 발생한 재생의 행은 true"를 근거로 반대로(기산점 아님) 판단했고, 팀 결정으로 뒤집었다. 문서가 그대로면 다음 사람이 같은 문장으로 같은 추론을 해서 코드가 잘못된 것으로 보인다 — 문서와 충돌하는 구현은 반려한다는 팀 규칙상, 결정이 코드에만 있으면 코드가 진다.

## 완료 조건

- Given `paywall.md` 4.3-1을 읽는다 / When 기산점 규칙을 확인한다 / Then 한도 없는 티어의 재생이 기산점이 된다는 것과 그 이유(구독으로 지불·강등 역전 방지), 도입 미정이라는 사실이 적혀 있다
- Given `domain.md` 6.3을 읽는다 / When `is_counted` 정의를 확인한다 / Then "차감 발생"만이 아니라 **기산점 여부**로 정의되어 있고, 한도 없는 티어의 재생이 `true`임이 명시돼 있다
- Given 한도 없는 티어가 도입되고 그 구독자가 콘텐츠를 들은 뒤 15일 안에 무료로 강등된다 / When 당일 한도를 소진한 상태에서 그 콘텐츠를 재청취한다 / Then 차감·차단 없이 재생된다
- Given 위 재생의 응답을 본다 / When `counted`를 확인한다 / Then `false`다(`library-api.md` 4.4의 정의 그대로 — 차감이 발생하지 않았다)
