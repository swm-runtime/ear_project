# 프로필 이메일 진입점 — 카드가 아니라 헤더 이메일 줄

| 항목 | 값 |
|---|---|
| 발행 날짜 | 2026-08-15 |
| 발행 파트 | frontend |
| 대상 문서 | `spec/uiux/profile-uiux.md` 1·4.1·4.3장 · `wireframe/profile.html` |
| 관련 구현 | `frontend/src/features/profile/components/ProfileHeader.tsx` · `features/auth` 이메일 인증 화면 |

## 배경

UI 개편(PR #46, `ee16d9d`)이 프로필의 이메일 카드·플랜 카드를 걷어 헤더로 통합하면서
"등록·인증 진입점은 설정이 갖는다"로 코드가 바뀌었지만, 문서는 갱신되지 않았다:

- `profile.md` 4.3 — 이메일 항목을 탭하면 인증 화면으로 이동한다(프로필 진입점 소유)
- `profile-uiux.md` — 4개 카드 구성([현재 플랜]·[이메일]·[관심 주제 관리]·[커리어 정보])
- `frontend/architecture.md` 4.4 — profile → auth 의존 사유에 "이메일 인증 진입"
- `auth-uiux.md` 8장 금지 — 미인증 이메일을 인증된 것과 같은 모양으로 표시(A5·프로필).
  헤더 통합 시 미인증 배지가 함께 사라져 이 금지에 걸린 상태였다

## 결정 (2026-08-15, 이메일 인증 화면 구현과 함께)

**헤더 통합 디자인은 유지하되, 헤더의 이메일 줄이 프로필 쪽 진입점이 된다.**

- 이메일 카드를 복원하지 않는다 — 같은 값을 한 화면에 두 번 쓰지 않는다는 개편 취지를
  유지한다(플랜 카드도 이미 헤더로 통합된 상태라 카드 복원은 일관성이 없다).
- 헤더 이메일 줄을 탭 가능하게 하고(`hitSlop`으로 44pt), 이메일 인증 화면으로 보낸다.
  `profile.md` 4.3의 진입점 소유·복귀 규칙은 그대로 성립한다.
- 미등록/미인증/인증됨 세 상태 구분을 회복한다 — 미인증이면 "인증되지 않음" 배지를
  줄에 붙인다(색 + 텍스트).

## 반영할 내용

- `profile-uiux.md` 1장 "4개 카드" → "2개 카드(관심 주제·커리어) + 헤더(정체·플랜·이메일)"로
  구성 서술 개정. 4.1 구성 목록의 [현재 플랜]·[이메일] 카드 항목을 헤더 서술로 이동
- `profile-uiux.md` 4.3(이메일 카드) → "헤더 이메일 줄" 기준으로 상태 3종(P3·P4)·배지·
  탭 이동·복귀 갱신 서술 개정
- `wireframe/profile.html` — 헤더 통합 + 이메일 줄 배지·탭 상태 반영
- (참고) 플랜 카드의 헤더 통합은 이 개편이 아니라 PR #46의 것이다 — 함께 개정한다

## 완료 조건

- Given 미인증 이메일 사용자(P3) / When 프로필 헤더를 본다 / Then 주소 옆에 "인증되지 않음"
  배지가 보이고, 낭독기는 "이메일, <주소>, 인증되지 않음, 이메일 인증 열기"로 읽는다
- Given 프로필 헤더의 이메일 줄 / When 탭한다 / Then 이메일 인증 화면(A10)이 열리고
  "현재 이메일"에 같은 주소가 표시된다
- Given 인증 성공 후 복귀 / When 프로필을 본다 / Then 주소·배지가 새 값으로 갱신되어 있다
  (주소가 같고 인증 상태만 바뀐 경우에도 배지가 사라진다)
- Given profile-uiux.md / When 구성 서술을 읽는다 / Then 카드 목록과 실제 화면(헤더 통합)이
  일치한다
