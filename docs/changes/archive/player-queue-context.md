## 배경

재생 목록 패널(PL12, 2026-09-17)은 **어디서 열었든 "필터 없는 라이브러리 첫 페이지"**다(`player.md` 4.2-1). 탐색·검색에서 **라이브러리에 없는 편**을 틀면 지금 듣는 편이 목록에 없고 "재생 중" 줄도 없다 — 유저에게는 "이게 왜 내 재생목록이지"가 된다. 패널을 만들 때는 라이브러리가 유일한 재생 입구에 가까웠지만, 지금은 탐색 피드·주제 필터·인기·검색·시리즈 화면이 모두 재생을 시작한다.

PM 결정(2026-10-22):

1. **재생 목록 = 들어온 맥락.** 라이브러리에서 틀면 종전 그대로(사용자 지정 순서·끌기·서버 저장). 탐색 목록(피드 섹션·주제 필터·인기·검색 결과·시리즈 화면 편 목록)에서 틀면 **그 목록의 스냅샷**이 재생 목록이다 — 유튜브 뮤직·애플 뮤직이 하는 방식. 클라이언트가 들고 들어가며 서버 변경은 없다.
2. **탐색 맥락에는 추천 블록.** 목록 아래 두 번째 섹션 **"다음에 들어볼 만한"** 3~5편 — 1차는 지금 듣는 편과 **대본이 비슷한 편**(`content_embeddings` 코사인, 새 API), 비거나 못 받으면 탐색 `interest` 섹션 재사용. 라이브러리 맥락에는 두지 않는다(내가 정리한 목록에 끼어드는 것은 싫어한다).

**바뀌지 않는 것** — 연속 재생(완청 후 자동 다음)은 그대로 비범위다(FR-24, `player.md` 8장). 패널은 여전히 **열람·선택 전용**이고 추천 블록도 목록일 뿐이다. 줄 탭은 재생 시작이라 단일 게이트(`paywall.md` 4.2)를 그대로 지난다. 시리즈 "다음 화 듣기" 버튼도 두지 않는다(KAN-225 보류 그대로) — 시리즈 화면 편 목록을 **맥락 스냅샷으로 쓰는 것**은 "들어온 목록을 보여 준다"일 뿐 다음 화 유도가 아니다. 이 구분이 애매하면 PM이 다시 본다(확인 항목).

## 수정 내용

### 1. `player.md` 4.2-1 재생 목록 패널 — 목록의 정체 개정

- 종전: "목록은 **필터를 걸지 않은 라이브러리 첫 페이지**(`sort=queue`)다."
- 개정: **목록은 재생을 시작한 맥락이다.**
  - **라이브러리 맥락**(라이브러리 화면·이어듣기·푸시·공유·콜드 스타트 미니플레이어 복원·맥락을 모르는 모든 진입): 종전 그대로 — 필터 없는 라이브러리 첫 페이지 `sort=queue`, 열 때마다 새로 받는다, 끌어 순서 변경(4.7-1).
  - **탐색 맥락**(탐색 피드 섹션·주제 필터 목록·인기 목록·검색 결과·시리즈 화면 편 목록에서 시작): **그 목록의 콘텐츠 행 스냅샷** — 재생을 시작한 순간 화면이 불러 둔 페이지까지, 서버 순서 그대로, 시리즈 카드는 뺀다(편이 아니다). 지금 재생 중인 편이 스냅샷에 없으면(상세 화면을 거쳐 왔거나 카드가 접혀 있던 편) 맨 위에 둔다. **추가 로딩·재조회·순서 변경이 없다** — 패널은 열람·선택 전용이고, 스냅샷은 플레이어가 살아 있는 동안만 산다(앱 재실행 복원은 라이브러리 맥락).
  - 패널 안에서 다른 줄을 틀어도 **맥락은 유지**된다(그 목록 안에서 옮겨 다닌 것이다). 다른 화면에서 새로 재생을 시작하면 그 화면의 맥락으로 바뀐다.
  - 전환은 종전처럼 단일 게이트를 지나며, **진입점 값은 맥락을 따른다** — 라이브러리 맥락 `library`, 탐색 맥락 `explore`(`paywall.md` 4.2 진입점 표에 "재생 목록 패널 = 맥락의 진입점"을 적는다).
  - 탐색 맥락의 줄은 라이브러리에 없을 수 있다 — 줄에 **담기**(E 계열과 같은 담기 규칙 `explore.md` 4.3)를 둔다. 라이브러리 맥락은 전부 담긴 편이라 담기가 없다(종전).
- "**재생 목록 패널 ≠ 연속 재생**" 문단은 그대로 둔다. 맥락이 바뀌어도 완청 후 자동 다음 재생은 없다.

### 2. `player.md` 4.2-2 신설 — "다음에 들어볼 만한" 추천 블록 (탐색 맥락 전용)

- 탐색 맥락의 패널에서 **목록 아래 두 번째 섹션**. 3~5편. 라이브러리 맥락에는 없다.
- 소스 두 단계: ① `GET /contents/:content_id/related`(`player-api.md` 4.8 — 지금 듣는 편과 대본 임베딩이 비슷한 편) → ② 비거나 실패하면 **탐색 `interest` 섹션**(앱이 이미 받아 둔 피드 캐시 재사용, 없으면 피드 조회). 두 소스 모두에서 **지금 듣는 편·스냅샷에 이미 있는 편은 뺀다.** 결과가 0이면 섹션을 그리지 않는다(빈 섹션 없음).
- 줄 탭 = 재생 시작(단일 게이트, 진입점 `player`). 틀면 그 편이 **현재 맥락 스냅샷에 더해진다**(맥락은 바뀌지 않는다). 줄에 담기.
- **자동 재생·다음 편 예약은 없다**(FR-24). 추천 블록은 목록이다.
- 추천 소스는 재생 중 콘텐츠가 바뀔 때 다시 받는다. 패널을 닫았다 열어도 같은 편이면 다시 받지 않는다.
- 같은 시리즈의 다음 화를 여기 올리는 것은 **하지 않는다**(KAN-225 보류 — 시리즈 단위 유도는 별도 결정). related 결과에 같은 시리즈 편이 코사인으로 올라오는 것까지 막지는 않는다.

### 3. `player-uiux.md` 4.6-1 PL12 — 헤더·줄·추천 섹션

- **헤더**: 라이브러리 맥락은 종전 "재생 목록". 탐색 맥락은 출처 한 줄 — **"탐색 · 인기 주간"** / **"탐색 · 새로 나온 콘텐츠"**(섹션 제목 그대로) / **"주제 · 커리어"** / **"검색 ‘커리어’"** / **"시리즈 · <시리즈 제목>"**. 손잡이(닫힘 상태) 글자도 같은 값. 보조 글자색·한 줄 말줄임.
- **줄**: 종전과 같다(썸네일 48·제목·`카테고리 · N분`, 재생 중 굵게 + 낭독 "재생 중", 완청 "완청함"). 탐색 맥락은 **순서 손잡이가 없고** 그 자리에 **담기 버튼**(라이브러리에 없는 줄만 — 담긴 줄은 자리만 비운다, E 타일의 담기와 같은 아이콘·낭독 "라이브러리에 담기"). 담기는 낙관 반영 + 토스트 규칙이 탐색과 같다.
- **추천 섹션**(탐색 맥락만): 목록 끝 아래 섹션 제목 **"다음에 들어볼 만한"**(sm·굵게·보조색, 위 여백 lg) + 같은 줄 모양 3~5개 + 담기. 로딩은 줄 스켈레톤 2개(0.3초 미만 미표시), 실패·0건은 섹션 자체를 그리지 않는다(패널 안 오류 표시 없음 — 목록은 멀쩡하다).
- 접근성: 헤더는 header 역할. 섹션 제목도 header. 담기 버튼은 44pt.
- 영어: 헤더 "Explore · Popular this week" / "Topic · Career" / "Search “career”" / "Series · <title>", 섹션 "Up next for you", 담기 "Save to library".

### 3-1. `player.md` 4.2-3 신설 · `player-uiux.md` 4.6-1 — 줄 스와이프(PM 추가 2026-10-22 04:05 "3번")

- **줄을 왼쪽으로 밀면 삭제, 오른쪽으로 밀면 담기.** 애플 뮤직·메일의 줄 스와이프 문법(드러나는 색 면 + 아이콘, 놓으면 실행, 임계 미달이면 복귀).
  - **왼쪽 = 삭제**: 라이브러리 맥락은 **[라이브러리에서 삭제]**(PL7 더보기와 같은 소프트 삭제 + 스낵바 "삭제했어요" [실행 취소] 5초 — 재생은 유지). 탐색 맥락은 **스냅샷에서 빼기**(로컬만 — 서버에 아무것도 보내지 않는다, 실행 취소 없음). 지금 듣는 편은 밀리지 않는다.
  - **오른쪽 = 담기**: 라이브러리에 없는 줄(탐색 맥락·추천 블록)만. 이미 담긴 줄은 오른쪽으로 밀리지 않는다(면이 드러나지 않음). 담기 버튼(3절)은 **그대로 둔다** — 스와이프는 숨은 조작이라 발견성·접근성은 버튼이 맡고, 스와이프는 지름길이다.
- **충돌 정리**: 종전 "목록 위 오른쪽 스와이프는 패널 닫힘"(4.6-1 자리·전환)을 **걷는다** — 줄 오른쬭 스와이프가 담기가 되면서 같은 제스처가 둘이 된다. 닫기는 손잡이 탭·시트 아래로 끌기만 남는다(스크립트 패널과 같다).
- 끌기 손잡이(라이브러리 맥락 순서 변경)와의 공존: 손잡이 영역에서 시작한 터치는 순서 변경, 본문에서 시작한 **가로** 이동은 스와이프, 세로는 목록 스크롤. 축 판정 비율은 종전 스와이프 값(가로가 세로의 1.5배)을 그대로 쓴다.
- 접근성: 낭독기에는 스와이프 대신 줄의 액션(`accessibilityActions` "라이브러리에서 삭제"/"목록에서 빼기"/"라이브러리에 담기")으로 같은 일을 한다.
- 영어: "Delete from library" / "Remove from list" / "Save to library".

### 3-2. `player.md` 4.2-1 · `player-uiux.md` 4.6-1 — 시트 2단(PM 추가 2026-10-22 04:05 "4번 — 한 번 더 올리면 재생목록 더 보기")

- 지금은 손잡이를 한 번 끌어올리면 **1단**(아트워크가 배너로 압축 + 목록)에서 멈춘다. **1단에서 한 번 더 끌어올리면 2단** — 목록이 **화면을 다 쓴다**: 배너·제목·시크바·컨트롤이 접히고 맨 위에 **한 줄 재생 바**(썸네일 32 · 제목 1줄 · 재생/정지)만 남는다. 손잡이 글자는 1단에서 "재생목록 더 보기"(탐색 맥락이면 출처 글자 뒤에 ` · 더 보기`), 2단에서 출처/“재생 목록”.
- 내리기는 단계별로 돌아온다(2단 → 1단 → 닫힘). 2단에서 탭은 1단으로. 임계는 1단과 같은 규칙(이동 비율 35% 또는 속도 0.5dp/ms)을 각 단 사이에 쓴다.
- 1단·2단 모두 같은 목록·같은 추천 블록이다 — 2단은 더 많은 줄이 보일 뿐 데이터가 늘지 않는다(스냅샷·첫 페이지 그대로. "더 보기"는 화면을 더 보는 것이다).
- 진행값은 하나(`queueProgress` 0 → 1 → 2)로 둔다 — 아트워크 압축(0→1)과 배너 접힘(1→2)이 같은 값의 구간이다. 모션은 UI 스레드(Reanimated).
- 영어 손잡이: "Up next · more" / 2단 "Up next".

### 4. `player-api.md` 3장 목록 · 4.8 신설 `GET /contents/:content_id/related`

- 요청: 경로 `content_id`, 쿼리 `limit`(기본 5, 최대 10), `exclude_ids`(uuid 콤마 구분, 최대 50 — 스냅샷에 이미 있는 편을 뺀다).
- 응답 200: `{ "items": [ { "content": {...}, "library": {...} | null, "is_counted_today": false } ] }` — **탐색 `explore-api.md` 4.1 콘텐츠 행과 같은 모양**(담기·재생 처리를 재사용한다). 시리즈 카드로 접지 않는다(편 단위). `type` 키는 `"content"`로 고정이거나 생략.
- 후보: 사용자 시장·발행 상태·회수 아님·자기 자신 제외·`exclude_ids` 제외·임베딩 현행 `model`·`content_version` 일치. **코사인 내림차순**, 임계값 이하 제외(값은 서버 소유 — 시작 0.3, 반응 보고 조정). 기준 편에 임베딩이 없으면 `items: []`.
- 에러: 없는·다른 시장·회수 콘텐츠 404 `NOT_FOUND`. `limit`·`exclude_ids` 범위 밖 400 `VALIDATION_FAILED`.
- 응답 캐시 없음(라이브러리 상태가 사용자별). 전수 코사인(ANN 없음 — `domain.md` 5.6).
