## 왜 기록하는가

현행 규칙에서 **완청(`completed`)한 콘텐츠를 다른 서비스 날짜에 재청취하면 새로 차감된다.**

- `paywall.md` 4.3의 카운트 단위는 "오늘 재생한 고유 콘텐츠 수"다 — 같은 날 재청취만
  무료이고(`play_records` 유니크 제약), **날짜가 바뀌면 완청 여부와 무관하게 새 행이 생겨
  1회가 차감된다.** 한도가 소진된 상태면 `BLOCKED`라 재청취 자체가 불가능하다.
- 통합 테스트에서 실제로 확인했다: 완청 기록이 있는 콘텐츠도 재생 가능 횟수의 영향을
  그대로 받아, 횟수가 남지 않으면 재청취할 수 없다.
- 이 동작이 의도인지가 문서에 없다. `library.md` 4.4는 "완료된 아이템은 목록에서 자동
  제거하지 않는다(재청취 지표 수집 — PRD 10)"고 정해 **재청취를 기대 행동으로 전제**하는데,
  한도 규칙이 그 행동을 막을 수 있다 — 두 문서 사이의 긴장이 있는 지점이다.

## 기록할 내용 (paywall.md 미결 사항에 추가)

**완청 기록이 있는 콘텐츠의 재청취를 재생 한도 판정·차감에서 제외할지 결정한다.**

- **A안 — 현행 유지(한도 적용)**: 재청취도 새 차감. 규칙이 단순하고("오늘 들은 고유 콘텐츠
  수" 하나), 한도의 우회로가 없다.
- **B안 — 완청 콘텐츠는 한도 미적용**: 재청취는 차감도 차단도 없다. 재청취 지표 수집
  (`library.md` 4.4)과 정합하고, "이미 소비를 지불한 콘텐츠"라는 사용자 감각과 맞는다.

## 함께 결정할 것

1. **B안의 어뷰징 경로** — 무료 티어가 완청분만 돌려 들으면 사실상 무제한 소비가 된다.
   무료 2편 제한(PRD 티어 정책)의 취지와 충돌하는지 판단 필요.
2. **B안의 "완청" 판정 기준** — `library_items.status = 'completed'`로 보면 라이브러리에서
   삭제한 콘텐츠·담지 않고 들은 콘텐츠의 완청 이력은 제외된다. `playback_progresses` 기준으로
   보면 판정 조회가 하나 늘어난다. 판정은 어느 쪽이든 **서버 소유**이며 클라이언트는 표시만
   한다(변경 없음 — `paywall.md` 4.1).
3. **표시값·팝업 힌트의 확장** — B안이면 완청 콘텐츠 탭 시 확인 팝업을 띄우지 않아야 하므로,
   목록 응답의 힌트(`is_counted_today` 또는 신규 필드)로 "차감 없는 재생"을 구분해 내려줘야
   한다(`library-api.md` 4.1·4.4 계약 변경 — 백엔드 협의 필요).
4. **지표 영향** — B안이면 재청취가 한도에 걸리지 않아 늘어난다. 재청취 지표(PRD 10)·추천
   신호(`user_signals`)의 해석에 영향이 있는지 확인.

- Given 팀이 A/B안 중 하나로 결정한다 / When `paywall.md` 4.1·4.3을 읽는다 / Then 결정된

  FE·BE 구현 티켓(`tickets/<파트>/pending`)이 함께 생성되어 있다
