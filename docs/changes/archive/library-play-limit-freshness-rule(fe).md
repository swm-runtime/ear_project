> **2026-08-07 반영 결과 — 대상 문서를 바꿔 반영했다.**
>
> 이 문서는 대상을 `features/library.md` 4.1-2 또는 7장으로 제안하고, 탐색은 `library.md`를 통해 상속받는 경로를 상정했다. **`paywall.md` 5장에 넣었다.**
>
> - `paywall.md` 5장이 **"규칙은 이 문서가, 자리는 각 화면이 정한다"** 로 소유를 못박고 있고, `explore.md` 4.4-1도 "규칙은 `paywall.md` 5장이 소유하고 이 문서는 자리만 정한다"로 시작한다. **신선도는 자리가 아니라 규칙이다.**
> - `library.md`에 두고 탐색이 상속하게 하면 소유자가 아닌 문서가 규칙을 정하는 모양이 된다. 소유자에 두면 **탐색은 손대지 않아도 자동으로 적용된다** — 실제로 `explore.md`는 한 글자도 고치지 않았다.
>
> 반영한 곳
>
> - `features/paywall.md` 5장 "잔여 횟수 상시 표시" — **"신선도" 소절 신설.** 판정 3단계 표 + 단조 증가 근거(`play_records`는 추가만 되고 라이브러리 삭제에도 이력이 남는다) + 기기 시각 미사용 + 재조회 중 로딩 미표시 규칙과의 관계
> - `features/library.md` 4.1-2 — 갱신 시점 항목에 신선도 규칙 참조 한 줄
> - `spec/uiux/library-uiux.md` 4.3 — 표시 규칙에 참조 + 역행 시 무엇을 잃는지
>
> **제안에 없던 것 하나를 덧붙였다** — **"한도가 있는 티어에만 적용한다."** 무제한 티어는 `daily_play_limit` · `daily_play_count`가 모두 `null`이라 3번의 크기 비교가 성립하지 않는다. 표시 자체를 하지 않는 상태라 실무상 문제는 없지만, 규칙을 읽고 구현하는 사람이 `null` 비교를 어떻게 할지 고민하지 않게 명시했다.
>
> **계약·코드 변경 없음.** 서버는 이미 세 필드를 항상 내려주고 있고(`library-api.md` 4.1), 이 규칙은 전적으로 클라이언트 표시 규칙이다.

## 왜 필요한가

현행 4.1-2는 "목록을 조회할 때마다 서버 값으로 덮어쓴다"까지만 정한다. 그런데 클라이언트에는
**여러 시점의 서버 응답이 섞여 도착한다** — 탭(필터 조합)별 쿼리 캐시가 재조회 완료 전에 먼저
렌더되고, 먼저 보낸 요청이 늦게 도착하기도 한다. 어느 값을 신뢰할지 규칙이 없으면 구현이
"마지막에 렌더/도착한 값"을 그대로 덮어쓰게 되고, 실제로 FE 구현에서 **재생 직후 탭을 옮기면
차감 전 문구가 1~2초 역행 표시되는 버그**가 발생했다(2026-08-07 수정 완료).

## 추가할 규칙 (구현 반영 완료)

**같은 서비스 날짜의 응답끼리는 `daily_play_count`가 큰 쪽을 신뢰한다.** 근거는 스키마 성질이다:

- 같은 서비스 날짜 안에서 `daily_play_count`는 **단조 증가**다 — `play_records`는 추가만 되고,
  라이브러리 삭제에도 재생 이력은 남는다(`library.md` 4.5, `domain.md` 6.3). 여러 기기 재생도
  늘리기만 한다. 줄어드는 유일한 경우는 04:00 경계인데 그때는 `service_date` 자체가 바뀐다.

판정 순서:

1. `service_date`가 보관값과 다르면 → 무조건 새 값으로 덮어쓴다 (04:00 경계·날짜 전환)
2. `daily_play_limit`이 다르면 → 새 값으로 덮어쓴다 (티어 변경 — 결제·만료)
3. 같은 날짜·같은 한도면 → `daily_play_count`가 보관값 **이상일 때만** 덮어쓴다
   (작으면 차감 전의 낡은 응답이므로 버린다)

- **기기 시각·도착 시각을 판정에 쓰지 않는다** — 시각 기반 비교는 시계 조작·응답 순서 역전에
  깨진다. 이 규칙은 "기기 시각을 정책 판정에 쓰지 않는다"는 공통 원칙과도 정합한다.
- 재조회 중 로딩·숨김 처리를 하지 않는 기존 규칙(uiux 4.3 "스켈레톤조차 그리지 않는다")은
  그대로다 — 이 규칙 덕에 재조회 중 유지되는 값이 곧 "알고 있는 최신 값"이 된다.

## 완료 조건

- Given 이 변경이 통합 과정에서 반영된다 / When `features/library.md` 4.1-2(또는 7장)를 읽는다 /
  Then 위 신선도 판정 규칙(단조 증가 근거 포함)이 서술되어 있다
- Given 무료 사용자가 전체 탭에서 1회를 재생해 "0/2 남음"이 표시됐다 / When 다른 탭으로
  전환한다 / Then 재조회가 끝나기 전에도 문구가 "1/2 남음"으로 역행하지 않는다
