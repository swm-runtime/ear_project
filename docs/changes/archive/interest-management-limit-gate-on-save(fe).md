## 결정 내용 (2026-08-11)

**상한(3개)은 탭이 아니라 저장을 막는다 — 0개 상태(개정 2026-08-09)와 같은 패턴.**

- 3개를 채워도 미선택 칩을 비활성 처리하지 않고, 4번째 탭도 그대로 선택된다(토스트 없음)
- 선택이 3개를 넘으면 **[저장] 비활성 + 하단 사유 문구 "관심 주제는 3개까지 선택할 수 있어요" 상시 노출**(0개 사유 문구와 같은 위치·패턴)
- 개수 표기는 "4/3 선택"처럼 사실대로 표시(기존 IM6 무클램프 규칙 확장)
- 클라이언트 저장 게이트의 판정식은 서버와 동일한 **max(3, 저장 전 보유 개수)** — 초과
  보유자(기존 5개)의 해제·재저장(5→4)을 막지 않는다(features 7장 규칙 유지)
- IM6 초과 보유자 안내 배너는 **기존 보유가 3개를 넘는 경우에만** 노출(일반 사용자의 일시적
  4개 선택에는 저장 게이트 문구만 노출 — 안내 중복 방지)

## 개정할 조항

- features 4.1: "3개를 채우면 미선택 칩 비활성 + 4번째 탭 토스트" → 삭제, 저장 게이트로 대체
- features 4.2: 저장 분기에 "3개 초과 상태 → [저장] 비활성 + 사유 문구" 추가(0개 행과 대칭)
- features 5장: "3개 선택 완료"·"4번째 선택 시도" 행 → "3개 초과" 행으로 교체
- features 8장 완료 조건: "4번째 주제를 탭한다 / Then 선택되지 않고 토스트" → "4번째 주제를
  탭한다 / Then 선택되고, [저장]이 비활성이며 상한 사유 문구가 노출된다"
- uiux IM2: 화면 정의 교체(비활성 칩·탭 토스트 → 초과 상태의 저장 게이트 표현)
- uiux 7장: 미선택 칩 aria-disabled + 이유 낭독 항목 삭제(비활성 상태 자체가 없어짐),
  사유 문구 라이브 리전 추가
- uiux 8장 금지 사항: "4번째 탭 무반응 금지"는 전제(비활성 칩)가 사라지므로 삭제, "상한 초과
  상태의 [저장]을 활성으로 두는 것"을 추가
- **온보딩과의 관계**: 온보딩 1단계는 현행(탭 차단) 유지 — uiux 1장의 "온보딩 1단계와 같은
  규칙" 서술에 상한 처리 예외를 명시해야 한다. 온보딩도 같은 방식으로 바꿀지는 별도 결정

## 완료 조건

- Given 관심 주제 3개를 선택한 사용자 / When 4번째 주제를 탭한다 / Then 선택되어 "4/3 선택"이
  되고, [저장]이 비활성이며 "관심 주제는 3개까지 선택할 수 있어요"가 상시 노출된다
- Given 4개 선택 상태 / When 1개를 해제해 3개가 된다 / Then 사유 문구가 사라지고 (변경이
  있으면) [저장]이 활성된다
- Given 기존 5개 보유 사용자 / When 1개만 해제하고 저장한다(4개) / Then 게이트에 걸리지 않고
  정상 저장된다
