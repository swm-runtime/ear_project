## 문제

9.11의 마지막 항목이 이렇게 적혀 있다.

> **9장 표 중 42개는 `error-code.enum.ts`와 1:1로 일치한다.** … **신설 4종(2026-08-10 — 9.8·9.9)은 enum 반영 대기다** — 백엔드 구현 시 `architecture.md` 7.5의 순서(enum → 9장 표 → 해당 api 문서 5장)에서 enum만 남았다.

**두 부분 다 사실이 아니다.**

- **"반영 대기"** — 넷 다 등재돼 있다. `INTEREST_REQUIRED` · `INTEREST_LIMIT_EXCEEDED` · `INTEREST_TOPIC_UNAVAILABLE` · `CAREER_JOB_CATEGORY_UNAVAILABLE` 전부 `error-code.enum.ts`에 있다.
- **"42개"** — 지금 enum은 **51개**이고, 9장 표의 코드 집합과 **양방향 차집합이 공집합**이다(2026-09-08 기계 대조). 42에서 벌어진 차이는 신설 4종과 9.10 관리자 5종(2026-08-30 등재)이다.

## 수정 내용

해당 불릿을 다음으로 교체한다.

> - **9장 표의 코드는 `error-code.enum.ts`와 1:1로 일치한다**(대조 2026-09-08). 어느 한쪽에만 있는 코드는 없다.

**개수를 다시 적지 않기를 제안한다.** 이 문장이 낡은 이유가 정확히 그것이다 — 코드가 늘 때마다 숫자를 같이 고쳐야 하는데 아무도 그러지 않는다. 굳이 남긴다면 **대조 날짜를 반드시 함께** 적는다.

## 처리 기록 (반영 날짜: 2026-09-08)

9.11 마지막 불릿을 교체했다. **개수를 다시 적지 않았다** — 이 문장이 낡은 이유가 정확히 그것이라, 숫자를 새로 박으면 다음 코드 추가에서 같은 일이 반복된다. 대신 "새로 세었다면 대조 날짜를 함께 적는다"를 규칙으로 남겼다.
