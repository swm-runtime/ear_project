## 배경

글로벌 빌드 출시(10-24 제출)를 앞두고, 해외 유입과 청취를 어드민을 열지 않고 매일 보려 한다. 일일 보고의 GA4 이벤트에는 시장이 없다(사용자 속성 미등록). 그래서 **서버 값만 시장으로 나눈다.**

## 수정 내용

- **3-3 "가입자" 행** — 현재 가입자 수와 어제 가입 수를 `users.market`별로 괄호에 나눈다. 계정이 없는 시장도 0으로 적는다("0명"과 "집계 누락"을 가르기 위해서).
  - 예: `가입자   현재 836명 (KR 836 · GLOBAL 0)  ·  어제 가입 3명 (KR 3 · GLOBAL 0)`
- **3-3에 "시장별 청취" 행 신설** — 가입자 줄 바로 다음 줄. 서버 값이다.
  - 보고일(KST 달력일, 재생 시작 시각 기준)의 시장별 **청취자 수 · 재생 수 · 청취 시간**을 적는다.
  - 청취자·재생은 지금 계정 기준이다(보고 전 탈퇴한 사람은 빠진다). 청취 시간은 재생 시작일 기준(경계를 넘겨 들어도 시작일에 쌓인다).
  - 시간은 1시간 미만이면 분(`42분`), 그 이상이면 소수 한 자리 시간(`12.5시간`)이다.
  - 예: `시장별 청취  KR 11명 · 재생 34 · 4.5시간  ·  GLOBAL 0명 · 재생 0 · 0분`
- **3-3 "출처" 행** — "서버 값은 가입자 줄 하나뿐이다"를 "서버 값은 가입자·시장별 청취 두 줄이다"로 고친다. 각주도 그렇게 바뀌었다.
- **3-3 "사용자" 행에서 신규를 뺀다**(2026-10-17 사용자 결정). GA4 `newUsers`는 앱 첫 실행 수라 가입 수와 다르다. 가입은 가입자 줄(서버)이 정확히 세므로, 두 숫자가 함께 있으면 어느 쪽이 가입인지 헷갈린다. 사용자 행은 "활성·세션·평균 세션 길이·7일 활성 — GA4 `activeUsers` `sessions` `averageSessionDuration`. 활성의 ▲▼는 전일 대비"가 된다. GA4 조회는 그대로 두고 문구에서만 뺀다.
- **3-3·3-4 "경계" 행 — 서버 값의 하루를 KST 달력일(00시)로 바꾼다**(2026-10-17 사용자 결정). 종전에는 서버 값(어제 가입·탈퇴)이 서비스 날짜(05시 경계)라 같은 보고의 GA4 줄(00시)과 5시간 어긋났다. 이제 "어제"는 전 줄이 KST 00~24시다. "현재 가입자"만 보고 시각 값이다. 시장별 청취는 재생을 시작한 시각(`play_records.played_at`)으로 자른다. 각주는 "어제 = KST 00~24시(전 줄 같은 범위) · 현재 가입자는 보고 시각 값"으로 바뀌었다. **일일 보고 쿼리만 바뀐다** — 서비스 날짜(재생 한도·편성 배치)는 그대로다.
- **`domain.md` 3.4 `withdrawal_logs`에 `market` 컬럼을 추가한다**(2026-10-17 사용자 결정 — 탈퇴를 시장별로 보고, 해외 전용 탈퇴 사유를 둘 수 있게).
  - `market varchar(10) NOT NULL DEFAULT 'kr'` — 탈퇴 당시 `users.market`. 마이그레이션 `1790600000000-AddWithdrawalLogMarket`.
  - 기존 행은 `kr`로 채운다. 운영은 GLOBAL 가입이 열린 적이 없어 지금까지의 탈퇴가 전부 KR이다(개발계의 GLOBAL 시험 탈퇴는 KR로 잘못 들어갈 수 있다 — 감수).
  - 값이 둘뿐이라 사람을 가리키지 않는다. "`user_id` FK를 두지 않는다"는 원칙은 그대로다. 3.4의 설명에 "시장은 집계용, 비식별"을 한 줄 덧붙인다.
- **3-4 이탈 보고를 시장별로 나눈다.** 탈퇴 합계 뒤 괄호에 시장별 수(`5명 (KR 4 · GLOBAL 1)`), 그 아래 탈퇴가 있던 시장만 소제목(`*KR*  4명`)과 사유 목록을 적는다. 사유 코드를 모르면 원값을 그대로 적으므로, 해외 전용 사유를 새로 만들어도 문구표 갱신 전까지 코드값으로 보인다.

## 범위 밖

- GA4 줄(사용자·획득·재생·리텐션)의 시장 분리. 하려면 FE가 GA4 사용자 속성 `market`을 올려야 한다(별도 FE 티켓 후보).
