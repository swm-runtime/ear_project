# 재발행 시 재생 위치 폐기 — 폐기 주체를 클라이언트에서 서버로

| 항목 | 값 |
|---|---|
| 대상 문서 | `docs/features/player.md` 7 · `docs/spec/api/player-api.md` 4.1 · `docs/spec/api/admin-api.md` 4.10 |
| 발행 날짜 | 2026-09-07 |
| 발견 시점 | `tickets/backend/pending/republish-stale-playback-position.md` 구현(안 A, PR #165) — 문서의 "클라이언트가 폐기" 규칙이 구현과 어긋나게 됐다 |
| 요청 파트 | 백엔드 |

## 수정 내용

### 1. `player.md` 7 — 폐기 주체 서술을 바꾼다

현재:

> 클라이언트는 버전이 달라지면 **저장된 재생 위치와 오프라인 파일을 폐기한다.**

바꿀 것:

> **재생 위치는 서버가 폐기한다** — 재발행 시 그 콘텐츠의 `playback_progresses`를 재발행
> 트랜잭션에서 전부 삭제한다(2026-09-07 확정, `republish-stale-playback-position.md` 안 A).
> 클라이언트는 위치를 로컬에 보관하지 않으므로 4.1 응답의 `progress`를 그대로 쓰면 된다 —
> 재발행 후에는 `null`이 내려와 0부터 재생된다.
> 오프라인 파일 폐기는 P1 오프라인 저장 구현 시 클라이언트 몫으로 남는다(로컬 보관값이
> 그때 처음 생긴다 — `offline-download.md`).

### 2. `player-api.md` 4.1 — `content_version` 필드 서술을 바꾼다

현재의 "클라이언트가 **보관한 값**보다 크면 저장된 위치를 폐기하고 0부터 재생한다"를 지우고:

> `content.content_version` — 현재 발행본의 버전. 재발행 후 낡은 위치는 **서버가 이미
> 폐기했으므로**(`admin-api.md` 4.10) 클라이언트가 비교·폐기할 것은 없다. 이 값의 용도는
> 4.3 위치 저장의 버전 가드 입력이다(응답의 버전을 저장 요청에 되돌려 보낸다).

### 3. `admin-api.md` 4.10 — 재발행 부수 효과에 위치 폐기를 추가한다

- 4.10의 동작 서술에 추가: **"재발행 트랜잭션에서 그 콘텐츠의 `playback_progresses`를 전부
  삭제한다. 라이브러리(`library_items`)·재생 기록(`play_records`)은 유지된다."**
- 4.10 말미의 경고 블록(2026-09-07, `changes/archive/admin-api-republish-implemented.md` 처리
  기록의 "일어나지 않는 동작" 경고)은 이 수정으로 해소되므로 제거하고, 위 부수 효과 서술로
  대체한다.

## 사유

- 클라이언트에는 "보관한 값"이 없다 — 재생 위치를 로컬에 저장하지 않고 매 진입마다 4.1
  응답에서 받는다. 문서의 규칙은 수행 주체가 존재하지 않았고, 재발행 후 낡은 위치가 그대로
  내려가고 있었다(티켓 참조).
- 판정은 서버가 하고 클라이언트는 표시만 한다(공통 원칙). 서버 삭제(안 A)로 확정해 PR #165에
  구현했으므로, 문서가 구현을 따라와야 한다.

## 완료 조건

- Given `player.md` 7 / When 재발행 항을 읽는다 / Then 재생 위치 폐기 주체가 서버로 적혀 있고 클라이언트 폐기 서술이 없다
- Given `player-api.md` 4.1 / When `content_version` 서술을 읽는다 / Then "보관한 값과 비교" 문구가 없고 4.3 버전 가드 용도가 적혀 있다
- Given `admin-api.md` 4.10 / When 재발행 동작을 읽는다 / Then `playback_progresses` 삭제와 라이브러리 유지가 부수 효과로 적혀 있다

## 처리 기록 (반영 날짜: 2026-09-08)

세 문서 전부 반영했다.

- **`player.md` 7** — 폐기 주체를 서버로(재발행 트랜잭션에서 삭제), 클라이언트는 4.1 응답을
  그대로 사용. **발행 이후 확인된 사례 하나를 더 반영했다** — 재생 중 재발행이면 세션이 낡은
  위치를 들고 있으므로 버전 변경 감지 시 세션 위치를 폐기한다(실증 2026-09-08, 회수 동기화
  티켓에서 발견). 오프라인 파일 폐기는 P1 클라이언트 몫으로 남김.
- **`player-api.md` 4.1** — "보관한 값과 비교" 서술 제거, 용도를 4.3 버전 가드 입력 + 재생 중
  재발행 감지로 교체.
- **`admin-api.md` 4.10** — 경고 블록(⚠️ 폐기가 일어나지 않는다)을 제거하고 "재생 위치 폐기"
  확정 서술로 대체. 첫 문단의 `playback_progresses` 참조 유지 서술도 함께 교정.
