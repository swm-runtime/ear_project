## 배경

온보딩(O1~O9)과 같은 시각 문법으로 A4를 맞췄다. **동의 화면의 법적 명확성은 그대로**:
체크리스트 구조·필수/선택 구분·기본값 해제·[보기]·버튼 비활성 규칙·확정 카피 전부 유지.

> **방향 개정(2026-09-04 저녁)**: 아래 1~7 중 요약 카드(7)와 면 카드(3·4)·맨몸 체크(5)는
> 폐기하고 **로고+환영 인사 중심 구성(스타벅스 결)**으로 확정했다 — 최종 구성은 이 블록이
> 기준: ① 브랜드 로고 ② 환영 인사 헤드라인("만나서 반가워요!" — 카피 확정 필요) ③ 기존
> 확정 타이틀은 보조 톤 안내로 ④ 리스트는 화면 하부(전체 동의 굵게 + 구분선 + 항목 3종)
> ⑤ 체크 = 빈 원형, 체크 시 primary 채움 ⑥ [보기] = 밑줄 텍스트 → 오른쪽 셰브론(>)
> ⑦ 버튼 = radius full 알약, 텍스트 라벨 유지 ⑧ **마케팅 항목은 [보기] 없음** — 열람 문서
> 대신 한 줄 고지로 충분(4.3 "각 항목 [보기]" 서술의 예외로 명시 요청).

## 바뀐 표현(이력)

1. **인사 라인 신설** — 타이틀 위 "만나서 반가워요 👋" (신규 카피, 확정 필요).
2. **타이틀** — 큰 회색 헤드라인(xl·textSecondary)로 온보딩과 통일. 문자열 동일.
3. **전체 동의** — 면(surface) 알약 카드로 한 단계 위임을 표현(구분선 대체).
4. **항목 묶음** — 은은한 면 카드로 감쌈. 행 내부(체크·태그·보기)는 기존 그대로.
5. **체크 컨트롤 = 맨몸 ✓(토스식)** — 박스·원 없이 글리프가 컨트롤. 미체크 = 흐린 회색 ✓,
   체크 = primary ✓. 행 전체가 탭 영역(기존 그대로), 동작·낭독(checkbox 시맨틱) 불변.
6. **[동의하고 시작하기]** — radius full 알약. **텍스트 라벨 유지**(동의 버튼의 아이콘화 금지).

## 추가 (2026-09-04) — 약관 [보기]를 실제 본문에 연결

지금까지 A2 시작 화면의 `이용약관 · 개인정보 처리방침` 링크와 A4 동의 항목의 [보기]는
둘 다 `TODO(auth)` 로그만 남기고 아무것도 열지 않았다(URL 미확정). 랜딩(`earcast.co.kr`)에
약관 v0.1(출시 준비본)이 이미 게시돼 있어 그쪽으로 연결했다.

- URL은 `auth.constants.ts`의 `POLICY_DOCUMENT_URL` 한 곳에서만 관리한다
  (`/terms`, `/privacy`). 마케팅 동의는 열람 문서가 없어 [보기]를 그리지 않는다.
- 여는 방법은 `services/policy-document.service.ts`의 `openPolicyDocument()` —
  인앱 브라우저(`expo-web-browser`)다. 외부 브라우저로 나가면 동의 화면의 체크 상태를
  잃을 수 있다. **열람은 동의로 기록되지 않는다.**
- 본문을 앱에 넣지 않은 이유: 약관 개정이 스토어 배포를 기다리지 않아야 한다.

### 확인 필요 — 약관 문서가 두 벌이다

랜딩에 게시된 v0.1과 이번에 만든 `docs/legal/*-draft.md`(19조/12장)는 **조문 구조가 다른
별개 문서**다. 어느 쪽을 정본으로 삼을지 정하고 한 벌로 합쳐야 한다. 초안 쪽 검수 결과는
`docs/legal/review-2026-09-04.md`에 있다(3사 교차 검수).

### 완료 조건 (Given/When/Then)

- Given A4 약관 동의 화면에서, When 이용약관 동의 행의 [보기]를 누르면,
  Then 인앱 브라우저로 `https://earcast.co.kr/terms`가 열리고 체크 상태는 그대로다.
- Given A2 시작 화면에서, When 하단 `개인정보 처리방침`을 누르면,
  Then 인앱 브라우저로 `https://earcast.co.kr/privacy`가 열린다.
- Given 마케팅 정보 수신 동의 행에서, When 화면을 보면, Then [보기] 셰브론이 없다.
