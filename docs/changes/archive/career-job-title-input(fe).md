| 파급 | 커리어 uiux·api 명세(미작성 — 작성 시 이 값 기준). 온보딩 쪽은 수정 없음 |

## 왜 기록하는가

`career.md` 4.1의 화면 구성이 직무를 **"선택형"**이라 적었는데, 커리어는 온보딩 커리어 단계와
**같은 필드·같은 값 체계를 쓴다**(career.md 3장)는 원칙 아래에서 온보딩 쪽은 문서·계약·시안이
전부 **자유 입력**으로 일관한다.

- `onboarding.md` 3장 — `job_title: string` (자유 문자열)
- `onboarding-uiux.md` 4.3 — 구성: "직군(**선택**) · 직무(**입력**) · 연차(칩)"
- `onboarding-api.md` 4.4 — `job_title` string, 길이 상한 100자 (선택지 enum이 아니다)
- `wireframe/onboarding.html` O4 — 입력 필드(placeholder "예) 서비스 기획자")

즉 career.md 4.1의 "선택형" 한 줄만 홀로 어긋난 상태다. 와이어프레임 검토(2026-08-09)에서
**온보딩과 동일하게 자유 입력으로 확정**했다 — 두 화면이 같은 컬럼(`users.job_title`)을 쓰므로
입력 방식이 갈리면 같은 컬럼에 다른 값 체계(enum vs 자유 문자열)가 쌓인다.

직군(job_category)은 온보딩대로 **선택형 유지**이며 이 요청의 대상이 아니다(선택지 목록의
원천은 career.md 미결 그대로 — 온보딩 쪽 결정을 따른다).

## 기록할 내용 (반영 완료 2026-08-09)

`career.md` 4.1 화면 구성의 `[직무]   선택형` 을 **`[직무]   자유 입력 (온보딩과 동일 —
길이 상한 100자, onboarding-api.md 4.4)`** 로 교체한다.

## 완료 조건

- Given 이 요청이 통합 과정에서 반영된다 / When `career.md` 4.1을 읽는다 / Then 직무가
  자유 입력으로 기재되어 있고 "선택형" 표기가 남아 있지 않다
- Given 반영 후 / When `onboarding.md` 3장·`onboarding-uiux.md` 4.3과 대조한다 /
  Then 두 화면의 직무 입력 방식·값 체계가 일치한다
