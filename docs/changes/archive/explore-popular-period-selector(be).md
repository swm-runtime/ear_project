## 팀이 의도한 것

**사용자가 탐색 화면에서 인기 콘텐츠를 주간·월간·전체로 나눠서 볼 수 있어야 한다**(2026-08-07 확인).

## 문서의 현재 상태

세 문서 어디에도 그런 내용이 없다. 인기 섹션은 **서버가 고른 한 구간을 섹션 하나로 내려주는 것**으로만 적혀 있다.

| 문서 | 현재 문장 | 빠진 것 |
|---|---|---|
| `explore.md` 4.1 | "인기 콘텐츠 \| `content_stats`의 **직전 확정 구간**(지난주·지난달) 재생·완청 수 기준" | 사용자가 구간을 고른다는 규칙이 없다. `(지난주·지난달)`은 "직전 확정 구간"의 예시일 뿐이라 **서버가 주간을 쓸지 월간을 쓸지도 정해지지 않았다** |
| `explore-api.md` 4.1 | "**Request** — 파라미터 없음" | 구간을 실어 보낼 자리가 없다. 3장 엔드포인트 목록 5개에도 인기 전용 조회가 없다 |
| `explore-uiux.md` 4.1 | "구성 — 검색창 줄 / 주제 칩 줄 / 섹션(섹션 제목 + 세로 행 목록)의 반복 / 하단 탭 3개" | 기간 선택 컨트롤이 없다. 화면 목록 E1~E12에도 해당 화면·상태가 없다 |

**`content_stats` 테이블은 이미 세 구간을 갖고 있다**(`domain.md` 5.4 — `period_type: week | month | all`). 즉 **스키마 변경은 필요 없고**, 빠진 것은 그것을 사용자에게 노출하는 화면·계약 정의다.

### 주간·월간·전체가 문서에 등장하는 곳

혼동을 없애기 위해 적어 둔다. 이 표현은 문서에 있지만 **전부 파트너·운영 쪽 화면**이다.

| 문서 | 맥락 |
|---|---|
| PRD FR-34 | 파트너 **리포팅과 정산 연동**의 집계 단위 |
| `partner-control.md` 4.6 | 파트너 대시보드의 **기간별 추이** 3단위 |
| `admin.md` | **관리자 운영 현황** 조회 |
| `domain.md` 5.4 | `content_stats.period_type` 컬럼 정의 |

`features/README.md` 결정 28도 `partner-control 4.6`과 `explore 4.1`을 함께 묶고 있는데, 탐색이 물려받은 것은 3단위 축이 아니라 **"순위는 직전 확정 구간을 쓴다"는 규칙 한 줄**이다.

## 결정해야 할 것

### 1. API 형태 — FE와 합의가 필요하다

백엔드 권고는 **A안**이다.

| 안 | 형태 | 장점 | 단점 |
|---|---|---|---|
| **A (권고)** | `GET /explore/popular?period=week\|month\|all` 신설 | 토글 시 **그 섹션만** 재조회한다. 목록이 길어지면 커서 페이지네이션을 자연스럽게 붙일 수 있다 | 계약 문서에 6번째 엔드포인트가 늘어난다 |
| B | `GET /explore/feed?popular_period=...` | 새 엔드포인트가 없다 | 구간만 바꾸는데 **피드 전체가 재생성된다** — 관심사 섹션 랭킹(소비 신호 재계산)·주제별 모아보기까지 다시 만든다. `explore-api.md` 4.1의 "Request — 파라미터 없음" 규정도 바뀐다 |
| C | 피드에 세 구간을 모두 실어 보냄 | 추가 왕복이 없다 | 인기 섹션이 3배로 나가고, 클라이언트가 `sections[]`에서 `popular` 3개를 골라 토글해야 한다 — **"`key`를 화면 분기에 쓰지 않는다"**(`explore-api.md` 4.1) 규약과 정면으로 부딪친다 |

- A안을 고르면 응답에 **잔여 재생 표시값 3필드를 함께 실어야 한다**(`explore-api.md` 2장 — 목록을 여는 시점이 곧 그 값을 갱신하는 시점이다).
- 어느 안이든 **행 모양은 피드·필터 목록과 완전히 같아야 한다**(`explore-api.md` 4.2 — 두 모드가 다른 행 타입을 쓰면 담기·재생 처리가 두 벌이 된다).

### 2. 기본 구간 — 토글 없이 진입했을 때

| 후보 | 근거 |
|---|---|
| 주간 | 가장 최신 구간이라 "지금 인기"에 가깝다. **현재 서버 구현값이다** |
| 월간 | 표본이 더 크다. **온보딩 추천이 이미 월간을 쓰고 있어**(`toPreviousFinalMonthStart`) 두 화면의 "인기"가 같은 구간을 보게 된다 |
| 전체 | 표본이 가장 크지만 순위가 거의 고정된다 |

### 3. '전체' 구간에는 "직전 확정 구간" 규칙이 적용되지 않는다

주간·월간은 구간이 끝나면 `is_final = true`로 잠기지만(`domain.md` 5.4), **`all`은 끝나는 시점이 없어 확정·진행 중 구분 자체가 없다.** `period_start`도 `1970-01-01` 고정이다.

- 따라서 `all`을 조회할 때는 **`is_final` 조건을 걸지 않아야 한다.** 걸면 아무것도 안 나온다.
- 기존 코드에 선례가 있다 — 온보딩 추천 후보 조회(`ContentRepository.findCandidates`)는 `all` 구간을 조인할 때 `is_final`을 보지 않는다.
- **문서에 이 예외를 명시해 달라.** 안 적으면 구현마다 갈린다.

### 4. 배포 첫 주 합의를 세 구간에 각각 어떻게 적용하는가

2026-08-06 합의는 이렇다.

> 직전 확정 구간이 없는 배포 첫 주에는 섹션을 숨기지 않고, 표본 크기와 무관하게 같은 선정 기준으로 정렬한 상위를 보여준다.

구간이 셋이 되면 **월간은 첫 달 내내 확정 구간이 없다.** 그때 월간 탭이 사실상 신선도 순으로만 정렬된 목록이 되는데, 이것을 그대로 두는지(합의의 연장) 아니면 탭 자체를 비활성으로 두는지 정해야 한다. 백엔드 권고는 **그대로 두기**다 — 탭이 조건부로 사라지면 클라이언트가 서버 상태를 추측해야 한다.

### 5. 주제 필터를 걸면 인기 토글은 어떻게 되는가

주제 칩을 고르면 **섹션 구조를 버리고 단일 목록으로 전환한다**(`explore.md` 4.2). 그 화면에는 인기 섹션이 없으므로 토글도 사라진다.

- 칩을 전부 해제해 섹션형으로 돌아왔을 때 **직전에 고른 구간을 유지하는지 기본값으로 되돌리는지** 화면 명세가 정해야 한다.

### 6. 토글 상태의 유지 범위

탭을 떠났다 돌아오거나 앱을 재실행했을 때 고른 구간이 남는지, 매번 기본값으로 시작하는지. **서버에 저장할 값이 아니므로**(사용자 상태가 아니라 화면 상태다 — `paywall.md`의 억제 플래그와 같은 성격) 클라이언트 로컬 규칙으로 정하면 된다.

## 함께 확인할 것 — PRD와의 관계

PRD 4.2가 **"탐색 확장 필터(시리즈 여부·출처별): 중분류 확정 후 구체화"** 를 MVP 비범위로 두고 있다.

- 기간 토글은 그 두 축(시리즈·출처)과 다른 축이라 **별개로 보이지만**, "탐색에 필터 축을 늘리는 것"이라는 점은 같다.
- **MVP에 넣을지 P1로 미룰지**를 함께 정해 달라. `explore.md`·`explore-uiux.md`의 미결 사항 목록에도 이 항목이 없어 현재는 어느 쪽으로도 읽히지 않는다.

## 서버 구현 상태

**아직 반영하지 않았다.** 현재는 문서에 적힌 대로 서버가 한 구간을 골라 내려준다.

- `GET /explore/feed`의 인기 섹션 — **직전 확정 주**(`period_type = 'week'`, `is_final = true`)로 구현되어 있다. 정렬은 `play_count DESC → complete_count DESC → published_at DESC → id DESC`
- `ContentService.findPopular(periodStart, limit, now)`가 **구간을 인자로 받는 구조**라, 확정되면 `period_type`을 함께 받도록 넓히는 정도의 작업이다
- 스키마 변경은 필요 없다 — `content_stats`가 이미 세 구간을 갖고 있다(`domain.md` 5.4)

## 완료 조건

- Given `explore.md` 4.1 인기 섹션 규칙을 읽는다 / When 구간을 어떻게 정하는지 찾는다 / Then **사용자가 주간·월간·전체 중 하나를 고른다**는 규칙과 기본 구간이 명시되어 있다
- Given `explore-api.md`를 읽는다 / When 인기 구간을 바꾸는 요청을 찾는다 / Then 엔드포인트(또는 파라미터)와 응답 모양이 정의되어 있고, 행 모양이 4.1·4.2의 `items[]`와 같다
- Given `explore-uiux.md` 2장 화면 목록을 본다 / When 인기 구간 토글을 찾는다 / Then 화면 ID와 상태(선택 강조·전환 중·빈 결과)가 정의되어 있다
- Given `all` 구간을 조회한다 / When 서버가 `content_stats`를 읽는다 / Then `is_final` 조건을 걸지 않으며, 그 예외가 문서에 적혀 있다
- Given 배포 첫 달에 월간 탭을 연다 / When 목록을 본다 / Then 탭이 사라지지 않고 2026-08-06 합의대로 같은 선정 기준의 상위가 노출된다
- Given 주제 필터를 걸었다 해제한다 / When 인기 섹션을 다시 본다 / Then 직전에 고른 구간의 유지 여부가 문서가 정한 대로 동작한다
