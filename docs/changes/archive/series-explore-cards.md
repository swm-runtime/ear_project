## 배경

탐색에서 시리즈는 하나의 요소다(결정 2026-10-09). 지금은 편마다 한 줄이라 16편짜리 시리즈 하나가 목록을 덮는다. 같은 시리즈 편들을 **시리즈 카드 하나**로 접는다. 항목 종류가 새로 생기므로(`type: "series"`) **1.2.x 앱은 이 응답을 그리지 못한다** — 헤더로 가르지 않고(철회 2026-10-17) 앱 1.3.0과 함께, 최소 지원 버전을 1.3.0으로 올린 뒤 서버 스위치로 켠다.

## 수정 내용

### 1. 서버 스위치 `SERIES_EXPLORE_CARDS_ENABLED`

- 선택 키, 값 `true`/`false`/빈 값. **`true`를 명시했을 때만 켜진다**(`GLOBAL_SIGNUP_ENABLED`와 같은 꼴 — `env.validation.ts`, `deploy/push.sh`의 알려진 선택 키, `.env.example`). Secrets에 없으면 빈 채로 꺼진다.
- **꺼져 있으면 응답·커서가 1단계와 같다** — 항목에 `type` 키가 없고, 시리즈 편은 편마다 한 줄이고, 검색은 시리즈 제목을 보지 않는다. 피드 섹션의 후보 수도 종전 그대로(10)다. e2e `test/series-explore-cards.e2e-spec.ts`가 피드·주제 칩·주제별·인기·검색에서 이를 확인한다.
- 개발계: FE KAN-225가 준비되면 켠다(지금 개발계 미리보기 앱에는 카드 UI가 없어 켜면 탐색이 깨진다). 운영: 아래 "켜는 순서".

### 2. `explore-api.md` — 항목 종류(스위치 켬)

피드 섹션의 `items[]` · 주제별(4.2) · 인기(4.2-1) · 검색(4.5)의 `items[]`와 검색 `fallback.popular_items[]`가 **두 종류가 섞인 목록**이 된다. 클라이언트는 `type`으로 가른다(모르는 `type`은 건너뛴다).

**콘텐츠 행** — 종전 행과 같고 `type`만 붙는다(시리즈가 아닌 콘텐츠만 이 모양으로 나온다 — 시리즈 편은 카드가 대신한다):

```jsonc
{
  "type": "content",
  "content": {
    "id": "uuid", "title": "…", "author_name": null, "source_name": "…", "source_url": null,
    "duration_sec": 620, "thumbnail_url": "https://…", "language": "ko", "content_version": 1,
    "topic_ids": ["uuid"], "tags": ["…"],
    "series": null
  },
  "library": { "item_id": "uuid", "source": "save", "status": "completed" } | null,
  "is_counted_today": false
}
```

**시리즈 카드**:

```jsonc
{
  "type": "series",
  "series": {
    "id": "7de91e6e-2e96-4aea-9ddb-80fe99179c2e",
    "title": "키워드로 빠르게 배우는 CS 지식",
    "description": "소프트웨어 개발부터 …",
    "total_episodes": 16,     // 계획 편수(시리즈 표)
    "episode_count": 16,      // 지금 사용자 시장에 노출 중인 편 수 — 진행 중 시리즈면 total_episodes 보다 적다
    "status": "completed",    // ongoing | completed — 표시용
    "thumbnail_url": "https://…/1화.webp",   // 표지 = 노출 중인 가장 앞 편(보통 1화)의 썸네일
    "topic_ids": ["uuid", "uuid"]            // 노출 중인 편들의 주제 합집합(처음 나온 순서)
  }
}
```

- 카드를 탭하면 `GET /series/:series_id`(1단계 계약)로 시리즈 화면을 연다 — "행 탭 = 즉시 재생"(`explore.md` 4.4)의 예외. 카드에는 편 단위 상태(`library`·`is_counted_today`)가 없다 — 시리즈 화면이 편마다 준다.
- **카드의 자리(순위) = 그 시리즈 편 중 순위가 가장 높은 편의 자리**(= 편 점수의 최댓값, 확정한 세부). 그 목록의 정렬 규칙(인기·추천 랭킹·검색 점수)을 바꾸지 않고, 순위순으로 훑다가 시리즈를 처음 만난 편에서 카드를 낸다.
- **한 목록(페이지를 넘어도)에 같은 시리즈 카드는 한 번**이다. 피드는 **섹션마다** 접는다 — 같은 시리즈가 인기·새로 나온 콘텐츠 두 섹션에 각각 카드로 나올 수 있다(콘텐츠가 섹션마다 겹쳐 나오는 것과 같다).
- 주제 필터·검색은 **편 단위로 걸고** 접는다 — 필터에 맞는 편이 하나라도 있으면 카드가 나오고, 카드의 `topic_ids`·`episode_count`는 필터와 무관한 시리즈 전체(노출 편) 값이다.
- 시장 격리는 종전과 같다 — 다른 시장 편은 목록에 없으므로 카드도 없다.

### 3. 페이지네이션(주제별·인기·검색) — 커서 의미

- **커서 모양·`has_next`·`next_cursor` 규칙이 꺼진 모드와 같다**(편 단위 정렬 키 + 조회 조건 지문). 커서에 시리즈 정보를 싣지 않는다 — 시리즈가 몇 개든 커서 길이가 같다.
- 서버는 목록의 필터(노출·시장·주제·검색 일치)를 건 편들 중 **시리즈마다 그 목록의 정렬 키로 가장 앞선 편 하나(대표 편)와 단일 콘텐츠만** 남기고, 그 위에서 종전과 같은 키셋 페이지를 낸다(SQL `ROW_NUMBER() OVER (PARTITION BY series_id ORDER BY <목록의 정렬 키>) = 1`). 대표 편이 카드로 바뀐다.
  - 필터가 대표 고르기 **앞**에 걸린다 — 대표는 "그 목록에 들어온 편 중 가장 앞 편"이다(주제 필터·검색에 맞지 않는 편은 대표가 될 수 없다).
  - 대표 고르기는 커서와 무관하다 — 페이지를 넘어도 한 시리즈는 목록 전체에서 한 번, 단일 콘텐츠는 키셋이 한 번만 읽는다.
  - 페이지는 언제나 `limit`개로 차고(마지막 페이지 제외), 빈 커서 페이지는 진짜 끝일 때만 나온다.
- 스위치를 켜고 끄는 순간 받아 둔 커서는 그대로 쓸 수 있다(모양이 같다). 전환 직후 그 목록에서 한 시리즈가 편으로 한 번·카드로 한 번 보일 수 있다(전환 순간 한 번).

### 4. 검색(4.5) — 시리즈 제목 일치

- 스위치를 켜면 **시리즈 제목이 맞는 편도 결과에 든다**(가중은 제목과 같다). 그 편들의 대표 하나가 카드가 된다. 편 제목이 이미 시리즈 이름을 품고 있는 경우(CS 시리즈)는 결과가 같다.
- 태그 전용 검색(`#…`)은 종전대로 태그만 본다.
- 검색 로그(`search_query_logs`)의 결과 수·결과 콘텐츠 id는 페이지의 행 기준이다(카드는 그 대표 편 id).
- **대체 콘텐츠(`fallback`)는 첫 페이지의 빈 결과에만** 붙는다(종전 규칙 그대로). 빈 페이지가 진짜 끝일 때만 나오므로 결과가 남았는데 `has_next: false`로 끊기는 일이 없다.
- 빈 결과의 `fallback.popular_items`도 같은 규칙(대표 편)으로 접는다.

### 5. 피드(4.1) 섹션

- **인기·새로 나온 콘텐츠** 섹션은 위와 같은 대표 편 조회로 10건을 읽는다(인기 섹션 = 인기 목록 첫 페이지).
- **관심사·주제별** 섹션은 후보를 메모리에서 다시 줄 세우거나(관심사 — 개인 적합도) 후보 조회를 그대로 써서 SQL이 대표를 고를 수 없다. 켜져 있으면 후보를 **30건(10 × 3)** 읽어 메모리에서 같은 규칙(처음 만난 편)으로 접은 뒤 10칸으로 자른다.

### 6. 성능 메모 (로컬 EXPLAIN ANALYZE, 2026-10-17)

- 대표 고르기는 **상관없는 부분 질의**라 질의당 한 번(`hashed SubPlan`) 계산된다 — 행마다 다시 돌지 않는다. 윈도는 필터를 통과한 **시리즈 편만**(`series_id IS NOT NULL`) 정렬한다(`WindowAgg` + `Run Condition: row_number() <= 1`).
- 비용은 같은 필터를 한 번 더 도는 것(콘텐츠 표·집계 조인)이다. 로컬(콘텐츠 33건)에서 주제별 목록 0.35ms. 운영 카탈로그(수백 건 미만)에서 이 차이는 무시할 만하다. 카탈로그가 수만 건이 되면 시리즈 편 수에 비례하는 정렬 하나가 더해진다.
- 꺼진 모드는 부분 질의가 붙지 않는다 — SQL·파라미터가 종전과 같다.

## 켜는 순서 (운영)

1. **`dev → main` 배포 — 스위치는 꺼진 채**(빈 값). 응답은 1단계와 같아 1.2.1이 안전하다.
2. **스토어 1.3.0 빌드·심사·공개** — main 머지와 독립이다. **FE는 1.3.0의 `runtimeVersion`을 36으로 올린다** — main 머지가 운영 OTA를 자동으로 내보내므로, 올리지 않으면 1.3.0 번들이 1.2.x 바이너리에 OTA로 실린다.
3. **최소 지원 버전(`MIN_SUPPORTED_APP_VERSION_IOS`/`_ANDROID`)을 1.3.0으로** — 2가 끝나기 전에는 절대 올리지 않는다(받을 업데이트가 없는 사용자가 막힌다).
4. **스위치를 켠다** — Secrets에 `SERIES_EXPLORE_CARDS_ENABLED=true` → API 컨테이너 재생성(`API_IMAGE` 고정 — runbook). 끄려면 값을 비우고 다시 띄운다(즉시 1단계 응답).

## 완료 조건

- Given 스위치가 비어 있다 / When 피드·주제 칩·주제별·인기·검색을 부른다 / Then 항목에 `type` 키가 없고 시리즈 편이 편마다 한 줄이다(1단계와 같은 모양 — 커서 모양은 켜도 같다)
