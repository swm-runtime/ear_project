## 수정 내용

`features/common-error-handling.md` 5장 표의 "로딩" 행을 바꾼다.

- 지금: `| 로딩 | 스켈레톤(목록) / 스피너(액션). 0.3초 미만이면 표시하지 않아 깜빡임 방지 |`
- 바꿀 것: `| 로딩 | 스켈레톤(화면·영역의 **내용** 로딩 — 목록·칩 줄·카드·대본·대기열 등) / 스피너(액션 진행 · 목록 하단 추가 로딩 · 이미 보이는 내용의 갱신). 0.3초 미만이면 표시하지 않아 깜빡임 방지. 모양·모션은 frontend/design.md §5 스켈레톤 |`

## 사유

KAN-140으로 앱이 목록 밖 내용 영역(온보딩 진입 화면, 직군 칩 줄, 플레이어 대기열·대본, 라이브러리 필터 시트의 주제 칩, 첫 검색 결과)의 스피너도 스켈레톤으로 바꿨다. 표가 "목록"만 적고 있으면 다음 사람이 칩 줄·대본 같은 영역을 "목록이 아니니 스피너"로 읽고 되돌릴 수 있다. 반대로 스피너가 남는 곳(버튼 액션·하단 추가 로딩·당겨서 새로고침·직전 검색 결과 위 갱신)도 표에 드러나야 구분이 확인 가능하다. `features/`는 FE 단독 소유가 아니라 개발 중 직접 고치지 않고 여기 기록한다(루트 `CLAUDE.md` 요청 문서 규칙). FE 문서(`frontend/architecture.md` 8.3 · `frontend/design.md` §5)는 같은 PR에서 이미 맞췄다.

## 완료 조건

- Given `features/common-error-handling.md` 5장 "로딩" 행 / When 읽는다 / Then 스켈레톤이 목록뿐 아니라 화면·영역의 내용 로딩 전반에 쓰이고, 스피너가 액션·하단 추가 로딩·이미 보이는 내용의 갱신에 남는다는 구분이 적혀 있다
