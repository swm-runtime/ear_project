## 문제

1. Sentry 알림 규칙의 Throttle 기본값이 "Get notified on every trigger"다. "이벤트 발생" 트리거와 만나면 이벤트마다 웹훅이 와서 Slack 웹훅 한도(초당 1건)에 걸린다 — 런북의 켜는 법에 빈도 설정이 없었다.
2. 주간 지표 SQL은 KST 자정 경계인데 일일 지표(Slack 보고)는 서비스 날짜 경계(04:00, 전환 뒤 05:00)다 — 두 숫자를 직접 대조하면 어긋난다는 말이 없었다.

## 수정 내용

- 런북 ③ 단계에 Throttle 설정(이슈당 30분 권장)을 추가.
- 주간 지표 SQL 머리말에 경계 차이 메모.
- 같은 PR의 코드(문서 변경 없음): ① 처음 연결하는 구독에서 Apple 답의 거래가 제출된 거래와 다른 계정 토큰이면 그 답으로 반영하지 않고 거래로 판정(주인 확인은 제출 거래로 했으므로) ② 알림 넘겨받기가 거절되면 새 계정의 결제 의도를 `verified`로 찍지 않음.

## 완료 조건

- Given 런북 켜는 법 / When ③ 단계를 본다 / Then Throttle 설정이 적혀 있다
- Given 주간 지표 SQL / When 머리말을 본다 / Then 일일 지표와 경계가 다르다는 메모가 있다
- Given Apple 답의 거래 토큰이 제출 거래와 다르다 / When 영수증을 제출한다 / Then 제출 거래로 연결되고 요청자의 의도만 확인된다
- Given 끝난 구독에 다른 계정 토큰의 비되살림 알림 / When 반영한다 / Then 그 계정의 결제 의도는 `created` 그대로다
