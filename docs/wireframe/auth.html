계정 — 로그인 · 가입 · 탈퇴

자체 아이디·비밀번호가 없으므로 이 플로우 전체가 소셜 제공자에 의존합니다. 가장 무거운 화면은 로그인이 아니라 탈퇴입니다 — 즉시 파기와 5년 보존이 갈리는 지점이기 때문입니다.

계정 온보딩 라이브러리
이 시안의 용도. 범위 검증용입니다 — 화면에 무엇이 있고 없는지를 확인하세요. 색·서체·간격은 제안이며 확정된 아이덴티티가 아닙니다. 앱 다크 테마는 아직 설계하지 않아 기기 안은 항상 라이트로 렌더됩니다. 각 요소의 번호는 명세 조항으로 연결됩니다. 주황 번호는 명세에 근거가 없는 지점입니다.

계정 플로우에서 나온 것

화면으로 옮기니 명세만 읽을 때는 보이지 않던 빈칸이 나왔습니다.

V1시작 화면의 동의 문구

시작 화면에 "계속하면 약관에 동의하게 됩니다"를 넣으면 A4의 명시적 동의와 이중이 됩니다. 명세는 동의를 A4에서만 받도록 정의하므로, 시안에서는 링크만 두고 동의 의미는 부여하지 않았습니다. 이대로 확정할지 확인이 필요합니다.

auth 4.1 · 5 / 화면 A1

V2탈퇴 화면의 보존 고지

명세는 "삭제되는 데이터"만 명시합니다. 그런데 실제로는 결제 이력·이메일이 5년 보존됩니다. 사용자가 "다 지워진다"고 이해한 채 탈퇴하면 나중에 문제가 됩니다. 시안에는 넣어뒀지만 명세에 근거가 없으므로 넣기로 확정하면 auth 4.3에 추가해야 합니다.

auth 4.3 / domain 12.2~12.3 / 화면 A7

V3이메일이 없는 계정의 표시

카카오 선택 동의를 거부하면 이메일 없이 가입됩니다. 설정의 계정 요약(A5)에서 이메일 자리를 어떻게 채울지 정해야 합니다. 더 중요한 건 탈퇴 아카이브인데, 이메일이 없으면 거래 주체 식별이 provider_user_id에만 의존합니다.

auth 7 / domain 11.3 / 화면 A5 · A7

V4스토어 해지 유도 버튼

시안에 [스토어에서 해지하기] 버튼을 넣었지만 명세에는 안내 문구만 있습니다. 버튼으로 스토어 딥링크를 제공할지, 텍스트 안내만 할지 정해야 합니다. 버튼이 있으면 해지율이 올라가고 탈퇴 후 잔여 결제 CS는 줄어듭니다.

auth 4.3-2 / subscription 4.5 / 화면 A7
