계정 — 로그인 · 가입 · 이메일 인증 · 탈퇴

자체 아이디·비밀번호가 없으므로 이 플로우 전체가 소셜 제공자에 의존합니다. 가장 무거운 화면은 로그인이 아니라 탈퇴입니다 — 즉시 파기와 5년 보존이 갈리는 지점이기 때문입니다. 화면 수가 가장 많은 곳은 이메일 코드 인증인데, 제한이 유효 시간·검증 시도·발송 횟수 세 갈래로 갈리기 때문입니다.

계정 온보딩 라이브러리 탐색 프로필 설정
이 시안의 용도. 범위 검증용입니다 — 화면에 무엇이 있고 없는지를 확인하세요. 색·서체·간격은 제안이며 확정된 아이덴티티가 아닙니다. 앱 다크 테마는 아직 설계하지 않아 기기 안은 항상 라이트로 렌더됩니다. 각 요소의 번호는 명세 조항으로 연결됩니다. 문자 표기는 검토가 필요했던 지점이며, 그중 주황 문자는 아직 명세에 근거가 없는 것입니다.

V5이메일이 없는 계정의 표시 — 해소됨

A5는 세 상태(없음 / 있음·미인증 / 있음·인증됨)를 구분해 표시합니다. 탈퇴 아카이브 쪽 우려도 사라졌습니다 — 결제 이력이 없으면 아카이브 자체를 하지 않고 전량 즉시 파기하기 때문입니다. 아카이브되는 사용자는 전원 결제자이고, 결제는 인증된 이메일 없이 시작되지 않으므로 archived_users.email은 NOT NULL이 됩니다.

V6계정 단위 발송 상한이 사라졌습니다 — P0

발송 제한을 주소 단위로 바꾸면서(V1) 계정 단위 총량 제한이 없어졌습니다. [메일 다시 입력]으로 주소를 계속 갈아 끼우면 한 계정이 보낼 수 있는 메일 수에 상한이 없고, 서비스가 임의의 제3자에게 메일을 보내는 발송기로 악용될 수 있습니다. 주소 단위 5회는 유지하되 그 위에 계정 단위 상한(예: 1시간 20회 / 하루 50회)을 얹을지 정해야 합니다. 발신 도메인 평판이 걸린 문제라 메일 인프라 선택보다 먼저 정하는 편이 좋습니다.
