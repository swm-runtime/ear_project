# 이어 - PRD

## 1. 개요

#### 1.1 서비스 한 줄 정의

자기계발·커리어·교양을 주제로 한 팟캐스트 콘텐츠를 AI로 생성하여 제공하고 사용자의 관심사에 맞춰 추천·자동 편성·제공하는 서비스

#### 1.2 문제 정의

자기계발·커리어·교양 콘텐츠를 소비하려는 직장인의 가용 시간은 대부분 통근 시간이다. 그러나 이 시간에는 눈과 손이 자유롭지 않아 콘텐츠의 주류인 텍스트를 소비하기 어렵다.

오디오 대안들은 각자 한계가 있다.

- **기존 인간 팟캐스트**: 주제가 진행자에게 종속되어 내 관심사에 맞는 선택권이 없고, 발행 주기가 불규칙하며, 종영 리스크가 있다. 관심사를 따라 이어지는 커리큘럼형 청취가 불가능하다.
- **NotebookLM류 AI 오디오 도구**: 사용자가 직접 자료를 찾아 넣어야 하는 '도구'다. 무엇을 들을지 고르는 수고가 그대로 남는다.
- **유튜브·뉴스레터**: 화면을 봐야 하거나 텍스트라서, 통근 맥락(눈·손 비가용)을 해결하지 못한다.

결과적으로 "출근길에 앱을 열면, 내 관심사에 맞는 믿을 만한 콘텐츠가 들을 수 있는 형태로 준비되어 있는" 경험은 현재 존재하지 않는다.

#### 1.3 솔루션

1. **콘텐츠 — 하이브리드 수급**
    - 검증된 외부 아티클(퍼블리 등 라이선스 파트너, 개인 작가)을 TTS로 오디오화한다. 이 라이선스 콘텐츠가 서비스 신뢰의 축이다.
    - 외부 아티클의 양적 한계는 AI 자체 생성 콘텐츠로 보완한다(롱테일 주제 커버). 변환·생성 콘텐츠 모두 환각 방지를 위한 원문·소스 대조 QA를 거친다.
    - **모든 콘텐츠는 단일 표준 형태의 에피소드로 제공된다.** 같은 콘텐츠는 모든 사용자에게 동일하며, 콘텐츠 변형(버전)은 존재하지 않는다.
        - 한 에피소드의 권장 길이는 약 10~15분으로 하되, 콘텐츠의 완결성을 우선하여 분할한다.
2. **소비 — 두 경로**
    - **자동 드립**: 관심사 기반으로 콘텐츠가 라이브러리에 자동 적립된다. 앱을 열면 들을 것이 준비되어 있고, 주제 고갈·확장은 소비 신호를 바탕으로 백그라운드에서 자동 처리된다. **드립은 무료 티어를 포함한 전 티어에 제공하며**, 무료 티어는 하루 2편으로 고정한다(유료 티어 편수는 시범 운영 후 결정).
    - **능동 탐색**: 탐색 피드에서 직접 발견해 듣는다. 소비 기반 추천이 작동한다.
3. **개인화 — 피드 레벨**
    - 콘텐츠(대본) 자체는 전 사용자 동일하며, 개인화는 추천·드립 편성(무엇을 언제 들려줄지)에서 이루어진다. 이 구조로 재생은 항상 즉시 가능하고(생성 대기 없음), 사용자 수와 무관하게 콘텐츠 원가가 통제된다.

## 2. 목표/비목표

#### 2.1 목표 - 달성할 것

- 통근하는 주니어 직장인이 "열면 들을 게 준비되어 있는" 경험으로 텍스트 자기계발 콘텐츠 소비를 오디오로 전환하게 한다.
- 검증된 파트너 콘텐츠(퍼블리)와 AI 생성 콘텐츠를 하나의 파이프라인으로 자동 오디오화하여, 무검수에 가까운 일일 발행을 품질 보증(QA)과 함께 성립시킨다. **MVP는 팀이 직접 제작·업로드하는 방식으로 시작하고, 자동화는 성장 단계 목표다**(4.1·4.2).
- 피드 레벨 개인화(추천·드립 편성)만으로 개인 관심사에 맞는 청취 경험을 만들어준다.
- 소마 기간 내(11월) 시범 운영 → 정식 운영까지 도달하고, 파트너십 확대 판단이 가능한 성과 데이터를 확보한다.

#### 2.2 비목표 - 달성하지 않을 것

- **대본(콘텐츠) per-user 개인화를 하지 않는다.** 모든 콘텐츠는 전 사용자 동일하며, 개인화는 피드 레벨만. 이를 뒤집는 것은 PRD 개정 사안이다.
- **범용 TTS를 만들지 않는다.** 자체 TTS는 본 서비스용 도메인 특화(한국어 팟캐스트 발화) 스코프다. 특정 인물 음성 복제(보이스 클로닝)도 목적이 아니다.
- **사용자가 자료를 넣는 도구(NotebookLM류)가 아니다.** 수급·편성을 서비스가 알아서 하는 '방송국' 모델이다.
- **무단 콘텐츠 수집을 하지 않는다.** 파트너·유료 콘텐츠는 공식 제공 경로로만 수급하며, 스크래핑·크롤링 등 비정상적 수집을 일절 사용하지 않는다(파트너 약속 사항, 절대 조항). AI 생성 콘텐츠를 위한 일반 소스 수집은 금지가 아니라 **저작권·이용약관·수집 정책(robots 등)을 준수하는 적법한 범위**로 한정한다 — 권리를 침해하는 수집이 비목표이지, 수집 자체가 비목표는 아니다.

## 3. 타깃 사용자

#### 3.1 주요 타깃

**편도 30분 이상 대중교통으로 통근하는 20대 후반~30대 초반의 주니어 직장인.** 이미 아티클·뉴스레터·유튜브 등으로 자기계발 콘텐츠를 소비하고 있으며, 성장에 대한 갈증은 크지만 텍스트를 꾸준히·차분하게 읽을 시간이 부족한 사람.

- **사용 맥락**: 통근 중(팟캐스트 최대 청취 맥락, 전체 청취의 ~34%). 눈과 손이 자유롭지 않은 상태.
- **핵심 니즈**: 통근 시간을 의미 있게 쓰고 싶으나, 무엇을 들을지 매번 고르는 것 자체가 비용. "열면 준비되어 있는" 경험을 원함.
- **지불 준거**: 윌라·밀리(월 9,900원) 등 국내 콘텐츠 구독을 이미 인지·경험한 층.

#### 3.2 보조 타깃

- 통근 외 이동이나 작업 중에도 틈틈이 자기계발과 지식 습득을 위해 콘텐츠를 소비하려는 사용자
- 취업준비생·대학생: 커리어·자기계발 니즈는 동일하나 지불 여력이 낮은 층 — 무료 티어(라이트)의 주 사용자층이자 향후 전환 풀.

## 4. 범위

#### 4.1 MVP에 포함할 것

**클라이언트 (기능 기준)**

- 온보딩
- 라이브러리(메인·앱 첫 화면)
- 탐색
- 팟캐스트 플레이어
- 프로필(관심사·커리어·이메일 인증·현재 플랜)
- 설정 — 프로필 화면에서 진입
- 유료 결제
- 공통: 스플래시(진입 분기·버전 체크), 소셜 로그인, 페이월 바텀시트(+인앱 결제), 오류/업데이트 안내
- 운영(관리자): 콘텐츠 업로드, 주제 추가·삭제·노출 관리 — 관리자 계정으로 로그인해 사용하는 앱 내 제한 기능

하단 탭은 **라이브러리 / 탐색 / 프로필** 3개다. 설정은 탭이 아니라 프로필 화면 안의 진입점으로 둔다.

**수익화**

- 3티어(**라이트·데일리·프로**) 구독제도 (1~2주 간의 무료 시범 운영을 거쳐 사용자 반응을 보고 가격 설정)
- **라이트 = 무료 티어**: 담기 무제한, 광고 제공, **재생 하루 2편 + 드립 하루 2편** — 페이월 트리거는 2편 소진 후 재생 시도 시점
- 데일리·프로: 재생 한도·드립 편수·가격 모두 시범 운영 후 확정

**콘텐츠 공급 (서버·운영)**

- **MVP는 자동 파이프라인을 운영하지 않는다.** 대본 생성·QA 대조·TTS 변환은 팀이 앱 밖에서 수행하고, 완성된 오디오를 **관리자 계정으로 업로드하면 즉시 발행**된다. 업로드 이전 단계의 상태는 시스템에서 관리하지 않는다.
- 파트너 원문 수급(공식 경로) → 표준 에피소드 형태로 제작 → 원문 대조 검수 → 업로드·발행
- 파트너 통제 반영(콘텐츠 단위 제외 지정·회수 즉시 반영)
- 상용 TTS 기반 오디오 생성, 모든 콘텐츠에 출처·저자 고지(시작·종료 멘트) 및 원문 연결 정보
- 드립 편성·추천 시스템: 관심사 기반 편성, 소비 신호(완청·스킵 등) 반영 갱신, 주제 고갈 시 인접 주제 자동 확장, 신규 유저 콜드스타트(인기·신규 기반 대체)

#### 4.2 MVP에 포함하지 않을 것

- **자동 콘텐츠 파이프라인**: 원문 인입 → 대본 생성 → QA 대조 → TTS → 발행을 시스템이 자동 수행하는 구조. MVP는 팀이 직접 제작해 관리자 업로드로 대체하며, 자동화는 콘텐츠 볼륨이 수작업 한계를 넘는 시점에 도입한다.
- **파트너 발행 전 검수**: 업로드 즉시 발행 구조이므로 검수 대기 상태를 두지 않는다. 파트너 요구가 확정되면 도입한다.
- **자체 TTS 전환**: MVP는 상용 TTS. 자체 학습 모델(태깅 모델 → 도메인 특화 TTS)은 성장 단계에 병행 개발 후 전환.
- **프리미엄 팩/코스 본격 운영(예정)**: MVP는 0~1개 테스트 수준. 프로 티어 월 팩 크레딧(1개) 포함 본격 운영은 로열 베이스 확보 후.
- **오픈 마켓**(창작자 지정가 단건 판매 시스템): 후순위. 추가 여부 결정 필요
- **오프라인 저장**(유료 기능으로 방향 확정, **P1로 이연 확정** — FR-26) — *현재 IA에 미반영, 도입 시점에 IA 추가 필요.*
- **공유 수신자용 웹 랜딩**: MVP는 스토어 링크로 대체.
- **탐색 확장 필터**(시리즈 여부·출처별): 중분류 확정 후 구체화.

## 5. 사용자 흐름

#### 5.1 신규 사용자 (최초 실행)

스플래시 → 시작 화면(서비스 소개) → 소셜 로그인 → 관심 주제 선택(중분류, **최소 1개·최대 3개**) → 커리어 정보 입력(건너뛰기 가능, 이후 프로필에서 입력·수정) → 추천 콘텐츠 선택 및 라이브러리 담기 → 온보딩 완료(주제 요약) → 알림 권한 요청 → **라이브러리 진입**

- 진행 인디케이터는 값을 입력하는 **3단계**(관심 주제·커리어·추천 담기)에만 표시하고, 완료·알림 화면은 인디케이터 밖에 둔다.

#### 5.2 일상 사용 (핵심 루프 — 유료)

앱 실행 → 라이브러리 → 아이템 탭 → **즉시 재생**(플레이어) → 청취(배속·타이머·스크립트) → 완청/스킵
→ *[백그라운드]* 소비 신호 반영 → 다음 드립 편성 갱신 → 다음 접속 시 새 콘텐츠 적립

#### 5.3 탐색·획득

탐색 탭 → 추천 피드(필터·검색) → 카드 탭=즉시 재생 / 더보기 → 담기(라이브러리 적립, 무제한) 또는 공유

#### 5.4 무료 사용자 제한·전환

재생 시도 → **재생 전 확인**(남은 횟수·1회 차감 고지, 확인해야 재생 시작) → 하루 2편 재생 소진 → 3편째 재생 시도 → **페이월 바텀시트**(제한 안내·요금제 비교) → **(이메일 미등록 시) 이메일 등록·인증** → 인앱 결제 → 결제 완료 시 티어 즉시 반영 + 막혔던 지점으로 복귀해 이어 진행 (닫기 시 원래 화면 복귀, 담기에는 페이월 미노출)

#### 5.5 관심사 변경

프로필(또는 설정) → 관심사 관리 → 주제 일괄 편집·커리어 정보 수정·자동 확장 토글 → 저장(해제 주제 포함 시 변경 확인 팝업) → 변경 사항 적용: 추가=드립 편성 대상, 해제=신규 적립 중단(미청취분 유지)

#### 5.6 시스템 흐름 (사용자 비노출·백그라운드)

**콘텐츠 공급 (MVP — 앱 밖 수작업 + 관리자 업로드)**: 파트너 원문 수급/AI 생성 → 대본 생성 → 원문 대조 검수 → 표준 형태 변환(TTS) → **관리자 업로드 = 즉시 발행** → 카탈로그 편입
**편성·갱신**: 관심사·소비 신호 기반 드립 편성 → 주제 고갈 감지 → 인접·심화 주제 자동 확장 → 추천 순위 갱신
**파트너 통제**: 회수 요청 → 대상 콘텐츠 즉시 제외

### 6.1 계정

- **FR-01** (P0) 소셜 로그인으로 가입·인증한다. (제공자 — 카카오·구글·네이버)
- **FR-02** (P0) 로그아웃·회원 탈퇴를 제공한다. 탈퇴 시 라이브러리·관심사·커리어·재생 이력은 **즉시 파기**하고, 결제 이력과 거래 주체 식별 정보(전자우편주소 등)·동의 이력은 **별도 영역에 5년 보존 후 파기**한다(전자상거래법 제6조, 개인정보보호법 제21조). 활성 구독이 있으면 구독 만료에 동의한 뒤에만 탈퇴할 수 있다. 세부 정책은 `docs/backend/domain.md` 12장.
- **FR-39** (P0) 이메일은 소셜 제공자가 제공하면 **가입 시점에 그대로 저장**하고, 제공하지 않거나 발송이 불가능한 주소(마스킹 등)면 저장하지 않는다. 이메일은 가입 조건이 아니며 계정 식별에도 쓰지 않는다. 이메일이 없는 사용자는 **첫 결제 직전에 이메일 코드 인증을 완료해야 결제가 시작된다**(거래기록 보존 목적 — 전자상거래법 시행령 제6조). 등록·변경은 프로필·설정에서 언제든 가능하며, 세 경로가 같은 인증 규칙과 발송 횟수 제한을 공유한다.

### 6.2 관심사 설정

- **FR-03** (P0) 최초 온보딩에서 자기계발/교양 내 중분류 관심 주제를 **최소 1개·최대 3개** 선택받는다. 상한은 드립 편성이 여러 주제로 분산되는 것을 막기 위한 것이며, 클라이언트뿐 아니라 **서버에서도 검증**한다. 같은 상한이 이후 관심사 편집(FR-05)에도 적용된다. 주제 목록은 수급 콘텐츠에서 역산한다.
- **FR-04** (P0) 커리어 정보(직업, 연차 등)를 입력받는다. 입력은 선택 사항이며 **이후 프로필에서 언제든 입력·수정**할 수 있다.
- **FR-05** (P0) 관심 주제·커리어 정보를 언제든 일괄 편집할 수 있고, 변경은 추천에 즉시 반영된다 — 추가=드립 편성 대상, 해제=신규 적립 중단(기존 미청취분 유지).
- **FR-06** (P1) 주제 자동 확장 허용 여부를 사용자가 설정할 수 있다.

### 6.3 콘텐츠 공급

- **FR-07** (P0) 파트너 원문은 공식 제공 경로로만 수급하고, 협의된 갱신 주기로 최신성을 유지한다.
- **FR-08** (P0) 수급 원문과 AI 생성 대본을 **단일 표준 에피소드 형태**로 변환한다. 같은 콘텐츠는 전 사용자에게 동일하며 변형(버전)은 없다.
- **FR-09** (P0) 변환·생성 시 원문·소스에 없는 사실을 임의로 생성·추가.변형하지 않는다.
- **FR-10** (P0) 발행 전 원문/소스 사실관계를 대조한다. **MVP는 업로드 전 수동 검수로 수행하며, 자동 QA·자동 재생성은 P1이다.**
- **FR-11** (P0) AI 생성용 일반 소스 수집은 저작권·이용약관·수집 정책을 준수하는 적법 범위로 한정한다.
- **FR-12** (P0) 모든 오디오는 적합한 형태로 원저자·출처를 고지하고 필요에 따라 원문 연결 정보를 제공한다.
- **FR-13** (P0) 한 에피소드의 권장 길이는 약 10~15분으로 하되, 콘텐츠의 완결성을 우선하여 분할한다. 분할된 편은 시리즈로 묶어 순서를 유지한다.

### 6.4 편성·추천 (드립)

- **FR-14** (P0) 모든 사용자에게 관심사 기반 콘텐츠를 라이브러리에 자동 적립한다. **무료(라이트) 티어는 하루 2편으로 확정하며**, 유료 티어 편수는 1~2주 시범 운영 후 결정한다.
- **FR-15** (P0) 소비 신호(완청·스킵·저장 등)를 편성·추천 갱신에 반영한다.
- **FR-16** (P0) 이미 라이브러리에 있거나, 재생한 적이 있거나, 한 번 적립된 콘텐츠는 다시 적립하지 않는다. **라이브러리에서 삭제하거나 탐색에서 담기를 해제한 콘텐츠도 경로와 무관하게 드립 대상에서 영구 제외한다.** 영구 제외는 **사용자에게 고지하지 않고** 적용하며, 탐색에서 직접 다시 담는 것은 허용한다.
- **FR-17** (P0) 신규 사용자(신호 부족)는 인기·신규 기반 대체 편성으로 콜드스타트를 처리한다.
- **FR-18** (P1) 주제 고갈을 감지해 인접·심화 주제로 자동 확장한다. 사용자 노출 없는 백그라운드 처리로 한다.
- **FR-19** (P1) 드립 도착을 푸시로 알리고, 알림 수신 여부를 설정할 수 있다.

### 6.5 콘텐츠 소비

- **FR-20** (P0) 라이브러리: 자동 드립·담은 콘텐츠를 **하나의 통합 목록**으로 제공하고, 상태(미청취·완료)·출처(드립)·주제 기준 필터와 삭제를 지원한다. **출처별로 보관함을 분리하지 않는다** — 드립만 모아 보는 것은 필터 축으로 해결한다.
- **FR-21** (P0) 탐색: 추천 피드와 주제 필터로 콘텐츠를 발견하고 담을 수 있다. 담기는 무제한이다.
- **FR-22** (P1) 검색: 키워드로 콘텐츠를 찾을 수 있다.
- **FR-23** (P0) 재생: 모든 콘텐츠는 즉시 재생된다(생성 대기 없음). 재생·일시정지, 구간 이동, 배속 조절을 제공한다.
- **FR-24** (P0) 이어듣기: 마지막 재생 콘텐츠·위치를 앱 재실행 후에도 유지한다. 앱 실행 시 완청하지 않은 가장 최근 콘텐츠를 **미니플레이어로 복원하되 자동 재생하지 않으며**, 사용자가 재생을 시작해야 소리가 난다. 이어듣기 진입점은 미니플레이어 하나로 통일한다.
- **FR-25** (P1) 스크립트 열람(구간 탭 이동 포함)과 수면 타이머를 제공한다.
- **FR-26** (**P1**) 오프라인 저장(유료 전용): 저장한 콘텐츠는 오프라인에서 재생 가능하다. 저장은 앱 내 암호화 저장소에 한정하며(파일 내보내기·외부 접근 불가), 구독 만료 시 저장분 재생을 차단한다.
- **FR-27** (P1) 콘텐츠를 OS 공유 시트로 공유할 수 있다. 수신자용 웹 랜딩은 MVP에서 스토어 링크로 대체한다.

### 6.6 구독·결제

- **FR-28** (P0) 3티어(라이트/데일리/프로) 구독 상태를 관리하고 기능 접근을 분기한다.
- **FR-29** (P0) 무료(라이트) 사용자의 재생을 하루 2편으로 제한한다. 소진 후 재생 시도 시 페이월을 노출한다. 카운트는 04시를 하루 경계로 하며, 같은 날 같은 콘텐츠를 다시 재생해도 중복 계산하지 않는다. 담기는 카운트에 포함하지 않는다. **차감이 발생하는 재생은 시작 전에 남은 횟수와 1회 차감 사실을 고지하고 사용자 확인을 받는다.** 차감이 없는 재생(같은 날 같은 콘텐츠 재청취)과 재생 한도가 없는 티어에는 고지하지 않으며, 한도를 이미 소진한 경우에는 고지 대신 페이월을 노출한다. 확인 시점의 한도 판정은 **서버가 다시 수행한다.**
- **FR-30** (P0) 인앱 결제로 구독을 처리하고, 결제 완료 시 즉시 티어를 반영하며 차단됐던 지점에서 이어 진행한다.
- **FR-31** (P0) 요금제 변경·해지를 제공한다. 해지 시 만료일까지 혜택을 유지한다.

### 6.7 파트너 통제·리포팅

- **FR-32** (P0) 파트너의 콘텐츠 단위 제외 지정·회수 요청을 지원하고, 회수는 전 노출면(라이브러리·탐색·드립)에서 즉시 반영한다. **발행 전 검수는 MVP 범위에서 제외한다**(업로드 즉시 발행 — FR-37).
- **FR-33** (P0) 파트너 콘텐츠는 협의된 범위·기간 내에서만 제공하고, 무단 재배포·다운로드를 방지하는 접근 통제를 적용한다.
- **FR-34** (P1) 재생·완청·**실제 청취 시간**·원문 유입 등 성과 데이터를 집계해 파트너 리포팅과 정산 연동 검증에 사용한다. 집계 단위는 **주간·월간·전체**이며, 순위·리포팅은 직전 확정 구간의 값을 사용한다(예: 5월에는 4월 집계).

### 6.8 공통·시스템

- **FR-35** (P0) 앱 실행 시 온보딩 완료 여부로 진입을 분기하고 버전을 체크한다. 최소 지원 버전 미달 시 강제 업데이트를 안내한다.
- **FR-36** (P0) 네트워크 오류 등 공통 오류 처리와 재시도를 제공한다.

### 6.9 운영 (관리자)

- **FR-37** (P0) 관리자 계정으로 콘텐츠를 업로드한다. **업로드 시점에 즉시 발행 상태가 되며**, 업로드 이전 단계의 상태는 시스템에서 관리하지 않는다. 관리자 권한은 일반 사용자 계정과 동일한 소셜 로그인 위에서 역할로 구분한다.
- **FR-38** (P0) 관리자 페이지에서 주제를 추가·삭제하고 노출 여부를 제어한다. 콘텐츠가 0건인 주제는 관리자가 판단해 숨긴다. 사용자가 특정 주제의 콘텐츠를 모두 소비했더라도 주제를 목록에서 제외하지 않는다.

## 7. 비기능 요구사항

- **재생 즉시성**: 모든 노출 콘텐츠는 사전 변환 완료 상태 — 재생 시 생성 대기 없음. 재생 버튼 탭 후 2초 내 재생 시작(정상 네트워크 기준).
- **콘텐츠 신뢰성(QA)**: 변환·생성 콘텐츠는 원문/소스 사실관계 대조를 통과해야 발행. **MVP는 업로드 전 수동 검수**로 이를 보장하고, 자동 대조·재생성은 P1로 이연한다. 파트너 콘텐츠의 신뢰도가 훼손되지 않아야 한다.
- **저작권·파트너 계약 준수**: 협의된 범위·기간 내 제공, 출처·저자 고지 필수, 무단 재배포·다운로드 방지 접근 통제, 회수 요청 즉시 반영. 원문 수급은 공식 경로만.
- **오디오 품질**: 상용 TTS 기준 오독·발음 오류 없는 수준을 발행 기준으로 하고, 운율(억양·강세) 자연스러움은 자체 TTS 전환의 개선 목표로 둔다. NotebookLM 보다 높은 수준의 음성 품질 제공 목표.
- **개인정보·보안**: 소셜 로그인 기반 인증. 회원 탈퇴 시 라이브러리·관심사·커리어·재생 이력은 즉시 파기하되, **결제 이력·거래 주체 식별 정보·동의 이력은 법령상 보존 대상**이므로 운영 데이터와 **물리적으로 분리된 영역에 5년 보존 후 파기**한다(개인정보보호법 제21조 제3항, 전자상거래법 시행령 제6조의 별도 보존 의무). 마케팅 수신 동의는 동의일로부터 2년마다 재확인한다(정보통신망법 제50조 제8항). **개인정보 유효기간제 폐지(2023.9.15)에 따라 장기 미접속 기반 휴면 전환·파기는 두지 않는다.**
- **비용 구조**: 콘텐츠 원가는 사용자 수와 무관하게 유지(공유 콘텐츠 + 피드 레벨 개인화). 파트너 정산은 구독 매출 % 풀 방식으로 지급 총액이 매출을 넘지 않는 구조. *(구체 비용모델은 라이선스 협의·TTS 원가 실측 후 확정)*
- **안정성**: 네트워크 오류 공통 처리, 최소 지원 버전 강제 업데이트 체계.

## 8. 제약/의존성/리스크

#### 8.1 제약

- **일정**: 소마 4개월 — MVP 2주(8월 말 중간평가) + 성장 12주(9월 초~11월 최종). 자체 TTS는 10월까지 실사용 가능한 성능이 나와야 함.
- **팀 리소스**: 3인 팀(팀장/UI·UX/기술책임) + 멘토진. 범위는 이 리소스로 2주 내  MVP 구현 가능해야 함.
- **콘텐츠 볼륨**: 초기 콘텐츠 풀이 작음 — 검색 빈 결과·탐색 피드 밀도 등 UX가 이를 전제로 설계됨. 단 **온보딩 추천에는 "0건" 상태를 두지 않는다** — 콘텐츠 풀이 없는 주제는 관리자가 노출에서 제외하므로(FR-38) 애초에 선택할 수 없고, 그럼에도 0건이 반환되면 정상 상태가 아니라 데이터 정합성 오류로 다룬다.

#### 8.2 의존성

- **외부 콘텐츠 파트너십**: 콘텐츠 범위·수량·정산 구조·갱신 주기 협의 결과. 특히 저자 권리(오디오 2차적저작물·재배포) 확보 여부. **단, 서비스는 계약과 무관하게 성립하도록 설계한다**(자체 AI 콘텐츠·기타 외부 콘텐츠로 운영 가능, 파이프라인 독립 구축).
- **상용 TTS 엔진**: 초기 오디오 생성 전량 의존. 비용·품질·약관(상업 이용) 확인 필요.
- **스토어 인앱 결제**: 구독 결제 전 과정이 스토어 정책·수수료에 종속.
- **소셜 로그인 제공자**: 카카오·구글·네이버 확정 및 심사 요건.

## 9. 검증 계획

#### 9.1 단위 테스트

- **정책 로직**: 무료 일 2편 재생 카운트(04시 기준 경계·같은 콘텐츠 중복 미계산), 페이월 트리거 조건, **재생 전 고지 분기**(차감 발생=고지 / 같은 날 같은 콘텐츠·무제한 티어=고지 없음 / 한도 소진=페이월), **관심 주제 개수 상한(최소 1개·최대 3개) 서버 검증**, 무료 티어 드립 편수 상한(2편), 결제 완료 시 티어 반영.
- **드립 편성 로직**: 관심사 변경 사항 적용(추가=편성, 해제=중단·미청취 유지), 중복 적립 방지, 콜드스타트 대체 편성, 자동 확장 토글 반영.
- **QA 검수**(MVP는 수동): 변환 대본↔원문 사실관계 대조 체크리스트 이행률. 자동 대조·재생성 트리거 테스트는 P1 도입 시 추가.
- **관리자 기능**: 관리자 권한 검증(비관리자 업로드 차단), 업로드 즉시 발행 상태 확인, 주제 노출 토글 반영.
- **파트너 권한**: 콘텐츠 단위 제외 지정 반영, 회수 시 노출 제외.
- **탈퇴 처리**: 즉시 파기 대상과 보존 대상의 분리 이관, 활성 구독 시 만료 동의 없이는 탈퇴 불가, 보존 만료 5년 후 파기.
- 이외에 각 기능별 단위 테스트

#### 9.2 통합 테스트

- **E2E 핵심 루프**: 온보딩 → (유료) 첫 드립 적립 → 라이브러리 노출 → 즉시 재생 → 완청 신호 → 편성 갱신 확인.
- **무료 사용자 시나리오**: 온보딩(무료) → 탐색 → 재생 전 확인 → 2편 재생 → 3편째 페이월 → (이메일 미등록 시) 이메일 코드 인증 → 결제 → 막힌 지점 복귀·재생 계속.
- **콘텐츠 업로드 E2E**: 관리자 로그인 → 오디오·메타 업로드 → 즉시 발행 → 카탈로그·탐색·드립 편입, 출처 고지 멘트 포함 확인. *(자동 파이프라인 E2E는 P1 도입 시 추가)*
- **파트너 통제 E2E**: 회수 요청 → 라이브러리·탐색·드립에서 즉시 제외 확인.
- **관심사 변경 E2E**: 주제 해제 저장 → 확인 팝업 → 드립 중단·미청취 유지 → 주제 추가 → 편성 재개.
- **재생 연속성**: 앱 재실행 시 미청취 최근 콘텐츠의 미니플레이어 복원과 재생 위치 유지(**자동 재생되지 않을 것**), 스크립트 구간 이동, 수면 타이머 정지.
- **오프라인 시나리오** *(P1 — FR-26 이연)*: 유료 사용자 저장 → 네트워크 차단 상태에서 저장분 재생 → 저장 해제 시 파일 삭제 확인, 구독 만료 시 저장분 재생 차단.
- **시범 운영 = 실사용 통합 검증**: 9월 시범 운영을 소규모 실사용자 대상 통합 검증 단계로 삼고, 성과 지표(10장)와 초기 이슈를 수집한다. 추가로 사용자 지표를 통해 유료 모델 규모와 금액을 설정한다.

## 10. 성공 지표

**사용자 지표**

- 완청률 (15분 내외 규격이 완청에 유리하다는 가설 검증이 필요함 — 25분 콘텐츠 이탈률 58% 벤치마크)
- D1 / D7 / D30 리텐션
- 주간 청취 시간·편수 (관여 청취자 벤치: 주 5~7시간)
- 무료→유료 전환율, 구독 유지율

**콘텐츠·편성 지표**

- 추천 콘텐츠 재생률 (추천 품질 프록시)
- 콘텐츠별 재생 수·재청취·저장 등 반응 지표
- 검수 반려율·재제작 발생률 (제작 품질) — 자동 파이프라인 도입 시 QA 통과율·재생성 발생률로 대체

**파트너 지표** (파트너십 공유·확대 판단 기준)

- 오디오를 통한 원문 유입 수, 파트너 업체 구독·열람 전환
- 재생·완청·실제 청취 시간 데이터의 저자 정산 구조 정합 검증 (정산은 구독 매출 % 풀 배분이므로 재생 점유율 산출이 가능해야 함)
