## 배경

KAN-163(2026-10-09)에서 카드·상세 헤더의 `#태그`는 **표시만**으로 두었다 — "검색 연결은 탐색 검색에 질의어를 넘기는 경로가 아직 없어 미루었다 — 필요하면 별도 티켓". PM(이주호) 요청 2026-10-16: **해시태그로 검색할 수 있게 한다.** 서버는 KAN-218(검색이 `tags`도 매칭, `#` 접두 = 태그 전용 모드)이 맡고, 이 티켓은 **태그 탭 → 검색 실행 경로**와 **검색창에서 `#` 입력**이다.

## 요청 내용

1. **태그 탭 → 검색** — 탐색 인기 대표 카드·콘텐츠 상세 헤더의 `#태그`를 탭하면 **탐색 탭의 검색 화면을 열고 질의 `#태그`로 즉시 검색**한다(디바운스 없이, 키보드 [검색] 제출과 같은 경로). 상세 화면이 다른 탭 스택 위에 있으면 탐색 탭으로 전환한 뒤 검색을 연다 — 지금 없는 "질의어를 넘겨 검색을 여는 진입 경로"(`openSearch(query)` 꼴)를 만든다. 피드 상태(필터·구간·스크롤)는 4.5-1대로 유지.
   - **탐색 타일**(두 칸 격자 — 태그 최대 2개가 길이와 한 줄 메타)은 글자가 작고 카드 탭(재생 팝업)과 겹친다. 타일에서도 탭을 지원할지, 표시만 둘지는 **FE가 정하고 uiux에 적는다.** 지원하면 태그 글자만 별도 Pressable(최소 44), 카드 탭과 분리. Android는 Text가 `pointerEvents`를 무시하니 View(none)로 감싸는 패턴 주의.
2. **검색창 직접 입력** — `#뱅크런`을 치면 그대로 서버에 보낸다(클라이언트 가공 없음 — 4.5 "트림 외 가공하지 않는다"). 클라이언트 검증은 서버와 같다: 트림 뒤 `#` 하나를 뗀 길이가 2자 미만이면 요청하지 않고 "검색어를 입력해주세요" 유지. `#`만 입력도 같다.
3. **최근 검색어** — 태그 탭은 "검색이 사용자 행동으로 이어진 때"라 `#태그` 그대로 저장(4.5-4 규칙 그대로 — 중복은 최신으로, 10건, 로컬).
4. **빈 결과** — "'#뱅크런' 검색 결과가 없어요" 입력 그대로 되비춤 + fallback 칩·인기 목록 종전과 같다.
5. **mock** — 서버 전에는 mock 검색이 `#` 질의를 태그 정확 일치, 일반 질의를 태그 부분 일치까지 보도록 갱신(`CLAUDE.local.md` mock 패턴).
6. **문서** — `spec/uiux/explore-uiux.md`·`content-detail-uiux.md`의 태그 탭 동작("표시만" → 검색 실행), 검색 화면 진입 경로(태그 탭) 추가. `changes/pending/`에 기록.

## 완료 조건

- Given 상세 헤더에 `#뱅크런` / When 탭 / Then 탐색 탭 검색 화면이 열리고 검색창에 `#뱅크런`, 결과가 즉시 로딩된다(디바운스 없음)
- Given 인기 대표 카드의 `#태그` / When 탭 / Then 카드 재생 팝업이 아니라 검색이 열린다
- Given 라이브러리 탭에서 연 상세 화면 / When 태그 탭 / Then 탐색 탭으로 전환되고 검색이 열린다
- Given 검색창에 `#` 또는 `#a` / When 입력 / Then 요청이 나가지 않고 "검색어를 입력해주세요"
- Given 태그 탭으로 검색 / When 검색 초기 화면 재진입 / Then 최근 검색어 맨 앞에 `#뱅크런`
- Given 태그 전용 질의에 결과 없음 / Then "'#뱅크런' 검색 결과가 없어요" + fallback
- Given uiux 문서 2종 / Then 태그 탭 동작이 적혀 있고 "표시만"이 없다
