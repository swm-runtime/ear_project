# [FE] CI의 레거시 OTA 백필 두 단계를 지운다 — 옛 빌드가 사라진 뒤

| 항목 | 값 |
|---|---|
| 대상 | `.github/workflows/eas-update.yml`의 "레거시 백필 발행" 두 단계 |
| 요청 파트 | 프론트엔드 |
| 발행 날짜 | 2026-09-09 |
| 발견 시점 | `platform-runtime-version-divergence`(KAN-33) 완료 — 통일은 끝났고 전환용 임시 단계만 남았다 |
| 근거 문서 | `tickets/frontend/archive/platform-runtime-version-divergence.md` · `frontend/architecture.md` 2.1 |
| 심각도 | **하** — 기능에 해가 없다. 매 머지마다 **아무도 받지 않는 발행이 두 번씩** 도는 낭비다 |
| 상태 | **완료 (2026-09-10)** — 팀원 기기 전환 확인 후 제거 |

## 배경

2026-09-09에 `runtimeVersion`을 `"1"`로 통일하고 Android vc=8 · iOS build 4를 냈다. 그런데
**이미 배포된 옛 빌드는 옛 지문을 embed한 채 남아 있다.**

| 빌드 | embed된 runtimeVersion |
|---|---|
| Android vc=7 | `cc07cb6e497796c40be4778873fb8502e9e1f827` |
| iOS vc=3 | `1.0.0` |

새 빌드가 스토어를 거쳐 깔리기까지 시간이 걸리는데, 그동안 옛 빌드로 테스트하는 사람에게
JS 수정을 못 보내면 안 된다. 그래서 CI가 **옛 지문 둘로도 각각 발행**하게 해 뒀다. 발행이
세 번 돈다.

## 요청 내용

**팀원 기기가 전부 새 빌드로 올라간 것을 확인한 뒤**, `eas-update.yml`에서 아래를 함께 지운다.

1. `레거시 백필 발행 (Android vc=7 지문)` 단계 전체
2. `레거시 백필 발행 (iOS vc=3 지문)` 단계 전체
3. 워크플로 헤더의 "발행은 세 번 한다" 주석을 한 번으로 되돌린다

## 지우기 전에 확인할 것 — 이걸 안 하면 조용히 끊긴다

**지운 순간 옛 빌드를 쓰는 사람은 OTA를 못 받는다.** 그리고 그 실패는 **에러가 아니라 침묵**이라
당사자도 모른다(2026-09-08·09에 같은 함정을 두 번 밟았다).

- 팀원 3인이 각자 **설정 › 정보 › 버전**을 확인한다. 새 빌드면 괄호 값이 새 발행의 해시로 바뀐다
- Play Console·App Store Connect에서 옛 버전 활성 사용자 수가 0인지 본다
- 확인되면 지우고, 지운 뒤 첫 머지에서 발행이 **한 건만** 도는지 로그로 확인한다

## 완료 조건

- Given `frontend/` 변경을 머지한다 / When CI 로그를 본다 / Then 발행이 **한 건**만 돈다(레거시 백필 없음)
- Given 그 발행 / When 결과를 본다 / Then `Platform: android, ios`로 한 번에 양쪽에 닿는다
- Given 팀원 기기 / When 그 발행 뒤 앱을 두 번 재시작한다 / Then 세 명 모두 버전 괄호 값이 새 해시로 바뀐다
- Given `eas-update.yml` / When 파일을 연다 / Then `LEGACY_RUNTIME_VERSION` 이 남아 있지 않다

### 반영 내용

`eas-update.yml`에서 아래를 함께 지웠다. 파일이 130행 → 91행이 됐다.

1. `레거시 백필 발행 (Android vc=7 지문)` 단계 전체
2. `레거시 백필 발행 (iOS vc=3 지문)` 단계 전체
3. 두 단계에 딸린 `LEGACY_RUNTIME_VERSION` env 둘, 그리고 블록 위의 "레거시 백필" 설명 주석
4. 헤더의 "발행은 세 번 한다" 주석 → "발행은 한 번 한다 — android·ios 양쪽에 한꺼번에 닿는다"

`app.json`을 임시로 고쳤다가 `git checkout -- app.json`으로 되돌리던 두 단계가 사라져,
워크플로가 체크아웃을 변조하지 않는다.

### 완료 조건 확인

| 완료 조건 | 결과 |
|---|---|
| `eas-update.yml`에 `LEGACY_RUNTIME_VERSION`이 남아 있지 않다 | **충족** — `grep`으로 확인, "레거시"·"세 번" 모두 0건 |
| 발행이 한 건만 돈다 | **구조상 충족, 로그 확인은 머지 후** — YAML 파싱 결과 발행 단계가 `OTA 발행` 하나뿐이다 |
| 그 발행이 `Platform: android, ios`로 한 번에 닿는다 | **구조상 충족** — 남은 단계에 `--platform` 플래그가 없어 양쪽으로 나간다 |
| 팀원 기기 세 대의 버전 괄호 값이 새 해시로 바뀐다 | **머지 후 확인 대상** — 이 PR이 머지돼 발행이 돌아야 판정 가능하다 |

**뒤 두 조건은 머지 전에 판정할 수 없다**(발행이 돌아야 로그와 기기가 생긴다). 구조는 확인했고
머지 직후 CI 로그에서 발행이 한 건인지, 팀원 기기가 새 해시를 받는지 한 번 보면 닫힌다.
그 확인만 남기고 `archive/`로 옮긴다 — 코드에서 지울 것은 남아 있지 않다.
