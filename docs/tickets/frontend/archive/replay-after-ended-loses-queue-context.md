## 요지 (Jira 본문용)

- 탐색에서 재생한 편을 끝까지 들은 뒤 완료 화면의 ▶(다시 듣기)를 누르면, 재생 목록이 탐색 목록에서 라이브러리 목록으로 바뀐다(손잡이 글자도 "재생 목록"으로).
- 개발계(운영 미배포) 빌드에서 확인됐다.
- 원인: 완료 상태 ▶가 재생 게이트에 재생 목록 맥락(`queue`)을 넘기지 않는다. 게이트는 맥락이 없으면 라이브러리 맥락으로 덮어쓴다.
- 할 일: 같은 편 다시 듣기는 지금 맥락을 그대로 넘긴다. 결제 뒤 다시 틀기 경로도 같이 고친다.
- 상세 재현·원인·완료 조건은 원본 문서.

## 재현

1. 탐색 인기(주간)에서 편 하나를 재생한다.
2. 끝까지 시크해 완료 상태로 만든다.
3. ▶를 누르고 재생 목록을 연다.
4. 기대: 손잡이·헤더가 "주간 인기 콘텐츠"이고 그 목록 그대로다. 실제: "재생 목록"으로 바뀌고 라이브러리 첫 페이지가 뜬다(지금 편은 맨 위에 끼워진다).

2단 한 줄 재생 바의 ▶도 같은 핸들러다(`PlayerScreen.tsx:1841·2253`).

## 원인 (코드 확인 — dev `9f024ecd`)

1. `handlePlayPausePress`(`usePlayerScreen.ts:274`)는 `session.state === 'ended'`면 `playGate.requestPlay({ contentId, isCountedToday: true, restartFromBeginning: true, meta }, 'player')`를 부른다(`:279`). `queue`가 없다.
2. 게이트의 `applyQueueContext`(`usePlayGate.ts:48-49`)가 `target.queue ?? { kind: 'library' }`로 스토어 맥락을 덮는다(즉시 시작 `:110`, 발급 먼저 `:187` 모두).
3. 같은 계열(코드 정독, 기기 미확인): 플레이어에서 재생이 막혀 결제 안내로 갈 때 잡아 두는 "결제 뒤 다시 틀 대상"(`usePlayerScreen.ts:154·159-162` — `{ contentId, isCountedToday: false }`)에도 `queue`가 없다. 결제 뒤 다시 틀면 라이브러리 맥락이 된다.

## 무엇을 한다

1. 완료 상태 ▶는 지금 맥락(`usePlaybackStore.getState().queueContext`)을 `queue`로 넘긴다 — `playQueueItem`과 같은 방식.
2. 결제 뒤 다시 틀 대상에도 그 시점 맥락을 실어 둔다.
3. 게이트의 기본값(맥락이 없으면 라이브러리로 덮는다)이 진입점마다 맞는지 본다. KAN-251(2026-10-23 완료)은 미니플레이어 진입을 라이브러리 맥락 그대로 두기로 정했다 — 그건 새로 여는 진입이고, 이 티켓은 같은 세션 안의 다시 듣기라 맥락을 이어 가는 쪽이 4.2-1에 맞다.

## 완료 조건

- Given 탐색 맥락에서 끝까지 들었다 / When 완료 화면 ▶를 누른다 / Then 재생 목록 손잡이·헤더가 그 출처이고 목록이 그대로다
- Given 2단 한 줄 재생 바 / When 완료 상태에서 ▶를 누른다 / Then 위와 같다
- Given 라이브러리 맥락에서 끝까지 들었다 / When ▶를 누른다 / Then 라이브러리 맥락 그대로다(회귀 없음)
- Given 탐색 맥락에서 듣다 플레이어에서 결제 안내로 막혔다 / When 결제 뒤 다시 튼다 / Then 탐색 맥락이다
