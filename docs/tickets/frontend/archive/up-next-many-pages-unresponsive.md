## 요지 (Jira 본문용)

- 재생 목록 아래 "다음에 들어볼 만한"을 끝까지 내려 추천을 계속 이어 받으면 플레이어가 점점 느려진다. 열댓 편쯤에서는 잠깐 기다리면 반응이 돌아오지만, 그 이상 붙이면 플레이어 전체가 아예 멈춘다.
- 개발계(운영 미배포) 빌드에서 확인됐다. 끝없는 추천(#1954, 2026-10-23)과 함께 들어온 동작이다.
- 의심 원인(코드 정독, 미확정): 재생 위치가 0.5초마다 갱신될 때 플레이어 화면 전체가 다시 그려지고, 그때 재생 목록의 모든 줄(추천 포함)을 다시 그린다. 줄 컴포넌트에 메모가 없고 줄마다 애니메이션 보간을 새로 만들어, 줄 수에 비례해 JS 스레드를 잡는다.
- 다음 장 불러오기 판정도 매 렌더 다시 돌아, 바닥 근처에서는 손대지 않아도 장이 계속 붙을 수 있다(목록이 스스로 길어지는지 확인).
- 할 일: 재생 위치 갱신이 목록을 다시 그리지 않게 하고, 추천 장 수에 상한을 두거나 목록을 가상화한다.
- 상세 재현·원인 후보·완료 조건은 원본 문서.

## 재현

1. 플레이어에서 재생 목록을 연다(재생 중).
2. 아래 "다음에 들어볼 만한" 블록을 끝까지 내려 다음 장을 계속 이어 받는다.
3. 기대: 몇 편을 붙여도 스크롤·탭·스와이프가 그대로 반응한다. 실제: 열댓 편쯤에서는 터치가 잠깐 늦게 반응하고, 그 이상 붙이면 플레이어 전체(재생 목록·컨트롤)가 아예 멈춘다.

원인을 가르려면 함께 확인한다.

- 일시정지 상태에서도 같은지(아래 원인 1이면 일시정지 중에는 덜하다 — 위치 갱신이 멈춘다)
- 바닥에 손을 떼고 가만히 있어도 추천이 계속 붙어 목록이 길어지는지(아래 원인 2)
- Android·iOS 차이

## 의심 원인 (코드 정독 — dev `9f024ecd`, 기기 재현 전이라 미확정)

1. **재생 위치 갱신마다 목록 전체를 다시 그린다 (확신도 높음 — 줄 수에 비례해 느려지다 멈추는 증상과 맞는다).** 플레이어 화면은 세션 전체를 구독하고(`usePlayerScreen.ts:55` `usePlaybackStore((s) => s.session)`), 재생 중에는 위치가 0.5초마다 바뀐다(`playback.service.ts:439`, `PLAYBACK_STATUS_UPDATE_INTERVAL_MS = 500`). 그때마다 `PlayerScreen` → `PlayerQueuePanel`(`:616`, 메모 없음) → 모든 `QueueRow`(`:260`, 메모 없음)가 다시 그려진다. 줄마다 렌더할 때 `swipeX.interpolate(...)` 등 보간 노드를 새로 만들고(`:430~`), 추천 줄에는 인라인 콜백을 넘긴다(`:965` 등). 모션 중에는 `holdPositionUpdates`로 막지만, 시트가 앉은 뒤에는 막지 않는다. 추천이 끝없이 붙으면서 줄 수가 늘어 이 비용이 커진다.
2. **다음 장 판정이 매 렌더 다시 돌아 장이 스스로 붙는다 (확신도 중간).** `fetchMore`는 렌더마다 새 함수다(`useUpNextQuery.ts:80`). 그래서 `onEndReached`(`PlayerScreen.tsx:2436`) → `onUpNextEnd`(`PlayerQueuePanel.tsx:978`) → `checkUpNextEnd`(`useCallback`, `:980`)가 렌더마다 바뀌고, `useEffect([checkUpNextEnd, upNextCount])`(`:987-989`)가 **렌더마다** 바닥 판정을 다시 한다. 0.5초 렌더와 겹치면, 바닥 근처(`UP_NEXT_PREFETCH_ROWS = 4`줄 안쪽)에 있는 한 계속 다음 장을 부른다. 한 장이 거른 뒤 네 줄보다 적게 붙으면(이미 본 편 제외) 판정이 계속 참이라 연달아 이어 받는다. 장이 붙는 직후에는 콘텐츠 높이가 아직 옛 값이라 한 번 더 부를 수도 있다.
3. **추천 줄은 가상화·상한이 없다.** 위 목록은 모션 중에만 창(`previewCount`)을 쓰고, 추천 섹션은 받은 줄을 전부 그린다(`:945` `upNext.items.map`). 장 수 상한도 없다(`getNextPageParam`은 빈 장이 와야 끝난다).

## 무엇을 한다

1. **재생 위치 갱신이 재생 목록을 다시 그리지 않게 한다.** 예: `PlayerQueuePanel`·`QueueRow`를 `memo`로 감싸고 넘기는 콜백·배열을 안정화한다(인라인 콜백 제거, `items`·`upNext` 메모) / 위치를 쓰는 컴포넌트만 위치를 구독하게 나눈다. 보간 노드는 `useMemo`로 한 번만 만든다.
2. **다음 장 판정은 스크롤·크기 변화 때만 한다.** `fetchMore`를 안정된 함수로 바꾸거나(`useCallback`/ref), 판정 effect의 의존을 `upNextCount`로 줄인다. 손대지 않으면 장이 붙지 않아야 한다.
3. **추천 장 수에 상한을 두거나 섹션을 가상화한다.** 예: 일정 편수(예: 50)에서 멈추고 "더 보기"로 잇기, 또는 목록 전체를 `FlatList`류로.
4. 고친 뒤 원래 의심이던 "위 목록 줄을 지우면 추천이 처음부터 다시 로딩되고 지운 편이 추천에 섞인다"도 확인한다(그 증상은 이 문제에 가려 재현하지 못했다 — 제외 목록이 쿼리 키에 들어가 키가 바뀐다, `useUpNextQuery.ts:9-10`).

## 완료 조건

- Given 재생 중 재생 목록 / When 추천을 50편 넘게 이어 받는다(또는 상한까지) / Then 스크롤·탭·스와이프가 끊김 없이 반응한다
- Given 바닥 근처에 손을 떼고 30초 둔다 / Then 추천 장이 스스로 더 붙지 않는다
- Given 추천을 여러 장 받아 둔 상태 / When 위 목록 줄 하나를 스와이프로 지운다 / Then 추천 블록이 처음부터 다시 로딩되지 않고, 지운 편이 추천에 나타나지 않는다(또는 의도된 동작으로 문서에 적는다)
