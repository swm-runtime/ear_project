## 증상 (2026-10-23 박준현, Android dev 빌드)

라이브러리에서 재생을 시작한 뒤(라이브러리 맥락) 재생 목록 아래 "다음에 들어볼 만한"에서 편을 **직접 탭하거나**, 자동 재생이 추천 편으로 넘어가도 **목록이 늘지 않는다.** 라이브러리 편(이 계정은 2편)은 그대로이고 **맨 위 한 줄만 새 편으로 바뀐다** — 목록이 3줄에서 더 커지지 않는다. 앞서 들은 추천 편은 목록에서 사라진다. 자동 재생을 끈 상태에서 직접 골라도 같다.

## 원인 — 문서대로 구현된 결과다(버그가 아니라 설계 공백)

- `player.md` 4.2-2: "틀면 그 편이 **현재 맥락 스냅샷의 지금 듣는 편 뒤에 더해진다** … **라이브러리 맥락은 목록이 서버 것이라 더하지 않고**, 지금 듣는 편이 첫 페이지에 없으면 **목록 맨 위에 세운다**". 4.2-4 자동 재생도 같다.
- 코드: `appendToSnapshot` 이 `context.kind !== 'explore'` 면 맥락을 그대로 돌려준다 → 라이브러리 맥락의 패널 목록은 `라이브러리 첫 페이지 + 지금 듣는 편(없으면 맨 위)` 뿐이다(`PlayerScreen.tsx` `libraryShownItems`). 그래서 추천 편을 틀 때마다 맨 위 "지금 듣는 줄"만 교체되고, 지나간 추천 편은 어디에도 남지 않는다.
- 탐색 맥락은 스냅샷(로컬 목록)이라 지금 듣는 편 뒤에 쌓인다 — 정상.

PM 의도("재생목록 무한으로, 유튜브 뮤직처럼" — 2026-10-23)와 어긋난다: 유튜브 뮤직은 추천으로 넘어간 편이 목록에 이어 붙고 지나간 편이 위에 남는다.

## 결정 항목 (PM)

라이브러리 맥락에서 틀린 추천 편(직접 탭·자동 재생)을 **이번 재생 세션 동안 로컬 꼬리로 남긴다** — 서버 라이브러리·순서는 건드리지 않는다. 제안:

- 패널 목록 = `라이브러리 첫 페이지` + **꼬리**(이번 세션에 추천에서 틀어 온 편들, 튼 순서). 지금 듣는 편이 꼬리에 있으면 그 줄이 "재생 중". 라이브러리 첫 페이지에 없는 편을 맨 위에 세우는 종전 규칙(복원·푸시로 들어온 지금 편)은 유지.
- 꼬리 줄은 담기 버튼(라이브러리에 없으니) · 왼쪽 밀어 빼기(로컬) · 손잡이 끌기 없음(서버 순서와 섞지 않는다).
- 자동 재생 다음 편 = 지금 편 뒤의 첫 안 들은 편(꼬리 포함) → 없으면 추천(종전).
- 꼬리는 맥락이 바뀌면(라이브러리·탐색에서 새로 재생 시작) 비운다. 콜드 스타트 복원엔 없다.

## 완료 조건

- Given 라이브러리 맥락(라이브러리 2편) / When 추천 줄 A 를 탭하고, 이어서 B 를 탭한다 / Then 목록에 라이브러리 2편 + A + B 가 남고 B 가 "재생 중"이다
- Given 같은 상태, 자동 재생 켜짐 / When B 가 끝난다 / Then 다음 추천 편 C 가 B 뒤에 붙어 재생되고 A·B 는 남아 있다
- Given 자동 재생 꺼짐 / When 추천 줄을 직접 탭한다 / Then 위와 같이 목록에 더해진다(자동 재생 스위치와 무관)
- Given 꼬리가 있는 상태 / When 라이브러리 화면에서 다른 편을 새로 재생한다 / Then 꼬리가 비워진다
- Given 라이브러리 맥락 / Then 서버 라이브러리·순서(`sort=queue`)는 바뀌지 않는다
