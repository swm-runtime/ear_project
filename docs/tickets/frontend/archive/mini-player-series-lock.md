## 왜

개발계 실기기 확인(2026-10-30, 박준현)에서 발견했다. 프로모션(Pro)으로 시리즈 4편 이후를 듣던 사용자가 무료로 돌아간 뒤:

1. 듣던 중에는 이미 받은 오디오 URL로 그 편이 계속 재생된다 — **정상으로 둔다**(이미 내준 URL은 회수하지 않는다. 재생 한도와 같다).
2. 앱을 나갔다 다시 들어오면 미니플레이어에 그 잠긴 편이 **평범한 ▶로** 떠 있고, 눌러도 재생되지 않는다. 서버는 `POST /contents/:id/audio-urls`를 403 `SERIES_EPISODE_LOCKED`로 막는다(개발계 로그 확인). 앱이 복원 응답의 `content.is_locked`를 읽지 않아 잠금 표시도 시트도 없다 — 고장처럼 보인다.

미니플레이어를 없애지 않는다 — 방금까지 듣던 편이라 "이어 듣고 싶은데 막힌" 순간이고, **구독을 권하기 가장 좋은 자리**다(결정 2026-10-30). 라이브러리에 담긴 편도 그대로 둔다.

## 무엇을 한다

- **복원 응답의 `content.is_locked`를 읽는다**(`/users/me/library-items/resume` — 옛 서버·필드 없음은 `false`). 미니플레이어 상태에 `isLocked`로 싣는다.
- **잠긴 편이면 미니플레이어 ▶를 자물쇠로 그린다** — 시리즈 머리 [재생]과 같은 규칙(`shared/ui/LockIcon`). 누르기 전에 잠긴 줄 보이게 한다.
- **누르면 발급 없이 잠금 시트(PW2)를 띄운다** — 목록의 "미리 막기"(`PlayGateTarget.isLocked`)와 같다. 소리 · 확인 팝업 · 플레이어 없음, 403도 만들지 않는다. 미니플레이어 본체를 눌러 플레이어를 여는 경로도 같다.
- **결제 뒤에는 그 편을 바로 이어 재생한다** — 기존 "결제 뒤 잠금 힌트를 떼고 다시 요청" 흐름 그대로(`usePlayGate` 결제 후 재요청).
- **듣는 도중 잠긴 경우**(위 1번): 받은 URL은 끝까지 둔다. 그다음 URL 갱신·재생 시작에서 403 `SERIES_EPISODE_LOCKED`가 오면 플레이어를 닫고 같은 잠금 시트로 잇는다(KAN-294에서 넣은 처리가 미니플레이어 상태에서도 동작하는지 확인 · 안 되면 맞춘다).
- **자동재생에서 다음 줄이 잠긴 편이면 건너뛰지 않고 잠금 시트(PW2)를 띄운다**(결정 2026-10-30 박준현). 지금은 조용히 멈춘다 — 라이브러리 · 탐색 목록 자동재생이 대상이고, 추천 목록이 잠긴 편을 빼고 만드는 것은 그대로다. 결제하면 그 편을 이어서 재생한다. 화면 밖(백그라운드)에서 끝났으면 앱이 앞으로 올 때 띄우거나 미니플레이어 자물쇠 ▶로 남긴다 — FE 판단.
- 분석: `paywall_view` `reason = series_locked` 그대로(진입 위치를 따로 가르고 싶으면 `analytics.md`부터).

## 범위 밖

- 서버 판정·필드(KAN-290 — 변경 없음).
- 이미 내준 오디오 URL 회수.

## 완료 조건

- Given 잠긴 시리즈 편을 마지막으로 들은 무료 사용자 / When 앱을 다시 연다 / Then 미니플레이어에 그 편이 자물쇠 ▶로 보인다
- Given 위 상태 / When 미니플레이어 ▶(또는 본체)를 누른다 / Then 오디오 URL 요청 없이 잠금 시트(PW2)가 뜨고 소리가 나지 않는다
- Given 잠금 시트에서 Pro 결제를 마쳤다 / Then 그 편이 이어서 재생된다
- Given 잠긴 편을 이미 받은 URL로 듣는 중 / When 다음 URL 갱신이 403 `SERIES_EPISODE_LOCKED` / Then 플레이어를 닫고 잠금 시트가 뜬다
- Given 자동재생 중(라이브러리 · 탐색 목록) 다음 줄이 잠긴 편 / When 지금 편이 끝난다 / Then 건너뛰지 않고 잠금 시트가 뜬다 · 결제하면 그 편이 재생된다
- Given 유료 요금제(데일리 · 프로) 사용자 또는 잠기지 않은 편 / Then 미니플레이어는 지금과 같다

## 처리 기록

- 2026-10-30 발행(마크다운 + Jira KAN-302, KAN-294와 연결).
- 2026-10-30 자동재생 항목 추가(다음 줄이 잠긴 편이면 잠금 시트 — Jira KAN-302 댓글). 데일리도 4편 이후가 열린다(KAN-290 #2189).
- 2026-10-30 반영(반영 날짜 2026-10-30 — PR 아래 커밋). FE 판단 — 화면 밖에서 끝난 자동 재생은 **앱이 앞으로 올 때 시트**를 띄운다(미니플레이어엔 끝난 편이 그대로 남는다 — 잠긴 편으로 바꿔 끼우지 않았다: 그 편은 아직 발급 전이라 세션이 없다).
  - 복원 응답 `content.is_locked` → `ResumeContent.isLocked`(없으면 false) → 미니플레이어 자물쇠 ▶(`LockIcon`, 낭독 "재생, 잠김"). ▶·본체 탭·끌어올리기 모두 게이트의 미리 막기(`isLocked`)로 잠금 시트 — 발급·플레이어 없음, 잠긴 편은 iOS 줌 전환도 걸지 않는다. 결제 뒤 재요청은 기존 흐름 그대로.
  - **듣는 도중 잠긴 경우의 구멍을 메웠다** — URL 갱신·재생 시작 403 `SERIES_EPISODE_LOCKED`(한도 403도)가 **플레이어가 닫힌 상태**에서 오면 종전엔 세션이 `blocked`로 바뀌며 미니플레이어만 사라지고 아무 시트도 뜨지 않았다(차단 처리는 플레이어 화면에만 있었다). 새 호스트 `useLockedPlaybackHost`(MainNavigator에 하나)가 플레이어가 안 떠 있을 때 같은 갈래(잠금 시트 · 페이월 · 한도 안내)로 잇는다.
  - 자동 재생: 다음 줄이 잠긴 편이면 서비스가 `lockedNext`(끝난 편 · 잠긴 줄 · 목록 맥락) 기록을 남기고, 플레이어가 떠 있으면 플레이어 화면이 닫고 시트, 아니면 호스트가 시트를 띄운다(앱이 앞에 있을 때만). 그사이 다른 편을 틀면 기록을 지운다. `paywall_view` 진입은 `player`, 미니플레이어 상태의 403은 `miniplayer` — `reason = series_locked` 그대로.
