## 문제

재생 시작 게이트는 **서버에 묻기 전에** 확인 팝업을 띄울지 정한다 — 잔여 횟수가 1 이상이고 오늘 아직 듣지 않은 콘텐츠면 띄운다(`usePlayGate.requestPlay`). 목록에서 고른 재생은 목록에 있던 콘텐츠라 문제가 없다.

푸시 딥링크는 **아무것도 모르는 채로** 들어온다. `isCountedToday` 를 알 수 없어 "방금 도착했으니 안 들었다"(false)로 넘기고, 그 콘텐츠가 아직 있는지도 모른다. 그래서

1. 없는·회수된 콘텐츠에도 "오늘 N회 남았어요 / 재생하면 1회가 차감돼요"가 먼저 뜨고
2. [재생하기]를 누른 뒤에야 발급이 404/403 으로 돌아와 "콘텐츠를 찾을 수 없어요"가 뜬다.

횟수는 차감되지 않는다(차감은 `POST /play`, 발급 `audio-urls` 는 차감 없음). 그래도 동의를 받아 놓고 거절하는 순서다.

같은 뿌리의 문제가 하나 더 있다 — **오늘 이미 들은 콘텐츠**의 알림이면 차감이 없는데도 팝업이 뜬다(힌트를 false 로 고정해서).

## 요청

푸시 진입(`openAfterIssue`)에 한해 순서를 바꾼다: **발급 → (있으면) 확인 팝업 → 재생.**

1. 재생 서비스의 시작을 **발급**과 **재생 시작**으로 나눈다. 푸시 진입은 `autoplay` 없이 발급만 먼저 한다 — 발급은 차감하지 않으므로 팝업보다 앞서도 규칙(동의 없이 차감하지 않는다)을 어기지 않는다.
2. 발급이 404/403(회수) 이면 팝업 없이 곧바로 라이브러리 + 토스트(종전 폴백 그대로).
3. 발급이 성공하면 그때 팝업 여부를 정한다. 발급 응답에 "오늘 이미 재생했는가"에 해당하는 값이 있으면 그것을 쓰고(없으면 BE 에 요청 — `is_counted_today`), 차감이 없는 재생이면 팝업 없이 연다.
4. 팝업에서 [취소]하면 세션을 내린다(발급만 받고 재생하지 않은 세션이 미니플레이어에 남지 않게).
5. 목록·탐색·미니플레이어 진입은 **바꾸지 않는다** — 누르는 즉시 팝업·플레이어가 떠야 한다.
6. 문서: `paywall.md` 4.2 에 "푸시 딥링크는 발급 뒤에 팝업을 정한다"를, `notification.md` 4.4 에 순서를 적는다(`changes/pending/`).

## 완료 조건

- Given 없는(또는 회수된) 콘텐츠의 알림 / When 탭한다 / Then 확인 팝업 없이 라이브러리 + "콘텐츠를 찾을 수 없어요"가 뜬다
- Given 오늘 아직 듣지 않은 콘텐츠의 알림 · 잔여 1회 이상 / When 탭한다 / Then 확인 팝업이 뜨고 [재생하기]에 플레이어가 열린다
- Given 오늘 이미 들은 콘텐츠의 알림 / When 탭한다 / Then 팝업 없이 플레이어가 열린다
- Given 확인 팝업에서 [취소] / When 닫힌다 / Then 차감이 없고 미니플레이어에 그 콘텐츠가 남지 않는다
- Given 라이브러리·탐색에서 고른 재생 / When 누른다 / Then 종전과 같이 즉시 팝업 또는 플레이어가 뜬다

  - 재생 서비스에 `playWhenReady()`를 더해 시작을 **발급**(`autoplay: false`)과 **재생** 두 걸음으로 나눴다. 차감은 종전대로 소리가 난 시점 한 번이다.

  - 팝업 판단 값은 렌더 때가 아니라 **판단 시점의 store** 에서 읽는다 — 지연 경로는 발급이 끝난 뒤에 판단하므로 그 사이의 변화를 놓치지 않는다.
