# [FE] 새 콘텐츠 도착 배너가 사용자가 담은 항목까지 센다

| 항목 | 값 |
|---|---|
| 대상 | `frontend/src/features/library/hooks/useLibraryScreen.ts` (98~108행 — `newArrivalCount` 계산) |
| 요청 파트 | 프론트엔드 |
| 발견 시점 | 2026-08-08 탐색 통합 테스트 (`integration/explore`, 실서버 전환) — 탐색 재생 후 라이브러리로 돌아왔을 때 |
| 근거 문서 | `features/library.md` 4.6(**개정 2026-08-08** — 배너가 알리는 사건은 드립 도착 하나다) · `spec/api/library-api.md` 4.1 "새 콘텐츠 도착 배너"(**개정 2026-08-08** — 비교 대상·기준값 규칙) |
| 심각도 | **중** — 목록·재생·적립은 정상이다. 다만 사용자가 방금 스스로 한 조작을 "도착했어요"로 되돌려 알린다 |
| 상태 | **완료(2026-08-08)** — FE 반영 + mock 확인(아래 기록) |

> **처리 기록 (2026-08-08, FE)**
> ① `library.new-arrival.ts` 신설 — `evaluateDripArrivals()` 순수 함수: `source = drip`만 센다 / 기준값은 드립의 최대 `added_at` / 드립 0건 조회는 기준값 미갱신 / 첫 관측은 기록만 / 기준값 단조 증가(옛 드립만 보이는 조회가 기준값을 되돌리지 않게)
> ② `useLibraryScreen`의 판정 effect를 위 함수 호출로 교체, ref를 `dripBaselineRef`로 개명
> ③ 티켓 외 연쇄 수정 — 기존 `resetArrivalTracking`이 필터 변경 시 기준값을 null로 버려 완료 조건 5(필터 중 도착분 반영)를 깨는 상태였다. 배너 표시만 접고 기준값은 유지하도록 변경(`resetArrivalBanner`)
> ④ 배너 우선순위·탭 동작·카피 무변경. API·타입 변경 없음
> mock에서 확인: 라이브러리 열람 → 탐색 재생(자동 적립)·담기 → 복귀 시 배너 없음(수정 전엔 mock에서도 떴을 경로). 새 드립 도착 시 배너 N 검증은 mock에 드립 유입 흐름이 없어 다음 실서버 통합 테스트에서 확인한다.

> **문서는 이미 고쳐져 있다**(2026-08-08). 이 티켓은 **코드를 그 규칙에 맞추는 일**이다. 서버 계약은 바뀌지 않았다 — 판정 재료인 `source`는 목록 응답에 원래 있다.

## 증상

탐색에서 콘텐츠를 재생하면 라이브러리에 자동 적립되는데(`explore.md` 4.4, `source = save`), **그 직후 라이브러리로 돌아오면 상단에 "새 콘텐츠 1개 도착" 배너가 뜬다.**

드립이 온 것이 아니라 **사용자가 방금 자기 손으로 담은 그 한 건**을 두고 도착을 알린다.

`features/library.md` 4.6이 정하는 사건은 드립 도착 하나다.

> 새로 **도착한 드립**이 있으면 상단에 "새 콘텐츠 N개 도착" 배너를 노출한다

## 재현 절차

1. 실서버로 전환하고(`EXPO_PUBLIC_LIBRARY_API=real` + `EXPO_PUBLIC_EXPLORE_API=real`) 온보딩까지 마친 계정으로 로그인한다.
2. 라이브러리 탭에 진입해 목록을 한 번 본다(기준값이 기록된다).
3. 탐색 탭으로 이동해 **라이브러리에 없는** 콘텐츠의 행을 탭하고 [재생하기]를 누른다.
4. 뒤로 나와 라이브러리 탭으로 돌아온다.
5. → 상단에 **"새 콘텐츠 1개 도착"** 배너가 뜬다.

담기(더보기 시트 > [라이브러리에 담기])로도 같다. 2026-08-08 테스트에서는 4번 경로로 확인했다.

## 원인

```ts
/* ── "새 콘텐츠 N개 도착" — 서버가 아니라 클라이언트가 직전 조회와 비교한다(library-api.md 4.1) ── */
useEffect(() => {
  const firstPage = pages?.[0];
  const top = firstPage?.items[0]?.addedAt ?? null;
  if (top === null || !firstPage) return;
  const prev = lastTopAddedAtRef.current;
  if (prev !== null && top > prev) {
    setNewArrivalCount(firstPage.items.filter((item) => item.addedAt > prev).length);
  }
  lastTopAddedAtRef.current = top;
}, [pages]);
```

판정 재료가 **"최상단 `added_at`이 직전에 본 것보다 새로운가"** 하나뿐이라 **그 항목이 어디서 왔는지가 들어 있지 않다.** 드립이든 담기든 온보딩 적립이든 전부 배너가 된다.

**코드가 잘못 짠 것이 아니라 문서를 정확히 따른 결과다.** 개정 전 `library-api.md` 4.1이 판정 방식을 "최상단 `added_at` 비교"로만 고정해 두었고, 그 방식으로는 `library.md` 4.6이 정한 "드립"을 가려낼 수 없었다. **어긋난 것은 코드와 문서가 아니라 두 문서 사이였고, 그쪽은 2026-08-08에 닫았다.**

## 고쳐야 할 것

개정된 `library-api.md` 4.1의 표가 규칙이다.

| 항목 | 규칙 |
|---|---|
| 기준값 | 직전에 노출한 목록에서 `source = 'drip'`인 항목의 **최대 `added_at`** |
| 배너 수 | 재조회 결과 중 `source = 'drip'`이면서 `added_at`이 기준값보다 큰 항목 수 |
| 기준값이 없을 때 | 배너를 띄우지 않고 기준값만 기록한다 |

### 1. 드립만 센다

`items`를 `source === 'drip'`으로 거른 뒤 비교한다. `source`는 목록 응답에 이미 있다(`library-api.md` 4.1 응답 필드표) — **API 변경도, 새 필드도 필요 없다.**

- **`save`·`onboarding`은 제외한다.** `source_filter`가 `save`를 `save + onboarding`으로 묶는 것과는 다른 판정이다 — 저쪽은 "내가 담은 것"을 보여주는 필터이고, 이쪽은 "이어가 보내준 것"이 새로 왔는지다.

### 2. 최상단이 아니라 드립의 최대값과 비교한다

`items[0]`은 정렬이 `added_at` 내림차순일 때만 최신이다. `sort`가 다르거나 사용자가 방금 담은 항목이 맨 위에 오면 최상단은 드립이 아니다. **거른 목록의 `added_at` 최대값**을 기준값으로 쓴다.

### 3. 드립이 보이지 않는 조회에서는 기준값을 갱신하지 않는다

`source_filter = save`이거나 주제 필터로 드립이 전부 걸러지면 그 조회에는 드립이 0건이다. 이때 기준값을 `null`이나 현재값으로 덮어쓰면 **필터를 푸는 순간 그동안 도착한 드립을 놓치거나, 반대로 전부 새 것으로 세어 버린다.** 드립이 0건인 조회는 기준값을 건드리지 않고 지나간다.

### 4. 배너 자체의 동작은 그대로 둔다

우선순위(`오프라인 > 드립 준비 중 > 새 콘텐츠 도착`)와 탭 시 필터를 유지한 채 목록만 갱신하는 규칙(`library-uiux.md` 4.1)은 바뀌지 않았다. **이 티켓은 세는 대상만 좁힌다.**

## 함께 확인할 것

- **mock에서는 재현되지 않는다.** mock 라이브러리에 드립·담기가 섞여 들어오는 흐름이 없으면 이 버그는 실서버 전환 후에야 보인다(실제로 그렇게 발견됐다). 테스트를 붙일 때 **`drip`과 `save`가 섞인 목록**을 케이스로 둔다.
- **드립 도착과 푸시 알림의 중복 안내는 이 티켓 밖이다** — `library.md` 미결 사항으로 남아 있다.
- 배너 문구·개수 표현(`새 콘텐츠 N개 도착`)은 `library.copy.ts` 그대로다. 카피는 바뀌지 않는다.

## 완료 조건

- Given 라이브러리 목록을 한 번 본 상태다 / When 탐색에서 라이브러리에 없는 콘텐츠를 탭해 재생하고 라이브러리로 돌아온다 / Then **배너가 뜨지 않는다**(자동 적립분은 목록 맨 위에 그대로 있다)
- Given 라이브러리 목록을 한 번 본 상태다 / When 더보기 시트에서 [라이브러리에 담기]를 하고 목록을 갱신한다 / Then **배너가 뜨지 않는다**
- Given 라이브러리 목록을 한 번 본 상태다 / When 새 드립이 적립된 뒤 목록을 재조회한다 / Then **"새 콘텐츠 N개 도착"이 뜨고 N이 새로 온 드립 수와 같다**
- Given 담기 1건과 새 드립 2건이 함께 들어온 상태다 / When 목록을 재조회한다 / Then 배너의 N이 **2**다(담기는 세지 않는다)
- Given 출처 필터를 [내가 담은 콘텐츠]로 걸어 드립이 보이지 않는 상태다 / When 그 상태에서 목록을 재조회한 뒤 필터를 해제한다 / Then 필터가 걸린 동안 도착한 드립이 배너에 그대로 반영된다
- Given 첫 진입이라 기준값이 없다 / When 목록이 처음 그려진다 / Then 배너가 뜨지 않고 기준값만 기록된다
