## 문제

**카카오톡은 링크를 인앱 브라우저로 연다.** 인앱 브라우저는 유니버설 링크(iOS)·App Links(Android)를
타지 않으므로, **앱이 설치돼 있어도 앱으로 넘어가지 않는다.** 대신 랜딩의 미설치 안내 페이지가 뜬다.

메모·문자에서 탭하면 정상 동작한다(2026-09-08 실기기 확인) — **인프라·라우팅은 문제없다.**
문제는 링크가 도착하는 자리다.

> **이것이 왜 중요한가** — 우리 사용자가 링크를 주고받는 곳은 사실상 카톡이다. 지금 구조면
> 받는 사람 대부분이 안내 페이지에서 멈춘다. 앱을 이미 설치한 사람도 마찬가지다.

## 원인 두 겹

### ① 인앱 브라우저가 OS 링크 검증을 타지 않는다

우리가 고칠 수 없는 부분이다. **탈출 경로를 우리가 제공해야 한다.**

### ② 앱이 커스텀 스킴으로 열릴 수 없다 — 파서가 거절한다

`app.json`에 `scheme: "ear"`가 있어 `ear://...`로 앱을 띄울 수는 있는데, 게이트의 파서가
**https 만** 받는다.

```ts
// share.link.ts
const SHARE_LINK_PATTERN = /^https:\/\/earcast\.co\.kr\/contents\/([^/?#]+)/;
```

즉 `ear://contents/<id>`로 앱이 떠도 **목적지를 버리고 정상 진입 분기를 탄다.**
주석이 *"https 외 스킴·다른 host·다른 경로는 전부 null"* 이라고 의도를 밝히고 있으므로,
바꾼다면 **의도적인 확장**으로 다뤄야 한다.

## 요청 내용

1. **파서가 커스텀 스킴도 받게 한다** — `ear://contents/:id`. 다른 host·경로는 지금처럼 거절한다.
   보안 관점의 변화는 없다: 링크에 실리는 값은 `content_id` 하나이고, 조회 스코프는 언제나
   수신자 자신의 토큰이 정한다(`share.link.ts` 상단 주석).
2. **랜딩 안내 페이지에 [앱에서 열기]를 둔다** — `ear://contents/<id>`로 이동한다.
   인앱 브라우저에서도 커스텀 스킴은 대개 동작한다.
   - 지금 페이지는 **`content_id`를 읽지 않는다**(주석에 명시). 이 버튼을 두려면 읽어야 하므로
     그 결정을 함께 갱신한다 — 미리보기(제목·썸네일)를 그리자는 것이 **아니라** 링크 조립용이다.
3. **카톡 한정 탈출 경로를 검토한다** — `kakaotalk://web/openExternal?url=<encoded>`는 카톡
   인앱 브라우저에서 외부 브라우저를 여는 카카오 공식 스킴이다. 외부 브라우저로 나가면 유니버설
   링크가 정상 동작한다. **UA에 `KAKAOTALK`이 있을 때만** 노출한다.
   - Android는 `intent://…#Intent;scheme=https;package=com.android.chrome;end` 방식도 있다.
   - **둘 다 실기기 확인이 필요하다** — 카카오·구글 모두 동작이 바뀔 수 있는 영역이라 문서만 보고
     확정하지 않는다.
4. **버튼 문구와 배치는 `share-uiux.md`가 소유하지 않는다** — 랜딩은 앱 화면이 아니다.
   문구는 이 티켓에서 정하되 확정본을 여기 기록한다.

## 완료 조건

- Given 앱이 설치된 기기 / When **카톡에서** `https://earcast.co.kr/contents/<발행 id>`를 탭한다 / Then 앱이 열리거나, 안내 페이지의 **[앱에서 열기] 한 번으로** 앱이 열린다
- Given 그 경로로 앱이 열렸다 / When 관문을 통과한 사용자다 / Then **그 콘텐츠 상세에 도착한다**(목적지를 버리지 않는다)
- Given 앱이 설치되지 않은 기기 / When 같은 링크를 카톡에서 탭한다 / Then [앱에서 열기]를 눌러도 아무 일도 일어나지 않거나 스토어 안내로 이어진다(오류 화면이 뜨지 않는다)
- Given 메모·문자에서 탭한다 / When 앱이 설치돼 있다 / Then 지금처럼 곧바로 앱이 열린다(회귀 없음)
- Given `share.link.ts` / When 파서를 읽는다 / Then 허용 스킴이 문서화돼 있고, 다른 host·경로는 여전히 거절한다

## 참고 — 지금 확인된 것

| 경로 | 앱 열림 |
|---|---|
| 메모·문자에서 탭 | ✅ |
| **카톡에서 탭** | ❌ **인앱 브라우저** |
| 카톡 → ⋯ → 다른 브라우저로 열기 | ✅(수동) |
| 사파리 주소창 직접 입력 | ❌(유니버설 링크 정의상) |

## 진행 기록 (2026-09-08 — 요청 1·2·3 구현. 실기기 확인 대기)

### 요청 1 — 파서가 커스텀 스킴을 받는다

`share.link.ts` 의 단일 정규식을 배열로 바꿨다.

```ts
const SHARE_LINK_PATTERNS = [
  /^https:\/\/earcast\.co\.kr\/contents\/([^/?#]+)/,
  /^ear:\/\/contents\/([^/?#]+)/,
] as const;
```

**거절 조건은 그대로다** — 다른 host·다른 경로·`http`는 여전히 `null`이다. 테스트로 고정했다:
`ear://about` · `ear://contents/`(id 없음) · `earcast://contents/x` · `notear://contents/x` 전부 거절.
스킴만 흉내 낸 것이 통과하지 않는지까지 확인한다(share.link.test.ts, 11개 통과).

### 요청 2·3 — 랜딩에 앱 전환 버튼

`landing-page/src/app/contents/OpenInApp.tsx`(신규).

| 버튼 | 동작 | 노출 |
|---|---|---|
| **앱에서 열기** | `ear://contents/:id` | 항상 |
| **다른 브라우저로 열기** | `kakaotalk://web/openExternal?url=<현재 URL>` | **UA에 `KAKAOTALK`이 있을 때만** |

- `content_id`는 **주소에서 읽는다** — `vercel.json` rewrite가 모든 `/contents/:id`를 정적 페이지
  하나로 보내므로 서버 파라미터가 없다.
- 앱이 없으면 커스텀 스킴이 무시되고 **아무 일도 일어나지 않는다.** 그 경우 기존 스토어 안내가
  원래 역할을 한다.
- SSR 안전을 위해 `useSyncExternalStore`로 읽는다. `useEffect`+`setState`는
  `react-hooks/set-state-in-effect`에 걸리고, 서버 렌더에서는 어차피 빈 값이어야 한다.

### 페이지의 전제가 바뀌었다 — 주석 갱신

기존 `page.tsx` 주석은 *"앱이 설치된 기기는 이 페이지에 오지 않는다 — 여기 도착한 방문자는 앱
미설치"* 였다. **카톡 인앱 브라우저 때문에 그 전제가 깨졌다.** 주석을 사실에 맞게 고쳤고,
`content_id`를 읽지 않는다는 서술도 "앱 링크 조립을 위해서만 읽는다"로 갱신했다.
미리보기(제목·썸네일)를 그리지 않는 방침은 그대로다.

### 확인 필요 — 실기기

- **카톡에서** 공유 링크 탭 → 안내 페이지 → **[앱에서 열기] 한 번으로 앱이 열리고 그 콘텐츠 상세에 도착**
- 카톡에서 **[다른 브라우저로 열기]** → 외부 브라우저로 나가고, 거기서 링크가 앱을 연다
- **앱 미설치 기기**에서 [앱에서 열기] → 오류 화면 없이 아무 일도 일어나지 않는다
- 메모·문자에서 탭 → 지금처럼 곧바로 앱이 열린다(회귀 없음)

> `kakaotalk://web/openExternal` 은 카카오 스킴이라 **동작이 바뀔 수 있다.** 실기기에서 확인되지
> 않으면 그 버튼만 걷어내고 [앱에서 열기]만 남긴다.

## 처리 완료 (2026-09-08 — 실기기 확인)

**카톡에서 공유 링크를 탭했을 때 앱으로 들어가는 경로가 성립한다.**

### 완료 조건 판정

- Given 앱이 설치된 기기 / When 카톡에서 링크를 탭한다 / Then 안내 페이지의 버튼 한 번으로 앱이 열린다 → ✅
- Given 그 경로로 앱이 열렸다 / Then 그 콘텐츠 상세에 도착한다(목적지를 버리지 않는다) → ✅
- Given 메모·문자에서 탭 / Then 지금처럼 곧바로 앱이 열린다(회귀 없음) → ✅
- Given `share.link.ts` / Then 허용 스킴이 문서화돼 있고 다른 host·경로는 여전히 거절한다 → ✅ (테스트 11개)
- Given **앱 미설치 기기**에서 [앱에서 열기] / Then 오류 화면이 뜨지 않는다 → **미확인**

마지막 하나는 미설치 기기를 따로 준비해야 해서 확인하지 않았다. 커스텀 스킴은 처리할 앱이 없으면
브라우저가 무시하는 것이 일반적이고, **실패해도 기존 스토어 안내가 그대로 남는다** — 이 티켓이
막고 있던 문제(주 경로에서 앱 진입 불가)가 해소됐으므로 `archive/`로 옮긴다. 스토어 게시 후
미설치 폴백을 확인할 때 함께 본다(`share-p1-activation-next-build.md`).

### 남겨 둘 판단

`kakaotalk://web/openExternal` 버튼은 **카카오 스킴이라 언제든 동작이 바뀔 수 있다.** 쓸모없어지면
그 버튼만 걷어내고 [앱에서 열기]만 남기면 된다 — 두 버튼은 서로 독립이다.
