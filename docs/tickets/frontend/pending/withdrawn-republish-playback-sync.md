# [FE] 회수·재발행 신호 연결 — 재생 중단·목록 동기화·낡은 위치 폐기

| 항목 | 값 |
|---|---|
| 대상 | 플레이어 재생 세션 · 포그라운드 복귀 동기화 · `refreshAudioUrl()` |
| 요청 파트 | 백엔드 (서버 신호 구현 완료 통지 — 2026-09-08) |
| 발행 날짜 | 2026-09-08 |
| 발견 시점 | `tickets/backend/pending/withdrawn-sync-stops-playback.md` 서버 몫 구현 완료 — 신호를 소비할 클라이언트 연결이 FE 몫으로 남았다 |
| 근거 문서 | `features/partner-control.md` 4.3 · `spec/api/player-api.md` 4.3(응답 `content_status`)·회수 동기화 절 |
| 심각도 | **중** — 회수해도 재생 중인 사용자는 끝까지 듣고(실측: 5분 경과에도 재생), 재발행 순간 듣던 사용자는 서버가 지운 낡은 위치를 되살린다(실측: 03:48 재저장) |
| 상태 | 대기 |
| 연관 | `tickets/backend/pending/withdrawn-sync-stops-playback.md` — 이 티켓이 닫혀야 그쪽 완료 조건 2·3이 닫힌다 |

## 배경 — 서버가 준비된 신호 2개

1. **위치 저장(4.3) 응답에 `content_status`가 추가됐다** (PR #211). 재생 중 위치 저장은 5초
   주기로 돌므로, 회수가 일어나면 늦어도 다음 저장 응답에 `"withdrawn"`이 실린다 — 파일이
   통째로 버퍼링돼 있어도 이 신호는 닿는다.
2. **`GET /contents/withdrawn?since=<ISO8601>`** — 그 시각 이후 회수된 `content_id` 목록.
   앱 실행·포그라운드 복귀 시 동기화용이다.

## 요청 내용

1. **재생 중단** — 4.3 응답의 `content_status === 'withdrawn'`이면 재생을 즉시 멈추고
   "제공이 종료된 콘텐츠예요"를 안내한 뒤 플레이어를 닫는다(토스트 카피·플레이어 상태
   enum은 이미 FE에 있다 — 연결만 안 돼 있다).
2. **회수 목록 동기화** — 앱 실행·포그라운드 복귀 시 마지막 동기화 시각으로
   `GET /contents/withdrawn`을 호출해, 목록의 콘텐츠를 로컬 캐시·미니플레이어·재생 세션에서
   걷어낸다. 마지막 동기화 시각은 기기에 저장한다(첫 호출은 앱 설치 시각 등 보수적 기준).
3. **재발행 감지 시 낡은 위치 폐기** — `refreshAudioUrl()`이 받은 `content_version`이 세션이
   아는 버전과 다르면 **세션 위치를 0으로 폐기**하고 그 위치를 서버에 다시 저장하지 않는다.
   지금은 URL만 갈아끼우고 낡은 위치를 유지해서, 재발행이 지운 `playback_progresses` 행을
   앱이 몇 초 뒤 되살린다(2026-09-08 실증 — 03:45 삭제 → 03:48 재저장).

## 완료 조건

- Given 콘텐츠를 재생 중이다 / When 관리자가 회수한다 / Then 버퍼가 남아 있어도 다음 위치 저장 주기 안에 재생이 멈추고 안내가 뜬다
- Given 콘텐츠를 재생 중이다 / When 관리자가 재발행한다 / Then 앱이 낡은 위치를 서버에 다시 저장하지 않는다(재진입 시 0부터)
- Given 회수 시점에 앱이 백그라운드였다 / When 포그라운드로 복귀한다 / Then 그 콘텐츠가 라이브러리·미니플레이어에서 사라져 있다
- Given 회수된 콘텐츠가 없다 / When 복귀 동기화가 돈다 / Then 아무 변화가 없다(빈 목록 — 회귀 없음)
