# [FE] 공유 메시지 최종 확정 — '참고한 자료'(저자·출처 줄)는 넣지 않는다

| 항목 | 값 |
|---|---|
| 대상 | `frontend/src/features/share/share.service.ts`(`buildShareMessage`) · `spec/uiux/share-uiux.md` 6장(공유 텍스트 형식) · `features/share.md` 4.1 |
| 요청 파트 | 프론트엔드 |
| 발행 날짜 | 2026-09-09 |
| 발견 시점 | v8 스토어 제출 공유(2026-09-09) — "KAN-34 공유 P1 카피 2개 미확정으로 이번 빌드 미반영". 카피가 다시 열린 김에 메시지 내용 자체를 확정한다 |
| 근거 문서 | `features/share.md` 4.1(공유 시트에 전달하는 내용) · `spec/uiux/share-uiux.md` 6장 · `changes/archive/share-p1-copy-decisions.md`(2026-09-04 잠정 확정) |

## 배경

현재 코드(`buildShareMessage`)와 `share-uiux.md` 6장은 2026-09-04에 잠정 확정한 **세 줄 형식**이다.

```
제목
저자 · 출처        ← 콘텐츠 상세의 "참고한 자료"에 해당하는 줄 (author_name · source_name)
링크
```

이 형식은 `features/share.md` 4.1의 "텍스트: 콘텐츠 제목 + 저자·출처"를 그대로 옮긴 것인데, 2026-09-09 공유 회의에서 **참고한 자료는 공유 메시지에 넣지 않아도 된다**고 결정됐다. 받는 사람 입장에서 링크를 열면 상세에서 어차피 보이고, 출처 문구가 길면 메시지 앱에서 링크 미리보기보다 텍스트가 먼저 잘린다.

## 결정된 것

- **둘째 줄('저자 · 출처' = 참고한 자료)을 뺀다.** 공유 메시지에 `author_name`·`source_name`을 싣지 않는다.

## 남은 것 — 확정해야 한다

둘째 줄을 뺀 뒤의 **최종 형식**을 정한다. 후보:

| 안 | 형식 | 비고 |
|---|---|---|
| A | `제목 ⏎ 링크` (두 줄) | 현행에서 한 줄만 빼는 최소 변경. 내부 용어·안내 문구 없음 원칙(6장) 그대로 |
| B | `안내 문구 ⏎ 제목 ⏎ 링크` | 예: "이어에서 들어보세요" 같은 한 줄 추가. 6장의 "링크를 설명하는 문구를 덧붙이지 않는다(제안)"와 충돌하므로 채택 시 그 줄을 함께 개정 |

확정되면 이 티켓에 최종 문자열을 기록하고 아래를 한 번에 반영한다.

## 요청 내용

1. 최종 형식(A/B 또는 다른 안)을 확정해 이 티켓에 기록한다 — 확정 주체: 팀장.
2. `share.service.ts#buildShareMessage`를 확정 형식으로 바꾸고 테스트(`share.service.test.ts`의 세 줄 기대값)를 갱신한다.
3. 문서 반영은 `changes/`로 올린다 — `share-uiux.md` 6장 "공유 텍스트 형식" 행, `features/share.md` 4.1 "텍스트: 콘텐츠 제목 + 저자·출처" 문구. 두 문서 모두 FE 소유가 아니므로 직접 고치지 않는다.
4. 다음 스토어 빌드에 포함한다(빌드 타임 문자열).

## 완료 조건

- Given 이 티켓 / When "결정된 것"을 읽는다 / Then 최종 문자열 형식이 후보가 아니라 확정값으로 적혀 있다
- Given 확정 형식 / When 콘텐츠 상세에서 [공유]를 탭해 OS 공유 시트에 넘어간 텍스트를 본다 / Then `author_name`·`source_name`이 들어 있지 않고, 확정 형식과 줄 단위로 일치한다
- Given 저자가 있는 콘텐츠와 없는 콘텐츠 / When 각각 공유한다 / Then 두 메시지의 형식이 같다(저자 유무로 줄 수가 달라지지 않는다)
- Given `changes/pending/` / When 목록을 본다 / Then `share-uiux.md` 6장·`share.md` 4.1 개정 요청이 올라가 있다
