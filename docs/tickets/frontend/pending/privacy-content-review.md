## 요지 (Jira 본문용)

- 수집 항목(이용자가 직접 입력)에 "콘텐츠 후기(별점 · 글)" 추가 — KR · EN
- 처리 목적에 "서비스 개선 · 콘텐츠 품질 관리", 보유 기간 "회원 탈퇴 시까지(탈퇴 시 즉시 파기)"
- 선행: PM 판단(티켓 아님 · **미정**) — 고지 기간 7일 / 30일(중대한 변경) · 문구 확정. **시행일이 후기 기능을 켜는 날을 정한다**
- 11/1 시행 개정(광고 ID)은 이미 고지가 나가 있어 합치지 않고 별도 개정으로
- 상세 · 완료 조건은 원본 문서

## 요청

**콘텐츠 후기는 이용자가 직접 입력하는 새 수집 항목이라 처리방침을 먼저 고친다**(`content-review.md` 4.9 — 처리방침 시행 전에는 후기 기능을 켜지 않는다).

1. **수집 항목** — 1.3(이용자 직접 입력)에 "콘텐츠 후기(별점 · 글)". 영어판 같은 위치
2. **처리 목적** — 2장 표에 "서비스 개선 · 콘텐츠 품질 관리 | 콘텐츠 후기". 후기를 **공개하지 않고 추천에 쓰지 않는다**는 사실과 어긋나는 표현(예: "맞춤 추천")을 넣지 않는다
3. **보유 기간** — "회원 탈퇴 시까지" 행에 포함(탈퇴 시 즉시 파기 — 결제 기록 보존 대상 아님)
4. **고지** — PM이 정한 기간(7일 / 30일) 전에 앱 내 공지 · 랜딩 개정 안내. 11/1 개정(광고 ID)과는 따로 낸다 — 그 개정은 10/2에 이미 고지했다
5. **초안 문서** — `docs/legal/privacy-policy-draft.md`를 랜딩 본문과 맞춘다
6. 시행일이 정해지면 KAN-279 담당(박준현)에게 알린다 — 그날 이후 `CONTENT_REVIEW_ENABLED`를 켠다

## 완료 조건

- Given 개정 예정본 / When KR · EN 처리방침을 본다 / Then 수집 항목 · 목적 · 보유 기간에 콘텐츠 후기가 있고, "공개하지 않음 · 추천 미사용"과 어긋나는 문구가 없다
- Given 고지 기간 / Then 시행일 기준 PM이 정한 기간 전에 앱 내 공지가 게시돼 있다
- Given 시행일 / Then 백엔드에 날짜가 전달돼 있다(이 티켓 처리 기록에 남긴다)
