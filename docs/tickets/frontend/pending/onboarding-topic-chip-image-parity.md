## 문제

같은 주제인데 iOS와 Android에서 칩에 깔리는 배경 사진이 다르다. 사진은 서버가 주는 게 아니라 **주제 이름 → 로컬 번들 에셋** 매핑이라, 같은 JS 번들이면 두 플랫폼이 같은 사진을 보여야 한다.

## 원인 후보 (확인 절차 포함 — 수정 전 규명 필요)

1. **두 플랫폼 빌드의 JS 번들 세대가 다르다 (유력)** — `TOPIC_IMAGE` 매핑은 주제 체계 개편(topic-taxonomy-v2, 2026-09-03 merge)에서 크게 바뀌었다. 한쪽 내부 테스트 빌드가 개편 이전 번들(옛 매핑 → 옛 사진이나 `default.jpg` 폴백)이고 다른 쪽이 이후 번들이면 정확히 이 증상이 된다. OTA(EAS Update)는 2026-09-06에야 도입됐고 **fingerprint 정책 이전의 기존 빌드는 OTA를 받지 못하므로**, 두 스토어에 올린 빌드 시점이 다르면 세대 차이가 고정된다.
   - 확인: 두 기기에서 같은 계정으로 O1 스크린샷 → 다르게 보이는 주제 이름 목록 확보 → 각 빌드의 업로드 시점·포함 커밋(빌드 번호)과 `TOPIC_IMAGE` 변경 커밋의 선후 비교.
2. 매핑 누락 — 서버 주제 이름 중 한 플랫폼 노출분이 `TOPIC_IMAGE`에 없어 `default.jpg`로 떨어지는 경우. 단 이름은 서버 공통이라 "플랫폼 간" 차이는 설명하지 못한다(1과 결합된 형태로만 성립).
3. 렌더 차이 — 같은 사진의 `resizeMode="cover"` 크롭·색 처리 차이. "다른 사진"이 아니라 "같은 사진이 다르게 보임"이면 이쪽이며 수정 범위가 달라진다.

## 요청 내용

1. 위 확인 절차로 원인을 확정하고 티켓에 기록한다.
2. 원인 1이면: 코드 수정이 아니라 **두 플랫폼 모두 최신(fingerprint 포함) 빌드 재업로드**로 해소 — 이후에는 OTA가 세대 차이를 자동으로 없앤다. 재업로드 후 재확인만 하면 된다.
3. 원인 2·3이면: 해당 매핑 추가 또는 렌더 보정(코드 수정) 후 두 플랫폼 스크린샷 대조.

## 완료 조건

- Given 같은 계정·같은 주제 목록 / When iOS·Android에서 O1을 나란히 본다 / Then 같은 주제 칩에 같은 배경 사진이 보인다
- Given 원인 규명 결과 / When 이 티켓을 읽는다 / Then 원인(번들 세대/매핑 누락/렌더 차이)과 조치가 기록되어 있다

## 진행 기록 (2026-09-08 — 원인이 후보 3(렌더 차이)로 확정됐다. 후보 1은 아니다)

OTA로 최신 JS가 iOS vc=3에 전달된 뒤(약관 화면 4개 확인으로 도달 확정) 다시 보니, 증상이
"사진이 다르다"가 아니라 **"사진이 알약을 못 채운다"** 였다.

> **iOS 실기기** — 사진이 한쪽으로 쏠려 있고 **아래쪽에 흰 배경이 드러난다.**

### 원인 — `photo`에만 있던 퍼센트 크기

```ts
photo: {
  position: 'absolute', top: 0, left: 0, right: 0, bottom: 0,
  width: '100%',   // ← 이 둘이 문제
  height: '100%',
}
```

절대 배치 자식에 inset 4개와 퍼센트 크기를 **함께** 주면 크기가 이깁니다 — 그리고 퍼센트는
부모의 **콘텐츠 박스**(패딩 제외)로 풀린다. 칩은 `paddingHorizontal: lg(24)` ·
`paddingVertical: sm(8)` 을 갖고 있으므로 사진 상자가 알약보다 **가로 48 · 세로 16만큼 작아진다.**
그 차이가 배경으로 드러난다.

**바로 아래 `overlay`가 inset만으로 정확히 채워지는 것이 반증이다** — 같은 절대 배치인데
퍼센트가 없다. 둘의 상자가 어긋나 있었으므로 오버레이가 사진 밖까지 덮고 있었다.

### 반영

`photo`에서 `width`·`height`를 걷어내고 inset만 남겼다(`overlay`와 같은 형태).

### 후보 1(번들 세대 차이)은 원인이 아니었다

발행 시점에는 "iOS·Android 빌드의 JS 번들 세대가 다르다"를 유력 후보로 봤는데, **OTA로 양쪽을
같은 번들로 맞춘 뒤에도 증상이 남았다.** 세대 차이는 실재했지만(iOS vc=3은 2026-09-06 빌드)
이 증상의 원인은 아니다.

### 확인 필요

- Given iOS·Android / When O1을 본다 / Then 사진이 알약을 **가장자리까지** 채우고 배경이 드러나지 않는다
- Given 같은 주제 / When 두 플랫폼을 나란히 본다 / Then 같은 사진이 같은 크롭으로 보인다
- Given 관심사 관리(IM) 격자 / When 칩을 본다 / Then 같은 규칙으로 채워진다(같은 컴포넌트다)

에셋 자체는 문제없다 — 32장 전부 `800×320`(2.50:1)로 통일돼 있다(실측).

## 진행 기록 (2026-09-08 — 비율을 알약에 맞췄다. 사진을 더 자르지 않는다)

앞선 수정(inset만으로 채우기)으로 배경이 드러나는 문제는 없어졌지만, **사진이 무엇을 찍은
것인지 알아볼 수 없다는 문제가 남았다.** 원인은 비율이다.

```
사진   800 x 320 = 2.50 : 1
알약   156 x 52  = 3.00 : 1   ->  cover 로 세로가 17% 잘린다
```

**원본이 이미 한 번 잘린 상태다**(Openverse 원본 -> 800x320). 거기서 또 17%를 자르니 피사체가
두 번 잘려 창틀·흐릿한 덩어리만 남았다.

### 사진을 더 자르지 않고 알약을 맞췄다

```
156 / 2.50 = 62.4  ->  minHeight 52 -> 62
```

높이 62면 `156/62 = 2.52`로 **크롭이 사실상 0**이다. 이미지를 재가공하지 않으므로 화질 손실도,
에셋 교체도 없다. 온보딩 화면은 알약 4줄 아래에 빈 공간이 크게 남아 있어(실기기 스크린샷)
높이가 늘어도 레이아웃이 밀리지 않는다.

**사진을 바꿀 때는 이 비(2.50:1)를 함께 본다** — 컴포넌트 주석에 남겼다.

### 함께 확인해야 할 것 — 상한 dim 가독성

3개를 다 고르면 나머지 칩이 `rgba(255,255,255,0.78)` 오버레이 + `textSecondary` 라벨이 되는데,
**실기기에서 글자가 거의 안 읽힌다**(스크린샷 2026-09-08 00:14 — 커리어·조직·스타트업).
"하얗게 물러난다"는 uiux 의도(4.1)는 맞지만 대비가 WCAG AA(4.5:1)에 못 미쳐 보인다.

**이번 변경에 포함하지 않았다** — 물러남의 정도는 디자인 결정이라 임의로 바꾸지 않는다.
오버레이 불투명도를 올려 더 균일한 흰 면으로 만들고 라벨을 진하게 하는 것이 후보다.

## 원인 확정 (2026-09-08 — 브라우저에서 직접 재서 잡았다)

추측을 멈추고 **iPhone 16e 크기(390x844)로 웹을 띄워 실제 렌더 수치를 측정**했다.

```
알약 :  156 x 62   (2.52:1)   <- 높이 수정은 적용돼 있었다
<img>:  800 x 320             <- 알약 밖으로 가로 644px 넘침
```

**react-native-web 은 `Image` 래퍼에 원본 크기를 박는다.** 그래서 앞선 수정(inset만 남기기)이
웹에서는 크기를 못 잡게 만들었다 — 원래 코드에 `width/height: '100%'`가 있던 이유가 이것이다.

동시에 **그 퍼센트가 iOS에서는 부모의 콘텐츠 박스(패딩 제외)로 풀려** 사진이 알약보다 작아졌다.
`paddingHorizontal: lg(24)` · `paddingVertical: sm(8)` 만큼 배경이 드러난 것이 그 결과다.

**둘 다 만족하는 형태는 하나다 — 칩에서 패딩을 걷어내고 라벨에 준다.**
그러면 콘텐츠 박스 = 알약 전체가 되어 퍼센트가 알약과 같아지고, 웹은 크기를 얻는다.

브라우저에서 검증한 결과(코드 수정 후 재측정):

```
padding : 0px
알약    : 156 x 62
래퍼    : 156 x 62
<img>   : 156 x 62      -> 정확히 일치
```

`objectFit`이 `fill`로 잡히지만 비율이 2.52 대 2.50이라 왜곡은 0.8%로 눈에 보이지 않는다.
**사진 비율(2.50:1)을 바꾸면 이 전제가 깨진다** — 컴포넌트 주석에 남겼다.

### 남은 확인

- iOS 실기기에서 사진이 알약을 가장자리까지 채우는지
- 관심사 관리(IM) 격자도 같은 규칙으로 채워지는지(같은 컴포넌트, 폭만 다르다)
