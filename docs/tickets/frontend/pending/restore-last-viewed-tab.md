## 문제

`splash.md` 4장 4단계가 도착지를 라이브러리로 못박고 있어, 무엇을 보다 껐든 다시 켜면 라이브러리다.

## 결정 (사용자 2026-09-15)

| 항목 | 결정 | 이유 |
|---|---|---|
| 복원 범위 | **탭까지만** | 스택까지 되살리면 열지 않은 화면이 떠 있는 것처럼 읽힌다. 상세는 그 사이 사라질 수 있어(회수·삭제) 존재 판정과 실패 경로가 따로 필요해진다 |
| 유효 기간 | **30분** | 잠깐 다른 앱 갔다 오는 경우를 살리는 것이 목적이다. 어제 본 탭이 오늘 뜨면 어색함이다 |

## 반영 내용

**우선순위는 온보딩 직후 > 마지막 탭 > 라이브러리다.** 온보딩을 막 끝낸 사람에게는 이전
기록보다 "고를 것이 많은 화면"(탐색)이 먼저다(2026-09-02 결정 유지).

- `last-tab.ts` — 기록·판정·삭제를 한곳에 둔다. `<탭>:<epoch ms>` 한 줄로 저장
- **기기 로컬에만 둔다.** 세션(메모리)에 두면 앱 종료와 함께 사라져 목적을 달성하지 못한다.
  서버에 보내지 않는다 — 기기마다 마지막으로 본 탭이 다른 것이 자연스럽다
- 기록 시점은 **탭에 도착한 때**다. 떠나는 시점을 잡으려면 이탈 경로마다 훅이 필요하고,
  마지막으로 머문 탭이 곧 마지막으로 본 탭이다
- `initialRouteName`은 첫 마운트에만 읽히는데 저장소 조회는 비동기다. 그래서 **실행 관문이
  기다리는 동안 미리 읽어 두고**(`primeTabToRestore`) 마운트 시 동기로 꺼낸다(`takePrimedTab`)
- **꺼내면 비운다.** 앱 수명 안에서 로그아웃 → 재로그인으로 탭이 다시 마운트될 때 실행
  시점의 기록이 또 적용되면, 그때는 "마지막으로 본 탭"이 아니라 남의 흔적이다
- 로그아웃·탈퇴 시 지운다(`app/bootstrap`의 인증 전이 구독에 배선)

### 버린 값을 명시한다

판정이 조용히 틀리기 쉬운 자리라 유닛 테스트 9건을 붙였다. `null` 처리 대상:

- 기록 없음 · 형식 깨짐(`Explore`, `:123`, `Explore:abc` …)
- **복원 대상이 아닌 화면 이름** — 탭이 아닌 값이 들어오면 내비게이터가 깨진다
- **미래 시각** — 시계를 뒤로 돌린 기기에서는 만료 판정이 성립하지 않는다
- 저장소 예외 — 복원 실패가 앱 실행을 막으면 안 된다

전부 라이브러리로 떨어진다. 이는 이 기능이 없던 종전 동작과 같다.

## 완료 조건

- Given 탐색 탭을 보다 앱을 종료했다 / When 30분 안에 다시 연다 / Then 탐색 탭으로 시작한다
- Given 같은 상황 / When 30분이 지난 뒤 연다 / Then 라이브러리로 시작한다
- Given 콘텐츠 상세를 보다 종료했다 / When 다시 연다 / Then 그 상세가 아니라 **그 상세가 속한 탭**으로 간다
- Given 온보딩을 막 끝냈다 / When 라이브러리 탭 기록이 남아 있다 / Then 기록보다 **탐색**이 먼저다
- Given 로그아웃한다 / When 다른 계정으로 로그인한다 / Then 앞 사용자의 탭이 아니라 라이브러리로 간다
- Given 딥링크로 앱이 열린다 / When 마지막 탭 기록이 있다 / Then 딥링크 목적지가 보인다
