## 배경

추천 고도화(결정 51·52)로 **정규 드립 2편과 별개로 매일 1편이 탐험 슬롯**으로 적립된다(`drip-scheduling.md` 4.8 — 신규·저노출 콘텐츠 노출 + 취향 신호 다양화). 취향 밖 콘텐츠가 정규 드립처럼 보이면 "나 이런 거 관심 없는데 왜 왔지?"가 되므로, **화면이 구분해서 보여주는 것이 이 기능의 절반**이다.

구분 판정 재료는 목록 응답의 `source` 원값 하나다(`library-api.md` 4.1 — 새 필드 없음). 서버 쪽 계약 변경은 enum 값 `discovery` 추가뿐이다.

## 요청 내용

1. **`source` enum 값 `discovery` 수신 처리** — 목록 응답 `items[].source`에 `discovery`가 추가됐다(`library-api.md` 4.1). 알 수 없는 값으로 떨어뜨리지 않는다.
2. **[이어 PICK] 필터 뷰 — 두 구획 분리** (`library.md` 4.6-1): 정규 드립 구획 + "이런 주제는 어떠신가요?" 구획(탐험 편). 클라이언트가 `source`로 그룹핑한다 — 탐험 편은 하루 1편이라 정렬·커서 계약에 영향이 없다. 참고: [이어 PICK] 필터의 조회 조건 자체는 서버가 `source IN ('drip','discovery')`로 처리하므로 클라이언트 쿼리 값(`source_filter=drip`)은 그대로다.
3. **필터 미적용 전체 목록 — 행 배지** (`library.md` 4.6-1): 구획 없이 시간순 유지, 탐험 편 행에만 작은 배지. 목록 구조를 깨지 않으면서 제안 성격을 드러낸다.
4. **도착 배너 카운트에 discovery 포함** (`library-api.md` 4.1 개정): 배너 판정의 비교 대상·기준값이 `source = 'drip'` → `source IN ('drip','discovery')`로 바뀌었다. **탐험 전용 배너는 만들지 않는다** — 기존 "새 콘텐츠 N개 도착" 하나에 합산이다.
5. **카피는 제안값으로 선진행** — 섹션 타이틀 "이런 주제는 어떠신가요?"·배지 문구는 제안 카피이며 `spec/uiux/library-uiux.md` 개정으로 확정 예정(`library.md` 미결). 구조를 먼저 구현하고 카피 확정 시 문자열만 교체한다.
6. **범위 밖** — 탭·삭제·재생·더보기 등 행 동작은 정규 아이템과 완전히 동일하다(`library.md` 4.6-1 "구분은 표시까지다"). 동작 분기를 만들지 않는다.

## 완료 조건

- Given `source = discovery` 항목이 포함된 목록 응답 / When [이어 PICK] 필터를 적용한다 / Then 목록이 정규 드립 구획과 "이런 주제는 어떠신가요?" 구획으로 나뉘어 렌더링된다
- Given 같은 응답 / When 필터 없이 전체 목록을 본다 / Then 탐험 편은 시간순 위치 그대로 노출되고 행에 구분 배지가 붙는다
- Given 정규 드립 1편 + 탐험 편 1편이 새로 도착한 상태 / When 라이브러리를 재조회한다 / Then "새 콘텐츠 2개 도착" 배너 하나만 노출된다(탐험 전용 배너 없음)
- Given 탐험 편 행 / When 탭·삭제·더보기를 조작한다 / Then 정규 아이템과 동일하게 동작한다(재생 확인 팝업·삭제 실행취소 포함)
- Given `source` 값이 `discovery`인 항목 / When 구버전 처리 로직(3값 가정)이 남아 있는지 확인한다 / Then 알 수 없는 source로 인한 크래시·미표시가 없다
