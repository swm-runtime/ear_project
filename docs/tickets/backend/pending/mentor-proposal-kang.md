## 요청

강준혁 멘토님께 드릴 **이어 프로젝트 제안서**를 작성한다(PM 2026-10-07 15:44).

## 착수 전에 PM과 맞출 것

요청 시점에 아래가 정해져 있지 않다. 담당이 PM에게 확인하고 처리 기록에 남긴다.

- 제안서의 용도(무엇을 제안·요청하는 문서인가)와 멘토님 쪽 마감
- 형식·분량(문서/슬라이드, 페이지 수)
- 전달 경로(메일·노션 등)

## 완료 조건

- Given 위 세 가지를 PM과 확인한 뒤, When 제안서 초안을 보면, Then 이어의 문제 정의·대상 사용자·현재 진행 상황이 들어 있고 PM이 검토했다
- Given 검토가 끝난 제안서, When 전달 기록을 보면, Then 강준혁 멘토님께 전달한 날짜·경로가 아래 처리 기록에 적혀 있다

## 처리 기록

### 2026-10-07 — 초안 작성 (PR `docs(be)/mentor-proposal-kan-153`)

- PM과 맞출 세 가지(용도·형식/분량·전달 경로)는 **아직 확인하지 못했다.** 기다리지 않고 초안을 먼저 썼다 — 어느 용도든 들어가야 할 몸통(문제 정의·대상 사용자·동작·현재 진행 상황·계획)은 같기 때문이다. 세 항목은 초안 상단 표에 **[PM 확인]** 가정으로 적었다: 용도 = 멘토링 착수용(조언 요청), 형식 = 문서 1부(본문 2쪽 + 부록, PDF), 전달 = 메일 첨부. 확인되면 고치고 표시를 지운다. 7장(여쭙고 싶은 것)은 용도에 따라 통째로 바뀔 수 있어 가정 표시를 뒀다.
- 초안 내용의 출처: 문제·대상·솔루션은 `prd/ear_root_prd.md` 1·3장, 진행 상황·숫자는 `retrospective/2026-W5.md`(9/29~10/5 주간 지표)와 10/6 운영 집계(누적 가입 167, 발행 46편). 개인 식별 정보는 싣지 않았다.
- **남은 것**: ① PM 확인(세 항목) → 초안 수정 ② PM 검토 ③ 전달 → 날짜·경로를 여기 적는다. 기한(10/10)은 PM 확인이 늦으면 넘길 수 있다.
