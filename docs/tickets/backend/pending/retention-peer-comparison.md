## 요청

**다른 사용자와의 비교로 다시 듣게 만드는 장치를 넓히고, 그 비교를 푸시로 보낼지 검토**한다(10월 5주차 계획(2026-10-26 회의)).

- 지금 있는 것: 프로필 주제 한 줄의 "같은 직군 1위"(KAN-266·268 — 같은 시장·직군, 본인 제외, 청취자 5명 이상, 집계만. `features/profile.md` 4.7-1)
- 할 것
  1. **비교 항목** — 무엇을(주제·청취 시간·완청 등) 누구와(같은 직군·같은 시장 전체) 비교할지 정하고 판정을 서버에 둔다
  2. **푸시 여부** — 보낸다면 빈도·대상·시각·수신 토글·문구(KR/GLOBAL)·딥링크를 `features/notification.md` 4.3에 맞춰 정한다. 지금 푸시는 드립 도착 1종(하루 1회, 07:00)이라 **두 번째 종류가 생기는 것**이다 — 하루 최대 횟수와 토글 분리 여부를 함께 정한다
- **개인을 드러내지 않는다** — 집계·최소 인원 하한을 유지한다
- 규칙이 정해지면 `features/notification.md`·`features/profile.md`·`spec/api/`를 먼저 고친다(문서 먼저)

## 완료 조건

- Given 비교 항목 결정 / When `features/`를 본다 / Then 항목·대상 집단·최소 인원·판정 위치(서버)가 적혀 있다
- Given 푸시를 보내기로 함 / When `features/notification.md`를 본다 / Then 새 알림의 시각·빈도·대상·토글·문구·딥링크가 적혀 있고, 발송 판정이 서버에 구현돼 테스트가 통과한다
- Given 푸시를 안 보내기로 함 / When 처리 기록을 본다 / Then 사유가 적혀 있다
