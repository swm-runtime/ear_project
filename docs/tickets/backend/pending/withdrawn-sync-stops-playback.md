## 문제

`partner-control.md` 4.3은 회수의 반영 시점을 노출면별로 못박는다.

| 노출면 | 명세 | 실제(2026-09-08 실기기) |
|---|---|---|
| 카탈로그·탐색·검색 | 즉시 | ✅ |
| 이미 적립된 라이브러리 | 즉시 서버에서 삭제 | ✅ 사라진다 |
| 상세 조회 | 차단 | ✅ 진입 안 된다 |
| **재생 중인 세션** | **"오디오 서명 URL 발급 차단. 진행 중 재생은 버퍼 소진 시 중단"** | ❌ **5분이 지나도 끝까지 재생된다** |

서명 URL 만료는 5분인데(`audio_access_logs.expires_at` 실측) 그보다 오래 재생됐다.
**클라이언트가 파일을 통째로 버퍼링했기 때문**으로 보인다 — 15분짜리 mp3는 재생 초반에 전부 받아둘 수 있다.

명세의 "버퍼 소진 시 중단"은 **버퍼가 곧 파일 전체인 경우를 상정하지 않았다.** 문자 그대로는 위반이
아니지만, 이 조항의 목적(회수 즉시 청취 중단)은 달성되지 않는다.

## 왜 이렇게 됐나 — 동기화 채널이 없다

`partner-control.md` 4.3의 처리 순서 5번은 **"오프라인 회수 목록에 추가 → 클라이언트가 앱 실행·
포그라운드 복귀 시 동기화"** 이고, 조회 수단으로 `GET /contents/withdrawn?since=<timestamp>` 를
지정한다(같은 절 "클라이언트 동기화").

**그 엔드포인트가 없다.** 서버 코드가 스스로 그렇게 적고 있다.

```ts
// backend/src/modules/content-detail/content-detail.controller.ts:24
// `GET /contents/withdrawn`(회수 동기화 — partner-control 소유, 미구현)을 나중에 만들 때는 …
```

클라이언트에도 회수 목록을 받아 처리하는 코드가 없다(`grep withdrawn frontend/src` — 토스트 카피와
플레이어 상태 enum 뿐).

## 요청 내용

1. **`GET /contents/withdrawn?since=<ISO8601>` 를 구현한다.** `contents` 에서 `status = withdrawn`
   이고 `withdrawn_at > since` 인 `content_id` 목록을 돌려준다(별도 테이블 없이 — `domain.md` 14장).
2. **응답 계약을 `spec/api/` 에 등재한다.** 지금은 `partner-control.md` 본문에만 언급돼 있어 확정
   계약이 아니다. 어느 화면 문서에도 속하지 않으므로 위치 결정이 필요하다.
3. **재생 중단의 판정 주체를 정한다.** 클라이언트가 목록을 받아 스스로 멈추는 것 외에,
   진행 중 세션을 서버가 끊을 수단이 있는지(예: 진행 저장 4.3 응답에 회수 신호를 실어 보내기)를
   함께 검토한다 — **클라이언트는 이미 4.3 으로 주기적으로 서버와 통신한다.** 그쪽이 즉시성이 높다.
4. **오프라인 저장분(P1)** 은 이 티켓 범위 밖이다(`offline-download.md` 이연).

## 완료 조건

- Given `GET /contents/withdrawn?since=<시각>` / When 그 시각 이후 회수된 콘텐츠가 있다 / Then 그 `content_id` 목록이 반환된다
- Given 앱이 그 콘텐츠를 재생 중이다 / When 관리자가 회수한다 / Then **버퍼가 남아 있어도 재생이 멈추고** "제공이 종료된 콘텐츠예요"가 안내된다
- Given 회수 시점에 재생 중이 아니었다 / When 앱을 포그라운드로 복귀시킨다 / Then 라이브러리·목록에서 그 콘텐츠가 사라져 있다(현재도 조회 시점에 반영되므로 회귀 확인)
- Given 계약 / When `spec/api/` 를 연다 / Then 이 엔드포인트가 등재돼 있다

## 참고 — 함께 확인된 정상 동작

같은 실기기 확인에서 아래는 **명세대로 동작했다.** 회귀 판단의 기준선으로 남긴다.

- 회수 즉시 `library_items` 가 삭제된다
- **복구해도 라이브러리는 되살아나지 않는다**(`partner-control.md` 4.3 "삭제된 `library_items` 는 복구하지 않는다")
- 상세 진입이 차단된다
