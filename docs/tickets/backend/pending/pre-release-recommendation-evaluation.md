## 요청

추천 로직을 배포하기 전에 품질을 평가하는 체계를 만든다 — 오프라인 평가 지표(예: 적중률·다양성·신규 콘텐츠 노출률)와 샘플 사용자 셋, 배포 전 체크리스트. 이주호의 추천 알고리즘 조사 티켓과 기준을 공유한다.

## 완료 조건

- Given 추천 로직 변경 PR, When 평가를 돌리면, Then 지표 결과가 남는다
- Given 평가 문서, When 기준을 보면, Then 통과 조건이 적혀 있다

## 처리 기록

### 2026-09-30 — 체계 구축 완료(PR 대기). 이주호 KAN-104와 기준 공유는 문서로

**설계 원칙** — 점수식을 두 벌 두지 않는다. 평가기는 제품 편성기(`DripBatchOrchestrator.planForUser`)를 **그대로** 돌리고, DB 대신 인메모리 세계(`EvalWorld`)가 SQL이 답하던 것(후보 필터·라이브러리 집계·신호)만 대신한다. 스코어링·시리즈 게이트·MMR·취향 계산·자동 확장을 고치면 평가가 따라 움직인다.

**만든 것** (`backend/src/modules/recommend-eval/`)
- `GET /admin/recommend-eval/snapshot` — 발행 콘텐츠(메타·주제·집계·임베딩) + 익명 사용자(관심·신호·라이브러리·제외·토글) 내보내기, 읽기 전용(`admin-api.md` 4.18)
- `npm run eval:recommend` — ① **백테스트**: 사용자가 스스로 고르고 완청한 콘텐츠를 고르기 직전으로 되감은 세계에서 정규 순위 몇 위였나(Hit@2/5/10·MRR, 인기순·무작위 기준선) ② **편성분 지표**: 고갈률·주제 다양성·편성분 내 거리·신규·미노출·커버리지·사용자 간 겹침·자동 확장 분포 ③ **페르소나 7종 N일 시뮬레이션**(cold-start·focused·negative·outside-listener·series-follower·heavy·remover — 카탈로그 구조에서 고르므로 어떤 스냅샷에서도 같은 정의) ④ **불변식 7개**(관심 밖 정규 편성 없음·본 것 재편성 없음·중복 없음·시리즈 순서·플랜 편수·해제 주제 탐험 제외·자동 확장이 직접 고른 주제 보존)
- 판정: 불변식·페르소나 검사는 절대 기준, 지표는 기준선 대비(`PASS_CRITERIA` 초기값). 마크다운 요약을 PR에 붙인다
- CI 게이트: `eval-runner.spec.ts`가 PR마다 합성 카탈로그(주제 6×콘텐츠 14, 시드 고정) 위에서 불변식·hard 검사를 돌린다
- 문서: `docs/backend/recommendation-evaluation.md`(지표 정의·통과 기준·배포 전 체크리스트·한계) — KAN-104의 대안 비교도 이 형식·기준으로

**첫 실행에서 발견한 것** — `series-follower` 검사 실패: 시리즈 1편을 완청한 콜드스타트 사용자에게 2편이 정규 19위(0.528 vs 1위 0.761). `drip-scheduling.md` 4.2 ③ "강한 가점"·완료 조건 "2편 우선 적립"과 달리 코드는 `seriesContinuity` 가중치 0.1(전체의 약 3.5%)뿐이다. 코드를 맞출지 명세를 낮출지 팀 결정 대기 — 그때까지 `soft`(경고)로 둔다

**남은 것** — 운영 스냅샷으로 첫 기준선 리포트 만들기(관리자 토큰으로 curl — 3.1). 어드민 웹 [스냅샷 내려받기] 버튼은 후속 티켓 후보
