## 요청

구글 플레이 결제·애플 인앱 결제를 뚫는다 — 스토어 상품 등록, 서버 영수증 검증(`features/subscription.md`), 구독 상태 반영·복원, 샌드박스/테스트 트랙에서 결제 성공까지.

## 완료 조건

- Given 샌드박스 계정, When iOS·Android 에서 구독을 결제하면, Then 서버가 영수증을 검증하고 구독 상태가 반영된다
- Given 재설치, When 구매 복원을 하면, Then 구독 상태가 돌아온다

## 처리 기록

- **2026-10-10 — 반영(반영 날짜 2026-10-10).** 기술 원본은 KAN-40(`subscription-receipt-verification.md`)이고 이 티켓과 같은 작업이다. 서버 구현 #1090(계약) · #1097(iOS) · #1114(Play), 스토어 상품 등록(iOS — KAN-155 기록의 dev 앱 상품 2개 · Android — KAN-130 Play Console 상품 2개 활성·`plans` 매핑).
  | 완료 조건 | 근거 |
  |---|---|
  | 샌드박스 계정으로 iOS·Android 결제 → 서버 영수증 검증·구독 상태 반영 | **iOS** — KAN-157(2026-10-10, 개발계 앱 1.2.0(44) · Apple 샌드박스 테스터): ② 시트에 Sandbox 표시, 승인 뒤 구독 중 · ④ 해지 예약/재개 반영 · ⑦ "N월 N일부터 Daily" · ⑧ 강제 종료 뒤 미완료 거래 회복 · ⑨ 만료 뒤 무료 전환. **Android** — KAN-130(2026-10-08, 라이선스 테스터): 구매 → 행 생성·`users.tier` 반영·확인(acknowledge), 갱신·취소·환불까지 서버 상태 확인 |
  | 재설치 → 구매 복원 → 구독 상태 복귀 | **iOS** — KAN-157 ⑤ 삭제·재설치·같은 계정 로그인 뒤 구독 중, [구매 복원]도 "복원 완료" 정상, ⑥ 다른 계정 복원은 409 거부. **Android** — KAN-130 재설치 뒤 [구매 복원] → `restored: 1`, 기존 행에 연결 |
- KAN-157에서 무료 제공 프로모션 때문에 확인하지 못한 ② 결제 뒤 자동 재생 · ⑨ 페이월 재노출은 앱 화면 동작이라 이 티켓 조건 밖이다 — 프로모션 종료 뒤 재확인(KAN-157 기록).
