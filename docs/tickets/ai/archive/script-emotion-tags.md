## 배경

- **기반은 있다.** TTS 모델 `eleven_v3`는 대괄호 오디오 태그를 읽는다. `spec/06` 5장에 규격이 있다 — 확인 태그 7개(`[curious]` `[surprised]` `[sighs]` `[exhales]` `[laughs]` `[whispers]` `[excited]`), 턴당 최대 1개 수준, 속도·정지는 태그로 조절하지 않는다. 정규화는 태그를 보존하고(`tts/normalize.ts`) 자막은 태그를 뺀다(`tts/segments.ts`).
- **실제 대본에는 없다.** 대본 지침에 태그 규칙이 없어 모델이 넣지 않는다 — full-v6 무렵(2026-09 초) 편당 1개 남짓에서 **full-v7 이후 약 150편 태그 0개**, CS 시리즈 16편도 0개(2026-10-07 실측). 음성이 감정 없이 평평하게 읽힌다.

## 무엇을 한다

1. **파일럿** — 한 편의 일부 구간을 태그 있음·없음으로 합성해 윤아·이음 보이스에서 태그가 자연스럽게 먹히는지 듣는다(`spec/06` 5장 "파일럿에서 보이스별 반응 확인"). 반응 없거나 어색한 태그는 목록에서 뺀다
2. **방식** — 대본이 QA·비평을 통과한 뒤, TTS 직전의 **별도 단계**에서 텍스트 모델이 문장은 그대로 두고 태그만 끼운다. 대본 규칙·QA·L0 에 영향을 주지 않고, 직접 쓴 시리즈 대본에도 같은 단계를 쓴다
3. **규칙 자산** — 쓸 태그 목록 · 턴당·편당 상한 · 쓰는 자리(진행자의 리액션·놀람, 해설의 한숨 등)를 DB 자산으로 둔다
4. **코드 검사** — 태그를 뺀 본문이 확정 대본과 같은지(문장이 바뀌지 않았는지) · 목록 밖 태그 · 상한을 확인한다
5. **적용 범위** — 새로 TTS 하는 편부터. 기존 발행분은 재합성·재발행이 필요하고 청취자 재생 위치가 초기화되므로(`admin-api.md` 4.10) 파일럿 뒤 따로 정한다
6. `ai/spec/06-audio.md` 5장 갱신

## 완료 조건

- Given 파일럿 / When 태그 있음·없음 합성본을 듣는다 / Then 쓸 태그 목록과 상한이 확정돼 `spec/06` 5장에 적혀 있다
- Given 새로 TTS 하는 에피소드 / When 합성 입력을 본다 / Then 확정 목록의 태그가 상한 안에서 들어 있고, 태그를 뺀 문장은 확정 대본과 같다
- Given 같은 에피소드 / When 앱 자막을 본다 / Then 태그 글자가 보이지 않는다
- Given 기존 발행분 / When 처리 기록을 본다 / Then 적용 여부와 사유가 적혀 있다
