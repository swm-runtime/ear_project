## 무엇을 한다

에피소드 오디오의 **맨 앞에 인트로 효과음, 맨 뒤에 아웃트로 효과음**을 붙인다. 지금은 대사 앞뒤로 **디지털 무음 2초**만 있어서(`assemble`의 `leadSec`·`tailSec` 기본 2) 재생을 누르면 아무 신호 없이 바로 대사가 시작된다. 매 편 같은 자리에서 같은 소리가 나야 "이어의 콘텐츠"로 읽힌다.

현재 조립 순서는 이렇다:

```
[앞 무음 2s] → 세그먼트 연결(요청 사이 이음새 처리) → [뒤 무음 2s] → 라우드니스 정규화
```

여기에 인트로·아웃트로가 들어갈 자리를 정하고, 아래 결정 사항을 확정해야 한다.

## 결정해야 할 것

### 1. 음원을 어디서 구하는가

자체 제작 / 라이선스 구매 / 무료 라이선스 중 무엇인지. **상업적 이용 가능 여부와 출처를 문서로 남겨야 한다** — 앱스토어 배포물에 들어가는 소리다. 로고 모션을 맡긴 전문가에게 함께 의뢰하는 안도 있다(브랜드 톤 일치).

### 2. 길이와 구성

- 인트로 몇 초, 아웃트로 몇 초인가
- 대사와 **겹치는가(페이드 아래로 깔림) 아니면 이어 붙이는가**. 겹치면 조립이 훨씬 복잡해지고 자막 시각도 어긋난다 — 이어 붙이기를 먼저 검토할 것
- 앞뒤 무음 2초를 **유지하는가 대체하는가**. 무음 2초는 "첫 음절이 잘리지 않게"가 목적이었으므로(2026-09-07 박수헌), 인트로가 그 역할을 대신하면 앞 무음은 줄여도 된다

### 3. 소급 적용 범위

**이미 발행된 에피소드에 넣을 것인가.** 새 편부터만 넣으면 목록에서 어떤 편은 효과음이 있고 어떤 편은 없다. 소급하려면 발행본 재조립 + 재업로드 + `script-segments.json` 재생성이 필요하고, 콘텐츠 버전이 바뀌면 **사용자의 재생 위치가 보존되는지** 확인해야 한다.

## 반드시 함께 처리할 것 — 자막 시각

`script-segments.json`의 시각은 **배포본(`dist.mp3`) 기준**이고, 계산에 **앞 무음 2초를 더하고 있다**(`segments.ts`, spec/06 7장). 인트로를 앞에 붙이면 **모든 자막이 인트로 길이만큼 밀린다.**

- 인트로 길이를 `assemble`과 `segments.ts`가 **같은 상수**로 읽게 한다. 한쪽만 고치면 자막이 통째로 어긋나고, 어긋난 자막은 없는 것보다 나쁘다(spec/06 7장의 기존 판단과 같은 이유).
- 소급 적용하는 편은 `script_align` 경로로 자막을 다시 뽑아야 한다(발행본을 강제 정렬에 넣는 방식이라 인트로가 포함된 파일을 넣으면 시각이 맞는다).

## 그 밖에 확인할 것

- **라우드니스 정규화 전에 붙인다.** 정규화 후에 붙이면 효과음만 음량이 튄다.
- 마스터(wav)·배포본(mp3 192k) 양쪽에 반영한다 — 재처리는 항상 마스터에서 한다는 규칙을 깨지 않게.
- 효과음 원본은 저장소가 아니라 프롬프트 자산과 같은 경로(운영 DB / 파이프라인 S3)에 둘지, 워커 번들에 넣을지 정한다.

## 완료 조건

- Given 새 에피소드를 합성한다 / When 배포본을 처음부터 재생한다 / Then 인트로 효과음이 먼저 나오고 이어서 대사가 시작된다
- Given 같은 에피소드를 끝까지 재생한다 / When 마지막 대사가 끝난다 / Then 아웃트로 효과음이 나오고 끝난다
- Given 그 에피소드의 `script-segments.json`을 앱에서 본다 / When 자막을 따라 읽는다 / Then 인트로 길이만큼 밀린 시각이 실제 발화와 맞는다(어긋남 ±0.3초 이내)
- Given 효과음이 들어간 배포본의 라우드니스를 측정한다 / When 효과음 구간과 대사 구간을 비교한다 / Then 효과음이 대사보다 튀지 않는다
- Given 음원의 출처·라이선스를 묻는다 / When 문서를 연다 / Then 상업적 이용 가능 여부와 출처가 적혀 있다
- Given 소급 적용 범위를 결정했다 / When 이 문서를 연다 / Then 그 결정과 사유가 적혀 있다
