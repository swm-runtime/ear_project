## 문제

글로벌판의 유일한 입구는 주제 기획이고, 노트북 워커 없이 서버 워커가 처리한다(명세 4.4). 그런데 서버의 OpenAI 실행기는 단발 호출만 지원하고 도구가 필요한 작업(웹 검색)을 거절한다. 한국판은 그래서 주제 기획·보강을 노트북 Claude 워커만 집는다. 이 상태로는 글로벌판에서 후보가 하나도 생기지 않는다. 또 게이트 1 자동 승인을 끄고 도메인 판정 완료를 승인 조건으로 거는 일, 한 편에 주제 2개를 붙이는 칸도 어느 티켓에도 없다.

## 요청 내용

1. **OpenAI 실행기 웹 검색** — 제공자는 OpenAI로 확정(2026-10-14). 단발 호출 + OpenAI 웹 검색 도구로 주제 기획(B-②)·보강(B-①)을 서버 워커가 처리한다. 검색 8회 상한은 실행기가 센다. 결과는 링크·제목·스니펫만 스키마로 받고, 검색 요약 텍스트는 근거로 쓰지 않는다. 가용 모델은 구현 시 확인하고 기본은 한국판 서버 기본값(`gpt-6.1-sol`).
2. **검색 결과 코드 필터** — 차단·보류 도메인, robots 불허, 이미 판정된 배제 도메인을 빼고 남은 것만 적재한다. 제공자의 도메인 제외 옵션은 함께 쓰되 그것만 믿지 않는다. 풀 밖 도메인은 `candidate` 행으로 등록한다.
3. **배제 주제 입력 거부** — 명세 2.1(실존 인물 사안·진행 중 정치/군사 현안·홍보성)에 해당하는 기획은 작업을 만들지 않고 사유를 보인다.
4. **보조 주제 칸** — `backlog`에 NULL 허용 칸을 더한다(공유 마이그레이션 — 한국판 행은 NULL). 주제 기획 입력은 주제 1~2개(첫째가 대표).
5. **게이트 1 승인 조건**(`en` 인스턴스) — 소스 도메인 중 `candidate` 0건 · 뼈대 소스가 1군 · 배제 주제 아님 · 빈 역할·소스 겹침 경고가 있으면 사람 확인 기록. 조건이 안 되면 [승인]을 막고 판정 대기 도메인 목록·판정 링크를 보인다.

## 범위 밖

한국판 주제 기획·보강을 서버로 옮기는 일 — 한국판은 그대로 노트북 워커가 집는다

## 완료 조건

- Given 노트북 워커 없이 글로벌 서버 워커만 켜져 있다 / When 주제 기획 1건을 넣는다 / Then 후보가 먼저 `held`로 생기고, 검색 8회 이내로 소스가 적재되며, `proposed` 또는 `held` + `gaps`까지 완주한다
- Given 검색 결과에 차단·보류 도메인이 섞여 있다 / When 적재한다 / Then 그 결과가 빠지고 나머지만 적재된다
- Given 배제 주제를 기획한다 / When 입력한다 / Then 작업이 생성되지 않고 배제 사유가 표시된다
- Given 후보 소스 중 `candidate` 도메인이 있다 / When 게이트 1 승인을 시도한다 / Then 승인되지 않고 판정 대기 목록이 표시된다
- Given 한국판 백로그 행 / When 보조 주제 칸 마이그레이션을 적용한다 / Then 기존 행의 값·동작이 바뀌지 않는다
- Given 한국판 서버 워커 / Then 도구가 필요한 작업의 처리 방식이 종전과 같다(한국판 범위 밖)

  - 작업 집기: `claimJob` 의 도구 작업 허용이 `executor !== "openai" || en` — 한국판 값은 종전과 같다.
