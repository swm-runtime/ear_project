## 요청

1.2.0 운영 배포 뒤, **운영계에서 결제를 마지막으로 테스트**한다(PM 2026-10-12).

- 결제창은 OTA 로 일반 사용자에게 가려 두고 **관리자 계정에만 열린 상태**에서 테스트한다
  - 2026-10-15 정정: iOS 는 2026-10-12 KAN-180(첫 구독 상품 심사)으로 결제창을 **전원에게 열었다**. 관리자 게이트는 구현되지 않았다(`main` `feature-flags.ts`). 그래서 운영 App Store 앱에서 일반 계정으로 실결제 테스트했다
- 테스트를 통과하면 FE 가 OTA 로 사용자에게 연다(선행 티켓의 4번)
- **플랫폼은 iOS 로 적었다** — PM 요청 원문엔 플랫폼이 없고, 같은 날 박준현 티켓이 Android 라 나눠 맡는 것으로 읽었다. 다르면 PM 이 고친다

## 완료 조건

- Given 운영 앱의 관리자 계정(iOS), When 요금제를 구매하면, Then 서버에 구독이 반영되고 재생 한도가 구독 등급대로 바뀐다
- Given 같은 구독, When 해지·교체·갱신 알림이 오면, Then 서버 상태가 App Store 와 같다
- Given 테스트 결과, When 처리 기록을 보면, Then 항목별 통과·실패와 실패 시 원인이 적혀 있고, 사용자 오픈 가능 여부를 PM 에게 알렸다

## 테스트 계획 (2026-10-15)

iOS 1.2.0 (16)과 첫 구독 상품 2개가 심사를 통과했다(사용자 확인 2026-10-15). 그래서 **App Store 설치본으로 실결제**한다. TestFlight 설치본은 샌드박스라 이 테스트에 쓰지 않는다. 개발계 샌드박스 테스트(KAN-155 ①~⑦)와 같은 흐름이고, 다른 점만 적는다.

- **준비**
  - 기기: App Store에서 받은 1.2.0 (16). 결제는 기기의 실제 Apple ID로 나간다.
  - 앱 계정: 이메일 인증을 마친 운영 계정 A(요청자 본인 계정)·B(⑥ 전용). 결제와 복원은 인증된 이메일이 필요하다(`EMAIL_REQUIRED_FOR_PURCHASE`).
  - 서버 확인: 운영 로그·DB를 백엔드(박준현)가 보거나, 요청자가 운영 조회 스크립트로 본다. 결과는 건수와 `user_id`까지만 적는다.
- **비용**: Daily 3,900원 + Pro 업그레이드 9,900원. Daily 잔여분은 Apple이 비례로 정산한다. 마지막 ⑦에서 환불을 요청한다.
- **운영에서 못 보는 것**: 갱신(`DID_RENEW`)은 한 달 뒤라, 개발계 샌드박스(KAN-155 ②)에서 확인한 것으로 갈음한다. 만료(`EXPIRED`)도 같다.

| 순서 | 할 일 | 기대(앱) | 기대(서버) |
|---|---|---|---|
| ① | 계정 A · 페이월 → **Daily** 구독 → 시트 승인 **직후 앱 강제 종료** → 재실행 | 자동으로 구독 중(Daily), 한도 하루 5편 | `purchase applied` · 구독 행 `environment = production` · `tier = daily` · `SUBSCRIBED` 알림 |
| ② | 요금제 변경 → **Pro로 업그레이드** | 즉시 Pro, 무제한 | 업그레이드 알림 처리 · `tier = pro` |
| ③ | 요금제 변경 → **Daily로 다운그레이드** 예약 → 다시 Pro 선택 | 예약 중 "다음 결제일부터 Daily" 표시, Pro 혜택 유지 → 예약 해제 | `pending_tier = daily` → 해제 뒤 null · `tier = pro` 유지 |
| ④ | [구독 해지] → App Store 구독 관리에서 자동 갱신 끄기 | "N월 N일까지 이용 가능해요" + [구독 다시 시작], Pro 혜택 유지 | `DID_CHANGE_RENEWAL_STATUS`(자동 갱신 끔) · `tier = pro` 유지 |
| ⑤ | 앱 삭제 → 재설치 → 계정 A → [구매 복원] | "구독이 복원되었어요" | `purchases restored` `restored: 1` |
| ⑥ | 계정 B로 로그인 → [구매 복원] | 409 "이미 다른 계정에서 사용 중인 구독이에요" | `SUBSCRIPTION_OWNED_BY_ANOTHER_ACCOUNT` · 계정 B는 `light` 유지 |
| ⑦ | reportaproblem.apple.com에서 환불 요청 — 승인 여부와 시점(최대 48시간)은 Apple이 정한다 | 승인되면 무료로 돌아가고 페이월이 다시 보인다 | `REFUND` 알림 → 즉시 `tier = light` |

- 끝나면 항목별 통과·실패와 원인을 아래 처리 기록에 적고, PM에게 사용자 오픈 가능 여부를 알린다.
- 테스트 구독은 실결제라 운영 매출·구독 통계에 잡힌다. 지울지, 표시만 할지 백엔드와 정한다.

## 처리 기록
- 2026-10-15 테스트 실행 — 운영 App Store 1.2.0 (16), 실결제, 계정 A = 요청자 본인 계정. 결과는 **앱 화면 기준**이다. 서버 로그·DB 대조는 하지 않았다.

  | ⑥ 계정 B 구매 복원 → 409 | 통과 |
