## 무엇을 한다

시리즈 콘텐츠의 제작 쪽 구현(PRD FR-13 "분할된 편은 시리즈로 묶어 순서를 유지한다").

- 한 주제를 몇 편으로 나눌지(분할 기준·편수 상한), 편 사이 연결(이전 화 요약·다음 화 예고)
- 대본·QA·패키지 단계에서 시리즈 메타(`series_id`·`episode_no`·`total_episodes`)를 싣고 발행
- `docs/ai/`에 시리즈 제작 절차 추가

## 완료 조건

- Given KAN-128 완료 / When 이 티켓을 다시 잡는다 / Then 중요도·기한이 범위에 맞게 갱신돼 있다
- Given 시리즈 주제 하나 / When 파이프라인을 돌린다 / Then 정해진 편수의 에피소드가 같은 `series_id`와 연속 `episode_no`로 발행된다
- Given `docs/ai/` / When 시리즈 제작을 찾는다 / Then 분할 기준과 절차가 적혀 있다

## 처리 기록

### 2026-10-09 — 제작 범위 결정 · 설계 확정 (구현 대기)

- **결정(박수헌)**: ① 시리즈는 **기획 시리즈만** — 처음부터 N편으로 기획한 주제. 군집 분할(spec/03 5.1)은 독립 편으로 둔다 ② 편 사이는 **회상 + 예고**로 잇는다 ③ 기존 CS 키워드 시리즈 16편도 나중에 시리즈로 묶되, **시리즈 시스템은 지금 도입하지 않는다** — 그 전에는 시리즈 필드를 실어 발행하지 않는다(서버 드립이 이미 `series_id`로 편성 순서를 바꾼다)
- **설계**: `ai/spec/11-series.md` — 설계안·게이트 S(편수 확정) → 편별 B-② 후보(`series_id`·`series_no`, 형제 편 소스 겹침은 자동 승인 예외) → 대본(별도 자산 `skills/draft/series.md`, 인트로 시리즈 줄·회상(해설 턴)·예고(고정 슬롯, 다음 화 제목을 워커가 채움)·연결 재료는 claims `시리즈` 행) → L0 시리즈 검사 → 순서 발행. 데이터(`series` 테이블·backlog 2칸)·콘솔(`/series`)·구현 순서 9단계
- **확인한 사실**: 서버 업로드는 시리즈 필드를 이미 받는다(`series_id` uuid — 파이프라인이 만든다 · `episode_no`·`total_episodes` 필수 · 번호 ≤ 총 편수). 시리즈 필드는 업로드 뒤 못 바꾼다(`admin-api.md` 4.10). 콘솔은 지금 시리즈 필드를 보내지 않는다 — CS 16편은 단일 콘텐츠로 올라가 있다
- **KAN-128(PM)에 넘길 미결**: 편수 상한 · 시리즈 이름 저장·표시(제품에 이름 칸 없음) · 기존 16편 전환 방식(회수·재업로드는 담기·재생 기록이 끊긴다 — BE 일회성 시리즈 지정 API 안) · 발행 단위 · 한 편 회수 처리. 썸네일 통일 여부는 AI 쪽 결정
- **같은 날 서비스 쪽 결정(박수헌 전달)**: 탐색에서 시리즈는 한 요소 — 누르면 편 목록 · "다음 화 듣기" 보류 · 시리즈 표지 = 1화 썸네일(spec/11 미결 #5 해소). BE 설계 제안(`series` 테이블 · 관리·지정 API · `GET /series/:id` · 탐색 묶음 · 드립 순서 보정)은 BE 티켓 `backend/pending/series-backend.md`(KAN-134)에 적었다
- **발행 결정(박수헌)**: 전 편 준비 뒤 [시리즈 발행]으로 한꺼번에 · 검수는 편마다 · 서버 시리즈 등록은 발행 시점 · 발행 뒤 문제 편은 회수하지 않고 고쳐서 재발행(회수는 시리즈 전체) · 콘텐츠 제목 `{시리즈 이름} N - {편 제목}`(시리즈 이름을 따로 보여 줘도 유지). spec/11 7장·미결 #4·#6 해소
- **CS 16편(박수헌)**: 시리즈로 묶을 때 대본은 그대로 둔다 — 회상·예고 없는 예외, 재합성 안 함(spec/11 미결 #3)
- **시작 경로(박수헌)**: 관리자가 시작한다 — 입구는 [주제 기획] 화면의 "단일 편 / 시리즈" 선택. 군집화 제안·단일 편 확장 경로는 두지 않고, AI 시리즈 주제 제안은 몇 개 운영한 뒤 더한다(spec/11 1장·미결 #7)
- **다시 잡을 때**: KAN-128 완료 → 이 표의 중요도·기한 갱신 → spec/11 10장 순서로 구현
