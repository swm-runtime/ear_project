## 절차 — 운영 콘솔 발행 목록

1. **선행 확인**(아래) — provider 가 `openai` 가 아니면 시작하지 않는다. stub 벡터는 [반영]이 임베딩을 빼고 메타만 올리므로 소급이 반쪽이 된다.
2. 대상 18행마다 **[다시 뽑기]** — 워커가 순차로 대본 기준 메타 5종을 다시 판정한다(편당 1~2분, LLM 비용 $0.1~0.3 → 18편 $2~5). 한 번에 다 넣어도 된다. 20~40분 잡는다.
3. 배지가 준비로 바뀐 행마다 **[반영]** — `enrichment_file` **단독 PATCH**. 콘텐츠 버전은 오르지 않고 재생 위치가 보존된다(`admin-api.md` 4.10) — 사용자 영향 없음. **임베딩은 이 순간 웹이 AI 서버에서 받아 파일에 합친다**(`pipeline/apps/web/lib/embedding.ts`). 서버는 `content_embeddings` 행을 현재 모델·현재 `content_version` 으로 **통째로 교체**하므로 12번(구버전 행)도 이걸로 고쳐진다.
4. 반영 메시지 `반영됨 — v2 · <임베딩 노트> · 콘텐츠 버전 N 그대로` 를 확인한다. 임베딩 노트가 "임베딩 없음 — …" 이면 그 편은 임베딩이 안 실린 것이다 → 처리 기록에 사유를 적는다.

**"구형·없음 메타만" 필터에는 이 18편이 걸리지 않는다** — 필터가 `enrichment_schema_version` 만 보고 18편 전부 v2 이기 때문이다. 그래서 [전부 다시 뽑기] 버튼도 뜨지 않는다. 행별로 한다(개선은 "범위 밖").

## 판정 규칙 — 억지로 채우지 않는다

- 다시 뽑아도 `target_audiences` 가 비면 **범용 대본 판정**이다. 그대로 둔다(`metadata-pipeline.md` 4.2 — "직군 무관·연차 무관인 범용 대본은 억지로 좁히지 말고 키를 생략한다"). 스코어링에서 항목이 빠질 뿐 불리해지지 않는다. 단, 결과를 처리 기록에 남긴다 — 15편이 다 비어 있는 상태로 다시 나오면 판정 프롬프트 쪽 문제일 수 있다(그때는 별도 티켓).
- 5번의 난이도가 다시 판정 불능이면 NULL 그대로.
- [반영]이 **거부됨**이면 사유를 처리 기록에 적고 다음 편으로 넘어간다. 그 편은 백엔드(박준현)가 검증 코드(`enrichment-file.ts`)를 본다.

## 검증 (소급 직후 · 백엔드)

운영 DB 에서 아래를 돌려 `emb_cur` 가 26편 전부 1 인지 본다. 발행 전 조회에서는 14 였다.

```sql
select left(c.title,30) title,
  coalesce(jsonb_array_length(c.target_audiences),0) ta,
  (c.difficulty is not null)::int d,
  (select count(*) from content_embeddings ce
    where ce.content_id=c.id and ce.model='text-embedding-3-small'
      and ce.content_version=c.content_version) emb_cur
from contents c where c.status='published' and c.withdrawn_at is null
order by emb_cur, ta;
```

소급 다음 날 05:00 편성 배치 뒤 콘솔 추천 검증 페이지에서 "임베딩 없음" 표시가 없어졌는지 본다.

## 범위 밖

- 발행 목록 필터를 "임베딩 없음·청자 없음"까지 넓히고 [전부 다시 뽑기]가 그 대상에도 뜨게 하는 것 — 100편/월이 쌓이면 필요해진다. 별도 티켓.
- 판정 프롬프트(`docs/ai/skills`)의 `target_audiences` 생략 기준 조정 — 이번 결과를 보고 판단.
- 추천 스코어링 코드 — 결여 축 재정규화는 그대로 둔다.

## 완료 조건
