## 왜

짧은 길이와 새 도입 훅이 완청률을 올리는지 본다. 같은 편의 두 버전을 동시에 내보내는 구조가 없어(별도 콘텐츠·변형 태그·BE 분할 — L) **순차 비교**로 한다: 새 기준으로 만든 편과 기존 편의 완청률을 비교한다(길이별 완청률 차트 `backend-logs/experiments` 기존).

## 무엇을 한다

- 길이: KR 13분 하한이 코드 여러 곳에 박혀 있다(설계 프롬프트 13분 거절·26분 분할, 작성 목표 분×341자, L0 4,300자, `series.ts`). 영어 트랙 `MIN_MINUTES_EN`(script-length.ts) 방식으로 KR 목표·하한을 설정값으로 뺀다.
- 짧은 길이에 맞춰 섹션 수·소스 규칙(4~6섹션, 섹션당 2+ 소스)과 비평 루브릭 구조 비율·길이 상한을 조정한다.
- 도입 훅: 콘솔 템플릿·가이드라인(13) 수정 — 코드 없음. 콜드오픈 부활은 별도 결정.
- 비교 설계(대상 편, 기간, 지표 — 완청률·초반 이탈)를 처리 기록에 남긴다.
- `ai/spec` 수정은 `changes/pending`에 기록.

## 결정 (2026-10-29)

- 길이를 **하한 5분 ~ 상한 12분**으로 크게 줄여 테스트한다(현행 목표 15분·하한 13분·26분 분할).
- 비교 기간·편수와 도입 훅 방향은 담당자가 정해 처리 기록에 남긴다(권장: 새 기준 편 10편 이상, 2주).

## 범위 밖

- 동시 A/B(BE 사용자 분할·변형 연결).
- 기존 발행분 재녹음.

## 완료 조건

- Given 새 길이 설정 / When 대본을 만든다 / Then 설정한 목표 길이로 만들어지고 L0·QA·비평을 통과한다

- Given 비교 기간 종료 / Then 새 기준 편과 기존 편의 완청률 비교가 처리 기록에 남는다
