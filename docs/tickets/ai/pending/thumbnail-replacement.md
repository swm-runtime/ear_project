## 무엇을 한다

1. 새 썸네일 스타일·규칙 확정 — 톤·구도·텍스트 유무·주제별 일관성
2. 파이프라인 썸네일 생성 프롬프트·후처리 갱신
3. 이미 발행된 콘텐츠 썸네일 일괄 교체 — **오디오를 건드리지 않는 경로**로(재발행으로 `contentVersion`이 바뀌면 사용자 재생 위치가 초기화된다 — `player-api.md` 4.3)

## 완료 조건

- Given 새 규칙 / When `docs/ai/`를 본다 / Then 썸네일 스타일·규칙이 적혀 있다
- Given 새로 발행한 콘텐츠 / When 썸네일을 본다 / Then 새 규칙대로 생성돼 있다
- Given 기발행 콘텐츠 / When 교체 후 앱에서 본다 / Then 썸네일만 바뀌고 사용자 재생 위치는 유지된다

## 처리 기록

- **2026-10-07 진행 — 1·2번 반영, pending 유지** (브랜치 `feat(ai)/thumbnail-scene-d`)
  - 1 새 기준(박수헌 확정): **장면 방식 + 무광 점토 3D + 코드 코너 삼각형**. 지금 썸네일(thumb-v3 + 앵커)은 오브젝트 하나를 은유로 그려 발행 40편에서 소재가 겹쳤다(토글 3·깔때기 2·옆얼굴 5, 회색·크림 한 톤 — 앵커가 색까지 고정). 시안 비교(`pipeline/.work/thumb-test/`): 화풍은 A 종이 디오라마·B 플랫·C 리소그래프·D 무광 3D·E 구아슈·시네마틱·고흐풍, 테마는 에디토리얼 컨셉·아이소메트릭·위에서 본 정물 → D. 장면은 손으로 쓴 것과 자동화(텍스트 모델) 결과를 같은 구조로 비교했다
  - 코너 삼각형: 모델이 그리지 않고 코드가 얹는다 — 두 변 30% · 대분류 색 · 흰 경계선 없음 · 빗변 바깥 검은 그림자 S2(28px@1024, 20%). 원본 대비 ΔE 를 기록하고 20 미만이면 경고
  - 2 생성 단계: 장면 쓰기(자산 `skills/thumbnail/scene.md` scene-v1, gpt-5.6-terra) → 이미지(자산 `prompt.md` thumb-v4, 앵커 없음, 금지 소재·보호 표장 명시 — 10편 시험에서 뇌 조형물·적십자가 끼어들었다) → 합성(`thumbnail-compose.ts`). 활성 프롬프트에 `{장면}` 칸이 있을 때만 새 경로 — 자산만으로 켜고 끈다(`spec/07` 1-1)
  - 1 의 문서화: `ai/spec/07-publish.md` 1-1 · 자산 머리말
  - 남은 것: 배포 뒤 자산 활성화(thumb-v4·scene-v1) → 새 발행분부터 적용. **3 기존 발행분 교체는 결정 대기** — 썸네일만 재발행해도 `content_version` 이 오르고 재생 위치가 지워진다(`admin-api.md` 4.10). 선택지: 백엔드에 썸네일 단독 재발행의 버전 유지 요청 / 위치 초기화 감수하고 교체 / 새 발행분만. 완료 조건 3("재생 위치는 유지")은 첫째 선택지가 아니면 성립하지 않는다
