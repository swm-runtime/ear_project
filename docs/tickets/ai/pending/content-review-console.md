## 요지 (Jira 본문용)

- 발행 목록 · 발행 상세에 편별 후기 수 · 평균 · 1~5 분포 · 글 수
- 후기 글 목록 화면(편별 · 최신순 — 별점 · 글 · 작성 서비스 날짜 · 시장 · 완청 여부 · `content_version`)
- 작성자 계정은 받지도 그리지도 않는다. 원문은 Supabase · Slack에 복사하지 않고 매번 admin API로 읽는다
- 서비스 지표에 후기 참여 프로모션 발급 · 사용 · 소멸 건수
- 저평점 편의 글은 판정→규칙 승격 루프의 재료 — 자동 반영 없음
- 상세 · 완료 조건은 원본 문서

## 요청

**운영자가 편별 후기를 보고 파이프라인 규칙 개정 후보를 찾을 수 있게 콘솔에 후기 화면을 붙인다**(기획 KAN-278 · `content-review.md` 4.7).

1. **발행 목록 · 발행 상세** — 편별 후기 수 · 평균 · 1~5 분포 · 글 수. 평균은 표본이 작을 때(예: 5건 미만) 흐리게 — 숫자 하나로 판단하지 않게
2. **후기 글 목록** — 발행 상세 안에서 그 편의 글을 최신순으로. 별점 · 글 · 작성 서비스 날짜 · 시장 · 완청 여부 · `content_version`(재발행 전후 구분 표시)
3. **개인정보** — 작성자 계정(`user_id`) · 닉네임은 API가 주지 않고 콘솔도 그리지 않는다. **원문을 파이프라인 Supabase에 저장하지 않는다**(캐시 테이블 · `runs` 기록 포함). 화면 렌더에만 쓰고 로그에 남기지 않는다
4. **서비스 지표** — 후기 참여 프로모션 발급 · 사용 · 소멸 건수(건수만)
5. **운영 절차 메모** — 판정→규칙 승격 루프(3편 단위 검토)에 저평점 편의 글을 읽는 단계를 더할지는 이 화면이 붙은 뒤 정한다. 지금은 화면까지만

## 완료 조건

- Given 후기가 있는 발행 편 / When 발행 상세를 연다 / Then 후기 수 · 평균 · 분포 · 글 수와 글 목록이 보인다
- Given 후기 글 목록 / Then 작성자 계정 · 닉네임이 화면에도 네트워크 응답에도 없다
- Given 후기를 본 뒤 / When Supabase를 확인한다 / Then 후기 원문이 저장된 행이 없다
- Given 재발행된 편 / Then 글마다 어느 `content_version`의 후기인지 구분된다
- Given 서비스 지표 / Then 프로모션 발급 · 사용 · 소멸 건수가 보인다
