## 무엇이 문제인가

PM 청취: 배포본 앞부분의 인트로가 원본 징글(`이어_인트로.wav`)보다 **많이 깨져 들린다.**

실측(2026-10-05, 파이프라인 S3 `datasets/channel-audio/intro.wav` ↔ 운영 배포본 앞 6초, 에피소드 2편):

| 비교 | 원본 대비 잔차 | 판정 |
|---|---|---|
| S3 징글 → 모노 → mp3 192k 인코딩**만** | −53.6 dB | 사실상 동일 — mp3 는 원인이 아니다 |
| 실제 배포본(`d23d7fed…` · `8576c419…`) | **−14.8 dB** | 귀로 들리는 변형 |

(잔차 = 배포본에서 "원본 × 최적 게인"을 뺀 나머지의 상대 크기. 모노 합치기 영향을 뺀 기준과 비교한 값이라, 모노 손실은 이 수치에 **더해진다**.)

## 원인

1. **징글을 모노로 합친다** — `fileToWav`가 `-ac 1`(`audio.ts` `fileToWav`). 이 징글은 스테레오 폭이 아주 넓다:
   - 좌우 상관 **0.18**, 사이드 성분이 미드와 거의 같은 크기(−1.1 dB 차), 왼쪽이 오른쪽보다 7.6 dB 크다
   - 모노로 합치면 사이드 성분(소리의 절반 가까이)이 상쇄된다 — 에너지만 2.5 dB 준다. 원본에서 넓게 퍼지던 소리가 납작하고 비어 들린다
2. **징글까지 통째로 정규화한다** — `assemble`이 [인트로 + 본편 + 아웃트로]를 이은 **뒤** 1패스 `loudnorm=I=-16:TP=-1.5:LRA=11`을 건다.
   - 징글 원본은 조용해서(모노 RMS 약 −33 dB) **약 +12 dB 끌어올려지고**, 최대 레벨 −1.5 dB 리미터와 구간별 동적 게인에 눌린다 — 위 −14.8 dB 잔차의 대부분
   - 인트로 구간이 −15.7 LUFS, 본편이 −17.2 LUFS — 징글이 목소리보다 크다
3. (본편에도 해당) **1패스 `loudnorm`은 동적 모드다** — 파일을 읽으며 게인을 계속 바꿔, 말소리가 출렁이거나 쉼 뒤 바닥이 들뜰 수 있다

## 요청

1. **배포본을 스테레오로 낸다.** 목소리는 양쪽 채널에 같게, 징글은 원래 스테레오 그대로. 목소리가 모노라 같은 비트레이트(192k joint stereo)에서도 손해가 거의 없다. 마스터 wav 도 스테레오로 맞춘다
2. **정규화는 본편 목소리에만 건다.** 징글은 목표 음량(본편과 어울리는 크기 — 본편보다 크지 않게)에 맞춰 **한 번만** 조정해 두고, 조립 때는 처리 없이 그대로 붙인다
3. **본편 정규화를 2패스 `loudnorm` `linear=true`로 바꾼다.** 1패스에서 측정값을 받아 2패스에 `measured_I/LRA/TP/thresh/offset`을 넘겨, 전체에 고정 게인 한 번만 적용한다
4. `ai/spec/06-audio.md` 7장에 채널 수·정규화 대상·방식을 적는다
5. 이미 발행된 40편을 다시 렌더할지는 담당이 정한다(재렌더하면 `content_scripts` 자막 시각도 함께 교체된다 — 인트로 길이가 같으면 시각은 그대로)

## 재현

```bash
# 징글 원본(파이프라인 S3) 스테레오 폭
aws s3 cp s3://earcast-pipeline-prod/datasets/channel-audio/intro.wav .
# 배포본 앞 6초 vs 원본 모노×게인 잔차, mp3-only 대조군 — 측정 스크립트는 numpy 로 상관·잔차 계산
ffmpeg -i <배포본>.mp3 -t 8 -af ebur128 -f null -        # 인트로 구간 LUFS
ffmpeg -i <배포본>.mp3 -ss 8 -t 60 -af ebur128 -f null - # 본편 LUFS
```

## 확인하지 못한 것

- **NAS 원본(`이어_인트로.wav`)과 S3 사본이 같은지**는 확인하지 못했다. 스펙 06 7장은 "소리 구간에 페이드인 0.5초·페이드아웃 1초, 앞뒤 무음 1초로 정규화해 올린다"고 적고 있고 처리 스크립트(`pipeline/.work/upload-jingle.mts`)는 저장소에 없다. 원본 대비 S3 사본에 레벨·채널 변형이 있었는지 함께 확인한다.
- 아웃트로도 같은 경로(`fileToWav` → 전체 `loudnorm`)라 같은 영향을 받을 것으로 보지만 따로 재지 않았다.

## 완료 조건

- Given 고친 파이프라인으로 렌더한 에피소드 / When 앞 인트로 구간을 S3 징글 원본(스테레오)과 비교한다 / Then 채널이 스테레오로 유지되고, 원본×게인 대비 잔차가 −40 dB 이하다(mp3 대조군 수준)
- Given 같은 에피소드 / When 인트로 구간과 본편의 LUFS 를 잰다 / Then 인트로가 본편보다 크지 않다
- Given 같은 에피소드 / When 본편 정규화 로그를 본다 / Then 2패스 `linear=true`로 적용됐다(1패스 측정값이 2패스에 넘어갔다)
- Given `ai/spec/06-audio.md` 7장 / When 읽는다 / Then 배포본 채널 수와 정규화 대상·방식이 적혀 있다
- Given 이미 발행된 에피소드 / When 처리 기록을 본다 / Then 재렌더 여부와 그 사유가 적혀 있다
