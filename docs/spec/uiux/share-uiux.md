# 공유 UI/UX 명세서

> 기준 문서: [`docs/features/share.md`](../../features/share.md) · 진입점 자리는 [`docs/features/library.md`](../../features/library.md) 3 · [`docs/features/explore.md`](../../features/explore.md) 3 · [`docs/features/player.md`](../../features/player.md) 3 · [`docs/features/content-detail.md`](../../features/content-detail.md) 2·4.2, 수신자 상세 화면은 [`content-detail-uiux.md`](content-detail-uiux.md)
> 와이어프레임: [`docs/wireframe/share.html`](../../wireframe/share.html) (화면 ID SH1–SH3 — 시안의 제안 ID를 정식 채택, 2026-08-25)
> API: **없음.** 공유는 서버 엔드포인트가 P1에도 없다(`share.md` 4.1 · `explore-api.md` 1장 경계 표 — 텍스트·링크 조립은 클라이언트, 수신자 진입은 기존 단건 상세 조회 재사용). **`share-api.md`는 만들지 않는다.**

> **전체가 P1이다(FR-27 — MVP 미노출, README 결정 42·48).** MVP 빌드에서는 이 문서의 어떤 요소도 화면에 나타나지 않는다.

## 1. 범위

공유(FR-27) — **전용 화면이 없는 기능**이다. 진입점 네 곳([공유] 행·아이콘), OS 공유 시트에 전달하는 내용, 수신자 링크 진입의 화면 표현까지 `share.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 진입점·전달 내용·링크·수신자 처리·미기록 원칙은 `share.md`가 소유한다. 여기서 정하는 것은 **[공유]가 어디에 어떻게 보이고, 탭에 어떻게 반응하는가**다.

- **네 진입점의 동작은 완전히 동일하다**(`share.md` 2). 진입점마다 다시 정의하지 않는다 — 이 문서의 4.3(전달 내용)이 네 곳 전부에 적용된다.
- **OS 공유 시트는 앱 화면이 아니다.** 앱이 그리지 않고 커스터마이즈하지 않는다 — 앱이 정하는 것은 전달 내용뿐이다.
- 수신자가 도착하는 상세 화면의 구성은 `content-detail-uiux.md`(CD1~CD4)가 소유한다. 이 문서는 **진입 경로가 하나 늘었을 때 달라지는 것**(복귀 목적지)만 적는다.

```

     ※ 플레이어에서 공유해도 재생 유지. 어느 경로든 시트가 닫히면 열었던 화면으로 복귀

[받는 쪽]
공유 링크 탭 ─┬─ 앱 미설치 ─> 스토어 리다이렉트 (웹 — 앱 밖)
              └─ 앱 설치됨 ─> 실행 관문(splash.md — 버전·로그인·온보딩 판정, 우회 없음)
                    ├─ 관문 통과(온보딩 완료) ─> 콘텐츠 상세 (CD1/CD2 — 단건 재조회)
                    │      └─ 회수·만료·잘못된 링크 ─> 토스트 후 라이브러리로 이동 (CD4 변형)
                    └─ 미로그인·온보딩 미완 ─> 목적지 폐기, 정상 진입 분기 (안내 없음)
```

## 4. 화면별 명세

### 4.1 SH1 — 더보기 시트의 [공유] 행

**구성** — 기존 더보기 시트(대상 요약 + 액션 행 목록)에 **[공유] 행이 담기/제거류 아래에 추가**된다. 세 화면(라이브러리·탐색·플레이어)의 시트에 동일하게 들어간다.

- **행 순서** — 상세 정보 · 원문 보기(조건부) · 담기/제거(라이브러리는 삭제) · **공유**. 기존 항목의 순서·구성은 각 화면 uiux가 소유하고, 이 문서는 [공유]가 그 아래 온다는 것만 정한다.
- **아이콘은 OS 공유 관용 표현**(위로 나가는 화살표 계열)을 쓴다. 위험색이 아니다 — 파괴적 조작이 아니다.
- **모든 콘텐츠에 노출된다.** 조건부가 아니다 — [원문 보기]와 달리 값 유무 분기가 없고, 담김·재생·차감 여부와도 무관하다(`share.md` 2).
- 탭 → **더보기 시트가 닫히고 OS 공유 시트가 열린다**([상세 정보]와 같은 전이). 플레이어의 시트에서 탭해도 **재생은 유지**된다.
- **MVP 빌드에는 이 행이 없다.** 비활성으로 두는 것이 아니라 행 자체가 없다(`share.md` 2 — 이 조건이 다른 모든 규칙에 우선).

### 4.2 SH2 — 콘텐츠 상세 상단 바의 [공유] 아이콘

**구성** — 상세 화면(CD1·CD2) 앱바 우측에 [공유] 아이콘 버튼. 좌측 뒤로가기·중앙 타이틀은 그대로다.

- **조회가 성공해 상세가 그려진 상태(CD1·CD2)에서만 표시한다.** 로딩(CD3)·전면 에러에서는 그리지 않는다 — 전달할 제목·출처가 아직 없고, 반쪽 값으로 공유 내용을 만들지 않는다. CD4는 화면 자체를 그리지 않으므로 해당 없다.
- 탭 → OS 공유 시트. 전달 내용은 4.3 — 더보기 시트 경로와 **완전히 동일**하다.
- 아이콘 스타일·히트 영역은 다른 화면의 앱바 아이콘 버튼과 같은 규칙이다.

### 4.3 OS 공유 시트에 전달하는 내용 (SH3)

**전달 내용 = 텍스트 + 링크.** 네 진입점 공통이며, 진입점 화면이 이미 들고 있는 응답 값으로 조립한다(공유용 서버 호출 없음 — `share.md` 4.1).

| 요소 | 값 | 규칙 |
|---|---|---|
| 텍스트 — 제목 | `title` | 항상 |
| 텍스트 — 저자·출처 | `author_name` · `source_name` | **저자가 없으면(`author_name = null`) 출처만.** "저자 없음"으로 채우지 않는다(`content-detail.md` 4.3-1과 같은 조건부 생략) |
| 링크 | 그 콘텐츠의 상세 연결 링크 | `share.md` 4.2 — `content_id` 외의 값(사용자 식별자·토큰)을 싣지 않는다 |

- 텍스트의 줄바꿈·순서 형식은 **미확정**이다(6장 TODO — 시안 SH3은 "제목 / 저자 · 출처 / 링크" 세 줄 제안).
- **전송·취소 어느 쪽에도 앱의 후속 동작이 없다.** 토스트·기록·신호 적재 전부 없다(`share.md` 4.4).

### 4.4 수신자 진입 — 상세 화면 재사용, 복귀 목적지만 다르다

수신자가 도착하는 화면은 `content-detail-uiux.md`의 CD1~CD4 그대로다. 이 경로에서 달라지는 것은 하나 — **복귀할 원 화면이 없다.**

- 회수·만료·잘못된 링크: CD4와 같은 토스트("제공이 종료된 콘텐츠예요" — 기존 문자열 재사용)를 띄우되, 원 화면 복귀 대신 **라이브러리로 이동**한다(`share.md` 4.3 · `content-detail.md` 2).
- 정상 도착한 상세의 뒤로가기도 **라이브러리로** 간다 — 뒤로 갈 목록 화면이 없다.
- 미로그인·온보딩 미완: **"공유받은 콘텐츠" 안내 화면·배너를 만들지 않는다.** 목적지를 버리고 정상 진입 분기를 따른다 — 관문 통과 후에도 복원하지 않는다(`share.md` 4.3, 디퍼드 딥링크와 같은 이유).

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **더보기 시트 행** | SH1 | 각 화면 시트의 기존 행과 같은 문법. 위험색 아님 |
| **앱바 아이콘 버튼** | SH2 | 다른 화면 앱바 아이콘과 같은 규칙. CD1·CD2에서만 표시 |
| **OS 공유 시트** | 전달 | 시스템 컴포넌트 — 앱이 그리지도 닫지도 않는다 |
| **토스트** | 수신자 회수 안내 | "제공이 종료된 콘텐츠예요" — 기존 문자열·기존 규칙 재사용 |

- **공유에는 성공 피드백이 없다** — "사용자가 시작한 액션의 결과는 조용히 처리하지 않는다"(`content-detail-uiux.md` 5장)의 예외다. 전송 여부를 앱이 모르기 때문이며, OS 시트가 열린 것 자체가 조작에 대한 응답이다.

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 시트의 [공유] 행(행 전체 히트 영역), 상세 앱바의 [공유] 아이콘.
- **[공유]의 낭독 라벨은 동작이 드러나게** — 아이콘 단독 버튼(SH2)은 "공유"로 낭독한다. 시트 행(SH1)은 행 텍스트가 곧 라벨이다.
- **OS 공유 시트의 접근성은 OS 몫이다** — 앱이 개입하지 않는다. 앱의 책임은 시트가 열리기 전까지다.
- **공유 성공의 무피드백은 낭독에서도 무피드백이다** — 시트가 닫힌 뒤 상태 변화 낭독을 만들지 않는다. 그리지 않은 것은 존재하지 않는 것이다(`content-detail-uiux.md` 7장과 같은 원칙).
- 수신자 회수 안내 토스트는 조작(링크 탭)의 직접 결과이므로 `assertive` — CD4와 같은 규칙.

## 8. 금지 사항

`share.md`의 규칙이 명시적으로 금지했거나 곧장 따라 나오는 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

**노출·진입**

- **MVP 빌드에 [공유]를 노출하는 것** — 행·아이콘 자체가 없어야 한다. 비활성 노출도 금지다
- [공유]를 특정 콘텐츠에서 숨기는 것 — 조건부가 아니다. 담김·재생·origin과 무관하게 항상 노출한다
- 공유에 **페이월·확인 팝업**을 붙이는 것

**공유 실행**

- **자체 공유 UI**(수신 대상 선택·미리보기·커스텀 시트)를 그리는 것 — OS 시트에 위임한다
- 공유를 위해 **서버를 호출**하는 것 — 조립은 화면이 든 값으로 한다
- 전송·취소를 **추적하거나 피드백(토스트·신호 적재)을 만드는 것**
- 링크에 `content_id` 외의 값(보낸 사용자 식별자·토큰·캠페인 파라미터)을 싣는 것
- 공유 시점에 콘텐츠 상태를 **재검증**하는 것 — 수신자 쪽 판정이 거른다

**수신자**

- 실행 관문(버전·로그인·온보딩)을 **딥링크라고 건너뛰는 것**
- 미로그인·온보딩 미완 수신자에게 **목적지를 복원해 주는 것**(디퍼드 딥링크 포함)
- 수신자용 **별도 화면·배너**("OO님이 공유한 콘텐츠")를 만드는 것 — 도착지는 표준 상세 화면이다
- 수신자의 재생 판정을 **완화하는 것** — 수신자 자신의 티어·한도 그대로다

## 9. 미결 사항
