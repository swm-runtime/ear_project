# 프로필 UI/UX 명세서

> 기준 문서: [`docs/features/profile.md`](../../features/profile.md) · 이메일 인증 규칙은 [`docs/features/auth.md`](../../features/auth.md) 4.4~4.5, 커리어 편집 화면은 [`docs/features/career.md`](../../features/career.md), 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/profile.html`](../../wireframe/profile.html) (화면 ID P1–P10)
> API: [`profile-api.md`](../api/profile-api.md)

## 1. 범위

하단 탭의 프로필 화면 — 헤더(닉네임·제공자·설정 아이콘)와 **4개 카드(현재 플랜 · 이메일 · 관심 주제 관리 · 커리어 정보)**, 카드 아래의 **청취 통계 세 영역(요약 3지표 · 주간 그래프 · 주제 분포)**, 그 상태 변형과 로딩·오류까지 `profile.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 화면은 편집 로직을 갖지 않는다**(`profile.md` 1장). 관심사·커리어·이메일·구독의 저장 규칙은 전부 소유 화면의 것이고, 프로필은 **현재 값을 요약해 보여주고 소유 화면으로 보낼 뿐**이다. 청취 통계도 같다 — **모든 수치는 서버가 계산해 내려주고 클라이언트는 그리기만 한다**(서비스 날짜 04시 · 주 경계 월요일 04시 판정은 서버 몫).

**카드 구성의 확정 사항** (합의 2026-08-06 — `profile.md` 4.1 반영 완료)

- **카드는 4개다 — 현재 플랜 · 이메일 · 관심 주제 관리 · 커리어 정보.** 관심 주제와 커리어는 **별도 카드 · 별도 화면**이다.
- [관심 주제 관리] 카드는 **관심사 관리 화면**(`interest-management.md` — 주제 전용)으로, [커리어 정보] 카드는 **커리어 정보 화면**(`career.md`)으로 이동한다. 두 편집을 한 화면에 합치지 않는다.
- 이 문서의 이전 판이 확정했던 "3카드(커리어 카드 없음)" 구성은 **폐기됐다.**

- **청취 통계는 2026-08-06 확정으로 추가됐다**(`profile.md` 4.5~4.7). 화면 ID P8–P10. **수치 표기 형식(단위·반올림)은 이 문서가 확정한다**(4.6).
- 이메일 인증 화면 자체(A 계열)는 `auth-uiux.md`가 소유한다. 프로필은 진입점과 복귀만 다룬다.
- 구독 관리·관심사 관리·커리어 정보 화면은 각 명세의 UIUX 문서가 소유한다(관심사 관리 `interest-management-uiux.md` · 커리어 `career-uiux.md`는 작성됨 2026-08-10, 구독은 미작성).

## 2. 화면 목록

| ID | 화면 | 대응 상태(`profile.md` 5장) |
|---|---|---|
| P1 | 정상 — 유료 구독 · 인증된 이메일 | 정상 · 유료 사용자 |
| P2 | 무료 사용자 | 무료(라이트) |
| P3 | 이메일 미인증 | 이메일 있음 · 미인증 배지 |
| P4 | 이메일 미등록 | 이메일 없음 |
| P5 | 해지 예약 · 결제 문제 | 해지 예약 · 결제 문제 |
| P6 | 로딩 | 카드·통계 영역 스켈레톤 |
| P7 | 조회 실패 — 카드별 에러 | 조회 실패(부분·전체) |
| P8 | 청취 통계 — 정상 | 정상(통계 영역) · 주간 그래프 기본 |
| P9 | 이전 주 탐색 | 이전 주 탐색 |
| P10 | 기록 없음 · 통계 조회 실패 | 청취 기록 없음 · 통계 조회 실패 |

- **커리어 미입력은 별도 화면이 아니라 [커리어 정보] 카드의 변형이다**(4.5) — "입력하면 추천이 정확해져요" + [입력하기].
- "편집 후 복귀" 상태는 화면이 아니라 갱신 동작이므로 ID를 두지 않고 4.9에서 다룬다.
- 오프라인 상태는 P1~P5에 오프라인 배너가 얹힌 변형이다(4.10).
- P8–P10은 별도 화면이 아니라 **P1~P5의 카드 아래에 이어지는 통계 영역**을 상태별로 그린 것이다. 화면은 하나의 세로 스크롤이다.

## 3. 화면 흐름

```
하단 탭 [프로필] ──> P6 로딩 ─┬─ 조회 성공 ──> P1~P5 (+ 통계 P8/P10)
                               └─ 조회 실패 ──> P7 (화면은 열고 카드만 에러)

P1~P5 ─[⚙ 설정 아이콘]─> 설정 화면 (settings-uiux.md)
   ─[플랜 카드]──────────> 구독 관리 (subscription.md)
   ─[이메일 카드]────────> 이메일 인증 화면 (auth.md 4.4~4.5)
   │                         └─ 인증 성공 ─> 프로필 복귀 + 해당 카드 갱신
   │                         └─ 중도 이탈 ─> 프로필 복귀. 기존 값 그대로
   ─[관심 주제 관리 카드]─> 관심사 관리 — 주제 전용 (interest-management.md)
   │                         └─ 저장 후 복귀 ─> 요약 재조회 (스켈레톤 없이 카드만 갱신)
   │                         └─ [취소] 복귀 ─> 재조회하지 않음
   └─[커리어 정보 카드]───> 커리어 정보 화면 (career.md)
                             └─ 저장 후 복귀 ─> 요약 재조회 / [취소] 복귀 ─> 재조회 없음

통계 영역 (표시 전용 — 탭 이동 없음)
   └─ 주간 그래프 [◀ 이전 주] ──> P9 해당 주만 추가 조회 (가입 주에서 ◀ 비활성)
      주간 그래프 [다음 주 ▶] ──> 이번 주 방향 (이번 주에서는 비활성)
```

**진입 방향은 프로필 → 설정 한 방향이다.** 설정 화면에는 프로필로 되돌아가는 계정 카드가 없다(`settings.md` 2장).

## 4. 화면별 명세

### 4.1 P1 정상 — 화면 골격

**구성** — 헤더(닉네임 + 로그인 제공자 아이콘 + **우상단 ⚙ 설정 아이콘**) / [현재 플랜] 카드 / [이메일] 카드 / 구분선 / **[관심 주제 관리] 카드** / **[커리어 정보] 카드** / [통계 요약] 가로 3분할 / [주간 그래프] / [주제 분포] / 하단 탭 3개([프로필] 활성)

- **카드 순서는 바꾸지 않는다**(`profile.md` 4.1). 위 두 개는 계정·결제, 아래 두 개는 추천에 쓰이는 값 — 성격이 달라 구분선으로 나눈다.
- **청취 통계 세 영역은 카드 아래에 요약 → 주간 그래프 → 주제 분포 순서로** 이어진다(`profile.md` 4.1). 모두 표시 전용이며 탭 이동이 없다 — 주간 그래프의 주 이동 화살표만 예외다(4.6~4.7).
- **설정 진입점은 우상단 아이콘 하나뿐이다.** 목록 항목으로 두지 않는다 — 설정은 프로필의 하위 항목이 아니라 별개 화면이다(`profile.md` 4.1).
- **닉네임·제공자는 표시만 한다.** 탭해도 아무 일도 일어나지 않는다 — 편집 진입점을 두지 않는다(닉네임 편집·계정 통합은 MVP 비범위).
  - 제공자는 아이콘(네이버/카카오/구글/애플)으로 표시한다. 아이콘에는 "카카오 계정으로 로그인" 형태의 접근성 라벨을 붙인다.
  - **`nickname`이 `null`이면 "이어 사용자"를 대신 그린다**(`profile-api.md` 4.1 — 서버가 널을 그대로 내려준다). 제공자가 닉네임을 주지 않거나, **애플에서 이름을 가린 사용자**가 여기에 해당한다.
    - **빈 자리로 두지 않는다.** 헤더에 이름 줄만 비면 로딩이 덜 끝난 화면으로 보이고, 그 아래 설정 아이콘과 카드가 위로 딸려 올라와 레이아웃이 흔들린다.
    - **"닉네임 없음" 같은 결핍 표현을 쓰지 않는다.** 편집 진입점이 없어 사용자가 채울 방법이 없는데 없다고만 알리면 막다른 안내가 된다.
    - 낭독기에도 같은 문자열을 읽힌다 — 시각·비시각 경로가 다른 이름을 말하면 안 된다.
- 각 카드는 카드 전체가 탭 영역이다. 우측 셰브론(>)으로 이동 가능함을 표시한다.
- **플랜 카드(유료)**: 플랜명 + "다음 결제일 N월 N일" + [구독 관리] 진입. **해지 버튼을 두지 않는다** — 결제 조작의 진입점은 구독 관리 하나다(`profile.md` 4.2).
- **이메일 카드(인증됨)**: 주소 표시 + [변경]. 배지 없음.
- 관심 주제·커리어 카드의 내용은 4.5.

### 4.2 P2 무료 사용자

- **플랜 카드**: **"무료 이용 중 · 하루 N편"** + **[구독 알아보기]** 강조(주 액션 톤).
  - "하루 N편"의 N은 서버가 내려준 `daily_play_limit`이다. **2를 하드코딩하지 않는다**(`paywall.md` 5장).
  - 플랜명만으로는 무엇이 제한되는지 알 수 없으므로 한도를 함께 적는다(`profile.md` 4.2).
  - [구독 알아보기]도 구독 화면 진입일 뿐이다. 프로필에서 결제를 시작하지 않는다.
- **관심 주제 0개 상태는 없다.** 관심사 관리 화면이 최소 1개 선택을 강제하므로(합의 2026-08-06 — `profile.md` 4.4) 0개 요약은 생기지 않는다. 이 문서의 이전 판이 임의로 정했던 "관심 주제를 골라주세요" 카피는 **폐기한다.**

### 4.3 P3 이메일 미인증 · P4 이메일 미등록

**세 상태를 같은 카드의 변형으로 구분한다**(`profile.md` 4.3 — `email` × `is_email_verified` 조합).

| 상태 | 카드 표시 | 버튼 |
|---|---|---|
| 미등록(P4) | **"등록되지 않음"** | [등록] |
| 미인증(P3) | 주소 + **"인증되지 않음" 배지** | [인증하기] · [변경] |
| 인증됨(P1) | 주소 | [변경] |

- **미인증 배지를 생략하지 않는다.** 저장된 주소와 인증된 주소를 같아 보이게 하면, 사용자는 결제 직전에야 인증이 필요함을 알게 된다(`profile.md` 4.3).
- P3·P4에는 보조 문구 **"결제하려면 인증된 이메일이 필요해요"** 를 카드 아래 한 줄로 둔다. **인증을 강요하는 팝업·배너를 띄우지 않는다** — 강제 지점은 첫 결제 하나뿐이다(`auth.md` 4.4).
- [인증하기]는 저장된 주소로 바로 코드를 발송하고, [등록]·[변경]은 주소 입력부터 시작한다. **세 버튼 모두 같은 인증 화면(A 계열)으로 간다** — 규칙이 갈라지면 발송 횟수 제한이 경로별로 샌다(`auth.md` 4.4).
- 인증 화면에서 성공하면 프로필로 복귀하고 이메일 카드가 새 값·인증 상태로 갱신된다. **중도 이탈하면 기존 값이 그대로다** — 카드에 어떤 중간 상태도 표시하지 않는다.
- 발송 5회 소진·쿨다운 등의 안내는 인증 화면(A 계열) 몫이다. 프로필 카드는 관여하지 않는다.

### 4.4 P5 해지 예약 · 결제 문제

| 상태 | 플랜 카드 표시 |
|---|---|
| 해지 예약 | 플랜명 + **"N월 N일까지 이용 가능"** — 중립 톤. 경고색을 쓰지 않는다 |
| 결제 문제(유예) | 플랜명 + **"결제에 문제가 있어요"** — 경고색 |

- **해지 예약을 경고 톤으로 그리지 않는다.** 사용자가 스스로 내린 결정이지 장애가 아니다. 경고색은 사용자가 조치해야 하는 상태(결제 문제)에만 쓴다.
- 결제 문제 카드를 탭하면 구독 관리로 이동한다. **프로필에서 결제 수단 수정을 시도하지 않는다.**
- 판정은 서버가 내려준 `plan.status`(`profile-api.md` 4.1)를 그대로 그린다. 클라이언트가 `expires_at`과 기기 시각을 비교해 상태를 재판정하지 않는다.
- 같은 상태를 설정의 구독 요약도 같은 문구·같은 톤으로 표시한다(`settings-uiux.md` 4.1).

### 4.5 관심 주제 관리 · 커리어 정보 — 카드 2종

**두 카드는 서로 다른 화면으로 이동한다**(합의 2026-08-06 — `profile.md` 4.4). 요약만 보여주고, 저장 규칙에는 관여하지 않는다.

**[관심 주제 관리] 카드** → 관심사 관리 화면(`interest-management.md` — 주제 전용)

- **"N개 선택"** + 대표 주제 칩 최대 3개 + 나머지 `+N`.
- **대표 3개는 별도 선정 기준 없이 서버 응답(`top_topics`) 순서의 앞 3개다**(합의 2026-08-06 — `profile.md` 4.4).
- `+N`은 **상한(3개) 도입 이전 초과 보유자에게만** 나타난다(`interest-management.md` 7장). `N = count - 3`.
- 칩은 표시 전용이다 — 칩을 탭해도 개별 편집이 아니라 카드와 같은 관심사 관리 진입이다(개별 편집을 열면 저장 규칙이 두 벌이 된다).
- 관심 주제 0개 상태는 없다(4.2 — 최소 1개 강제).

**[커리어 정보] 카드** → 커리어 정보 화면(`career.md`)

| 상태 | 카드 표시 | 버튼 |
|---|---|---|
| 입력됨 | **"직군 · 직무 · 연차"** 한 줄 — 예: "기획 · 서비스 기획 · 4-6년" | (카드 탭 이동) |
| 미입력 | **"입력하면 추천이 정확해져요"** | **[입력하기]** |

- 세 값이 모두 선택 입력이므로(`career.md` 3장) **입력된 값만 가운데점(·)으로 이어 표시한다.** 하나라도 있으면 "입력됨" 표시이고, 셋 다 없을 때만 미입력 변형이다.
- 연차 구간 라벨은 온보딩 커리어 단계와 같은 표기를 쓴다 — **"0-1년" · "2-3년" · "4-6년" · "7년+"**(`career.md` 3장의 enum과 1:1). 두 화면의 라벨이 갈라지면 같은 값이 다른 말로 보인다.
- [입력하기]도 카드 탭과 같은 목적지(커리어 정보 화면)다. 버튼을 따로 두는 이유는 미입력 카드가 "비어 있음"이 아니라 "할 일"로 읽히게 하기 위해서다.

**공통**

- 편집 화면에서 저장하고 돌아오면 요약을 재조회한다(4.9). 저장 규칙(관심 주제 최소 1개, 커리어 확인 팝업 없음 등)은 각 편집 화면이 판정하고 프로필은 관여하지 않는다.

### 4.6 P8 청취 통계 — 정상

카드 아래에 이어지는 표시 전용 영역. **요약 3지표(가로 3분할) → 주간 그래프 → 주제 분포** 순서다(`profile.md` 4.5~4.7).

**통계 요약 — 누적 3지표 (가로 한 줄 3분할)**

| 지표 | 라벨 | 값 표기 | 근거 |
|---|---|---|---|
| 누적 청취 콘텐츠 수 | **"누적 청취"** | **"N편"** | **완청한 고유 콘텐츠 수**(`profile.md` 4.5 — 완청 판정 값은 `player.md` 소유). 같은 콘텐츠를 여러 번 완청해도 1편 |
| 누적 청취 시간 | **"청취 시간"** | **60분 미만 "N분" · 60분 이상 "N시간"** | `listened_sec` 총합 — 실제 들은 시간 |
| 연속 청취 일수 | **"연속 청취"** | **"N일"** | 서비스 날짜(04시 경계) 기준. 그날 재생 기록 1건이면 인정 |

**수치 표기 형식 — 이 문서의 확정이다**(`profile.md` 4.5가 위임)

- 콘텐츠 수는 정수 **"N편"**. 연속 일수는 정수 **"N일"**.
- 청취 시간은 **60분 미만이면 분 단위 "N분"(초 버림), 60분 이상이면 시간 단위 "N시간"(분 버림)** — 반올림·올림하지 않는다. 아직 듣지 않은 시간을 표시하면 수치의 신뢰가 깨진다. 예: 59분 59초 → "59분", 31시간 40분 → "31시간".
- 기록이 없으면 **"0편" · "0분" · "0일"** 로 표시한다(P10 변형 A). 자리를 비우거나 "-"로 두지 않는다.
- 세 값 모두 서버 계산 값을 그대로 그린다. 연속 일수는 **오늘 아직 듣지 않았어도 어제까지의 연속을 그대로 표시한다**(`profile.md` 4.5) — 클라이언트가 "오늘 안 들었으니 0"으로 재판정하지 않는다.

**주간 청취 그래프**

- 영역 제목 **"주간 청취"** + 우측에 **[◀] 주 범위 [▶]**. 주 범위 표기는 **"N월 N일 – N월 N일"**(서버가 내려준 주 경계를 기기 로캘로 그린다 — 경계 판정은 서버 몫).
- 막대는 **월~일 7개 세로 막대(아래에서 위로)**. 기본 표시는 **이번 주**이고 이번 주에서 [▶]는 비활성이다(미래 주는 없다).
- **막대 스케일은 표시 중인 주의 최댓값 기준 상대 높이다.** 막대에 수치 라벨을 상시 표시하지 않는다 — 좁은 7분할에 숫자를 얹으면 겹친다. 대신 **막대를 탭하면 그 요일의 값을 막대 위 말풍선으로 표시한다**(개정 2026-08-08 — 개발 중 사용성 확인으로 9장 재검토 조건이 충족됐다. 상대 높이만으로는 한 시간인지 십 분인지 알 수 없다).
  - 같은 막대를 다시 탭하면 닫히고, 다른 막대를 탭하면 옮겨 가며, **주를 이동하거나 그래프 밖 빈 영역을 탭하면 해제된다**(카드·버튼 등 다른 상호작용 요소를 탭하면 그 요소의 동작을 그대로 수행한다).
  - 값 표기는 **60분 미만 "N분", 60분 이상 "N시간 N분"(버림)** — 스크린리더 라벨(7장)과 같은 형식이다. **0인 요일도 탭하면 "0분"을 표시한다** — 0 막대의 자리를 유지하는 것과 같은 태도다.
  - 스크린리더 요일별 라벨은 그대로 유지한다(7장).
- 기록이 없는 요일과 아직 오지 않은 요일은 **0 막대(자리 유지)** 다. 오늘에 해당하는 요일 라벨은 강조한다.
- 한 주 전체가 0이면 그래프 대신 빈 상태 문구를 보여준다(P10).

**주제 분포 — 원형 그래프**

- 영역 제목 **"주로 듣는 주제"**. 원형(도넛) 그래프 + 우측 범례(주제명 + 비율).
- **상위 5개 주제 + "기타"** 를 서버가 내려준 비율 그대로 그린다(`profile.md` 4.7 — 합 100%). 클라이언트가 재정렬·재계산하지 않는다.
- 비율 표기는 **정수 "N%"** — 서버가 정수로 정규화해 내려준 값을 그대로 쓴다.
- **절대값(시간)을 표시하지 않는다** — 집계 기간이 가입 후 전체라 비율만 보여준다(합의 2026-08-06).
- 색만으로 조각을 구분하지 않는다 — 범례에 주제명 텍스트가 항상 함께 있다.

### 4.7 P9 이전 주 탐색

- [◀ 이전 주] 탭 → **그 주만 추가 조회**한다(`profile.md` 4.6 · `profile-api.md`). 로딩 중에는 그래프 자리만 스켈레톤이고 요약·분포는 그대로다.
- 한 번 받은 주는 화면을 벗어나기 전까지 재조회하지 않는다.
- **[◀]는 가입 주까지** — 가입 주에서 비활성. **[▶]는 이번 주에서만 비활성** — 이전 주를 보는 중에는 활성이다(미래가 아니라 이번 주 방향이므로).
- 주 단위 조회가 실패하면 그래프 자리에 인라인 에러 + [다시 시도]를 두고, 주 범위 표기는 이동하려던 주를 유지한다. 요약·분포는 건드리지 않는다.
- 이전 주를 보다가 화면을 떠났다 돌아오면 **이번 주부터 다시 시작한다.** 주 위치는 저장할 상태가 아니다.

### 4.8 P10 기록 없음 · 통계 조회 실패

**변형 A — 청취 기록 없음(신규 사용자)**

- 요약 3지표는 **"0편" · "0분" · "0일"** 로 표시한다.
- 주간 그래프·주제 분포는 그래프 대신 빈 상태 문구 **"청취 기록이 없어요"** 를 각 영역 안에 보여준다.
- **영역을 숨기지 않는다**(`profile.md` 7장) — 숨기면 무엇이 채워질 자리인지 알 수 없다.

**변형 B — 통계 조회만 실패**

- 통계 영역 전체를 하나의 에러 블록으로 접는다 — 영역 제목 "청취 통계" + **"통계를 불러올 수 없어요"** + [다시 시도].
- **카드 4개와 내비게이션은 정상 동작한다**(`profile.md` 4.8). 반대(카드 실패·통계 정상)도 같다 — 부분 실패가 화면 전체를 덮지 않는다.
- [다시 시도]는 통계를 포함한 전체 재조회다(`profile-api.md` — 섹션별 부분 조회를 두지 않는다).

### 4.9 P6 로딩 · P7 조회 실패

**P6 로딩**

- 헤더의 닉네임 자리·카드 4개·통계 영역(요약 3지표 + 그래프 자리)에 스켈레톤. **설정 아이콘은 즉시 노출한다**(`profile.md` 5장) — 설정 진입은 프로필 조회 결과와 무관하다.
- 0.3초 미만이면 표시하지 않는다(`common-error-handling.md` 5장).

**P7 조회 실패**

- **화면 자체는 연다**(`profile.md` 4.8). 실패한 카드에만 **"정보를 불러올 수 없어요"** + [다시 시도]를 표시한다.
- **부분 실패**: `failed_sections`에 담긴 카드만 에러로 두고 나머지는 정상 노출한다(`profile-api.md` 4.1). 통계만 실패하면 P10 변형 B다. 화면 전체를 에러로 덮지 않는다.
- **카드가 에러여도 그 카드의 내비게이션은 동작한다** — 하위 화면은 자기 데이터를 직접 조회하므로 요약 실패가 편집까지 막을 이유가 없다.
- [다시 시도]는 전체 재조회다. 연타는 인플라이트 요청이 있으면 무시한다.
- 세션 만료(401 갱신 실패)는 공통 처리로 시작 화면으로 이동한다(`common-error-handling.md` 4.1).

**편집 후 복귀 — 카드만 갱신**

- 하위 화면(관심사 관리·커리어 정보·이메일 인증·구독 관리)에서 **저장하고 돌아오면 요약을 재조회한다**(`profile.md` 4.4). 캐시를 그대로 두면 방금 한 변경이 반영되지 않은 것처럼 보인다.
- **전체 스켈레톤을 다시 띄우지 않는다.** 기존 값을 유지한 채 조용히 재조회하고, 도착한 값으로 카드만 갱신한다(`profile.md` 5장).
- **[취소]·뒤로가기로 나온 경우는 재조회하지 않는다**(`profile.md` 7장). 바뀐 것이 없는데 조회를 반복할 이유가 없다.
- 다른 기기에서 구독을 바꾼 경우는 다음 진입 시 재조회로 흡수된다.

### 4.10 오프라인 진입

- 마지막으로 받은 요약을 표시하고 상단에 오프라인 배너를 노출한다(`profile.md` 7장). 통계도 마지막 값 그대로다 — 낡았을 수 있으나 판정에 쓰이는 값이 아니다.
- **이메일 카드 탭 시 "온라인에서 인증할 수 있어요" 안내**를 띄우고 인증 화면으로 가지 않는다 — 코드 발송·검증이 전부 서버 왕복이다.
- 주간 그래프의 [◀ 이전 주]는 추가 조회가 필요하므로 실패 시 인라인 에러 + [다시 시도]다(4.7과 동일).
- 다른 카드의 내비게이션은 허용한다. 하위 화면이 각자 오프라인 처리를 한다.

## 6. 카피 원칙

- **해요체**로 통일한다.
- 카드 라벨은 **"현재 플랜" · "이메일" · "관심 주제 관리" · "커리어 정보"** 다. "관심 주제 관리"에만 "관리"가 붙는 이유는 일괄 편집 화면의 진입점임이 이름에 드러나야 하기 때문이고, "커리어 정보"는 명사구로 통일한다(`settings.md` 4.1의 항목명과 동일).
- 무료 플랜: **"무료 이용 중 · 하루 N편"** — N은 서버 값. 유료: 플랜명 + **"다음 결제일 N월 N일"**. 해지 예약: **"N월 N일까지 이용 가능"**. 결제 문제: **"결제에 문제가 있어요"**.
- 이메일: **"등록되지 않음"** / **"인증되지 않음"**(배지) / 보조 **"결제하려면 인증된 이메일이 필요해요"**.
- 커리어: 입력됨 **"직군 · 직무 · 연차"**(예: "기획 · 서비스 기획 · 4-6년") / 미입력 **"입력하면 추천이 정확해져요"** + **[입력하기]**.
- 통계 라벨: **"누적 청취" · "청취 시간" · "연속 청취"**(요약 3지표) / **"주간 청취"** / **"주로 듣는 주제"**.
- 통계 값: **"N편" · "N분"/"N시간" · "N일" · "N%"** — 표기 형식은 4.6이 확정한다.
- 통계 빈 상태: **"청취 기록이 없어요"**(개정 2026-08-08 — "아직"을 뺐다. 이 문구는 신규 사용자의 이번 주뿐 아니라 **주 이동으로 도달한 과거의 전체 0인 주**에도 쓰이는데, 지나간 주에 "아직"은 시제가 어긋난다. 두 곳에 문구를 가르지 않고 하나로 통일한다). 통계 에러: **"통계를 불러올 수 없어요"** + [다시 시도]. 카드 에러: **"정보를 불러올 수 없어요"** + [다시 시도].
- 주간 범위: **"N월 N일 – N월 N일"**.
- **내부 용어를 노출하지 않는다** — "티어", "라이트", "구독 행", "캐시", "완청", "서비스 날짜". 화면에 쓰는 것은 플랜의 표시명(`plan_name`)과 위의 확정 카피뿐이다.
- 날짜는 "N월 N일" 형식으로 표기한다. 서버의 ISO 시각을 기기 로캘로 변환해 그린다 — 단 **만료·결제일·주 경계의 판정은 서버 몫**이고 표기만 클라이언트가 한다.

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 설정 아이콘, 카드 내 버튼([인증하기]·[변경]·[입력하기]), 주 이동 화살표 [◀]/[▶].
- 설정 아이콘은 `role=button` + **"설정 열기"** 라벨. 아이콘만으로 의미가 전달되지 않는다.
- **카드는 하나의 탭 영역으로 읽힌다** — "관심 주제 관리, 4개 선택, 커리어, 자기계발, 경제 외 1개, 관심사 관리 열기" / "커리어 정보, 기획, 서비스 기획, 4에서 6년, 커리어 정보 열기"처럼 값과 목적지를 한 문장으로. 카드 안의 조각(배지·칩)을 개별 포커스로 쪼개지 않는다. 단 이메일 카드처럼 버튼이 두 개([인증하기]·[변경])면 버튼만 개별 포커스를 준다.
- **미인증 배지는 색 + 텍스트다.** 스크린리더는 "인증되지 않음"을 주소 뒤에 이어 읽는다.
- 관심 주제의 `+N`은 "외 N개"로 읽힌다 — "+3"을 "플러스 삼"으로 읽히게 두지 않는다.
- **통계 요약 타일은 값과 라벨을 한 문장으로 읽는다** — "누적 청취 128편".
- **주간 그래프의 막대는 요일별 값이 개별로 읽힌다** — "화요일, 32분"(60분 이상이면 "N시간 N분"). 그래프 컨테이너 라벨은 "주간 청취, 8월 3일부터 8월 9일". [◀]/[▶]는 "이전 주" / "다음 주" 라벨 + 비활성 시 `disabled` 상태가 함께 읽힌다.
  - 막대는 탭 가능한 요소(버튼)로 노출되지만 **말풍선(4.6)은 보조기기에 별도로 알리지 않는다** — 라벨이 이미 값을 읽고 있어 시각 중복이다.
- **주제 분포는 범례가 곧 대체 텍스트다** — "커리어 38%, 자기계발 24%, …, 기타 6%" 순서로 읽힌다. 원형 그래프 자체는 장식으로 처리한다.
- 이전 주 탐색으로 그래프가 갱신되면 `aria-live="polite"`로 주 범위를 알린다.
- 편집 후 복귀로 카드가 갱신되면 `aria-live="polite"`로 해당 카드만 알린다. 전체 화면을 다시 읽지 않는다.
- 동적 텍스트 200%에서 카드 내 줄바꿈을 허용한다 — 값이 길어지면(이메일 주소·커리어 요약) 말줄임 대신 두 줄로 접는다. 통계 요약 3분할은 세로 스택으로 전환을 허용한다.

## 8. 금지 사항

`profile.md`와 이 문서의 확정이 명시적으로 금지한 것들이다.

- **프로필에서 직접 서버에 쓰는 조작** — 인라인 편집, 토글, 저장 버튼 일체
- **관심 주제와 커리어의 편집을 한 화면·한 카드로 합치는 것** — 별도 카드·별도 화면이다(합의 2026-08-06). [관심 주제 관리]가 커리어 정보 화면으로, [커리어 정보]가 관심사 관리 화면으로 가게 만드는 것도 같다
- 플랜 카드에 **[해지]·[요금제 변경] 버튼**을 두는 것 — 결제 조작은 구독 관리 한 곳이다
- **닉네임 편집·프로필 이미지** 진입점
- 이메일 미인증·미등록 사용자에게 **인증을 강요하는 팝업·전면 배너** — 강제 지점은 첫 결제뿐이다
- 저장된 주소와 인증된 주소를 **같은 모양으로 표시**하는 것 — 배지 생략 금지
- 조회 실패 시 **화면 전체를 에러로 덮거나 내비게이션을 막는 것**
- 편집 화면 [취소] 복귀에 **재조회를 붙이는 것** / 저장 복귀에 **전체 스켈레톤을 다시 띄우는 것**
- 관리자가 숨긴 주제를 **요약 개수·주제 분포에서 빼는 것** — 편집 화면과 개수가 어긋난다(`profile.md` 7장)
- 클라이언트가 `expires_at`과 기기 시각으로 **구독 상태를 재판정**하는 것
- **통계를 클라이언트가 집계·보정하는 것** — 연속 일수 재계산, 기기 시각으로 주 경계 나누기, 04시 경계 보정 일체
- 주제 분포에 **절대값(시간)을 표시**하는 것 — 비율만 보여준다
- 청취 기록이 없다고 **통계 영역을 숨기는 것**
- 통계 수치를 **반올림·올림으로 부풀리는 것** — 표기는 버림이다(4.6)
- 설정 화면에 **프로필로 되돌아가는 계정 카드**를 만드는 것 (`settings.md` 2장 — 설정 쪽 금지지만 이 화면 쌍의 규칙이다)

## 10. 합의 사항

2026-08-06 합의로 확정되어 features(`profile.md` · `career.md`)와 이 문서에 반영을 마친 항목들이다.

- 관심사 관리 카드와 커리어 정보 카드를 분리한다. 편집 화면도 분리한다 — 관심사 관리 카드는 관심사 관리 페이지로, 커리어 정보 카드는 커리어 정보 페이지(`career.md`)로 이동한다.
- 관심 주제 관리에서 관심 주제를 최소 1개는 선택해야 저장할 수 있도록 강제한다 — 프로필에 0개 요약 상태가 생기지 않는다.
- 대표 주제 3개의 선정 기준은 따로 두지 않고 API 응답 순서의 앞 3개를 쓴다.
- 청취 통계를 프로필에 도입한다 — 누적 3지표 · 주간 요일별 그래프(이전 주 탐색) · 주제 분포 원형 그래프.
- 연속 청취 일수 인정 기준은 그날 재생 기록 1건으로 한다(최소 청취 시간 조건 없음).
- 주제 분포 집계 기간은 가입 후 전체 기간으로 하고 비율만 보여준다.
- 누적 콘텐츠 수에는 완청한 콘텐츠만 반영한다(완청 판정 값은 `player.md` 소유).
- **수치 표기 형식(이 문서 확정, 4.6)** — 콘텐츠 "N편", 시간 60분 미만 "N분"·이상 "N시간"(버림), 연속 "N일", 분포 "N%"(정수), 주 범위 "N월 N일 – N월 N일".
