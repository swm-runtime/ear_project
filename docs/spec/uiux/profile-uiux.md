# 프로필 UI/UX 명세서

> 기준 문서: [`docs/features/profile.md`](../../features/profile.md) · 이메일 인증 규칙은 [`docs/features/auth.md`](../../features/auth.md) 4.4~4.5, 커리어 편집 화면은 [`docs/features/career.md`](../../features/career.md), 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/profile.html`](../../wireframe/profile.html) (화면 ID P1–P10)
> API: [`profile-api.md`](../api/profile-api.md)

## 1. 범위

하단 탭의 프로필 화면 — **헤더(아바타·닉네임·제공자 배지 + 이메일 줄 + 플랜 줄 + 우상단 ⚙ 설정 아이콘)**와 **2개 카드(관심 주제 관리 · 커리어 정보)**, 그 아래의 **청취 통계(요약 3지표 · 주간 청취 카드 — 주간 그래프와 그 주의 주제 분포를 한 카드에 담는다)**, 그 상태 변형과 로딩·오류까지 `profile.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 화면은 편집 로직을 갖지 않는다**(`profile.md` 1장). 관심사·커리어·이메일·구독의 저장 규칙은 전부 소유 화면의 것이고, 프로필은 **현재 값을 요약해 보여주고 소유 화면으로 보낼 뿐**이다. 청취 통계도 같다 — **모든 수치는 서버가 계산해 내려주고 클라이언트는 그리기만 한다**(서비스 날짜 04시 · 주 경계 월요일 04시 판정은 서버 몫).

**구성의 확정 사항**

- **플랜·이메일은 카드가 아니라 헤더의 줄이다**(개정 2026-08-15 — UI 개편 PR #46이 두 카드를 헤더로 통합했고, 이메일 인증 화면 구현과 함께 **헤더의 이메일 줄이 프로필 쪽 진입점**으로 확정됐다. `changes/archive/profile-email-entry-header(fe).md`). 같은 값을 한 화면에 두 번 쓰지 않는다 — 카드를 복원하지 않는다.
- **카드는 2개다 — 관심 주제 관리 · 커리어 정보.** 관심 주제와 커리어는 **별도 카드 · 별도 화면**이다(합의 2026-08-06 — `profile.md` 4.1 반영 완료).
- [관심 주제 관리] 카드는 **관심사 관리 화면**(`interest-management.md` — 주제 전용)으로, [커리어 정보] 카드는 **커리어 정보 화면**(`career.md`)으로 이동한다. 두 편집을 한 화면에 합치지 않는다.
- 이 문서의 이전 판이 확정했던 "3카드(커리어 카드 없음)" 구성과 "4카드(플랜·이메일 카드 포함)" 구성은 **폐기됐다.**

- **청취 통계는 2026-08-06 확정으로 추가됐다**(`profile.md` 4.5~4.7). 화면 ID P8–P10. **수치 표기 형식(단위·반올림)은 이 문서가 확정한다**(4.6).
  - **주제 분포는 별도 영역이 아니라 주간 청취 카드의 맨 아래 구획이다**(개정 2026-09-28 — `changes/archive/profile-weekly-topics-merge.md`). 종전에는 주간 카드가 선택한 주를, 그 밑 주제 카드가 가입 후 전체를 보여줘 한 화면에 기간 기준이 둘이었다. 전체 누적은 요약 3지표가 맡고, 주제 분포는 **표시 중인 주**를 따른다(4.6).
- 이메일 인증 화면 자체(A 계열)는 `auth-uiux.md`가 소유한다. 프로필은 진입점과 복귀만 다룬다.
- 구독 관리·관심사 관리·커리어 정보 화면은 각 명세의 UIUX 문서가 소유한다(관심사 관리 `interest-management-uiux.md` · 커리어 `career-uiux.md`는 작성됨 2026-08-10, 구독은 미작성).

- P8–P10은 별도 화면이 아니라 **P1~P5의 카드 아래에 이어지는 통계 영역**을 상태별로 그린 것이다. 화면은 하나의 세로 스크롤이다.

## 3. 화면 흐름

```
하단 탭 [프로필] ──> P6 로딩 ─┬─ 조회 성공 ──> P1~P5 (+ 통계 P8/P10)
                               └─ 조회 실패 ──> P7 (화면은 열고 카드만 에러)

P1~P5 ─[⚙ 설정 아이콘]─> 설정 화면 (settings-uiux.md)
   ─[헤더 플랜 줄]───────> 구독 관리 (subscription.md)
   ─[헤더 이메일 줄]─────> 이메일 인증 화면 (auth.md 4.4~4.5)
   │                         └─ 인증 성공 ─> 프로필 복귀 + 헤더 이메일 줄 갱신
   │                         └─ 중도 이탈 ─> 프로필 복귀. 기존 값 그대로
   ─[관심 주제 관리 카드]─> 관심사 관리 — 주제 전용 (interest-management.md)
   │                         └─ 저장 후 복귀 ─> 요약 재조회 (스켈레톤 없이 카드만 갱신)
   │                         └─ [취소] 복귀 ─> 재조회하지 않음
   └─[커리어 정보 카드]───> 커리어 정보 화면 (career.md)
                             └─ 저장 후 복귀 ─> 요약 재조회 / [취소] 복귀 ─> 재조회 없음

통계 영역 (표시 전용 — 탭 이동 없음)
   └─ 주간 그래프 [◀ 이전 주] · 오른쪽으로 밀기 ──> P9 이전 주 (가입 주에서 ◀ 비활성)
      주간 그래프 [다음 주 ▶] · 왼쪽으로 밀기 ──> 이번 주 방향 (이번 주에서는 비활성)
        · 표시 주의 이웃 주는 미리 받아 둔다 — 받아 둔 주는 조회 없이 넘어간다 (4.7)
      주간 그래프 막대 탭 ──> 그 요일의 값 말풍선 + 주제 구획이 그날 분포로 (4.6)
```

**진입 방향은 프로필 → 설정 한 방향이다.** 설정 화면에는 프로필로 되돌아가는 계정 카드가 없다(`settings.md` 2장).

## 4. 화면별 명세

### 4.1 P1 정상 — 화면 골격

**구성** — **헤더**(아바타 + 제공자 배지 + 닉네임 + **이메일 줄** + **플랜 줄** + **우상단 ⚙ 설정 아이콘**) / **[관심 주제 관리] 카드** / **[커리어 정보] 카드** / [통계 요약] 가로 3분할 / [주간 청취 카드 — 주간 그래프 + 주제 구획] / 하단 탭 3개([프로필] 활성)

- **헤더는 "내가 누구인지"의 블록이다** — 정체(아바타·닉네임·제공자), 연락처(이메일 줄), 플랜(플랜 줄)을 한 블록에 쌓는다. 플랜·이메일을 카드로 따로 세우지 않는다(1장 확정 — 개정 2026-08-15).
  - **헤더 이메일 줄**: 주소(또는 "이메일 미등록") 표시. **줄 전체가 탭 영역**이며 이메일 인증 화면으로 이동한다(4.3). 줄이 작으므로 hitSlop으로 터치 타깃 44pt를 채운다(7장).
  - **헤더 플랜 줄(유료)**: 플랜명 + "다음 결제일 N월 N일". 탭하면 구독 관리로 이동한다. **해지 버튼을 두지 않는다** — 결제 조작의 진입점은 구독 관리 하나다(`profile.md` 4.2).
- **청취 통계는 카드 아래에 요약 3지표 → 주간 청취 카드 순서로** 이어진다(`profile.md` 4.1). 주제 분포는 주간 청취 카드 안의 맨 아래 구획이다(개정 2026-09-28 — 4.6). 모두 표시 전용이며 탭 이동이 없다 — 주간 그래프의 주 이동(화살표·가로 스와이프)과 막대 탭(말풍선)만 예외다(4.6~4.7).
- **설정 진입점은 우상단 아이콘 하나뿐이다.** 목록 항목으로 두지 않는다 — 설정은 프로필의 하위 항목이 아니라 별개 화면이다(`profile.md` 4.1).
- **닉네임·제공자는 표시만 한다.** 탭해도 아무 일도 일어나지 않는다 — 편집 진입점을 두지 않는다(닉네임 편집·계정 통합은 MVP 비범위). 헤더에서 탭 가능한 것은 이메일 줄·플랜 줄·설정 아이콘 셋뿐이다.
  - **아바타는 제공자 프로필 사진(`profile_image_url`)을 원형으로 그린다**(도입 2026-09-16 — `profile.md` 미결 확정). `null`이거나 **로드에 실패하면 닉네임 첫 글자, 닉네임도 없으면 사람 아이콘**으로 대신 그린다 — 실패를 오류 상태로 띄우지 않는다(`profile-api.md` 4.1: 옛 URL 실효는 정상 경로). 아바타는 장식이라 낭독기에 읽히지 않는다.
  - 제공자는 아바타 우하단 배지 아이콘(네이버/카카오/구글/애플)으로 표시한다. 아이콘에는 "카카오 계정으로 로그인" 형태의 접근성 라벨을 붙인다.
  - **`nickname`이 `null`이면 "이어 사용자"를 대신 그린다**(`profile-api.md` 4.1 — 서버가 널을 그대로 내려준다). 제공자가 닉네임을 주지 않거나, **애플에서 이름을 가린 사용자**가 여기에 해당한다.
    - **빈 자리로 두지 않는다.** 헤더에 이름 줄만 비면 로딩이 덜 끝난 화면으로 보이고, 그 아래 설정 아이콘과 카드가 위로 딸려 올라와 레이아웃이 흔들린다.
    - **"닉네임 없음" 같은 결핍 표현을 쓰지 않는다.** 편집 진입점이 없어 사용자가 채울 방법이 없는데 없다고만 알리면 막다른 안내가 된다.
    - 낭독기에도 같은 문자열을 읽힌다 — 시각·비시각 경로가 다른 이름을 말하면 안 된다.
- 각 카드는 카드 전체가 탭 영역이다. 우측 셰브론(>)으로 이동 가능함을 표시한다.
- **헤더 이메일 줄(인증됨)**: 주소만 표시. 배지 없음(4.3).
- 관심 주제·커리어 카드의 내용은 4.5.

### 4.2 P2 무료 사용자

- **헤더 플랜 줄**: **"무료 이용 중 · 하루 N편"** + **[구독 알아보기]** 칩 강조(주 액션 톤). 칩과 줄 전체가 같은 목적지(구독 화면)다 — 무료 사용자에게는 유일한 전환 지점이므로 칩을 함께 둔다.
  - "하루 N편"의 N은 서버가 내려준 `daily_play_limit`이다. **2를 하드코딩하지 않는다**(`paywall.md` 5장).
  - 플랜명만으로는 무엇이 제한되는지 알 수 없으므로 한도를 함께 적는다(`profile.md` 4.2).
  - [구독 알아보기]도 구독 화면 진입일 뿐이다. 프로필에서 결제를 시작하지 않는다.
- **가입 체험 중이면 플랜 줄이 "무료 체험 중 · N월 N일까지 무제한"이다**(2026-10-05, KAN-119 — `subscription.md` 4.8). 체험 중인 무료 계정은 `daily_play_limit`이 `null`이라 종전에는 "무료 이용 중"으로만 나와, 체험 중인지·언제 끝나는지가 보이지 않았다.
  - **판정은 `plan.trial !== null` 하나다.** `tier === "trial"`·`plan_name`으로 가르지 않는다(`profile-api.md` 4.1 — 표시용 값).
  - **날짜는 서버의 `trial.last_free_date`**(무제한으로 들을 수 있는 마지막 날) 그대로다. `ends_at`에서 계산하지 않는다 — 04시 경계 판정은 서버 몫이다. 문자열(`YYYY-MM-DD`)을 시간대를 거치지 않고 "N월 N일"로 적는다.
  - **이후 한도("하루 N편")는 이 줄에 적지 않는다.** 줄이 길어지고, 지금 사용자에게 중요한 것은 "언제까지 무제한인가"다. 이후 한도는 가입 체험 안내 팝업(P11)이 알린다.
  - [구독 알아보기] 칩·MVP 바이너리 규칙은 무료와 같다(칩은 플래그가 켜진 빌드에서만).
  - **구독자가 체험 중이면 플랜 줄은 구독 문구 그대로다**(플랜명 + 다음 결제일). 구독자에게 체험은 한도만 넉넉해지는 부수 효과이고, 플랜 줄의 주인은 구독이다.
  - 체험이 끝나면 서버가 `trial`을 `null`로 내려 주므로 줄은 저절로 "무료 이용 중 · 하루 N편"으로 돌아간다 — 클라이언트가 기기 시각으로 종료를 판정하지 않는다.
  - **MVP 바이너리(구독 UI 플래그 꺼짐)에서는 헤더 플랜 줄이 정보 표시만 한다**(2026-09-17 — App Store 반려 2.1(b), `changes/archive/subscription-ui-hidden-mvp.md` · `paywall.md` 4.5): "무료 이용 중 · 하루 N편"(유료 상태 문구도 그대로), **탭 불가, [구독 알아보기] 칩 없음.** 위 규칙은 플래그가 켜진 빌드의 규칙으로 남는다. 헤더에서 탭 가능한 것은 이메일 줄·설정 아이콘 둘이 된다.
- **관심 주제 0개 상태는 없다.** 관심사 관리 화면이 최소 1개 선택을 강제하므로(합의 2026-08-06 — `profile.md` 4.4) 0개 요약은 생기지 않는다. 이 문서의 이전 판이 임의로 정했던 "관심 주제를 골라주세요" 카피는 **폐기한다.**

### 4.3 P3 이메일 미인증 · P4 이메일 미등록

**세 상태를 헤더 이메일 줄의 변형으로 구분한다**(`profile.md` 4.3 — `email` × `is_email_verified` 조합. 개정 2026-08-15 — 카드에서 헤더 줄로 이동, `changes/archive/profile-email-entry-header(fe).md`).

| 상태 | 헤더 이메일 줄 표시 |
|---|---|
| 미등록(P4) | **⚠ 배지("이메일 미등록") 하나만** — 값 자리는 비운다 |
| 미인증(P3) | 주소 + **⚠ 느낌표 배지**(경고색 + 텍스트 "이메일 미인증") |
| 인증됨(P1) | 주소만. 배지 없음 |

- **인증 전(P3·P4)에는 줄 전체가 하나의 진입점이다** — 탭하면 이메일 인증 화면(`auth.md` 4.4~4.5)으로 이동한다. 두 상태를 버튼으로 가르지 않는다 — 같은 인증 화면으로 가고, 저장된 주소가 있으면 인증 화면의 "현재 이메일"에 표시된다. 규칙이 갈라지면 발송 횟수 제한이 경로별로 샌다(`auth.md` 4.4).
- **인증됨(P1)에서는 인증 화면으로 이동하지 않는다**(변경 불가 — `auth.md` 4.4, 확정 2026-09-07). 대신 탭하면 **안내 다이얼로그**를 띄운다: "인증된 이메일은 앱에서 변경할 수 없어요" + [닫기] · **[문의하기]**(설정의 카카오 채널과 같은 목적지 — `settings.md` 4.1).
  - **탭에 아무 반응도 주지 않는 선택은 하지 않는다.** 같은 줄이 다른 상태에서는 눌리므로, 무반응은 비활성이 아니라 고장으로 읽힌다.
  - 다이얼로그는 **변경 수단이 아니라 안내다.** 여기서 주소를 입력받지 않는다.
- **미인증 배지를 생략하지 않는다.** 저장된 주소와 인증된 주소를 같아 보이게 하면, 사용자는 결제 직전에야 인증이 필요함을 알게 된다(`profile.md` 4.3 · `auth-uiux.md` 8장 금지).
- **배지 색은 `warning`(노랑)이지 `danger`(빨강)가 아니다.** danger 는 실패·파괴에 쓰고, 인증 전 상태는 **아직 하지 않은 일**이라 경고 톤으로 둔다. 면을 채운 알약으로 그린다 — 테두리만 두면 작은 글씨가 배경에 묻힌다.
- **미등록(P4)은 값 자리를 비우고 배지만 둔다.** 값("이메일 미등록")과 배지가 같은 말을 하면 한 줄에 같은 문구가 두 번 나온다. 낭독기에는 줄 라벨로 한 번만 들린다.
- **미등록(P4)에도 같은 배지를 단다**(확정 2026-09-08). 사용자에게는 "주소가 없다"와 "주소가 확인되지 않았다"가 모두 **아직 인증 안 된 상태**다. 둘을 다르게 취급하면 미등록 사용자만 결제 직전에 처음 알게 된다. 문구는 상태에 맞게 나눈다 — 미등록은 "이메일 미등록", 미인증은 "이메일 미인증".
- 카드 시절의 보조 문구("결제하려면 인증된 이메일이 필요해요")는 헤더 통합과 함께 **두지 않는다** — 결제 필요 안내는 강제 지점인 첫 결제 흐름(인증 화면의 진입 사유 문구)이 맡는다. **인증을 강요하는 팝업·배너도 띄우지 않는다** — 강제 지점은 첫 결제 하나뿐이다(`auth.md` 4.4).
- 인증 화면에서 성공하면 프로필로 복귀하고 헤더 이메일 줄이 새 값·인증 상태로 갱신된다 — **주소가 같고 인증 상태만 바뀐 경우에도 배지가 사라진다.** **중도 이탈하면 기존 값이 그대로다** — 줄에 어떤 중간 상태도 표시하지 않는다.
- 발송 5회 소진·쿨다운 등의 안내는 인증 화면(A 계열) 몫이다. 프로필은 관여하지 않는다.

### 4.4 P5 해지 예약 · 결제 문제

| 상태 | 헤더 플랜 줄 표시 |
|---|---|
| 해지 예약 | 플랜명 + **"N월 N일까지 이용 가능"** — 중립 톤. 경고색을 쓰지 않는다 |
| 다운그레이드 예약(`plan.pending_plan`) | 플랜명 + **"N월 N일까지 이용 · 이후 {다음 요금제}"** — 중립 톤, 설정 요약과 같은 문자열(2026-10-08 PM — KAN-161) |
| 결제 문제(유예) | 플랜명 + **"결제에 문제가 있어요"** — 경고색 |

- **해지 예약을 경고 톤으로 그리지 않는다.** 사용자가 스스로 내린 결정이지 장애가 아니다. 경고색은 사용자가 조치해야 하는 상태(결제 문제)에만 쓴다.
- 결제 문제 상태의 플랜 줄을 탭하면 구독 관리로 이동한다. **프로필에서 결제 수단 수정을 시도하지 않는다.**
- 판정은 서버가 내려준 `plan.status`(`profile-api.md` 4.1)를 그대로 그린다. 클라이언트가 `expires_at`과 기기 시각을 비교해 상태를 재판정하지 않는다.
- 같은 상태를 설정의 구독 요약도 같은 문구·같은 톤으로 표시한다(`settings-uiux.md` 4.1).

### 4.5 관심 주제 관리 · 커리어 정보 — 카드 2종

**두 카드는 서로 다른 화면으로 이동한다**(합의 2026-08-06 — `profile.md` 4.4). 요약만 보여주고, 저장 규칙에는 관여하지 않는다.

**[관심 주제 관리] 카드** → 관심사 관리 화면(`interest-management.md` — 주제 전용)

- **"N개 선택"** + 대표 주제 칩 최대 3개 + 나머지 `+N`.
- **대표 3개는 별도 선정 기준 없이 서버 응답(`top_topics`) 순서의 앞 3개다**(합의 2026-08-06 — `profile.md` 4.4).
- `+N`은 **상한(3개) 도입 이전 초과 보유자에게만** 나타난다(`interest-management.md` 7장). `N = count - 3`.
- 칩은 표시 전용이다 — 칩을 탭해도 개별 편집이 아니라 카드와 같은 관심사 관리 진입이다(개별 편집을 열면 저장 규칙이 두 벌이 된다).
- 관심 주제 0개 상태는 없다(4.2 — 최소 1개 강제).

**[커리어 정보] 카드** → 커리어 정보 화면(`career.md`)

| 상태 | 카드 표시 | 버튼 |
|---|---|---|
| 입력됨 | **"직군 · 직무 · 연차"** 한 줄 — 예: "기획 · 서비스 기획 · 4-6년" | (카드 탭 이동) |
| 미입력 | **"입력하면 추천이 정확해져요"** | **[입력하기]** |

- 세 값이 모두 선택 입력이므로(`career.md` 3장) **입력된 값만 가운데점(·)으로 이어 표시한다.** 하나라도 있으면 "입력됨" 표시이고, 셋 다 없을 때만 미입력 변형이다.
- 연차 구간 라벨은 온보딩 커리어 단계와 같은 표기를 쓴다 — **"0-1년" · "2-3년" · "4-6년" · "7년+"**(`career.md` 3장의 enum과 1:1). 두 화면의 라벨이 갈라지면 같은 값이 다른 말로 보인다.
- [입력하기]도 카드 탭과 같은 목적지(커리어 정보 화면)다. 버튼을 따로 두는 이유는 미입력 카드가 "비어 있음"이 아니라 "할 일"로 읽히게 하기 위해서다.

**공통**

- 편집 화면에서 저장하고 돌아오면 요약을 재조회한다(4.9). 저장 규칙(관심 주제 최소 1개, 커리어 확인 팝업 없음 등)은 각 편집 화면이 판정하고 프로필은 관여하지 않는다.

### 4.6 P8 청취 통계 — 정상

카드 아래에 이어지는 표시 전용 영역. **요약 3지표(가로 3분할) → 주간 청취 카드** 순서이고, 주간 청취 카드 하나가 **주간 그래프와 그 아래 주제 구획(주제 분포)** 을 함께 담는다(`profile.md` 4.5~4.7. 개정 2026-09-28 — 종전 "요약 → 주간 그래프 → 주제 분포" 세 영역에서 주제 분포를 주간 카드 안으로 합쳤다. `changes/archive/profile-weekly-topics-merge.md`).

**통계 요약 — 누적 3지표 (가로 한 줄 3분할)**

| 지표 | 라벨 | 값 표기 | 근거 |
|---|---|---|---|
| 누적 청취 콘텐츠 수 | **"누적 청취"** | **"N편"** | **완청한 고유 콘텐츠 수**(`profile.md` 4.5 — 완청 판정 값은 `player.md` 소유). 같은 콘텐츠를 여러 번 완청해도 1편 |
| 누적 청취 시간 | **"청취 시간"** | **60분 미만 "N분" · 60분 이상 "N시간"** | `listened_sec` 총합 — 실제 들은 시간 |
| 연속 청취 일수 | **"연속 청취"** | **"N일"** | 서비스 날짜(04시 경계) 기준. 그날 재생 기록 1건이면 인정 |

**수치 표기 형식 — 이 문서의 확정이다**(`profile.md` 4.5가 위임)

- 콘텐츠 수는 정수 **"N편"**. 연속 일수는 정수 **"N일"**.
- 청취 시간은 **60분 미만이면 분 단위 "N분"(초 버림), 60분 이상이면 시간 단위 "N시간"(분 버림)** — 반올림·올림하지 않는다. 아직 듣지 않은 시간을 표시하면 수치의 신뢰가 깨진다. 예: 59분 59초 → "59분", 31시간 40분 → "31시간".
- 기록이 없으면 **"0편" · "0분" · "0일"** 로 표시한다(P10 변형 A). 자리를 비우거나 "-"로 두지 않는다.
- 세 값 모두 서버 계산 값을 그대로 그린다. 연속 일수는 **오늘 아직 듣지 않았어도 어제까지의 연속을 그대로 표시한다**(`profile.md` 4.5) — 클라이언트가 "오늘 안 들었으니 0"으로 재판정하지 않는다.

**주간 청취 그래프**

- 연한 회색 카드 안에 제목 **"주간 청취"**를 왼쪽에 두고, 그 오른쪽에 **[◀] 주 범위 [▶]**를 같은 머리 줄로 둔다. 머리 줄 아래에 **"하루 평균" + 큰 시간 값**, 그래프, **주제 구획**을 순서대로 둔다(2026-09-27 UI 개정 · 주제 구획은 2026-09-28 합침). 주 범위 표기는 **"N월 N일 – N월 N일"**(서버가 내려준 주 경계를 기기 로캘로 그린다 — 경계 판정은 서버 몫). 평균은 기존 집계대로 이번 주는 오늘까지 지난 날 수로(오지 않은 요일은 분모에서 뺀다), 지난주는 7일로 나누며, 그래프의 평균 점선과 같은 값이다. 하루 평균 값은 막대 값과 같은 형식으로 적는다(아래 "값 표기").
- 막대는 **월~일 7개 세로 막대(아래에서 위로)**. 기본 표시는 **이번 주**이고 이번 주에서 [▶]는 비활성이다(미래 주는 없다).
- **막대 스케일은 표시 중인 주의 최댓값 기준 상대 높이다.** 막대에 수치 라벨을 상시 표시하지 않는다 — 좁은 7분할에 숫자를 얹으면 겹친다. 대신 **막대를 탭하면 그 요일의 값을 막대 위 말풍선으로 표시한다**(개정 2026-08-08 — 개발 중 사용성 확인으로 9장 재검토 조건이 충족됐다. 상대 높이만으로는 한 시간인지 십 분인지 알 수 없다).
  - 같은 막대를 다시 탭하면 닫히고, 다른 막대를 탭하면 옮겨 가며, **주를 이동하거나 그래프 밖 빈 영역을 탭하면 해제된다**(카드·버튼 등 다른 상호작용 요소를 탭하면 그 요소의 동작을 그대로 수행한다). **막대를 탭한 동안에는 아래 주제 구획도 그 요일의 분포로 바뀐다**(아래 "주제 분포").
  - 값 표기는 **60분 미만 "N분", 60분 이상 "N시간 N분"(버림)** 이다. **1~59초는 "1분 미만"** 으로 적는다(개정 2026-09-28 — KAN-114) — 버림하면 "0분"이 되는데 막대는 색이 있는 채로 서 있어 "들은 게 없는데 막대가 있다"로 읽힌다(연속 청취 일수도 이 날을 들은 날로 센다, `features/profile.md` 4.5). **0초만 "0분"** 이고 회색 0막대다 — 0인 요일도 탭하면 "0분"을 표시한다(0 막대의 자리를 유지하는 것과 같은 태도다).
  - 말풍선 문구는 **"화요일, 32분"** 처럼 요일과 값을 함께 적는다 — **스크린리더 요일별 라벨(7장)과 같은 문자열이다.** 시각·비시각 경로가 다른 값을 말하지 않게 한다.
  - 말풍선은 그래프 상단의 예약 영역에서 선택한 요일 위에 놓고 양 끝에서 카드 안으로 보정한다. 선택 세로선·요일 알약을 함께 표시하고 나머지 막대는 흐리게 한다. 예약 영역의 높이는 말풍선의 실측 높이로 처음부터 잡아 둔다 — 탭할 때 그래프가 아래로 밀리지 않고, 큰 글씨에서는 그만큼 영역이 늘어난다.
  - **7칸은 항상 그래프 폭을 등분한다 — 그래프 안에 가로 스크롤을 두지 않는다**(개정 2026-09-28 — 종전 "좁은 화면에서만 가로 스크롤"을 폐기). 가로 움직임은 주 넘김(4.7)이 쓰고, 스크롤이 끼면 요일과 격자가 한 칸씩 어긋난다. 요일 칸이 44pt보다 좁아져도 칸 높이(막대 + 요일) 전체가 탭 영역이다.
- **격자**(추가 2026-09-28): 가로선 3줄(0 · 절반 · 그 주 최댓값) 1pt, 요일 경계마다 세로선(가로선보다 한 단 옅게 — 값 눈금이 주인공이다). 격자는 칸 끝에서 끝까지 그어 옆 주의 선과 이어진다(4.7).
- **오른쪽 축**(추가 2026-09-28): 그래프 오른쪽 끝의 고정 칸에 **위 = 그 주의 최댓값, 평균 점선 옆 = "평균", 아래 = "0"** 을 적는다.
  - 최댓값은 좁은 축 칸에 맞춰 **분 단위만** 적는다 — "72분"(말풍선·하루 평균은 "1시간 12분" 형식 그대로). **1~59초면 축도 "1분 미만"** 이다 — "0분" 축은 막대가 선 이유를 설명하지 못한다.
  - **"평균"과 14pt 이내로 붙는 최댓값·"0" 라벨은 숨긴다** — 겹쳐 읽히지 않는 것보다 하나를 빼는 편이 낫다.
  - 축은 주를 넘기는 동안 사라졌다가 새 주가 자리 잡은 뒤 나타난다(4.7). 조회 중·조회 실패·빈 주에는 비운다.
- **평균 기준선**: 그 주 하루 평균 높이에 가로 점선을 긋는다. **그 주에 지난 날이 하루뿐이면 평균 점선과 "평균" 축 라벨을 그리지 않는다**(개정 2026-09-28 — KAN-114). 평균은 지난 날 수로 나누므로 월요일에는 평균이 곧 그날 값이고, 점선이 유일한 막대 꼭대기와 정확히 겹쳐 축의 최댓값 라벨까지 가린다. 한 점을 자기 자신과 견주는 선은 전할 것이 없다 — **이틀째부터** 그린다. 카드 위의 "하루 평균" 값은 그대로 둔다(그건 견줌이 아니라 값이다).
- 기록이 없는 요일과 아직 오지 않은 요일은 **0 막대(자리 유지)** 다. 오늘에 해당하는 요일 라벨은 강조한다.
- 한 주 전체가 0이면 그래프 대신 빈 상태 문구를 보여준다(P10).

**주제 분포 — 주간 청취 카드의 주제 구획**

- **주간 청취 카드의 맨 아래 구획이다**(개정 2026-09-28 — 종전 별도 영역). 자기 카드(면·모서리)를 그리지 않고 그래프와는 여백으로만 가른다. **영역 제목 "주로 듣는 주제"는 두지 않는다** — 구획 안 헤드라인 라벨과 겹친다(개정 2026-09-27).
- **표현은 가로 막대 + 순위 목록이다**(개정 2026-09-27 — 종전 원형(도넛) 그래프 + 범례를 교체. `changes/archive/profile-topic-distribution-bars.md`). 도넛은 비슷한 크기 조각끼리 비교가 안 되고(38% vs 31%) 좁은 폭에서 범례가 도넛 밑으로 접혔다. 위에서부터:
  1. **1위 헤드라인** — 라벨 **"가장 많이 들은 주제"** + 1위 주제명 + 비율("커리어 38%").
  2. **전체 비율 가로 누적 막대** — 한 줄을 주제별 색으로 나눈다.
  3. **주제별 줄** — 색 점 · 주제명 · "N%" · 그 비율만큼의 가로 막대.
- **기간은 표시 중인 주다**(개정 2026-09-28 — 종전 가입 후 전체. `profile-api.md` 4.1 `weekly_listening.topic_distribution`). [◀]/[▶]·스와이프로 주를 넘기면 주제 구획도 그 주의 분포로 바뀐다.
  - **막대를 탭한 동안에는 그 요일의 분포를 그린다**(`daily_topic_distribution`의 해당 요일). 라벨이 **"가장 많이 들은 주제 · 화요일"** 로 바뀌어 기간을 밝히고, 탭을 해제하면(재탭·그래프 밖 탭·주 이동) 주 분포와 라벨 "가장 많이 들은 주제"로 돌아온다.
  - 주 이동의 조회 중·조회 실패 동안에는 주제 구획을 비우지 않고 **직전에 표시하던 주의 분포를 그대로 둔다**(4.7).
  - 방어 경로: 주 응답에 `topic_distribution`이 없으면(구버전 서버) 전체 기간 분포로 대신 그리고 라벨을 **"가장 많이 들은 주제 · 전체 기간"** 으로 밝힌다. 현행 서버는 항상 주별 분포를 내려주므로 정상 경로에서는 나타나지 않는다.
- **상위 5개 주제 + "기타"** 를 서버가 내려준 순서·비율 그대로 그린다(`profile.md` 4.7 — 합 100%). 클라이언트가 재정렬·재계산하지 않는다. "기타"는 `others_ratio`가 0보다 클 때만 맨 마지막 줄로 둔다.
- 비율 표기는 **정수 "N%"** — 서버가 정수로 정규화해 내려준 값을 그대로 쓴다.
- **절대값(시간)을 표시하지 않는다** — 비율만 보여준다(합의 2026-08-06. 기간이 주 단위로 바뀐 뒤에도 유지 — PM 2026-09-28 "비율만").
- 색만으로 주제를 구분하지 않는다 — 줄마다 주제명 텍스트가 항상 함께 있다.
- **분포가 바뀌면 막대가 왼쪽에서 자라난다** — 처음 나타날 때, 주를 넘길 때, 요일을 탭·해제할 때. 같은 분포면 다시 그리지 않는다.
- 그 주(또는 탭한 요일)에 청취 기록이 없으면 구획 안에 빈 상태 문구 **"청취 기록이 없어요"** 를 보여준다. 구획을 숨기지 않는다(4.8).

### 4.7 P9 이전 주 탐색

- **표시 주의 이웃 주를 미리 받아 둔다**(개정 2026-09-28 — 종전 "[◀ 이전 주] 탭 시점에 그 주만 추가 조회". `changes/archive/profile-weekly-swipe-pager.md`). 표시 주가 정해지면 그 주의 이전 주(`previous_week_start`)와, 이번 주가 아닌 다음 주(`next_week_start`)를 주 단위 조회(`profile-api.md` 4.2)로 미리 받아 옆 칸에 그린다 — 프로필 진입 시 이전 주 조회 1회가 따라붙는다. 다음 주가 이번 주면 요약 응답 값을 그대로 쓴다(조회 없음).
  - **받아 둔 주로 넘길 때는 조회도 스켈레톤도 없이 바로 옮긴다.** 스켈레톤이 한 프레임이라도 끼면 이어진 느낌이 깨진다.
  - 아직 받지 못한 주로 넘기면 그 시점에 조회한다(`profile.md` 4.6). 로딩 중에는 그래프 자리만 스켈레톤이고, 요약 3지표와 주제 구획은 그대로다(주제 구획은 직전 주의 분포 — 4.6).
  - **미리 받기 실패는 화면에 알리지 않는다.** 넘기는 시점에 다시 받고, 그때 실패하면 아래 인라인 에러로 알린다.
- 한 번 받은 주는 화면을 벗어나기 전까지 재조회하지 않는다. 화면을 벗어나면 받아 둔 주를 모두 버린다(미리 받은 주 포함).
- **카드를 가로로 밀면 주가 페이지처럼 넘어간다**(추가 2026-09-28 PM · 같은 날 "전 주가 완전히 이어진 것처럼"으로 보강) — 손가락을 오른쪽으로 밀면 이전 주, 왼쪽이면 다음 주(애플 건강·스크린 타임 방향). 화살표와 같은 활성 규칙을 따르고, 세로 움직임이 더 크면 화면 스크롤이 우선이다. 화살표는 그대로 둔다(보조 기술·발견성).
  - 그래프 구획에 **[이전 주 | 이 주 | 다음 주] 세 칸**을 같은 폭으로 나란히 두고, **끄는 만큼 줄 전체가 따라온다** — 옆 칸은 미리 받아 둔 이웃 주라 끌면 그 주의 막대가 실제로 딸려 들어온다(아직 받는 중이면 스켈레톤). 격자가 칸 끝까지 이어져 주와 주 사이에 이음새가 없다.
  - 놓으면 손가락 속도를 이어받은 스프링으로 **넘기거나 제자리로 돌아온다.** 충분히 밀었거나 빠르게 튕겼을 때만 넘긴다.
  - **갈 수 없는 쪽(가입 주의 이전 · 이번 주의 다음)은 고무줄이다** — 손가락 이동의 25%만 따라오고 놓으면 제자리로 돌아온다.
  - **화살표도 같은 모션으로 넘긴다** — 탭하면 같은 방향으로 한 칸 미끄러진다.
  - **미끄러지는 것은 그래프 구획(막대·격자·요일)뿐이다.** 머리 줄·"하루 평균"·오른쪽 축·주제 구획은 제자리에 있다. 하루 평균은 숫자만 새 주의 값으로 굴러 바뀌고, 오른쪽 축과 평균 점선은 끌기 시작하면 사라졌다가 새 주(또는 제자리)에 앉은 뒤 함께 나타난다 — 축 값은 주마다 달라, 미끄러지는 동안 옛 값이 새 막대 옆에 있으면 안 된다.
- **[◀]는 가입 주까지** — 가입 주에서 비활성. **[▶]는 이번 주에서만 비활성** — 이전 주를 보는 중에는 활성이다(미래가 아니라 이번 주 방향이므로).
- 주 단위 조회가 실패하면 그래프 자리에 인라인 에러 + [다시 시도]를 두고, 주 범위 표기는 이동하려던 주를 유지한다. 요약 3지표·주제 구획은 건드리지 않는다.
- 이전 주를 보다가 화면을 떠났다 돌아오면 **이번 주부터 다시 시작한다.** 주 위치는 저장할 상태가 아니다.

### 4.8 P10 기록 없음 · 통계 조회 실패

**변형 A — 청취 기록 없음(신규 사용자)**

- 요약 3지표는 **"0편" · "0분" · "0일"** 로 표시한다.
- 주간 청취 카드의 그래프 자리와 주제 구획은 각각 그래프 대신 빈 상태 문구 **"청취 기록이 없어요"** 를 보여준다. 머리 줄(제목·주 범위·화살표)과 "하루 평균"(0분)은 그대로 둔다.
- **영역을 숨기지 않는다**(`profile.md` 7장) — 숨기면 무엇이 채워질 자리인지 알 수 없다.

**변형 B — 통계 조회만 실패**

- 통계 영역 전체를 하나의 에러 블록으로 접는다 — 영역 제목 "청취 통계" + **"통계를 불러올 수 없어요"** + [다시 시도].
- **헤더·카드 2개와 내비게이션은 정상 동작한다**(`profile.md` 4.8). 반대(헤더·카드 실패·통계 정상)도 같다 — 부분 실패가 화면 전체를 덮지 않는다.
- [다시 시도]는 통계를 포함한 전체 재조회다(`profile-api.md` — 섹션별 부분 조회를 두지 않는다).

### 4.9 P6 로딩 · P7 조회 실패

**P6 로딩**

- 헤더(닉네임·이메일 줄·플랜 줄 자리)·카드 2개·통계 영역(요약 3지표 + 그래프 자리)에 스켈레톤. **설정 아이콘은 즉시 노출한다**(`profile.md` 5장) — 설정 진입은 프로필 조회 결과와 무관하다.
- 0.3초 미만이면 표시하지 않는다(`common-error-handling.md` 5장).

**P7 조회 실패**

- **화면 자체는 연다**(`profile.md` 4.8). 실패한 섹션(헤더 플랜 줄 포함)에만 **"정보를 불러올 수 없어요"** + [다시 시도]를 표시한다.
- **부분 실패**: `failed_sections`에 담긴 섹션만 에러로 두고 나머지는 정상 노출한다(`profile-api.md` 4.1). 통계만 실패하면 P10 변형 B다. 화면 전체를 에러로 덮지 않는다.
- **섹션이 에러여도 그 섹션의 내비게이션은 동작한다** — 하위 화면은 자기 데이터를 직접 조회하므로 요약 실패가 편집까지 막을 이유가 없다.
- [다시 시도]는 전체 재조회다. 연타는 인플라이트 요청이 있으면 무시한다.
- 세션 만료(401 갱신 실패)는 공통 처리로 시작 화면으로 이동한다(`common-error-handling.md` 4.1).

**편집 후 복귀 — 카드만 갱신**

- 하위 화면(관심사 관리·커리어 정보·이메일 인증·구독 관리)에서 **저장하고 돌아오면 요약을 재조회한다**(`profile.md` 4.4). 캐시를 그대로 두면 방금 한 변경이 반영되지 않은 것처럼 보인다.
- **전체 스켈레톤을 다시 띄우지 않는다.** 기존 값을 유지한 채 조용히 재조회하고, 도착한 값으로 해당 카드·헤더 줄만 갱신한다(`profile.md` 5장).
- **[취소]·뒤로가기로 나온 경우는 재조회하지 않는다**(`profile.md` 7장). 바뀐 것이 없는데 조회를 반복할 이유가 없다.
- 다른 기기에서 구독을 바꾼 경우는 다음 진입 시 재조회로 흡수된다.

### 4.10 오프라인 진입

- 마지막으로 받은 요약을 표시하고 상단에 오프라인 배너를 노출한다(`profile.md` 7장). 통계도 마지막 값 그대로다 — 낡았을 수 있으나 판정에 쓰이는 값이 아니다.
- **헤더 이메일 줄 탭 시 "온라인에서 인증할 수 있어요" 안내**를 띄우고 인증 화면으로 가지 않는다 — 코드 발송·검증이 전부 서버 왕복이다.
- 주간 그래프의 이전 주는 추가 조회가 필요하다 — 이웃 주 미리 받기는 조용히 실패하고, [◀ 이전 주]·스와이프로 넘기는 시점에 다시 받아 실패하면 인라인 에러 + [다시 시도]다(4.7과 동일).
- 다른 카드의 내비게이션은 허용한다. 하위 화면이 각자 오프라인 처리를 한다.

### 4.11 P11 가입 체험 안내 팝업 (2026-10-05, KAN-119 · 개정 KAN-121)

**체험을 받은 계정에 한 번, 체험이 언제까지 무제한인지와 그 뒤 하루 한도를 알린다**(`subscription.md` 4.8 "안내"). 신규 가입자는 온보딩을 마친 직후, 체험 도입 전에 가입한 계정은 서버가 체험을 준 뒤 처음 앱에 들어왔을 때 본다.

**구성** — 제목 **"N월 N일까지 무제한으로 들을 수 있어요"** / 본문 **"작은 선물을 준비했어요. 이후에는 하루 N편씩 들을 수 있어요."** / **[확인]** 하나

| 값 | 쓰는 곳 | 규칙 |
|---|---|---|
| `trial.last_free_date` | 제목의 "N월 N일" | 무제한으로 들을 수 있는 마지막 날. `ends_at`에서 계산하지 않는다 |
| `trial.daily_play_limit_after` | 본문의 "하루 N편" | **2를 하드코딩하지 않는다.** `null`(체험 중인 프로 구독자)이면 본문 둘째 문장이 **"이후에도 지금처럼 제한 없이 들을 수 있어요."** 가 된다 |

- **문구는 신규·기존 가입자가 같다**(KAN-121, FE 결정 2026-10-05). 종전 본문 첫 문장 "가입을 환영하는 선물이에요"는 몇 달 전에 가입한 사람에게 맞지 않아 **가입을 말하지 않는** "작은 선물을 준비했어요"로 바꿨다. 두 벌로 가르면 어느 진입에서 열렸는지를 팝업이 알아야 하고, 한 문장으로 둘 다 자연스럽게 읽혀 가를 이유가 없다. 체험 기간("7일")도 적지 않는다 — 기간은 서버 스위치(`SIGNUP_TRIAL_DAYS`)이고 날짜는 제목이 이미 말한다.
- **언제 뜨나 — `plan.trial`이 `null`이 아니고, 이 계정이 이 팝업을 아직 본 적이 없을 때**(KAN-121 — 종전 "온보딩을 막 끝낸 진입에서만"을 넓혔다). 온보딩 직후 여부로 가르지 않는다. Main(탭 화면)에 들어올 때마다 판정한다.
  - **신규 가입**: 첫 사용 튜토리얼 → 알림 사전 안내(O10) 다음이다(`onboarding-uiux.md` 4.6). 알림 사전 안내보다 먼저 두지 않는다 — 알림은 튜토리얼이 "매일 아침 도착한다"를 막 말한 직후가 가장 설득력 있다. 그 사이에 다른 팝업을 끼우면 그 순간을 잃는다.
  - **기존 가입자(앱 시작)**: 튜토리얼·알림 안내는 없다. 대신 **앱 시작에 먼저 뜰 수 있는 것이 모두 사라진 뒤**에 연다 — 실행 관문의 권장 업데이트 안내(`splash.md` 4.1), 푸시를 눌러 들어온 재생 확인 팝업(`paywall.md` 4.2), 한도 안내 시트. 업데이트 안내는 관문이 먼저 띄운 것이고, 푸시 재생 확인·한도 안내는 사용자가 고른 동작의 결과라 알리기만 하는 P11이 끼어들지 않는다. 떠 있는 도중에 그중 하나가 열리면 P11은 잠시 내려갔다가 그것이 닫힌 뒤 다시 뜬다(아직 "봤다"로 적히지 않았으므로).
  - 어느 경우든 앞의 것이 사라지고 **400ms 뒤** 연다(알림 사전 안내와 같은 박자 — 곧바로 뜨면 같은 팝업의 연속으로 읽힌다).
- **`plan.trial`이 있을 때만 그린다.** 스위치(`SIGNUP_TRIAL_ENABLED`)가 꺼져 있을 때 가입한 계정·체험이 끝난 계정은 `null`이다 — "가입했으니 체험 중"으로 가정하지 않고, 응답 `user.tier`가 `trial`인지로도 가르지 않는다. 값은 가입·로그인 응답에 없어 프로필 요약(`GET /users/me/profile`)에서 받는다 — **아직 안 본 계정만** Main 진입마다 한 번 받는다(본 계정은 서버도 부르지 않는다). 조회가 실패하거나 플랜 섹션이 부분 실패면 **띄우지 않고 "봤다"로도 적지 않는다** — 다음 실행에서 다시 판정되고, 그동안 체험은 프로필 플랜 줄(4.2)이 알린다.
- **"한 번"은 기기가 기억한다.** 서버에는 봤는지 기록하는 값이 없다(재생 확인 팝업 억제와 같은 기기 로컬 상태). 닫으면 **그 계정의 id**를 기기에 적고, 같은 계정에는 다시 띄우지 않는다. 같은 기기에서 다른 계정이 새로 가입하면 그 계정에는 뜬다.
  - **KAN-119 때(가입 직후에만 뜨던 때) 이미 본 계정은 다시 뜨지 않는다** — 같은 저장 키에 그 계정 id가 남아 있다.
  - **재설치·새 기기**: 기기 저장소에 그 계정 id가 없으면 체험 기간 안에 한 번 더 뜬다(FE 결정 2026-10-05). 같은 날짜를 다시 알리는 것이라 해가 없고, 막으려면 서버 컬럼이 필요한데 만들지 않기로 했다(`subscription.md` 4.8). 같은 기기의 재로그인은 기록이 남아 있어 뜨지 않는다 — 다만 기기는 **마지막으로 본 계정 하나**만 기억하므로, 그 사이 다른 계정이 이 기기에서 봤다면 체험 기간 안에 한 번 더 뜰 수 있다.
- **[확인] 하나만 둔다** — 고를 것이 없는 안내라 [취소]·[닫기]를 나란히 세우지 않는다(HIG Alerts — 정보 전달 알림은 버튼 하나). 공용 확인 다이얼로그의 버튼 하나짜리 변형이다(`design.md` §5). **딤 탭·뒤로가기도 [확인]과 같다** — 모두 "봤다"로 기록한다.
- **구독 유도를 얹지 않는다.** [구독 알아보기]를 두지 않는다 — 선물을 알리는 자리에서 결제를 권하면 선물이 미끼로 읽힌다.
- 체험이 바꾸는 것은 **재생 한도뿐**이다(광고·드립 편수는 무료 그대로) — 문구에 "모든 기능"·"광고 없이" 류를 쓰지 않는다.

## 6. 카피 원칙

- **해요체**로 통일한다.
- 카드 라벨은 **"관심 주제 관리" · "커리어 정보"** 다. "관심 주제 관리"에만 "관리"가 붙는 이유는 일괄 편집 화면의 진입점임이 이름에 드러나야 하기 때문이고, "커리어 정보"는 명사구로 통일한다(`settings.md` 4.1의 항목명과 동일). 플랜·이메일은 카드가 아니라 헤더 줄이므로 화면에 라벨 텍스트를 따로 쓰지 않는다 — 낭독기 라벨("현재 플랜"·"이메일")로만 쓴다(7장).
- 무료 플랜: **"무료 이용 중 · 하루 N편"** — N은 서버 값. 가입 체험 중: **"무료 체험 중 · N월 N일까지 무제한"** — 날짜는 서버 `last_free_date`(4.2).
- 가입 체험 안내 팝업(P11): 제목 **"N월 N일까지 무제한으로 들을 수 있어요"** / 본문 **"작은 선물을 준비했어요. 이후에는 하루 N편씩 들을 수 있어요."**(신규·기존 가입자 같은 문구. 이후 한도 `null`이면 둘째 문장 **"이후에도 지금처럼 제한 없이 들을 수 있어요."**) / 버튼 **[확인]**(4.11). 유료: 플랜명 + **"다음 결제일 N월 N일"**. 해지 예약: **"N월 N일까지 이용 가능"**. 결제 문제: **"결제에 문제가 있어요"**.
- 이메일: 미등록 **"이메일 미등록"** / 미인증 배지 **"인증되지 않음"**. 보조 문구는 두지 않는다(4.3 — 개정 2026-08-15).
- 커리어: 입력됨 **"직군 · 직무 · 연차"**(예: "기획 · 서비스 기획 · 4-6년") / 미입력 **"입력하면 추천이 정확해져요"** + **[입력하기]**.
- 통계 라벨: **"누적 청취" · "청취 시간" · "연속 청취"**(요약 3지표) / **"주간 청취" · "하루 평균"** / 오른쪽 축 **"평균" · "0"** / 주제 구획 **"가장 많이 들은 주제"** · 요일을 탭한 동안 **"가장 많이 들은 주제 · 화요일"**(요일은 "월요일"~"일요일") · 묶음 줄 **"기타"**.
  - 영역 제목 **"주로 듣는 주제"는 쓰지 않는다**(개정 2026-09-27 — 헤드라인 라벨 "가장 많이 들은 주제"와 겹친다).
  - **"가장 많이 들은 주제 · 전체 기간"** 은 주 응답에 주별 분포가 없을 때의 방어 경로에만 쓴다(4.6) — 주별 분포 도입 전 1단계의 라벨이었고, 정상 경로에서는 나타나지 않는다.
- 통계 값: **"N편" · "N분"/"N시간" · "N일" · "N%"** — 표기 형식은 4.6이 확정한다. 요일 값·하루 평균은 **"N분" / "N시간 N분" / "1분 미만"**(1~59초 — 개정 2026-09-28), 말풍선은 **"화요일, 32분"** 형태, 축 최댓값은 분 단위 **"N분"**(1~59초면 "1분 미만").
- 통계 빈 상태: **"청취 기록이 없어요"**(개정 2026-08-08 — "아직"을 뺐다. 이 문구는 신규 사용자의 이번 주뿐 아니라 **주 이동으로 도달한 과거의 전체 0인 주**에도 쓰이는데, 지나간 주에 "아직"은 시제가 어긋난다. 두 곳에 문구를 가르지 않고 하나로 통일한다). 통계 에러: **"통계를 불러올 수 없어요"** + [다시 시도]. 카드 에러: **"정보를 불러올 수 없어요"** + [다시 시도].
- 주간 범위: **"N월 N일 – N월 N일"**.
- **내부 용어를 노출하지 않는다** — "티어", "라이트", "구독 행", "캐시", "완청", "서비스 날짜". 화면에 쓰는 것은 플랜의 표시명(`plan_name`)과 위의 확정 카피뿐이다.
- 날짜는 "N월 N일" 형식으로 표기한다. 서버의 ISO 시각을 기기 로캘로 변환해 그린다 — 단 **만료·결제일·주 경계의 판정은 서버 몫**이고 표기만 클라이언트가 한다.

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 설정 아이콘, 헤더 이메일 줄·플랜 줄(줄이 작으므로 hitSlop으로 확보), [입력하기], 주 이동 화살표 [◀]/[▶].
- 설정 아이콘은 `role=button` + **"설정 열기"** 라벨. 아이콘만으로 의미가 전달되지 않는다.
- **카드·헤더 줄은 하나의 탭 영역으로 읽힌다** — "관심 주제 관리, 4개 선택, 커리어, 자기계발, 경제 외 1개, 관심사 관리 열기" / "커리어 정보, 기획, 서비스 기획, 4에서 6년, 커리어 정보 열기"처럼 값과 목적지를 한 문장으로. 안의 조각(배지·칩)을 개별 포커스로 쪼개지 않는다.
  - 헤더 이메일 줄: **"이메일, <주소>, 인증되지 않음, 이메일 인증 열기"**(미인증) / "이메일, <주소>, 이메일 인증 열기"(인증됨) / "이메일, 이메일 미등록, 이메일 인증 열기"(미등록).
  - 헤더 플랜 줄: "현재 플랜, 무료 이용 중 · 하루 2편, 요금제 관리 열기" 형태(2026-10-06 KAN-146 — 목적지 화면 이름 "요금제 관리"). 가입 체험 중이면 "현재 플랜, 무료 체험 중 · 10월 9일까지 무제한, 요금제 관리 열기". **MVP 바이너리(구독 UI 플래그 꺼짐)에서는 "현재 플랜, 무료 이용 중 · 하루 2편"까지만** — 목적지가 없으므로 role도 주지 않는다(4.2).
- **미인증 배지는 색 + 텍스트다.** 스크린리더는 "인증되지 않음"을 주소 뒤에 이어 읽는다.
- 관심 주제의 `+N`은 "외 N개"로 읽힌다 — "+3"을 "플러스 삼"으로 읽히게 두지 않는다.
- **통계 요약 타일은 값과 라벨을 한 문장으로 읽는다** — "누적 청취 128편".
- **주간 그래프의 막대는 요일별 값이 개별로 읽힌다** — "화요일, 32분"(60분 이상이면 "N시간 N분", **1~59초면 "토요일, 1분 미만"**, 0초면 "0분"). **말풍선(4.6)과 같은 문구다**(개정 2026-09-28 — KAN-114) — 값 표기 규칙이 한 곳이라 시각·비시각 경로가 어긋나지 않는다. 그래프 컨테이너 라벨은 "주간 청취, 8월 3일부터 8월 9일". [◀]/[▶]는 "이전 주" / "다음 주" 라벨 + 비활성 시 `disabled` 상태가 함께 읽힌다.
  - 막대는 탭 가능한 요소(버튼)로 노출되지만 **말풍선(4.6)은 보조기기에 별도로 알리지 않는다** — 라벨이 이미 값을 읽고 있어 시각 중복이다. 탭한 막대는 선택 상태(`selected`)로 읽힌다.
  - **"하루 평균"은 라벨과 값을 한 문장으로 읽는다** — "하루 평균 32분"(값 형식은 막대와 같다).
  - **격자·평균 점선·오른쪽 축("평균"·"0"·최댓값)은 장식으로 처리한다** — 평균은 "하루 평균" 문장이, 요일 값은 막대 라벨이 이미 읽는다.
  - **스와이프로 끌 때 옆에 딸려 보이는 이웃 주 칸은 보조기기에 노출하지 않는다** — 읽히는 것은 가운데(표시 중인) 주뿐이다. 스와이프를 쓸 수 없는 사용자는 [◀]/[▶]로 같은 이동을 한다(4.7).
- **주제 분포는 주제별 줄이 곧 대체 텍스트다** — 구획 전체가 하나로 "커리어 38%, 자기계발 24%, …, 기타 6%" 순서로 읽힌다(표현을 가로 막대로 바꾼 뒤에도 문구는 그대로 — 개정 2026-09-27). 누적 막대·주제별 막대는 장식으로 처리한다. 요일을 탭해 그날 분포로 바뀌면 같은 형식으로 그날 값을 읽는다.
- 이전 주 탐색으로 그래프가 갱신되면 `aria-live="polite"`로 주 범위를 알린다.
- 편집 후 복귀로 카드가 갱신되면 `aria-live="polite"`로 해당 카드만 알린다. 전체 화면을 다시 읽지 않는다.
- 동적 텍스트 200%에서 카드 내 줄바꿈을 허용한다 — 값이 길어지면(이메일 주소·커리어 요약) 말줄임 대신 두 줄로 접는다. 통계 요약 3분할은 세로 스택으로 전환을 허용한다.

## 8. 금지 사항

`profile.md`와 이 문서의 확정이 명시적으로 금지한 것들이다.

- **프로필에서 직접 서버에 쓰는 조작** — 인라인 편집, 토글, 저장 버튼 일체
- **관심 주제와 커리어의 편집을 한 화면·한 카드로 합치는 것** — 별도 카드·별도 화면이다(합의 2026-08-06). [관심 주제 관리]가 커리어 정보 화면으로, [커리어 정보]가 관심사 관리 화면으로 가게 만드는 것도 같다
- 헤더 플랜 줄에 **[해지]·[요금제 변경] 버튼**을 두는 것 — 결제 조작은 구독 관리 한 곳이다
- **닉네임 편집·프로필 이미지** 진입점
- 이메일 미인증·미등록 사용자에게 **인증을 강요하는 팝업·전면 배너** — 강제 지점은 첫 결제뿐이다
- 저장된 주소와 인증된 주소를 **같은 모양으로 표시**하는 것 — 배지 생략 금지
- 조회 실패 시 **화면 전체를 에러로 덮거나 내비게이션을 막는 것**
- 편집 화면 [취소] 복귀에 **재조회를 붙이는 것** / 저장 복귀에 **전체 스켈레톤을 다시 띄우는 것**
- 관리자가 숨긴 주제를 **요약 개수·주제 분포에서 빼는 것** — 편집 화면과 개수가 어긋난다(`profile.md` 7장)
- 클라이언트가 `expires_at`과 기기 시각으로 **구독 상태를 재판정**하는 것
- **통계를 클라이언트가 집계·보정하는 것** — 연속 일수 재계산, 기기 시각으로 주 경계 나누기, 04시 경계 보정 일체
- 주제 분포에 **절대값(시간)을 표시**하는 것 — 비율만 보여준다
- 청취 기록이 없다고 **통계 영역을 숨기는 것**
- 통계 수치를 **반올림·올림으로 부풀리는 것** — 표기는 버림이다(4.6)
- 설정 화면에 **프로필로 되돌아가는 계정 카드**를 만드는 것 (`settings.md` 2장 — 설정 쪽 금지지만 이 화면 쌍의 규칙이다)

## 10. 합의 사항

2026-08-06 합의로 확정되어 features(`profile.md` · `career.md`)와 이 문서에 반영을 마친 항목들이다.

- 관심사 관리 카드와 커리어 정보 카드를 분리한다. 편집 화면도 분리한다 — 관심사 관리 카드는 관심사 관리 페이지로, 커리어 정보 카드는 커리어 정보 페이지(`career.md`)로 이동한다.
- 관심 주제 관리에서 관심 주제를 최소 1개는 선택해야 저장할 수 있도록 강제한다 — 프로필에 0개 요약 상태가 생기지 않는다.
- 대표 주제 3개의 선정 기준은 따로 두지 않고 API 응답 순서의 앞 3개를 쓴다.
- 청취 통계를 프로필에 도입한다 — 누적 3지표 · 주간 요일별 그래프(이전 주 탐색) · 주제 분포 원형 그래프. (개정 2026-09-27 — 원형 그래프는 가로 막대 + 순위 목록으로 교체, 2026-09-28 — 주간 청취 카드의 주제 구획으로 합침. 4.6)
- 연속 청취 일수 인정 기준은 그날 재생 기록 1건으로 한다(최소 청취 시간 조건 없음).
- 주제 분포 집계 기간은 가입 후 전체 기간으로 하고 비율만 보여준다. (개정 2026-09-28 — PM 결정 "주마다 · 비율만": 화면이 그리는 기간은 **표시 중인 주**이고 막대를 탭하면 그 요일이다. 비율만 보여주는 것은 그대로다. 4.6)
- 누적 콘텐츠 수에는 완청한 콘텐츠만 반영한다(완청 판정 값은 `player.md` 소유).
- **수치 표기 형식(이 문서 확정, 4.6)** — 콘텐츠 "N편", 시간 60분 미만 "N분"·이상 "N시간"(버림), 연속 "N일", 분포 "N%"(정수), 주 범위 "N월 N일 – N월 N일".
