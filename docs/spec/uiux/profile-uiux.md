# 프로필 UI/UX 명세서

> 기준 문서: [`docs/pages/profile.md`](../../pages/profile.md) · 이메일 인증 규칙은 [`docs/pages/auth.md`](../../pages/auth.md) 4.4~4.5, 로딩·오류 표현은 [`docs/pages/common-error-handling.md`](../../pages/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/profile.html`](../../wireframe/profile.html) (화면 ID P1–P7)
> API: [`profile-api.md`](../api/profile-api.md)

## 1. 범위

하단 탭의 프로필 화면 — 헤더(닉네임·제공자·설정 아이콘)와 **3개 카드(현재 플랜 · 이메일 · 관심 주제 관리)**, 그 상태 변형과 로딩·오류까지 `profile.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 화면은 편집 로직을 갖지 않는다**(`profile.md` 1장). 관심사·커리어·이메일·구독의 저장 규칙은 전부 소유 화면의 것이고, 프로필은 **현재 값을 요약해 보여주고 소유 화면으로 보낼 뿐**이다.

**카드 구성의 확정 사항** (FE 확정 2026-08-06)

- **커리어 카드를 두지 않는다.** 커리어의 표시·입력·수정은 [관심 주제 관리] 카드로 들어간 **관심사 관리 화면에서 주제와 함께** 한다(그 화면의 커리어 섹션 — `interest-management.md` 4.1).
- 관심 주제 카드의 이름은 **"관심 주제 관리"** 다 — 카드가 요약 표시이자 편집 화면의 진입점임이 이름에 드러난다.
- 이 구성은 `profile.md` 4.1(4개 카드·순서 고정)과 어긋난다 — **pages 개정 필요**(9장 미결).

- 이메일 인증 화면 자체(A 계열)는 `auth-uiux.md`가 소유한다. 프로필은 진입점과 복귀만 다룬다.
- 구독 관리·관심사 관리 화면은 각 명세의 UIUX 문서가 소유한다(미작성).

## 2. 화면 목록

| ID | 화면 | 대응 상태(`profile.md` 5장) |
|---|---|---|
| P1 | 정상 — 유료 구독 · 인증된 이메일 | 정상 · 유료 사용자 |
| P2 | 무료 사용자 | 무료(라이트) |
| P3 | 이메일 미인증 | 이메일 있음 · 미인증 배지 |
| P4 | 이메일 미등록 | 이메일 없음 |
| P5 | 해지 예약 · 결제 문제 | 해지 예약 · 결제 문제 |
| P6 | 로딩 | 3개 카드 스켈레톤 |
| P7 | 조회 실패 — 카드별 에러 | 조회 실패(부분·전체) |

- "커리어 미입력" 상태는 프로필 화면 상태가 아니다 — 유도 문구("입력하면 추천이 정확해져요")는 관심사 관리 화면의 커리어 섹션 몫으로 옮겨졌다.
- "편집 후 복귀" 상태는 화면이 아니라 갱신 동작이므로 ID를 두지 않고 4.6에서 다룬다.
- 오프라인 상태는 P1~P5에 오프라인 배너가 얹힌 변형이다(4.7).

## 3. 화면 흐름

```
하단 탭 [프로필] ──> P6 로딩 ─┬─ 조회 성공 ──> P1~P5 (상태에 따라)
                               └─ 조회 실패 ──> P7 (화면은 열고 카드만 에러)

P1~P5 ─[⚙ 설정 아이콘]─> 설정 화면 (settings-uiux.md)
   ─[플랜 카드]──────────> 구독 관리 (subscription.md)
   ─[이메일 카드]────────> 이메일 인증 화면 (auth.md 4.4~4.5)
   │                         └─ 인증 성공 ─> 프로필 복귀 + 해당 카드 갱신
   │                         └─ 중도 이탈 ─> 프로필 복귀. 기존 값 그대로
   └─[관심 주제 관리 카드]─> 관심사 관리 — 주제 + 커리어를 한 화면에서 (interest-management.md)
                              └─ 저장 후 복귀 ─> 요약 재조회 (스켈레톤 없이 카드만 갱신)
                              └─ [취소] 복귀 ─> 재조회하지 않음
```

**진입 방향은 프로필 → 설정 한 방향이다.** 설정 화면에는 프로필로 되돌아가는 계정 카드가 없다(`settings.md` 2장).

## 4. 화면별 명세

### 4.1 P1 정상 — 화면 골격

**구성** — 헤더(닉네임 + 로그인 제공자 아이콘 + **우상단 ⚙ 설정 아이콘**) / [현재 플랜] 카드 / [이메일] 카드 / 구분선 / **[관심 주제 관리] 카드** / 하단 탭 3개([프로필] 활성)

- **카드 순서는 바꾸지 않는다.** 위 두 개는 계정·결제, 마지막 하나는 추천 입력 — 성격이 달라 구분선으로 나눈다(`profile.md` 4.1의 2단 구성 유지, 카드 수만 3개).
- **설정 진입점은 우상단 아이콘 하나뿐이다.** 목록 항목으로 두지 않는다 — 설정은 프로필의 하위 항목이 아니라 별개 화면이다(`profile.md` 4.1).
- **닉네임·제공자는 표시만 한다.** 탭해도 아무 일도 일어나지 않는다 — 편집 진입점을 두지 않는다(닉네임 편집·계정 통합은 MVP 비범위).
  - 제공자는 아이콘(카카오/네이버/구글)으로 표시한다. 아이콘에는 "카카오 계정으로 로그인" 형태의 접근성 라벨을 붙인다.
- 각 카드는 카드 전체가 탭 영역이다. 우측 셰브론(>)으로 이동 가능함을 표시한다.
- **플랜 카드(유료)**: 플랜명 + "다음 결제일 N월 N일" + [구독 관리] 진입. **해지 버튼을 두지 않는다** — 결제 조작의 진입점은 구독 관리 하나다(`profile.md` 4.2).
- **이메일 카드(인증됨)**: 주소 표시 + [변경]. 배지 없음.
- **[관심 주제 관리] 카드**: **"N개 선택"** + 대표 주제 칩 최대 3개 + 나머지 `+N`. 칩은 표시 전용이다 — 칩을 탭해도 개별 편집이 아니라 카드와 같은 관심사 관리 진입이다(개별 편집을 열면 저장 규칙이 두 벌이 된다).
  - **커리어도 이 카드로 들어가 같은 화면에서 입력·수정한다.** 프로필에 커리어 요약·입력 유도를 따로 두지 않는다(1장 확정). 카드에 커리어 요약 한 줄을 함께 표시할지는 미결이다(9장).

### 4.2 P2 무료 사용자

- **플랜 카드**: **"무료 이용 중 · 하루 N편"** + **[구독 알아보기]** 강조(주 액션 톤).
  - "하루 N편"의 N은 서버가 내려준 `daily_play_limit`이다. **2를 하드코딩하지 않는다**(`paywall.md` 5장).
  - 플랜명만으로는 무엇이 제한되는지 알 수 없으므로 한도를 함께 적는다(`profile.md` 4.2).
  - [구독 알아보기]도 구독 화면 진입일 뿐이다. 프로필에서 결제를 시작하지 않는다.
- 관심 주제가 0개인 사용자(기존 초과 보유자의 전체 해제 등): "0개 선택" 대신 **"관심 주제를 골라주세요"** + [고르러 가기]로 유도한다. 0이라는 숫자는 정보가 아니라 결핍 표시일 뿐이다.

### 4.3 P3 이메일 미인증 · P4 이메일 미등록

**세 상태를 같은 카드의 변형으로 구분한다**(`profile.md` 4.3 — `email` × `is_email_verified` 조합).

| 상태 | 카드 표시 | 버튼 |
|---|---|---|
| 미등록(P4) | **"등록되지 않음"** | [등록] |
| 미인증(P3) | 주소 + **"인증되지 않음" 배지** | [인증하기] · [변경] |
| 인증됨(P1) | 주소 | [변경] |

- **미인증 배지를 생략하지 않는다.** 저장된 주소와 인증된 주소를 같아 보이게 하면, 사용자는 결제 직전에야 인증이 필요함을 알게 된다(`profile.md` 4.3).
- P3·P4에는 보조 문구 **"결제하려면 인증된 이메일이 필요해요"** 를 카드 아래 한 줄로 둔다. **인증을 강요하는 팝업·배너를 띄우지 않는다** — 강제 지점은 첫 결제 하나뿐이다(`auth.md` 4.4).
- [인증하기]는 저장된 주소로 바로 코드를 발송하고, [등록]·[변경]은 주소 입력부터 시작한다. **세 버튼 모두 같은 인증 화면(A 계열)으로 간다** — 규칙이 갈라지면 발송 횟수 제한이 경로별로 샌다(`auth.md` 4.4).
- 인증 화면에서 성공하면 프로필로 복귀하고 이메일 카드가 새 값·인증 상태로 갱신된다. **중도 이탈하면 기존 값이 그대로다** — 카드에 어떤 중간 상태도 표시하지 않는다.
- 발송 5회 소진·쿨다운 등의 안내는 인증 화면(A 계열) 몫이다. 프로필 카드는 관여하지 않는다.

### 4.4 P5 해지 예약 · 결제 문제

| 상태 | 플랜 카드 표시 |
|---|---|
| 해지 예약 | 플랜명 + **"N월 N일까지 이용 가능"** — 중립 톤. 경고색을 쓰지 않는다 |
| 결제 문제(유예) | 플랜명 + **"결제에 문제가 있어요"** — 경고색 |

- **해지 예약을 경고 톤으로 그리지 않는다.** 사용자가 스스로 내린 결정이지 장애가 아니다. 경고색은 사용자가 조치해야 하는 상태(결제 문제)에만 쓴다.
- 결제 문제 카드를 탭하면 구독 관리로 이동한다. **프로필에서 결제 수단 수정을 시도하지 않는다.**
- 판정은 서버가 내려준 `plan.status`(`profile-api.md` 4.1)를 그대로 그린다. 클라이언트가 `expires_at`과 기기 시각을 비교해 상태를 재판정하지 않는다.

### 4.5 P6 로딩 · P7 조회 실패

**P6 로딩**

- 헤더의 닉네임 자리와 3개 카드에 스켈레톤. **설정 아이콘은 즉시 노출한다**(`profile.md` 5장) — 설정 진입은 프로필 조회 결과와 무관하다.
- 0.3초 미만이면 표시하지 않는다(`common-error-handling.md` 5장).

**P7 조회 실패**

- **화면 자체는 연다**(`profile.md` 4.5). 실패한 카드에만 **"정보를 불러올 수 없어요"** + [다시 시도]를 표시한다.
- **부분 실패**: `failed_sections`에 담긴 카드만 에러로 두고 나머지는 정상 노출한다(`profile-api.md` 4.1). 화면 전체를 에러로 덮지 않는다.
- **카드가 에러여도 그 카드의 내비게이션은 동작한다** — 하위 화면은 자기 데이터를 직접 조회하므로 요약 실패가 편집까지 막을 이유가 없다.
- [다시 시도]는 전체 재조회다. 연타는 인플라이트 요청이 있으면 무시한다.
- 세션 만료(401 갱신 실패)는 공통 처리로 시작 화면으로 이동한다(`common-error-handling.md` 4.1).

### 4.6 편집 후 복귀 — 카드만 갱신

- 하위 화면(관심사 관리·이메일 인증·구독 관리)에서 **저장하고 돌아오면 요약을 재조회한다**(`profile.md` 4.4). 캐시를 그대로 두면 방금 한 변경이 반영되지 않은 것처럼 보인다.
- **전체 스켈레톤을 다시 띄우지 않는다.** 기존 값을 유지한 채 조용히 재조회하고, 도착한 값으로 카드만 갱신한다(`profile.md` 5장).
- **[취소]·뒤로가기로 나온 경우는 재조회하지 않는다**(`profile.md` 7장). 바뀐 것이 없는데 조회를 반복할 이유가 없다.
- 관심사 관리에서 **커리어만 수정하고 돌아온 경우에도** 재조회한다 — 카드에 커리어 요약을 표시하지 않는 동안은 화면 변화가 없지만, 갱신 규칙을 저장 종류별로 나누면 표시 정책이 바뀔 때 누락이 생긴다.
- 다른 기기에서 구독을 바꾼 경우는 다음 진입 시 재조회로 흡수된다.

### 4.7 오프라인 진입

- 마지막으로 받은 요약을 표시하고 상단에 오프라인 배너를 노출한다(`profile.md` 7장).
- **이메일 카드 탭 시 "온라인에서 인증할 수 있어요" 안내**를 띄우고 인증 화면으로 가지 않는다 — 코드 발송·검증이 전부 서버 왕복이다.
- 다른 카드의 내비게이션은 허용한다. 하위 화면이 각자 오프라인 처리를 한다.

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **요약 카드** | 3개 항목 | 카드 전체가 탭 영역 + 우측 셰브론. 카드별 독립 에러 상태를 가진다 |
| **배지** | 이메일 미인증 | 색 + **"인증되지 않음" 텍스트.** 색만으로 구분하지 않는다 |
| **스켈레톤** | 최초 조회 | 카드 3개. 0.3초 미만 미표시. 설정 아이콘은 제외 |
| **카드 인라인 에러** | 부분 조회 실패 | 문구 + [다시 시도]. 화면 전체 에러로 덮지 않는다 |
| **상단 배너** | 오프라인 | 공통 규칙(`common-error-handling.md` 5장) |
| **토스트** | 인증 성공 복귀 등 하위 화면발 통지 | 3초. 하위 화면 규칙을 따른다 |

## 6. 카피 원칙

- **해요체**로 통일한다.
- 카드 라벨은 **"현재 플랜" · "이메일" · "관심 주제 관리"** 다. 마지막 카드만 "관리"가 붙는 이유는 그 카드가 편집 화면(주제 + 커리어)의 진입점이기 때문이다.
- 무료 플랜: **"무료 이용 중 · 하루 N편"** — N은 서버 값. 유료: 플랜명 + **"다음 결제일 N월 N일"**. 해지 예약: **"N월 N일까지 이용 가능"**. 결제 문제: **"결제에 문제가 있어요"**.
- 이메일: **"등록되지 않음"** / **"인증되지 않음"**(배지) / 보조 **"결제하려면 인증된 이메일이 필요해요"**.
- 카드 에러: **"정보를 불러올 수 없어요"** + [다시 시도].
- "입력하면 추천이 정확해져요"(커리어 유도)는 **프로필 카피가 아니다** — 관심사 관리 화면의 커리어 섹션 몫이다.
- **내부 용어를 노출하지 않는다** — "티어", "라이트", "구독 행", "캐시". 화면에 쓰는 것은 플랜의 표시명(`plan_name`)이다.
- 날짜는 "N월 N일" 형식으로 표기한다. 서버의 ISO 시각을 기기 로캘로 변환해 그린다 — 단 **만료·결제일의 판정은 서버 몫**이고 표기만 클라이언트가 한다.

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 설정 아이콘, 카드 내 버튼([인증하기]·[변경] 등).
- 설정 아이콘은 `role=button` + **"설정 열기"** 라벨. 아이콘만으로 의미가 전달되지 않는다.
- **카드는 하나의 탭 영역으로 읽힌다** — "관심 주제 관리, 4개 선택, 커리어, 자기계발, 경제 외 1개, 관심사 관리 열기"처럼 값과 목적지를 한 문장으로. 카드 안의 조각(배지·칩)을 개별 포커스로 쪼개지 않는다. 단 이메일 카드처럼 버튼이 두 개([인증하기]·[변경])면 버튼만 개별 포커스를 준다.
- **미인증 배지는 색 + 텍스트다.** 스크린리더는 "인증되지 않음"을 주소 뒤에 이어 읽는다.
- 관심 주제의 `+N`은 "외 N개"로 읽힌다 — "+3"을 "플러스 삼"으로 읽히게 두지 않는다.
- 편집 후 복귀로 카드가 갱신되면 `aria-live="polite"`로 해당 카드만 알린다. 전체 화면을 다시 읽지 않는다.
- 동적 텍스트 200%에서 카드 내 줄바꿈을 허용한다 — 값이 길어지면(이메일 주소 등) 말줄임 대신 두 줄로 접는다. 주소의 뒷부분(도메인)이 잘리면 어느 계정인지 확인할 수 없다.

## 8. 금지 사항

`profile.md`와 이 문서의 확정이 명시적으로 금지한 것들이다.

- **프로필에서 직접 서버에 쓰는 조작** — 인라인 편집, 토글, 저장 버튼 일체
- **커리어 카드·커리어 입력 유도를 프로필에 되살리는 것** — 커리어는 관심 주제 관리 화면에서 주제와 함께 다룬다(1장 확정)
- 플랜 카드에 **[해지]·[요금제 변경] 버튼**을 두는 것 — 결제 조작은 구독 관리 한 곳이다
- **닉네임 편집·프로필 이미지** 진입점
- 이메일 미인증·미등록 사용자에게 **인증을 강요하는 팝업·전면 배너** — 강제 지점은 첫 결제뿐이다
- 저장된 주소와 인증된 주소를 **같은 모양으로 표시**하는 것 — 배지 생략 금지
- 조회 실패 시 **화면 전체를 에러로 덮거나 내비게이션을 막는 것**
- 편집 화면 [취소] 복귀에 **재조회를 붙이는 것** / 저장 복귀에 **전체 스켈레톤을 다시 띄우는 것**
- 관리자가 숨긴 주제를 **요약 개수에서 빼는 것** — 편집 화면과 개수가 어긋난다(`profile.md` 7장)
- 클라이언트가 `expires_at`과 기기 시각으로 **구독 상태를 재판정**하는 것
- 설정 화면에 **프로필로 되돌아가는 계정 카드**를 만드는 것 (`settings.md` 2장 — 설정 쪽 금지지만 이 화면 쌍의 규칙이다)

## 9. 미결 사항

- **`profile.md` 개정 필요** — FE 확정(2026-08-06): 커리어 카드 제거, 관심 주제 카드 → "관심 주제 관리", 커리어는 그 화면에서 주제와 함께. `profile.md` 4.1(4개 카드·순서)·4.4·5장(커리어 미입력 상태)의 개정이 필요하다. **개정 내역은 미결 검토가 끝난 뒤 `changes/pending`에 일괄 기록하기로 했다**(현재 기록 위치: 이 문서·`profile-api.md`·`profile.html` 검증 섹션).
- **[관심 주제 관리] 카드의 커리어 요약 표시 여부** — 주제 요약만 둘지, 커리어 한 줄을 함께 둘지. 표시하기로 하면 `profile-api.md` 응답에 필드를 추가하고 연차 구간 라벨 정의를 `interest-management.md`와 한 곳으로 못 박는다.
- **관심 주제 0개 카드의 문구(4.2)** — "관심 주제를 골라주세요"는 이 문서가 임의로 정했다. `profile.md` 5장에 이 상태의 정의가 없다 — pages 확정 필요.
- **대표 주제 3개의 선정 기준** — `display_order` 정렬로 정했으나(`profile-api.md` 9장) "대표"의 의도 확인 필요.
- **관심사 관리 화면의 커리어 섹션 구성** — 주제와 커리어를 한 화면에서 다루는 구체 배치(스크롤 진입·저장 단위)는 그 화면의 UIUX 명세(미작성)에서 확정한다. 커리어 유도 문구("입력하면 추천이 정확해져요")도 그쪽으로 옮겨졌다.
- **청취 통계 카드** — PRD에 요구가 없어 범위 밖(`profile.md` 미결). 도입되면 카드 구성의 재검토가 필요하다.
- **와이어프레임 동기화** — `profile.html`은 3카드 구성(P1–P7) 기준. 커리어 요약 표시 여부가 확정되면 함께 갱신한다.
