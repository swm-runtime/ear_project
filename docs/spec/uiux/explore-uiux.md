# 탐색 · 검색 UI/UX 명세서

> 기준 문서: [`docs/features/explore.md`](../../features/explore.md) · 재생 판정·확인 팝업은 [`docs/features/paywall.md`](../../features/paywall.md), 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/explore.html`](../../wireframe/explore.html) (화면 ID E1–E13)
> API: [`explore-api.md`](../api/explore-api.md)

## 1. 범위

탐색 탭 — 섹션형 추천 피드(**세로 행 목록**), 주제 필터와 단일 목록 전환, 검색창 줄의 잔여 재생 표시, 더보기 시트의 상세 정보·담기/제거, 재생 확인 팝업의 탐색 적용, 검색과 빈 상태·오류 상태까지 `explore.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 피드 구성·담기·자동 적립은 `explore.md`가, **재생 한도 판정과 확인 팝업·[오늘은 그만 보기] 억제는 `paywall.md`가**, 통신 계약은 `explore-api.md`가 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 조작에 어떻게 반응하는가**다.

- **판정과 표시를 섞지 않는다.** 검색창 줄의 잔여 횟수는 서버 값을 그리는 힌트다. 표시된 숫자를 근거로 재생을 통과시키지 않는다(`paywall.md` 4.1).
- 페이월 바텀시트·한도 안내의 구성·문구는 다루지 않는다. 탐색은 **그것을 여는 지점**만 소유한다.
- **재생 확인 팝업의 구성은 `library-uiux.md` 4.6(L3)과 동일하다.** 탐색이 다시 정의하지 않는다 — 진입점이 달라도 같은 팝업이다(`paywall.md` 4.2).

**화면 구성의 확정 사항** (FE 확정 + 합의 2026-08-06·2026-08-23 — `explore.md` 반영 완료)

- 콘텐츠는 카드 그리드가 아니라 **길고 좁은 행(row)을 세로로 일렬 배치**한다 — 음악 앱의 트랙 리스트와 같은 형태이며, 라이브러리의 아이템 행과 같은 문법이다.
- **행 본문 탭 = 곧장 재생 판정.** 행에는 담기 버튼이 없다.
- **담기/제거는 더보기 액션시트가 소유한다**(`explore.md` 4.3). **행에는 담김 표시를 두지 않는다** — 담김 여부는 시트의 담기/제거 분기로만 확인한다(합의 2026-08-07).
- **담김 여부는 노출에 영향을 주지 않는다.** 담았든 안 담았든 전부 보이며, 행에 구분 표시도 없다.
- **완청한 콘텐츠는 썸네일 좌상단에 체크를 붙인다** — 라이브러리 카드와 같은 마킹이다(합의 2026-08-07).
- **공유(FR-27)는 MVP 제외다**(`explore.md` 4.6). MVP의 더보기 시트에 공유 항목을 노출하지 않고, P1 도입 시 활성화한다.
- **더보기 시트에 [상세 정보] 항목을 둔다**(합의 2026-08-23 — `explore.md` 3장). 탭하면 콘텐츠 상세 화면으로 이동하며, 화면 규칙은 `content-detail.md`가 소유한다. **행 본문 탭 = 즉시 재생은 그대로다** — 상세는 더보기 경유로만 진입한다.
- **인기 콘텐츠는 사용자가 주간·월간·전체 중 하나를 골라 본다**(확정 2026-08-07 — `explore.md` 4.1-1). 기본은 **월간**이고, 전환은 그 섹션만 갈아끼운다.
- **검색(FR-22)은 MVP 포함으로 격상됐다**(개정 2026-08-23 — `explore.md` 4.5, 종전 "P1 유지·검색창 비활성 노출" 합의 2026-08-06 폐기). 검색창을 탭하면 검색 화면(E6)으로 전환한다.
- **오프라인 캐시 피드는 사용하지 않는다**(`explore.md` 5장·7장). 오프라인·조회 실패는 에러 화면 + [다시 시도]다.

E1 ─[인기 구간 토글]─> E13 ─ GET /explore/popular?period=... ─┬─ 성공 ─> 인기 섹션만 교체
   │                                                            └─ 실패 ─> 직전 목록 유지 + 인라인 에러
   ─[주제 칩 선택]─> E2 단일 목록 ─┬─ 결과 있음 ─> E2 (잔여 표시 유지)

   ├─ 소진(BLOCKED) ────────> 페이월 바텀시트 (팝업 없음. 시트 안에 한도 안내 문구 포함)

## 4. 화면별 명세

### 4.1 E1 정상 — 섹션형 피드(행 목록)

**구성** — 검색창 줄(검색창 + **우측 잔여 재생 표시**) / 주제 칩 줄(가로 스크롤) / 섹션(섹션 제목 + **세로 행 목록**)의 반복 / 하단 탭 3개([탐색] 활성)

**행(row)**: 썸네일(소, **완청이면 좌상단 체크**) · 제목 · 출처·저자 · 길이 · 더보기 버튼 — 라이브러리 아이템 행과 같은 문법이다.

- **가로 스크롤 카드·그리드를 쓰지 않는다.** 행을 세로로 일렬 배치한다(1장 확정). 섹션이 바뀌어도 행의 모양은 같다 — 목록의 밀도와 스캔 방향이 화면 전체에서 하나여야 한다.
- **검색창을 탭하면 검색 화면(E6)으로 전환한다**(개정 2026-08-23 — `explore.md` 4.5 MVP 포함 격상, 종전 "MVP 비활성 노출" 폐기). 검색 화면의 규칙은 4.6이다.
- **섹션 제목은 서버가 내려준 `title`을 그대로 그린다.** 섹션 구성·순서·섹션당 행 수는 서버 제어다(`explore.md` 4.1) — `key`로 제목을 조립하면 서버가 섹션을 바꿀 수 없다.
  - **인기 섹션 제목 줄에는 구간 토글(주간·월간·전체)이 붙는다** — 그 섹션에만 있는 컨트롤이며 상세는 4.10(E13)이다. 첫 진입의 선택 상태는 피드 응답의 `period`가 정한다.
  - **인기 섹션은 배포 첫 주(직전 확정 구간 없음)에도 숨기지 않는다**(합의 2026-08-06 — `explore.md` 4.1). 표본 크기와 무관하게 같은 선정 기준으로 정렬한 상위가 내려온다. 클라이언트는 섹션 유무를 판단하지 않고 응답을 그대로 그린다.
- **행 본문 탭은 상세를 거치지 않고 곧장 재생 판정으로 간다**(PRD 5.3). 더보기 버튼만 별도 히트 영역이다 — 우측 끝에 고정하고 최소 44×44pt를 확보한다(`library-uiux.md` 4.1과 같은 이유: 경계가 불분명하면 재생하려다 시트가 열린다).
- **행에 담기 버튼을 두지 않는다.** 담기/제거는 더보기 시트(4.4)가 소유한다.
- **라이브러리 상태 표시** — `explore-api.md` 4.1의 `library` 필드로 가른다:

| `library` | 행 표시 |
|---|---|
| `null` | 표시 없음 |
| 값 있음 · `status != completed` | 표시 없음 |
| 값 있음 · `status == completed` | 썸네일 좌상단 **완청 체크** |

  - **담김 여부를 행에 표시하지 않는다.** 행 탭은 담김 여부와 무관하게 재생이라 표시가 행동을 바꾸지 않고, 담기/제거 판단이 필요한 순간은 시트를 연 때다 — 시트가 상태를 이미 말해준다. 노출·순서에도 쓰지 않는다(서버 랭킹 그대로).
  - **완청 체크는 라이브러리 카드와 같은 마킹을 쓴다** — 같은 콘텐츠가 화면에 따라 표시가 달라지면 행 문법이 어긋난다. 판정 근거는 `library.status`이며 클라이언트가 별도 조회하지 않는다.
  - 출처(`drip`/`save`/`onboarding`)를 구분해 표시하지 않는다 — 탐색에서 필요한 정보는 "이미 내 라이브러리에 있다" 하나뿐이고, 그것도 시트가 말해준다. 출처 구분은 라이브러리 화면의 몫이다.
- **주제 칩은 사용자의 관심 주제를 앞쪽에, 나머지를 뒤에 배치한다**(`explore.md` 4.2). 칩 줄은 가로 스크롤이다.
- **잔여 표시를 주제 칩 줄에 넣지 않는다.** 칩은 가로 스크롤이라 숫자가 스크롤을 따라 사라진다(`explore.md` 4.4-1). **행마다 붙이지도 않는다** — 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다(`paywall.md` 5장).
- 당겨서 새로고침은 인디케이터를 노출하고, 포그라운드 복귀·플레이어 복귀 시 재조회는 **인디케이터 없이 조용히** 수행한다(`common-error-handling.md` 4.3). 잔여 표시·완청 체크도 이때 서버 값으로 덮어쓴다.

### 4.2 E1 검색창 줄의 잔여 재생 표시 (E1 · E2 · **E5**)

**자리는 검색창 줄의 우측 한 곳이다**(`explore.md` 4.4-1). 문구는 `paywall.md` 5장의 **"오늘 재생 N/M 남음"** 한 문자열을 그대로 쓴다.

| 조건 | 표시 | 인터랙션 |
|---|---|---|
| `daily_play_limit != null`, N > 0 | "오늘 재생 N/M 남음" — 중립색 | 없음(탭 불가) |
| N = 0 (소진) — **E5** | "오늘 재생 0/M 남음" — **주의색 유지** | 탭 → 페이월 바텀시트. **최상위 티어는 페이월 대신 한도 안내**(`paywall.md` 4.1) |
| `daily_play_limit == null` (무제한) | **표시하지 않는다.** "무제한" 배지도 없다 | — |
| 응답에 값 없음 | **표시하지 않는다.** 0으로 가정하지 않는다 | — |
| 검색 화면(E6·E7) | **숨긴다** — 검색창이 입력 상태로 그 줄을 다 쓴다 | — |
| 오프라인·네트워크 오류(E10) | 화면 자체가 전체 에러라 검색창 줄이 없다 | — |
| 최초 로딩(E11) | 스켈레톤도 그리지 않는다 | — |

- **소진 상태(E5)에서 표시를 탭했을 때의 분기는 티어의 위치로 가른다**(`paywall.md` 4.1 — 합의 2026-08-06). 최상위가 아닌 한도 티어(무료 포함)는 페이월 바텀시트를 열고 — 시트 헤드라인에 **"오늘 청취 한도를 모두 사용했어요"** 문구가 포함된다 —, 최상위 티어는 페이월 없이 같은 한도 안내 문구만 띄운다. 시트·안내의 구성과 문구는 `paywall.md` 소유이며 탐색은 여는 지점만 소유한다.
- **필터를 걸어 단일 목록(E2)으로 전환해도 표시는 유지한다.** 검색창 줄은 두 모드 모두에 남아 있다(`explore.md` 4.4-1).
- **검색 화면에서 숨기는 것은 표시이지 규칙이 아니다.** 검색 결과를 탭한 재생은 판정·팝업을 동일하게 거친다(`explore.md` 7장).
- **라이브러리와 같은 숫자여야 한다.** 각자 계산하지 않고 서버가 내려준 세 필드를 그대로 쓴다(`explore-api.md` 2장). 클라이언트가 임의로 1을 빼지 않고, 기기 시각으로 04시 리셋을 판단하지 않는다 — 세부 규칙은 `library-uiux.md` 4.3과 전부 동일하다.
- 무제한 티어 결제 직후에는 복귀 시 피드를 재조회해 표시를 제거한다(`explore.md` 7장 · `paywall.md` 4.5).

### 4.3 E2 주제 필터 적용 — 단일 목록

**구성** — 검색창 줄(잔여 표시 유지) / 주제 칩 줄(선택 칩 강조) / **단일 행 목록** / 무한 스크롤

- **필터 선택 시 섹션 구조를 버리고 단일 목록으로 전환한다**(`explore.md` 4.2). 섹션 안에서 필터링하지 않는다.
- **행의 모양·동작은 E1과 완전히 같다**(탭=재생, 더보기=담기/제거, 완청 체크). 바뀌는 것은 섹션 묶음이 사라지는 것뿐이다.
- **다중 선택은 OR 조합이다.** 선택 칩이 늘수록 결과가 넓어진다. 칩을 전부 해제하면 섹션형(E1)으로 복귀한다.
- 추가 로딩은 리스트 하단 인라인 스피너, 실패 시 인라인 에러 + [다시 시도] — **기존 목록을 유지한다**(`common-error-handling.md` 4.3).
- 결과가 없으면 E9로 전환한다. **칩 줄은 유지한다** — 비어 보이는 원인이 그 조작에 있으므로 되돌릴 컨트롤을 감추지 않는다.

### 4.4 E3 · E12 담기/제거 — 더보기 시트 소유

**담기/제거의 진입점은 행의 더보기 버튼 하나다.** 행 본문 탭은 언제나 재생이다.

**E12 더보기 액션시트 구성(MVP)** — 대상 콘텐츠 요약(썸네일·제목·출처) / **[상세 정보]**(추가 2026-08-23) / **[원문 보기]**(`source_url` 있을 때만 — 추가 2026-08-10) / **[라이브러리에 담기]** 또는 **[라이브러리에서 제거]**(제거는 **위험색** — `library-uiux.md` 4.7, 세 화면 공통 규칙) / [닫기]

- **[상세 정보]**(합의 2026-08-23 — `explore.md` 3장) — 탭하면 시트가 닫히고 콘텐츠 상세 화면으로 이동한다. 화면 규칙은 `content-detail.md`가 소유한다(진입·복귀는 그 문서 2장 — 뒤로가기로 원 화면 복귀, 목록 스크롤 위치 유지). **행 본문 탭 = 즉시 재생은 그대로다** — 상세는 더보기 경유로만 진입한다.
- **[원문 보기]** — 탭하면 인앱 브라우저로 원문을 열고 원문 유입 클릭을 기록한다(`player.md` 4.5와 같은 규칙 — `source_link_clicks`). 라이브러리 L4·플레이어 PL7 더보기와 통일된 공통 항목이다(검토 결정 2026-08-10 — `explore.md` 4.3).

- **MVP 시트에 [공유] 항목을 노출하지 않는다**(`explore.md` 4.6 — 합의 2026-08-06, FR-27 MVP 제외). 종전의 "상세 항목도 없다"(합의 2026-08-06)는 **재개정됐다** — 상세 화면 도입 확정(합의 2026-08-23)으로 [상세 정보] 항목이 시트에 들어간다.
- **P1에서 공유가 활성화되면** [공유] 항목이 담기/제거 아래에 추가된다 — OS 공유 시트를 열고, 공유 텍스트는 **콘텐츠 제목 + 저자·출처 + 스토어 링크**(`explore.md` 4.6). **공유 시트에서 취소하면 아무 동작 없고 신호도 기록하지 않는다**(`explore.md` 7장 — 시트 오픈만으로는 공유가 아님).
- **어느 콘텐츠에 대한 조작인지 시트 상단에 다시 보여준다**(`library-uiux.md` 4.7과 같은 규칙).
- 담기/제거는 `library` 값으로 가른다 — `null`이면 [라이브러리에 담기], 값이 있으면 [라이브러리에서 제거]. **출처와 무관하게 제거를 허용한다**(드립 적립분도 여기서 뺄 수 있다 — `explore-api.md` 9장).
- 담기 시 서버가 `user_signals(action = save)`를, 제거 시 `unsave`를 적재하지만(`explore.md` 4.3 — FR-15) **화면에는 어떤 표시도 없다.** 신호 적재는 서버 몫이고 이 문서의 화면 동작에 나타나지 않는다.

**E3 담기 완료**

- [라이브러리에 담기] 탭 → 시트가 닫히고 토스트 **"라이브러리에 담았어요"** + **[보러가기]**(라이브러리 탭 이동, 3초). **행의 모양은 바뀌지 않는다** — 결과는 토스트와, 시트를 다시 열었을 때의 [라이브러리에서 제거]로 확인된다.
- **담기에는 어떤 티어에서도 페이월이 뜨지 않는다**(PRD 5.4). 소진 상태(E5)에서도 담기는 정상 동작한다.
- **[라이브러리에서 제거]는 토스트 없이** 시트가 닫히는 것으로 피드백한다.
  - 실행 취소는 다시 담기가 대신한다. **제거도 드립 영구 제외를 만들지만 고지하지 않는다**(`explore.md` 4.3 — 라이브러리 삭제와 같은 이유: 가벼운 조작에 무거운 고지를 붙이지 않는다).
- 담기·제거를 번갈아 반복하면 마지막 조작이 시트의 최종 상태다. 오래된 응답은 `client_seq`로 무시한다(`explore-api.md` 4.3).
- 담기 실패(서버 오류)는 시트의 낙관적 상태를 원상 복구하고 토스트로 알린다(`common-error-handling.md` 4.4).
- 회수된 콘텐츠를 담으면 "제공이 종료된 콘텐츠예요" 토스트 + 행 제거(403 — `explore-api.md` 4.3).
- **재생 자동 적립**(`explore-api.md` 4.6)도 행에 표시를 남기지 않는다 — 조용한 재조회로 `library` 값만 갱신되고, 그 결과는 시트를 열 때 [라이브러리에서 제거]로 나타난다.

### 4.5 E4 재생 확인 팝업 — 탐색 적용

**구성·문구·버튼·[오늘은 그만 보기] 규칙 전부 `library-uiux.md` 4.6(L3)과 동일하다.** 이 절은 탐색 고유의 것만 적는다.

- 노출 조건 판정에 쓰는 `is_counted_today` · `daily_play_limit`은 피드·목록 응답의 값이다(`explore-api.md` 4.1).
- **억제 상태는 라이브러리와 같은 로컬 키를 공유한다**(`explore.md` 6장). 라이브러리에서 [오늘은 그만 보기]를 눌렀으면 탐색에서도 뜨지 않고, 반대도 같다.
- [재생하기] 재판정이 소진(`BLOCKED`)이면 팝업을 닫고 페이월로 전환한다 — 겹쳐 쌓지 않는다. 최상위 티어의 재판정 소진(`LIMIT_REACHED`)이면 페이월 대신 한도 안내다(`paywall.md` 4.1).
- **[취소]하면 자동 적립도 일어나지 않는다**(`explore.md` 7장). 적립은 재생이 실제로 시작된 뒤다.

### 4.6 E6 · E7 검색

**검색은 MVP 포함이다**(개정 2026-08-23 — `explore.md` 4.5, 종전 "P1 유지·검색창 비활성 노출" 합의 2026-08-06 폐기).

**진입·이탈** (`explore.md` 4.5-1)

- 검색창을 탭하면 검색 화면(E6)으로 전환하고 키보드를 올린다. **잔여 표시는 숨긴다**(4.2). **하단 미니플레이어는 유지된다.**
- [취소]·뒤로가기로 피드에 복귀한다. **피드의 상태(필터·인기 구간·스크롤 위치)는 전환 전 그대로 유지**되고, **검색 상태(검색어·결과)는 버린다** — 재진입하면 검색 초기(E6)부터다. 다시 찾는 경로는 최근 검색어가 맡는다.

**E6 검색 초기** — 검색창(입력 포커스) / 최근 검색어(로컬 10건, 개별 × · [전체 삭제]) / 추천 키워드 칩

- **2자 이상 입력 시 300ms 디바운스로 자동 검색**한다. **키보드의 [검색] 제출은 디바운스를 기다리지 않고 즉시 실행한다**(`explore.md` 4.5-2).
- 2자 미만·특수문자·이모지만 입력이면 검색을 실행하지 않고 초기 상태를 유지한다(**"검색어를 입력해주세요"** — `explore.md` 7장). 앞뒤 공백은 무시한다.
- **연속 입력으로 응답 순서가 뒤바뀌면 최신 질의의 응답만 반영한다**(`explore.md` 4.5-2). 늦게 도착한 이전 질의의 응답으로 화면을 덮지 않는다.
- 최근 검색어는 **기기 로컬 10건**이다(`domain.md` 13.1). 서버에 보내지 않는다. 같은 검색어는 중복 저장하지 않고 최신으로 끌어올리며, 10건 초과 시 가장 오래된 것부터 밀어낸다.
- **최근 검색어 저장 시점은 "검색이 사용자 행동으로 이어진 때"다** — 키보드 [검색] 제출, 또는 결과 행 탭(재생·더보기)(`explore.md` 4.5-4). **디바운스 자동 검색마다 저장하지 않는다** — 타이핑 중간어가 목록을 오염시킨다.
- **추천 키워드는 서버가 내려주는 주제명 목록**이다 — 관심 주제를 앞에 배치한다(주제 칩과 같은 서버 정렬 재사용 — `explore.md` 4.5-4). **탭하면 그 키워드로 즉시 검색을 실행한다** — 주제 필터(E2) 적용이 아니다. 이 화면은 검색 흐름 안에 있다.

**검색 결과 — E6의 상태 변형(별도 ID 없음)**

- 결과 행은 **피드의 행과 완전히 같다**(5장 공통 행 문법 — `explore.md` 4.5-3). 탭=재생 판정(E4·페이월 분기 동일), 더보기=E12 시트([상세 정보]·[원문 보기]·담기/제거 동일).
- **정렬은 서버가 정하고 클라이언트는 재배열하지 않는다.** 추가 로딩은 피드와 동일한 **커서 기반 20건 무한 스크롤** — 하단 인라인 스피너, 실패 시 인라인 에러 + [다시 시도](기존 목록 유지).
- **검색 중에는 인라인 로딩을 쓰고, 직전 결과가 있으면 유지한 채 로딩을 겹친다**(`explore.md` 5장). 결과를 지우고 스켈레톤으로 갈지 않는다.

**E7 검색 결과 없음** — **"'OO' 검색 결과가 없어요"** + 관련 주제 칩 + "인기 콘텐츠" 행 목록

- 빈 결과의 검색어는 **입력한 검색어를 그대로 되비춘다**(`explore.md` 4.5-3).
- 대체 콘텐츠는 같은 응답의 `fallback`으로 온다(`explore-api.md` 4.5) — 빈 화면이 한 박자 늦게 채워지지 않는다.
- 관련 주제 칩을 탭하면 그 주제의 단일 목록(E2)으로 이동한다.
- 검색 결과의 행(정상·fallback 모두)은 피드의 행과 완전히 같다 — 탭=재생, 더보기=상세 정보·담기/제거.
- **검색 중 네트워크가 끊기면 이전 결과를 유지하고 상단 배너로 알린다**(`explore.md` 7장). 결과를 지우지 않는다.

### 4.7 E8 · E9 빈 상태 2종

| ID | 원인 | 문구 | 다음 행동 |
|---|---|---|---|
| E8 | **발행된 콘텐츠 풀 자체가 0건** | **"준비된 콘텐츠가 곧 늘어나요"** | [라이브러리로 가기] |
| E9 | 필터 때문에 안 보인다 | **"이 주제의 콘텐츠는 아직 없어요"** | [필터 해제] |

- **E8은 담김 여부와 무관하다.** 탐색은 라이브러리에 담긴 콘텐츠를 제외하지 않으므로(4.1), 피드가 비는 경우는 **서비스 극초기·전량 회수처럼 노출 가능한 발행 콘텐츠가 하나도 없는 상황**뿐이다. 정상 운영에서는 나타나지 않는 방어적 상태다. **배포 첫 주의 인기 섹션 표본 부족도 E8을 만들지 않는다** — 첫 주에도 같은 기준으로 정렬한 상위가 내려온다(4.1).
- **E8과 E9의 문구를 공유하지 않는다.** E8은 콘텐츠 풀의 문제고 E9는 사용자의 조작 결과다 — 다음 행동이 다르다.
- **E9는 검색창 줄·주제 칩 줄을 유지한다.** 원인을 만든 컨트롤(선택 칩)이 보여야 사용자가 되돌릴 수 있다. [필터 해제]는 선택 칩을 전부 해제하고 E1로 복귀한다.
- **E8은 주제 칩 줄을 숨긴다.** 어떤 칩을 골라도 결과가 없는데 조작할 것을 남겨두면 하나씩 눌러보게 된다. 검색창 줄(잔여 표시 포함)은 유지한다.

### 4.8 E10 오프라인 · 네트워크 오류 — 에러 화면

**캐시 피드를 노출하지 않는다**(합의 2026-08-06 — `explore.md` 5장·7장). 오프라인 진입·피드 조회 실패 모두 **전체 화면 에러 + [다시 시도]** 하나다.

- 문구는 공통 규칙을 따른다 — 오프라인이면 **"인터넷 연결을 확인해주세요"**, 서버 오류면 공통 에러 문구(`common-error-handling.md` 5장). 라이브러리 L14와 같은 컴포넌트다.
- **검색창 줄·주제 칩 줄·잔여 재생 표시를 그리지 않는다.** 낡은 목록 위의 반쪽 동작(재생 불가·담기 큐)을 제공하지 않는다 — 오프라인에서는 재생이 어차피 되지 않고(오프라인 저장 P1 이연 — FR-26), 낡은 잔여 숫자는 고지가 아니라 오정보다.
- [다시 시도] 탭 → 재조회. 성공하면 E11 없이 곧장 E1로 그린다(이미 로딩 의사를 밝힌 조작이므로 스켈레톤을 다시 끼우지 않는다). 온라인 복귀를 감지해도 자동 재조회한다.
- **피드가 이미 떠 있는 상태에서 끊긴 경우** — 화면을 E10으로 갈아치우지 않는다. 이후의 조작 실패(추가 로딩·담기·재생)는 각자의 실패 표현(인라인 에러·원상 복구 토스트·네트워크 안내)을 따르고, 탐색을 떠났다가 재진입하면 캐시로 그리지 않고 조회부터 다시 시작한다.

### 4.9 E11 최초 로딩

- **섹션별 스켈레톤** — 섹션 제목 자리 + **행 스켈레톤 3개** 묶음을 2세트. **0.3초 미만이면 표시하지 않는다**(`common-error-handling.md` 5장).
- **잔여 표시는 스켈레톤조차 그리지 않는다**(`library-uiux.md` 4.3과 같은 이유 — 무제한 티어에서는 값이 와도 자리가 사라진다).
- 검색창·주제 칩 줄 자리는 스켈레톤으로 잡아 둔다 — 로딩 완료 시 레이아웃이 뛰지 않게.

### 4.10 E13 인기 섹션 구간 토글

**인기 섹션에만 붙는 3택 1 컨트롤이다.** 다른 세 섹션에는 구간 개념이 없다(`explore.md` 4.1-1).

**구성** — 인기 섹션 제목 줄 우측에 **주간 · 월간 · 전체** 세그먼트 컨트롤. 기본 선택은 **월간**.

| 상태 | 화면 | 인터랙션 |
|---|---|---|
| 정상 | 선택 구간 강조, 나머지 둘은 기본 톤 | 탭 → 그 구간으로 전환 |
| 전환 중 | **그 섹션의 행 목록만** 인라인 로딩. 직전 목록을 유지한 채 위에 겹치거나 흐리게 처리한다 | 토글 중복 탭 차단 |
| 전환 실패 | **직전 구간의 목록을 유지**하고 섹션 안에 인라인 에러 + [다시 시도] | 선택 상태를 직전 구간으로 되돌린다 |
| 추가 로딩 | 섹션 하단 인라인 스피너 | 커서로 이어 받는다 |

- **전환은 그 섹션만 갈아끼운다.** 피드를 다시 조회하지 않으므로 다른 섹션·검색창 줄·주제 칩 줄·잔여 재생 표시는 그대로 있다(`explore-api.md` 4.2-1).
- **기본 구간을 클라이언트가 정하지 않는다.** 첫 진입의 인기 섹션은 피드 응답에 이미 기본 구간으로 들어 있고, 응답의 `period`로 토글의 선택 상태를 그린다 — 기본값을 양쪽에 두면 서버가 그것을 바꿀 때 화면과 어긋난다.
- **확정 구간이 없어도 탭을 숨기거나 비활성화하지 않는다**(`explore.md` 4.1-1). 배포 첫 주의 주간, 첫 달의 월간도 같은 기준으로 정렬한 상위가 내려온다. **탭이 조건부로 사라지면 사용자는 자기가 뭘 잘못 눌렀는지 추적하게 된다.**
- **빈 결과 화면을 따로 두지 않는다.** 구간과 무관하게 발행 콘텐츠가 있으면 목록이 채워지므로, 비는 경우는 콘텐츠 풀 자체가 0건인 E8뿐이다(4.7).
- **주제 필터(E2)로 전환하면 토글이 사라진다** — 섹션 구조가 없어지기 때문이다. 칩을 전부 해제해 E1로 돌아오면 **직전에 고른 구간이 유지된다**(`explore.md` 4.1-1).
- 고른 구간은 **서버에 저장하지 않는다.** 탭 이탈·앱 재실행 시의 유지 범위는 클라이언트가 정한다.
- 행의 모양·동작은 E1·E2와 완전히 같다(탭=재생, 더보기=담기/제거, 완청 체크).

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **콘텐츠 행** | 피드·필터 목록·인기 목록·검색 결과 | 한 가지 모양. 본문 탭=재생, 더보기만 별도 히트 영역, 완청 체크 조건부 |
| **검색창 줄 상태 표시** | 잔여 재생 | 화면당 한 곳. 행 아님. 검색 화면에서는 숨김 |
| **더보기 바텀시트** | 상세 정보·원문 보기·담기/제거(공유는 P1) | 대상 요약을 상단에 재표시. 딤 탭·뒤로가기로 닫히며 변경 없음 |
| **토스트** | 담기 완료·회수 안내·실패 | 3초. 담기 완료만 [보러가기] 액션을 가진다. 제거는 무음 |
| **다이얼로그** | 재생 확인 팝업 | `library-uiux.md` 4.6과 동일 |
| **스켈레톤** | 최초 조회 | 섹션 단위 행 스켈레톤. 0.3초 미만 미표시 |
| **구간 토글** | 인기 섹션 제목 줄 | 3택 1(주간·월간·전체). 선택 상태를 형태로도 드러낸다. 인기 섹션에만 붙는다 |
| **인라인 스피너·에러** | 추가 로딩·검색 중·구간 전환 | 기존 내용 유지 |
| **전체 화면 에러** | E10 오프라인·조회 실패 | 공통 컴포넌트(L14와 동일). 캐시 피드로 대체하지 않는다 |
| **상단 배너** | 검색 중 네트워크 끊김 | 한 번에 하나 |

- **낙관적 반영 후 실패는 원상 복구 + 토스트**(`common-error-handling.md` 4.4).
- **사용자가 시작하지 않은 실패는 알리지 않는다** — 자동 적립(`save reason=auto_play`) 실패, 포그라운드 조용한 재조회 실패.

## 6. 카피 원칙

- **해요체**로 통일한다.
- 잔여 표시는 **"오늘 재생 N/M 남음"** 한 문자열만 쓴다. `M` 하드코딩 금지(`paywall.md` 5장).
- **담김 여부를 말해주는 문구는 더보기 시트의 액션 둘뿐이다** — **"라이브러리에 담기" / "라이브러리에서 제거"**. 행에는 담김 관련 문구가 없다.
- 담기 토스트는 **"라이브러리에 담았어요"** + [보러가기]. 제거는 무음(4.4).
- 빈 상태 2종의 문구를 재사용하지 않는다(4.7).
- 검색 빈 결과는 **"'{검색어}' 검색 결과가 없어요"** — 입력한 검색어를 그대로 되비춘다(`explore.md` 4.5-3).
- 검색 미실행 안내는 **"검색어를 입력해주세요"**(`explore.md` 7장 — 2자 미만·특수문자·이모지만 입력).
- 검색창 플레이스홀더는 제안값 **"콘텐츠 검색"** — features에 확정 문구가 없다(**카피 미확정 — TODO**).
- 더보기 시트의 상세 진입 항목 라벨은 **"상세 정보"**(`explore.md` 3장).
- 회수 안내는 **"제공이 종료된 콘텐츠예요"** — 사실만 말한다. 재시도 유도를 붙이지 않는다.
- E10 오프라인 문구는 공통 **"인터넷 연결을 확인해주세요"**(`common-error-handling.md` 소유).
- 한도 안내 문구 **"오늘 청취 한도를 모두 사용했어요"** 는 `paywall.md` 4.1 소유다 — 페이월 시트 헤드라인과 최상위 티어 안내가 같은 문자열을 쓰며, 탐색이 변형하지 않는다.
- **내부 용어를 화면에 노출하지 않는다** — "드립", "섹션", "피드", "적립", "페이월".
- **인기 구간 토글의 라벨은 "주간 / 월간 / 전체" 세 단어다.** `period` 값(`week`·`month`·`all`)은 전송값이고 라벨은 화면 문구다 — 라벨을 바꿔도 계약은 그대로다.
- 섹션 제목은 서버 문자열을 그대로 쓴다. 클라이언트가 편집하지 않는다. **구간 토글은 제목의 일부가 아니라 별도 컨트롤이므로, 서버가 내려준 "인기 콘텐츠" 제목에 구간명을 덧붙이지 않는다.**

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 행의 더보기 버튼, 주제 칩, 최근 검색어 삭제 ×, 소진 상태의 잔여 표시.
- **행은 하나의 탭 영역으로 읽힌다** — "퇴사 전에 반드시 점검할 5가지, 퍼블리, 14분, 완청한 콘텐츠, 재생"처럼 값과 동작을 한 문장으로. 더보기 버튼만 개별 포커스("더보기, 상세·담기·제거")를 준다.
- **잔여 표시의 스크린리더 라벨은 `library-uiux.md` 7장과 동일하다** — "오늘 재생 2회 중 1회 남음". N = 0일 때만 `role=button` + "구독 안내 열기"(최상위 티어는 "한도 안내 열기").
- **검색창은 `role=search`로 읽힌다** — "콘텐츠 검색, 검색창"(플레이스홀더 카피 확정 전 제안 라벨 — 6장). 검색 화면 전환 시 입력에 포커스를 준다. (종전 "MVP 비활성 — disabled 낭독"은 검색 MVP 격상으로 폐기 — 개정 2026-08-23)
- **완청 체크는 색이 아니라 형태 단서다** — 행 낭독에 **"완청한 콘텐츠"** 를 포함한다(`library-uiux.md` 7장과 같은 문구). 담기/제거 결과는 **토스트와 시트 액션 라벨이 알린다.**
- **주제 칩은 다중 선택 토글이다** — `aria-pressed`로 선택 상태를 읽히고, 선택 시 목록 전환 결과를 polite로 한 번 알린다("커리어, 콘텐츠 12개").
- 검색 결과 갱신(디바운스 완료·[검색] 제출)은 `aria-live="polite"`로 건수를 알린다("'커리어' 검색 결과 12개"). 빈 결과(E7)도 같은 채널로 알린다. **검색 결과 행의 낭독은 피드 행과 동일하다** — 값과 동작을 한 문장으로, 더보기만 개별 포커스.
- **최근 검색어는 검색어 + 삭제 버튼이 각각 포커스를 받는다** — 검색어는 "커리어, 최근 검색어, 탭하면 검색", 삭제 ×는 "'커리어' 검색어 삭제, 버튼". [전체 삭제]는 별도 버튼으로 읽힌다.
- **추천 키워드 칩은 버튼으로 읽힌다** — "커리어, 추천 키워드, 탭하면 검색". 주제 칩(다중 선택 토글, `aria-pressed`)과 역할이 다르다 — 탭 결과가 필터가 아니라 검색 실행이다(4.6).
- **더보기 시트의 [상세 정보]는 버튼으로 읽힌다** — "상세 정보, 버튼". 탭하면 시트가 닫히고 상세 화면으로 포커스가 이동한다(상세 화면의 낭독 규칙은 `content-detail.md` 계열 소유).
- **인기 구간 토글은 3택 1이므로 라디오 그룹(또는 탭 목록)으로 읽힌다** — 선택 상태를 `aria-checked`(또는 `aria-selected`)로 알리고, 전환 완료를 `aria-live="polite"`로 한 번 알린다("월간 인기 콘텐츠, 10개"). 터치 타깃 최소 44×44pt.
- 더보기 시트는 포커스를 가두고, 닫으면 그 행의 더보기 버튼으로 포커스를 되돌린다.
- 담기 완료 토스트는 `aria-live="polite"`, 회수 안내는 조작의 직접 결과이므로 `assertive`.
- **동적 텍스트 200%에서 잘리지 않아야 한다** — 검색창 줄(잔여 표시와 공간 경합), 행 제목(2줄 접기 허용), 섹션 제목.

## 8. 금지 사항

`explore.md` · `paywall.md`와 이 문서의 확정이 명시적으로 금지한 것들이다.

**피드·행·담기**

- 섹션 구성·순서·제목을 **클라이언트가 하드코딩**하는 것 (배포 첫 주의 인기 섹션을 클라이언트가 숨기는 것 포함)
- **인기 구간 기본값을 클라이언트 상수로 두는 것** — 미전송이면 서버가 정한다(`explore-api.md` 4.2-1)
- **구간을 바꿀 때 피드 전체를 재조회하는 것** — 인기 섹션만 갈아끼운다
- **확정 구간이 없다는 이유로 구간 탭을 숨기거나 비활성화하는 것** — 세 구간 모두 항상 고를 수 있다
- **담김 여부로 노출을 거르는 것** — 담긴 콘텐츠를 피드·필터 목록·검색 결과에서 제외하거나 순서를 미루는 것
- **행에 담기 버튼을 두는 것** — 담기/제거의 진입점은 더보기 시트 하나다
- **행에 담김 표시를 두는 것** — 확인 수단은 더보기 시트다
- 완청 체크를 **색만으로** 구분하는 것
- **담기에 페이월·횟수 제한**을 붙이는 것 (PRD 5.4)
- 제거에 **영구 제외 고지·확인 팝업**을 붙이는 것
- 행 탭에 **상세 화면을 끼워 넣는 것** — 본문 탭은 곧장 재생 판정이다. 상세는 더보기 시트의 [상세 정보] 경유로만 진입한다(`content-detail.md`)
- 같은 화면에서 **행 모양을 섹션·모드마다 다르게** 만드는 것
- **MVP의 더보기 시트에 [공유] 항목을 노출하는 것** (FR-27 MVP 제외 — [상세 정보]는 노출한다, 개정 2026-08-23)
- 공유 시트 오픈을 **신호로 기록**하는 것 (P1 활성화 이후에도)

**검색** (`explore.md` 4.5)

- **디바운스 자동 검색마다 최근 검색어를 저장하는 것** — 저장 시점은 [검색] 제출·결과 행 탭뿐이다
- **최근 검색어를 서버에 보내는 것** — 기기 로컬 10건이다(`domain.md` 13.1)
- **늦게 도착한 이전 질의의 응답으로 최신 결과를 덮는 것** — 최신 질의의 응답만 반영한다
- **검색 중 직전 결과를 지우는 것** — 인라인 로딩을 겹친다
- **추천 키워드 탭을 주제 필터 적용으로 처리하는 것** — 즉시 검색 실행이다
- **검색에서 복귀한 피드의 상태(필터·구간·스크롤)를 초기화하는 것** / **검색 상태(검색어·결과)를 복귀 후에도 유지하는 것**

**잔여 재생 표시** (`library-uiux.md` 8장과 공통)

- 행마다 표시 / 주제 칩 줄에 배치 / 무제한 티어에 배지 / N = 0일 때 숨김
- 클라이언트가 1을 빼는 것 / 기기 시각으로 리셋 판단 / 값 없음을 0으로 가정
- **검색 화면에서 표시만 숨기고 판정까지 빼는 것** — 숨긴 것은 표시이지 규칙이 아니다

**재생·팝업·오프라인**

- 탐색 진입점만 **판정·팝업을 건너뛰게** 하는 것
- 억제 플래그를 **화면별로 따로 저장**하는 것 — 기기 단위 공유다
- 페이월로 막힌 재생을 **라이브러리에 적립**하는 것 — 적립은 재생이 실제 시작된 뒤다
- 팝업 [취소]에 적립·차감을 붙이는 것
- **최상위 티어의 한도 소진에 페이월을 띄우는 것** — 한도 안내만 띄운다(`paywall.md` 4.1)
- **오프라인·조회 실패에 캐시 피드를 그리는 것** — 에러 화면 + [다시 시도]뿐이다

## 10. 합의 사항

2026-08-06 합의로 확정되어 features(`explore.md` · `paywall.md`)와 이 문서에 반영을 마친 항목들이다. 이후 재개정된 항목은 화살표로 표시한다.

- **오프라인 캐시 피드는 사용하지 않는다** — E10은 에러 화면 + [다시 시도]다(4.8).
- 탐색에서 재생한 콘텐츠는 라이브러리에 담기가 되는 것이 맞고, 라이브러리에서 재생한 콘텐츠는 이미 라이브러리에 담겨 있으므로 추가 자동 담기가 동작하지 않는 것이 맞다.
- 담기/제거 버튼은 더보기 시트만 가지고 있는 것으로 확정한다.
- "상세"에 대한 명세는 추후에 추가한 뒤 개발한다 — 그 전까지 시트에 항목이 없다. → **재개정(합의 2026-08-23): 상세 화면 도입 확정(`content-detail.md`) — 더보기 시트에 [상세 정보] 항목을 둔다(4.4).**
- "검색"은 P1으로 유지하고, 검색창은 탐색 페이지에 있지만 비활성화된 상태로 존재한다. → **재개정(합의 2026-08-23): 검색 MVP 포함 격상 — 검색창 활성, 탭하면 검색 화면으로 전환한다(4.6).**
- 탐색 페이지에서 잔여 표시는 한도 미만과 상관없이 항상 보여주는 것으로 확정한다.
- 배포 이후 첫 주 동안은 표본의 크기와 상관없이 인기 콘텐츠 선정 기준에 따라 정렬했을 때의 상위 콘텐츠를 보여준다 — 선정 기준 값이 모두 같아도 정렬상 먼저 오는 콘텐츠가 존재하기 때문이다.
- **공유(FR-27)는 MVP 제외** — 더보기 시트에 공유 항목을 노출하지 않고 P1 도입 시 활성화한다.
- **한도 소진 처리는 티어의 위치로 가른다** — 최상위 티어는 페이월 대신 "오늘 청취 한도를 모두 사용했어요" 한도 안내만, 그 외 한도 티어(무료 포함)는 페이월(시트 안에 같은 한도 안내 문구 포함)이다(`paywall.md` 4.1).
