# 설정 UI/UX 명세서

> 기준 문서: [`docs/pages/settings.md`](../../pages/settings.md) · 알림 토글·OS 권한·사전 안내는 [`docs/pages/notification.md`](../../pages/notification.md) 4.1~4.2, 로그아웃·탈퇴·이메일·동의는 [`docs/pages/auth.md`](../../pages/auth.md), 커리어 편집 화면은 [`docs/pages/career.md`](../../pages/career.md), 로딩·오류 표현은 [`docs/pages/common-error-handling.md`](../../pages/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/settings.html`](../../wireframe/settings.html) (화면 ID S1–S7)
> API: [`settings-api.md`](../api/settings-api.md)

## 1. 범위

설정 화면 — 섹션 구분 리스트(계정·구독·콘텐츠·재생·알림·정보·지원·관리자), 토글의 낙관적 저장, 알림 토글과 OS 권한의 관계, 알림 사전 안내 유도 배너, 로그아웃 확인, 조회 실패까지 `settings.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**설정은 허브다**(`settings.md` 1장). 이 화면이 소유하는 조작은 **토글·배속 시트뿐**이고, 나머지 항목은 전부 소유 화면으로 보낸다. 하위 화면(이메일 인증 A 계열, 관심사 관리, 커리어 정보, 구독 관리, 탈퇴, 관리자 페이지)의 생김새는 각 소유 문서가 정한다.

## 2. 화면 목록

| ID | 화면 | 대응 상태(`settings.md` 5장) |
|---|---|---|
| S1 | 정상 — 유료 · 이메일 인증됨 | 정상 · 유료 사용자 |
| S2 | 무료 사용자 · 이메일 미등록 · 알림 유도 배너 | 무료(라이트) · 이메일 미등록 · 알림 유도 배너 |
| S3 | 이메일 미인증 · 업데이트 있음 | 이메일 미인증 · 업데이트 있음 |
| S4 | 알림 토글 — OS 권한 안내 | 토글 ON 시도(권한 없음) |
| S5 | 로그아웃 확인 팝업 | 로그아웃 확인 |
| S6 | 조회 실패 — 상단 카드만 에러 | 조회 실패 |
| S7 | 토글 저장 실패 — 원복 + 토스트 | 토글 저장 실패 |

- 로딩 상태는 별도 ID를 두지 않는다 — 상단 계정·구독 카드만 스켈레톤이고 나머지 메뉴는 즉시 노출되므로(`settings.md` 5장) 화면 골격은 S1과 같다. 4.6에서 다룬다.
- **관리자 계정 변형·구독 결제 문제(유예) 변형은 S1의 상태 변형**으로 다루고 별도 ID를 두지 않는다(4.1).
- **알림 유도 배너는 S2에 얹혀 그려져 있으나 티어와 무관하다** — 노출 조건은 OS 권한 미결정 하나다(4.3).
- 탈퇴 안내·처리 화면은 `auth-uiux.md`(A 계열) 소유다. 알림 사전 안내 화면의 문구·규칙은 `notification.md` 소유다.
- 해지 예약·결제 문제의 구독 요약 변형은 `profile-uiux.md` 4.4와 같은 규칙이므로 별도 화면을 두지 않는다.

```

   │
   ├─ 계정 · 이메일 ────> 이메일 인증 화면 (auth-uiux.md) ─ 성공 ─> 복귀 + 항목 갱신
   ├─ 구독 ────────────> 구독 관리 (subscription.md)
   ├─ 콘텐츠 · 관심 주제 관리 ─> 관심사 관리 — 주제 전용 (interest-management.md)
   ├─ 콘텐츠 · 커리어 정보 ───> 커리어 정보 화면 (career.md — 관심사 관리가 아니다)
   ├─ 재생 · 기본 배속 ──> 선택 시트 ─ 선택 즉시 저장(낙관적) ─┬─ 성공 ─> 반영 유지

   ├─ 알림 · 이어 PICK 알림 ─┬─ OS 권한 있음 ─> 토글 즉시 전환 + 저장
   │                          └─ OS 권한 없음 ─> S4 안내 ─[설정 열기]─> OS 설정
   │                                                └─ 복귀 시 권한 재확인 · 동기화
   ├─ 알림 · 마케팅 수신 동의 ─> 토글 즉시 전환 + 저장(낙관적) ─ 실패 ─> S7 원복 + 토스트
   ├─ 정보 · 공지사항 ──> 인앱 공지 화면 (명세 추후 작성)
   ├─ 정보 · 약관 / 개인정보처리방침 ─> 인앱 브라우저

   ├─ 지원 · 문의하기 ──> 카카오톡 채널 (열 수 없으면 링크 복사 다이얼로그)
   ├─ 계정 · 로그아웃 ──> S5 확인 팝업 ─[로그아웃]─> 로컬 삭제 → 시작 화면
   ├─ 계정 · 회원 탈퇴 ──> 탈퇴 화면 (auth-uiux.md)
   └─ 관리자 · 관리자 (관리자 계정에만) ──> 관리자 페이지 (admin.md 2장)
```

## 4. 화면별 명세

### 4.1 S1 정상 — 화면 골격

**구성** — 앱바(뒤로가기 + "설정") / 섹션 구분 리스트:

| 섹션 | 항목 | 형태 |
|---|---|---|
| 계정 | 이메일 | 값 + 상태별 버튼(4.2) |
| 구독 | 현재 플랜 요약 | 카드 → 구독 관리 |
| 콘텐츠 | 관심 주제 관리 | 요약("N개 선택") + 이동 → 관심사 관리(주제 전용) |
| 콘텐츠 | 커리어 정보 | 이동 → **커리어 정보 화면**(`career.md` — 합의 2026-08-06으로 관심사 관리에서 분리, `profile.md` 4.4와 같은 목적지) |
| 콘텐츠 | 주제 자동 확장 **(P1 — 미구현 시 미노출)** | 토글 |
| 재생 | 기본 배속 | 현재 값("1.2×") + 선택 시트 |
| 알림 | (조건부) 알림 사전 안내 유도 배너 | 섹션 상단 배너(4.3) |
| 알림 | **이어 PICK 알림** (P1) | 토글 — 명칭은 합의 2026-08-06 확정, "PICK"은 전부 대문자다(`notification.md` 4.2). "드립"은 내부 용어라 화면에 노출하지 않는다 |
| 알림 | **마케팅 수신 동의** | 토글 — 가입 시 동의(`agreed_marketing`)의 **철회 경로**다(합의 2026-08-06, 정보통신망법 — `settings.md` 4.1). 저장 규칙은 4.5 |
| 정보 | 공지사항 | **인앱 화면**(합의 2026-08-06 — 화면 명세는 추후 작성) |
| 정보 | 이용약관 / 개인정보처리방침 | 인앱 브라우저 |
| 정보 | 앱 버전 | 버전 문자열 (+ 배지·[업데이트]). 최신 버전의 원천은 **배포 시 입력된 버전(배포 설정)** 이고 판정은 서버가 한다(합의 2026-08-06) |
| 지원 | 문의하기 | **카카오톡 채널**(합의 2026-08-06 — 폴백은 4.6) |
| 계정 | 로그아웃 | 확인 팝업 |
| 계정 | **회원 탈퇴** | 이동 — 사용자 메뉴 최하단, 낮은 시각 비중 |
| 관리자 | **관리자** | **관리자 계정에만 노출** — 리스트 맨 아래 별도 섹션 → 관리자 페이지(`admin.md` 2장) |

- **프로필로 되돌아가는 계정 카드를 두지 않는다**(`settings.md` 2장). 방금 지나온 화면으로 다시 보내는 항목은 경로만 헷갈리게 한다. 닉네임·제공자 표시도 없다 — 그것은 프로필 몫이다.
- **오프라인 저장 관리 메뉴를 노출하지 않는다**(P1 이연 — `settings.md` 4.1). 자리를 비워두지도 않는다.
- **회원 탈퇴는 로그아웃과 나란히 같은 무게로 두지 않는다.** 사용자 메뉴의 최하단에 보조 텍스트 톤으로 둔다 — 파괴적이고 되돌릴 수 없는 조작을 일상 조작과 같은 비중으로 두면 오탭이 사고가 된다. 단 **숨기지는 않는다**(찾을 수 없는 탈퇴는 다크 패턴이다).
- **관리자 섹션은 회원 탈퇴보다도 아래, 리스트 맨 끝이다**(`settings.md` 5장). 운영 도구는 사용자 조작이 아니므로 사용자 메뉴가 다 끝난 뒤에 온다. **일반 계정에는 섹션·행 자체가 없다** — 비활성으로도 그리지 않는다(존재를 알릴 이유가 없다). 노출 판정은 서버가 내려준 계정 속성으로 하고 클라이언트가 추측하지 않는다.
- **구독 요약 카드의 상태별 표시는 `profile-uiux.md` 4.2·4.4와 같은 문구·같은 톤**을 쓴다. 두 화면이 같은 값을 다른 말로 표시하면 어느 쪽이 맞는지 사용자가 판단하게 된다:

| 상태 | 구독 섹션 표시 |
|---|---|
| 무료(라이트) | "무료 이용 중" + [구독 알아보기] 강조 |
| 유료 | 플랜명 + "다음 결제일 N월 N일" |
| 해지 예약 | 플랜명 + "N월 N일까지 이용 가능" — 중립 톤 |
| **결제 문제(유예)** | 플랜명 + **"결제에 문제가 있어요"** — **경고색**(`profile.md` 4.2 · `subscription.md` 4.7과 동일) |

- 배속 항목은 현재 값을 항목 우측에 상시 표시한다. 시트에서 선택 즉시 저장하고 시트를 닫는다 — [저장] 버튼을 두지 않는다(`settings.md` 4.2).

### 4.2 S2 · S3 계정 섹션의 이메일 상태 3종 (+ 업데이트 배지)

이메일 항목의 세 상태는 **`profile.md` 4.3과 동일하게 구분한다**(`settings.md` 4.1).

| 상태 | 항목 표시 | 버튼 |
|---|---|---|
| 미등록(S2) | "등록되지 않음" | [등록] |
| 미인증(S3) | 주소 + **"인증되지 않음" 배지** | [인증하기] · [변경] |
| 인증됨(S1) | 주소 | [변경] |

- 세 버튼 모두 **auth의 같은 인증 화면**으로 간다. 설정 경로만의 규칙 차이는 없고, 발송 횟수는 결제·프로필 경로와 합산된다(`auth.md` 4.5). 인증 성공 시 설정으로 복귀하고 항목이 갱신된다.
- **S3 업데이트 있음**: 앱 버전 항목에 배지 + [업데이트]. 탭하면 스토어로 이동한다.
  - 판정은 서버의 `update_available`이다(`settings-api.md` 4.1). 클라이언트가 버전 문자열을 비교하지 않는다. 비교 대상인 최신 버전의 원천은 **배포 시 입력된 버전(배포 설정)** 이다(합의 2026-08-06).
  - **강제 업데이트 화면은 여기 소관이 아니다**(`splash.md`). 설정의 배지는 안내일 뿐 차단하지 않는다.

### 4.3 S4 알림 — OS 권한 안내 · 사전 안내 유도 배너

**이어 PICK 알림 토글**

- OS 권한이 허용된 상태: 토글은 즉시 전환(낙관적) + 서버 저장. 성공하면 그대로, 실패하면 S7.
- **OS 권한이 거부된 상태에서 토글 ON 시도**: **토글을 켜지 않고** 다이얼로그를 띄운다 — **"기기 설정에서 알림을 허용해주세요"** + [닫기] / **[설정 열기]**.
  - [설정 열기] → OS 앱 설정 화면. **앱 복귀 시 권한 상태를 재확인**해 허용됐으면 사용자가 다시 토글을 켤 수 있다(자동으로 켜지 않는다 — 사용자가 OS에서 무엇을 바꿨는지 앱이 단정할 수 없다).
  - 이 경우 **서버 호출이 발생하지 않는다**(`settings-api.md` 3장) — 켜지지 않은 토글을 저장할 것이 없다.
- OS 권한이 거부된 동안 토글은 **OFF 상태로 조작 가능하게** 둔다(비활성 처리하지 않는다). 비활성이면 사용자가 "왜 안 켜지는지"를 알 길이 없다 — 탭했을 때 이유를 말해주는 쪽이 낫다(`interest-management.md` 4.1의 "비활성 무반응은 오류로 읽힌다"와 같은 원칙).
- **포그라운드 복귀 시마다 권한을 재확인해 서버에 동기화한다**(`notification.md` 4.2 — `PUT /users/me/devices/:device_id`). OS 설정에서 권한을 끄고 돌아온 경우 토글 표시를 갱신한다.

**알림 사전 안내 유도 배너** — (b)안 채택(합의 2026-08-06 — `notification.md` 4.1 · `settings.md` 4.3)

- **노출 대상**: 온보딩에서 사전 안내를 보지 못해 **OS 권한이 미결정인 사용자.** 알림 섹션 **상단에 상시 노출**한다 — 일회성으로 끼어들지 않는다(놓치면 경로가 사라지는 (a)안을 기각한 이유 그대로).
- **배너 문구는 사전 안내의 헤드라인을 그대로 쓴다** — **"새 콘텐츠가 도착하면 알려드릴까요?"** + 우측 셰브론. 배너와 사전 안내가 다른 말을 쓰면 탭했을 때 다른 곳에 온 것처럼 읽힌다. "드립"은 카피에 쓰지 않는다(`notification.md` 5장).
- 배너 탭 → **사전 안내**(문구·버튼 [알림 받기]/[나중에]는 `notification.md` 소유) → [알림 받기]에서 OS 다이얼로그.
- **권한이 결정되면(허용·거부 모두) 배너를 숨긴다.** 거부한 사용자에게 배너를 남겨 다시 조르지 않는다 — 거부 후 경로는 토글 ON 시도 → S4 안내다.
- 배너에 닫기(×)를 두지 않는다. 노출·숨김은 권한 상태 하나로 판정하며, 별도의 "닫음" 로컬 상태를 만들지 않는다.

### 4.4 S5 로그아웃 확인

**구성** — 다이얼로그: **"로그아웃할까요?"** / [취소] · [로그아웃]

- 본문 보조 문구는 두지 않는다. 로그아웃은 데이터가 사라지는 조작이 아니므로("다시 로그인하면 그대로예요" 같은 안심 문구도 소음이다) 질문 하나로 충분하다.
- [로그아웃] → 서버 세션 폐기(실패해도 진행 — `auth.md` 4.2) → 로컬 토큰·캐시 삭제 → 푸시 토큰 등록 해제 → **시작 화면으로 이동(스택 전체 초기화)**.
- 처리 중에는 팝업의 버튼을 비활성화한다. 전체 화면 로딩을 띄우지 않는다 — 1초 내외의 조작이다.
- [취소]·딤 탭은 아무 변화 없이 닫는다.

### 4.5 S6 조회 실패 · S7 토글 저장 실패

**S6 조회 실패**

- **계정·구독 카드 영역에만** "정보를 불러올 수 없어요" + [다시 시도]를 표시한다. **나머지 메뉴는 정상 동작한다**(`settings.md` 5장) — 약관·로그아웃·탈퇴는 서버 조회 값이 필요 없다.
- 부분 실패(`failed_sections`)면 실패한 요약만 에러로 둔다(`settings-api.md` 4.1).
- 토글 값 조회가 실패하면 응답 전체가 실패하므로(`settings-api.md` 4.1) 토글 섹션도 에러 영역에 포함된다 — 기준값 없는 낙관적 토글은 성립하지 않는다.

**S7 토글 저장 실패**

- 낙관적으로 전환했던 **토글을 원래 상태로 되돌리고** 토스트로 알린다: **"설정을 저장하지 못했어요"**(`settings.md` 4.2).
- **조용히 되돌리지 않는다** — 사용자는 자기가 켠 것이 왜 꺼졌는지 알아야 한다(`common-error-handling.md` 4.4).
- 배속 시트의 선택 실패도 같은 규칙이다 — 항목의 표시 값을 이전 값으로 되돌린다.
- 토글 연타는 마지막 조작이 최종이다. 오래된 응답은 `client_seq`로 무시한다(`settings-api.md` 4.2).
- **오프라인 중 토글 조작은 되돌리지 않는다.** 큐에 적재하고 복귀 시 동기화한다(`settings.md` 7장) — 오프라인은 실패가 아니라 지연이다.

**마케팅 수신 동의 토글 — 같은 규칙 + 이력 기록**

- 화면 동작은 다른 토글과 완전히 같다 — 낙관적 전환, 실패 시 원복 + 토스트(`settings.md` 5장). OS 권한 게이트는 **없다**(푸시 권한과 무관한 법적 동의 상태다).
- 서버는 동의·철회를 **`consents`에 이력으로 기록한다**(`settings.md` 4.1 — `auth.md`의 동의 3종 별개 기록). 단순 설정값 갱신이 아니라 법적 이력이므로, **실패를 조용히 삼키지 않는 것이 특히 중요하다** — 사용자가 철회했다고 믿는데 서버에 기록이 없으면 위법 상태가 된다. 원복 + 토스트로 철회가 완료되지 않았음을 반드시 보인다.
- 토글 상태 표시는 서버가 내려준 현재 동의 상태를 기준값으로 쓴다. 확인 팝업은 두지 않는다 — 철회는 잃는 것이 없는 조작이다.

### 4.6 로딩 · 문의하기 · 공지사항

- **로딩**: 상단 계정·구독 카드와 관심 주제 요약만 스켈레톤. **정적 메뉴(정보·지원·로그아웃 등)는 즉시 노출한다**(`settings.md` 5장) — 서버 값이 필요 없는 항목까지 로딩 뒤에 숨길 이유가 없다. 0.3초 미만이면 스켈레톤 미표시.
- **문의하기**: **카카오톡 채널을 연다**(합의 2026-08-06 — `settings.md` 4.1). **채널을 열 수 없으면(미설치·열기 실패) 채널 링크를 복사할 수 있는 다이얼로그로 폴백한다**(`settings.md` 7장) — 링크 텍스트 + [복사] + [닫기], 복사 성공 시 토스트 "링크를 복사했어요".
- **공지사항**: **인앱 화면**으로 목록을 연다(합의 2026-08-06 — `settings.md` 4.1). 공지 화면 자체의 명세·UIUX는 추후 작성한다(9장).

## 6. 카피 원칙

- **해요체**로 통일한다.
- 이메일 상태·구독 요약 문구는 **프로필과 완전히 같은 문자열**을 쓴다(`profile-uiux.md` 6장) — "등록되지 않음", "인증되지 않음", "무료 이용 중 · 하루 N편", "다음 결제일 N월 N일", "N월 N일까지 이용 가능", **"결제에 문제가 있어요"**(유예).
- 알림 토글 명칭은 **"이어 PICK 알림"** — "PICK"은 전부 대문자다(합의 2026-08-06, `notification.md` 4.2 · `settings.md` 4.1). "이어 Pick" · "드립 도착 알림" 표기를 쓰지 않는다.
- 마케팅 토글 명칭은 **"마케팅 수신 동의"**.
- 유도 배너·사전 안내 헤드라인: **"새 콘텐츠가 도착하면 알려드릴까요?"**(`notification.md` 5장 — "드립"을 카피에 쓰지 않는다).
- 권한 안내: **"기기 설정에서 알림을 허용해주세요"** + [설정 열기].
- 로그아웃: **"로그아웃할까요?"** + [취소]/[로그아웃]. 저장 실패: **"설정을 저장하지 못했어요"**. 링크 복사: **"링크를 복사했어요"**.
- 자동 확장 토글 설명: **"관심 주제와 가까운 주제도 자동으로 찾아드려요"**(`interest-management.md` 4.1).
- **내부 용어를 노출하지 않는다** — "드립", "티어", "유예", "grace". 관리자 항목명은 "관리자" 한 단어다(운영자용 진입점에 설명을 붙이지 않는다).
- 메뉴 항목명은 동사구가 아니라 명사구로 통일한다 — "관심 주제 관리", "커리어 정보", "문의하기".

## 7. 접근성

- **터치 타깃 최소 44×44pt** — 모든 리스트 항목, 토글, 시트의 선택지, 유도 배너.
- **토글은 `role=switch` + 상태**로 읽힌다("이어 PICK 알림, 켜짐" / "마케팅 수신 동의, 꺼짐"). 항목명과 토글을 하나의 포커스로 묶는다.
- 저장 실패로 토글이 원복되면 `aria-live="assertive"`로 알린다 — 시각적 원복은 스크린리더 사용자에게 전달되지 않는다.
- OS 권한 안내 다이얼로그는 포커스를 가두고, 닫으면 토글 항목으로 포커스를 되돌린다.
- **유도 배너는 `role=button`** — "새 콘텐츠가 도착하면 알려드릴까요, 알림 설정 열기"로 읽힌다. 배너가 사라질 때 포커스를 잃지 않게 알림 섹션 제목으로 되돌린다.
- 배속 시트의 선택지는 `role=radiogroup`. 현재 값에 `aria-checked=true`.
- 배지(미인증·업데이트)는 색 + 텍스트이며, 항목 라벨에 이어 읽힌다("앱 버전 1.3.0, 업데이트 있음").
- 회원 탈퇴 항목은 시각 비중이 낮아도 **포커스 순서에서 제외하지 않는다.** 관리자 항목도 노출되는 계정에서는 같은 규칙이다.
- 동적 텍스트 200%에서 항목명·값이 겹치지 않게 두 줄 배치를 허용한다. 이메일 주소는 말줄임 대신 줄바꿈한다(`profile-uiux.md` 7장과 같은 이유).

## 8. 금지 사항

`settings.md` · `notification.md` · 관련 명세가 명시적으로 금지한 것들이다.

- 설정에 **프로필로 되돌아가는 계정 카드**를 두는 것
- 설정을 **하단 탭**으로 만드는 것 — 진입점은 프로필 우상단 아이콘 하나다
- 토글에 **[저장] 버튼**을 붙이는 것 (관심사 관리 화면의 일괄 저장은 예외 — 그 화면 소관)
- 토글 저장 실패를 **조용히 원복**하는 것 — 마케팅 수신 동의는 법적 이력이라 특히 금지다(4.5)
- **마케팅 수신 동의의 철회 경로를 숨기거나 문의 경유로 만드는 것** — 토글이 곧 철회 경로다(정보통신망법)
- OS 권한이 거부된 상태에서 **토글을 비활성 처리해 무반응**으로 두는 것 — 탭하면 이유를 말한다
- OS 권한이 거부된 상태에서 **OS 다이얼로그를 다시 띄우려는 시도** — 거부된 권한은 앱에서 재요청할 수 없다. [설정 열기]로 보낸다
- OS 설정에서 권한을 허용하고 돌아왔을 때 **토글을 자동으로 켜는 것**
- **유도 배너를 권한 결정(허용·거부) 후에도 남겨두는 것** — 거부한 사용자를 배너로 다시 조르지 않는다
- 유도 배너·사전 안내를 건너뛰고 **OS 다이얼로그를 바로 띄우는 것**(`notification.md` 4.1)
- **관리자 항목을 일반 계정에 노출하는 것** — 비활성 행으로도 그리지 않는다. 행 자체가 없다
- **오프라인 저장 메뉴를 자리만 잡아 노출**하는 것 (P1 이연 — 메뉴 자체 미노출)
- 탈퇴 항목을 **숨기거나** 탈퇴 화면에 **스토어 딥링크**를 두는 것 (`auth.md` 4.3 — 안내는 텍스트만)
- 클라이언트가 **버전 문자열을 스스로 비교**해 업데이트 판정을 하는 것
- 재생 한도·만료 등 **정책 판정을 이 화면에서 하는 것** — 설정은 표시와 이동뿐이다
