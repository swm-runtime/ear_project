## 1. 범위

**이 문서는 동작 규칙을 새로 정하지 않는다.** 판정(티어·만료·버튼 종류)은 서버가 하고(`subscription-api.md` 4.1 `action` · 4.2 `plan.status`), 동작 규칙은 `subscription.md` · `paywall.md` 가 소유한다. 여기서 정하는 것은 **화면 ID·상태·확정 카피·접근성**이다.

**노출 조건 — 세 겹이 전부 열려야 그린다**(`frontend/src/shared/lib/feature-flags.ts`):

| 겹 | 값 | 꺼져 있으면 |
|---|---|---|
| 빌드 플래그 | `EXPO_PUBLIC_SUBSCRIPTION_UI=on` | 구독을 한 글자도 언급하지 않는다(App Store 2.1(b) — KAN-66) |
| 결제 네이티브 모듈 | 바이너리에 `ExpoIap` 가 있다(런타임 검사) | 같다 — 플래그가 켜진 번들이 OTA 로 옛 바이너리(runtime 31 이하)에 닿아도 결제 버튼만 보이는 상태가 되지 않는다 |
| 플랫폼 | iOS, 또는 Android + `EXPO_PUBLIC_SUBSCRIPTION_ANDROID=on` | **개발계(preview) `on`(2026-10-08 — dev 앱 정기 결제·RTDN 연결 완료, KAN-155 코멘트) · 운영(production) `off`**(운영 Play 상품 등록 KAN-130 전까지). `eas.json` 프로필 env 와 `eas-update.yml` 채널 env 두 곳이 같은 값이어야 한다 — production 은 preview 를 extends 하므로 `off` 를 명시한다 |

꺼진 바이너리에서 이 문서의 화면은 하나도 그려지지 않는다 — 설정 구독 섹션·프로필 [구독 알아보기]·페이월 요금제 비교가 모두 빠지고, 한도 소진은 **한도 안내 시트**(`paywall.md` 5장) 그대로다.

## 3. 화면 흐름

```
카드를 골라 목록 아래 [<요금제> 구독하기]·[<요금제> 업그레이드]·[<요금제>로 변경] 탭
   ├─ is_email_verified == false ──> 토스트 "구독하려면 이메일 인증이 필요해요"
   │                                 → 이메일 등록·인증(A 계열). 페이월이면 시트를 내려 둔다
   │                                 → 인증 성공 → (페이월은 시트를 다시 연다) → 같은 요금제로 결제 시트
   ↓ 결제 의도 → 스토어 결제 시트(StoreKit 2)
   ├─ 닫음(취소) ─────────────────> 원래 화면. 문구 없음
   ├─ 승인 대기(Ask to Buy) ──────> 안내 "결제 승인을 기다리고 있어요…"
   ↓ 결제 완료 → "구독을 확인하고 있어요"
   ├─ 서버 200 ────────────────────> 토스트(4.3) → 화면 갱신. 페이월이면 시트 닫힘 → 막혔던 콘텐츠 자동 재생
   ├─ 503 · 네트워크 ──────────────> "구독을 확인하고 있어요… 잠시 후 자동으로 반영됩니다"(뒤에서 재시도)
   │                                 페이월이면 같은 문구 토스트 후 시트 닫힘
   └─ 400 · 409 ───────────────────> 인라인 오류(4.4). 시트·화면 유지
```

## 4. 화면별 명세

### 4.1 SB1 요금제 관리 — 골격

(개정 2026-10-06 KAN-146 — PM 미리보기 확정 `KAN120_약관줄중앙.png`. 종전: 앱바 제목 "구독 관리" + "현재 구독" 섹션 + "요금제" 섹션 제목 + 카드 아래 큰 [구매 복원])

앱바: **뒤로(유리 원 셰브론)만** — 제목 없음. 본문 좌우 여백 **32pt**(카드·버튼·필수 표기가 한 세로선 — SE 375pt 에서 카드 폭 311pt, PM 2026-10-07). 본문 순서:

1. **이어 로고 폭 88pt**(투명 PNG, 그림 테두리에 맞춰 위아래 여백을 잘라 낸 파일 — 로고 위 추가 여백 없음, 장식 — 낭독 제외) → 8pt → **"요금제 관리"**(28pt 굵게, 가운데, 낭독 `header`)
2. SB2 요금제 카드(섹션 제목 없음) + 목록 아래 결제 버튼 하나. **현재 구독 정보는 이용 중 카드(`action = current`) 안**, 이름 밑 시작선에 맞춰 둔다(아래 표)
3. 결과 안내(SB3)
4. 필수 표기(4.5) + 맨 아래 **"이용약관 · 개인정보처리방침 · 구매 복원"** 한 줄(카드와 필수 표기 사이 16pt)

**현재 구독 정보 — 이용 중 카드 안**(서버 `GET /users/me/subscription` 의 `plan.status`)

| 상태 | 이용 중 카드 안(카드 요약·[이용 중] 아래) |
|---|---|
| 로딩 | 그리지 않는다(카드 목록 스켈레톤이 자리를 잡는다) |
| 조회 실패 | **"구독 정보를 불러올 수 없어요"** + [다시 시도] |
| `free` | 없음 — 카드의 설명(서버 `description`)이 한도를 말한다 |
| `subscribed` | **"다음 결제일 N월 N일"** / (다운그레이드 예약 시) **"N월 N일부터 {플랜명} 요금제가 적용돼요"**(`pending_plan.effective_at`) / **[구독 해지]** — 단 **목록에 `cancel` 카드가 있으면 그리지 않는다**: 해지는 무료 요금제 카드를 고르고 [{이름}로 변경]으로 한다(2026-10-08 PM — 조작 문법을 "카드 고르기 + 아래 버튼 하나"로 통일. 서버가 `cancel` 을 주기 전엔 종전 버튼이 해지 경로다) |
| `cancel_scheduled` | **"N월 N일까지 이용 가능해요"** — 중립 톤 / **[구독 다시 시작]** |
| `grace` | 경고 면 **"결제에 문제가 있어요"** + "결제 수단을 확인하지 않으면 구독이 종료될 수 있어요" / **[결제 수단 확인]** |
| 다른 스토어 구독(`store` ≠ 이 기기의 스토어) | 위 상태 문구 + **"Google Play에서 구독 중이에요. 구독한 기기에서 변경해주세요"**(반대는 "App Store에서…") — 스토어 이동 버튼 없음 |

- **카드는 회색이어도 누를 수 있는 버튼([구독 해지]·[구독 다시 시작]·[결제 수단 확인]·[다시 시도])은 평소 색이다** — 해지 경로는 심사 대상이다. 구독 정보 글자도 회색 단계가 아니라 보조 글자색(`textSecondary`)이다.
- **서버가 `current` 카드를 주지 않으면**(비활성 요금제 구독자·다른 스토어 구독자 — `subscription-api.md` 4.1, 또는 요금제 조회 실패) 같은 정보를 **카드 목록 바로 아래 별도 면**에 플랜명과 함께 그린다. 해지 경로가 사라지지 않게 한다. 무료 이용자는 그릴 것이 없다.
- [구독 해지]·[구독 다시 시작]·[결제 수단 확인]은 **스토어 구독 관리 화면으로 보낸다**(해지 API 없음 — `subscription.md` 4.5). 어느 스토어인지는 서버 `store` 가 정한다.
- 날짜는 서버 값(ISO)을 기기 로캘의 월·일로 표기만 한다. 만료·해지 판정을 하지 않는다.
- 결제·복원 진행 중에는 **전체 로딩 + 뒤로가기·스와이프 차단**.

### 4.2 SB2 요금제 카드

서버 `plans[]` 순서(낮은 티어 → 높은 티어) 그대로. 무료 요금제도 비교를 위해 그린다. **카드는 라디오 · 이름 · 가격 · 설명 한 줄**(2026-10-06 KAN-146 — 기능 줄 "하루 N편 듣기 · 이어 PICK · 광고" 제거). **결제 버튼은 카드마다가 아니라 목록 아래 하나**다(2026-10-07 PM 미리보기 확정 — 카드마다 [구독하기]가 반복되고 [이용 중]만 혼자 버튼 모양이라 어색했다).

| 요소 | 내용 |
|---|---|
| 이름 · 가격 | 서버 `name`(하드코딩 금지 — 지금 값 Light·Daily·Pro, KAN-147) / 유료: **스토어가 준 현지 가격 + "/월"**(예: `₩3,900/월`) · 무료: **"무료"** |
| 설명 | 서버 `description` 한 줄 |
| 라디오(서버 `action`) | `purchase`·`upgrade`·`downgrade` 카드, 그리고 **요금제 관리 화면에서는 `cancel` 카드(유료 구독자의 무료 요금제)**만 고를 수 있다. `cancel` 을 고르면 아래 버튼은 **보조 버튼 [{이름}로 변경]** + 밑 안내 **"지금 요금제는 N월 N일까지 이용할 수 있어요"**(다음 결제일), 누르면 스토어 구독 관리. 기본 선택은 유료 카드다 — 해지는 직접 골라야만 선택된다. 페이월에서는 `cancel` 카드를 고를 수 없다(2026-10-08 PM — KAN-159) — 카드 전체가 라디오 하나(왼쪽 원 22pt, 선택이면 검정 테두리 2pt + 안 점). `current`·`none` 카드는 라디오 없이 **라디오 칸을 비워** 이름·설명 시작점을 맞춘다 |
| 기본 선택 | **고를 수 있는 첫 카드**(서버 순서) — 무료 사용자는 Daily, Daily 구독자는 Pro. 티어명으로 고르지 않는다. 고른 카드가 목록에서 빠지면(결제 후 이용 중으로 바뀜) 다시 첫 카드 |
| 버튼(고른 카드의 `action`) | 목록 아래 알약 하나 — `purchase` **"{이름} 구독하기"** · `upgrade` **"{이름} 업그레이드"** · `downgrade` **"{이름}로/으로 변경"**(보조 버튼, 조사는 이름 마지막 글자로) + "다음 결제일부터 적용돼요". 고를 카드가 없으면(다른 스토어 구독 등) 버튼 없음 |
| 이용 중 | `current` 카드 이름 옆 **[이용 중] 배지**(버튼 아님 — 아래) |

- 버튼은 **알약**(`design.md` §2) — 주 동작 검정 채움, 변경은 흰 면 + 머리카락 선. 카드를 누르면 고르기만 하고 결제는 버튼이 연다.
- 모든 카드에 2pt 테두리를 투명으로 깔아 둔다 — 선택에 따라 안쪽 글자가 움직이지 않는다.
- **이용 중 카드(`action = current`)는 회색 처리** — 강조 테두리 없음, 이름·가격 `#8E8E93`(`color.textMuted`), 설명 `#AEAEB2`(`color.textMutedSecondary`), 이름 옆 회색 배지 **[이용 중]**(면 `#E5E5EA` `color.fillMuted`, 글자 `#8E8E93` 12pt 굵게, 체크 없음, 누를 수 없음 — 2026-10-07 버튼 자리 알약에서 배지로). 색만으로 구분하지 않는다 — "이용 중" 글자가 상태를 말한다. 현재 구독 정보는 이 카드 안(4.1).
- 무료 사용자의 무료 요금제가 `current` 인지는 서버가 정한다(KAN-147 이후 `current`). 서버가 `none` 으로 주면 [이용 중] 없이 그린다 — 클라이언트가 추측하지 않는다.
- **가격은 스토어 현지 가격만 그린다.** 스토어 조회가 실패하거나 상품 하나라도 빠지면 카드 대신 **"요금제를 불러올 수 없어요"** + [다시 시도] — `price_krw` 로 메우지 않는다(`subscription-api.md` 4.1).
- 버튼 종류를 클라이언트가 고르지 않는다(티어 순서 비교 금지).
- 결제·복원 진행 중에는 카드 선택·버튼 모두 비활성, 결제 중이면 버튼에 스피너.

### 4.6 PW1 페이월 시트

`paywall.md` 5장 "바텀시트 구성" 그대로 — **한도 안내 시트 위에 얹는다.**

순서: 주의색 빈 링 `0` → 제목(**"오늘 청취 한도를 모두 사용했어요"** 또는 서버 문구) → "매일 새벽 5시에 다시 채워져요" → **SB2** → SB3 안내 → 필수 표기 + **"이용약관 · 개인정보처리방침 · 구매 복원"** 줄(4.5 — 요금제 관리와 같은 컴포넌트) → **[닫기]**(보조 면 알약 — 결제 버튼이 주 동작).

## 5. 접근성

- 요금제 카드: 카드 요약(이름·가격·설명)을 **"{플랜명}, {가격}, {설명}"** 한 문장으로 읽고, 이용 중이면 끝에 **", 이용 중"**. 고를 수 있는 카드는 **라디오**(선택 상태 함께), 카드 묶음은 **"요금제" 라디오 그룹**으로 읽힌다. 목록 아래 버튼 라벨은 화면 글자와 같다(예: "Pro 구독하기"). 이용 중 카드 안의 구독 정보·[구독 해지]도 따로 읽힌다.
- "이용 중"·결제 문제는 **색만으로 구분하지 않는다** — [이용 중] 글자·경고 제목을 함께 둔다. 로고와 링크 줄·필수 표기의 "·"는 장식이라 낭독하지 않는다.
- 결과 안내(SB3)는 바뀔 때 읽히도록 라이브 영역으로 둔다. 결제 문제 배너는 `alert`.
- 터치 타깃 44pt 이상(복원·약관 링크 포함).
