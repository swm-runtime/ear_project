# 인증·계정 UI/UX 명세서

> 기준 문서: [`docs/pages/auth.md`](../../pages/auth.md)
> 와이어프레임: [`docs/wireframe/auth.html`](../../wireframe/auth.html) (화면 ID A1–A18)
> API: [`auth-api.md`](../api/auth-api.md)

## 1. 범위

로그인·가입(약관 동의) → 로그아웃 → 회원 탈퇴 → 이메일 등록·코드 인증까지, `auth.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 판정·규칙은 `auth.md`, 통신 계약은 `auth-api.md`가 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 사용자 조작에 어떻게 반응하는가**다.

## 3. 화면 흐름

```
A1 시작 ──[제공자 버튼]──> A2 인증 중
                             ├─ 취소 ────────> A1 (에러 표시 없음)
                             ├─ 실패 ────────> A3
                             ├─ 기존 계정 ───> 라이브러리 / 온보딩
                             └─ 신규 ────────> A4 약관 동의 ──> 온보딩
                                                  └─ 이탈 시 계정 미생성

A5 설정 ──[로그아웃]──> A6 ──> A1
        ──[회원 탈퇴]──> A7 ──> A8 ──> A1
        ──[이메일]────> A10

결제 시도(이메일 없음) ──> A9
A9 / A10 ──[인증 코드 받기]──> A12 ──> A13 ──> A18 ──> 복귀
                                  ├─ 불일치 ─> A14
                                  ├─ 만료 ───> A15
                                  ├─ 시도소진 > A16
                                  └─ 발송소진 > A17
```

**복귀 지점만 다르고 화면은 같다** — 결제 경로(A9)는 원래 결제 플로우로, 설정·프로필 경로(A10)는 직전 화면으로 돌아간다. 인증 화면 자체를 두 벌 만들지 않는다.

## 4. 화면별 명세

### 4.1 A1 시작 화면

**구성** — 서비스 소개 / 카카오·구글·네이버 버튼 3개 / 약관·개인정보 처리방침 **링크**

- **묵시적 동의 문구를 두지 않는다.** "계속하면 약관에 동의한 것으로 봅니다" 류의 문구는 금지다. 링크만 제공하고 동의 의미를 부여하지 않는다(`auth.md` 4.1).
- 약관 링크를 열어도 **동의로 기록되지 않는다.** 인앱 브라우저로 본문만 연다.
- 제공자 버튼은 각 브랜드 가이드(색·로고·명칭)를 따른다. 심사 반려 사유가 된다.

### 4.2 A2 제공자 인증 중 · A3 인증 실패

- 외부 앱·웹뷰로 전환되며, 복귀까지 **로딩 오버레이**를 유지한다.
- **사용자가 인증을 취소한 경우 에러를 표시하지 않는다.** A1 상태로 조용히 복귀한다 — 취소는 실패가 아니다.
- 인증 실패는 토스트: **"로그인에 실패했어요. 다시 시도해주세요"**
- 제공자 앱이 없으면 웹 로그인으로 폴백한다. 사용자에게 별도 안내를 띄우지 않는다.

### 4.3 A4 약관 동의

**구성** — 전체 동의 / 필수 2종(이용약관·개인정보 처리방침) / 선택 1종(마케팅) / 각 항목 [보기] / [동의하고 시작하기]

- **필수 2종을 모두 체크해야 버튼이 활성화된다.**
- **이 버튼을 누른 시점에 계정이 생성된다.** 화면 카피가 이 사실을 흐리지 않게 한다.
- 전체 동의 체크박스는 선택 항목까지 포함하며, **기본값은 해제**다.
- 마케팅 동의 옆에는 수신 내용을 한 줄로 밝힌다(정보통신망법 고지 의무).
- 뒤로가기·앱 종료로 이탈하면 계정이 만들어지지 않는다. 재로그인 시 이 화면부터 다시 시작한다.

### 4.4 A5 설정 — 계정 섹션 · A6 로그아웃 확인

- 계정 섹션에 **[이메일] · [로그아웃] · [회원 탈퇴]** 세 진입점을 둔다.
- 이메일 항목은 값이 있으면 주소를, 없으면 **"등록되지 않음"** + [등록]을 보여준다.
- 로그아웃은 확인 다이얼로그를 거친다: **"로그아웃할까요?"** [취소] / [로그아웃]
- 로그아웃은 **이 기기 세션만** 폐기한다는 점을 다이얼로그 보조 문구로 밝힌다.

### 4.5 A7 탈퇴 안내

이 플로우에서 **정보량이 가장 많은 화면**이다. 순서를 지킨다.

```
1. 삭제되는 데이터
2. 보존되는 데이터 ─ "결제·구독 이력과 이메일 주소는 관련 법령에 따라 5년간 보관됩니다"
3. (활성 구독 시) 스토어 해지 안내 ─ 텍스트만
4. 구독 만료 동의 체크
5. 탈퇴 사유(선택)
6. 최종 확인 체크
7. [탈퇴하기]
```

- **삭제 항목과 보존 항목을 나란히 노출한다.** 삭제만 보여주면 "전부 지워진다"고 이해한 채 탈퇴하게 된다.
- **스토어로 보내는 버튼·딥링크를 두지 않는다.** 탈퇴 도중 외부 앱으로 이탈하면 돌아오지 못한다. 해지 진입점은 설정 > 구독 관리에 이미 있다.
- 활성 구독이 있으면 **만료 동의 체크 없이 [탈퇴하기]를 활성화하지 않는다.**
- [탈퇴하기]는 파괴적 액션 스타일(경고색)로 두되, 취소 경로를 같은 화면에 남긴다.

### 4.6 A8 탈퇴 처리 중 → 완료

- **전체 화면 로딩이며 취소할 수 없다.** 서버가 이관과 파기를 하나의 트랜잭션으로 수행하는 구간이다.
- 뒤로가기·제스처를 차단한다.
- 완료 후 **"탈퇴가 완료되었습니다"** 토스트 → A1으로 이동하며 **스택 전체를 초기화**한다.

### 4.7 A9 / A10 이메일 입력

|  | A9 결제 전 | A10 설정·프로필 |
|---|---|---|
| 진입 사유 문구 | **있음** — 왜 지금 이메일이 필요한지(거래기록 보존) | 없음 |
| 현재 이메일 | 없음(`null`이라 진입) | **표시** — 없으면 "등록되지 않음" |
| 버튼 | [인증 코드 받기] | [인증 코드 받기] |
| 이탈 시 | 결제 중단, 저장 안 함 | 기존 값 유지 |

- 입력 필드는 `type=email`, 키보드는 이메일 자판, 자동 대문자·자동 수정 비활성.
- 자동완성(`autocomplete="email"`)을 허용한다.
- **변경도 신규 등록과 같은 절차를 거친다**는 점을 A10 보조 문구로 밝힌다.

### 4.8 A11 형식 오류

- 형식이 맞지 않으면 **[인증 코드 받기]를 비활성 상태로 둔다.** 발송 요청 자체를 보내지 않는다.
- 인라인 에러: **"이메일 형식을 확인해주세요"**
- 검증 시점은 **입력 중이 아니라 포커스 아웃 또는 버튼 탭 시점**이다. 타이핑 중간마다 빨간 글씨를 띄우지 않는다.
- 같은 주소를 다시 입력한 경우(`EMAIL_ALREADY_REGISTERED`)는 인라인 **"이미 등록된 이메일이에요"** — 이 경우 **발송 횟수가 소모되지 않았음**을 사용자가 걱정하지 않도록 별도 경고를 덧붙이지 않는다.

### 4.9 A12 코드 발송 중 → 발송 실패

- 버튼을 로딩 상태로 바꾸고 **중복 탭을 차단한다.**
- 발송 실패 토스트: **"인증 메일을 보내지 못했어요. 다시 시도해주세요"**
- 실패는 **발송 횟수를 차감하지 않는다.** 화면의 남은 횟수 표시를 줄이지 않는다.

### 4.10 A13 인증 코드 확인 — 이 플로우의 핵심 화면

**구성** — 발송된 주소 표시 / 6칸 코드 입력 / `mm:ss` 카운트다운 / [재전송] / 스팸함 안내

**코드 입력**

- 6칸 분리 입력. 키보드는 **숫자 전용**(`inputmode="numeric"`), 자동 포커스 이동, 백스페이스 시 이전 칸으로.
- **6자리 붙여넣기를 지원한다.** 메일에서 복사한 값이 한 번에 채워져야 한다.
- 6칸이 모두 채워지면 **자동으로 검증을 요청한다.** 별도 [확인] 버튼을 두지 않는다.

**카운트다운**

- 발송 시각 기준 **3분**을 `mm:ss`로 표시한다(`02:41` 형태).
- **클라이언트 타이머는 표시용이다.** 만료 판정은 서버가 한다. 재진입 시 자체 타이머를 복원하지 말고 서버가 준 `expires_at`으로 다시 계산한다.
- 남은 시간이 30초 이하가 되면 색으로 강조한다.

**재전송 버튼 상태**

| 조건 | 표시 |
|---|---|
| 쿨다운 중(60초) | 비활성 — **"47초 후 재전송"** |
| 쿨다운 종료 | 활성 — **[재전송]** |
| 발송 5회 소진 | 비활성 — 잠금 안내(A17) |

- 재전송하면 이전 코드가 즉시 무효화된다. 입력칸을 비우고 카운트다운을 초기화한다.

### 4.11 A14 코드 불일치

- 인라인 에러: **"인증 코드가 올바르지 않아요 (남은 시도 4회)"**
- **입력값을 지우지 않는다.** 사용자가 어디를 틀렸는지 볼 수 있어야 하고, 한 자리만 고치면 되는 경우가 많다.
- 남은 시도 횟수는 **서버 응답값**을 그대로 쓴다. 클라이언트가 세지 않는다.

### 4.12 A15 코드 만료

- 카운트다운이 `00:00`이 되면 **입력칸을 비활성화**한다.
- 안내: **"인증 시간이 지났어요. 코드를 다시 받아주세요"**
- **[재전송]을 활성 상태로 만든다.** 이 화면에서 사용자가 할 수 있는 유일한 행동이므로 명확히 드러낸다.
- "틀림"과 "만료"를 같은 문구로 처리하지 않는다. 재입력해야 하는지 재발송해야 하는지가 갈린다.

### 4.13 A16 검증 시도 5회 소진

- 코드가 무효화되므로 A15와 같은 형태로 처리한다: 입력 비활성 + **"코드를 다시 받아주세요"** + [재전송] 활성.
- **A17(발송 소진)과 혼동되지 않게 한다.** 여기서는 재전송이 가능하다.

### 4.14 A17 발송 5회 소진

- [인증 코드 받기]·[재전송]을 **모두 비활성**으로 둔다.
- 안내: **"인증 코드는 1시간에 5번까지 보낼 수 있어요. 약 43분 후 다시 시도해주세요"**
- **남은 시간을 분 단위로 표시한다.** "잠시 후 다시 시도해주세요"만으로는 언제 풀리는지 알 수 없어 그대로 CS 문의가 된다. 서버가 준 `retry_after_sec`을 분으로 환산한다.
- **유효 시간이 남은 코드가 있으면 입력칸은 살려둔다.** 잠기는 것은 발송이지 검증이 아니다. 이 상태에서 코드를 넣어 인증을 끝낼 수 있어야 한다.

### 4.15 A18 인증 성공

| 진입 경로 | 복귀 | 토스트 |
|---|---|---|
| 결제 전(A9) | 원래 시도했던 결제 플로우 | 없음 — 결제 화면이 이어지므로 |
| 설정·프로필(A10) | 직전 화면 | **"이메일이 등록되었어요"** |

- 복귀 후 이메일 항목이 **새 값으로 갱신되어 있어야 한다.**

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **토스트** | 되돌릴 필요 없는 결과 통지 | 로그인 실패, 발송 실패, 등록 완료. 3초 |
| **인라인 에러** | 입력값과 직접 관련된 오류 | 형식 오류, 코드 불일치. 해당 필드 바로 아래 |
| **다이얼로그** | 확인이 필요한 되돌릴 수 없는 조작 | 로그아웃. 파괴적 액션이 오른쪽 |
| **전체 화면 로딩** | 취소 불가 서버 트랜잭션 | 탈퇴 처리 중에만 사용 |
| **버튼 로딩** | 중복 탭 차단 | 코드 발송, 동의하고 시작하기 |

- **모든 제출 버튼은 인플라이트 동안 비활성화한다.** 발송 횟수·계정 생성처럼 중복이 실제 부작용을 만드는 곳이라 필수다.
- 에러 문구는 **무엇이 잘못됐는지 + 다음에 무엇을 하면 되는지** 두 가지를 담는다.

## 6. 카피 원칙

- **해요체**로 통일한다.
- 사용자를 탓하지 않는다: "잘못 입력하셨습니다" (×) / "인증 코드가 올바르지 않아요" (○)
- 내부 사유·에러 코드·기술 용어를 노출하지 않는다. 서버가 준 `message`를 그대로 쓰되, 클라이언트가 더 적절한 문구를 아는 경우(남은 시간 환산 등)는 재구성한다.
- **법적 고지는 완곡하게 바꾸지 않는다.** 5년 보존 고지, 마케팅 수신 동의 문구는 정확한 표현을 유지한다.

## 7. 접근성

- 터치 타깃 최소 44×44pt. 6칸 코드 입력도 이 기준을 지킨다.
- 코드 입력 6칸은 스크린리더에서 **"인증 코드 1번째 자리" 형태로 읽히게** 라벨을 붙인다.
- 카운트다운은 `aria-live="polite"` — 매초 읽히지 않도록 30초·10초 등 임계 시점에만 갱신을 알린다.
- 인라인 에러는 `aria-live="assertive"` + 해당 입력 필드와 `aria-describedby`로 연결한다.
- **색만으로 상태를 구분하지 않는다.** 비활성 버튼은 색과 함께 텍스트("47초 후 재전송")로 이유를 밝힌다.
- 동적 텍스트 크기(최대 200%)에서 잘리지 않아야 한다. 탈퇴 안내(A7)가 특히 위험하다.

## 8. 금지 사항

`auth.md`가 명시적으로 금지한 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

- 시작 화면(A1)의 **묵시적 동의 문구**
- 약관 동의 필수 항목의 **기본 체크 상태**
- 탈퇴 화면(A7)의 **스토어 이동 버튼·딥링크**
- 탈퇴 안내에서 **보존 항목 생략**
- 로그인 화면의 "이전에 OO로 가입한 이력이 있어요" 안내 — **개인정보 노출 우려**
- 인증 취소를 **실패로 표시**하는 것
- "틀린 코드"와 "만료된 코드"를 **같은 문구**로 처리하는 것
- 발송 잠금 안내에서 **남은 시간을 생략**하는 것
- 클라이언트 타이머만으로 만료·쿨다운을 **판정**하는 것

## 9. 미결 사항

- **탈퇴 사유 선택지 문구** — `reason_code` 값 목록과 함께 확정 필요(`auth-api.md` 9장).
- **A17 잠금 상태의 화면 유지 시간** — 43분을 앱 안에서 기다릴 수는 없으므로, 이탈 후 재진입 시 어디로 보낼지(입력 화면 / 코드 화면) 정해야 한다.
- **스팸함 안내 문구의 노출 시점** — 항상 노출할지, 재전송 1회 이후에만 노출할지.
- **다크 모드 대응 범위** — 와이어프레임은 단일 테마 기준이다.
