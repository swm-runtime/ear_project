# 온보딩 UI/UX 명세서

> 기준 문서: [`docs/features/onboarding.md`](../../features/onboarding.md)
> 와이어프레임: [`docs/wireframe/onboarding.html`](../../wireframe/onboarding.html) (화면 ID O1–O11)
> API: [`onboarding-api.md`](../api/onboarding-api.md)

## 1. 범위

관심 주제 선택(1/3) → 커리어 입력(2/3) → 추천 콘텐츠 담기(3/3) → 자동 드립 편성 대기 → 완료 요약 → 알림 권한 사전 안내 → 라이브러리 진입까지, `onboarding.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 판정·규칙은 `onboarding.md`, 통신 계약은 `onboarding-api.md`가 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 사용자 조작에 어떻게 반응하는가**다.

온보딩은 **한 번만 지나가는 경로**이고, 이탈하면 되돌아올 유도 화면이 없다. 그래서 이 문서의 판단 기준은 일관되게 하나다 — **어느 상태에서도 사용자를 막다른 곳에 두지 않는다.**

> **와이어프레임 동기화 필요** — `onboarding.html`은 O1–O11까지만 그려져 있고, 그중 O7은 정상 상태 하나만 그려져 있다. **O7-b(표본 부족 변형), O12(추천 카드 로딩), O13(완료 대기 로딩)** 은 아직 화면이 없다(9장 미결).

**화면을 만들지 않는 상태를 여기 함께 못 박는다.** 없는 화면은 나중에 누군가가 "빠졌다"고 판단해 되살리기 때문이다.

| 상황 | 화면 |
|---|---|
| [0] 온보딩 시작 안내 | **두지 않는다.** 약관 동의 직후 O1로 바로 진입한다 — 정보가 없는 환영 화면은 이탈 지점만 하나 늘린다 |
| 주제 목록이 빈 배열 | 에러가 아니다. **O1을 기본 주제 세트(하드코딩 폴백)로 그린다**(`onboarding.md` 7) |
| 3단계 추천이 0건 | **사용자 화면을 두지 않는다.** 데이터 정합성 오류이므로 3단계를 건너뛰고 O13으로 보낸다 + 운영 알림(`onboarding.md` 7) |
| 완료 대기 재시도 중 | O13을 **그대로 유지한다.** 별도 화면·문구 변화가 없다 |
| 완료 대기 재시도 소진·15초 초과 | 에러 화면을 두지 않는다. **O9로 진행한다** |

## 3. 화면 흐름

```
[약관 동의 완료] ──> O1 [1] 관심 주제 (1/3)
                       ├─ 조회 중 ───────> O5 스켈레톤
                       ├─ 조회 실패 ─────> O6 ──[다시 시도]──> O1
                       └─ 목록 빈 배열 ──> O1 (기본 주제 세트 · 에러 아님)

O1 ─[1~2개 선택]─> O2 ─[3개 선택]─> O3 ─[4번째 탭]─> O3 유지 + 토스트
O2 / O3 ──[다음]──> O4 [2] 커리어 (2/3)
                      ├─[건너뛰기]─┐
                      └─[다음]─────┴─> O12 스켈레톤 ──> O7-a [3] 추천 담기 (3/3)
                                                          └(월간 표본 부족)─> O7-b (같은 자리, 제목만 다름)

O7 ─[1건 이상 선택]──[N개 담기]──────────────────────> O9   ← 로딩 없음
O8 (0건 선택)──[건너뛰기]──> O13 [완료 대기] 전체 화면 로딩
                               ├─ 편성 성공 ──────────> O9
                               ├─ 재시도(최대 2회) ───> O13 유지 (사용자에게 변화 없음)
                               └─ 소진 · 15초 초과 ───> O9   ← 에러 화면 없음
━━━━━━━━━━━━━━━ 여기서부터 인디케이터 없음 ━━━━━━━━━━━━━━━
O9 [완료] ──[시작하기]──> O10 [알림] 사전 안내
                            ├─[알림 받기]─> OS 다이얼로그 ─> 라이브러리
                            └─[나중에]───> O11 재고 팝업 ─┬─[알림 받기]─> OS 다이얼로그 ─> 라이브러리
                                                          └─[괜찮아요]─> 라이브러리 (OS 다이얼로그 없음)

(OS 권한이 이미 허용됨) O9 ──────────────────────────> 라이브러리 (O10 · O11 통째로 건너뜀)
```

**인디케이터 경계선이 이 흐름도의 핵심이다.** 경계선 위(O1–O8)만 `N/3`을 그리고, 아래(O13 · O9 · O10 · O11)는 그리지 않는다. 인디케이터에 들어가는 것은 **사용자가 값을 입력하는 단계뿐**이다(`onboarding.md` 4 단계 구성).
- 완료 화면은 결과 확인이고 알림은 권한 요청이라, 이 둘을 `4/5` · `5/5`로 세면 입력이 다 끝난 사용자에게 "아직 두 단계 남았다"는 인상을 준다. 이탈 지점을 스스로 두 개 더 만드는 셈이다.
- **O13은 0건 경로에서만 나타난다.** 여기에 번호를 붙이면 단계 수가 사람마다 달라져, `3/3` 다음이 누구는 끝이고 누구는 `4/4`가 된다.

**O13은 0건 경로 전용 게이트다.** 1건 이상 담은 사용자는 이 화면을 **한 프레임도 보지 않는다** — 라이브러리가 이미 비어 있지 않으므로 기다리게 할 이유가 없고, 기다림은 완료 직전의 이탈 지점이 된다.

## 4. 화면별 명세

### 4.1 O1 · O2 · O3 관심 주제 선택 (1/3)

**구성** — 인디케이터 `1/3` / 제목 "어떤 이야기가 궁금하세요?" / 개수 안내 / 주제 칩 목록 / 하단 [다음]

- **이 화면에는 [건너뛰기]가 없다.** 커리어(O4)에는 있고 여기에는 없다는 비대칭이 화면에 그대로 드러나야 한다.
  - 주제는 드립 편성의 **유일한 필수 신호**다. 건너뛰기를 열어두면 신호 없는 계정이 대량으로 생기고, 그 사용자들은 첫날부터 대체 편성만 받는다 — 온보딩을 한 이유가 사라진다.
- 개수 안내는 **선택 전과 후의 문구가 다르다.**

| 상태 | 개수 안내 | [다음] |
|---|---|---|
| 미선택 (O1) | "최소 1개, 최대 3개까지 고를 수 있어요" + 하단 "관심 주제를 1개 이상 선택해주세요" | 비활성 |
| 1~2개 (O2) | **"N/3 선택"** | 활성 |
| 3개 (O3) | **"3/3 선택"** + 미선택 칩 비활성 | 활성 |

- **남은 자리를 상한에 부딪히기 전에 알린다.** `N/3`을 선택 직후부터 노출하는 이유다.
  - 4개째에 처음 알리면 같은 규칙이 안내가 아니라 제약으로 읽힌다. 이미 고른 것을 지워야 한다는 사실을 그때 알게 되기 때문이다.
- **3개를 채워도 선택된 칩은 계속 누를 수 있어야 한다.** 비활성 처리 대상은 미선택 칩뿐이다.
  - 선택을 바꾸는 유일한 경로가 "기존 선택 해제"인데 선택된 칩까지 잠그면 3개를 고른 순간 되돌릴 방법이 없어진다.
- **4번째 칩을 탭하면 토스트로 이유를 알린다** — "관심 주제는 3개까지 선택할 수 있어요"
  - 비활성 칩이 탭 이벤트를 삼켜 아무 반응도 없으면 사용자는 규칙이 아니라 **버그로 읽는다.** 비활성 스타일을 입히되 **탭은 받아서 토스트를 띄운다.**
  - 토스트는 3초, 같은 토스트가 쌓이지 않게 중복 노출을 억제한다.
- **선택 상태는 서버가 아니라 로컬에 임시 저장한다.** [다음] 탭 시점에 서버로 넘어간다(`onboarding-api.md` 관심 주제 저장).
  - 칩 탭마다 서버를 때리면 고르고 지우는 동안 요청이 수십 건 나가고, 그중 하나만 실패해도 화면과 서버 상태가 어긋난다.
  - 복원 시 **임시 저장분이 3개를 넘으면 앞의 3개만 선택 상태로 그린다**(상한 도입 이전 버전 잔재). 4개를 그려놓고 저장 단계에서 거절하지 않는다.
- **[다음]은 인플라이트 동안 비활성으로 둔다.** 연타로 저장 요청이 중복되면 서버가 상한 검증을 두 번 하고 화면은 두 번 전환된다.
- **클라이언트의 비활성 처리를 방어선으로 삼지 않는다.** 상한은 서버가 저장 시 다시 검증한다(`onboarding.md` 3). 화면 제한은 안내이지 검증이 아니다.
- **뒤로가기로 이 화면에서 더 뒤로 가면 아무 동작도 하지 않는다.** 이탈 확인 팝업을 띄우지 않는다.
  - 계정은 이미 만들어졌고 되돌릴 화면이 없다. 물어봐도 사용자가 고를 수 있는 선택지가 없는 팝업이다.
- 온보딩 중에는 **탭바를 그리지 않는다.** 라이브러리·탐색으로 빠져나갈 진입점을 화면에 두지 않는다(`onboarding.md` 2).

### 4.2 O5 주제 목록 로딩 · O6 목록 조회 실패

- O5는 **칩 모양 스켈레톤**이다. 스피너를 중앙에 띄우지 않는다 — 곧 채워질 레이아웃을 미리 보여주면 전환이 튀지 않는다.
- **0.3초 미만이면 스켈레톤을 표시하지 않는다**(`common-error-handling.md` 5). 빠른 응답에서 스켈레톤이 한 프레임 깜빡이면 오히려 느려 보인다.
- 로딩 중에도 인디케이터 `1/3`과 제목은 **먼저 그린다.** 이 단계가 무엇인지는 서버 응답과 무관하게 이미 정해져 있다.
- 로딩 중 [다음]은 비활성이다.
- **O6은 전체 화면 에러 + [다시 시도]만 둔다.** [건너뛰기]·[나중에 하기]를 두지 않는다.
  - 온보딩은 서버 저장이 필수라 오프라인으로 진행할 수 없다. 라이브러리(캐시 + 오프라인 배너)와 다른 점이며, 여기서 진행 경로를 열어주면 저장되지 않은 온보딩이 완료 처리된다.
- 문구: **"주제를 불러오지 못했어요"** + "잠시 후 다시 시도해주세요"
- **[다시 시도] 연타는 인플라이트 중 무시한다**(`common-error-handling.md` 7).
- **목록이 빈 배열로 오는 것은 실패가 아니다.** O6을 띄우지 말고 **기본 주제 세트(하드코딩 폴백)로 O1을 그린다**(`onboarding.md` 7).
  - 콘텐츠 풀 미구축은 서버 장애가 아니다. 여기서 에러 화면을 띄우면 신규 사용자가 앱에 아예 들어오지 못하고, [다시 시도]를 눌러도 영원히 같은 결과가 나온다.

### 4.3 O4 커리어 정보 (2/3)

**구성** — 인디케이터 `2/3` / 뒤로가기 / 직군(선택) · 직무(입력) · 연차(칩) / 안내 문구 / [다음] · [건너뛰기]

- **[건너뛰기]와 [다음]을 모두 노출한다.** [건너뛰기]는 보조 스타일로 두되 **숨기거나 작게 만들지 않는다.**
  - 전부 선택 항목인 화면에서 빠져나갈 버튼이 눈에 띄지 않으면, 쓸 생각이 없는 사용자가 아무 값이나 넣고 넘어간다. 그렇게 들어온 값은 없느니만 못한 편성 신호가 된다.
- **"나중에 프로필에서 언제든 입력할 수 있어요"를 상시 노출한다.**
  - 손해가 없다는 사실을 화면에서 말하지 않으면 사용자는 이 단계를 필수로 읽는다. 이 문구가 [건너뛰기] 버튼보다 중요하다.
- **미입력 필드에 에러 표시를 하지 않는다.** [다음]은 입력값과 무관하게 항상 활성이다. 아무것도 넣지 않고 [다음]을 눌러도 [건너뛰기]와 결과가 같다.
- 어느 버튼을 눌러도 `onboarding_step = pick`으로 저장된다(`onboarding-api.md` 커리어 저장). **[건너뛰기]도 서버 요청을 보낸다** — 단계 이동은 서버가 아는 재개 지점이기 때문이다.
- **뒤로가기로 O1에 돌아갈 수 있고, 이때 선택한 주제가 그대로 남아 있어야 한다.** 되돌아갔다가 선택이 비어 있으면 다시 고르는 대신 이탈한다.
- **커리어를 건너뛴 사용자에게 재촉 화면·배너를 만들지 않는다.** 입력·수정 경로는 프로필이 담당한다(`profile.md` 4.4). 온보딩에서 안 받은 값을 다시 조르는 화면은 "건너뛰어도 손해가 없다"는 방금 한 약속을 뒤집는다.

### 4.4 O12 추천 카드 로딩 · O7-a · O7-b · O8 추천 콘텐츠 담기 (3/3)

**구성** — 인디케이터 `3/3` / 제목 "먼저 들어볼 콘텐츠를 골라보세요" / 보조 문구 "지금 고르지 않아도 괜찮아요" / **두 개의 섹션(6건 + 3건)** / 하단 [N개 담기] 또는 [건너뛰기]

**두 섹션 구분**

- **6건과 3건을 한 덩어리로 그리지 않는다.** 섹션 제목과 간격으로 명확히 나눈다.
  - 두 그룹은 선정 기준이 다르다(`onboarding.md` 4-[3]). 섞어 놓으면 "내가 고른 주제"와 "새로 만나는 주제"의 구분이 화면에서 사라지고, 두 번째 섹션의 목적인 관심사 확장이 사용자에게 전달되지 않는다.
- 섹션 제목에 건수를 함께 표기한다 — "관심 주제 추천 · 6" / "이번 달 인기 · 3"

**O7-b 월간 표본 부족 변형** — 두 번째 섹션 제목만 바뀐다

| | O7-a 정상 | O7-b 표본 부족 |
|---|---|---|
| 두 번째 섹션 제목 | **"이번 달 인기"** | **"이런 주제는 어때요?"** |
| 건수·카드 레이아웃 | 3건 | **동일하게 3건** |
| 사용자 고지 | — | **없음** |

- **랜덤 3건을 "이번 달 인기"라는 제목 아래 두지 않는다.**
  - 인기 순위가 아닌 것을 인기라고 부르면 **사실과 다른 표시**가 된다. 사용자는 그 자리에 있는 것을 실제 인기 상위로 믿고 담는다.
- **표본이 부족하다는 사실을 사용자에게 알리지 않는다.** 배지·주석·"추천 정확도가 낮을 수 있어요" 같은 문구를 붙이지 않는다.
  - 운영 사정이라 사용자가 할 수 있는 일이 하나도 없고, 알리는 순간 추천 전체의 신뢰만 깎인다. **제목을 정직하게 바꾸는 것으로 충분하다.**
- **카드 레이아웃·건수·위치를 O7-a와 동일하게 유지한다.** 시각적으로 축소하거나 뒤로 미루지 않는다 — 그 자체가 "덜 좋은 추천"이라는 고지가 된다.
- **클라이언트가 순서를 다시 섞지 않는다.** 뽑기 결과는 사용자·세션 단위로 서버가 고정한다(`onboarding.md` 4-[3]). 뒤로 갔다 돌아와도 **같은 3건이 같은 순서로** 보여야 한다.
  - 방금 보던 카드가 사라지면 담기를 망설였던 사용자는 다시 찾지 못하고 그대로 이탈한다.

**선택과 담기**

- 카드 탭은 **선택이지 재생이 아니다.** 이 화면에 재생 버튼·미리듣기를 두지 않는다 — 탭했더니 오디오가 나오면 다중 선택 인터랙션이 통째로 깨진다.
- 선택 표시는 **체크 아이콘 + 테두리**다. 색만으로 구분하지 않는다.
- **하단 버튼은 담은 개수에 따라 바뀐다.**

| 선택 수 | 버튼 |
|---|---|
| 0개 (O8) | **[건너뛰기]** |
| N개 (O7) | **[N개 담기]** |

  - "0개 담기"는 **누를 이유가 없는 버튼**이다. 비활성 버튼을 두면 진행이 막힌 것처럼 보이고, 0개도 진행 가능하다는 규칙이 화면에서 지워진다.
- 담기 성공 시 라이브러리에 적립되고(`source = onboarding`), 담은 콘텐츠는 첫 드립 후보에서 제외된다.
- **담기 일부 실패는 진행을 막지 않는다.** 성공한 건만 적립하고 실패 건은 토스트로 알린 뒤 다음 화면으로 넘어간다(`onboarding.md` 7).
  - 온보딩 마지막 단계에서 사용자를 세워 두는 비용이 콘텐츠 몇 건을 못 담는 비용보다 크다.
- **여기서의 담기는 재생이 아니므로 무료 재생 한도 문구를 붙이지 않는다.** "2편까지 들을 수 있어요" 류의 안내를 이 화면에 두면 담을 수 있는 개수 제한으로 오해한다.
- [담기]·[건너뛰기]는 인플라이트 동안 로딩 상태로 두고 중복 탭을 차단한다.

**O12 로딩**

- 9칸 카드 스켈레톤 + **섹션 제목도 스켈레톤으로 둔다.**
  - 표본 충분 여부는 응답이 와야 알 수 있다. 제목을 미리 "이번 달 인기"로 그려두면 응답 직후 "이런 주제는 어때요?"로 바뀌는 것이 사용자 눈에 그대로 보인다 — **틀린 라벨을 잠깐 보여준 셈**이 된다.
- 0.3초 미만이면 표시하지 않는다.

**추천이 0건으로 온 경우**

- **"추천할 콘텐츠가 없어요" 화면을 만들지 않는다.** 3단계를 통째로 건너뛰고 **O13(완료 대기)으로 보낸다** — 담은 것이 0건인 경로이기 때문이다.
  - 정상 경로가 아닌 것을 정상 화면으로 만들면 관리자가 문제를 인지하지 못한다. 사용자는 조용히 통과시키고, 대신 **운영 알림을 발생시킨다**(`onboarding.md` 7).

### 4.5 O13 완료 대기 — 자동 드립 편성 중 (0건 경로 전용)

**이 화면은 0건 담기 경로에서만 존재한다.** 1건 이상 담은 사용자는 [담기] 직후 곧바로 O9로 간다.

**구성** — 전체 화면 / 스피너 / **"첫 콘텐츠를 준비하고 있어요"** / 그 외 아무것도 없음

- **인디케이터를 그리지 않는다.** 값을 입력하는 단계가 아니라 서버 처리를 기다리는 구간이다.
- **뒤로가기·스와이프 제스처를 차단한다.**
  - 완료 요청은 이미 서버에서 처리돼 `onboarding_completed = true`가 기록된 상태다. 3단계로 되돌리면 **이미 끝난 온보딩을 다시 진행하는 모순 상태**가 된다.
- **[취소]·[건너뛰기]·[닫기] 버튼을 두지 않는다.** 이 로딩의 존재 이유가 "라이브러리가 빈 채로 도착하는 것을 막는 것"인데, 빠져나갈 버튼을 주면 그 목적이 무효가 된다. 대신 **상한(15초)이 사용자 대신 빠져나가 준다.**
- **0.3초 미만이면 이 화면을 표시하지 않고 곧바로 O9로 넘긴다**(`common-error-handling.md` 5). 편성이 빨리 끝난 사용자에게 로딩이 한 프레임 깜빡이면 완료 화면 전환이 튀어 보인다.
- **진행률·남은 시간·"거의 다 됐어요" 류를 표시하지 않는다.** 편성 소요 시간을 예측할 수 없어 어떤 숫자를 그려도 거짓 진행률이 된다.
- **재시도 중에도 화면과 문구를 바꾸지 않는다.** "다시 시도하고 있어요"를 띄우지 않는다(`onboarding.md` 5).
  - 사용자가 할 수 있는 일이 하나도 없는데 실패를 알리면 불안만 남는다. 재시도는 최대 2회, 백오프 1초 → 3초로 **조용히** 진행된다(`common-error-handling.md` 4.2).
- **재시도를 소진하거나 15초를 넘기면 에러 화면 없이 O9로 진행한다.**
  - 사용자를 로딩 화면에 가둬 두는 것이 이 플로우의 최악이다. 서버에서는 이미 완료 처리된 계정이라, 앱만 멈춰 있으면 **강제 종료 말고는 빠져나갈 방법이 없다.**
  - 이 경로에서 사용자에게는 아무 에러도 노출하지 않는다. 준비 중 상태는 라이브러리 상단 배너 **"콘텐츠를 준비하고 있어요"** 가 이어받는다(`library.md` 5).
  - 동시에 **운영 알림을 발생시킨다.** 신규 사용자의 첫 편성 실패는 편성 배치 장애의 조기 신호라, 사용자에게 조용히 넘기고 끝내면 아무도 모른다.
- **편성할 후보 자체가 없는 경우는 대기하지 않는다.** 실패가 아니라 결과가 빈 것이므로 재시도해도 같은 결과다 — 즉시 O9로 진행한다(`onboarding.md` 7).
- **이 화면에서 앱이 강제 종료되면 재실행 시 이 화면을 다시 그리지 않는다.** `onboarding_completed == true`이므로 스플래시가 라이브러리로 직행한다(`splash.md` 4). **이 경로에서 O10·O11을 영영 보지 못하는 문제는 9장 미결이다.**

### 4.6 O9 완료 — 주제 요약

**구성** — 체크 아이콘 / "준비됐어요" / **선택한 주제 칩 요약** / "이 주제로 매일 2편이 라이브러리에 도착합니다" / 무료 티어 안내 / [시작하기]

- **인디케이터를 그리지 않는다.** 여기서 `4/4`나 `4/5`가 보이면 인디케이터 규칙이 깨진 것이다.
- **선택한 주제를 칩으로 그대로 되비춘다.** 방금 한 선택이 반영됐다는 것을 확인시키는 것이 이 화면의 유일한 기능이다. 요약을 문장으로 뭉뚱그리지 않는다.
- **무료 티어 안내를 함께 둔다** — "무료로 이용 중 · 하루 2편까지 재생할 수 있어요"
  - 드립 편수(2편)와 재생 한도(2편)가 같다는 것을 여기서 알려야 "받았는데 못 듣는다"는 오해가 생기지 않는다. 무료 티어도 드립을 받는다(PRD FR-14).
- **완료 요청은 이 화면의 [시작하기]가 아니라 3단계 종료 시점에 이미 나갔다**(`onboarding-api.md` 온보딩 완료 요청).
  - 1건 이상 경로: [담기]와 동시에 완료 요청 → 응답을 기다리지 않고 O9 노출
  - 0건 경로: [건너뛰기]와 동시에 완료 요청 → O13 → 편성 확인 후 O9 노출
- **따라서 [시작하기]는 화면 전환 버튼이다.** 다만 1건 이상 경로에서는 완료 요청이 아직 인플라이트인 채로 O9가 떠 있을 수 있으므로, **그동안 [시작하기]를 버튼 로딩 상태로 두고 중복 탭을 차단한다**(`onboarding.md` 5 "완료 · 서버 처리 중").
- **완료 처리는 어떤 이유로도 롤백하지 않는다.** 드립 트리거가 실패해도 이 화면을 그대로 띄운다.
  - 편성 실패를 이유로 `onboarding_completed`를 되돌리면 사용자는 온보딩을 처음부터 다시 하게 되는데, 원인인 편성 장애는 다시 해도 그대로다.
- 뒤로가기로 3단계에 돌아가지 못한다. **[시작하기] 이후 온보딩 스택 전체를 제거한다.**

### 4.7 O10 알림 사전 안내

**구성** — 벨 아이콘 / "드립 도착을 알려드릴까요?" / "새 콘텐츠가 도착하면 알림 한 번만 보내드려요. 하루 1회를 넘지 않습니다" / [알림 받기] · [나중에]

- **인디케이터를 그리지 않는다.** 이 화면을 "5단계"로 부르지도 않는다(`notification.md` 4.1).
- **OS 다이얼로그는 [알림 받기]를 눌렀을 때만 띄운다.** 이 화면 없이 OS 다이얼로그를 먼저 띄우지 않는다.
  - **OS 권한은 한 번 거부되면 앱에서 다시 요청할 수 없다.** 사전 안내는 회수 불가능한 한 번의 기회를 낭비하지 않기 위한 장치다.
- **발송 빈도를 문구에 명시한다**(하루 1회). 알림을 거부하는 가장 큰 이유가 "얼마나 올지 모른다"이므로, 상한을 먼저 말하는 것이 허용률에 직접 작용한다.
- **[나중에]는 주 액션보다 약한 스타일로 두되 감추지 않는다.** 여기서 두 버튼의 비중이 다른 것은 허용된다 — 되짚을 기회(O11)가 한 번 더 남아 있기 때문이다. **O11에서는 허용되지 않는다**(4.8).
- **권한 허용·거부 결과와 무관하게 라이브러리로 진입한다.** 거부한 사용자에게 안내 화면·재요청을 붙이지 않는다.
- **OS 권한이 이미 허용된 사용자(재설치 등)에게는 이 화면을 그리지 않는다.** 띄운 뒤 자동으로 닫지 않는다 — 화면이 한 번 깜빡이고 사라지는 것이 사용자에게는 오작동으로 보인다. **O11도 함께 건너뛴다.**
- 뒤로가기는 무시한다. O9는 이미 스택에서 제거된 상태이고, 되돌릴 조작이 없다.

### 4.8 O11 알림 재고 팝업

**구성** — 배경 딤 + 다이얼로그 / "알림을 받는 분들이 평균 **N%** 이상 더 많이 듣고 있어요." / "정말 설정하지 않으시겠어요?" / [괜찮아요] · [알림 받기]

- **두 버튼을 같은 행·같은 크기·같은 시각적 무게로 둔다.** [괜찮아요]를 회색 텍스트 버튼으로 두거나 작게 만들지 않는다 — 외곽선 버튼과 주 버튼처럼 **동등한 형태**로 둔다.
  - 거부를 어렵게 만드는 순간 다크패턴이 되고, 스토어 심사에서도 지적 대상이다. 이 팝업은 이미 한 번 거절한 사용자에게 다시 묻는 화면이라 기준이 더 엄격하다.
- **온보딩 전체에서 1회만 뜬다.** [괜찮아요]·[알림 받기]·뒤로가기 **어느 경로로 닫혀도 노출 이력을 소진 처리한다.**
- **배경 딤 탭으로는 닫히지 않게 한다.** 한 번뿐인 노출이 의도 없는 탭으로 소모되면 되짚을 기회가 사라진다.
- **[괜찮아요] 경로에서는 OS 다이얼로그를 띄우지 않는다.** 거부 이력을 소진하지 않기 위해서다 — 나중에 설정에서 켤 여지를 남긴다.
- **`N`에 임의의 수치를 넣지 않는다.** 출처가 확인된 값을 넣거나, 확보하지 못하면 **수치를 빼고 정성 문구로 대체한다** — "알림을 받으면 새 콘텐츠를 놓치지 않아요".
  - 자체 실측 없이 수치를 단정하면 표시광고법상 실증 책임이 생기고, 실증하지 못하면 문구를 내려야 한다.
  - 와이어프레임의 "20%"는 **자리 표시일 뿐 확정값이 아니다.** 릴리스 빌드에 근거 없는 숫자가 남아 있으면 안 된다(9장 미결).
- 문구에서 수치를 뺄 경우 **문장 구조가 무너지지 않는 두 벌의 카피를 준비한다.** 숫자만 지우면 "평균 이상 더 많이 듣고 있어요" 같은 비문이 남는다.

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **스텝 인디케이터** | 입력 단계 진행 표시 | **O1–O8에서만.** `N/3` 형태. O13 · O9 · O10 · O11에는 그리지 않는다 |
| **토스트** | 되돌릴 필요 없는 결과 통지 | 주제 상한 초과, 담기 부분 실패. 3초. 같은 토스트 중복 노출 억제 |
| **스켈레톤** | 목록 조회 대기 | O5(칩), O12(카드 9칸 + 섹션 제목). 0.3초 미만이면 미표시 |
| **전체 화면 로딩** | 취소 불가 서버 대기 | **O13에만.** 뒤로가기 차단, 취소 버튼 없음, 0.3초 미만이면 미표시 |
| **전체 화면 에러** | 진입 조회 실패 | **O6에만.** [다시 시도]만 두고 진행 경로를 열지 않는다 |
| **다이얼로그** | 되짚기 | **O11에만.** 두 선택지 동등 비중, 배경 탭으로 닫히지 않음 |
| **버튼 로딩** | 중복 탭 차단 | [다음], [N개 담기], [건너뛰기], [시작하기] |

- **하단 주 버튼은 스크롤 영역이 아니라 고정 독(dock)에 둔다.** O7은 9건이 세로로 쌓여 스크롤이 생기는 유일한 화면이라, 버튼이 목록에 묻히면 담고도 진행하지 못한다.
- **모든 제출 버튼은 인플라이트 동안 비활성화한다.** 관심사 저장·담기·완료 요청은 모두 상태를 바꾸는 요청이며, 중복 실행이 실제 부작용을 만든다.
- **온보딩 전 구간에서 탭바를 그리지 않는다.**
- 에러 문구는 **무엇이 잘못됐는지 + 다음에 무엇을 하면 되는지** 두 가지를 담는다(`common-error-handling.md` 4.6).

## 6. 카피 원칙

- **해요체**로 통일한다.
- **선택 단계임을 문구로 명시한다** — "지금 고르지 않아도 괜찮아요", "나중에 프로필에서 언제든 입력할 수 있어요". 선택 항목을 조용히 두면 필수로 읽힌다.
- **사실과 다른 라벨을 쓰지 않는다.** 랜덤 3건을 "인기"라고 부르지 않고, 근거 없는 수치를 "평균 N%"로 단정하지 않는다. 이 문서에서 두 번 반복되는 유일한 원칙이다.
- **운영 사정을 사용자 문구로 번역하지 않는다.** 표본 부족, 재시도 진행 중, 편성 실패 — 사용자가 할 일이 없는 사실은 화면에 올리지 않는다.
- **남은 단계 수를 문장으로 반복하지 않는다.** "이제 한 단계 남았어요" 류의 문구를 두지 않는다 — 인디케이터가 이미 말하고 있고, 둘이 어긋나면 문구가 먼저 낡는다.
- 사용자를 탓하지 않는다: "3개를 초과했습니다" (×) / "관심 주제는 3개까지 선택할 수 있어요" (○)
- 내부 사유·에러 코드·기술 용어를 노출하지 않는다.

## 7. 접근성

- **터치 타깃 최소 44×44pt.** 주제 칩과 추천 카드의 체크 영역이 특히 위험하다 — 칩은 글자 수에 따라 폭이 달라지므로 **최소 높이를 고정**한다.
- **주제 칩은 다중 선택 컨트롤로 노출한다.** `role="checkbox"` + `aria-checked`. 3개를 채운 뒤의 미선택 칩은 `aria-disabled="true"` + **"관심 주제는 3개까지 선택할 수 있어요"** 를 이유로 함께 읽히게 한다. 비활성 사실만 읽히면 이유를 알 수 없다.
- **인디케이터는 장식 이미지가 아니라 텍스트로 읽히게 한다** — "3단계 중 1단계". 세그먼트 막대에 `aria-hidden`을 걸고 별도 텍스트 라벨을 둔다.
- **선택 개수 변화는 `aria-live="polite"`로 알린다** — "2/3 선택". 매 탭마다 전체 목록을 다시 읽지 않게 개수 영역만 라이브 리전으로 둔다.
- **토스트는 `aria-live="polite"`.** 4번째 선택 시도는 오류가 아니라 안내이므로 `assertive`로 끼어들지 않는다.
- **O13 로딩은 `role="status"` + `aria-live="polite"`로 "첫 콘텐츠를 준비하고 있어요"를 한 번 읽는다.** 뒤로가기가 차단된 구간이므로 **포커스를 로딩 컨테이너 안에 가둔다** — 뒤 화면의 컨트롤로 포커스가 새면 스크린리더 사용자만 차단이 뚫린다.
- **O11 팝업은 열릴 때 포커스를 다이얼로그로 이동시키고, 닫을 때 [나중에] 버튼으로 되돌린다.** 포커스 트랩을 적용한다.
- **색만으로 상태를 구분하지 않는다.** 선택된 칩·카드는 색 변화와 **체크 아이콘**을 함께 쓰고, 비활성 [다음] 버튼은 하단 안내 문구("관심 주제를 1개 이상 선택해주세요")로 이유를 밝힌다.
- **동적 텍스트 크기(최대 200%)에서 잘리지 않아야 한다.** 칩 그리드(O1–O3)는 줄바꿈으로, O9의 주제 요약은 칩 줄바꿈으로 대응한다. 두 화면 모두 고정 높이를 쓰지 않는다.
- O7의 두 섹션은 **제목을 헤딩으로 마크업**해 스크린리더에서 섹션 단위 이동이 가능하게 한다.

## 8. 금지 사항

`onboarding.md`가 명시적으로 금지한 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

- 완료 대기(O13)·완료(O9)·알림(O10 · O11) 화면에 **인디케이터를 그리는 것**
- 인디케이터를 **`4/5` · `5/5`로 세는 것** — 완료·알림은 입력 단계가 아니다
- 1단계(O1)에 **[건너뛰기]를 두는 것**
- 4번째 칩 탭을 **무반응으로 삼키는 것** — 규칙이 버그로 읽힌다
- 3개를 채운 뒤 **선택된 칩까지 비활성화**하는 것 — 되돌릴 방법이 사라진다
- 클라이언트 비활성 처리를 **상한 검증으로 취급**하는 것(서버 재검증 생략)
- 목록 빈 응답을 **조회 실패(O6)로 처리**하는 것 — 기본 주제 세트 폴백이다
- 조회 실패 화면(O6)에 **[건너뛰기]·오프라인 진행 경로**를 두는 것
- 커리어 미입력자에게 **재촉 화면·배너**를 만드는 것
- 랜덤 폴백(O7-b)에 **"이번 달 인기" 제목을 그대로 두는 것**
- 표본 부족 사실을 **사용자에게 알리는 배지·주석**을 붙이는 것
- 랜덤 3건을 **화면 재진입마다 다시 뽑거나 클라이언트가 섞는 것**
- **"추천할 콘텐츠가 없어요" 화면을 만드는 것** — 정상 상태가 아니라 운영 알림 대상이다
- 0개 선택 상태에 **비활성 [0개 담기] 버튼**을 두는 것
- 담기 화면에 **재생·미리듣기**를 두는 것, **무료 재생 한도 문구**를 붙이는 것
- **1건 이상 담은 경로에 완료 대기 로딩(O13)을 태우는 것**
- O13에 **[취소]·[건너뛰기]를 두거나 뒤로가기를 허용**하는 것
- O13에서 **재시도 중임을 노출**하는 것("다시 시도하고 있어요")
- 재시도 소진·상한 초과 시 **에러 화면을 띄우는 것**, 또는 **로딩 화면에 사용자를 가두는 것**
- 드립 실패를 이유로 **완료 처리를 롤백**해 온보딩을 다시 시키는 것
- 사전 안내(O10) 없이 **OS 권한 다이얼로그를 먼저 띄우는 것**
- 재고 팝업(O11)의 **[괜찮아요]를 회색·소형으로 두는 것** — 다크패턴이자 심사 지적 대상
- 재고 팝업을 **2회 이상 띄우는 것**
- [괜찮아요] 경로에서 **OS 다이얼로그를 띄우는 것** — 회수 불가능한 거부 이력을 소진한다
- 이미 권한이 허용된 사용자에게 **O10 · O11을 노출**하는 것
- 재고 팝업에 **출처 없는 수치를 남긴 채 릴리스**하는 것
- 온보딩 중 **탭바를 노출**하는 것, 완료 후 **뒤로가기로 온보딩에 복귀**할 수 있게 두는 것

## 9. 미결 사항

- **와이어프레임 갱신** — `onboarding.html`에 **O7-b(표본 부족 변형)**, **O12(추천 카드 로딩)**, **O13(완료 대기 로딩)** 을 추가해야 한다. 현재 O1–O11만 그려져 있어 이 문서와 어긋난다.
  - 함께 고칠 것: **O9의 주석(완료 요청 시점)** 이 "[시작하기] 탭 시점에 `onboarding_completed = true` + 첫 드립 트리거"로 적혀 있으나, `onboarding.md` 4-[완료]는 **3단계 종료 시점**에 완료 요청이 나간다고 규정한다. 이 문서는 후자를 따랐다.
- **완료 대기 중 앱을 종료한 사용자의 알림 사전 안내 경로 (P0)** — O13에서 강제 종료하면 `onboarding_completed`가 이미 `true`라 재실행 시 라이브러리로 직행하고, **O10을 영영 보지 못한다.** `notification.md` 4.1이 제시한 두 안 중 하나를 정해야 한다.
  - (a) 라이브러리 첫 진입 시 사전 안내를 1회 노출 — 이 문서 기준으로는 O10을 그대로 재사용하는 안이다
  - (b) 설정의 알림 항목에 유도 배너 상시 노출
  - **OS 다이얼로그를 대신 띄우는 방식은 배제됐다.** 거부되면 회수할 수 없다.
- **랜덤 폴백 섹션 제목** — "이런 주제는 어때요?"는 잠정안이다. 인기 순위가 아님을 사실대로 말하면서도 "덜 좋은 추천"으로 읽히지 않아야 한다.
- **재고 팝업의 수치와 출처** — 와이어프레임의 "20%"는 자리 표시다. 출처 확보 여부에 따라 **수치 문구 / 정성 문구 두 벌의 카피**가 필요하며, 어느 쪽이든 릴리스 전에 확정해야 한다.
- **완료 화면(O9) 문구의 조건부 처리** — "매일 2편이 라이브러리에 도착합니다"는 첫 드립 성공을 전제한 문장이다. 트리거가 실패해 라이브러리가 "콘텐츠를 준비하고 있어요" 상태로 시작하는 경우 이 문장이 도착 즉시 어긋난다. **문구를 조건부로 바꿀지, 실패해도 그대로 둘지** 정해야 한다(와이어프레임 V3).
- **O13 로딩 상한(15초)과 재시도 횟수(2회)** — 공통 규칙에서 가져온 기본값이다. 실제 편성 소요 시간을 측정한 뒤 조정하되, **"재시도가 끝나면 반드시 완료 화면으로 진행한다"는 규칙은 유지한다.**
- **월간 인기 표본 기준값(재생 30건)** — O7-a와 O7-b를 가르는 문턱이다. 첫 달 실데이터로 조정한다.
- **[0] 온보딩 시작 안내 화면** — 이 문서는 화면을 두지 않는 것으로 정리했다. 가입 직후 맥락 전달이 부족하다는 판단이 서면 O1 상단 카피 강화로 대응하고, 별도 화면을 추가하지 않는 편이 낫다.
- **다크 모드 대응 범위** — 와이어프레임은 단일 테마 기준이다.
