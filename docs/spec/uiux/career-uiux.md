# 커리어 정보 UI/UX 명세서

> 기준 문서: [`docs/features/career.md`](../../features/career.md) · 입력 형식·선택지는 온보딩 커리어 단계와 동일([`onboarding-uiux.md`](onboarding-uiux.md) 4.3 — O4), 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/career.html`](../../wireframe/career.html) (화면 ID CR1–CR5)
> API: `career-api.md` 작성 시 이 문서의 직군 목록·저장 계약과 대조한다 (직무 길이 상한은 `onboarding-api.md` 4.4의 100자를 따른다)

## 1. 범위

프로필·설정에서 진입하는 커리어 정보 편집 화면 — 직군(서버 제공 목록에서 선택) · 직무(자유 입력) · 연차(구간 선택) 세 필드와 앱바 우측 [초기화], 하단 [저장], 저장 실패와 이탈 확인 팝업까지 `career.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 저장·초기화·빈 값 허용 규칙은 `career.md`가, 진입 카드·요약 표시는 `profile.md` 4.4 · `settings.md` 4.1이 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 사용자 조작에 어떻게 반응하는가**다.

- **관심사 관리와 별개 화면이다**(합의 2026-08-06 분리). 주제 편집 UI를 이 화면에 섞지 않는다.
- **세 값 모두 선택 입력이다.** 필수 표시·미입력 에러가 이 화면에 존재하지 않고, 값을 전부 비워 저장하는 것도 정상 경로다(`career.md` 4.2).
- **온보딩 커리어 단계(O4)와 같은 필드·같은 선택지·같은 값 체계를 쓴다.** 두 화면이 다르면 같은 컬럼에 다른 값이 쌓인다(`career.md` 3장). 이 문서 작성 시점에 대조 완료 — 필드 라벨(직군·직무·연차) · 직무 자유 입력(100자) · 연차 구간(0-1/2-3/4-6/7+) · 용도 안내 문구까지 일치한다.

## 2. 화면 목록

| ID | 화면 | 대응 상태(`career.md` 5장) |
|---|---|---|
| CR1 | 정상 — 입력됨 · 변경 없음 | 로딩(필드 스켈레톤 변형) · 정상(입력됨) |
| CR2 | 미입력 | 미입력 |
| CR3 | 변경 있음 · 직군 선택 시트 | 변경 있음 · 초기화 탭 · 저장 중 |
| CR4 | 저장 실패 | 저장 실패 (오프라인 저장 시도 포함) |
| CR5 | 이탈 확인 팝업 | 뒤로가기(변경 있음) |

**화면을 만들지 않는 상태를 여기 함께 못 박는다.**

| 상황 | 화면 |
|---|---|
| 저장 성공 | **별도 화면이 없다.** 토스트 + 이전 화면 복귀다(4.7) — 성공을 확인시키는 완료 화면을 두면 저장마다 화면이 하나 더 생긴다 |
| 진입 조회 실패 | **공통 전체 화면 에러 + [다시 시도]**(`common-error-handling.md` 4.3 — 화면 진입 조회는 차단형). 공통 컴포넌트를 그대로 쓰므로 별도 ID를 두지 않는다 |
| 오프라인에서 저장 시도 | **CR4와 같은 화면이다**(`career.md` 7장). 폼 제출은 오프라인 큐 대상이 아니다 — 즉시 실패 + [다시 시도], 편집 유지 |
| 초기화 탭 직후 | CR2와 같은 빈 폼이지만 **[저장] 활성 · [초기화] 비활성**인 변형이다(4.3). 별도 화면을 두지 않는다 |

## 3. 화면 흐름

```
프로필 [커리어 정보] 카드 · 설정 > 콘텐츠 > 커리어 정보
   └─> 진입 조회 ─┬─ 성공 ─┬─ 값 있음 ──> CR1 정상(입력됨)
                   │         └─ 값 없음 ──> CR2 미입력 ("입력하면 추천이 정확해져요")
                   └─ 실패 ──> 전체 화면 에러 + [다시 시도] (공통 — 별도 ID 없음)

CR1 / CR2 ─[직군 필드 탭]─> CR3 직군 선택 시트(서버 목록 + [선택 안 함])
          │                    ├─[항목 탭]─> 필드 반영 + 시트 닫힘 (저장 아님)
          │                    └─[딤·뒤로가기]─> 반영 없이 닫힘
          ─[직무 입력]─> 자유 입력 · 100자 상한
          ─[연차 칩 탭]─> 단일 선택 · 재탭하면 해제
          ─[초기화(앱바 우측)]─> 전 필드 비움 · 확인 팝업 없음 · 변경 있음 취급

편집 값 ≠ 서버 값 ──> 변경 있음: [저장] 활성
   ├─[저장]─> 저장 중(버튼 로딩 · 조작 차단)
   │            ├─ 성공 ─> 토스트 "커리어 정보가 저장되었어요" + 이전 화면 복귀
   │            └─ 실패 ─> CR4 인라인 에러 + [다시 시도] (편집 값 유지)
   └─[뒤로가기]─> CR5 "변경 사항을 저장하지 않고 나갈까요?"
                    ├─[계속 편집]─> 폼 그대로
                    └─[나가기]───> 편집 폐기 · 이전 화면 (서버 값 그대로)

편집 값 = 서버 값 ──[뒤로가기]──> 팝업 없이 이전 화면
```

**진입 경로가 둘이어도 화면은 하나다.** 프로필 카드로 들어오든 설정으로 들어오든 같은 폼·같은 규칙이고, 저장 후에는 **들어온 곳으로** 복귀한다. 복귀한 화면의 요약은 재조회로 갱신된다(`profile.md` 4.4).

## 4. 화면별 명세

### 4.1 CR1 정상(입력됨) — 화면 골격

**구성** — 앱바(뒤로가기 · 타이틀 "커리어 정보" · **우측 [초기화]** 텍스트 버튼) / 용도 안내 **"추천을 더 정확하게 하는 데만 쓰여요"** / 직군(선택 필드) / 직무(텍스트 입력) / 연차(칩 4개) / 하단 고정 독의 [저장]

- **용도 안내는 온보딩 O4와 같은 문자열이다.** 커리어는 추천 랭킹의 보조 신호일 뿐이라는 사실이 두 화면에서 다른 말로 표현되면 어느 쪽이 맞는지 사용자가 판단하게 된다.
- **[저장]은 변경 사항이 있을 때만 활성이다.** 진입 직후(편집 값 = 서버 값)에는 비활성으로 시작한다.
  - **변경 있음 판정은 탭 이력이 아니라 필드 단위 값 비교다.** 값을 바꿨다가 손으로 원래 값에 되돌리면 [저장]은 다시 비활성이 되고 이탈 팝업도 뜨지 않는다 — 아무것도 바뀌지 않았는데 저장이 활성이면 사용자는 무엇이 바뀌었는지 찾게 된다.
- **필드를 편집해도 그 시점에는 아무것도 서버로 가지 않는다.** 반영은 [저장]에서 일괄이다. 필드 단위 자동 저장을 두면 세 값 중 일부만 반영된 상태가 생기고, 이탈 확인이 성립하지 않는다.
- **미입력 필드에 에러·필수 표시를 하지 않는다.** 온보딩과 같은 원칙이다(`onboarding-uiux.md` 4.3) — 전부 선택 입력인 화면에서 빈 필드는 오류가 아니라 상태다.

**로딩(변형)** — 세 필드 자리를 스켈레톤으로 그린다. 앱바·타이틀은 먼저 그린다.

- **0.3초 미만이면 표시하지 않는다**(`common-error-handling.md` 5장).
- 로딩 중 [저장]·[초기화]는 비활성이다. 서버 값을 모르는 상태에서는 "변경 있음"도 "비울 것 있음"도 판정할 수 없다.
- 진입 조회가 실패하면 공통 전체 화면 에러 + [다시 시도]로 전환한다(2장). [다시 시도] 연타는 인플라이트 중 무시한다(`common-error-handling.md` 7장).

### 4.2 앱바 우측 [초기화] (CR1 · CR2 공통 요소)

**자리는 앱바 우측 한 곳이다.** 하단 독의 [저장]과 **오탭 거리를 두기 위해** 화면 반대편에 있다(`career.md` 4.1 — 개정 2026-08-09). 화면이 아니라 화면에 얹히는 요소이므로 별도 ID를 두지 않는다.

| 조건 | 상태 |
|---|---|
| 편집 중인 폼에 값이 하나라도 있음 | **활성** |
| 편집 중인 폼의 세 필드가 모두 빈 상태 | **비활성** — 비울 것이 없다 |
| 로딩 중 · 저장 중 | 비활성 |

- **탭하면 직군·직무·연차를 전부 비워 미입력 상태로 만든다. 확인 팝업 없이 즉시.**
  - 저장 전의 로컬 편집 조작이라 재입력으로 복구되고, 실수로 비워도 저장하지 않고 나가면 서버 값이 그대로다. 잃는 것이 없는 조작에 확인을 물으면 확인 팝업 전체의 무게가 낮아진다.
- **비운 상태는 변경 있음으로 취급한다** → [저장] 활성. 저장하면 미입력 상태로 되돌아간다(`career.md` 4.2 빈 값 저장 허용). 이 상태에서 뒤로가기를 누르면 이탈 팝업(CR5)이 뜬다.
- **활성 판정의 기준은 편집 중인 폼이다.** 서버 값이 있어도 사용자가 손으로 세 필드를 다 비웠다면 더 비울 것이 없으므로 비활성이다.
- 비활성은 무반응으로 둔다. 이유가 화면에 이미 보인다 — 모든 필드가 비어 있다(와이어프레임 CR2 주석 10).
- **[초기화]를 하단 독으로 옮기지 않는다.** [저장] 옆에 반대 방향의 파괴적 조작이 붙으면 확인 팝업 없는 설계의 전제(오탭이 어렵다)가 무너진다.

### 4.3 CR2 미입력

**구성** — CR1과 같은 골격. 상단 안내만 **"입력하면 추천이 정확해져요"** 로 바뀌고, 직군 필드에 placeholder "선택", 직무 필드에 placeholder "예) 서비스 기획자", 연차는 전부 미선택.

- **유도 문구는 프로필 [커리어 정보] 카드의 미입력 문구와 같은 문자열이다**(`profile-uiux.md` 4.5). 카드에서 "입력하면 추천이 정확해져요"를 보고 들어왔는데 화면이 다른 말을 하면 다른 곳에 온 것처럼 읽힌다.
- **입력을 강제하는 지점은 없다.** 온보딩에서 건너뛴 값을 다시 조르는 화면·배너를 만들지 않는 원칙(`onboarding-uiux.md` 4.3) 그대로다. 유도는 이 한 줄이 전부다.
- [저장]은 비활성(변경 없음), [초기화]도 비활성(비울 것 없음)으로 시작한다.
- placeholder "예) 서비스 기획자"는 온보딩 O4와 같은 문자열이다. 예시 문구가 두 화면에서 다르면 같은 필드가 다른 것을 묻는 것처럼 읽힌다.

### 4.4 CR3 변경 있음 — 입력 컨트롤 3종과 직군 선택 시트

**직군 — 선택 필드 + 바텀시트**

- 필드를 탭하면 바텀시트가 올라온다. **구성** — 핸들 / 제목 "직군" / 서버가 내려준 직군 행 목록 / 맨 아래 **[선택 안 함]**.
- **목록 항목은 서버 응답이 정한다**(확정 2026-08-10 — 온보딩과 공용 목록, 클라이언트 상수 금지). 와이어프레임의 개발·기획·PM 등은 예시일 뿐이다. 클라이언트는 받은 목록을 받은 순서대로 그린다 — 임의 정렬·필터링을 하지 않는다.
- 현재 값이 있으면 해당 행에 **체크 아이콘 + 강조색**을 함께 표시한다. 색만으로 선택을 구분하지 않는다(7장).
- **행을 탭하면 시트가 닫히고 필드에 반영된다. 이 시점에 저장되지 않는다** — 반영은 [저장]에서 일괄이다(와이어프레임 CR3 주석 6).
- **[선택 안 함]을 반드시 둔다.** 한 번 고른 직군을 비우는 유일한 경로다 — 빈 값 저장이 허용되는데 비우는 조작이 없으면 규칙이 화면에서 성립하지 않는다. 탭하면 필드가 placeholder 상태로 돌아간다.
- 딤 영역 탭·뒤로가기로 닫으면 아무것도 반영하지 않는다.

**직무 — 자유 입력**

- 텍스트 입력 필드, **길이 상한 100자**(`onboarding-api.md` 4.4와 같은 값). 상한에서 추가 입력을 받지 않는다. 글자 수 카운터·에러 문구는 두지 않는다 — 직무명이 100자에 닿는 경우가 사실상 없어, 상시 카운터는 없는 제약을 광고하는 셈이 된다(카운터 도입 여부는 9장 미결 — 온보딩 O4와 함께 정한다).
- 선택지 목록이 없다. 자동완성·추천 직무 칩을 두지 않는다 — 온보딩과 동일한 자유 입력으로 확정됐다(2026-08-09).

**연차 — 구간 칩 4개**

- **0–1년 / 2–3년 / 4–6년 / 7년+** 한 줄. 값 체계는 온보딩과 같은 enum(0-1/2-3/4-6/7+)이다.
- **단일 선택이며, 선택된 칩을 다시 탭하면 해제된다.** 값을 비우는 경로가 있어야 빈 값 저장이 성립한다. "선택 안 함" 칩을 따로 두지 않는다 — 해제된 상태가 곧 그것이다.
- 재탭 해제는 발견하기 어려운 조작이지만 [초기화]가 있어 막다른 길은 아니다. 선택된 칩은 해제 가능함이 드러나는 형태(선택 표시 + 눌림 상태)로 그린다.

**저장 중(변형)**

- [저장]을 버튼 로딩 상태로 바꾸고 **조작을 차단한다**(`career.md` 5장) — 세 필드·[초기화]·뒤로가기 모두. 저장 도중 값을 바꾸면 무엇이 저장됐는지 알 수 없고, 도중 이탈하면 결과를 확인할 화면이 없다.
- 중복 탭은 차단한다. 서버는 트랜잭션 단위라 부분 반영은 없지만(`career.md` 7장), 요청이 두 번 나가면 last-write-wins 규칙과 얽혀 어느 쪽이 최종인지 알 수 없다.

### 4.5 CR4 저장 실패

**구성** — 편집 상태 그대로 + 폼 하단 인라인 에러 **"저장하지 못했어요. 다시 시도해주세요"** + 하단 독 버튼이 **[다시 시도]** 로 전환.

- **편집 값을 버리지 않는다.** 실패 후에도 사용자가 입력한 값이 전부 그대로 있어야 한다 — 세 필드를 다시 입력하게 만들면 재시도 대신 이탈한다.
- **[다시 시도]는 같은 편집 값으로 저장을 다시 보낸다.** 인플라이트 중 연타는 무시한다(`common-error-handling.md` 7장).
- **실패 후 편집을 이어가면 인라인 에러를 지우고 버튼을 [저장]으로 되돌린다.** 값이 바뀌었으므로 "다시 시도"가 가리키던 요청이 더는 없다.
- **오프라인 저장 시도도 이 화면이다.** 폼 제출은 오프라인 큐에 넣지 않는다(`common-error-handling.md` 4.5 — 단일 값 토글만 큐 대상). 나중에 몰래 전송되면 사용자가 보지 않는 곳에서 커리어가 바뀐다.
- 이 상태도 변경 있음이므로 뒤로가기 시 이탈 팝업(CR5)이 뜬다.

### 4.6 CR5 이탈 확인 팝업

**구성** — 다이얼로그 / **"변경 사항을 저장하지 않고 나갈까요?"** / [계속 편집] · [나가기]. [나가기]가 주 액션 자리(우측)다.

- **변경 있음 상태의 뒤로가기에만 뜬다.** 변경이 없으면 팝업 없이 바로 나간다 — 잃을 것이 없는 이탈에 확인을 물으면 팝업이 습관적으로 무시된다.
- **관심사 관리의 이탈 팝업과 같은 문구·같은 버튼·같은 동작이다**(`career.md` 5장 — 와이어프레임 IM7과 대조 완료). 같은 성격의 편집 화면 두 개가 다른 말로 물으면 사용자는 다른 결과를 예상한다.
- **[나가기]는 편집을 폐기하고 이전 화면으로 돌아간다. 서버 값은 그대로다.** 폐기를 서버에 알릴 것이 없다 — 아무것도 전송된 적이 없기 때문이다.
- [계속 편집]은 팝업만 닫고 폼을 그대로 유지한다.
- **앱바 뒤로가기·시스템 뒤로가기(Android)·엣지 스와이프(iOS) 모두 같은 판정을 거친다.** 제스처만 팝업을 우회하면 확인 규칙이 입력 수단에 따라 달라진다.
- 딤 영역 탭으로는 닫히지 않게 한다. 파괴적 결과([나가기])가 걸린 팝업이 의도 없는 탭으로 닫히면 어느 쪽을 고른 것인지 알 수 없다 — 명시적 버튼으로만 닫는다.

### 4.7 저장 성공 — 토스트와 복귀

- 저장 성공 시 **이전 화면으로 복귀하면서 그 위에 토스트 "커리어 정보가 저장되었어요"** 를 3초 노출한다(문구 확정 2026-08-10).
- **완료 화면·체크 애니메이션을 두지 않는다.** 저장은 잦을 수 있는 가벼운 조작이다 — 매번 완료 화면을 통과시키면 저장이 무거워진다.
- 복귀한 프로필·설정의 요약은 재조회로 갱신된다(`profile.md` 4.4). **클라이언트가 방금 저장한 값으로 요약을 직접 조립하지 않는다** — 요약 표기 형식은 프로필이 소유하고, 두 곳에서 조립하면 형식이 어긋난다.

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **필드 스켈레톤** | 진입 조회 | 세 필드 자리. 0.3초 미만이면 미표시 |
| **전체 화면 에러** | 진입 조회 실패 | [다시 시도]만. 공통 컴포넌트 그대로 — 별도 ID 없음 |
| **바텀시트** | 직군 선택 | 행 목록 + [선택 안 함]. 딤 탭·뒤로가기로 닫으면 반영 없음 |
| **인라인 에러** | 저장 실패 | 폼 하단 + 독 버튼 [다시 시도] 전환. **편집 상태 유지** |
| **다이얼로그** | 이탈 확인 | 변경 있음 + 뒤로가기에만. 딤 탭으로 닫히지 않음 |
| **토스트** | 저장 성공 | "커리어 정보가 저장되었어요" 3초, 복귀한 화면 위 |
| **버튼 로딩** | 저장 중 | [저장] 로딩 + 조작 차단, 중복 탭 차단 |

- **저장 결과는 절대 조용히 처리하지 않는다.** 성공은 토스트, 실패는 인라인 에러 — 사용자가 시작한 액션이기 때문이다(`common-error-handling.md` 4.3). 반대로 이 화면에는 사용자가 시작하지 않은 통신(백그라운드 동기화)이 없다.
- 이 화면에는 스낵바([실행 취소])가 없다. [초기화]는 저장 전 로컬 조작이라 되돌리기가 "재입력 또는 나가기"로 이미 존재하고, 저장은 확인 없는 대신 실패 시 편집이 보존된다.

## 6. 카피 원칙 — 확정 문자열 전수

| 위치 | 문자열 | 근거 |
|---|---|---|
| 앱바 타이틀 | "커리어 정보" | 프로필 카드·설정 항목과 같은 이름 |
| 앱바 우측 버튼 | "초기화" | `career.md` 4.1 |
| 용도 안내(입력됨) | "추천을 더 정확하게 하는 데만 쓰여요" | 온보딩 O4와 같은 문자열 |
| 유도 문구(미입력) | "입력하면 추천이 정확해져요" | `career.md` 5장 · 프로필 카드와 같은 문자열 |
| 필드 라벨 | "직군" / "직무" / "연차" | 온보딩 O4와 같은 라벨 |
| 직군 placeholder | "선택" | 이 문서 확정 (와이어프레임 CR2) |
| 직무 placeholder | "예) 서비스 기획자" | 온보딩 O4와 같은 문자열 |
| 연차 칩 | "0–1년" / "2–3년" / "4–6년" / "7년+" | enum(0-1/2-3/4-6/7+)의 표기 — 온보딩과 동일 |
| 직군 시트 | 제목 "직군" · 말행 "선택 안 함" | 이 문서 확정 (와이어프레임 CR3) |
| 저장 버튼 | "저장" / 실패 후 "다시 시도" | `career.md` 5장 |
| 저장 실패 인라인 | "저장하지 못했어요. 다시 시도해주세요" | 이 문서 확정 (와이어프레임 CR4 — 무엇이 잘못됐는지 + 다음 행동) |
| 저장 성공 토스트 | "커리어 정보가 저장되었어요" | 확정 2026-08-10 (`career.md` 4.2) |
| 이탈 팝업 | "변경 사항을 저장하지 않고 나갈까요?" · [계속 편집] · [나가기] | `career.md` 5장 — 관심사 관리와 같은 문구 |

- **해요체**로 통일한다.
- **온보딩·프로필과 공유하는 문자열은 그대로 쓴다.** 용도 안내(O4) · 유도 문구(프로필 카드) · 이탈 팝업(관심사 관리) 세 곳이다. 같은 개념을 화면마다 다른 말로 부르면 어느 쪽이 맞는지 사용자가 판단하게 된다.
- **내부 용어를 화면에 노출하지 않는다** — "드립", "보조 신호", "랭킹". 추천에 쓰인다는 사실만 말한다.
- **"필수 아님"·"선택 사항" 같은 안내를 따로 붙이지 않는다.** 필수 표시가 없는 것이 곧 그 안내다 — 굳이 말하면 어딘가에 필수가 있다는 인상을 준다.
- 저장 실패 문구는 서버가 `error_message`를 내려주면 그것을 우선 사용한다(`common-error-handling.md` 4.6).

## 7. 접근성

- **터치 타깃 최소 44×44pt.** 위험한 곳 — 앱바의 [초기화] 텍스트 버튼(글자가 작아도 히트 영역을 넓힌다), 연차 칩(높이 고정), 직군 시트의 행, 뒤로가기 아이콘.
- **모든 입력에 라벨을 프로그래밍적으로 연결한다.** 시각 라벨(직군·직무·연차)이 placeholder로 대체되면 값을 넣는 순간 라벨이 사라진다 — placeholder는 라벨이 아니다.
  - 직군 필드는 `role=button` + "직군, 기획·PM, 선택 목록 열기"(값이 없으면 "직군, 선택 안 됨, 선택 목록 열기") 형태로 현재 값과 동작을 함께 읽힌다.
  - 연차 칩 그룹은 단일 선택 그룹으로 노출하고 각 칩에 선택 상태(`aria-checked` 상당)를 붙인다. **재탭 해제가 있으므로 해제 시에도 상태 변화가 낭독되어야 한다.**
- **[초기화]는 "초기화"만 읽히면 무엇이 초기화되는지 알 수 없다.** 라벨 "입력 초기화" + 힌트 "직군, 직무, 연차를 모두 비워요" 형태로 낭독한다. 비활성일 때는 비활성 상태가 함께 읽히게 한다 — 이유는 화면 구조(모든 필드 비어 있음)로 전달된다.
- **[초기화] 실행 결과를 낭독한다.** 시각적으로는 세 필드가 동시에 비지만 스크린리더에는 아무 일도 일어나지 않은 것과 같다 — `aria-live="polite"`로 "모든 입력을 비웠어요"를 한 번 알린다.
- 직군 시트·이탈 팝업은 **포커스를 가두고, 닫으면 열기 전 요소로 포커스를 되돌린다.** 이탈 팝업은 열릴 때 제목을 먼저 읽힌 뒤 [계속 편집]에 포커스를 둔다 — 파괴적 쪽([나가기])을 기본 포커스로 두지 않는다.
- **직군 시트의 선택 표시는 색 + 체크 아이콘이다.** 색만으로 구분하지 않는다. 연차 칩의 선택도 색 변화 + 형태(눌림 상태)를 함께 쓴다.
- 저장 실패 인라인 에러는 `aria-live="assertive"` — 사용자가 시작한 저장의 직접 결과다. 저장 성공 토스트는 `polite`로 충분하다 — 화면 전환(복귀)이 이미 결과를 말하고 있다.
- **동적 텍스트 최대 200%에서 잘리지 않아야 한다.** 위험한 곳은 셋이다 — **앱바**(타이틀과 [초기화]가 폭을 다툰다 — 타이틀을 줄이고 버튼을 우선한다), **연차 칩 한 줄**(넘치면 줄바꿈으로 두 줄 허용, 가로 스크롤·폰트 축소 금지), **이탈 팝업 버튼 줄**([계속 편집]/[나가기]를 세로로 쌓는다).
- 직무 입력은 표준 텍스트 필드 동작(OS 편집·붙여넣기·음성 입력)을 막지 않는다. 100자 상한은 입력 차단으로만 적용한다.

## 8. 금지 사항

`career.md`가 명시적으로 금지했거나 규칙에서 곧장 따라 나오는 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

**입력·초기화**

- 세 필드에 **필수 표시·미입력 에러**를 두는 것
- 미입력 사용자에게 **입력을 재촉하는 배너·팝업·재진입 유도**를 만드는 것 (유도는 안내 한 줄이 전부다)
- **직군 목록을 클라이언트 상수로** 두는 것 — 서버 제공, 온보딩과 공용 목록이다(확정 2026-08-10)
- 직군 시트에서 **[선택 안 함]을 빼는 것** — 비우는 경로 없이는 빈 값 저장이 성립하지 않는다
- 연차 칩의 **재탭 해제를 막는 것**
- [초기화]에 **확인 팝업을 붙이는 것** — 즉시 실행이 확정 규칙이다
- [초기화]를 **하단 독의 [저장] 옆으로** 옮기는 것 — 오탭 거리가 배치의 이유다
- 초기화 후를 **변경 없음으로 취급**하는 것 — [저장]이 활성돼야 비운 상태를 저장할 수 있다
- 미입력 상태에서 [초기화]를 **활성으로 두는 것** — 아무 일도 안 하는 버튼이 된다

**저장·이탈**

- [저장]에 **확인 팝업을 붙이는 것** — 잃는 것이 없어 확인할 내용이 없다(`career.md` 4.2)
- 필드 편집 즉시 **자동 저장**하는 것 — 반영은 [저장]에서 일괄이다
- 저장 실패 시 **편집 값을 폐기**하는 것
- 저장 요청을 **오프라인 큐에 넣는 것** — 즉시 실패 + [다시 시도]다
- 변경 없음 상태에서 **이탈 팝업을 띄우는 것**
- 제스처(엣지 스와이프)만 **이탈 팝업을 우회**하게 두는 것
- 저장 성공 후 **완료 화면·확인 단계**를 추가하는 것 — 토스트 + 복귀다
- 복귀 화면의 요약을 **클라이언트가 로컬 값으로 조립**하는 것 — 재조회로 갱신한다

**화면 구성**

- 관심 주제 편집 UI를 **이 화면에 합치는 것** — 별도 화면 분리가 합의 사항이다(2026-08-06)
- 화면에 **"드립"·"보조 신호" 등 내부 용어**를 노출하는 것
- 동적 텍스트 확대 시 **폰트를 도로 줄이는 것**

## 9. 미결 사항

- **직군 목록의 조회 시점과 실패 표현** — 화면 진입 시 폼 값과 함께 받아둘지, 시트를 열 때 조회할지 정해지지 않았다. `career-api.md` 작성 시(백엔드 협의 — 온보딩 공용 목록 계약) 함께 확정한다.
  - (a) 진입 시 동시 조회 — 시트가 항상 즉시 뜨지만 진입 조회가 두 요청에 걸려 실패 지점이 늘어난다
  - (b) 시트 오픈 시 조회 — 진입이 가볍지만 시트 안 로딩·실패 상태(인라인 에러 + [다시 시도])가 필요하다
  - 어느 쪽이든 **실패가 폼 편집 자체를 막지 않아야 한다** — 직무·연차는 목록 없이도 편집 가능하다.
- **직무 입력의 글자 수 카운터** — 이 문서는 상한 입력 차단 + 카운터 없음으로 정했다. 카운터를 두기로 하면 **온보딩 O4와 함께** 바꿔야 한다 — 같은 필드가 한 화면에만 카운터를 가지면 상한이 다르게 읽힌다.
- **직무의 공백 처리** — 공백만 입력한 값을 빈 값으로 취급(트림)할지, 판정 주체(클라이언트 표시 vs 서버 정규화)를 `career-api.md` 작성 시 정한다. 트림하지 않으면 "공백 하나"가 프로필 요약에 입력됨으로 표시되는 값이 된다.
- **연차 표기의 하이픈** — 이 문서와 와이어프레임은 "0–1년" 표기를 쓴다. enum 값(0-1)과 화면 표기(0–1년)의 대응은 이 문서 기준이되, 요약을 그리는 프로필 카드(`profile-uiux.md` 4.5 — "4-6년" 표기)와 문자 단위까지 맞출지 확인이 필요하다.
- **다크 모드 대응 범위** — 와이어프레임은 단일 테마 기준이다.
