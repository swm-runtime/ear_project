# 관심사 관리 UI/UX 명세서

> 기준 문서: [`docs/features/interest-management.md`](../../features/interest-management.md) (2026-08-10 개정 반영) · 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/interest-management.html`](../../wireframe/interest-management.html) (화면 ID IM1–IM9 · 검증 항목 V1–V7 전부 해소)
> API: `interest-management-api.md` (작성 전 — 확정 전에는 `interest-management.md` 4.4·6장 + `backend/domain.md`로 추정하되 확정 계약으로 취급하지 않는다)

## 1. 범위

온보딩에서 고른 관심 주제를 언제든 바꾸는 일괄 편집 화면 — 주제 버블밭, "N/3 선택" 표기, 하단 요약 바, 해제 포함 저장의 확인 팝업, 0개 상태의 저장 게이트, 상한 초과 보유자 처리, 이탈 확인, 저장·조회 실패까지 `interest-management.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 상한(최소 1·최대 3)·저장 분기·변경 반영 규칙은 `interest-management.md`가 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 사용자 조작에 어떻게 반응하는가**다.

- **화면의 상한 처리는 안내이지 검증이 아니다.** 저장 게이트를 잠가도 상한 판정은 서버가 저장 시점에 다시 한다(`interest-management.md` 3장). 화면 제한을 방어선으로 삼지 않는다.
- 주제 목록·순서·헤드라인 문구는 **온보딩 1단계(O1–O3)와 같다**(`onboarding-uiux.md` 4.1). **표현은 갈라졌다**(개편 2026-10-09 — `changes/interest-management-bubbles`): 이 화면은 **원형 사진 버블**(4.1)이고 온보딩 O1은 사진 알약 그대로다. 온보딩 전환은 PM 결정 대기("D로 가는데 온보딩은 아직 바꾸지 말고 설정 관심 주제 관리만"). 동작의 차이는 하나 — 온보딩은 [다음]으로 전진하고, 여기는 **변경이 있을 때만 [저장]이 활성**된다.
- **상한 처리는 온보딩과 같다**(개정 2026-10-10 — `changes/interest-management-cap-block`. 종전 2026-08-11 "선택은 제한하지 않고 저장만 막는다" 폐기): 상한을 채우면 **새 선택은 막고 상한 토스트**를 띄운다(4.2). 이미 고른 주제의 해제는 언제나 된다. 상한을 이미 넘겨 보유한 사람(IM6)은 해제만 할 수 있고, 저장 게이트 max(3, 기존 보유)와 하단 상한 문구는 그 경우를 위해 남는다(4.5).
- 편집은 일괄(batch)이다. 화면에서 켜고 끈 것은 로컬 상태일 뿐이고, [저장]을 눌러야 서버로 간다. **자동 확장 토글은 이 화면에 두지 않는다 — 설정 화면이 소유한다**(KAN-181, 결정 2026-10-14 — 버블밭이라 토글 자리가 애매하다. 즉시 저장 계약은 `settings-api.md` 4.2). 이 화면은 자동 확장으로 들어온 주제를 **빗금으로 구분**하고 `N/3` 집계·저장 게이트에서 뺀다(4.8).

## 3. 화면 흐름

```
프로필 [관심 주제 관리] 카드 ─┐
설정 > 콘텐츠 > 관심 주제 관리 ─┼─> IM9 로딩 ─┬─ 성공 ─┬─ 1~3개 보유 ──> IM1 (변경 없음)
드립 안내 배너 [관심 주제 추가하기] ─┘          │         └─ 4개 이상 보유 ─> IM6 (초과 보유자)
                                                └─ 실패 ──> IM9 조회 실패 ─[다시 시도]─> 재조회

IM1 ─[버블 편집]─> IM3 변경 있음 ─┬─[3/3 에서 새 버블 탭]─> IM2 (선택되지 않음 + 상한 토스트 · 남은 버블 흐림)
                                   │                    └─[해제로 3개 미만]─> 흐림 해제·다시 고를 수 있음
                                   ├─[전부 해제]──> IM5 (0/3 · [저장] 비활성 + 사유 문구)
                                   ├─[해제 후 같은 버블 재선택]─> 변경 없음으로 복귀 (IM1)
                                 └─[뒤로가기]───> IM7 팝업 ─┬─[계속 편집]·딤 탭─> 화면 유지
                                                             └─[나가기]─────────> 이전 화면 (편집 폐기)
IM1 ─[뒤로가기 · 변경 없음]─> 팝업 없이 이전 화면

IM3 ─[저장]─┬─ 추가만 있음 ──────────────> 저장 (팝업 없음)
             └─ 해제 포함 ──> IM4 확인 팝업 ─┬─[변경하기]─> 저장
                                              └─[취소]·딤 탭─> 편집 화면 유지 (저장 안 함)
저장 ─┬─ 성공 ─> 토스트 "관심사가 변경되었어요" ─> 이전 화면 복귀
       └─ 실패 ─> IM8 인라인 에러 + [다시 시도] (편집 상태 유지)
```

**진입 경로는 셋이지만 화면은 하나다.** 어느 경로로 들어와도 같은 화면·같은 규칙이고, 저장 성공·[나가기]의 복귀 지점은 **들어온 경로의 화면**이다.

- 경로마다 화면을 나누면 같은 편집 규칙이 세 벌이 되고, 드립 배너로 들어온 사용자만 다른 동작을 만나게 된다.

**확인 팝업(IM4)과 이탈 팝업(IM7)은 겹쳐 쌓이지 않는다.** IM4는 [저장]에서만, IM7은 뒤로가기에서만 뜬다 — 이탈 팝업에 [저장] 버튼을 두지 않은 이유가 이것이다(와이어프레임 V7 · 결정 2026-08-10).

## 4. 화면별 명세

### 4.1 IM1 정상 — 화면 골격

**구성** — 앱바(뒤로가기 + 타이틀 **"관심 주제 관리"**) / 헤드라인 **"어떤 이야기가 궁금하세요?"**(28pt) / 개수 표기 **"N/3 선택"** 한 줄 / **주제 버블밭** / 하단 고정 독(dock)의 **요약 바**([저장] 포함)

(개편 2026-10-09 — `changes/interest-management-bubbles`. PM 스샷에서 "3/3 선택"인데 어느 주제가 선택됐는지 보이지 않았다 — 종전 사진 알약은 선택 시 막 농도만 34% → 62%로 바뀌어 원래 어두운 사진은 선택 여부가 구분되지 않았다(`design.md` "색만으로 상태를 구분하지 않는다" 위반). 6안 중 D안 — 버블로 결정.)

- **헤드라인은 온보딩 1단계와 같은 문구다**(와이어프레임 V2 제안 → 이 문서에서 확정 2026-08-10). 목록·상한이 온보딩과 같은 규칙이므로 문구가 다르면 같은 화면 문법이 두 이름을 갖게 된다. 크기만 28pt다.
- **주제 = 원형 사진 버블, UI 스레드 물리**(Reanimated, `services/bubble-physics.ts` · 컴포넌트 `InterestBubble`(얼굴) · `InterestBubbleField`(물리)).
  - 버블마다 **주제 순서대로 정한 자기 자리**(벌집, 읽는 순서)로 끌리는 용수철 + 원끼리 빈틈 6pt 충돌(큰 원이 덜 밀림) + 감속. 처음엔 밭 바깥(자기 자리 방향)에서 날아들어 와 모인다. **순서가 바뀌지 않는다**(PM 2026-10-10 — 중앙 중력 판은 자리가 섞였다).
  - 지름은 밭 넓이의 **58%** 를 덮게 주제 수로 정하고(PM 2026-10-11 "원형 조금만 키우자" — 종전 50%) **±20% 로 섞는다**(종전 ±5%).
  - 선택·상한으로 크기가 바뀌면 **그 크기 기준으로 자리를 다시 잡아** 옹기종기 붙는다(PM 2026-10-10 "나머지 원이 축소될 때 간격이 너무 커 보인다" — 줄 구성은 처음 것 그대로, 자리 격자는 평균보다 12% 조여 서로 눌린 채 자리 잡는다).
  - **끌기 없음 · 스크롤 없음.** 떠다니는 모션도 없다 — 물리가 움직임을 맡는다. 고요해지면 계산을 쉬고, 동작 줄이기면 끝 상태를 바로 그린다.
- **선택 표시는 형태로** — 고르면 **1.2배로 커지며** 이웃을 밀었다가 이웃은 제자리로 돌아오고, **그림자가 깊어진다.** 색만으로 구분하지 않는다. (처음엔 흰·검정 이중 링 + 체크 배지도 있었으나 PM 이 뺐다 — 2026-10-09 22:55.)
- **상한까지 고르면** 남은 버블이 **0.88배로 작아지며 흐려진다**(위에 흰 막 62% · 그림자 없음 — 반투명으로 흐리면 밑 그림자가 비쳐 Android 에서 육각형이 보였다, 2026-10-10). **눌러도 고르지 않고 상한 토스트가 뜬다**(4.2 — 개정 2026-10-10. 처음엔 08-11 규칙대로 탭을 받았다).
- **헤더는 `N/3 선택` 한 줄만** — "변경 사항 N개" 배지와 진행 막대는 PM 이 뺐다(2026-10-10 00:57).
- **하단 독은 요약 바다** — 고른 주제 사진 겹침(최대 3, 0개면 점선 없이 빈자리 — 2026-10-10 00:56) · 이름 `A · B · C` · [저장](종전 문구·게이트·IM8 [다시 시도] 그대로). 상한 초과 사유 문구(IM6)는 바 위에 종전대로. **0개 사유("관심 주제를 1개 이상 선택해주세요")는 바 안 [저장] 바로 왼쪽**에 이름 자리를 대신해 보조색으로 보인다(PM 2026-10-09 23:27).
- 주제 목록은 온보딩과 동일하게 `is_visible = true`인 주제만, 같은 `display_order`로 노출한다(FR-03 · FR-38). **관리자가 숨긴 주제는 목록에서 사라지지만 선택 이력은 지워지지 않는다** — 화면은 보이는 것만 그린다.
- **개수 표기는 항상 "N/3 선택" 형태다.** 선택 직후부터 노출해 상한에 부딪히기 전에 남은 자리를 알린다(온보딩 4.1과 같은 이유 — 4개째에 처음 알리면 안내가 아니라 제약으로 읽힌다).
- **[저장]은 변경 사항이 있을 때만 활성이다.** 진입 직후·해제 후 같은 버블을 재선택해 원상태로 돌아온 경우 모두 비활성이다.
  - 변경이 없는데 [저장]이 활성이면 눌러도 아무 일도 없는 버튼이 되거나, 무의미한 저장 요청이 나간다. 비활성 자체가 "바꾼 것이 없다"는 상태 표시다.
- **[저장]은 하단 고정 독(요약 바)에 둔다.** 버블밭은 스크롤이 없지만, 저장 버튼은 밭과 분리된 고정 자리에 있어야 물리로 움직이는 버블에 묻히지 않는다.
- **선택 상태는 로컬에만 둔다.** 버블 탭마다 서버를 부르지 않고, [저장] 시점에 **델타가 아니라 최종 목록 전체**를 한 번 보낸다(`interest-management.md` 4.4 — 멱등, 다중 기기 last-write-wins).
- 이 화면에는 탭바를 그리지 않는다. 프로필·설정·라이브러리에서 푸시된 하위 화면이다.

### 4.2 IM2 상한 도달 — 새 선택 차단 + 토스트 (개정 2026-10-10)

| 상태 | 표시 |
|---|---|
| 3개를 채움 | **"3/3 선택"** + 남은 버블 0.88배 흐림(4.1). 새 버블을 누르면 **선택하지 않고** 토스트 **"관심 주제는 3개까지 선택할 수 있어요"**(`INTEREST_COPY.limitNotice` — 온보딩 상한 토스트와 같은 문자열) |
| 해제로 3개 미만 | 흐림 해제 — 다시 고를 수 있다 |
| 초과 보유자(IM6)의 3개 초과 | **"N/3 선택"**(예: "5/3 선택" — 클램프 없음) + [저장] 비활성 + 바 위에 사유 문구 **"관심 주제는 3개까지 선택할 수 있어요"** 상시 노출(저장 게이트 — 4.5) |

- **상한을 채우면 새 선택은 막고 토스트를 띄운다 — 온보딩 1단계와 같은 동작이다**(PM 2026-10-10 01:08 "관심 주제 3개 이상 선택하면 toast 띄우고 선택 안 되게 하자" — `changes/interest-management-cap-block`). 버블 개편 뒤 상한을 채우면 남은 버블이 흐려지는데, 흐린 버블이 눌려서 4개째가 골라지는 것이 어긋나 보였다. 종전 규칙(2026-08-11 — 관리 화면은 상한 뒤에도 탭을 받아 "4/3 선택"처럼 사실대로 보이고 저장만 막는다)은 폐기했다.
- **이미 고른 주제의 해제는 언제나 된다.** 위치: `useInterestManagementScreen` `toggleTopic`.
- **상한을 이미 넘겨 보유한 사람(IM6)은 해제만 할 수 있다.** 저장 게이트(`isOverLimit` — 판정식은 서버와 같은 **max(3, 저장 전 보유 개수)**, `interest-management.md` 4.2)와 바 위의 상한 사유 문구는 그 경우를 위해 남는다 — 초과 보유자의 해제·재저장(5→4)을 게이트가 막지 않는다. 사유 문구는 토스트로 대체하지 않는다 — 사라지는 안내로는 [저장]이 왜 눌리지 않는지 화면에 남는 단서가 없다(IM5의 0개 사유와 같은 이유).
- 클라이언트의 차단·게이트는 안내다. 우회해 4개를 보내면 서버가 저장을 거부한다(`interest-management.md` 3장). 서버 검증은 그대로다.

### 4.3 IM3 변경 있음 — 저장 중

**구성** — IM1과 동일 + 요약 바의 [저장] 활성. 요약 바의 사진·이름이 현재 고른 주제를 보여 준다.

- **"변경 사항 N개" 배지와 진행 막대는 없다**(PM 2026-10-10 00:57 — 종전 2026-08-10 확정 위치 폐기). 변경 유무는 [저장] 활성·비활성이 말한다.
- **변경 유무 판정** — 서버에 저장된 현재 목록과 화면의 선택을 비교해, 추가·해제가 하나라도 있으면 변경 있음이다.
  - **해제했다가 같은 편집 안에서 다시 선택하면 변경 없음이다**(`interest-management.md` 7장). 조작 횟수가 아니라 결과의 차이를 본다.
- **변경이 없어지면 [저장]을 비활성으로 되돌린다.**

**저장 중**

- [저장]이 **버튼 로딩** 상태가 되고, 인플라이트 동안 **버블 탭·뒤로가기를 포함한 화면 조작을 차단한다**(`interest-management.md` 5장).
  - 저장 중에 버블을 바꾸면 방금 보낸 목록과 화면이 어긋나고, 성공 토스트가 어느 상태에 대한 것인지 알 수 없게 된다.
- 별도 전체 화면 로딩·딤을 두지 않는다. 저장은 요청 한 건이라 버튼 로딩으로 충분하고, 0.3초 미만이면 로딩 표시 자체를 생략한다(`common-error-handling.md` 5장).

### 4.4 IM4 해제 포함 저장 — 변경 확인 팝업

**노출 조건은 `interest-management.md` 4.2가 소유한다** — 해제가 포함된 저장에만 뜬다. 추가만 있으면 팝업 없이 바로 저장된다.

**구성** — 본문 **"선택이 해제된 주제의 새 콘텐츠가 더 이상 라이브러리에 도착하지 않아요. 이미 받은 콘텐츠는 그대로 남아 있어요."** / [취소] · [변경하기]

- **주제명을 명시하지 않는 단일 문구다**(확정 2026-08-10 — 와이어프레임 V4, 나열 제안 기각). 해제 개수(1개·복수)와 무관하게 같은 문구를 쓴다. 별도 제목 없이 본문만 두는 한 문단 팝업이다.
- **저장당 1회다.** 해제 항목 수만큼 반복하지 않는다 — 편집이 일괄(전체 목록 전송)이라 확인 단위도 저장 단위와 같다. 항목별로 띄우면 중간 [취소]의 의미(부분 적용?)가 성립하지 않는다.
- 버튼은 [취소] 좌, [변경하기] 우이며 [변경하기]가 주 액션 스타일이다.
- **[취소]·딤 탭은 저장하지 않고 편집 화면으로 돌아간다.** 편집 상태는 그대로 유지된다 — 저장이 일어나지 않았을 뿐 사용자가 고른 것을 버리지 않는다.
- **문구에 잃는 것과 남는 것을 함께 담는다.** "신규 도착 중단"만 말하면 이미 받은 것도 사라지는 줄 알고 해제를 겁내게 된다. 이 두 문장이 이 기능의 핵심 규칙(FR-05) 그 자체이므로 요약·의역하지 않고 그대로 쓴다.
- [변경하기] → 저장 → 성공 시 토스트 **"관심사가 변경되었어요"** → 이전 화면(진입 경로) 복귀. 오늘 이미 편성 확정된 콘텐츠가 그대로 적립되는 것은 별도로 안내하지 않는다(`interest-management.md` 7장 — 자연스러운 지연으로 보인다).

### 4.5 IM5 전부 해제 — 0개 상태 · IM6 상한 초과 보유자

**IM5 — 0개 상태**

**구성** — **"0/3 선택"** / 전 버블 미선택 / 요약 바 — 사진 자리는 빈자리(점선 없음), 이름 자리에 보조색 사유 문구 **"관심 주제를 1개 이상 선택해주세요"**([저장] 바로 왼쪽 — PM 2026-10-09 23:27) + [저장] 비활성

- **마지막 1개도 해제할 수 있다 — 편집 중 0개 상태를 허용한다**(개정 2026-08-09). 현재 선택을 전부 갈아엎고 새로 고르는 동선을 막지 않기 위해서다. **막는 것은 탭이 아니라 저장이다.**
- 사유 문구는 **요약 바 안 [저장] 바로 왼쪽에 상시 노출한다.** 토스트로 대체하지 않는다 — 사라지는 안내로는 [저장]이 왜 눌리지 않는지 화면에 남는 단서가 없다. 온보딩 O1(미선택 시 [다음] 비활성 + 같은 문구)과 같은 패턴·같은 문자열이다.
- 0개 상태에서 뒤로가기를 누르면 변경이 있으므로 IM7 이탈 팝업이 뜬다. [나가기]를 고르면 편집이 폐기되고 서버의 기존 선택이 그대로 남는다.

**IM6 — 상한 초과 보유자(상한 도입 이전 가입자 · 자동 확장으로 초과)**

**구성** — **"N/3 선택"**(예: "5/3 선택") + **선택 개수 옆 경고 아이콘** / 그 아래 해제할 개수 안내 **"관심 주제는 3개까지예요. N개를 해제하면 다시 추가할 수 있어요"**(배경 없는 인라인 안내 — 개정 2026-10-11 `changes/archive/inline-status-notices.md`, 종전 배경 있는 안내 배너. 실제 개수 표기는 그대로) / 보유 버블 전부 선택(확대) 상태, 나머지 버블은 상한 흐림 — **해제만 할 수 있다**(개정 2026-10-10, 4.2)

- **강제로 줄이게 하지 않는다.** 현재 목록을 그대로 노출하고 새 선택은 막되(흐린 버블을 누르면 상한 토스트) **기존 개수보다 늘어나는 저장은 게이트가 막는다**(저장 게이트 max(3, 기존 개수) — 4.2. 게이트에 걸리면 바 위에 사유 문구가 함께 노출된다). 해제·재저장은 자유이며, 3개 이하로 내려간 뒤부터 상한이 정상 적용된다(`interest-management.md` 7장 — 상한은 앞으로의 선택을 제한하는 규칙이지 기존 상태를 되돌리는 규칙이 아니다).
- **경고 아이콘·해제 안내는 기존 보유가 3개를 넘는 사용자에게만 노출한다**(개정 2026-08-11) — 일반 사용자의 일시적 4개 선택에는 게이트 사유 문구만 노출한다(같은 상황에 안내가 두 벌이면 어느 쪽이 판정인지 흐려진다). 안내의 `N`은 **3을 초과한 개수**다(5개 보유 → "2개를 해제하면"). 해제로 3개 이하가 되면 제거한다.
- **개수 표기를 "3/3"으로 거짓 클램프하지 않는다.** "5/3 선택"이 어색해 보여도 사실이 우선이다 — 3/3으로 그리면 해제 안내의 "N개를 해제하면"과 화면 숫자가 어긋난다.
- 초과 상태 그대로의 재저장(해제 없이 다른 변경만 저장)도 서버가 허용하므로("기존 개수보다 늘어나지 않으면 통과"), 화면도 이를 막지 않는다.

### 4.6 IM7 뒤로가기 — 이탈 확인 팝업

**구성** — **"변경 사항을 저장하지 않고 나갈까요?"** / [계속 편집] · [나가기]

- **변경이 있는 상태의 뒤로가기·스와이프 제스처에만 뜬다.** 변경이 없으면 팝업 없이 바로 나간다 — 잃을 것이 없는데 묻는 팝업은 모든 이탈에 세금을 매기는 것이다.
  - **스와이프 제스처는 팝업 대신 비활성화로 처리한다**(구현 제약 기록 2026-08-11). React Navigation native-stack에서는 스와이프 백이 네이티브에서 확정된 뒤에야 JS에 통지돼 `beforeRemove`로 막을 수 없다 — 변경·저장 중에는 `gestureEnabled: false`로 제스처 자체가 동작하지 않고(변경 없으면 정상 dismiss), 팝업은 뒤로가기 버튼·Android 하드웨어 백에서 뜬다. 동작 규칙의 목적("잃을 것이 있는 이탈은 확인 없이 일어나지 않는다")은 유지된다.
- 버튼은 **[계속 편집] / [나가기] 현행 유지다**(확정 2026-08-10 — 와이어프레임 V7, [저장]/[나가기] 안 기각). 이탈 팝업에 [저장]을 두면 해제 포함 편집에서 팝업 위에 확인 팝업(IM4)이 쌓인다.
- [나가기]는 편집을 버리고 이전 화면으로 복귀한다. [계속 편집]·딤 탭은 팝업만 닫고 편집 화면을 유지한다.
- **[나가기]를 위험색으로 강조하지 않는다.** 버려지는 것은 저장 전 로컬 편집뿐이고 서버 상태는 그대로다 — 파괴적 조작처럼 그리면 나가기를 겁내게 된다.

### 4.7 IM8 저장 실패 · IM9 로딩 · 조회 실패

**IM8 — 저장 실패**

- 인라인 에러 **"저장하지 못했어요. 다시 시도해주세요"** + [다시 시도]. **편집 상태를 버리지 않는다**(`interest-management.md` 5장).
  - 전체 화면 에러로 전환하지 않는다 — 실패한 것은 저장 한 건이지 화면이 아니다. 버블 선택·요약 바가 그대로 남아 있어야 [다시 시도]가 같은 내용을 다시 보낼 수 있다.
- **오프라인 저장 시도도 같은 처리다.** 폼 제출은 오프라인 큐 대상이 아니다(`common-error-handling.md` 4.5 — 즉시 실패 + [다시 시도], 편집 상태 유지).
- 해제 포함 편집이라면 [다시 시도] 성공 경로에서 **확인 팝업(IM4)을 다시 띄우지 않는다.** 사용자는 이미 [변경하기]로 확인을 마쳤다 — 실패 후 재시도는 같은 저장의 반복이지 새 저장이 아니다.
- [다시 시도] 연타는 인플라이트 요청이 있으면 무시한다(`common-error-handling.md` 7장).

**IM9 — 로딩 · 조회 실패**

- 로딩은 **같은 벌집 자리에 회색 원 8개**다(개수 표기 자리 포함). 칩 모양 스켈레톤은 버블 개편(2026-10-09)으로 바뀌었다. 스피너를 중앙에 띄우지 않는다. 앱바 타이틀·헤드라인은 서버 응답과 무관하므로 먼저 그린다. **0.3초 미만이면 표시하지 않는다**(`common-error-handling.md` 5장).
- 조회 실패는 에러 안내 **"주제 목록을 불러올 수 없어요"** + [다시 시도]다.
- **로딩·실패 중 [저장]은 비활성이다.** 현재 선택을 모르는 상태에서는 저장이 성립하지 않는다.
- **목록이 빈 배열로 오면 IM9를 그린다**(확정 2026-09-09 — `interest-management.md` 7). 응답은 200이지만 할 수 있는 일이 [다시 시도] 하나로 같다.
  - 문구(확정 2026-09-09): **"아직 준비 중이에요"** + "주제를 준비하고 있어요.\n잠시 후 다시 시도해주세요"
  - **온보딩 1단계와 문자열까지 동일하다.** 헤드라인·상한 문구와 같은 규칙이다(6장 — 변형 금지).
  - 기존 조회 실패 문구("주제 목록을 불러올 수 없어요")를 재사용하지 않는다 — 불러오기는 성공했다.
  - **[다시 시도]는 0건일 때도 실제로 재조회를 보낸다** — 0건은 성공 상태라, 실패 여부만 보고 재조회를 걸면 버튼이 눌려도 아무 요청이 나가지 않는다.

### 4.8 자동 확장으로 들어온 주제의 표시 (KAN-181)

행동 기반 자동 확장이 구현돼(2026-09-30, `drip-scheduling.md` 4.5-1) 운영이 켜지면, `GET /users/me/interests`의 응답에 `source = auto_expand`인 주제가 섞여 온다. 이 화면은 그것을 **직접 고른 주제와 구분해 보여주되, 상한·게이트에는 세지 않는다**.

- **구분 표현 — 빗금 오버레이.** 자동 슬롯 주제의 버블 사진 위에 애플식 대각선 빗금("창문 블라인드")을 한 겹 덮는다(결정 2026-10-14). 선택 버블의 링·체크 배지를 쓰지 않는 것과 같은 결이다(§5 — 빗금 한 겹). 낭독기에는 이름 뒤에 "자동 추가됨"을 붙인다(7장).
- **`N/3`·저장 게이트에서 뺀다.** N은 `source != auto_expand`인 선택만 센다(`interest-management-api.md` 4.1). 자동 슬롯이 붙은 사용자에게 아무 조작 없이 "4/3"이 보이거나 저장이 막히지 않게 — 직접 고른 상한(3)과 자동 슬롯(1개)은 따로 센다(`interest-management.md` 4.3). 탭 상한(3개까지만 더 고를 수 있음)도 직접 고른 개수로만 판정한다.
- **해제는 일반 저장의 해제분이다.** 자동 슬롯 버블을 눌러 해제하면 빗금이 사라지고(미선택), [저장] 시 해제로 집계돼 확인 팝업(IM4)이 뜬다. 저장하면 `is_user_removed = true`가 서며 같은 주제가 다시 자동 추가되지 않는다(`interest-management.md` 4.3).
- **토글은 이 화면에 없다 — 설정 화면이 소유한다**(KAN-181). "관심 주제와 가까운 주제도 자동으로 찾아드려요" 설명과 함께 설정 콘텐츠 섹션에 즉시 저장 토글로 둔다(`settings.md` 4.1 · `settings-api.md` 4.2).

- **모든 제출 버튼은 인플라이트 동안 비활성화한다.** 저장은 상태를 바꾸는 요청이라 중복 실행이 실제 부작용을 만든다.
- **저장 성공 토스트는 화면 복귀와 함께 띄운다.** 이전 화면 위에 얹혀도 3초 뒤 사라지는 통지이므로 복귀를 지연시키지 않는다.

## 7. 접근성

- **터치 타깃 최소 44×44pt.** 주제 버블은 원형이라 지름이 곧 터치 타깃이다 — 상한 흐림(0.88배)에서도 이 값을 밑돌지 않아야 한다.
- **주제 버블은 `checkbox` + `checked`로 노출한다.** 선택 상태가 형태(확대·그림자)와 함께 낭독으로도 전달돼야 한다. 상한 흐림 버블에도 `disabled`는 선언하지 않는다(아래).
- **"N/3 선택"은 화면 문자열 그대로 읽히면 안 된다.** "이 슬래시 삼"으로 읽힌다 — 라벨을 **"3개 중 N개 선택"** 형태로 따로 붙인다.
- **개수 표기는 라이브 리전(`aria-live="polite"`)이다** — 낭독은 **"3개 중 N개 선택"만**이다(변경 배지 제거, 2026-10-10). 값이 실제로 바뀔 때만 알린다.
- **선택 버블에 체크 배지·링을 쓰지 않는다**(PM 2026-10-09 22:55 — 처음엔 흰·검정 이중 링 + 체크 배지가 있었다). 선택은 **형태(1.2배 확대 + 깊은 그림자)**로 표시하고 색만으로 구분하지 않으며, 낭독기에는 `checkbox` + `checked`로 전달한다.
- **상한 흐림 버블에 `disabled`를 선언하지 않는다.** 낭독기가 "사용 안 함"으로 읽으면 사용자가 누르지 않아 상한 토스트를 못 듣는다. 이유는 `accessibilityHint`로 미리 알린다.
- **[저장] 비활성의 이유를 화면 텍스트로 밝힌다.** 0개 상태·초과 보유자의 3개 초과 상태는 사유 문구가 상시 노출되므로 충족된다(사유 문구는 `aria-live="polite"`로 등장·소멸을 알린다). 변경 없음 상태의 비활성은 "바꾼 것이 없다"는 상태 그 자체이므로 별도 문구를 두지 않는다.
- **다이얼로그(IM4·IM7)는 포커스를 가두고, 닫으면 열기 전 요소로 포커스를 되돌린다.** 열릴 때 본문을 먼저 읽힌 뒤 주 액션이 아니라 **안전한 쪽([취소]·[계속 편집])에 초기 포커스를 둔다** — 해제 확정과 편집 폐기는 실수로 눌렀을 때 비용이 큰 쪽이다.
- **토스트는 `aria-live="polite"`.** 저장 성공 토스트는 화면 복귀 직후 읽히게 한다.
- 초과 보유자 해제 안내(경고 아이콘 + 문구)는 진입 시 한 번 polite로 읽히게 하고, 매 조작마다 반복하지 않는다.
- **동적 텍스트 최대 200%에서 잘리지 않아야 한다.** 요약 바는 사유 문구·버튼의 세로 확장으로, 팝업 버튼 줄은 세로 쌓기로 대응한다. 고정 높이를 쓰지 않는다.

## 8. 금지 사항

`interest-management.md`가 명시적으로 금지했거나 검토(2026-08-09·10·11)에서 기각된 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

**선택·상한**

- **상한을 채운 뒤 새 버블 탭을 그대로 선택되게 두는 것**("4/3 선택") — 새 선택은 막고 상한 토스트를 띄운다(개정 2026-10-10 — 종전 2026-08-11 "저장만 막는다" 폐기). 상한 흐림 버블에 `disabled`를 선언하는 것도 금지다(7장)
- **이미 고른 버블의 해제를 탭 시점에 막는 것** — 마지막 1개도, 초과 보유자(IM6)의 것도 해제는 언제나 된다. 0개 상태를 금지 상태로 그리지 않는다(개정 2026-08-09)
- 초과 보유자(IM6)의 3개 초과 상태의 [저장]을 **활성으로 두는 것**, 그 상한 사유 문구를 **토스트로 대체**하는 것 — 0개 상태와 같은 규칙이다
- 버블을 **끌 수 있게** 하거나 밭을 **스크롤 영역**으로 만드는 것, 선택을 **링·체크 배지·색**으로 표시하는 것, **"변경 사항 N개" 배지·진행 막대**를 되살리는 것(2026-10-10)
- 클라이언트 저장 게이트를 **상한 검증으로 취급**하는 것(서버 재검증 생략)
- 저장 게이트에 **상수 3을 쓰는 것** — 판정식은 서버와 같은 max(3, 기존 보유 개수)다. 초과 보유자의 해제·재저장이 막힌다
- 초과 보유자에게 **강제 축소를 요구**하는 것("N개를 지워야 저장할 수 있습니다")
- 초과 보유자의 개수 표기를 **"3/3"으로 클램프**하는 것

**저장·팝업**

- 버블 탭마다 **즉시 저장**하는 것 — 편집은 일괄이고 반영 단위는 [저장]이다
- 추가만 있는 저장에 **확인 팝업을 띄우는 것**
- 확인 팝업을 **해제 항목마다 반복**하거나 **주제명을 나열**하는 것 — 저장당 1회·단일 문구 확정(2026-08-10)
- 0개 상태의 [저장]을 **활성으로 두는 것**, 사유 문구를 **토스트로 대체**하는 것
- 해제 후 같은 버블 재선택을 **변경으로 세는 것** — 변경 없음이다
- 이탈 팝업에 **[저장] 버튼을 두는 것** — 팝업 위에 확인 팝업이 쌓인다([계속 편집]/[나가기] 확정 2026-08-10)
- 변경이 없는데 **이탈 팝업을 띄우는 것**
- 저장 실패 시 **편집 상태를 폐기**하는 것, 저장 요청을 **오프라인 큐에 적재**하는 것
- 실패 후 [다시 시도] 성공 경로에서 **확인 팝업을 다시 띄우는 것**

**화면·카피**

- 이 화면에 **자동 확장 토글**을 두는 것 — 토글은 설정 화면이 소유한다(KAN-181, 2026-10-14)
- 자동 추가 주제(`source = auto_expand`)를 **`N/3`에 넣어 세거나 저장 게이트에 넣는 것** — 빗금으로 구분하고 집계에서 뺀다(4.8)
- 이 화면에 **커리어 입력을 되살리는 것** — 별도 화면이다(합의 2026-08-06)
- 온보딩과 공유하는 문구(헤드라인·상한 문구·0개 사유)를 **다른 문자열로 변형**하는 것
- 확인 팝업·안내에 **"드립"·"적립" 등 내부 용어**를 쓰는 것
- 해제 확인 팝업에 **경고 톤·데이터 삭제 뉘앙스**를 얹는 것 — 받은 콘텐츠는 남는다는 것이 핵심 규칙이다
- [나가기]를 **위험색으로** 그리는 것
- 색만으로 **선택 상태를 구분**하는 것

## 9. 미결 사항

- **조회 실패 문구의 온보딩과의 통일** — 이 문서는 와이어프레임 IM9의 "주제 목록을 불러올 수 없어요"를 썼고, 온보딩 O6은 "주제를 불러오지 못했어요"다. 같은 실패(주제 목록 조회)에 두 문구가 존재한다. 선택지: (a) 이 화면을 온보딩 문구로 맞춘다 (b) 각자 유지한다(화면 맥락이 달라 사용자가 비교할 일은 없다). 통일한다면 어느 쪽 문자열로 할지 결정 필요.
- ~~저장 성공 토스트의 표기 계열~~ → **해소(2026-08-10): 현행 유지.** 저장 성공 토스트는 **"관심사가 변경되었어요"** 로 확정한다(features 4.4 확정 문구 그대로). 화면의 다른 문구("관심 주제" 계열)도 그대로다 — 혼용을 수용한다.
- **저장 중 조작 차단의 시각 표현** — features는 "화면 조작 차단"만 규정한다. 이 문서는 버튼 로딩 + 조작 무시(별도 딤 없음)로 풀었는데, 차단을 시각적으로 보여줄지(칩 흐림 등)는 시안 검증에서 정한다.
- ~~**P1 자동 확장 도입 시 화면 확정**~~ → **해소(2026-10-14, KAN-181).** 자동 추가 주제는 버블 빗금으로 구분하고 `N/3`·게이트에서 뺀다(4.8), 토글은 설정 화면이 소유한다. 상한 3개와의 관계는 자동 슬롯 1개를 따로 세는 것으로 정리됐다(`interest-management.md` 4.3). **남은 것:** 빗금의 다크 모드 대비·동적 글자 확대에서의 가독성은 시안 검증에서 확인한다.
- **다크 모드 대응 범위** — 와이어프레임은 단일 테마 기준이다. 상한 흐림 버블(흰 막 62%)과 선택 그림자의 대비를 다크 모드에서 다시 확인해야 한다.
- **온보딩 O1의 버블 전환** — 이 화면은 버블(2026-10-09), 온보딩 1단계는 사진 알약 그대로여서 같은 주제 목록이 두 화면 문법으로 갈라졌다. 온보딩도 바꿀지는 PM 결정 대기("온보딩은 아직 바꾸지 말고 설정 관심 주제 관리만").
