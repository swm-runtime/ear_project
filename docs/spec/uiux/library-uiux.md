# 라이브러리 UI/UX 명세서

> 기준 문서: [`docs/features/library.md`](../../features/library.md) · 재생 판정·확인 팝업은 [`docs/features/paywall.md`](../../features/paywall.md), 로딩·오류 표현은 [`docs/features/common-error-handling.md`](../../features/common-error-handling.md)
> 와이어프레임: [`docs/wireframe/library.html`](../../wireframe/library.html) (화면 ID L1–L11)
> API: [`library-api.md`](../api/library-api.md)

## 1. 범위

앱의 첫 화면인 라이브러리 — 통합 목록, 상단 탭 3개(상태)와 출처·주제 필터, 앱바의 잔여 재생 표시, 미니플레이어 복원, 재생 확인 팝업, 삭제와 실행 취소, 빈 상태 4종과 오류 상태까지 `library.md` 5장 화면 상태 표를 화면 단위로 풀어낸 문서다.

**이 문서는 동작 규칙을 새로 정하지 않는다.** 목록 구성·상태 전이·삭제 규칙은 `library.md`가, **재생 한도 판정과 재생 확인 팝업·[오늘은 그만 보기] 억제 규칙은 `paywall.md`가**, 통신 계약은 `library-api.md`가 소유한다. 여기서 정하는 것은 **무엇을 어떤 상태로 보여주고, 사용자 조작에 어떻게 반응하는가**다.

- **판정과 표시를 섞지 않는다.** 앱바의 잔여 횟수도, 확인 팝업에 적힌 남은 횟수도 **서버가 내려준 값을 그리는 힌트**일 뿐이다.
  - 표시된 숫자를 근거로 재생을 통과시키는 순간 한도가 새는 구멍이 된다 — 다른 기기에서 재생한 결과가 이 화면에 반영돼 있지 않을 수 있다(`paywall.md` 4.1).
- 페이월 바텀시트 자체의 구성·문구는 이 문서가 다루지 않는다. 라이브러리는 **그것을 여는 지점**만 소유한다.

- 미니플레이어와 앱바 잔여 표시는 **화면이 아니라 화면에 얹히는 요소**이므로 별도 ID를 두지 않고 4.3·4.4에서 다룬다. 상태별로 ID를 쪼개면 같은 요소의 규칙이 화면 수만큼 복제된다.
- 페이월 바텀시트는 `paywall.md`가 소유하므로 L 번호를 부여하지 않는다. **여기에 ID를 붙이면 두 문서가 같은 시트를 각자 정의하게 된다.**

## 3. 화면 흐름

```
앱 실행 ──> L11 최초 로딩 ─┬─ 목록 있음 ──> L1 정상 (+ 미니플레이어 복원 · 일시정지)
                            ├─ 목록 없음 ──> L6 (신규·드립 준비 중) / L9 (전부 삭제)
                            └─ 조회 실패 ──> L10 (캐시 있음) / L14 (캐시 없음)

L1 ─[탭 전환]─> 전체 · 미청취 · 완료 ─┬─ 결과 있음 ─> L1
                                       └─ 결과 없음 ─> L7
   ─[필터 아이콘]─> L2 필터 시트(출처·주제) ─┬─[적용]─┬─ 결과 있음 ────────> L1(배지)
   │                                         │        ├─ 출처=이어 PICK만 걸고 비었음 > L8
   │                                         │        └─ 그 밖에 결과 없음 ──> L7
   │                                         ├─[초기화]─> 선택만 비움 (시트 유지)
   │                                         └─[딤·뒤로]─> 변경 폐기하고 닫힘
   ─[더보기]─> L4 ─[삭제]─┐
   ─[스와이프 삭제]───────┴─> L5 ─[실행 취소]─> L1 (원래 순서 복구)
   ─[하단 도달]─> L15 추가 로딩 ─ 실패 ─> L15 인라인 에러(기존 목록 유지)
   ─[당겨서 새로고침]─> 재조회 (잔여 표시도 서버 값으로 덮어씀)

L1 카드 탭 / 미니플레이어 재생 ──> 재생 한도 판정 (paywall.md 4.1 — 서버가 판정)
   ├─ 소진 ────────────────> 페이월 바텀시트 (확인 팝업 없음)
   ├─ 차감 있음 · 오늘 억제됨 ─> 플레이어 (팝업 없음 · 차감은 그대로)
   ├─ 차감 있음 · 억제 안 됨 ─> L3 ─┬─[재생하기]─> 재판정 ─┬─ 통과 ─> 플레이어
   │                                 │                       └─ 소진 ─> 페이월
   │                                 ├─[취소]──────────────> L1 (차감 없음)
   │                                 └─[오늘은 그만 보기]──> 플레이어
   │                                       └ 오늘·이 기기의 확인 팝업만 억제
   ├─ 차감 없음(오늘 이미 튼 콘텐츠 · 무제한) ─> 플레이어 (팝업 없음)
   └─ 회수됨(403) ─────────> L13 안내 ─> 목록에서 제거

앱바 잔여 표시 ─┬─ N > 0 ──────────────> 표시만 (탭 불가)
                ├─ N = 0 ──────────────> L12 주의색 ─[탭]─> 페이월 바텀시트
                └─ 무제한 · 캐시 · 값 없음 ─> 표시 없음 (자리를 비운다)
```

**탭·필터·재생 진입점이 갈라져도 판정은 한 갈래다.** 카드에서 시작하든 미니플레이어에서 시작하든 같은 판정과 같은 팝업을 거친다.

- 진입점마다 규칙을 다르게 두면 미니플레이어가 한도를 우회하는 뒷문이 된다(`library.md` 4.2).

**탭·필터는 같은 데이터의 다른 보기일 뿐 별도 보관함이 아니다.** 출처 [이어 PICK]을 건 상태에서 지운 아이템은 필터를 풀어도 사라져 있다.

## 4. 화면별 명세

### 4.1 L1 정상 — 화면 골격

**구성** — 앱바(타이틀 "라이브러리" + 우측 잔여 재생 표시) / 상단 배너(조건부) / 탭 3개 + 필터 아이콘 / 아이템 리스트 / 미니플레이어 / 하단 탭 3개

**아이템 카드(2줄)**: 썸네일(완청 시 좌상단 체크 마킹) · 제목 · 출처·저자·길이 · 진행률 바(`in_progress`만) · 더보기 버튼

- **카드에 3번째 줄을 두지 않는다**(개편 2026-08-07). 출처 배지와 상태 텍스트를 없앴다.
  - `제목 / 출처·저자·길이 / 배지·상태`가 쌓이면 한 카드가 세 줄을 쓰고, 20건짜리 목록에서 화면에 들어오는 카드 수가 줄어 스크롤이 길어진다. 배지와 상태 텍스트는 **모든 카드에 반복되면서 카드끼리 구별해 주지 않는** 정보다.
  - **완청은 썸네일 좌상단 체크 마킹**, 진행 중은 진행률 바만(텍스트 없음), 미청취는 표시 없음이다. 기본 상태가 곧 미청취이므로 따로 그릴 것이 없다.
  - **완청을 회색 제목으로 표현하지 않는다.** 색이 유일한 단서가 되면 7장(색만으로 상태 구분 금지)에 걸린다.
  - 진행률 바에는 퍼센트 텍스트를 붙이지 않되 **접근성 라벨로 "N% 들음"을 제공한다**(7장). 시각적으로 지운 정보를 스크린리더에서까지 지우지 않는다.

- **목록 맨 위에 이어듣기 카드를 두지 않는다.**
  - 히어로 카드가 한 자리를 차지하면 방금 도착한 드립이 화면 밖으로 밀려 내려간다. 이어듣기 진입점은 미니플레이어 하나로 통일돼 있으므로(4.4), 카드를 두면 같은 일을 두 군데서 하게 되고 두 곳의 상태가 어긋날 때 어느 쪽이 맞는지 사용자가 판단하게 된다.
- **드립과 담기를 구획으로 나누지 않는다.** 하나의 리스트에 적립 시각 내림차순으로 섞는다.
  - 섹션을 나누면 "어느 쪽에 있더라"를 사용자가 관리하게 된다. 출처별로 보고 싶은 요구는 **필터 시트의 출처 섹션**이 받는다(4.5).
- **카드 본문 탭은 상세 화면을 거치지 않고 곧장 재생 판정으로 간다.** 더보기 버튼만 별도 히트 영역으로 분리한다.
  - 본문 어디를 눌러도 재생인데 더보기 아이콘 주변만 다르게 동작하므로, 두 영역의 경계를 시각적으로 알 수 없다면 재생하려다 메뉴가 열린다. 더보기는 우측 끝에 고정하고 최소 44×44pt를 확보한다.
- **상단 배너는 한 번에 하나만 노출한다.** 우선순위는 `오프라인 > 드립 준비 중 > 새 콘텐츠 도착`이다.
  - 셋이 동시에 성립할 수 있는데(오프라인 상태에서 앱을 열었고, 드립이 아직 안 왔고, 캐시에는 새 항목 표시가 남아 있는 경우) 배너를 쌓아 올리면 목록이 화면 밖으로 밀린다. 통신이 끊긴 상태에서 "새 콘텐츠가 도착했어요"는 눌러도 아무 일도 일어나지 않으므로 가장 나중이다.
- **"새 콘텐츠 N개 도착" 배너를 눌러도 탭·출처·주제 필터를 초기화하지 않는다.** 목록만 최신으로 갱신한다(`library.md` 7장).
  - 필터를 걸어둔 사용자가 배너를 누른 이유는 새 것을 보려는 것이지 필터를 풀려는 것이 아니다. 조작하지 않은 상태가 조용히 바뀌면 다음에 목록이 이상해 보여도 원인을 찾지 못한다.
- **탭을 전환하면 리스트를 최상단부터 다시 그린다.** 탭별 스크롤 위치를 기억하지 않는다.
  - 커서 기반 20건 페이지네이션이므로 위치를 복원하려면 앞 페이지를 전부 다시 불러야 한다. 복원 비용을 치르고도 그 사이 목록이 바뀌면 엉뚱한 지점에 서게 된다.
- 무한 스크롤은 리스트 하단 도달 시 자동으로 다음 커서를 요청한다(L15).
- 당겨서 새로고침은 인디케이터를 노출하고, **포그라운드 복귀 시 재조회는 인디케이터 없이 조용히** 수행한다(`library.md` 4.6).
  - 앱으로 돌아올 때마다 로딩이 번쩍이면 사용자가 시작하지 않은 동작이 매번 화면을 차지한다(`common-error-handling.md` 4.3).

### 4.2 L1 상단 탭 3개(상태) + 필터 아이콘

> **개편 2026-08-07** — 탭에서 [이어 PICK]을 빼 필터 시트의 출처 옵션으로 옮겼다. 이 절이 다루던 **[이어 PICK] 라벨 폭 문제(등폭 4분할·말줄임·가로 스크롤 전환)는 함께 없어졌다.**

**구성** — `전체 · 미청취 · 완료` + 우측 필터 아이콘. 탭은 서로 배타적이며 한 번에 하나만 선택된다.

- **탭은 상태만 가른다.** 출처가 빠지면서 라벨이 전부 2–3자가 됐고, 360dp 폭에서 3분할이면 탭 하나가 90dp 이상이라 동적 텍스트 200%에서도 잘리지 않는다. 등폭 3분할을 그대로 쓴다.
- **그래도 넘치면 폰트를 줄이지 않는다.** 접근성 설정으로 키운 글씨를 앱이 도로 줄이는 셈이 된다. 탭 줄만 가로 스크롤로 전환하고 선택된 탭이 항상 화면 안에 오게 한다.
- **주제 칩을 탭 줄에 늘어놓지 않는다**(`library.md` 4.1-1). 금지된 것은 상태와 주제가 한 줄에 섞이는 것이다.
- 탭 높이는 라벨이 두 줄로 접히지 않는 범위에서 최소 44pt를 확보한다.
- **탭을 전환해도 걸려 있는 출처·주제 필터는 유지된다.** 탭은 상태 축이고 필터는 다른 축이라, 한쪽을 만졌다고 다른 쪽이 풀리면 사용자가 방금 무엇을 잃었는지 알 수 없다.

**필터 아이콘**

| 상태 | 표시 |
|---|---|
| 미적용 | 아이콘 기본색 |
| 적용 중 | 아이콘 강조 + **배지**(1–9, 초과 시 `9+`) |

- **배지 숫자는 출처 + 주제 선택 개수의 합이다.** 출처는 단일 선택이므로 0 또는 1이고, 주제는 선택한 개수다. 예: 출처 [이어 PICK] + 주제 2개 → `3`.
  - **두 섹션의 배지를 나누지 않는다.** 아이콘 하나에 숫자 둘을 붙이면 어느 쪽이 무엇인지 아이콘만으로 알 수 없고, 무엇이 걸렸는지는 어차피 시트를 열어야 안다. 배지가 답하는 질문은 "몇 개가 걸렸나"이지 "무엇이 걸렸나"가 아니다.
- **적용 중인 필터를 배지로 반드시 드러낸다.**
  - 선택은 시트를 닫는 순간 화면에서 사라진다. 배지가 없으면 목록이 비었을 때 사용자가 볼 수 있는 단서가 하나도 없고, "콘텐츠가 안 온다"는 오해가 그대로 이탈이 된다(L7).
- 배지는 숫자다. 점(dot)으로 대체하지 않는다 — 몇 개가 걸렸는지가 [초기화]를 누를지 결정하는 정보다.

### 4.3 앱바 잔여 재생 표시 (L1 · L3 · **L12**)

**자리는 앱바 우측 한 곳이다.** 문구는 `paywall.md` 5장이 규정한 한 문자열, **"오늘 재생 N/M 남음"** 을 그대로 쓴다.

| 조건 | 표시 | 인터랙션 |
|---|---|---|
| `daily_play_limit != null`, N > 0 | "오늘 재생 N/M 남음" — 중립색 | **없음(탭 불가)** |
| N = 0 (소진) — **L12** | "오늘 재생 0/M 남음" — **주의색으로 유지** | **탭 → 페이월 바텀시트** |
| `daily_play_limit == null` (무제한) | **표시하지 않는다.** 자리를 비운다 | — |
| 캐시 목록 표시 중(L10) · 응답에 값 없음 | **표시하지 않는다** | — |
| 최초 로딩 중(L11) | **스켈레톤도 그리지 않는다** | — |

- **카드마다 붙이지 않는다.**
  - 잔여 횟수는 콘텐츠의 속성이 아니라 사용자의 하루 상태다. 카드마다 같은 숫자를 반복하면 콘텐츠별 제한처럼 읽히고, 한 편을 재생하고 돌아오면 화면의 숫자가 전부 동시에 바뀌어 무엇이 바뀐 건지 알 수 없다.
- **탭 줄에 넣지 않는다.**
  - 탭과 필터 아이콘이 쓰는 줄이고, 상태 필터와 하루 잔여량은 축이 다르다. 같은 줄에 두면 숫자가 네 번째 탭처럼 읽힌다.
- **무제한 티어에는 "무제한" 배지조차 두지 않는다.**
  - 셀 것이 없는데 숫자를 두면 없는 한도가 있는 것처럼 읽힌다. 배지로 대체하면 매 화면마다 요금제를 광고하는 꼴이 된다 — 이미 결제한 사용자에게 결제 상태를 반복해 알릴 이유가 없다.
- **0일 때 숨기지 않는다.** 0이야말로 알려야 할 값이다.
  - 숨기면 사용자는 카드를 탭하고 페이월이 뜬 뒤에야 소진 사실을 안다. 그 시점의 페이월은 안내가 아니라 방해로 읽힌다.
- **N > 0일 때 이 표시는 탭 대상이 아니다.**
  - 아직 남아 있는 사용자가 눌렀을 때 페이월이 열리면 결제를 조르는 화면이 된다. 소진 상태에서만 인터랙티브해지므로 그때만 버튼 어포던스(눌리는 배경·`role=button`)를 부여한다.
- **클라이언트가 임의로 1을 빼지 않는다.** 갱신은 목록을 조회할 때(진입·당겨서 새로고침·포그라운드 복귀·플레이어에서 복귀) 서버 값으로 덮어쓰는 것뿐이다.
  - 재생 버튼을 누른 것만으로 숫자를 줄이면 오디오 로드에 실패했을 때 실제보다 적게 표시된다. 차감은 재생이 실제로 시작된 시점에만 일어난다(`paywall.md` 4.3).
- **덮어쓸지는 `paywall.md` 5장의 신선도 규칙이 정한다.** 탭·필터 조합마다 캐시가 따로 있어 재조회가 끝나기 전에 먼저 렌더되고, 먼저 보낸 요청이 늦게 도착하기도 한다. 같은 `service_date`·같은 `daily_play_limit`이면 **`daily_play_count`가 큰 쪽만 반영하고 작은 값은 버린다.**
  - 그냥 마지막에 도착한 값을 쓰면 **재생 직후 탭을 옮길 때 차감 전 숫자가 잠시 되돌아온다.** 숫자가 늘었다 줄었다 하면 사용자는 어느 것이 맞는지 판단하게 되고, 그 순간 신뢰를 잃는 것은 숫자가 아니라 한도 정책 전체다.
  - **도착 시각이나 기기 시각으로 비교하지 않는다.** 응답 순서 역전과 시계 조작에 그대로 깨진다.
- **앱을 켜 둔 채 04:00을 넘겨도 클라이언트가 스스로 숫자를 되돌리지 않는다.**
  - 기기 시각으로 리셋을 판단하면 시각 조작만으로 한도가 초기화된 것처럼 보인다. 다음 재조회에서 서버 값으로 갱신된다.
- **캐시 목록을 보여주는 중에는 표시를 지운다.**
  - 캐시된 숫자는 이미 낡았을 수 있다. 틀린 숫자를 확신 있게 보여주면 팝업·페이월과 어긋나고, 그때 사용자가 신뢰를 잃는 것은 숫자가 아니라 한도 정책 전체다.
- **응답에 `daily_play_count`가 없으면 표시를 생략한다. 0으로 가정하지 않는다.**
  - 아직 남아 있는 사용자에게 소진 표시를 띄우는 쪽이 표시가 없는 쪽보다 훨씬 나쁘다.
- **결제로 무제한 티어가 된 직후에는 시트가 닫히는 즉시 표시를 제거한다**(`paywall.md` 4.5).
  - 방금 결제한 화면에 남은 횟수가 그대로 있으면 결제가 반영되지 않은 것으로 읽혀 곧장 문의가 된다.

### 4.4 L1 미니플레이어 복원

**구성** — 썸네일 · 제목 · 진행률 바 · 재생 버튼. 본문 탭 시 전체 플레이어로 확장.

- **앱을 실행하면 일시정지 상태로 표시만 한다. 자동으로 재생하지 않는다.**
  - 앱을 열자마자 소리가 나면 공공장소에서 바로 문제가 된다. 이어듣기는 제안이지 실행이 아니며, 사용자가 재생 버튼을 눌러야 소리가 난다.
  - 재생 버튼 아이콘은 **▶(재생)** 이어야 한다. 일시정지 아이콘을 그려두면 지금 소리가 나는 중이라고 읽혀 사용자가 정지를 누른다.
- 대상은 완청하지 않은 것 중 `last_played_at`이 가장 최근인 1건이다. **대상이 없으면 미니플레이어 자체를 노출하지 않는다.**
  - 빈 껍데기를 남기면 하단에 아무것도 못 하는 바가 늘 붙어 있게 되고, 리스트가 그만큼 짧아진다.
- **재생 위치가 0이면 띄우지 않는다.** 처음부터 듣는 것과 같아 "이어듣기"가 아니다.
- **미니플레이어에서 시작하는 재생도 카드 탭과 완전히 같은 판정·팝업을 거친다**(3장 흐름도).
  - 진입점이 다르다고 규칙이 달라지면 미니플레이어가 한도를 우회하는 뒷문이 된다.
- 미니플레이어에 떠 있는 콘텐츠를 삭제하거나 그 콘텐츠가 회수되면 **미니플레이어를 내린다.** 다만 이미 재생 중이었다면 **재생은 중단하지 않는다**(`library.md` 7장).
  - 듣고 있던 소리가 목록 정리 때문에 끊기면 삭제가 재생 취소로 읽힌다.
- **스낵바·배너는 미니플레이어를 가리지 않는다.** 스낵바는 미니플레이어와 하단 탭 위에 겹쳐 띄운다.
  - [실행 취소]가 미니플레이어에 가려지면 5초짜리 되돌리기 수단이 사실상 없는 것과 같다.

### 4.5 L2 필터 바텀시트 — 출처 + 주제

> **개편 2026-08-07** — 주제 전용이던 시트에 **출처 섹션**이 들어왔다.

**구성** — 핸들 / "필터" 제목 / **출처 섹션**(제목 "출처" + 옵션 2개) / **주제 섹션**(제목 "주제" + 보조 문구 **"라이브러리에 담긴 콘텐츠의 주제만 보여줘요"** + 주제 칩) / [초기화] · [적용]

| 섹션 | 선택 방식 | 옵션 |
|---|---|---|
| **출처** | 단일 선택 · **재탭하면 해제** | **이어 PICK** / **내가 담은 콘텐츠** |
| **주제** | 다중 선택 | 라이브러리에 담긴 콘텐츠의 주제 칩 |

- **출처는 단일 선택이되 "전체" 옵션을 따로 두지 않는다.** 선택된 것을 다시 탭하면 해제되고, 그 상태가 곧 전체다.
  - 옵션을 셋(전체·이어 PICK·내가 담은 콘텐츠)으로 만들면 [초기화]와 [전체]가 같은 일을 하는 버튼 둘이 된다. 해제 가능한 토글이 상태 수를 늘리지 않는 방법이다.
  - 다만 **재탭 해제는 발견하기 어려운 조작이므로**, 선택된 칩은 해제 가능함이 드러나는 형태(예: 선택 표시 + 눌림 상태)로 그린다.
- **출처를 주제보다 위에 둔다.** 옵션이 2개뿐이라 세로 길이가 짧고, 주제 칩은 개수에 따라 여러 줄로 늘어난다. 긴 섹션이 위에 오면 출처가 접힌 화면 밖으로 밀린다.
- **출처 라벨에 "드립"을 쓰지 않는다.** 내부 용어이고, 탐색의 추천 피드와 구분하려고 [이어 PICK]으로 정한 이름이다(`library.md` 4.1-1). "내가 담은 콘텐츠"에는 **온보딩에서 담은 것도 포함된다** — 사용자에게 온보딩은 제3의 출처가 아니라 직접 고른 것이다.
- **노출할 주제는 사용자의 관심 주제가 아니라 라이브러리에 실제로 담긴 콘텐츠의 주제다.**
  - 담긴 게 없는 주제를 고를 수 있게 하면 사용자는 반드시 빈 결과에 도달한다. 고를 수 있는 것은 결과가 있는 것이어야 한다.
  - **주제 목록은 출처 선택에 따라 바뀌지 않는다.** 출처를 고를 때마다 칩이 사라졌다 나타나면 무엇을 고를 수 있는지 예측할 수 없다. 조합 결과가 비면 L7이 답한다.
- **[초기화]는 출처·주제를 함께 비우고 시트를 닫지 않는다.** [적용]만 시트를 닫는다.
  - 초기화가 곧 닫힘이면 "다 지우고 다시 고르기"를 하려던 사용자가 시트를 두 번 열어야 한다.
  - **탭(상태)은 초기화 대상이 아니다.** 시트 밖의 컨트롤이라 시트 안의 버튼이 건드리면 사용자가 보지 못한 곳이 바뀐다.
- **딤 영역 탭·뒤로가기로 닫으면 변경을 폐기한다.** 적용은 [적용]으로만 일어난다.
  - 닫는 동작이 곧 저장이면 잘못 누른 칩이 그대로 반영되고, 사용자는 목록이 왜 바뀌었는지 모른 채 원인을 찾게 된다.
- 적용 결과는 **탭·출처·주제가 전부 AND 조합**이고, 선택한 주제끼리만 OR다. 예: [완료] 탭 + 출처 `이어 PICK` + 주제 `글쓰기` → 드립으로 받아 완청한 글쓰기 콘텐츠만.
  - 축 사이가 OR이면 "완료"를 골랐는데 미청취가 섞여 나온다. 좁히려고 조작했는데 넓어지는 것은 필터가 아니다.
  - 주제끼리를 AND로 걸면 두 개만 골라도 대부분 빈 목록이 된다. 다중 선택의 의도는 "이 중 아무거나"다.
- 적용 즉시 필터 아이콘에 배지가 붙는다 — **출처 + 주제 선택 개수의 합**(4.2).
- **앱을 종료하면 출처·주제 필터가 초기화된다**(`library.md` 7장). 탭 선택도 [전체]로 돌아온다.
  - 다음 실행 때 필터가 남아 있으면 사용자는 필터가 걸린 줄 모른 채 "콘텐츠가 안 온다"고 판단한다. 앱의 첫 화면에서 그 오해는 곧바로 이탈이다.

### 4.6 L3 재생 확인 팝업 — [오늘은 그만 보기] 포함

**이 팝업의 노출 조건은 `paywall.md` 4.2가 소유한다.** 이 문서는 뜬 팝업의 생김새와 반응만 정한다.

**구성** — 제목 **"오늘 1회 남았어요"** / 본문 **"재생하면 1회가 차감돼요."** / [취소] · [재생하기] / 하단 **[오늘은 그만 보기]** 텍스트 버튼

- 버튼은 [취소] 좌, [재생하기] 우이며 [재생하기]가 주 액션 스타일이다.
- **알리는 것은 남은 횟수와 1회 차감 두 가지뿐이다.** 요금제 안내·업그레이드 유도를 여기 얹지 않는다.
  - 아직 한도가 남은 사용자에게 결제를 권하는 화면이 되면, 재생하려던 사람이 매번 광고를 통과해야 한다. 전환 유도는 페이월의 일이다.
- **[취소]는 라이브러리에 그대로 머문다.** 차감도 없고 억제도 걸리지 않는다.
  - [취소]가 억제까지 겸하면 사용자는 "이번엔 안 듣겠다"를 눌렀을 뿐인데 하루치 고지가 꺼진다.
- **[재생하기]를 누른 시점에 서버가 다시 판정한다.** 팝업에 적힌 숫자를 근거로 통과시키지 않는다.
  - 팝업이 떠 있는 사이 다른 기기에서 재생해 한도가 소진될 수 있다. 재판정 결과가 소진이면 **팝업을 닫고 페이월로 전환한다** — 팝업 위에 페이월을 겹쳐 쌓지 않는다.

**[오늘은 그만 보기]**

- **텍스트 버튼이며 [취소]·[재생하기]와 나란히 세우지 않는다.** 팝업 하단 중앙에 한 단 낮은 무게로 둔다.
  - 같은 크기의 버튼을 셋 두면 무엇이 기본 동작인지 흐려진다. 잘못 눌러서 끄게 되는 것이 하루치 고지라 되돌릴 수단도 없다(별도 해제 수단을 두지 않으므로).
- **누르면 팝업을 닫고 그대로 재생한다. 차감도 그대로 일어난다.**
  - 재생하지 않고 닫히면 [취소]와 결과가 같아지고, 사용자는 다시 탭해야 하는데 그때는 팝업이 없어 방금 무엇이 바뀐 건지 알 수 없다.
- **억제 대상은 이 팝업 하나뿐이다.** 페이월·한도 안내·회수 안내(L13)는 억제되지 않는다.
  - 억제한 것은 고지이지 판정이 아니다. 클라이언트의 표시 설정이 서버 판정을 건드리는 순간 표시가 정책이 된다(`paywall.md` 4.2).
- 억제 상태는 **기기 로컬**에 저장하며, 저장하는 값은 타이머가 아니라 **억제한 서비스 날짜**다. 서버가 응답에 실어준 `service_date`와 다르면 풀린 것으로 본다.
  - 기기 시각으로 만료를 재면 시각을 되돌려 억제를 무한정 연장할 수 있고, 반대로 04시가 지났는데 억제가 안 풀리는 구간이 매일 생긴다.
- 억제 중에는 이 팝업이 아예 뜨지 않으므로 **별도의 "억제 중" 표시를 화면에 두지 않는다.** 차감 고지는 앱바의 잔여 표시(4.3)가 대신 맡는다.
  - 억제 버튼과 상시 표시는 한 쌍이다. 상시 표시가 빠지면 억제한 사용자에게 고지 수단이 아예 없어진다(`paywall.md` 7장 · 시안 V7).

### 4.7 L4 더보기 액션시트 · L5 삭제와 실행 취소

**L4 구성** — 대상 아이템 요약 / [라이브러리에서 삭제](파괴적 스타일) / [닫기]

- 메뉴 항목은 **삭제 하나뿐**이다. 수동 완료 표시는 제공하지 않고, 공유·오프라인 저장은 P1이다(9장 미결 — 항목 하나짜리 시트의 존치 여부).
- **어느 아이템에 대한 조작인지 시트 상단에 반드시 다시 보여준다.**
  - 시트가 올라오면 대상 카드가 딤 처리돼 확인하기 어렵다. 삭제 대상을 눈으로 확인하지 못한 채 파괴적 액션을 누르게 하지 않는다.

**L5 삭제 직후**

- 스와이프(오른쪽→왼쪽)는 임계 거리를 넘으면 즉시 삭제하고, 미달이면 원위치로 되돌린다. **확인 팝업을 거치지 않는다.**
- 스낵바: **"삭제했어요"** + [실행 취소], 5초.
- **스낵바에 재추천·영구 제외 관련 문구를 넣지 않는다.**
  - 삭제는 목록 정리에 가까운 가벼운 조작인데 "다시 추천되지 않아요"가 붙는 순간 결정처럼 무거워진다. 지우기를 망설이면 라이브러리가 정리되지 않고, 정리되지 않은 목록은 결국 열지 않게 된다. 되돌릴 수단도 남아 있다 — 탐색에서 다시 담으면 돌아온다.
  - **동작은 그대로다.** 알리지 않을 뿐 제외는 영구적으로 적용된다.
- 삭제는 낙관적으로 즉시 반영하고, **서버 요청은 스낵바가 사라진 뒤에 보낸다**(`common-error-handling.md` 4.4).
  - 5초 안에 되돌릴 조작을 곧바로 서버에 보내면 삭제와 복구를 왕복시키게 된다.
- **[실행 취소]는 원래 순서 그대로 복구한다.** `added_at`을 새로 찍지 않는다.
  - 복구한 아이템이 목록 맨 위로 올라오면 되돌리기가 아니라 새로 담기가 된다. 사용자가 되찾으려던 것은 항목이 아니라 항목이 있던 자리다.
- 스낵바는 **한 번에 하나만** 띄운다. 연속 삭제 시 이전 스낵바를 교체하고 타이머를 초기화한다.
  - 스낵바를 쌓으면 어느 [실행 취소]가 어느 삭제인지 알 수 없다.
- 삭제 후 목록이 완전히 비면 L9로 전환한다.

### 4.8 빈 상태 4종 — L6 · L7 · L8 · L9

**네 화면의 문구를 공유하지 않는다.** 원인이 다르고, 그래서 다음 행동이 다르다.

| ID | 원인 | 문구 | 다음 행동 |
|---|---|---|---|
| L6 | 신규 — 아직 안 왔다 | **"곧 첫 콘텐츠가 도착해요"** / 보조 "그동안 탐색에서 직접 골라보셔도 좋아요" | [탐색 둘러보기] |
| L7 | 필터 때문에 안 보인다 | **"조건에 맞는 콘텐츠가 없어요"** / 보조에 걸린 조건을 그대로 적는다 | [필터 초기화] |
| L8 | 출처 필터 = 이어 PICK인데 드립이 아직 없다 | **"아직 도착한 이어 PICK이 없어요"** | 없음 |
| L9 | 다 지웠다 | **"라이브러리가 비어 있어요"** / 보조 "탐색에서 담으면 여기로 돌아와요" | [탐색 둘러보기] |

- **L6과 L9는 문구가 달라야 한다.**
  - L6은 기다리면 채워지지만 L9는 기다려도 채워지지 않는다. 지운 콘텐츠는 드립으로 다시 오지 않으므로(FR-16), L9에 "곧 도착해요"를 쓰면 오지 않을 것을 기다리게 만든다.
- **L7의 보조 문구에 걸린 조건을 그대로 적는다.** 탭·출처·주제를 모두 나열한다. 예: "완료 · 이어 PICK · 글쓰기 조건을 모두 만족하는 콘텐츠가 없습니다"
  - 출처와 주제는 시트 안에 숨어 있어 배지 숫자만으로는 무엇이 걸렸는지 알 수 없다. 원인을 화면에 남겨야 [필터 초기화]를 누를지 다른 조건을 고를지 판단할 수 있다.
  - **L7과 L8을 가르는 기준은 "출처 = 이어 PICK만 걸렸는가"다.** 출처만 걸어 비었으면 원인이 하나뿐이라 L8이 그 하나를 정확히 말해 줄 수 있다. 조건이 둘 이상 걸려 있으면 어느 것이 원인인지 특정할 수 없으므로 L7로 보내 조건을 전부 나열한다.
- **L8에는 다음 행동 버튼을 두지 않는다.**
  - 드립은 사용자가 앞당길 수 있는 것이 아니다. 여기서 [탐색 둘러보기]를 주면 담기로 유도하는 것인데, 담아봐야 출처가 `save`라 이 화면은 여전히 비어 있다 — 누르면 상황이 나아지지 않는 버튼이다.
- **L8과 L9는 탭 줄을 다르게 처리한다.**
  - **L7·L8은 탭 줄과 필터 아이콘(배지 포함)을 반드시 유지한다.** 비어 보이는 원인이 그 조작에 있으므로, 원인을 만든 컨트롤을 감추면 사용자는 되돌릴 방법을 잃는다.
  - **L6·L9는 목록 전체가 비어 있으므로 탭 줄과 필터 아이콘을 숨긴다.** 어느 탭을 눌러도 같은 빈 화면인데 조작할 것을 남겨두면 사용자가 탭을 하나씩 눌러보게 된다.
- **L6·L9에서는 미니플레이어를 띄우지 않는다.** 들을 것이 없기 때문이다.
- L6의 상단 배너 **"콘텐츠를 준비하고 있어요"** 는 온보딩 직후 드립 트리거가 실패·지연됐을 때만 노출한다. 온보딩 완료는 롤백되지 않으므로 이 상태는 실제로 발생한다.

### 4.9 L11 최초 로딩 · L15 추가 로딩

- **L11** — 스켈레톤 카드 5개 + 탭 줄·필터 아이콘 자리. **0.3초 미만이면 표시하지 않는다**(`common-error-handling.md` 5장).
  - 깜빡이는 로딩은 없는 편만 못하다. 이 규칙은 라이브러리 전용이 아니라 공통이다.
- **L11에서 앱바 잔여 표시는 스켈레톤조차 그리지 않는다.**
  - 아직 값을 모르는데 자리를 잡아 두면, 값이 도착했을 때 무제한 티어에서는 그 자리가 사라지며 앱바가 흔들린다. 값이 있는 티어에서만 나타나는 요소이므로 처음부터 비워 둔다.
- **L15 추가 로딩** — 리스트 하단 스피너. **기존 목록을 유지한다.**
- **L15 추가 로딩 실패** — 리스트 하단 인라인 에러 + [다시 시도]. 전체 화면 에러로 전환하지 않는다.
  - 이미 보고 있던 20건이 사라지면 추가 로딩 실패가 조회 실패처럼 보인다. 실패한 것은 다음 페이지뿐이다.

### 4.10 L10 오프라인(캐시 있음) · L14 캐시 없음

**L10 — 캐시 있음**

- 상단 오프라인 배너 **"오프라인 상태예요"** + 캐시된 목록(최근 1페이지). 온라인 복귀 시 배너는 자동으로 사라진다.
- 리스트 하단에 **"최근 목록만 표시하고 있어요"** 를 덧붙여 지금 보는 것이 전부가 아님을 밝힌다.
- **앱바 잔여 표시를 노출하지 않는다**(4.3).
- **오프라인에서는 재생이 되지 않는다**(오프라인 저장은 P1 이연 — FR-26). 카드를 탭하면 재생 판정으로 가지 않고 네트워크 안내를 띄운다.
  - 재생 판정 자체가 서버 왕복이므로, 시도하게 두면 로딩 후 알 수 없는 실패로 끝난다.
- 오프라인 삭제는 로컬에서만 반영하고 큐에 넣는다. **스낵바와 [실행 취소]는 온라인과 동일하게 동작한다.**
  - 되돌리기 수단이 통신 상태에 따라 사라지면 사용자는 오프라인에서 삭제를 겁내게 된다.

**L14 — 캐시 없음**

- 전체 화면 에러 + [다시 시도]. 문구는 **"인터넷 연결을 확인해주세요"**(`common-error-handling.md` 4.6).
- **탭 줄·필터 아이콘·미니플레이어를 함께 감춘다.**
  - 목록이 없는데 필터만 남으면 조작할 수 있어 보이는 컨트롤이 전부 아무 일도 하지 않는다.
- [다시 시도] 연타는 인플라이트 요청이 있으면 무시한다.

### 4.11 L13 회수 콘텐츠 안내

파트너가 회수한 콘텐츠(FR-32)는 서버 응답에서 빠지지만, **이미 화면에 떠 있는 카드**를 탭하면 재생 요청이 403으로 돌아온다.

- 안내는 **"제공이 종료된 콘텐츠예요"** 토스트다. 안내 후 해당 아이템을 목록에서 제거한다.
- **오류 톤으로 쓰지 않는다.** 실패 문구("재생할 수 없어요")나 [다시 시도]를 붙이지 않는다.
  - 사용자가 뭘 잘못한 것도, 일시적인 장애도 아니다. 다시 시도해도 결과가 같은 상황에 재시도 버튼을 주면 두 번 실패하게 만든다.
- **재생 횟수는 차감되지 않는다.** 재생이 시작되지 않았기 때문이다 — 앱바의 잔여 표시를 줄이지 않는다.
- 미니플레이어에 떠 있던 콘텐츠가 회수된 경우 **미니플레이어를 내리고 같은 안내를 띄운다**(4.4).
- 결제 직후 자동 재생하려던 콘텐츠가 회수된 경우도 같은 안내로 처리하고 원래 화면으로 돌아온다(`paywall.md` 7장).

## 5. 공통 컴포넌트 규칙

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| **상단 배너** | 화면 전체에 걸린 상황·도착 통지 | 오프라인 / 드립 준비 중 / 새 콘텐츠 도착. **한 번에 하나**, 우선순위는 4.1 |
| **스낵바** | 되돌릴 수 있는 파괴적 조작 | 삭제. 5초 + [실행 취소]. 미니플레이어·하단 탭 위에 겹친다 |
| **토스트** | 되돌릴 필요 없는 결과 통지 | 회수 안내, 복구 실패. 3초 |
| **바텀시트** | 목록에서 고르는 조작 | 필터(출처·주제), 더보기, 페이월. 딤 탭·뒤로가기로 닫히며 변경은 폐기 |
| **다이얼로그** | 진행 전 확인이 필요한 조작 | 재생 확인 팝업. 주 액션이 오른쪽 |
| **스켈레톤** | 최초 조회 | 카드 5개. 0.3초 미만이면 미표시 |
| **인라인 스피너·에러** | 추가 로딩 | 리스트 하단. **기존 목록 유지** |
| **전체 화면 에러** | 보여줄 데이터가 하나도 없는 조회 실패 | [다시 시도]. 탭 줄·미니플레이어까지 감춘다 |
| **앱바 상태 표시** | 사용자의 하루 상태 | 잔여 재생. **화면당 한 곳**, 카드 아님 |

- **모든 파괴적 조작은 되돌릴 수단을 화면에 남긴다.** 삭제는 확인 팝업 대신 [실행 취소]를 택했으므로, 스낵바가 가려지거나 조기에 사라지면 되돌릴 방법이 아예 없어진다.
- **낙관적 반영 후 서버 요청이 실패하면 원상 복구 + 토스트**로 알린다(`common-error-handling.md` 4.4). 조용히 되돌리면 사용자는 자기가 지운 것이 왜 살아났는지 모른다.
- **사용자가 시작하지 않은 실패는 알리지 않는다.** 포그라운드 복귀 시 조용한 재조회가 실패하면 캐시를 그대로 유지하고 에러 UI를 띄우지 않는다.

## 6. 카피 원칙

- **해요체**로 통일한다.
- **잔여 표시는 `"오늘 재생 N/M 남음"` 한 문자열만 쓴다.** `M`을 2로 하드코딩하지 않는다.
  - 유료 티어에 한도가 생기는 순간 그대로 깨진다. 같은 값을 라이브러리와 탐색이 다른 말로 표시하면 어느 쪽이 맞는지 사용자가 판단하게 된다(`paywall.md` 5장).
- **빈 상태 4종의 문구를 재사용하지 않는다**(4.8). 원인이 다르면 다음 행동도 다르다.
- **삭제 스낵바에 영구 제외를 고지하지 않는다.** "삭제했어요"와 [실행 취소]가 전부다.
- **내부 용어를 화면에 노출하지 않는다** — "드립", "적립", "소진", "라이브러리 아이템".
  - 출처를 부르는 이름은 화면 전체에서 **[이어 PICK] · [내가 담은 콘텐츠]** 둘뿐이며, 노출되는 자리는 필터 시트와 L8 문구다. 카드 배지가 "드립"으로 남아 한 화면이 같은 개념을 두 이름으로 부르던 문제는 **배지를 없애면서 해소됐다**(개편 2026-08-07).
- **[오늘은 그만 보기]는 라벨과 동작이 어긋난다**(시안 V8). 이 버튼은 **누르는 즉시 재생하고 차감**하는데, "그만 보기"는 재생 없이 닫는 동작으로 읽힌다.
  - 의도치 않은 재생과 차감으로 이어질 수 있다. 텍스트 버튼으로 비중을 낮춰 완화했을 뿐 모호함은 라벨 자체에서 오므로 **카피 재검토 대상이다**(후보: "재생하고 오늘은 그만 묻기"). **동작은 `paywall.md` 4.2가 소유하므로 여기서 바꿀 수 있는 것은 라벨뿐이다.**
- 회수 안내는 **사실만 말한다**: "제공이 종료된 콘텐츠예요". 사과·오류 톤·재시도 유도를 붙이지 않는다.
- 에러 문구는 **무엇이 잘못됐는지 + 다음에 무엇을 하면 되는지** 두 가지를 담는다.

## 7. 접근성

- **터치 타깃 최소 44×44pt.** 시각 크기가 그보다 작은 요소는 히트 영역을 넓혀 맞춘다 — 필터 아이콘(32dp), 카드의 더보기 버튼, 미니플레이어 재생 버튼, 스낵바의 [실행 취소], 소진 상태의 잔여 표시가 모두 해당한다.
- **잔여 표시는 화면 문자열 그대로 읽히면 안 된다.** `"오늘 재생 1/2 남음"` 은 스크린리더에서 "일 슬래시 이"로 읽힌다. 라벨을 **"오늘 재생 2회 중 1회 남음"** 형태로 따로 붙인다.
  - N = 0일 때는 `role=button` + **"오늘 재생 0회 남음, 구독 안내 열기"** 로 읽히게 한다. N > 0일 때는 버튼이 아니므로 role을 주지 않는다 — 누를 수 있는 것처럼 읽히면 눌러보게 되고 아무 일도 일어나지 않는다.
- **잔여 표시 갱신은 `aria-live="polite"`, 값이 실제로 바뀔 때만 알린다.** 목록을 조회할 때마다 읽으면 화면을 오갈 때마다 같은 문장이 반복된다.
- **탭은 `role=tablist` / `role=tab` + `aria-selected`** 로 구성하고, 전환 후 결과 건수를 polite로 한 번 알린다("미청취 12개"). 목록이 바뀌었다는 사실이 시각 외 수단으로는 전달되지 않기 때문이다.
- **필터 아이콘의 배지는 숫자만 읽히면 의미가 없다.** "필터, 3개 적용됨"으로 읽히게 한다. 배지는 출처와 주제의 합이므로 "주제 필터"라고 읽으면 틀린 안내가 된다.
- **색만으로 상태를 구분하지 않는다.**
  - **카드에서 상태 텍스트가 전부 사라졌으므로**(개편 2026-08-07) 세 상태 모두 시각 외 수단이 필요하다. `in_progress`는 진행률 바에 `aria-label` "34% 들음", `completed`는 썸네일 체크 마킹에 "완청함", `unplayed`는 표시가 없는 것이 곧 상태이므로 아무것도 붙이지 않는다.
  - **완청 체크는 색이 아니라 형태(체크 아이콘)로 구분된다.** 썸네일 위에 얹히므로 밝은 이미지에서도 보이도록 배경 처리(딤 또는 테두리)를 함께 둔다.
  - **완청을 제목의 회색 처리로 표현하지 않는다.** 색이 유일한 단서가 된다.
  - 소진 상태의 주의색은 숫자 `0`이라는 텍스트를 동반하므로 색이 유일한 단서가 아니어야 한다는 조건을 만족한다. 다만 **주의색은 배경색 대비 4.5:1 이상**을 확보한다.
- **진행률 바는 `role=progressbar` + `aria-valuetext`("14분 중 5분")** 로 읽히게 한다. 미니플레이어의 바도 같다.
- **스낵바는 5초 자동 소멸이지만, 스크린리더·시간 연장 접근성 설정이 켜져 있으면 소멸 시간을 연장한다.**
  - [실행 취소]까지 포커스를 옮기는 데만 5초가 걸린다. 되돌릴 유일한 수단이 도달하기 전에 사라지면 삭제가 사실상 확인 없는 영구 조작이 된다.
- **바텀시트·다이얼로그는 포커스를 가두고, 닫으면 열기 전 요소로 포커스를 되돌린다.** 재생 확인 팝업은 열릴 때 제목을 먼저 읽힌 뒤 [재생하기]에 포커스를 둔다.
- **동적 텍스트 최대 200%에서 잘리지 않아야 한다.** 위험한 곳은 둘이다 — **앱바의 잔여 표시**(타이틀을 줄이고 표시를 우선한다), **재생 확인 팝업의 버튼 줄**([취소]/[재생하기]를 세로로 쌓되 [오늘은 그만 보기]는 그 아래 텍스트 버튼 자리를 유지한다).
  - 탭 줄은 개편으로 라벨이 전부 2–3자가 되어 위험 목록에서 빠졌다(4.2). **[내가 담은 콘텐츠]는 8자로 길지만 시트 안에서 한 줄을 온전히 쓰므로** 폭 경쟁이 없다.
- 새 콘텐츠 도착 배너는 `aria-live="polite"`, 회수 안내(L13)는 사용자 조작의 직접 결과이므로 `aria-live="assertive"` 로 알린다.

## 8. 금지 사항

`library.md`·`paywall.md`가 명시적으로 금지한 것들이다. **UI 구현 시 되살아나기 쉬우므로 여기 모아 둔다.**

**목록·탭**

- 목록 최상단의 **이어듣기 카드·히어로 영역**
- **담기 전용 탭·보관함** — 라이브러리는 하나다
- **출처를 상단 탭으로 되돌리는 것** — 상태와 출처는 축이 달라 AND 조합이 필요하다(개편 2026-08-07)
- 출처 이름을 **"추천"** 으로 되돌리는 것 — 탐색의 추천 피드와 같은 단어를 두 화면에서 쓰게 된다
- [이어 PICK] 라벨의 **말줄임·축약**
- **카드에 출처 배지·상태 텍스트를 되살리는 것**
- **완청을 제목의 회색 처리로만** 표현하는 것 — 색이 유일한 단서가 된다
- 주제 칩을 **탭 줄에 가로로 늘어놓는 것**
- 필터가 걸렸는데 **배지를 표시하지 않는 것**
- 출처 선택에 따라 **주제 칩 목록을 바꾸는 것** — 무엇을 고를 수 있는지 예측할 수 없게 된다
- **수동 완료 표시** 기능
- 완료 아이템의 **자동 제거**(재청취 지표 수집 대상이다)
- 출처·주제 필터를 **앱 종료 후에도 유지**하는 것
- 새 드립 도착 시 **걸어둔 탭·출처·주제 필터를 초기화**하는 것
- 시트의 [초기화]가 **탭(상태) 선택까지 건드리는 것** — 시트 밖의 컨트롤이다

**잔여 재생 표시**

- 잔여 횟수를 **카드마다** 표시하는 것
- 잔여 횟수를 **탭 줄에** 넣는 것
- **무제한 티어에 숫자나 "무제한" 배지**를 두는 것
- **N = 0일 때 표시를 숨기는 것**
- 재생 버튼을 누른 것만으로 **클라이언트가 1을 빼는 것**
- **기기 시각으로 04:00 리셋을 판단**해 숫자를 되돌리는 것
- **캐시된 목록과 함께 낡은 잔여 숫자를 노출**하는 것
- 응답에 `daily_play_count`가 없을 때 **0으로 가정**하는 것
- **표시된 숫자를 근거로 재생을 통과**시키는 것 — 판정은 서버가 한다

**재생 확인 팝업**

- **한도 소진 상태에서 "0회 남았어요" 팝업**을 띄우는 것 — 곧바로 페이월이다
- 팝업과 페이월을 **연달아 겹쳐 띄우는 것**
- 차감이 없는 재생(무제한 티어 · 오늘 이미 튼 콘텐츠)에 **팝업을 띄우는 것**
- **[오늘은 그만 보기]를 [취소]·[재생하기]와 같은 크기로 나란히** 세우는 것
- [오늘은 그만 보기]가 **재생하지 않고 닫히게** 하는 것
- 억제가 **페이월·한도 안내·회수 안내까지** 끄게 만드는 것
- 억제 상태를 **서버에 저장**하는 것 / 설정 화면에 **해제 항목**을 두는 것
- 미니플레이어에서 시작하는 재생만 **판정·팝업을 건너뛰게** 하는 것

**삭제·기타**

- 삭제 시 **영구 제외 고지·확인 팝업**
- 복구 시 `added_at`을 새로 찍어 **목록 맨 위로 올리는 것**
- 재생 중인 콘텐츠를 삭제했다고 **재생을 중단**하는 것
- 앱 실행 시 미니플레이어를 **자동 재생**시키는 것
- **빈 미니플레이어**를 두는 것
- 회수 안내에 **[다시 시도]** 를 붙이는 것

## 9. 미결 사항

- **와이어프레임 갱신** — `library.html`에 **L12(잔여 `0/M` 소진)**, **L13(회수 콘텐츠 안내)**, **L14(캐시 없는 전체 화면 에러)**, **L15(추가 로딩·실패)** 를 추가해야 한다. 더해 잔여 표시가 **L1·L3에만** 그려져 있어(시안 주석 A2) 빈 상태·오프라인·필터 결과 없음 화면과 어긋난다.

- ~~**출처 배지의 용어**~~ → **해소(2026-08-07).** 카드에서 출처 배지를 없애면서 "드립"이라는 내부 용어가 화면에서 사라졌다. 출처 이름은 필터 시트의 [이어 PICK] · [내가 담은 콘텐츠]로만 노출된다.

- **무료 티어에서 확인 팝업 자체를 뺄지**(시안 V7 · `paywall.md` 미결) — 잔여 상시 표시가 들어오면서 팝업의 역할이 상당 부분 겹쳤다. 유료 티어 한도 값이 정해질 때 함께 판단하며, 결정되면 L3의 노출 조건이 바뀐다.

- **도착 배너와 푸시 알림의 중복**(시안 V6) — 푸시로 들어온 사용자에게도 배너를 띄울지.
