# 이어 디자인 원칙 — 애플 HIG 기준

> 2026-09-23 발행. 화면·컴포넌트를 만들거나 고칠 때 **이 문서를 먼저 본다.** 근거는 애플 Human Interface Guidelines(HIG)이고, 이 앱에서 확정한 값·이유를 적는다. 값의 원본은 `frontend/src/shared/theme/`(`index.ts` 토큰 · `motion.ts` 곡선)이다 — 여기 적힌 숫자와 코드가 다르면 코드가 틀린 것이다.
>
> 동작 규칙(`docs/features/`)·화면 상태·카피(`docs/spec/uiux/`)는 그대로 그쪽이 기준이다. 이 문서는 **어떻게 보이고 움직이는가**만 정한다.

## 0. 한 줄 원칙

**iOS 사용자가 "시스템 앱 같다"고 느끼게 만든다.** 브랜드는 검정 선 하나(로고)뿐이라 앱은 모노톤이고, 개성은 색이 아니라 **재질·곡률·움직임**으로 낸다. 애플이 정해 둔 것은 애플 값을 쓰고, 애플이 안 정한 것만 우리가 정한다.

HIG 원문: https://developer.apple.com/design/human-interface-guidelines/

## 1. 색 (HIG: Color)

| 역할 | 토큰 | 값 | 비고 |
|---|---|---|---|
| 바탕 | `color.background` | `#FFFFFF` | 앱의 유일한 큰 면. 어두운 건 플레이어뿐(`player.theme.ts`) |
| 면 | `color.surface` | `#F5F5F7` | 카드·시트 안 버튼(취소)·입력 상자 |
| 글자 | `color.textPrimary` / `textSecondary` | `#1A1A1E` / `#6E6E76` | |
| 강조 | `color.primary` | `#000000` | 버튼·선택. **유채색 강조는 두지 않는다** |
| 회색 단계(비활성·이미 가진 것) | `color.textMuted` / `textMutedSecondary` / `fillMuted` | `#8E8E93` / `#AEAEB2` / `#E5E5EA` | iOS systemGray · systemGray2 · systemGray5. 요금제 관리의 **이용 중 카드**(이름·가격 / 설명 / [이용 중] 알약 면 — 2026-10-06 KAN-146). 상태는 "이용 중" 글자가 함께 말한다 |
| 진행률 채움 | `color.progress` | `#8E8E93` | iOS systemGray. 사진 위에 놓이는 바 — 어두운 띠·흰 배경 양쪽에서 갈리는 중간값(2026-09-22 후보 6개 비교 후 확정) |
| 주의 | `color.danger` / `warning` | `#E5484D` / `#8A5B00` | 의미색은 강조가 아니다 — 소진·실패·미완에만 |
| 주의 면 | `color.dangerSurface` / `warningSurface` | `#FDECEC` / `#FFF3CD` | 파괴적 **보조 버튼**의 면·미인증 배지. 채운 빨강은 주 동작 자리를 빼앗는다 |

- **색만으로 상태를 구분하지 않는다**(HIG Accessibility) — 형태(바의 길이, 알약, 아이콘 채움)나 낭독기 라벨을 함께 둔다. 예: 완청은 "꽉 찬 바 + '완청한 콘텐츠' 라벨".
- 새 색을 넣고 싶으면 먼저 **"이게 앱의 유일한 유채색이 될 만큼 중요한가"** 를 묻는다. 아니면 회색 단계로 푼다.
- **파괴적 항목은 의미색 빨강을 그대로 쓴다** — 설정의 회원 탈퇴는 다른 항목과 **같은 크기**이고 색만 `color.danger` 다(2026-09-27 PM, iOS 설정의 "계정 삭제" 문법). 작게 회색으로 흐리면 경고가 아니라 "덜 중요한 항목"으로 읽히고 찾기만 어려워진다 — 오탭 방어는 그 뒤의 확인 절차가 맡는다(`changes/archive/settings-withdraw-destructive.md`).
- **예외 — 데이터 시각화의 범주 색**(주제 분포 막대 `color.chart` — 2026-09-28 도넛에서 누적 막대로). 강조가 아니라 구분이고, 애플의 스크린 타임·건강 차트도 색을 쓴다. 회색 단계로 만들지 않는다(2026-09-26 PM).

### 1-1. 다크 모드 (HIG: Dark Mode — 신설 2026-10-10)

**설정에서 시스템 설정 / 라이트 / 다크를 고른다**(기본 시스템 설정). 다크 값은 **iOS 시스템 의미색을 그대로** 쓴다 — 우리가 새 다크 색을 만들지 않는다. 원본은 `shared/theme/palette.ts`(`LIGHT_PALETTE` · `DARK_PALETTE`).

| 토큰 | 라이트 | 다크 | iOS |
|---|---|---|---|
| background | `#FFFFFF` | `#000000` | systemBackground |
| surface | `#F5F5F7` | `#1C1C1E` | secondarySystemBackground |
| textPrimary / textSecondary | `#1A1A1E` / `#6E6E76` | `#FFFFFF` / `rgba(235,235,245,.6)` | label / secondaryLabel |
| textMuted / textMutedSecondary / fillMuted | `#8E8E93` / `#AEAEB2` / `#E5E5EA` | `#8E8E93` / `#636366` / `#2C2C2E` | systemGray · Gray2 · Gray5 |
| border | `#E3E3E8` | `#38383A` | opaqueSeparator |
| **primary / onPrimary** | `#000` / `#FFF` | **`#FFF` / `#000`** | 주 버튼이 반전된다(애플 뮤직) |
| danger / dangerSurface | `#E5484D` / `#FDECEC` | `#FF453A` / 빨강 18% | systemRed |
| warning / warningSurface | `#8A5B00` / `#FFF3CD` | `#FF9F0A` / 주황 18% | systemOrange |

| chart | 6색 | 한 단계 밝게 · 기타 systemGray | |

- **색 값은 전부 JS** 다 — 네이티브 리소스(Android values-night)에 두면 색을 바꿀 때마다 빌드해야 한다. 바꾸는 법만 플랫폼별: iOS 는 `theme.color.*` 가 `DynamicColorIOS` 라 OS 가 즉시 다시 칠하고, Android 는 앱이 켜질 때 고른 팔레트로 칠한 뒤 모드가 바뀌면 JS 를 다시 불러 칠한다(설정에서 바꾸면 즉시, 시스템이 바뀐 것이면 앱이 앞으로 돌아올 때 — 재생 중이면 미룸). 네이티브는 `userInterfaceStyle: automatic` · `expo-system-ui` 뿐(runtime 34).
- **색 문자열이 꼭 필요한 곳**(SVG 아이콘·그라데이션·애니메이션 색 보간)은 `useThemePalette()` / `useResolvedColor()` 로 지금 모드의 값을 받는다 — iOS 의 `theme.color.*` 는 문자열이 아니다.
- **테두리·막 토큰**(2026-10-11 — 화면 코드에 박혀 있던 값 정리): `hairline`(검정 10% / 흰 14%) · `hairlineStrong` · `separator`·`separatorFaint`(iOS separator) · `fillTertiary`·`fillSecondary`(iOS tertiary/secondarySystemFill) · `divider` · `glassPillFill` · `glassRim`·`glassRimStrong`(다크에선 옅게) · `tabPillSolid` · `backgroundWash`(사진 칩을 배경 쪽으로 물리는 막 — 라이트 흰·다크 검정) · `onPrimarySecondary`. **`onPhoto`(두 모드 흰색)** — 사진·어두운 막 위 글자·아이콘·스위치 손잡이. `onPrimary` 는 다크에서 검정으로 뒤집혀 사진 위에 쓰면 안 보인다.
- 그대로 두는 고정 색: 소셜 로그인 버튼(카카오·네이버·구글·애플 브랜드 규정) · 그림자(검정) · 사진·썸네일 위 막과 흰 글자 · 첫 실행 튜토리얼 가림막 · 플레이어(원래 어두움).
- 사진 위 막(photoScrim)·플레이어(`playerColor`, 원래 어두움)는 두 모드 같다. 유리(GlassView)·블러(BlurView)·상태 바·내비게이션 바탕·루트 뷰 바탕은 모드를 따른다.

## 2. 모서리 (HIG: Layout — corner concentricity)

- **모든 둥근 모서리는 연속 곡률**(`borderCurve: 'continuous'`, iOS 만 적용·Android 는 원호). 원호는 곡률이 변 중간에서 갑자기 시작해 각져 보인다. 썸네일·카드·시트·다이얼로그·버튼·검색 상자 전부.
- 반지름 토큰: `radius.sm 8` · `md 12` · `lg 16` · `xl 24` · `full 999`.

| 대상 | 반지름 |
|---|---|
| 썸네일(격자 타일·대표 카드) | `lg` 16 / 대표 카드 안 커버는 카드가 클립 |
| 작은 썸네일(미니플레이어·시트·상세 72) | `sm` 8 |
| 검색 상자·문단·입력창 | `md` 12 |
| 다이얼로그·바텀시트(위 모서리) | `xl` 24 — **면이 클수록 반지름을 키운다**(같은 부드러움으로 읽히려면). **확인 다이얼로그는 32**(iOS 26 시스템 알림과 같은 결 — 2026-10-09) |
| 미니플레이어 카드 | 22 (`MINI_CARD_RADIUS`) — 캡슐 탭 바(높이 60)와 같은 결 |
| 캡슐(탭 바·세그먼트·**글자가 들어간 행동 버튼 전부**) | `full` |

- **텍스트 버튼 = 알약, 면 = 둥근 사각**(2026-10-06 KAN-146 "범위 B" — iOS 26 문법: 버튼은 캡슐, 면은 둥근 사각). **글자가 들어간 행동 버튼**(주·보조·파괴, 칩 모양의 [구독 알아보기]·[입력하기] 포함)은 `radius.full` + 연속 곡률이다. **둥근 사각 그대로인 것**: 입력창·카드·타일·배너·목록 행·토스트·스낵바·시트·다이얼로그 몸체·썸네일. **대상이 아닌 것**: 배경 없는 글자 링크형 버튼([건너뛰기] 등 — 모서리가 안 보인다), 아이콘 원형 버튼, 이미 알약인 칩. 종전(09-26~10-05)에는 버튼이 `md` 12 였고 화면마다 따로 정의해 알약·사각이 한 화면에 섞였다.
- **공용 알약 버튼 스타일은 `shared/ui/pill-button.styles.ts` 의 `pillButton`** 이다 — `base`(full + 연속 곡률 + 가운데 정렬) · 역할 면 `primary`(검정) · `secondary`(`surface`) · `destructive`(채운 빨강, 주 동작 자리만) · `destructiveSecondary`(`dangerSurface`) · 짝 글자 `primaryLabel`·`secondaryLabel`·`destructiveLabel`·`destructiveSecondaryLabel`. **모양과 역할 색만 여기서 정하고 크기(높이·폭·여백·flex)는 화면이 정한다** — 높이 44·52·56 은 화면마다 의도한 값이라 바꾸지 않는다. 쓰는 법은 `[pillButton.base, pillButton.primary, styles.<크기>, 비활성 && styles.<비활성 면>]` — 비활성 면이 역할 색을 덮도록 뒤에 둔다. 회색 면 위의 흰 알약([다시 시도]·[업데이트]·이메일 [등록])은 `base` + 화면의 흰 면이다. **새 텍스트 버튼은 화면에서 모서리를 새로 정의하지 말고 이것을 쓴다.**
- **동심원 규칙**: 안쪽 모서리 반지름 = 바깥 반지름 − 안쪽 여백. 캡슐 안 선택 알약(inset 4)이 `full` 인 것은 둘 다 반원이라 성립한다.
- 이미지에 라운드를 직접 주지 않는다 — expo-image 는 `borderCurve` 를 모른다. **프레임 View 가 라운드·클립**한다.

## 3. 재질 (HIG: Materials · Liquid Glass)

- **떠 있는 면은 유리다** — 미니플레이어 카드·탭 바 캡슐. `shared/ui/GlassSurface`: iOS 26+ 리퀴드 글라스(`expo-glass-effect`, regular · light), 그 밑 iOS·Android 는 블러 60 + 흰 틴트 72%(`expo-blur`). runtime 5 부터.
- 유리는 **밑에 지나가는 콘텐츠가 있어야** 유리다. 그래서 탭 바·미니플레이어는 목록 위에 절대 배치하고, 목록은 `useBottomDockInset()`(캡슐 + 카드 + 간격 8)만큼 바닥 여백을 둔다.
- **유리 위에 유리를 올리지 않는다**(WWDC25 Meet Liquid Glass — "Always avoid glass on glass … use fills, transparency, and vibrancy for the top elements"). 유리는 유리를 샘플링하지 않아 두 번째 유리는 밑의 유리를 건너뛰고 콘텐츠만 비춘다. **탭 바의 선택 알약은 유리가 아니라 캡슐 유리 위의 검정 8% 채움**이다(`GlassPill.lens`, 2026-09-24 저녁). 09-23~24 의 clear 렌즈(어두운 썸네일 위에서 검은 구멍)·regular 렌즈(회색 판)는 전부 이 규칙을 어긴 결과였다. 세그먼트의 알약은 바탕이 유리가 아니라 clear 유리 렌즈 그대로.
- **알약이 눌려 캡슐 밖으로 넘칠 때**(탭 바 1.3×) 채움은 캡슐 자리 안에만 그린다 — 캡슐의 유리·경계가 채움 아래로 그대로 비치고, 캡슐 밖으로 나간 부분은 **완전히 투명**하다(2026-09-24 PM). 구현: `GlassPill.lens` 에 캡슐 자리를 알약 로컬 좌표의 역변환(translate·1/scale)으로 준다. 떠오름은 림(흰 하이라이트 + 그림자)과 아이콘 확대가 보인다.
- 유리 위 경계는 hairline 윤곽(검정 10%) + 은은한 그림자(`0 4px 20px rgba(0,0,0,.10)`). 불투명 색을 유리 위에 깔면 유리가 사라진다 — 컨테이너는 `transparent`.
- 사진 위 표식(더보기 점·"새로운 주제" 글자)은 **스티커(불투명 원·알약)를 쓰지 않는다.** 아래 변 검정 그라데이션(투명→75%, 56pt) 또는 SVG 드롭섀도 필터로 읽히게 한다.

## 4. 움직임 (HIG: Motion)

원본 `shared/theme/motion.ts`. **여기 값 외의 `Easing.*`·기본 스프링을 쓰지 않는다.**

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `easing.easeInOut` | bezier(0.42, 0, 0.58, 1) | UIKit 기본. 길이가 정해진 대칭 전환 |
| `easing.easeOut` | bezier(0, 0, 0.58, 1) | 페이드·줄 이동·아이콘 회전·스와이프 퇴장 |
| `spring.smooth` | stiffness 195 · damping 28 · mass 1 (응답 ≈ 0.45s, 임계 감쇠) | 시트·패널처럼 큰 면 |
| `spring.snappy` | stiffness 440 · damping 42 · mass 1 (응답 ≈ 0.3s) | 세그먼트·탭 알약·시크 손잡이·복귀 |
| `spring.jelly` | stiffness 300 · damping 17 · mass 1 (감쇠비 ≈ 0.5, 한 번 넘쳤다 돌아온다) | **형태만** — 탭 알약의 부풀기·늘어남·복귀(iOS 26 버블). 위치에는 쓰지 않는다 |
| `duration.fast / normal` | 160 / 240ms | 짧은 전환 |

- **손이 관여하는 전환은 전부 스프링**이고, **놓는 순간의 속도를 `velocity` 로 넘긴다**(플레이어 시트). 던지면 빨리, 살살 놓으면 천천히. 끝점 overshoot 은 막는다(모션 레이어가 좌표 밖으로 튄다).
- **끌기는 1:1** — 시트가 손가락보다 빨리 달아나지 않는다.
- 선택 표시는 **하나가 미끄러진다**(세그먼트·탭 바 알약). 칸마다 켜고 끄지 않는다. 라벨 색은 알약이 지나가는 만큼 겹쳐(두 겹 텍스트 + 불투명도) 같은 프레임에 바뀐다.

### 상단 — 투명 시스템 바 + 콘텐츠 안 큰 제목 줄 (HIG: Navigation bars, iOS 26) — 라이브러리·탐색·검색
**애플은 상단을 "떠 있는 컨트롤"이 아니라 "바"로 만든다**(PM 2026-09-25 23:50 "애플이라면 상단을 어떻게" → "ㄱㄱ"). 떠 있는 유리 검색창·흰 칩은 어두운 카드가 밑에 오면 글자가 죽었고(23:48 실기기), 바 밑 블러는 바가 있어야 시스템이 그린다. 그런데 **UIKit 큰 제목(`.always`)은 바 버튼과 같은 줄에 못 둔다**(버튼은 위 줄, 큰 제목은 그 밑). ~~`.inline` 모드도 마찬가지~~ — **정정(09-28)**: 이 판단은 검증되지 않았다. react-native-screens 가 always/never 만 걸어 `.inline` 을 켜 본 적이 없었다. 애플 문서: `.inline` 은 "맨 위일 때 항상 큰 제목, 왼쪽·가운데 항목은 오버플로 메뉴로" — 큰 제목이 바 줄에 앉고 오른쪽 버튼과 같은 줄이다(아래 "시스템 큰 제목") — 애플 뮤직·앱스토어·팟캐스트 탭 화면은 그래서 **제목 줄을 콘텐츠로 직접 그린다**(09-26 00:29 PM 애플 뮤직 검색 탭 스샷: 큰 제목 "검색" + 프로필 원이 같은 줄, 검색창은 그 밑 채움 필드, 스크롤하면 바에 작은 "검색"). iOS 26 시스템 탭 바 갈래(`HAS_NATIVE_TAB_BAR`)의 라이브러리·탐색·검색 탭은 이 문법이다:
- **바는 투명 시스템 바**(`NativeMainTabs` `TRANSPARENT_BAR`: `headerTransparent`, 제목 없음, 그림자 없음 — 09-28 01:40 PM "애플에서 기본적으로 제공하는거로"로 되살렸다). **큰 제목 줄은 바 밑에서 시작한다** — 목록은 `contentInsetAdjustmentBehavior="automatic"` 으로 상태 바 + 바 줄(44)을 비우고, 스크롤 뷰가 아닌 상태 화면·검색 겹침도 같은 값(`useNativeHeaderInset` = 상태 바 + 44)을 비운다. 제목 줄을 바 줄 자리로 끌어올리면(종전 marginTop −44) UINavigationBar 가 그 자리의 터치를 먹어 링·필터가 안 눌렸다(09-26 17:42) — 그래서 끌어올리지 않는다. 대가는 정지 때 제목 위 빈 바 줄(44)이고, 애플 뮤직 iOS 26 보관함도 버튼 줄 밑에 큰 제목이 앉는다. - **큰 제목 줄은 콘텐츠의 첫 줄**(`shared/ui/LargeTitleRow`: 34pt bold = `font.size.xxl`, 높이 52, 오른쪽 `trailing`). 라이브러리는 링 + 필터 툴바 캡슐, 탐색은 잔여 링, 검색은 없음 — **제목과 컨트롤이 같은 줄**(00:25 PM "높이 맞추자"). 목록과 같이 스크롤한다.

### 떠 있는 머리 줄 (HIG: Liquid Glass — 콘텐츠 위의 컨트롤 층)
Android 하단 캡슐 탭은 손가락이 닿는 즉시 화면과 선택 알약을 함께 선택한다(2026-09-30 PM "길게 눌러도 선택 알약이 바로"). 손을 뗄 때 단순 탭 이벤트를 중복 발행하지 않아 같은 탭의 맨 위 이동도 한 번만 처리한다. 끌기는 누른 칸을 기준으로 따라가며 놓은 칸을 선택한다. `tabPress`가 취소되면 화면·알약 모두 현재 탭을 유지한다. iOS의 기존 누름 동작은 유지한다.
Android 설정의 큰 제목은 뒤로 버튼 줄 바로 아래에서 시작한다(2026-09-30 PM). 목록 상단 인셋은 `상태 바 + 버튼 줄 52`이며, 종전의 추가 16pt를 제거해 제목을 16pt 올린다. iOS 시스템 제목은 UIKit 배치를 유지한다. 버튼 크기·히트 영역·제목 아래 섹션 간격은 그대로다.
Android 탐색 검색도 iOS 26처럼 **제자리 검색**으로 연다(2026-09-30 PM). 큰 제목 "탐색"과 [잔여 링 | 닫기 ✕] 캡슐 아래에 채움 검색 필드를 고정하고 자동 포커스한다. 피드는 마운트된 채 덮어 스크롤·필터를 유지하고, 덮인 피드의 터치·접근성 탐색은 막는다. 닫기와 시스템 뒤로가기는 퇴장 모션 뒤 검색 상태를 버린다(키보드가 열린 상태의 첫 뒤로가기는 OS가 키보드를 닫을 수 있다). 탭 바·미니플레이어는 기존 독 하나만 유지한다. iOS 26 미만·웹의 스택 검색은 유지한다.
Android의 스크롤 접힘 상단바(`AndroidCollapsingBar`, 설정·탐색·라이브러리)는 블러 위에 미니플레이어와 같은 **밝은 틴트 72%**(`theme.color.frostedSurface`, `rgba(245,245,247,0.72)`)를 얹는다(2026-09-30 PM "너무 글자가 잘 안 보인다"). 기존 흰 12% 덮개를 강화해 뒤 콘텐츠와 제목의 대비를 확보한다. 틴트는 기존 접힘 진행도에 따라 바 배경과 함께 나타나며, 맨 위의 투명 상태·블러 강도 25·제목·컨트롤·iOS 시스템 바는 유지한다.
Android 제목과 잔여 횟수 숫자는 `includeFontPadding: false`로 기본 글꼴 여백을 제거한다(2026-09-29). 제목은 34·700을 유지하고 줄 높이 42로 한글 획의 여유를 확보하며, 숫자는 기존 11·700·줄 높이 13을 유지한다. 두 텍스트 모두 세로 중앙 정렬로 알약·링과 맞춘다.

**Android 글꼴 굵기는 iOS 코드의 역할별 값을 따른다**(2026-09-29 PM "iOS 굵기 분석해서 안드로이드에 적용"). `shared/ui/Typography`의 Text·TextInput·AnimatedText를 사용하며, Android만 Pretendard 1.3.9의 실제 400·500·600·700 파일에 연결한다. iOS·웹은 React Native 원본을 그대로 내보낸다. `FontProvider`는 앱 진입 때 로드하고, 로딩 중·실패 시 시스템 글꼴로 계속 표시한다. 중첩 Text의 굵기 상속·조건부 스타일·숫자 폭 설정·입력 ref·네이티브 애니메이션을 유지한다. 명시한 다른 fontFamily·기울임·지원하지 않는 굵기는 덮지 않는다. 서체가 달라 광학적 두께까지 동일하다는 뜻은 아니며, OS 접근성 굵게 설정의 실기기 비교는 별도다.

### 탭 바 — 떠 있는 캡슐 (HIG: Tab bars, iOS 26)
선택된 하단 탭을 다시 누르면 현재 화면의 세로 목록이 부드럽게 맨 위로 이동한다(2026-09-28). 라이브러리·탐색·프로필에 공통 적용하며, 탐색 제자리 검색 중에는 검색 목록을 올린다. 다른 탭으로 이동하거나 캡슐을 끌었다가 같은 칸에 놓는 동작은 스크롤 위치를 초기화하지 않는다. 시스템 헤더가 있는 목록은 상단 인셋까지 복원한다(`useTabScrollToTop`).
**iOS 26 은 시스템 탭 바를 쓴다**(`app/navigation/NativeMainTabs`, `HAS_NATIVE_TAB_BAR` — 2026-09-24 밤 PM "애플이 기본으로 제공하는 애니메이션 없나"). `@react-navigation/bottom-tabs/unstable` 의 `createNativeBottomTabNavigator` = `UITabBarController`(react-native-screens BottomTabs). 선택 알약의 부풀기·끌기·굴절·색수차·끝 넘김 고무줄이 애플 코드 그대로고, 이건 비공개 API 라 흉내낼 수 없다(아래 캡슐의 형태 스프링은 그 밑 OS 용이다). 미니플레이어는 `bottomAccessory`(Music 앱 자리 — 탭 바 위) 로 들어가고 유리·폭·높이·모서리는 시스템이 준다. **액세서리는 항상 마운트하고, 볼 게 없으면 숨긴다**(`useIsMiniPlayerVisible` → `tabBarAccessoryHidden`, 09-25 23:03). 숨김·표시 전환은 시스템 애니메이션(`setBottomAccessory(nil/accessory, animated:)` — 탭 바로 거둬들이고 솟아나는 유리 병합, "닫을 때 물방울처럼"). 언마운트 방식은 RNS 가 내용을 먼저 떼 애니메이션이 멈췄고(22:29), 내용만 비우면 빈 유리 껍데기가 남았다(22:56). React Navigation 이 RNS 의 `bottomAccessoryHidden` 을 옵션으로 안 넘겨 **`patches/@react-navigation+bottom-tabs`**(patch-package, postinstall)로 `tabBarAccessoryHidden` 을 뚫었다 — 패키지를 올릴 때 패치가 깨지면 `npm run postinstall` 이 알려 준다. **미니플레이어는 닫을 수 없다**(09-25 23:24 — 애플 뮤직과 같다. 시스템 액세서리는 껍데기가 합쳐지는 퇴장 모션이 없어 내용만 사라지는 게 더 어색했다; `changes/archive/mini-player-not-dismissable.md`). 위로 끌어 열기만 남는다. 숨김은 볼 게 없을 때(세션·스냅샷 없음)만 — 내용은 높이를 채워 세로 가운데, 썸네일 36·행 위아래 4(카드의 40·6 보다 작게. 09-24 밤 "아래 공백이 크고 썸네일이 큼"), 진행바는 위 변. 아이콘은 SF Symbols(`books.vertical`·`safari`·`person`, 선택 시 `.fill`). 배경·알약 색은 iOS 26 에서 바꿀 공개 API 가 없다 — 시스템 값이 곧 0장 원칙이다. 목록 바닥 여백은 시스템 안전영역(탭 바 + 액세서리)을 `contentInsetAdjustmentBehavior="automatic"`(`DOCK_SCROLL_PROPS`)이 비운다. `tabBarMinimizeBehavior: none` — 최소화는 껐다(09-25 18:00: 줄어드는 유리 모핑 중간 프레임이 큰 아이콘 잔상으로 남고, screens 의 최소화 + 액세서리 + 모달 조합 버그 #4176 로 액세서리가 굳는다. 목록도 그만큼 길지 않다).

### 시트·다이얼로그 (HIG: Sheets, Alerts)

**바텀시트 바닥 여백 — Android 버튼 내비게이션 바**(2026-10-10 PM): 시트마다의 바닥 여백(xl 32)은 iOS 홈 인디케이터·Android 제스처 바엔 맞지만 3버튼·2버튼 바(~48dp)엔 모자라 마지막 버튼이 가려졌다. 공용 `BottomSheet` 가 그 기기에서만 바 높이(insets.bottom)만큼 시트 면을 늘린다. 제스처 바·iOS 는 그대로.

**아래에서 올라오는 시트는 공용 `shared/ui/BottomSheet` 하나가 그린다**(2026-09-27 19:41 PM "아래에서 뜨는 모달 애니메이션이 부자연스럽다") — RN `Modal` 의 `animationType="slide"` 는 **딤까지 통째로 밀어 올려서** 어두운 사각형이 시트와 함께 솟아올랐고 곡선도 RN 고정값이라 `motion` 토큰과 어긋났다. 공용 셸은 **딤은 제자리 페이드, 시트만 자기 높이만큼 `spring.smooth` 로 올라온다**(닫힐 때 `duration.normal` + `easeInOut`). 나가는 모션을 보이려면 `isVisible` 이 false 가 된 뒤에도 잠시 붙어 있어야 해서 셸이 `isMounted` 를 따로 들고, `onClosed` 는 **모달이 실제로 내려간 뒤**(`Modal onDismiss`, iOS) 불린다 — 더보기 시트의 공유가 그 순서에 매달려 있다(`useDeferredSheetShare`). **아래로 끌면 닫힌다**(2026-09-27 19:55 PM "맨 위 팁 스와이프 내리면 내려가게") — 시트 어디서든(맨 위 손잡이 포함) 손가락을 따라 내려가고 **딤도 같이 밝아진다**(끌기가 `progress` 를 직접 움직이므로 놓는 순간의 값에서 이어서 닫혀 튐이 없다). 임계는 높이의 1/4(최소 80pt) 또는 던진 속도 0.8. 가로보다 세로가 큰 6pt 이상 움직임만 가져오고, 버튼은 탭을 먼저 받는다(capture 아님). **내려가는 동안 내용을 붙잡아 둔다**(2026-09-27 21:00 PM "내려갈 때 애니메이션이 이상하다") — 대상이 사라지면(`item = null`) 내용이 먼저 지워져 **빈 상자만 미끄러진다**. 더보기 시트는 마지막으로 열렸던 항목을 상태로 들고 있고 보일지 여부만 prop 이 정한다. 쓰는 곳: 더보기 3종(탐색·라이브러리·플레이어) · 라이브러리 필터 · 배속 2종 · 수면 타이머.

위 모서리 `xl` + 연속 곡률. 버튼은 **알약**(`full` + 연속 곡률, §2 — 2026-10-06 KAN-146, 종전 `md`). 기본 동작은 검정 채움, 보조 동작은 `surface` 면(테두리 없음). **이 버튼 규칙은 다이얼로그만이 아니라 버튼 줄을 가진 모든 곳에 적용된다** — 라이브러리 필터 시트의 [초기화]·[적용], 콘텐츠 상세의 [재생]·[담기/빼기]까지(2026-09-27 PM "저 버튼 다른 모달들이랑 살짝 다르다" — 그 둘만 테두리로 남아 있었다). **파괴적 확인의 주 동작은 채운 빨강**(`color.danger` 면 + 흰 글자)이다 — 로그아웃 확인 팝업(2026-09-28 PM, iOS 확인 시트의 [삭제]·SwiftUI `.borderedProminent` + red tint). **단 iOS 로그아웃 확인은 2026-10-07 부터 시스템 알림창**(`Alert.alert` destructive — PM "애플처럼"), 채운 빨강은 Android 에만 남는다. `ConfirmDialog` 의 `primaryAction.isDestructive` 로 켠다. 다만 **저장 전 로컬 편집만 버리는 [나가기]** 에는 쓰지 않는다 — 커리어·관심사 이탈 확인은 서버 상태가 그대로라 파괴적으로 그리면 나가기를 겁내게 된다(`interest-management-uiux.md` 4.6 금지 항목). 파괴적 **보조** 동작(상세의 [빼기])은 **연한 빨간 면(`color.dangerSurface`) + 빨간 글자**다(2026-09-28 PM — iOS 의 `.bordered` + red tint 가 이 모양이다). **채운 빨강(`danger`)은 쓰지 않는다** — 검정 주 동작보다 더 튀어 주·보조가 뒤바뀐다. 시트의 삭제 **행**(더보기 3종)은 버튼이 아니라 목록 항목이므로 면 없이 빨간 글자만 둔다(iOS 액션 시트와 같다). **확인 다이얼로그 구현은 `shared/ui/ConfirmDialog` 하나**(2026-09-27 — career·interest·settings 의 자체 다이얼로그는 이 컴포넌트의 껍데기로 바꿨다. 09-26 의 surface 규칙이 그쪽 셋엔 안 닿아 테두리 버튼이 남아 있었다, PM "4,5,6 을 1,2,3 에 맞춰"). 제목 생략·본문 슬롯·딤 탭 차단(`dismissOnBackdrop`)·버튼 비활성은 prop. **알리기만 하는 팝업은 버튼 하나**(`secondaryAction` 생략 — 주 동작이 버튼 줄을 채운다, 2026-10-05 가입 체험 안내 P11): HIG Alerts 의 정보 전달 알림 문법이다. 고를 것이 없는데 [취소]를 나란히 세우면 "무엇을 취소하나"로 읽힌다. 이때 딤 탭·뒤로가기는 주 동작과 같다. 세 번째 선택지("오늘은 그만 보기" 류)는 버튼 줄에 세우지 않고 **제목 줄 오른쪽 위 작은 회색 글자**(xs, 밑줄 없음, hitSlop 으로 44pt). 탭 가능한 글자에 밑줄을 쓰지 않는다 — 웹 문법이다.

### 세그먼트 컨트롤 (HIG: Segmented controls)
**탐색 주간·월간·전체(`PopularPeriodToggle`)는 iOS 에서 시스템 `UISegmentedControl` 그대로다**(2026-09-26 02:19 PM "iOS 26 에서 쓰이는 기본 토글로") — 로컬 네이티브 모듈 `modules/system-segmented-control`(runtime 11)이 색·글꼴·모서리를 하나도 손대지 않고 노출한다. iOS 26 에서는 OS 가 그리는 유리 선택바(탭하면 선택 칸이 미끄러진다)이고, OS 가 바뀌면 같이 바뀐다. 크기는 Yoga 가 모르므로 호출부가 준다(높이 32 = iOS 기본, 칸 52×3). 선택 칸의 기준은 여전히 서버 응답 `selected` — 시스템은 탭 즉시 스스로 움직이므로, 비활성 중 탭·전환 실패로 `selected` 가 안 바뀌면 `key` 로 다시 그려 되돌린다(uiux explore 4.10). `enabled` 는 내리지 않는다(시스템이 흐리게 그려 전환마다 깜빡인다). JS 재현 세 가지(`glass`·`system`·`modern`)는 iOS 26 실기기에서 전부 "옛날 것 같다"는 평을 받았고, 시스템 컨트롤이 답이었다 — **시스템에 같은 부품이 있으면 흉내 내지 말고 그 부품을 쓴다**(탭 바를 iOS 26 시스템 탭 바로 바꾼 것과 같은 결론). Android·모듈 없는 빌드는 아래 `modern` 으로 내려간다.

`shared/ui/SegmentedControl`(JS) — 탐색 토글의 Android·폴백(칸 48×26)은 **`appearance="modern"` — iOS 26 앱들의 캡슐 선택바**(2026-09-25 23:30 PM "현대식 애플 선택바처럼, 기본 세그먼트는 옛날 것 같다"): 완전 둥근 트랙(tertiarySystemFill, 안쪽 3) 위에 **선택 칸은 검정 채움 알약 + 흰 글자**, 비선택은 회색 13pt semibold. 그림자·유리 없음 — 메일 카테고리·피트니스 기간 선택 문법. 콘텐츠 층의 세그먼트는 애플도 유리를 안 쓴다(유리는 내비게이션 층). 22:12 의 `system`(UISegmentedControl 모양: 모서리 9 트랙 + 그림자 흰 칸)은 한 시간 만에 "옛날 것 같다" 로 대체됐고 모양은 남아 있다. `glass` 모양도 남아 있다. **라이브러리의 전체·미청취·완청은 세그먼트가 아니다**(2026-09-25 PM "애플이었으면") — HIG: 세그먼트는 뷰 전환용이고 같은 목록의 콘텐츠 필터에는 쓰지 않는다. 팟캐스트·메일처럼 **필터 시트의 라디오**로 옮기고(`TopicFilterSheet` 상태 섹션), 머리 줄엔 필터 원 버튼 + 조건 요약 한 줄만 둔다(`changes/archive/library-status-filter-in-sheet.md`). `segmentHeight` prop 은 남아 있다. 밑줄 탭은 iOS 문법이 아니다 — 배타적 뷰 전환은 항상 이 부품. 흰 트랙 + 테두리, 같은 폭 칸, 선택 알약 하나(iOS 26 유리 렌즈 `GlassPill`, 그 밑은 그림자로 뜬 흰 알약)가 snappy 스프링으로 이동, 라벨 굵기는 선택과 무관하게 같다(폭이 변하면 흔들린다).

### 주간 청취 카드 (2026-09-27)
프로필의 주간 청취는 건강 앱의 정보 위계를 참고해 **카드 안 보조 라벨과 날짜 이동 → 하루 평균 → 그래프**로 읽는다. 보조 라벨은 프로필 카드 라벨과 같은 `xs`·`textSecondary` 문법을 쓴다. 제목과 주 이동 컨트롤은 카드의 같은 머리 줄에 두고, 제목은 왼쪽, 날짜 범위와 양쪽 버튼은 오른쪽에 둔다. 콘텐츠 카드에는 유리가 아닌 `surface` 면과 `xl` 연속 곡률을 쓴다(§1~3). 날짜 양쪽 이동 버튼은 흰 원 44pt이며 날짜와 버튼 사이는 `md` 간격이다. 평균은 34pt 숫자와 보조 라벨, 그래프는 검정 막대·옅은 격자·평균 점선이다. 요일 선택은 세로선과 채운 요일 알약으로도 구분한다. 값 말풍선은 그래프 위 예약 영역에서 폭·높이를 실측해 가장자리와 큰 글씨를 수용한다. 요일 터치 영역은 44pt 이상이며 아주 좁은 화면에서만 그래프를 가로 스크롤한다. 로딩·빈 기록·오류도 같은 카드 안에 둔다. 주 이동과 집계 계약은 그대로이며 네이티브 부품이나 새 애니메이션은 추가하지 않는다.

### 설정 목록 (2026-09-28)
흰 화면 위에서 섹션마다 `surface` 면과 `xl` 연속 곡률로 항목을 묶는다. 바깥 여백과 행 안쪽 여백은 각각 `md`, 섹션 제목은 행 글자 시작점에 맞춘 `xs`·`textSecondary`다. 일반 행과 토글 행은 최소 56pt, 이동 표시는 16pt `ChevronIcon`, 우측 값은 굵게 강조하지 않는 `sm` 보조색이다. 긴 값은 줄바꿈하고 숫자는 고정 폭으로 정렬한다. 이메일 등록·재시도·업데이트 버튼은 흰 면 **알약**(`pillButton.base`, §2 — 2026-10-06, 종전 `md`), 최소 44pt 터치 영역을 쓴다. 네이티브 스위치의 켜짐은 모노톤 강조를 따른다. 알림 안내와 구독 요약은 그룹 면 안에 놓고 별도 카드 여백을 중첩하지 않는다. 개발계 진단은 마지막 별도 섹션에 둔다. 상단 로딩도 같은 그룹 골격을 쓰며 구독 기능이 꺼져 있으면 구독 스켈레톤을 그리지 않는다. 그룹 부품은 `shared/ui/InsetGroup`(2026-10-10 — 설정의 `SettingsSection` 을 공용으로 올렸다, 설정 안 이름은 재export).

### 스켈레톤 — 내용을 기다리는 자리 (2026-10-06, KAN-140)
화면·영역의 **내용**을 불러오는 동안은 스피너가 아니라 곧 나타날 레이아웃 모양의 스켈레톤을 그린다(HIG Loading 의 취지 — 빈 화면으로 기다리게 하지 말고 가능한 한 빨리 무언가를 보여 준다). 무엇이 올지 미리 보여 체감 대기가 줄고, 내용이 들어올 때 화면이 튀지 않는다.

| 상황 | 표현 |
|---|---|
| 화면·영역의 **내용**을 처음 불러오는 중(목록·칩 줄·카드·대본·대기열·온보딩 진입) | **스켈레톤** |
| 버튼을 누른 뒤 **액션**이 진행 중(저장·제출·로그인·탈퇴 처리·완료 요청) | 스피너 — 버튼 안, 또는 처리 중 전체 화면 |
| 목록 끝 다음 페이지(무한 스크롤 하단) | 작은 하단 스피너 |
| 내용이 **이미 화면에 있고** 새로 받는 중(당겨서 새로고침, 직전 검색 결과를 흐리게 둔 채 다음 질의) | 스피너 — 스켈레톤으로 바꾸면 보던 내용이 지워진다 |
| 기다림 자체를 안내하는 화면(첫 드립 준비 `FirstDripWaitingScreen`) | 스피너 + 안내 문구 그대로 |

- **공용 블록만 쓴다** — `shared/ui/Skeleton`: `SkeletonGroup`(로딩 영역 하나) 안에 `SkeletonBlock`(사각) · `SkeletonLine`(글자 한 줄) · `SkeletonCircle`(원)을 실제 레이아웃과 **같은 치수·간격**으로 놓는다. 화면마다 `View` 에 회색을 칠해 따로 만들지 않는다 — 색·모서리·반짝임이 화면마다 갈린다.
- **모양** — 면은 `color.surface`(흰 바탕 위). 바탕이 이미 `surface` 인 카드 안(주간 청취 카드)은 한 단 진한 `color.border`, 플레이어는 `playerColor.skeleton`(반투명 흰색 — 바탕이 차콜이거나 흐린 커버라 불투명 회색은 밝은 커버에서 묻힌다)을 `SkeletonGroup color` 로 넘긴다. 모서리는 대신하는 요소의 반지름 그대로(썸네일 `lg`·작은 썸네일 `sm`·칩 `full`·카드 `md`/`xl`), 글자 줄은 높이 = 글자 크기 · `sm` 모서리 · 마지막 줄은 짧게. 전부 연속 곡률(§2). 버튼처럼 **상태를 모르는 액션은 그리지 않는다**(담김 여부를 모르는 상세의 [담기] 등).
- **모션** — 영역 전체의 불투명도가 1 ↔ 0.5 를 **0.8초씩 `easeInOut` 으로 왕복**한다(느린 숨쉬기). 블록마다가 아니라 **영역마다 루프 하나**, `opacity` 만 네이티브 드라이버(§4 — 상시 도는 애니메이션). 가로로 훑는 빛 띠(그라데이션 shimmer)는 쓰지 않는다 — 마스크·그라데이션이 필요하고 iOS 시스템 placeholder 도 쓰지 않는다.
- **동작 줄이기**(iOS "동작 줄이기" · Android "애니메이션 삭제")가 켜져 있으면 숨쉬기 없이 **정지한 블록**만 그린다. 설정값을 아직 모르는 첫 순간도 정지 쪽이다(`shared/hooks/useReduceMotion`).
- **0.3초 미만이면 그리지 않는다**(`common-error-handling.md` 5 — 깜빡임 방지). `useDelayedVisible(isLoading)` 로 감싸고, 그 전에는 **같은 높이의 빈 자리**만 둔다(칩 한 줄 등) — 스켈레톤이 늦게 떠도 아래가 밀리지 않게.
- **접근성** — 블록은 각자 낭독에서 빠지고(`accessibilityElementsHidden` · `no-hide-descendants`), 영역(`SkeletonGroup`)에 라벨 **하나**("불러오는 중", 무엇인지 밝힐 카피가 있으면 그것 — 예: "대본을 불러오는 중")와 `progressbar` 역할·`busy` 상태를 둔다.

**행 안의 정렬 두 가지**(2026-09-28). ① **세로는 가운데**다 — 200% 글꼴의 두 줄 배치를 위해 `flexWrap` 을 쓰는 행은 `alignItems` 가 줄의 위치를 정하지 못하므로 `alignContent: 'center'` 를 함께 준다(RN 기본값 `flex-start` 라 최소 높이만큼 위로 붙는다). ② **끝선은 바깥 여백(16)에 맞춘다** — 셰브론 도형은 박스 안에서 오른쪽이 비어 있어(24 viewBox 중 7) 그대로 두면 스위치·글자 버튼보다 안쪽으로 들어가 보인다. `chevronTrailingGutter(size)` 만큼 음수 여백으로 당겨 **보이는 끝**을 같은 선에 세운다.

## 6. 터치·접근성 (HIG: Accessibility)

- 눌리는 영역 44×44pt 이상. 보이는 크기를 줄일 땐 `hitSlop` 으로 채운다.
- 사진 위 표식·바에는 반드시 낭독기 라벨("N% 들음"·"완청한 콘텐츠"·"새로운 주제").
- 장식 요소는 `accessibilityElementsHidden` + `importantForAccessibility="no"`.

## 7. 바꿀 때의 절차

1. HIG 에 해당 항목이 있으면 그 값·문법을 먼저 따른다. 없으면 이 문서의 결에 맞춘다.
2. 새 값은 **토큰·상수 한 곳**에 둔다(`theme`, `motion`, 컴포넌트 상단 상수). 리터럴을 흩뿌리지 않는다.
3. 실기기에서 보고 조절한다 — 값은 대부분 실물 튜닝 대상이다. 조절한 값과 이유를 코드 주석에 남긴다.
4. 이 문서를 같이 고친다. 문서와 코드가 다르면 다음 사람이 어느 쪽을 믿을지 모른다.

## 8. 미결

- 다크 모드 — 토큰만 참조하도록 강제해 두었다(convention.md). 플레이어는 이미 어둡다.
- `prefers-reduced-motion`(iOS "동작 줄이기") — 스프링·시트 모션을 페이드로 대체하는 분기가 없다. 설정을 읽는 훅(`shared/hooks/useReduceMotion`)은 생겼고 스켈레톤이 처음 쓴다(2026-10-06) — 다른 모션도 이 훅으로 분기하면 된다.
- 플레이어 화면 안 컨트롤 영역의 유리 적용 — 흐린 커버 바탕 위라 실물로 판단한다.
- 안드로이드에서 연속 곡률·리퀴드 글라스는 없다 — 원호·블러로 폴백된다. 안드로이드 전용 재질 규칙은 정하지 않았다.
