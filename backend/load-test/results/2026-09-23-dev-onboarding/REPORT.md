## 0. 먼저 — 앞의 세 번은 옛 이미지에서 돌았다

테스트 준비로 Sentry 샘플링을 0으로 내리려고 `docker compose … up -d --no-build api` 를 쳤는데, **`API_IMAGE` 를 주지 않아 컨테이너가 서버에 남아 있던 2026-09-15 로컬 빌드 이미지(`ear-prod-api`)로 재생성됐다.** 에러가 없어 알아채지 못했고, 램프 A · A2 · "B" 는 그 옛 코드(클러스터 진입점·Sentry 없음) 위에서 돌았다. "B" 는 클러스터를 켰다고 믿었지만 단일 프로세스였다 — 파일을 `ramp-single-high-2` 로 바꿨다.

발견 뒤 `API_IMAGE=$(cat .api-image)` 로 현재 이미지(`85c41aa`, dev HEAD)를 띄워 **클러스터 2(B)** 와 **단일 프로세스(A3)** 를 다시 쟀다. 옛 이미지 결과는 버리지 않고 **코드 비교용**으로 남긴다 — 덕분에 현재 코드가 온보딩 경로에서 얼마나 무거워졌는지가 드러났다(3장). 재발 방지는 `docs/infra/runbook.md` 4장.

## 1. 한 줄 결론

**현재 코드 기준, 가입 몰림은 단일 프로세스에서 분당 약 600명, 클러스터 2에서 약 900명까지 지연 없이 받는다.** 그 위로는 응답이 길어질 뿐 **실패는 0 이다**(분당 1,600명까지 5xx·429 없음, 온보딩 완료 100%). 광고 규모(설치 수천 건/캠페인)와는 두 자릿수 차이라 **가입 경로는 캠페인의 병목이 아니다.**

다만 **온보딩 경로가 2026-09-15 빌드보다 약 1.7배 무거워졌다** — 같은 분당 600명에서 API CPU 50% → 70~93%. 어느 변경 때문인지는 프로파일링이 필요하다(3장, BE 티켓 감).

## 3. 그래서 무엇을 하는가

1. **광고 대비로는 충분하다.** 분당 600명(시간당 3.6만)은 캠페인 규모를 한참 넘는다. 순간 스파이크(인플루언서 게시 등)에서도 실패가 아니라 지연으로 무너지고, 첫 드립은 늦게라도 전부 완료된다.
2. **온보딩 경로 회귀를 BE 티켓으로 잰다.** 09-15 → 09-23 사이 이 경로에 닿은 변경 후보: Sentry SDK 계측(`@sentry/nestjs` — 샘플링 0 이어도 http·pg 훅은 걸린다), 재생 목록 순서(KAN-70·74·75 — 라이브러리 적립 시 순서 계산), 콘텐츠 통계(#589), 임베딩 적재(KAN-89 — 추천이 읽는가?). **프로파일 없이 짚지 않는다** — 로컬에서 같은 시나리오를 `clinic`/`--cpu-prof` 로 돌려 함수 단위로 본다. 중요도 Low(캠페인 상한과 무관, 다만 청취 경로에도 같은 변경이 닿았을 수 있어 그쪽 재측정을 함께).
3. **운영 클러스터링 결정은 그대로다.** 온보딩에서도 1.3~1.4배. 켜기 전 `dev → main` 릴리즈(#586 레이트 리밋)가 먼저다(`scaling.md` 5.4).
4. **재생성 함정을 막았다.** `API_IMAGE` 없는 재생성이 옛 이미지로 빠지는 문제 — runbook 4장에 적었고 개발계의 옛 로컬 이미지는 지웠다(운영은 이날 image prune 으로 이미 없음).

## 4. 절차 기록 (재현용)

```bash
# 서버(개발계) — 계정 시드·토큰. 재생성 뒤에는 compose cp 를 다시 해야 한다(컨테이너 /tmp 는 휘발)
API_IMAGE=$(cat .api-image) docker compose -f docker-compose.prod.yml --env-file .env.prod cp /tmp/lt api:/tmp/lt
X="docker compose -f docker-compose.prod.yml --env-file .env.prod exec -T -e NODE_PATH=/app/node_modules api"
$X node /tmp/lt/seed-signups.js --count 4500 > /dev/null && $X node /tmp/lt/issue-tokens.js --ttl 2h > /tmp/tokens.json

# PC — 실행마다 ACCOUNT_OFFSET 을 옮긴다(완료한 계정은 다시 못 쓴다)
k6 run -e BASE_URL=https://api-dev.earcast.co.kr/api/v1 -e RATES=600,900,1200,1600 -e STEP_DURATION=1m \
  -e ACCOUNT_OFFSET=<지금까지 쓴 수> -e PREALLOC_VUS=200 -e MAX_VUS=600 \
  --summary-export=results/<날짜>/ramp-x.json k6/scenarios/onboarding-signup-ramp.js

# 정리 — 멱등키까지(cleanup-users.js 가 함께 지운다, 2026-09-23)
$X node /tmp/lt/cleanup-users.js --yes
```

- 서버 표본(15초): `docker stats` + `vmstat` idle + `pg_stat_activity` + `first_drip_jobs` 상태 분포 — `server-stats.log` 형식. 표본 루프를 `pkill -f <스크립트명>` 으로 죽이면 **같은 문자열이 든 ssh 셸까지 죽는다** — PID 로 죽인다.
