# AI 콘텐츠 제작 — 주제 발굴에서 업로드 패키지까지

명세는 [`docs/ai/pipeline.md`](../../../docs/ai/pipeline.md)다. **이 스킬은 그 명세의 구현이며, 명세와 어긋나면 스킬이 틀린 것이다.** 규칙을 바꿔야 하면 명세를 먼저 고친다.

## 원칙

- **게이트 두 개를 사람이 지킨다.** 주제 승인(A 다음)과 최종 검수(F 다음). 이 지점에서 임의로 진행하지 않는다.
- **소스 없이 쓰지 않는다.** 근거 소스 3건 미만이면 대본을 만들지 않고 반려한다. 내 지식으로 메우지 않는다.
- **QA를 스스로 채점하지 않는다.** E단계는 반드시 별도 에이전트로 돌린다(4단계 설명 참조).
- **통과를 만들어내지 않는다.** QA 3회 실패는 `review_required`다. 기준을 낮춰 통과시키지 않는다.
- 커밋·푸시는 하지 않는다. 산출물은 `runs/` 아래 파일로만 남긴다.

## 필요한 도구

`WebSearch` · `WebFetch`(소스 수집) · `Agent`(QA 분리) · `Write`/`Read`. 웹 접근이 불가능하면 2단계의 폴백으로 간다.

## 절차

### 0. 대상 주제 확인

1. `$topic` 인자가 있으면 그 주제, 없으면 AskUserQuestion으로 묻는다.
2. **`topics`에 있는 중분류인지 확인한다.** 현재 목록:

   | 대분류 | 중분류 |
   |---|---|
   | 일 | 커리어 · 생산성 · 리더십 · 커뮤니케이션 |
   | 돈 | 재테크 · 경제 상식 |
   | 배움 | 글쓰기 · 데이터·AI · 심리학 · 인문·교양 |

   목록에 없으면 진행하지 않는다 — 주제는 관리자 화면에서 먼저 만든다(FR-38).
3. **커리어·리더십이면 진행하지 않는다.** 명세 2.1의 배제 사유(개인 경험 서술이 지배적이라 소스 대조를 걸 대상이 없다)를 밝히고, 파트너 콘텐츠 수급이 유일한 경로임을 안내한다. 같은 `일` 대분류라도 **생산성·커뮤니케이션은 대상이다** — 대분류로 판단하지 않는다.
4. 작업 디렉토리를 만든다: `runs/{YYYY-MM-DD}-{topic-slug}/`. 날짜는 `date +%F`로 구한다.

### 1. 주제 후보 제안 (Phase A)

`runs/.../topic-candidates.md`에 후보 5건(또는 요청 개수)을 쓴다. 후보 1건의 구성:

| 항목 | 내용 |
|---|---|
| 제목(안) | 낭독 콘텐츠 제목. 클릭베이트 금지 |
| 한 줄 요지 | 이 편이 전달하는 것 |
| 타깃 적합성 | 편도 30분 통근하는 20대 후반~30대 초반 주니어 직장인에게 왜 유효한가 (PRD 3.1) |
| 근거 소스 방향 | 어떤 종류의 소스로 뒷받침할 수 있는지 |
| 중복 위험 | 기존 발행분·과거 실행분 대비 겹침 |

- **에피소드 단위로 쪼갠다.** 중분류 자체("재테크")가 아니라 한 편이 될 크기여야 한다.
- **중복 회피**: 기존 발행 콘텐츠 제목 목록을 사용자에게 요청하고, 같은 주제의 과거 `runs/` 디렉토리도 함께 대조한다. 목록을 받지 못하면 **"발행분과 대조하지 않았음"을 산출물 상단에 명시한다** — 대조한 척하지 않는다.
- **★게이트 1** — 후보를 제시하고 AskUserQuestion으로 승인을 받는다. 승인 없이 2단계로 넘어가지 않는다.

### 2. 소스 수집 · 적법성 체크 (Phase B)

[`reference/source-policy.md`](reference/source-policy.md)를 읽고 그 절차를 따른다. 결과는 `runs/.../sources.md`.

- 근거 소스 **3건 이상**. 미달이면 주제를 반려하고 사용자에게 알린 뒤 멈춘다.
- 소스마다 URL · 발행처 · 저자 · 발행일 · **인용할 구간의 발췌**를 남긴다. 발췌가 없으면 나중에 링크가 죽었을 때 근거가 사라진다.
- **웹 접근 불가 시 폴백**: 사용자에게 소스를 받아 같은 형식으로 기록한다. **소스 없이 지식만으로 쓰는 모드는 없다.**

### 3. 분할 판정 · 대본 생성

[`reference/writing-rules.md`](reference/writing-rules.md)를 읽고 그 규칙으로 쓴다. 결과는 `runs/.../script-{n}.md`와 `runs/.../claims-{n}.md`.

- 목표 분량 **본문 3,500~5,250자**(350자/분 × 10~15분, 공백 포함).
- 분할은 대본 생성 **전에** 결정한다. AI 생성은 원문 길이에 묶이지 않으므로 처음부터 한 편 분량을 목표로 쓰고, 주제가 한 편에 안 담길 때만 나눈다.
- `claims-{n}.md`(근거 대조표)를 반드시 함께 만든다. **이게 없으면 4단계 QA가 대본을 한 번 더 읽는 것에 그친다.**

### 4. QA 대조 — 반드시 별도 에이전트로

**같은 맥락에서 판정하면 자기 채점이 된다.** Agent 도구로 판정자를 띄우고, **대본을 쓰면서 한 판단을 넘기지 않는다.**

판정자에게 주는 것은 셋뿐이다: `sources.md` · `script-{n}.md` · `claims-{n}.md`. 판정 기준은 [`reference/qa-rubric.md`](reference/qa-rubric.md)를 읽게 한다. 결과는 `runs/.../qa-report-{n}.md`.

- 실패하면 **사유를 3단계에 피드백해 재생성**한다. **최대 3회.**
- 3회 모두 실패하면 `qa-report`에 `review_required`로 표시하고 사용자에게 넘긴다. **기준을 낮춰 통과시키지 않는다.**
- 재생성이 일어나면 `runs/.../attempts.md`에 회차·실패 사유·조치를 남긴다 — QA 통과율과 재생성 발생률이 PRD 10의 콘텐츠 지표다.

### 5. 업로드 패키지

[`templates/upload-meta.json`](templates/upload-meta.json)을 복사해 `runs/.../upload-meta.json`으로 채운다.

- `origin`은 `"ai_generated"`, `source_name`은 **`"이어"` 고정**(제작 주체 표기이지 출처 고지가 아니다), `author_name`·`source_url`·`partner_id`·`license_expires_at`는 `null`.
- `series_id`는 **비운다** — 관리자 화면에서 발급한다. 시리즈면 `episode_no`·`total_episodes`만 채운다.
- `topic_names`에 주제명을 넣는다. UUID(`topic_ids`)는 관리자 화면에서 고른다.
- `duration_sec`은 비운다 — 서버가 오디오에서 추출한다.
- **`sources.md`의 소스 목록을 여기 넣지 않는다.** `ai_generated`는 출처를 고지하지 않으며 소스는 내부 기록으로만 남는다(명세 4.4).

### 6. 마무리 보고

사용자에게 이렇게 보고한다.

1. 작업 디렉토리 경로와 산출물 목록
2. QA 결과 — 통과 여부, 재생성 횟수, 남은 지적사항
3. **사람이 해야 할 일**: 업로드 전 수동 검수 4항목(`admin.md` 4.2-1 — 사실관계 대조 · 금칙 · **출처 고지 멘트는 `ai_generated` 면제** · 오디오 품질) → TTS 합성 → 썸네일 → 관리자 업로드
4. 판단이 필요해 보류한 항목(소스 상충, 시의성, 조언 경계 등)

**"업로드 준비 완료"라고 말하지 않는다.** 이 패키지는 사람 검수 대기 상태다.

## 멈춰야 하는 상황

| 상황 | 처리 |
|---|---|
| 주제가 `topics`에 없음 | 진행하지 않는다. 관리자 화면에서 먼저 만든다 |
| 커리어·리더십 | 진행하지 않는다. 명세 2.1의 사유를 밝힌다 |
| 소스 3건 미만 | 대본을 쓰지 않고 반려한다 |
| 소스가 전부 차단·유료 | 전량 배제하고 반려한다. 예외 없다 |
| 본문이 3,500자를 못 채움 | 주제가 얇은 것이다. 단독 에피소드로 만들지 말고 인접 주제와 묶거나 반려한다 |
| QA 3회 실패 | `review_required`. 통과시키지 않는다 |
| 법률·의료·투자 조언에 근접 | 단정적 조언을 쓰지 않고 알려진 바 전달에 머문다. 사람 검수 플래그를 세워 보고한다 |
| 소스끼리 사실이 상충 | 한쪽으로 단정하지 않고 견해가 갈린다는 사실을 그대로 쓴다. 상충을 QA 리포트에 남긴다 |

## 산출물

```
runs/{YYYY-MM-DD}-{topic-slug}/
  topic-candidates.md    후보 + 승인 표시
  sources.md             근거 소스 + 적법성 체크 결과
  script-{n}.md          낭독 대본
  claims-{n}.md          근거 대조표
  qa-report-{n}.md       QA 판정
  attempts.md            재생성 이력 (재생성이 있었을 때만)
  upload-meta.json       관리자 업로드 메타
```

`runs/`는 커밋하지 않는다(루트 `.gitignore`). 검수 이행 증적은 `audit_logs`의 업로드 기록이 담당한다(`admin.md` 4.2-1).
