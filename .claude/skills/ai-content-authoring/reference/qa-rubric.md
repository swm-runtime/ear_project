# QA 판정 기준

명세 [`docs/ai/pipeline.md`](../../../../docs/ai/pipeline.md) 4.5의 구현. 원본은 [`features/content-pipeline.md`](../../../../docs/features/content-pipeline.md) 4.4다.

> **이 문서를 읽는 사람에게** — 당신은 이 대본을 쓰지 않았다. 대본을 쓴 쪽의 판단·의도·변명을 받지 않았고, 받을 필요도 없다. **`sources.md` · `script-{n}.md` · `claims-{n}.md` 세 파일만 보고 판정한다.** 대본이 그럴듯하게 읽히는지는 판정 대상이 아니다.

## 판정 항목 8개

`content-pipeline.md` 4.4의 7항목 중 **고지 멘트는 제외**하고(`ai_generated`는 출처를 고지하지 않으므로 검사할 대상이 없다), **정정 완결성과 문장 길이를 추가**한다.

| # | 항목 | 무엇을 보는가 | 실패 시 |
|---|---|---|---|
| 1 | 사실 일치 | `claims` 표의 각 주장이 소스 발췌에 **실제로** 있는가 | 재생성 |
| 2 | 미근거 정보 | 소스에 없는 수치·고유명사·인용이 대본에 있는가 | 재생성 |
| 3 | 주장 강도 왜곡 | 추정 → 단정, 부분 → 전체 일반화 | 재생성 |
| 4 | **정정 완결성** | 소스와 어긋나는 추측이 600자 이내에 정정되는가. 추측이 단정형으로 말해지지 않았는가 | 재생성 |
| 5 | 누락 | 승인된 주제의 요지가 대본에 담겼는가 | 재생성 |
| 6 | 금칙 | 욕설·차별 표현·특정인 비방 | 재생성, 3회 실패 시 보류 |
| 7 | 길이 | 본문이 3,500~5,250자인가 (화자명 제외) | 재생성 |
| 8 | 문장 길이 | 100자 초과 문장이 없고, 80자 초과가 전체의 10% 이하인가 | 재생성 |

> **항목 1·2·3은 `사실` 유형 발화에만 적용한다.** 2인 대화에서 반박은 자유롭게 허용되므로, 소스와 어긋나는 `추측` 발화가 대본에 의도적으로 들어간다. 그것을 항목 2로 잡으면 연출된 반박이 전부 실패가 된다. **`추측` 유형은 항목 4가 맡는다.**

## 항목별 판정법

### 1. 사실 일치

`claims` 표를 **한 줄씩** 본다. 대본 문장이 발췌에서 도출되는지 확인한다.

- 발췌에 **없는데 있다고 적힌 것** → 실패
- 발췌가 **대본 문장을 부분적으로만 받치는 것** → 실패. "대체로 맞다"는 통과가 아니다
- 발췌가 **다른 맥락에서 온 것**(조건·기간·대상이 다름) → 실패

### 2. 미근거 정보

`claims` 표에 **없는** 사실 주장을 대본에서 찾는다. 이게 이 항목의 전부다 — 표에 없으면 근거가 없는 것이다.

훑을 대상: 숫자 · 연도 · 비율 · 금액 · 기관명 · 인명 · 지명 · 제품명 · 따옴표 인용 · "~때문에" 형태의 인과 문장.

- 대조표에 "일반 상식"·"널리 알려진 사실"로 적힌 항목 → **실패로 본다.** 근거가 있으면 소스를 대고, 없으면 지웠어야 한다
- 예시·일화가 소스에 없이 등장 → 실패

**예외 — 전문용어 설명은 미근거로 잡지 않는다** (합의 2026-08-10). 소스가 정의 없이 쓰는 용어를 대본이 풀어 설명한 것은 허용된다. 단 아래를 확인하고, 하나라도 어긋나면 실패다.

- `claims` 표의 **"용어 설명" 항목에 따로 적혀 있는가.** 사실 주장 표에 섞여 있으면 실패
- **정의에서 멈추는가.** 평가·함의·적용으로 넘어가면 실패 — "결정지능은 쌓아온 지식을 꺼내 쓰는 능력이다"는 허용, "결정지능이 높으면 실무에 강하다"는 실패
- **널리 통용되는 표준적 정의인가.** 논쟁 중인 개념을 한 입장으로 정의했으면 실패

### 3. 주장 강도 왜곡

발췌와 대본 문장의 **강도를 나란히** 놓고 본다.

| 발췌 | 대본 | 판정 |
|---|---|---|
| "관련이 있는 것으로 나타났다" | "때문이다" | 실패 (상관 → 인과) |
| "일부 연구에서는" | "연구에 따르면" | 실패 (일부 → 전체) |
| "단기적으로는 효과가 있었다" | "효과가 있다" | 실패 (조건 삭제) |
| "국내 대기업 사무직 기준" | "직장인은" | 실패 (표본 확대) |
| "37.2%" | "약 40%" | 실패 (수치 변경) |
| "3~6개월" | "반년쯤" | 실패 (범위 → 점) |

**소스가 서로 상충해 대본이 "견해가 갈린다"고 쓴 것은 실패가 아니다.** 다만 상충 사실을 리포트에 남긴다.

### 4. 정정 완결성

`claims-{n}.md`의 **추측 발화 표**를 한 줄씩 본다. 대본에서 해당 발화를 찾아 직접 확인한다 — 표의 자기 신고를 그대로 믿지 않는다.

| 확인 | 실패 조건 |
|---|---|
| 단정형인가 | 소스와 어긋나는 내용을 "~이다", "~한다"로 말했으면 실패. "~인 것 같은데", "그거 ~ 아니야?" 처럼 추측임이 드러나야 한다 |
| 정정이 있는가 | 소스와 어긋나는데 대본 어디에도 바로잡는 대사가 없으면 실패 |
| 거리 | 어긋나는 발화의 끝에서 정정 대사의 시작까지 **600자를 넘으면 실패** |
| 정정이 실제로 바로잡는가 | 화제를 돌리거나 얼버무리면 정정이 아니다. **무엇이 틀렸는지가 말로 나와야 한다** |
| 표에서 누락됐는가 | 대본에 있는데 추측 표에 없는 반박·짐작을 찾으면 실패 |

- **어긋나지 않는 추측은 정정이 필요 없다.** 소스가 다루지 않은 영역에 대한 짐작("표본이 작으면 달라질 것 같은데")은 그대로 둔다.
- 마무리에 정정되지 않은 오류가 남아 있으면 거리와 무관하게 실패다.

### 5. 누락

승인된 주제의 요지(`topic-candidates.md`의 "한 줄 요지")가 대본에 담겼는지 본다. 다른 주제로 흘러갔으면 실패다.

### 6. 금칙

욕설·차별 표현·특정인 비방. **특정 기업·인물에 대한 부정적 단정**도 여기 포함한다 — 소스에 근거가 있어도 표현 강도를 검토한다.

### 7. 길이

본문(제목·메타 표 제외, 구분선 아래) 글자 수를 **공백 포함**으로 센다. 3,500 미만이거나 5,250 초과면 실패.

### 8. 문장 길이

문장 단위로 끊어 길이를 센다. **100자를 넘는 문장이 하나라도 있으면 실패**이고, 80자를 넘는 문장이 **전체 문장의 10%를 초과해도 실패**다.

- 목표는 60자 안팎이지만 그 자체를 실패 조건으로 삼지 않는다 — 나열이나 조건절이 붙으면 자연히 길어진다.
- 실패한 문장은 **글자 수와 함께** 지적한다. 어디를 끊어야 하는지는 재생성이 판단한다.
- 눈으로 되짚을 수 없는 매체라 문장 길이가 곧 이해 가능성이다. `content-pipeline.md` 4.4에는 없는 항목이며 이 파이프라인이 추가했다.

## 판정 원칙

- **애매하면 실패다.** 통과는 "문제를 못 찾았다"가 아니라 "확인했다"여야 한다.
- **개수를 맞추려 하지 않는다.** 문제가 없으면 없다고 하고, 열 개면 열 개를 적는다.
- **대본을 고쳐주지 않는다.** 판정자는 지적만 한다. 수정은 재생성이 한다.
- **소스를 새로 찾지 않는다.** 주어진 `sources.md`가 근거의 전부다.

```markdown
| 실패 항목 | 2·3 |
| 본문 글자 수 | N자 |

## 항목별

| # | 항목 | 판정 | 비고 |

| 2 | 미근거 정보 | ❌ | 아래 2건 |
| 3 | 주장 강도 왜곡 | ❌ | 아래 1건 |
| 4 | 정정 완결성 | ✅ | G1 정정 거리 120자 |
| 5 | 누락 | ✅ | |
| 6 | 금칙 | ✅ | |

## 지적사항

### [2-1] 미근거 — 소스에 없는 수치

> 대본: "직장인 열 명 중 일곱은 이 방법을 쓴다"

`claims` 표에 없고 `sources.md` 어느 발췌에도 근거가 없다. 삭제하거나 근거를 붙인다.

### [3-1] 강도 왜곡 — 상관을 인과로

> 발췌(S2): "…와 관련이 있는 것으로 나타났다"
> 대본: "…때문에 생긴다"

## 상충·판단 보류

소스 간 사실이 갈리거나 사람 판단이 필요한 것을 적는다. 실패 사유는 아니다.

| 내용 | 관련 소스 |
|---|---|
```

## 재생성 정책

- 실패 사유를 대본 작성 쪽에 피드백해 재생성한다. **최대 3회.**
- 3회 모두 실패하면 판정을 `review_required`로 두고 사람에게 넘긴다. **기준을 낮춰 통과시키지 않는다.**
- 회차마다 `attempts.md`에 회차·실패 항목·조치를 남긴다 — QA 통과율과 재생성 발생률이 PRD 10의 콘텐츠 지표다.

## 이 QA가 사람 검수를 대체하지 않는다

업로드 전 수동 검수 체크리스트([`admin.md`](../../../../docs/features/admin.md) 4.2-1)는 그대로 이행한다. 업로드 = 즉시 발행이라 검수 없는 업로드는 그대로 전 사용자에게 노출된다.
