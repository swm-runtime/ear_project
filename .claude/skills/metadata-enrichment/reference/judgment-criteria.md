# 메타 4종 판정 기준

값 집합의 원본은 [`domain.md`](../../../../docs/backend/domain.md) 5.1이다. **여기 적힌 값과 domain.md가 어긋나면 domain.md가 기준이고, 이 파일을 고친다.** 판정 기준의 원본은 [`metadata-pipeline.md`](../../../../docs/ai/metadata-pipeline.md) 4.2이며, 이 파일은 그 기준의 실행용 세부다.

공통 규칙:

- **대본 근거로만 판정한다.** 근거 대목을 못 짚는 판정은 판정 불능으로 처리하고 키를 생략한다.
- 청자 상(PRD 3.1): 편도 30분 통근하는 20대 후반~30대 초반 주니어 직장인. `difficulty`의 "전제 지식"은 이 청자 기준이다.

## difficulty — 청자 전제 지식 기준

| 값 | 기준 | 대본에서 보이는 신호 |
|---|---|---|
| `beginner` | 용어를 풀어 설명하며 사전 지식 불요 | 핵심 용어마다 정의·비유가 따라붙는다 · "처음 들어보셨다면" 류의 진입 안내 · 개념 개수가 적고 반복 설명 |
| `intermediate` | 기본 용어를 전제 | 기본 용어(예: 연금저축·API·코호트)는 정의 없이 쓰고, 그 위의 개념만 설명 · "이미 아시는 것처럼" 전개 |
| `advanced` | 실무 경험·선행 지식을 전제 | 실무 상황·세부 수치·예외 케이스 중심 · 기초 개념 설명이 아예 없음 · 도메인 관행을 아는 청자만 따라올 수 있는 전개 |

- 경계 판정: **대본이 가장 많은 분량을 쓰는 설명의 깊이**로 본다. 도입부 한 단락의 쉬운 요약 때문에 `beginner`로 내리지 않는다.
- 판정 불능(폴백 경로, 대본이 지나치게 짧음 등)이면 **키를 생략한다.** 중간값(`intermediate`)을 기본값처럼 쓰지 않는다.

## format — 지배적 서술 형식 하나

| 값 | 기준 | 경계 사례 |
|---|---|---|
| `news_analysis` | 뉴스·시사 해설 — 최근 사건·발표·수치를 다루고 그 의미를 해설 | 사건 소개 후 일반 원리로 넘어가면 분량 기준으로 `overview`와 겨룬다 |
| `howto` | 방법·실행 안내 — 청자가 따라 할 절차·단계·요령 | "무엇인지"보다 "어떻게 하는지"가 지배적일 때만 |
| `interview` | 대담·인용 중심 — 특정 인물의 발언·문답이 뼈대 | 두 진행자의 대화 형식(pipeline.md의 대본 형식)은 해당 없음 — 형식이 아니라 **소재가 인터뷰**여야 한다 |
| `opinion` | 주장·견해 — 화자의 입장이 뼈대이고 근거가 이를 뒷받침 | 균형 잡힌 해설이면 `news_analysis`/`overview` 쪽 |
| `case_study` | 사례 분석 — 특정 사례(기업·사건·인물)를 뜯어보는 구성 | 사례가 예시로 잠깐 쓰이는 것은 해당 없음 — 사례가 뼈대여야 한다 |
| `overview` | 개괄·입문 — 개념·영역을 넓게 소개 | 위 어느 것도 지배적이지 않은 설명형 대본의 기본 후보 |

- **혼합이면 분량 기준 지배 형식 하나만 낸다.** 복수 값·새 값을 만들지 않는다.
- `overview`를 "모르겠으면 넣는 값"으로 쓰지 않는다 — 개괄·입문이라는 적극적 판정일 때만.

## is_evergreen — 수명 판정

| 값 | 기준 |
|---|---|
| `false` (시의성) | 특정 시점의 사건·수치·정책에 묶여 시간이 지나면 유효성이 떨어지는 내용 |
| `true` (에버그린) | 원리·방법론 중심으로 수명이 긴 내용 |

- [`pipeline.md`](../../../../docs/ai/pipeline.md) 7장의 "시의성이 강한 주제" 판정과 같은 기준이다.
- 경계 판정: 시의적 소재로 **문을 열지만 본론이 원리·방법론**이면 `true`. 본론의 결론이 특정 시점 수치·제도에 의존하면(제도 개정 시 내용이 틀려지면) `false`.

## keywords — 세부 개념 명사구 3~8개

- **대본에 실제로 다뤄진** 개념만. 언급만 스쳐간 것, 대본 밖 연관 지식은 넣지 않는다(FR-09의 부여판).
- **주제명(`topic_names[]`)의 단순 반복 금지.** 주제가 "재테크"면 키워드는 "ISA 계좌", "비과세 한도"처럼 **주제보다 잘게** 잡는다 — 이게 존재 이유다(`drip-scheduling.md` 4.2 ②).
- 명사구로 쓴다: "ISA 계좌", "복리 계산", "손절 기준". 문장·서술형("ISA 계좌를 만드는 법")은 쓰지 않는다.
- 표기는 대본의 표기를 따르되, 같은 개념의 변형(띄어쓰기·조사 차이)을 중복으로 넣지 않는다. NFC·공백 정리는 `scripts/finalize.py`가 한다.
- 3개 미만이면 억지로 채우지 않는다(1~2개 허용, 0개면 키 생략). 대본이 얇거나 단일 주제 반복이라는 신호이며, 그대로 보고한다.
